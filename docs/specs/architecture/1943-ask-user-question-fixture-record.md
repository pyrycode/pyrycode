## Context

claude offers `AskUserQuestion` — a clarifying-question tool — alongside the
permission-prompt tool. Every committed `permission_protocol_*` capture in this
package lists the name in its `init` `tools` array and none of them holds a
`tool_use` block for it, so the repo has never recorded a **call** to it. This
slice is the first of four steps toward that capture, and it is the one that
settles the carrier: the record, its fully-populated fixture, the field listing,
and the round trip that locks both. No writer (#1941), no namer (#1944), no shape
assertion (#1942), no live claude, no filesystem write.

The record's field set is load-bearing beyond this ticket. #1941's writer refuses
to write by scanning the record's marshalled bytes, so **the field set is the leak
surface that refusal has to cover**. Four fields keep that a fixed deny list;
#1688's whole-stream capture ran past 1300 committed lines and needed three
follow-up tickets to build a redaction table for what it had swallowed. That is
why AC 1 caps the set rather than describing it.

No ADR is warranted. The decomposition (record → writer → live run → offline
read) is this package's existing, documented pattern, not a new decision.

### The record

Four fields, no more. `askQuestionFixtureRecord` — a distinct name is required,
`fixtureRecord` is taken by the permission-protocol spike's eleven-field capture.

```go
type askQuestionFixtureRecord struct {
	ClaudeVersionRaw  string          `json:"claude_version_raw"`
	ClaudeVersionSlug string          `json:"claude_version_slug"`
	ToolName          string          `json:"tool_name"`
	ToolInput         json.RawMessage `json:"tool_input"`
}
```

Three contract points that are not obvious:

- **`ClaudeVersionSlug`, not `claude_version`.** The family's other records tag
  the *token* (`"2.1.220"`) as `claude_version`. This field holds the **slug** —
  `versionSlug` applied to that token — which is a different quantity, so reusing
  the family's tag would hand a downstream decoder a value the family's other
  captures do not carry. The divergent tag is deliberate; do not harmonise it.
- **`ToolInput` is `json.RawMessage` and nothing else.** AC 3 exists because a
  decoded-and-re-marshalled input is not the bytes claude sent: `encoding/json`
  emits map keys in sorted order, so the re-marshal silently rewrites the call's
  own key ordering. The record carries the bytes.
- **No `omitempty` on any tag**, matching every other record in this family, so
  every key stays visible in a committed artifact a human reads.

There is deliberately **no** field for argv, the environment, the surrounding
stream, a `tool_use_id`, a session id or a timestamp. Each of those is a string a
#1941 deny-scan would have to reason about, and none is the call.

### The fixture

`askQuestionFullRecord() *askQuestionFixtureRecord` returns a **fresh pointer per
call** — never a package-level `var`. `initControlFullRecord`'s doc gives the
reason: a later cap or mutation test running parallel subtests over the returned
record turns a shared var into a `-race` data race discovered two tickets from
the line that caused it.

The input bytes live in a package-level `const askQuestionFixtureInput` string,
and the fixture sets `ToolInput: json.RawMessage(askQuestionFixtureInput)`.
**Splitting the literal out of the struct is what makes AC 3's mutant compile** —
see § Testing strategy.

Field values, with the constraint each one satisfies:

| Field | Value | Why this literal |
|---|---|---|
| `ClaudeVersionRaw` | `2.1.239-FIXTURE (Claude Code)` | Shaped like real `claude --version` output. Carries a space, parens and uppercase, so `versionSlug` rewrites it — the property below. |
| `ClaudeVersionSlug` | `2.1.239-fixture` | `versionSlug` of that line's leading token. Entirely inside `versionSlug`'s clean class, so re-slugging is a fixed point — the other half of the property. |
| `ToolName` | `AskUserQuestion` | The real tool name. It is capitalised, so it does **not** survive `versionSlug` — that is what leaves #1944's namer assertion non-vacuous on the tool-name column with no synthetic literal needed. |
| `ToolInput` | `askQuestionFixtureInput` | See below. |

The three strings are pairwise distinct, which AC 2's distinctness property
requires and which § Testing strategy asserts rather than trusts.

`askQuestionFixtureInput` is a **synthetic** input shaped like an
`AskUserQuestion` call, one compact line, and it is not a capture — this package
records captures under `testdata/`, and nothing here reads or writes that
directory. Two constraints bind its content:

1. **Its keys are not in sorted order, at more than one level.** The question
   object's keys run `header`, `question`, `multiSelect`, `options` (sorted would
   be `header`, `multiSelect`, `options`, `question`); each option object's run
   `label`, `description` (sorted would be `description`, `label`). A value
   re-marshalled from a generic decode reproduces neither ordering. AC 3's
   property is only as discriminating as this literal, and § Testing strategy
   asserts the divergence rather than assuming it.
2. **No `<`, `>` or `&` anywhere in it.** `encoding/json` HTML-escapes those by
   default, which would introduce a second, unrelated difference between the
   fixture bytes and a re-marshal, and muddy the one the test is about.

Carry a `-FIXTURE` marker inside at least one string value, for the reason
#1701's fixture carries one: nobody must be able to mistake this for a recording.

### The field listing

```go
type askQuestionFixtureField struct { name string; value any }

func askQuestionFixtureFields(rec *askQuestionFixtureRecord) []askQuestionFixtureField
```

Four hand-written rows in declaration order, each `{"<json tag>", rec.<Field>}`.

**A local row type, not `initControlFixtureField`.** The pair is trivial to
restate and reusing the other family's type would drag a reader toward
`compactInitControlRawRows`, whose touched-set assertion is scoped to that
record's three raw-JSON fields. This record has one. The duplication is four
lines and buys file independence — the property this file's `finOfflineExecBans`
entry exists to protect.

**The rows are hand-written and must never be generated by reflection.**
`initControlFixtureFields`' doc states both reasons and they hold unchanged here;
the second is the real one. These names are a *second, independent copy* of the
JSON tags, and the one defect a symmetric struct round trip structurally cannot
catch is a misspelled tag — #1662's code review established that even a *unique*
wrong tag round-trips green, since only a colliding tag makes `encoding/json`
drop both. The instrument that catches a misspelling is a reviewer diffing this
listing against the struct; a reflection listing reads each name off the very tag
it was meant to check and that instrument is gone. For the same reason there is
no reflection assertion that the listing's names equal the struct's tags.

### The one raw row

`ToolInput` is the record's only raw-JSON field. Both `json.Marshal` and
`json.MarshalIndent` rewrite an embedded raw message — `MarshalIndent` indents
*inside* it, plain `Marshal` compacts it — so a naive byte comparison after a
round trip is false for any input carrying insignificant whitespace and a
**perfectly correct record reddens**. `compactRawMessages` is the existing
normaliser; call it on both sides of the `tool_input` row.

**Do not copy `compactInitControlRawRows`.** That helper's type switch and
touched-name return exist because its record has three raw fields of two Go
types, and its "the normaliser touched exactly these three" subtest is what keeps
the type-scoped selection honest. With one raw field there is nothing for a
widened normaliser to blind and nothing for a narrowed one to miss that the row
itself would not report. Normalise at the single site instead:

- take a copy of each record, compact its `ToolInput` through
  `compactRawMessages(t, []json.RawMessage{...})[0]`, and build the listing from
  the copies;

so the normalisation is visibly scoped to one field. If a second raw-JSON field
is ever added, `compactInitControlRawRows`' type-scoped shape is the thing to
adopt then, not now.

Compaction **preserves key order** — `json.Compact` only strips insignificant
whitespace — so it does not blunt AC 3's mutant.

## Concurrency model

No goroutines, no channels, no context, no shutdown sequence. Both tests are
`t.Parallel()` at the top level; subtests are `t.Parallel()` too and read only
values the parent computed before starting them, so the shared slices are safe.
`askQuestionFullRecord` returning a fresh pointer per call is what keeps that
true if a later ticket adds a mutating subtest.

## Error handling

There are two failure modes and both are test-local:

- **A malformed `askQuestionFixtureInput`.** `compactRawMessages` `t.Fatalf`s on
  a raw message `json.Compact` rejects, and `json.MarshalIndent` over a record
  holding an invalid `json.RawMessage` returns an error. Every marshal and
  unmarshal in the tests checks its error and `t.Fatalf`s with a message naming
  the fixture — a swallowed error here leaves every assertion below it comparing
  zero values, which is green.
- **A decode that produces a nil `ToolInput`.** A dropped or `json:"-"`-tagged
  `tool_input` leaves the read-back side nil, and `json.Compact` over nil returns
  "unexpected end of JSON input", so that mutant surfaces as `compactRawMessages`'
  own `t.Fatalf` rather than as a row mismatch. The verdict is correct and the
  mutant *is* red; the diagnosis points at the helper. This is the known trap
  `compactInitControlRawRows`' doc records, expected rather than broken — note it
  in the file's header so the next reader is not sent chasing #1662.

No production error paths, no sentinels, no wire codes.

## Testing strategy

Two test functions. Scenarios only — the developer writes them in this package's
idiom.

### `TestAskQuestionFullRecord_PinsTheFourFieldsAndTheSlugShape`

Parent computes `rec := askQuestionFullRecord()` and
`rows := askQuestionFixtureFields(rec)` once; subtests read them.

- **the listing is exactly the record's four fields** — two assertions with
  *separate* failure messages, because they catch different mutants and neither
  catches the other's:
  - `len(rows)` equals `reflect.TypeOf(askQuestionFixtureRecord{}).NumField()`.
    Catches a field added with no listing row: it would go unchecked by every
    property below and by the round trip.
  - the rows' names, **in order**, equal a hand-written literal
    `["claude_version_raw", "claude_version_slug", "tool_name", "tool_input"]`.
    This is AC 1's cap. It catches a fifth field that arrives *with* a row —
    which the length check cannot, since both counts move together — and it
    catches a rename, a duplicated name and an omitted one in the same stroke,
    so no separate uniqueness pass is needed. This is a deliberate **third**
    hand-written copy of the tag set with a different job from the listing's: the
    listing exists to be zipped, this literal exists to say "nothing else".
- **every listed field carries a non-zero value** — via `fixtureFieldNonZero`. A
  zero-valued field round-trips green under *any* tag arrangement, so the round
  trip's row over it would settle nothing.
- **same-typed fields carry distinct values** — pairwise over rows grouped by
  `reflect.TypeOf`. The three strings must differ; `json.RawMessage` is its own
  named type and has no sibling here. Two same-typed fields carrying one value
  make a record with their two JSON tags swapped round-trip green. **Do not copy
  #1701's `reflect.Bool` skip:** this record has no bool field, so the `continue`
  would be dead code, and stating that here is what stops it being restored by
  harmonisation. Printing the shared value in the failure message is safe in this
  file and only in this file — every value here is a synthetic literal; the
  ticket that fills this record from a live child must not inherit the pattern.
- **the raw version is not a slug and the slug field is** — two assertions,
  again with separate messages:
  - `versionSlug(rec.ClaudeVersionRaw) != rec.ClaudeVersionRaw`. A raw
    `claude --version` line carries a space and parens; a literal "tidied" into a
    bare clean version would make #1944's name assertion 0-red on this column,
    which is #1722's measured lesson.
  - `versionSlug(rec.ClaudeVersionSlug) == rec.ClaudeVersionSlug`. The slug field
    holds a slugged value, so re-slugging is a fixed point. Reddens against the
    real mutant: a fixture populating both version fields from the same raw line.

  **The limit, stated rather than tested:** nothing here asserts the slug is
  `versionSlug` of *this* raw line's leading token. Splitting the token out of the
  raw line is `captureClaudeVersion`'s job and that helper execs, so re-deriving
  it here would be new logic with no consumer in this slice. #1941's fill site is
  where the two fields are minted from one call and where that coupling becomes
  checkable.

### `TestAskQuestionRecord_RoundTripsEveryFieldAndPreservesTheInputBytes`

Parent computes the record, marshals it with
`json.MarshalIndent(rec, "", "  ")` — the form the family's writers use, and the
form that puts indentation *inside* the raw message so the compaction below is
load-bearing rather than decorative — and decodes it back into a record. Subtests
are not parallel; they share one marshalled blob.

- **every field survives the round trip** — zip the two listings, built from
  copies whose `ToolInput` has been compacted on both sides, and
  `reflect.DeepEqual` row by row. No length guard before the zip: both slices come
  from one function over one struct type, so a divergence is impossible and the
  guard could never redden.
- **a re-marshalled decode would not reproduce the fixture's input** — the
  vacuity control, and it must run *before* the property it guards. Decode
  `askQuestionFixtureInput` into an `any`, re-marshal it with `json.Marshal`, and
  require the result to **differ** from the compacted const. If a later editor
  "tidies" the fixture's keys into sorted order, this reddens and says so,
  instead of the next subtest going quietly 0-red.
- **the input reaches the wire in the fixture's own key order** — AC 3's
  property, and the reason it is written over the *wire bytes* rather than over
  the decoded record. Unmarshal the marshalled blob into a
  `map[string]json.RawMessage`, compact `envelope["tool_input"]`, and require it
  to equal the compacted `askQuestionFixtureInput`.

  The mutant this is for: `ToolInput map[string]any` instead of
  `json.RawMessage`. **It is invisible to the round-trip row above** — both sides
  would then be maps and `reflect.DeepEqual` over maps is order-blind — and it
  **compiles**, because `askQuestionFixtureInput` is an untyped string constant
  that survives unused when the fixture switches to a Go map literal. Under it,
  `MarshalIndent` emits sorted keys and this comparison goes red. Compare the two
  as strings so the failure prints both blobs; that is safe here for the reason
  the distinctness subtest gives.

### Grading a mutant table here

Three lessons from this family bind, and the developer should read them before
predicting anything:

- **Grade by failure message, not by which subtest reddens.** #1701 measured a
  duplicate-name mutant reddening two subtests where one was predicted, while the
  length check stayed green throughout. A prediction of "exactly one subtest
  reds" is not checkable from red/green alone.
- **A subtest making a claim about the *type* runs over the zero value**, not
  over an indexed fixture field — indexing panics where the sibling vacuity check
  was supposed to report cleanly, and a panic takes the whole binary down. The
  ordered-name-literal assertion is a claim about the type; keep it independent
  of the fixture's values.
- **A touched-name canary selects by the row's Go type**, so it cannot see raw
  JSON nested inside another value. Nothing here relies on one; that is why
  § Design declines `compactInitControlRawRows`.

## Open questions

- **`claude_version_slug` is slug-clean by construction, which blunts one column
  of #1944's namer assertion.** #1722 measured this exact hazard on the sibling
  family: a minting input already inside `versionSlug`'s clean class makes a
  writer that interpolates it raw byte-identical to one that slugs it, so a
  "named exactly what the namer mints" assertion goes 0-red on that column. If
  #1944 mints its filename from this field, its non-vacuity has to come from
  somewhere else — `tool_name` is the obvious candidate, since `AskUserQuestion`
  is capitalised and does not survive slugging. Flagged here for #1944's
  architect; it is not resolvable inside this slice, because AC 1 fixes the field
  as the slug.
- **`askQuestionFixtureInput`'s shape is plausible, not recorded.** Nothing in
  this repo holds a real `AskUserQuestion` `tool_use` block, so the literal is
  modelled on the tool's documented shape. If the live run in the follow-up
  finds the real input's key ordering already sorted, AC 3's control subtest is
  what says so, and the fixture — not the property — is what changes.
- **Field count versus #1941's deny scan.** The four fields are the surface that
  writer must cover. If #1941 finds a field it cannot scan cleanly, the fix
  belongs there; widening this record is what this ticket's AC 1 exists to
  prevent.

## Security review

**Verdict:** PASS

**Findings:**

- **[Trust boundaries] No findings, by construction.** This slice has no trust
  boundary at all: every byte it handles is a literal declared in its own source
  file. Nothing crosses from network, file, subprocess stdout or environment into
  process state — `askQuestionFullRecord` returns hand-written constants and
  `json.MarshalIndent`/`json.Unmarshal` round-trip them in memory. The boundary
  this record *will* sit behind is #1941's fill site, where a live child's
  `tool_use` bytes land in `ToolInput`; naming that here is the point, because
  the field set fixed by AC 1 is what that boundary has to cover.
- **[Tokens, secrets, credentials] No findings in this slice — the design
  decision that makes it so is AC 1's cap, and it is enforced, not described.**
  The record's field set *is* the credential-exposure surface for the capture
  that follows it. It is capped at four and pinned by a hand-written name
  literal, so `argv`, an `env` map, a `stderr_capture` or a whole-stream field —
  each a documented leak carrier in this package's own history, and each the
  shape that cost #1688's family three redaction tickets — cannot arrive
  unnoticed. Separately, the file may not *read* a credential at all:
  `os.Getenv`, `os.Environ` and `os.LookupEnv` are banned for it in
  `finOfflineExecBans`, over the file's AST rather than over its prose, because
  this process environment carries `CLAUDE_CODE_OAUTH_TOKEN` and
  `ANTHROPIC_API_KEY`. No token is generated, stored, rotated or compared
  anywhere in this slice; every byte in it is a source literal.
- **[Trust boundaries, second pass] SHOULD FIX for #1941 — `tool_input` is not
  as inert as "model-authored prose" makes it sound, and this spec says so rather
  than letting the narrow field set imply a clean artifact.** `ToolInput` is the
  one field that will later carry live bytes, and the natural content of a
  clarifying question is a choice about a file operation — "overwrite
  `/Users/<operator>/…`?" — so an absolute path, and with it the operator's home
  directory name, reaches the field through ordinary use rather than through a
  bug. That is exactly the workdir/home class this package's `dropcapClass*`
  vocabulary exists for. Nothing in *this* slice can close it: the fixture is
  synthetic and the field carries no live bytes until the capture runs. The net
  is #1941's deny scan over the marshalled record, and this finding is the
  concrete carrier that scan must cover — a narrow field set bounds the surface,
  it does not clean it. Recorded here so #1941's review has a named scenario
  rather than a general worry.
- **[File operations] No findings — the design performs no filesystem operation
  in either direction.** No path is constructed, so there is no traversal, TOCTOU
  or symlink surface and no file mode to specify. That is not left to discipline:
  `packageDir` and its three wrappers `setModeFixturePath`, `writeSetModeFixture`
  and `writeFixture` are banned for this file, as are `os.ReadFile`,
  `os.WriteFile`, `os.Create`, `os.ReadDir` and `filepath.Glob`. The last group
  is the one that matters and it is not tidiness — `go test` runs in the package
  source directory, so a **relative** `os.WriteFile("testdata/…")` would reach
  and overwrite the eight committed `permission_protocol_*` captures while naming
  no wrapper at all. The ban list is copied whole from
  `initialize_control_record_test.go` precisely because the check is an AST
  identifier match and a hand-picked subset leaves the ban true and the property
  false. **The limit of that enforcement, stated so nobody over-reads it:
  `TestFinOfflineFilesReachNoExecHelper` is per-file *syntax*, not a call graph** —
  a banned read stays reachable through a helper the file calls while the ban
  stays green. The three helpers this file does call (`versionSlug`,
  `compactRawMessages`, `fixtureFieldNonZero`) were each checked to be pure: a
  regexp substitution, a `json.Compact`, and a `reflect` kind switch. A fourth
  helper added later inherits no such check.
- **[Subprocess / external command execution] No findings — no process is
  spawned.** `captureClaudeVersion` is the package's own direct `claude
  --version` exec and it is the single most likely thing for a developer here to
  reach for, since it returns the raw line and its leading token — exactly what
  this record's two version fields are minted from. It is banned for this file by
  name for that reason. `resolveClaudeBin` and `WithWorktreeAuthenticated` are
  banned on a different ground worth stating separately: they skip *inside* the
  test body, after `=== RUN` has printed, and a skipped suite exits 0 — so
  reaching either would convert AC 4's "runs and passes with no credentials" into
  a silent skip that is indistinguishable from a pass at the gate.
- **[Cryptographic primitives] Not applicable, by design.** No randomness, no
  hashing, no key material, no comparison against a secret. `versionSlug` is a
  deterministic regexp substitution with no security role — it normalises a
  version token for a filename and nothing branches on its output.
- **[Network & I/O] Not applicable.** No socket, no listener, no reader over
  attacker-controlled input, so there is no size cap, timeout or connection limit
  to specify. The one unbounded quantity in the design is `askQuestionFixtureInput`
  itself, and it is a compile-time constant in the repository — a reviewer reads
  it in the diff.
- **[Error messages, logs, telemetry] SHOULD FIX — bounded by a stated rule, not
  by a check.** § Testing strategy deliberately permits failure messages to print
  field values in full, which is normally the wrong default in this package. It
  is safe **here and only here** because every value in this file is a synthetic
  literal; the rule that keeps it safe is that the ticket filling this record from
  a live child must not inherit the pattern, exactly as
  `TestInitControlFixture_WriterCapsStderrCapture` reports lengths and a short
  prefix instead of values. Nothing enforces that across the file boundary — it
  is a doc-comment-and-review rule, and it is written into this spec so #1941's
  review has something to hold against. No `slog` call, no telemetry, no
  operator-identifiable data anywhere in the slice.
- **[Concurrency] No findings.** No goroutine, no lock, no shared mutable state:
  each test's parent computes its values before any `t.Parallel()` subtest starts
  and the subtests only read them. The one live hazard is a fixture returned as a
  package-level `var`, which a later mutating subtest turns into a `-race` data
  race two tickets from the cause; § Design forbids it — `askQuestionFullRecord`
  returns a fresh pointer per call.
- **[Threat model alignment] Not applicable — no wire protocol is touched.**
  `docs/protocol-mobile.md` § Security model governs relay traffic and nothing in
  this slice reaches a relay, a device or the control socket. The threat this
  slice *does* sit inside is this package's own: a committed test artifact that
  swallows operator state. It is out of scope here and named — #1941's deny scan
  over the marshalled record is what makes the clean-artifact claim, and this
  ticket's contribution to it is a four-field surface rather than a redaction
  table.
