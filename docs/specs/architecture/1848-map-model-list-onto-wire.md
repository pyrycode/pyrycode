## Context

`turnbridge.MapEvent` has no `turnevent.ModelList` arm — `internal/turnbridge` contains no
reference to the type at all, production or test — so the variant falls into the `default` and
is dropped. This slice adds the arm and nothing else.

Every piece the mapping reads is already in the tree:

- **The target** — `protocol.ModelListPayload` / `protocol.ModelOption`, declared by #1704, its
  encoding pinned by three committed fixtures and published in `docs/protocol-mobile.md`
  § `model_list` by #1705. Both types own their `MarshalJSON`.
- **The source** — `turnevent.ModelList`, decoded by `emitModelList` and bounded in all three
  dimensions, which **counts what it cuts** since #1812.

The two sides are field-for-field. `ConversationID` is the only value the mapping supplies, and
it comes from `tc`.

**What this slice does not change: anything a client sees.** `MapEvent`'s only production call
site is `emitMapped` in `cmd/pyry/interactive_turn_v2.go`, reached only from
`interactiveTurnEmitterV2.Handle`'s type switch — a **whitelist** whose `default` drops and
debug-logs. `Handle` has no `turnevent.ModelList` arm, so a decoded model list still never
reaches `MapEvent` on any lane. Verified, not assumed: `turnbridge.MapEvent` appears exactly
once in non-test production code outside comments. Adding this arm makes the mapping *possible*
and emits nothing. Putting the frame on the wire is the sibling slice.

**No ADR.** This is one arm on an existing exhaustive type switch, following four documented
precedents in the same function. Nothing here decides a question the tree has not already
settled.

## Design

### The arm

One `case` in `MapEvent`, placed **after** the `turnevent.ModelAnnounced` arm and before
`default` — the two model variants sit together, and the file's arm order is otherwise the
order variants landed.

Signature of the work, not the body:

```go
case turnevent.ModelList:
    // ~35 lines of doc comment stating the seven rules below.
    var models []protocol.ModelOption
    for _, m := range e.Models { models = append(models, protocol.ModelOption{ /* six fields, 1:1 */ }) }
    return protocol.TypeModelList, protocol.ModelListPayload{
        ConversationID: tc.ConversationID, Models: models, DroppedModels: e.DroppedModels,
    }, true
```

Field mapping, 1:1 and total — every field of `turnevent.ModelOption` has exactly one
destination and none is derived, defaulted, or synthesised:

| `turnevent.ModelOption` | `protocol.ModelOption` | Carry |
|---|---|---|
| `ResolvedModel` | `ResolvedModel` | verbatim string |
| `Value` | `Value` | verbatim string |
| `DisplayName` | `DisplayName` | verbatim string |
| `EffortLevels` | `EffortLevels` | **slice reference**, nil stays nil |
| `SupportsAutoMode` | `SupportsAutoMode` | verbatim bool |
| `TruncatedFields` | `TruncatedFields` | **slice reference**, nil stays nil |

| `turnevent.ModelList` | `protocol.ModelListPayload` | Carry |
|---|---|---|
| `Models` | `Models` | looped; nil stays nil |
| `DroppedModels` | `DroppedModels` | verbatim int |
| — | `ConversationID` | `tc.ConversationID` |

### The seven rules the arm's comment must state

These are the design; the comment is where they live, in the house style the four precedent arms
established. Do not restate the arithmetic those arms already carry — cite the symbol.

1. **Conversation identity only.** `tc.TurnID` and `tc.Seq` are ignored and the payload has no
   field for either. One `initialize` exchange per child produces one of these — it is not even
   per-turn, let alone turn-scoped — and it opens and closes no turn. `cmd/pyry`'s `turnMarkFor`
   already answers `turnMarkNone` by construction (whitelist opener set, `turnMarkNone` default),
   and `TestTurnMarkFor_TotalOverEveryVariant` pins that independently.

2. **A nil `Models` is forwarded, not pre-allocated.** `ModelListPayload.MarshalJSON` owns
   nil→`[]`. Allocating an empty slice here produces the same bytes while hiding which layer owns
   the normalisation — the rule the `ToolStart` and `BackgroundTaskRoster` arms both state.

3. **`EffortLevels` crosses as the slice it is.** Nil stays nil and `ModelOption.MarshalJSON`
   normalises it to `[]`. Same reason as rule 2, and note the hazard here is *only* the
   layer-ownership one: an allocation would produce identical bytes.

4. **`TruncatedFields` crosses as the slice it is, and here the nil is load-bearing.**
   `ModelOption.MarshalJSON` **deliberately exempts** this field, so nothing normalises it
   afterwards: nothing-was-cut is an ABSENCE and must reach the wire as `null`. A mapper that
   allocated an empty slice — or `append`ed into a fresh one — would emit `[]` and tell a phone
   that claude's cut text is complete. This is the `RateLimited` arm's rule (#1410) verbatim.
   **The asymmetry with rule 3 one field up is the whole point and must be said out loud**, in
   both directions, or the next reader takes it for an accident.

5. **`DroppedModels` is carried, never recomputed and never a constant.** It is the count the
   decode recorded when `maxModelListEntries` fired. Recomputing it from `len(models)` yields the
   wrong number by construction; shipping `0` tells a phone that a capped menu is the whole menu.
   `BackgroundTaskRoster.DroppedTasks`' stated reason, unchanged.

6. **Nothing is re-capped, re-ordered, canonicalised, or charset-checked.** The producer bounded
   all three dimensions at construction (`maxModelResolved` / `maxModelValue` /
   `maxModelDisplayName` on the strings, `maxModelEffortLevel` and `maxModelEffortLevelCount` on
   the levels, `maxModelListEntries` on the entries), so a second cap here would be a second
   place the limit is decided and the two could disagree silently. Entry order is claude's;
   effort-level order is claude's — measured non-alphabetical (`low, medium, high, xhigh, max`),
   so a sort is observable. `maxSummaryLen` and `maxResultSummaryRunes` live in this file and are
   **not** applicable bounds; reaching for either is the specific mistake to avoid.
   `internal/relay`'s `validModel` and `validEffort` bound a **phone-supplied inbound** value and
   are deliberately not applied here in either direction — `validEffort`'s enum is closed, so
   applying it outbound would drop a level claude legitimately publishes.

7. **No suppression branch, not even on an empty `Models`.** The gate that decides whether the
   event exists at all is the producer's, and `turnevent.ModelList.Models` documents that gate
   ("Never empty"). A second, differently-shaped filter here is the hazard the `ThinkingProgress`,
   `RateLimited` and `ModelAnnounced` arms each name. A zero-value `ModelList` therefore maps —
   `ok` is true — exactly as a zero-value `ModelAnnounced` does.

`SupportsAutoMode` needs no rule of its own beyond "verbatim": absent, `null` and explicit
`false` were already collapsed to `false` upstream by `encoding/json` and by
`turnevent.ModelOption.SupportsAutoMode`'s stated reading, and it is a REPORT to a client's menu
that nothing in the daemon may read as authorization.

### The doc correction (AC 5)

`protocol.ModelOption.TruncatedFields`' first sentence enumerates the vocabulary as
`("value", "display_name")`. The producer records **four** names, and the same type's SECURITY
paragraph already credits all four — the enumeration is 2-of-4 and every sibling
`TruncatedFields` doc in that file enumerates exhaustively.

Replace the enumeration with all four **in producer order**: `"resolved_model"`, `"value"`,
`"display_name"`, `"effort_levels"`. Add one sentence for the one name that is not a plain string

truth for that sentence; do not re-derive it.

Everything else in that paragraph stays: the `null`-when-nothing-was-cut clause, the
not-normalised-the-way-`EffortLevels`-is clause, and the load-bearing paragraph.

## Concurrency model

`MapEvent` stays pure and synchronous: no goroutines, no channels, no shared state, no clock, no
I/O. The package's concurrency surface has been zero since #1543 and this arm does not raise it.

**One aliasing invariant is genuinely load-bearing, and it is newer than the precedent arms.**
The arm copies slice *headers*, so the returned payload shares backing arrays with the
`turnevent.ModelList` it was handed. Two facts make that sharing safe only under a rule:

- `cmd/pyry`'s `sessionModelHold.Sink` (#1840, landed 2026-08-26) stores the `ModelList`
  **without copying** — its own comment says the hold "takes sole ownership of what it is
  handed" — and then forwards the **same value** downstream. `cloneModelList` deep-copies on the
  **read** side only. So the session's retained menu and anything the drain lane derives from the
  forwarded event point at one set of backing arrays.
- `sessionModelHold.ModelList()` is read on a **relay-leg goroutine** (#1837's publisher) while
  the parser's stdout-forwarder goroutine writes the hold.

**The rule: carry, never mutate through.** No `slices.Sort`, no in-place dedupe, no filtering,
no `append` into a slice the event owns, and nothing that writes `e.Models[i].*`. A mapper that
mutated through any of those would corrupt the session's retained list across two goroutines —
a data race, not merely a correctness bug. `ModelListPayload.MarshalJSON` refuses to reach
through into `p.Models[i]` for precisely this reason and says so; the arm inherits the same rule
one layer up. As specified — a read-only loop building a fresh outer slice — the arm never
writes through an aliased pointer, so the invariant holds by construction.

## Error handling

`MapEvent` returns no error and cannot fail. There is no I/O, no allocation that can be
observed to fail, no parse, and no branch that can reject an input:

- A zero-value `ModelList` maps (rule 7), it does not drop.
- A nil `Models` maps to a nil `Models` and marshals as `[]` (rule 2).
- `DroppedModels` is not range-checked in either direction — it is a daemon-computed `int` from
  a slice length, and the arm re-decides nothing about it (rule 5).
- The only `!ok` outcomes in this function remain `ThoughtChunk` and a nil/unknown `Event`.
  `MapEvent`'s own doc (*"ok is false for … any nil/unknown Event"*) stays accurate once the arm
  exists and needs no edit.

## Testing strategy

Two additions to `internal/turnbridge/outbound_test.go`. Both stand on **sentinels chosen to
falsify what the row claims**, not merely to differ from `tc` — the lesson
`docs/knowledge/features/turnbridge-package.md` records against the `ModelAnnounced` rows. All
scenarios are described as inputs + expected behaviour; write the code in the file's idiom.

### A. Rows in `TestMapEventOutbound` (`reflect.DeepEqual` on the payload)

The existing harness already distinguishes nil from empty slices, so these rows pin the nil-carry
at the struct level and the byte test below pins it on the wire.

- **Every field verbatim.** A two-entry list. Mixed-case sentinels on all three strings (an
  all-lowercase sentinel survives a `strings.ToLower` mutant). Effort levels in claude's measured
  **non-alphabetical** order (`low, medium, high, xhigh, max`, which sorts to a visibly different
  sequence) so a sort or a canonicalisation goes red. `SupportsAutoMode` **true on one entry and
  false on the other**, so a defaulted flag in either direction goes red. `DroppedModels` set to
  a value that is neither `0` nor `len(Models)`. Entry order itself distinguishable, so a reverse
  or a re-sort of the outer slice is caught.
- **Nothing-cut row keeps a nil `TruncatedFields`.** Same row family, `TruncatedFields` unset;
  `wantPayload` carries a nil, not `[]string{}`. `DeepEqual` fails on an allocating mapper.
- **Over-cap strings cross uncut.** One entry whose `ResolvedModel`, `Value` and `DisplayName`
  each exceed **both** the producer's bound (256) **and** this file's own `maxSummaryLen` (200),
  plus one effort level over `maxModelEffortLevel` (32). A re-cap mutant at any of those bounds
  goes red. This is the `overCapModel` discipline the file's preamble already states.
- **Turn addressing ignored.** A `tc` whose `TurnID` and `Seq` are conspicuous; the expected
  payload is unchanged from the plain-`tc` row.
- **Zero value maps rather than dropping.** `turnevent.ModelList{}` → `ok` true,
  `TypeModelList`, `ModelListPayload{ConversationID: …}` with a nil `Models` and `DroppedModels`
  zero.

### B. One new byte-level test — `TestMapEventModelListOnTheWire`

Shape: `TestMapEventRateLimitedTruncatedFieldsOnTheWire`'s harness exactly — `MapEvent`, assert
`ok` and `typ`, `json.Marshal` **the value `MapEvent` returned**, then `want` / `notWant`
substring needles. Never a test-built payload: with two `MarshalJSON` methods in play, a hand-built
payload proves the marshallers work and says nothing about whether the mapping reached them with
the nils intact.

Its doc comment must state the polarity trap explicitly, because **this one test carries both
polarities in adjacent rows and copying either onto the other is the realistic mistake**:
`models` and `effort_levels` want `[]` and forbid `null`; `truncated_fields` wants `null` and
forbids `[]`.

Needles are always the full `"key":"value"` or `"key":[…]` pair, never a bare value — a bare-value
needle passes against a mapping that swapped two same-typed neighbours (all six row fields but
one are strings here, so the hazard is acute).

Rows:

| Row | Fixture | `want` | `notWant` |
|---|---|---|---|
| nil models → `[]` | `ModelList{}` | `"models":[]`, `"dropped_models":0` | `"models":null` |
| populated control | one entry | the entry's `"value":"…"` pair | `"models":[]` |
| nothing cut → `null` (**AC 4**) | one entry, `TruncatedFields` unset | `"truncated_fields":null` | `"truncated_fields":[]` |
| only `resolved_model` cut (**AC 3**) | one entry, `TruncatedFields: ["resolved_model"]` | `"truncated_fields":["resolved_model"]` | `"truncated_fields":null` |
| only `effort_levels` cut (**AC 3**) | one entry, `TruncatedFields: ["effort_levels"]` | `"truncated_fields":["effort_levels"]` | `"truncated_fields":null` |
| all four, in producer order | `["resolved_model","value","display_name","effort_levels"]` | that array as **one** needle | `"truncated_fields":null` |
| nil effort levels → `[]` | one entry, `EffortLevels` unset | `"effort_levels":[]` | `"effort_levels":null` |
| effort levels in claude's order | five levels, measured order | the whole array as **one** needle | the sorted array as a needle |
| drop count ≠ row count (**AC 2**) | 2 entries, `DroppedModels: 3` | `"dropped_models":3` | `"dropped_models":0`, `"dropped_models":2` |
| no turn addressing leaks (**AC 1**) | any entry, `tc` with a conspicuous `TurnID` and `Seq` | `"conversation_id":"<sentinel>"` | the turn-id sentinel, the seq sentinel |

**Build each isolating row so exactly one name is present.** A row that also carries a second cut
name pins neither: a whitelist mutant keeping only the two names the old doc named would stay
green against an over-determined fixture. The two isolating rows are AC 3's whole point — they
are precisely the two names the stale doc omitted.

## Open questions

1. **`model_list` has no committed envelope-cap measurement, and the worst case is tight.**
   Its three siblings each have one (`TestToolUsePayload_FitV2EnvelopeCap`,
   `TestToolResultPayload_FitV2EnvelopeCap`, `TestAttachmentChunkPayload_FitV2EnvelopeCap`);
   `model_list` has none, and it is the frame with the largest structural fan-out.
   Rough arithmetic from the producer's own constants: 10 entries × (256 + 256 + 256 B of strings
   + 8 × 32 B of levels) = 1024 B of claude text per entry, ×6 worst-case wire bytes per escaped
   rune (`<`, `>`, `&`, control bytes — `tool_result`'s stated arithmetic) ≈ 6.1 KB, plus ~230 B
   of per-entry JSON structure, ≈ **64 KB against the 65519-byte cap**. That is single-digit-KB
   headroom on an estimate, and exceeding the cap does not truncate a frame — it **loses** it.
   Not this ticket: nothing puts the payload in an envelope here. It belongs with the payload's
   declaration (`internal/protocol`, #1704's gap) and it **must** be settled before the transport
   slice ships. File it against that slice.
2. **`docs/protocol-mobile.md` § `model_list`'s `truncated_fields` row does not enumerate the
   names at all** ("Names of **this row's** cut fields"), so it is vague rather than wrong and
   nothing here falsifies it. Worth the same four-name enumeration its `background_tasks_changed`
   and `slash_command_list` siblings carry — a documentation-phase item, outside the developer's
   writable paths.
3. **The turnbridge package overview needs a fifteenth row** in its per-variant table plus the
   nil-polarity note. Documentation phase; not a developer AC.

## Security review

**Verdict:** PASS

**Findings:**

- **[Trust boundaries]** No findings. The boundary is upstream and single-sited: claude's stdout
  crosses into daemon state at `streamsup.Parser`'s `emitModelList`, which bounds all three
  dimensions before an event exists. `MapEvent` is downstream of it, is pure, and re-decides
  nothing — the design's rule 6 is exactly this. The strings stay **untrusted,
  model-influenced text** all the way to the client; `protocol.ModelOption`'s SECURITY paragraph
  already states that the render boundary owing sanitization is the client's, and this arm
  neither weakens nor duplicates it. No type-system signal distinguishes trusted from untrusted
  here, which is the family's standing convention (every `*Payload` is in the same position) and
  not a regression this slice introduces.
- **[Trust boundaries — the round-trip field]** No finding, one decision recorded.
  `ModelOption.Value` is the first field in this family a client is meant to send **back**.
  Publishing it does not make it trusted: the inbound path re-validates at `internal/relay`'s
  `validModel` (widened at #1838 for exactly these rows), and nothing in this arm may be read as
  having pre-authorized a value. The converse — applying `validModel` or `validEffort` on this
  outbound path — is explicitly **forbidden** by rule 6, because `validEffort`'s enum is closed
  and would drop a level claude legitimately publishes.
- **[Subprocess / command execution]** No finding, named rather than skipped because the sink
  exists. `Value` reaches an argv position downstream via `set_session_settings` — #845's
  argv-injection defense, guarded by `validModel` on the inbound leg. This slice touches neither
  that guard nor any `exec.Command`, and the outbound mapping never feeds argv.
- **[Tokens, secrets, credentials]** No secret material. The adjacent standing rule is #833's
  posture — *model / effort / YOLO values are NEVER logged at any level*, restated across
  `internal/relay`'s `v2session_settings.go` and `internal/sessions`' `pool.go`. `MapEvent` is
  pure and logs nothing; **the arm must add no `slog` call**, and a drop-site or diagnostic log
  echoing an entry's `Value`, `ResolvedModel` or `DisplayName` is the realistic breach. Note
  `eventKind`'s `ModelList` arm already records that the temptation is *multiplied* here because
  every entry carries all three. Test failure messages print sentinel fixtures, not claude values.
- **[File operations]** Not applicable, by design rather than by luck: the arm is a pure
  value-to-value function with no path, no `os` call, and no filesystem reference of any kind.
- **[Cryptographic primitives]** Not applicable. No RNG, no key, no comparison against a secret.
  The envelope's AEAD seal is the consumer's (`emit`) and is untouched — this function does not
  mint an envelope ID, read a clock, or marshal.
- **[Network & I/O — resource exhaustion]** SHOULD FIX, and it is the strongest finding this pass
  produced. The mapped payload is bounded by construction in all three dimensions
  (`maxModelListEntries` = 10, the three 256-byte string caps, `maxModelEffortLevelCount` = 8 ×
  `maxModelEffortLevel` = 32), so no unbounded value crosses. But the **worst case sits at
  roughly 64 KB against the 65519-byte v2 application-envelope cap** (arithmetic in § Open
  questions 1), and unlike `tool_use`, `tool_result` and `attachment_chunk` this payload has
  **no committed `_FitV2EnvelopeCap` measurement**. Exceeding the cap loses the frame rather than
  truncating it. **Not exploitable as designed in this slice** — no production path puts this
  payload in an envelope, since `Handle` has no arm — which is why it is SHOULD FIX here and
  **MUST FIX before the transport slice ships**. Recorded with its numbers so the successor
  inherits a computed estimate rather than re-deriving one.
- **[Network & I/O — retained memory]** OUT OF SCOPE, named for the same successor. `model_list`
  is not classified in `internal/eventring` today. If the transport slice makes it control-class,
  `MaxEventsPerConversation` (1024) multiplies the per-frame worst case above into a
  per-conversation footprint — the multiplier `maxResultSummaryRunes`' never-raise rule exists
  for. Nothing is retained until a frame is emitted, so this slice adds no exposure.
- **[Error messages, logs, telemetry]** No findings. The function returns no error, produces no
  message, and emits no metric. Covered above for logs.
- **[Concurrency]** SHOULD FIX — addressed in the spec, and the reason it needed addressing is
  newer than every precedent arm. The arm copies slice **headers**, so the payload aliases the
  event's backing arrays; `sessionModelHold.Sink` (#1840) retains the same `ModelList`
  **without copying** and forwards the same value, and `sessionModelHold.ModelList()` is read on
  a relay-leg goroutine while the parser goroutine writes the hold. A mapper that sorted,
  deduped, filtered, or `append`ed in place would therefore corrupt the session's retained menu
  **across two goroutines** — a data race, not just a correctness bug. `cloneModelList` protects
  readers of the hold from each other and does **not** protect the hold from a mutating
  downstream consumer. § Concurrency states the invariant (*carry, never mutate through*); as
  specified — a read-only loop building a fresh outer slice — it holds by construction. Code
  review should check it explicitly, since the four precedent arms' comments pre-date #1840 and
  none of them names this hazard.
- **[Threat model alignment]** `docs/protocol-mobile.md` § Security model: this frame is a
  **report, never a control input** — nothing in the daemon keys a behaviour on it, and
  `SupportsAutoMode` in particular is never an authorization input, since a daemon reading its
  own subprocess's claim as permission is a subprocess authorizing itself
  (`turnevent.ModelOption.SupportsAutoMode` states this). The interactive-capability gate is
  filtered **once**, in the consumer's `emit()`, for every frame type; the arm adds no second
  gate — writing one here is how that single gate stops being single. Client-facing delivery
  threats (capability gating in practice, replay, per-conversation retention) belong to the
  transport slice, which carries the same label.
