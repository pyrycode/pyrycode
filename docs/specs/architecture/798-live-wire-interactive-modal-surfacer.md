## Context

`interactiveModalEmitterV2` (`cmd/pyry/interactive_modal_v2.go`) is fully built and unit-proven, but `newInteractiveModalEmitterV2` has **zero non-test callers** (verified). Three in-code comments defer the live `Session.Events()` wiring to "#708" (`relay.go:302-306`, `interactive_modal_v2.go:24`, `acp_permission.go:44-46`), but #708 closed and split into four test-only e2e tickets without carving out the production wiring. Consequence today: the real daemon can never emit `modal_shown`, `ArmModalTimeout`'s fail-closed deny never arms in production, and the Phase 3 live capstones #791/#793 are unbuildable against a live daemon.

This ticket delivers the missing wiring so those capstones become genuinely harness-only. **ACP proxy (`acpPermissionProxy`) is explicitly out of scope** — it is a separate unwired consumer of the same raw stream (#751 territory).

## Design

### One new file, one modified file

- **New:** `cmd/pyry/interactive_modal_stream_v2.go` — the wiring (no new exported symbols; `package main`).
- **Modified:** `cmd/pyry/relay.go` — one gated call + one cleanup join, co-located with the turn stream inside the shared gate.

### The reuse decision — a second independent follow-active subscription

The turn stream and the modal stream both need the *same* thing: the active conversation's live tui-driver event stream, following conversation switches with cross-conversation confidentiality. The turn stream gets it from `resolveTarget` + `NewTargetSubscriber`. `NewTargetSubscriber` yields **raw** `tuidriver.Event`s (the modal-dropping mapper lives downstream in `Producer.drain`, which the modal stream does not use). So the modal stream **reuses `resolveTarget` and `NewTargetSubscriber` verbatim** and adds only a bespoke, mapper-free drain loop.

This opens a *second* `Session.Events()` subscription on the same bound `*tuidriver.Session`. tui-driver blesses this explicitly (`events.go:159-161`): each `Events()` call spawns an independent merge goroutine over its own JSONL tail and output channel, reading the concurrent-safe `buffer.Snapshot`. Cost is one extra 50 ms poll loop + one extra JSONL tail per session — negligible. The two subscriptions never share mutable state, so the modal stream cannot perturb the turn stream.

The modal drain ignores every non-modal event (JSONL entries, idle/thinking, banners, stall); it acts only on `EventKindPtyModalShown` / `EventKindPtyModalHidden`. The wasted JSONL tail bytes are never inspected — the confidentiality-safe by-id resolver still selects the correct per-conversation file, so no foreign transcript is opened.

### The `ScreenSnapshot` seam — type-assert, do **not** widen `turnbridge.SessionHost`

`boundHost` returns a `turnbridge.SessionHost` (`Session()`/`WaitForPTY()` only), but the paired screen text (AC3) must come from the same bound supervisor, whose concrete type `*supervisor.Supervisor` also carries `ScreenSnapshot`. Two options were considered:

1. **Widen `turnbridge.SessionHost`** to add `ScreenSnapshot`. Rejected: `SessionHost` is a shared turnbridge interface the turn stream also drives; widening it forces a screen method onto a package that has no business with rendered screens, and touches a cross-package contract for a `cmd/pyry`-local need.
2. **Type-assert (chosen).** Define a consumer-side interface in `package main`:
   ```go
   // screenSnapshotter is the bound host's rendered-screen seam. *supervisor.Supervisor
   // satisfies it (supervisor.go:446); asserted from turnbridge.SessionHost so the
   // shared turnbridge interface stays screen-free.
   type screenSnapshotter interface{ ScreenSnapshot() (text string, live bool) }
   ```
   The host `boundHost` returns is concretely `*supervisor.Supervisor` (`main.go:774,778`), so the assertion succeeds in production and stays testable with a fake.

This keeps the blast radius inside `cmd/pyry`: no turnbridge edit, no turn-stream disturbance.

### The screen resolver — `boundScreenText`

A closure that mirrors `resolveTarget`'s host-selection branch and yields the current active bound host's screen text (contract sketch — signature + behavior, not the body):

```go
func boundScreenText(active *activeConversation, boundHost boundHostFunc, bootstrap screenSnapshotter) func() string
```

- `convID == ""` (no route yet) → `bootstrap.ScreenSnapshot()` — the pre-route path, mirroring `resolveTarget`'s bootstrap branch (AC4 consistency). `bootstrap` is the same `sup` (`*supervisor.Supervisor`) the turn stream takes.
- `convID != ""` and `boundHost(convID)` ok → type-assert the returned `SessionHost` to `screenSnapshotter`, return its `ScreenSnapshot()` text.
- `boundHost` miss, or host does not satisfy `screenSnapshotter` (defensive) → `""`. An empty screen is safe: the emitter surfaces a modal with an empty Title; the security-critical fields are unaffected.

Only `text` is used (the `live` bool is ignored — an empty text is the natural degrade). **Never logs the returned text.**

**AC3 "never a stale bootstrap host":** `active` never resets to `""` once a route lands (`CurrentConversation` only advances to non-empty ids, `main.go:1073`), so a modal raised on a bound session (`convID != ""`) always resolves that bound host's screen, never the bootstrap. The bootstrap branch is reachable only in the genuine no-route-yet state, exactly as `resolveTarget` intends.

### The drain loop — `runModalStream` (single goroutine)

The bespoke outer-resubscribe + inner-drain loop, mirroring `Producer.Run`/`drain` (contract sketch):

```go
func runModalStream(ctx context.Context, sub turnbridge.Subscriber, screenText func() string, emitter *interactiveModalEmitterV2, logger *slog.Logger)
```

- Outer loop: `ch, err := sub(ctx)`; on `err` (only ctx cancel per the `Subscriber` contract) return; else drain `ch`; on `ctx.Err()` return; else re-subscribe (session restart re-keys onto the now-active target — follow-active).
- Inner drain: `select` on `<-ctx.Done()` (return) and `ev, ok := <-ch` (`!ok` ⇒ break to re-subscribe). Per event:
  - `EventKindPtyModalShown` → `emitter.Handle(ctx, ev, screenText())` — evaluate the screen **only here**, so no `ScreenSnapshot` render happens on the 50 ms idle/thinking/JSONL ticks.
  - `EventKindPtyModalHidden` → `emitter.Handle(ctx, ev, "")` — screen unused on the hidden path (the body is already gone; `interactive_modal_v2.go:85`).
  - every other kind → ignored.

**Single-Run-goroutine invariant (AC2):** `Handle` is invoked only from this one goroutine, so the emitter's unguarded counters (`nextID`, `outstandingID`, `outstandingClass`) never race — the exact invariant the emitter's doc names (`interactive_modal_v2.go:22-26`). The one field a second goroutine touches is `reg` (`modalReg`, shared with the inbound resolver at `relay.go:337`), which carries its own mutex — the #717/#706 design, unchanged.

### Construction, gating, cleanup — `startInteractiveModalStreamV2`

Contract sketch (mirrors `startInteractiveTurnStreamV2`'s signature shape; all args are already in `startRelayV2`'s scope):

```go
func startInteractiveModalStreamV2(
    ctx context.Context,
    sup *supervisor.Supervisor,
    active *activeConversation,
    boundHost boundHostFunc,
    mgr *relay.V2SessionManager,
    modalReg *modalbridge.Registry,
    claudeSessionsDir string,

```

Body: `emitter := newInteractiveModalEmitterV2(modalReg, mgr, mgr, logger)` (`mgr` is both the `interactiveBroadcaster` — `ActiveConns`/`Push`, already the turn emitter's broadcaster — and the `modalTimeoutArmer` — `ArmModalTimeout`, `v2session.go:884`). Build `resolve := resolveTarget(active, boundHost, sup, claudeSessionsDir)`, `tr := tuidriver.NewTracker(tuidriver.TrackerOpts{})`, `sub := turnbridge.NewTargetSubscriber(resolve, tr, logger)`, `screenText := boundScreenText(active, boundHost, sup)`. Spawn one goroutine running `runModalStream(...)` that closes a `done` channel on exit; return `func(){ <-done }`.

### Relay wiring (`relay.go`)

Co-locate inside the existing shared gate at `relay.go:368`. Extend the current `if bridge != nil && claudeSessionsDir != ""` block to capture a second cleanup, and join it in the cleanup closure (`relay.go:407`) alongside `streamCleanup`. No new parameter reaches `startRelayV2` — `modalReg`, `sup`, `active`, `boundHost`, `mgr`, `claudeSessionsDir`, `logger` are all already local. The shared disabled-info log is reused (one gate, both streams).

### Data flow

```
claude permission/trust prompt appears on bound host A
  → tuidriver merge loop (modal subscription) emits EventKindPtyModalShown{class}
  → runModalStream drain (single goroutine) receives it
  → screenText() = A.ScreenSnapshot()   (rendered, ANSI/OSC-free, inside the seal)
  → emitter.Handle(ctx, ev, screenText)
      → PermissionRequestForClass(class, screenText)  (Title = trimmed screen)
      → modalReg.Record → mints modal_id nonce
      → mgr.ArmModalTimeout(ctx, modalID)             (fail-closed deny window, #725)
      → broadcast modal_shown to every interactive conn (#607 gate)

operator answers at the local attach TTY → claude modal vanishes
  → EventKindPtyModalHidden{class}
  → emitter.Handle → modalReg.Resolve(id) → if this head wins: audit + broadcast modal_dismissed{local} (#706)
```

## Concurrency model

- **One new goroutine** (`runModalStream`), spawned by `startInteractiveModalStreamV2`, owned by the relay lifecycle `ctx`. It is the sole caller of `emitter.Handle` (single-Run-goroutine invariant).
- **Two independent tui-driver subscriptions** per session (turn + modal), blessed by `events.go:159-161`. Each owns its own merge goroutine + JSONL tail + per-subscription ctx cancelled by session end / conversation switch / parent cancel — all internal to the reused `NewTargetSubscriber`.
- `ArmModalTimeout` schedules a `time.AfterFunc` against the relay ctx (owned by `V2SessionManager`, unchanged).
- **Shutdown:** ctx cancel → `sub(ctx)` returns `ctx.Err()` (or the drain's `<-ctx.Done()` fires) → `runModalStream` returns → `done` closes → cleanup's `<-done` unblocks. Cleanup is joined before `<-mgrDone` so no fan-out races a winding-down manager (mirrors the turn stream at `relay.go:401-412`).

## Error handling

- `sub(ctx)` errors only on ctx cancel (its contract) → clean return.
- Transient resolve/JSONL/Events errors are retried **inside** `NewTargetSubscriber` (backoff) — no new handling here.
- `boundHost` miss or failed type-assert → `boundScreenText` returns `""` → emitter surfaces an empty-Title modal (never a crash, never a foreign screen). Security-critical fields unaffected.
- Emitter-internal failures (RNG mint failure, marshal failure, zero interactive conns) are already handled inside the frozen emitter (drop + content-free log; deny-on-timeout still armed). Not re-handled here.
- The wiring adds **no reject branches** and **no new error types**.

## Testing strategy

New file `cmd/pyry/interactive_modal_stream_v2_test.go`. Reuse `scriptedSubscriber`, `fakeInteractiveBcast`, `fakeArmer`, `discardLogger`, `waitClosed`, `lockedWriter`. `runModalStream` and `boundScreenText` are factored out precisely so the drain can be driven by a `scriptedSubscriber` and a fake screen func, without a live supervisor/JSONL. Scenarios (bullet form — developer writes the bodies in-idiom):

- **Shown reaches emitter with bound screen (AC5 surface).** Scripted sub yields one `EventKindPtyModalShown{Permission}`; `screenText` returns a known body. Assert: broadcaster received a `modal_shown` push whose payload Title is the trimmed body; `fakeArmer` recorded exactly one `ArmModalTimeout`.
- **Local dismissal (AC5).** Shown then `EventKindPtyModalHidden{same class}`. Assert: one `modal_dismissed` push with `source=local`, `outcome=dismissed_local`.
- **Non-modal events cause no screen render / no push (AC2 efficiency + no-op).** Feed idle/thinking/JSONL events; a spying `screenText` func asserts it was **never called**; broadcaster received nothing.
- **`boundScreenText` host selection (AC3).** Table: (a) `active` set to a routed conv + `boundHost` returns a fake host implementing `screenSnapshotter` → that host's text; (b) `active` empty → bootstrap's text; (c) `boundHost` miss → `""`; (d) host not a `screenSnapshotter` → `""`.
- **Teardown unblocks (AC4).** A never-yielding `scriptedSubscriber`; spawn `runModalStream`; cancel ctx; assert the `<-done` cleanup returns within a deadline (mirror `TestInteractiveTurnStream_TeardownUnblocks`).
- **No screen-text log leak (AC5 content-free).** Feed a Shown carrying a secret screen body with `pushErr` set so the emitter's push-drop DEBUG branch fires for every conn (the most log-heavy path); assert the secret substring never appears in captured logs (mirror `TestInteractiveTurnStream_NoAppOutputLogLeak`). This guards the wiring — the first production code to handle rendered `ScreenSnapshot` bytes — against a new content-echoing log.

The loop's correctness (nonce anti-replay, deny-on-timeout, first-answer-wins) stays proven by #716/#717/#725/#706 and is **not** re-proven here.

## Security review (label `security-sensitive`, mandatory)

`agents/architect/security-review.md` is not present in this worktree (confirmed absent; same as specs #487, #670). Performing the review inline over the standard adversarial categories: **trust boundaries, input validation, output redaction, secret hygiene, denial-of-service, escalation paths.** Verdict at end.

**Trust boundaries.**
- The rendered screen crosses one boundary: the bound `*supervisor.Supervisor` (inside the tui-driver seal) → the emitter → interactive phones. `ScreenSnapshot` renders inside the seal (`supervisor.go:440-445`, `cmd/substrate-guard` green) and returns opaque text; this wiring forwards it without inspecting or storing it. No new seal breach.
- Cross-conversation confidentiality: the event stream reuses the #679/#686 by-id resolver, so a modal event is never read from a foreign conversation's transcript. The **screen** is re-resolved from the current active bound host. In the steady state (no concurrent switch) event and screen come from the same host. A narrow window exists where an in-flight `EventKindPtyModalShown` is paired with a just-switched host's screen — but the mobile modal surface is **operator-global, not conversation-scoped**: `ModalShownPayload` carries no `conversation_id` and `broadcastInteractive` fans to every interactive conn regardless of which conversation it is viewing (`interactive_modal_v2.go:222-246`). All conns are authenticated to the same operator (Noise_IK pairing). So the worst case is one operator momentarily seeing their own other conversation's screen text in a Title — within a single trust domain, not a cross-operator or cross-tenant leak. Documented as an accepted, benign race (Open questions).
- The wiring adds no new inbound surface: it only consumes an internal event stream and calls existing, already-authorized broadcast/arm methods.

**Input validation.**
- The screen text is untrusted claude-rendered content, consumed only as `strings.TrimSpace(screenText)` → `PermissionRequest.Title`, a display string that is JSON-marshaled by the emitter (`encoding/json` escapes it safely). No parsing, no path/command construction from it — no injection surface.
- The by-id JSONL resolver already validates the session-id stem against `jsonlStemPattern` before any `filepath.Join` (`interactive_turn_stream_v2.go:340`), reused unchanged — no path traversal.
- The type assertion `host.(screenSnapshotter)` is guarded (comma-ok); a non-satisfying host degrades to `""`, never a panic.

**Output redaction.**
- The emitter already guarantees no modal body / prompt / screen text is logged at any level (`interactive_modal_v2.go:28-31`, unit-covered). This wiring is the **first production code to handle the rendered `ScreenSnapshot` bytes**; it MUST NOT introduce a log that echoes them. Enforced by design (the drain loop and `boundScreenText` log nothing containing screen text) and by the mandated `No screen-text log leak` test above. Content-free discriminants only (event, class, conn_id, env_id) remain, inherited from the emitter.
- The reused subscriber logs only the JSONL path (a UUID under the trusted dir), offset, and a derived bool — never JSONL bytes (`producer.go:305-313`), unchanged.

**Secret hygiene.**
- No keys, tokens, or credentials flow through this path. `StaticPriv` and device secrets are untouched (owned by `V2SessionManager`, not reached here).

**Denial-of-service.**
- The second `Events()` subscription adds one 50 ms poll loop + one JSONL tail per session — bounded, blessed by tui-driver, and symmetric with the already-shipped turn stream. No unbounded growth: the emitter mints one registry entry per surfaced modal and the entry is consumed on Resolve / timeout (#717/#725), unchanged.
- This wiring **restores** a fail-closed control: without it, `ArmModalTimeout` never arms in production, so a surfaced-but-unanswered permission modal would block claude indefinitely. After wiring, every surfaced modal is safe-denied on the #725 window even if it reaches zero phones. Net-positive availability.
- Cleanup blocks until the goroutine exits (bounded by ctx cancel), so no leaked goroutine across relay shutdown.

**Escalation paths.**
- No privilege change: the goroutine runs as the daemon, calls only already-authorized `mgr` methods, and routes no keystrokes itself (local dismissal actuation lives in the frozen emitter's Resolve path / inbound resolver, unchanged).
- The wiring cannot grant a permission: `modal_shown` is a notification; the only allow keystroke is minted by the gated inbound `modal_answer` resolver (#717), which this ticket does not touch. Deny-on-timeout remains the default outcome. No new path to an allow.

**Verdict: PASS.** Net-positive for security: it activates the fail-closed deny-on-timeout that is dormant in production today, forwards only sealed, redaction-proven screen text, and adds no inbound surface, no new secret exposure, and no new escalation path. The single residual race (a within-operator, screen-only, cosmetic Title mismatch during a conversation switch) is bounded to one trust domain and touches no security-critical field; it is documented, not silently accepted.

## Open questions / out of scope

- **Switch-race atomicity (accepted).** The screen is re-resolved at handle time, not captured atomically with the event, because reusing `NewTargetSubscriber` (the S-sized path the PO confirmed available) hides the per-subscription host. The deterministic alternative — a bespoke subscriber yielding `(host, ch)` pairs — would re-implement the ~120-line follow-active WaitForPTY/switch/retry loop and blow the S ceiling. The residual mismatch is within-operator and cosmetic (see Security review → Trust boundaries). If a future ticket needs byte-exact screen/event pairing, widen the subscriber to surface the captured host; deferred until evidence demands it.
- **ACP proxy wiring** (`acpPermissionProxy`, `acp_permission.go`) is a separate unwired consumer of the same raw modal stream — #751 territory, explicitly out of scope.
- **Emitter is frozen.** If the wiring reveals a real gap in `interactiveModalEmitterV2`, route back rather than editing it here (per ticket Technical Notes).
