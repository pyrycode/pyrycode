## Context

Native suggestions are generated by claude after `result` when spawned with `--prompt-suggestions`. #2829 parses them, #2830 reconciles them on connect; nothing produces or emits state. This slice adds the producer. No decision record needed.

## Design

**Spawn flag.** `buildArgs(base, create, sessionID, promptSuggestions bool)` appends `--prompt-suggestions` after `--replay-user-messages` when true. `beginSpawn` computes it as `!promptSuggestionsDisabled(append(os.Environ(), env...))`, where the helper reads the last `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=` entry and returns true only for `false`.

**State owner** — new `cmd/pyry/reply_suggestion.go`, type `replySuggestions`, one per daemon, built in `startRelayV2` only when a stream sink exists. One leaf `sync.Mutex` over `map[convID]*replySuggestionConv`:

- published state: `revision uint64`, `published bool`, `text *string`, `sessionID string`
- eligibility: `delivered` (non-empty delivered user text since the last TurnEnd), `assistant` (main-agent text in the current turn), `invalidated` (since current turn start), `eligible` (last TurnEnd qualified and nothing since invalidated it).

Methods (all nil-safe, none pushes under the lock):

- `noteDelivered(convID, text)` — msgqueue OnDelivered path.
- `turnStarted(convID)` — emitter, when `startTurnIfNeeded` opens a turn: reset the turn flags, then clear.
- `noteAssistantText(convID)` — emitter TextChunk with `ParentToolCallID == ""` and non-empty text.
- `turnEnded(convID, success)` — emitter TurnEnd arm; `eligible = success && delivered && assistant && !invalidated`; consumes `delivered`.
- `suggest(convID, text)` — emitter `PromptSuggestion` arm; only when eligible: consume eligibility, store text with the conversation's current session id, revision++, mark dirty. Otherwise nothing.
- `invalidate(convID)` — accepted send, send-now, `/clear`, reset/eviction transition, exit/teardown close. Existing entries only: `invalidated = true`, `eligible = false`; if text is held, set it nil, revision++, mark dirty.
- `current()` — the `ReplySuggestions` seam: one payload per published conversation that still exists (via `sessionFor`), sorted by conversation id; deleted conversations are pruned there.
- `Run(ctx)` — publisher goroutine. Woken through a 1-buffered channel, takes the dirty set, snapshots each conversation's *current* payload under the lock, then pushes to every interactive conn from `ActiveConns`. Coalescing to current state means a wake can never lose a clear, and the relay's per-conn revision guard drops anything overtaken.

The broadcast leaves `EventID` nil: suggestion state is control state, never ring or history. Session id comes from `sessionFor(convID) (string, bool)` over the registry's `CurrentSessionID`.

**Wiring.** The OnDelivered hook is fixed in `main.go` before the relay leg, so `main.go` mints the owner (stream path only) and hands it on `relayWiring.suggestions`; `deliveredFuncs` gains `suggestions.noteDelivered`. `startRelayV2` sets its broadcaster and resolver, starts `Run`, assigns `emitter.suggestions`, wires `ReplySuggestions: suggestions.current` (nil seam without a sink), wraps the `SendMessage` enqueuer and resetter and `QueueSender` in small adapters that invalidate on acceptance only (`EnqueueSent != 0`, `SendNow == true`, `/clear` reaching `StartNewSession`), and wraps `w.transitions` so the composed observer also invalidates the transition's conversation. `sessions.Runner` is untouched.

## Concurrency model

Writers: drain goroutine (emitter hooks), relay handler goroutines (accept adapters), msgqueue drain (noteDelivered), pool transition observer. Reader: relay Run (`current`). All go through the one leaf mutex; the only push happens on the owner's own `Run` goroutine with no lock held, so no path round-trips through relay Run while holding anything. `Run` exits on ctx cancel; the wake channel is never closed.

## Error handling

Push errors are logged at Debug with conn id and conversation id only. Marshal cannot fail (strings, uint64, *string); defensive Debug without payload. Suggestion text is never logged anywhere.

## Testing strategy

- `runner_test.go`: existing argv tables gain the flag; a table for `promptSuggestionsDisabled` (unset, `true`, `false`, last entry wins).
- `reply_suggestion_test.go`: the eligibility table (success/fail outcome, error flag, non-end_turn reason, missing user text, missing main text, subagent-only text, invalidated mid-turn), set and clear revisions, clear after each trigger with `current()` returning null, delete pruning, other conversation untouched, `Run` fans out to interactive conns only.
- Fake-daemon e2e (`internal/e2e/relay_v2_stream_reply_suggestion_test.go`): replay fragment with assistant text, `result` success and a `prompt_suggestion` line; two interactive phones both see the set; a second send from phone A clears on both; phone C connecting afterwards receives null; a second conversation's state stays absent.
- Live (`internal/e2e/realclaude/interactive_stream_reply_suggestion_test.go`): drive turns until a non-null `reply_suggestion` arrives (fail, not skip, if none within the turn budget), send again, observe null.
