## Design

Add a private bound stopper in cmd/pyry implementing `StopBackgroundTask(ctx, conversationID, taskID) BackgroundTaskStopOutcome`. Validate `conversations.ValidID` before lookup; use one registry snapshot and its nonempty session binding for `Pool.Lookup` and `Pool.HarnessFor`. Unresolvable conversations return cannot-act; never consult the cursor. Resolved non-Claude sessions, missing/live-less capabilities and unreported/empty/nonmatching rosters refuse locally. Assert a narrow combined roster/stop capability on that same runner, keeping StopTask off sessions.Runner. Refuse matched rows marked task_id truncated, without rejecting an unmarked ID merely for its length.

For an eligible row, call StopTask exactly once with its retained ID and a child context capped at 30 seconds. Only true with an uncancelled context accepts. streamRunner forwards to its nonnil streamsup runner. Thread the stopper from main through relayWiring into V2SessionConfig; retain the handler's interactive gate and reply rules.

Fakeclaude tracks the current roster it emitted. A matching stop_task gets empty success then task_notification status stopped and roster removal; an unknown ID gets an error response. No user turn, interrupt or restart is generated by stopping. Fake completion vocabulary is provisional until the dispatcher observes the live signal.

## Concurrency model

No production goroutine is added. Existing relay workers supply cancellation; registry, pool and retention locks are acquired separately, never held across StopTask. A concurrent rebind does not switch runners midway. The primitive owns child-generation safety. Live FIFO cleanup uses the existing bounded release helper and only releases after completion or teardown.

## Error handling

All child false results, cancellation and deadlines refuse with the existing static error. Unknown/unbound conversations remain silent. No task ID, reflected conversation ID or child diagnostic is logged. Normal outcomes preserve the conversation and running reply; retain the primitive's blocked-write cancellation exception.

**Findings:**

- [Trust boundaries] Named canonical ID validation and one stored binding prevent cursor/bootstrap fallback. Truncated row IDs are ineligible; child-authored strings remain opaque JSON values.
- [Tokens/secrets] No credentials are created, read or persisted; the existing paired encrypted interactive transport supplies authorization.
- [Files] Production adds no file I/O. Test paths are rig-owned temporary files; FIFO uses existing bounded cleanup.
- [Subprocesses] StopTask writes a typed control envelope to the resolved existing child; no shell interpretation or spawn changes.
- [Cryptography] Existing Noise session framing is reused; no new crypto or nonce handling.
- [Network/I/O] Existing bounded relay decode remains; WithTimeout bounds a silent-child wait and inherits parent cancellation.
- [Errors/logs] Static requester-only refusal contains no task or child diagnostic. Adapter has no logger or error-text return.
- [Concurrency] One binding snapshot and same runner capability avoid cross-session races; separate leaf locks and existing captured-generation checks protect child replacement.
