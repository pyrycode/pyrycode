# Connect-time model-list reconcile (#1863) — `RetainedModelLists` seam + `reconcileModelLists`

`security-sensitive` — the third Mode B instance of the reconcile-on-connect mechanism (umbrella #829), a structural twin of [modal](#connect-time-modal-reconcile-877--outstandingmodals-seam--reconcilemodals) and [queue](#connect-time-queue-reconcile-878--outstandingqueues-seam--reconcilequeues) reconcile above. `ModelListPayload` otherwise reaches a live conn only on the interactive-turn lane (`interactiveTurnEmitterV2`), which has three independent loss points in front of it — an empty-conversation early return that is unconditional on the bootstrap child (the conversation cursor is only ever set by a successful route, while the `initialize` ask fires at child spawn), a droppable classification that can be shed under load, and `forwardEnvelope`'s `last_event_id` dedup, which is a *reconnect* mechanism with no fresh-connect backfill. **On a freshly-minted conversation's own child, that first loss point is a genuine race, not a deterministic drop** (found while building #1868's e2e diagnostic): `(*interactiveTurnEmitterV2).Handle`'s cursor read and the `initialize` ack's parse-and-forward both run on the child's own streamsup Run goroutine, but the cursor is stamped by `sessionRouter.Route`'s `active.set` on the separate routing goroutine servicing the mint's own `send_message` — no lock or channel orders the two, so whether the live lane also delivers the list to the very conn that minted the conversation is a coin flip, observed as 0 or 1 across otherwise-identical runs. This is additional reason the connect-time reconcile below exists as a snapshot rather than relying on lane timing — the live lane's delivery to *any* recently-active conn, not just a later-connecting one, is opportunistic. A client attaching later — and every client on the bootstrap session — therefore had no path to the list at all. `docs/protocol-mobile.md` § Reconnect / Backfill semantics binds the transport by **data class**, not by how long the client was away: control state is always a cheap current-state snapshot on connect (Mode B), and `ModelListPayload`'s own doc calls the frame exactly that — "a SNAPSHOT of what claude will accept, not a delta … receiving one neither opens nor closes a turn."

**`RetainedModelLists func() []protocol.ModelListPayload`** is the third optional `V2SessionConfig` seam in the family (nil ⇒ no reconcile, byte-identical to pre-#1863). Production wires a non-nil closure as of #1867: `cmd/pyry/session_model_list.go`'s `retainedModelLists(convReg, pool)`, built at the composition root in `main.go` and assigned straight through the `relayWiring` struct (§ below). Same closure-not-concrete-import idiom as `OutstandingModals`/`OutstandingQueues`: `internal/relay` imports neither `internal/turnevent` nor `internal/sessions` directly (`internal/sessions` reaches it only transitively, via `internal/control` — a `go list -deps` reading that looks contradictory and isn't), while `internal/protocol` is already a direct import, so the payload crosses with no new import and no cycle. **Enumerate-all, not conversation-keyed** — `V2Session` carries no conversation id, so there is no "this conn's conversation" to join on at connect time; `OutstandingQueues`' one-per-conversation shape is the precedent, and `RunConfigFor` (conversation-keyed) is the wrong shape here. The enumerator (`retainedModelLists`) walks `conversations.Registry.List()` unfiltered — including archived rows, since `Registry.SetArchived` writes one field without unbinding `CurrentSessionID` — and appends only the payloads `resolveBoundModelList` (#1857) answers `true` for; the comma-ok is its only filter, and every refusal (unbound conversation, session no longer in the pool, a runner that does not implement `ModelList`) stays decided inside the resolver rather than re-spelled at the enumerator. **The bound is the producer's**: this path applies no cap of its own to either the number of payloads or any entry's text — it relies entirely on the construction-time bounds upstream (`DroppedModels` on the aggregate, `TruncatedFields` per entry, frozen by #1704/#1705), and the seam's doc comment says so explicitly.

**`reconcileModelLists(ctx, s)`** is `reconcileQueues`'s structural twin, `protocol.TypeModelList`/`ModelListPayload` substituted, keyed by `conversation_id`:

- **Guard:** `if !s.interactive || m.cfg.RetainedModelLists == nil { return }` — identical shape to the other two. This is the one guard in the family with a sole-red mutant reachable by a *single-conn* test: dropping `!s.interactive` only reddens if a second, genuinely-interactive conn is opened after the non-interactive one under test — without that control conn, "zero frames" is indistinguishable from an empty seam and the mutant survives green. The other family members' non-interactive rows carry the same shape for the same reason.
- **Snapshot once**, empty ⇒ nothing sent. This half of the guard has **no** sole-red mutant: with a zero-length slice the loop body never executes, so deleting the `len(retained) == 0` check is an equivalent mutant, not an untested branch. The "zero payloads" test row is pinning the *contract* (a real producer returning `nil` must not error), not a reachable code path — worth knowing before it reads as coverage that was skipped.
- **Per payload:** marshal, then `m.Push(ctx, s.connID, protocol.Envelope{ID: 1, Type: TypeModelList, TS: ts, Payload: payload, EventID: nil})` — `ID: 1` non-load-bearing (the phone correlates on `conversation_id`); `EventID` left nil for the same double reason the twins have: it keeps the frame out of the #647/#777 turn-event replay ring, *and* it makes `forwardEnvelope`'s `last_event_id` dedup inert for this frame — the third loss point named above cannot re-drop what this path sends. A marshal failure logs only content-free discriminants (`event`, `conn_id`, `conversation_id` — **never** `err`, since `encoding/json` quotes input bytes and a `ModelOption` carries the exact fields #833 exists to keep out of logs) and continues to the next payload; a `Push` failure may log `err` (safe only because `Push`'s error is `ctx.Err()` or `ErrConnNotFound` and nothing else); `ctx.Err() != nil` returns early.

**No test can redden the defensive marshal branch, and none was written.** `ModelListPayload` is `string` + `[]ModelOption` + `int`, `ModelOption` is three strings / two `[]string` / one bool, and both custom `MarshalJSON`s delegate to `json.Marshal` over closed types — no value can fail to marshal. Neither `reconcileModals` nor `reconcileQueues` has a marshal test either, for the identical reason; the branch is defensive dead-in-practice code kept for the same reason the twins keep theirs, and the test file says so in its header rather than leaving the gap to read as an oversight.

**Call site:** one line in `handleNoiseInit`'s success tail, third — after `m.reconcileModals(ctx, s)` and `m.reconcileQueues(ctx, s)`, still before the [#647 replay hook](#reconnect-replay-647--hellolast_event_id--ring-replay--resync). Ordering among the three reconciles is immaterial (distinct payload types, all land in `m.queues`); third only documents intent (permission prompt, then backlog, then model list). `staticcheck`'s default U1000 forbids shipping the seam + `reconcileModelLists` without this call site — an uncalled unexported method fails `make check`, which is why this and #1864's producer wiring could not be split further than they already were (from #1858, prerequisite-split once already).

**Pure read, no turn opened.** `RetainedModelLists` mints nothing and retires nothing, so re-connecting re-sends the same snapshot idempotently. Nothing on this path touches turn state — the frame goes straight onto the push queue via `Push`, never through the interactive-turn lane, and `TypeModelList` is not a turn-boundary type by the same #1704/#1705 freeze the live-lane frame obeys.

**Security review verdict: PASS** (`docs/specs/architecture/1863-model-list-connect-reconcile.md` § Security review has the full pass). Same two gates as the other two Mode B instances — authentication (post-handshake, post-token-validation only) and capability (`!s.interactive`) — plus the resource-bound discharge above. No new goroutine, no new lock; `s.interactive`/`s.connID` are read lock-free under the Run-goroutine single-owner invariant, the caller's guarantee, restated (not merely implied) in the function's own doc comment per the modal/queue precedent.

Tests: `internal/relay/v2session_modelreconcile_test.go` (new; **table-driven, not one-function-per-arm** — the house idiom this package already uses in `v2session_dequeue_test.go`/`v2session_interrupt_test.go`/`v2session_modal_test.go`, and a deliberate divergence from #878's file layout for the same coverage in materially fewer lines) — one/two retained lists delivered and `reflect.DeepEqual`'d against the seam's own payloads including `DroppedModels`/`TruncatedFields` survival; unicast-only (opening conn B does not cause a second delivery to already-open conn A); the three AC2 no-frame arms (nil seam, zero-payload seam, non-interactive conn — the last needs a second interactive conn opened afterward, per the guard note above); content-free logging asserted via three distinct sentinel literals (`Value`, `ResolvedModel`, `DisplayName`) rather than one, since the three are separate struct fields a partial leak could miss. `ModelListPayload` has no `time.Time` field, so it is safely `reflect.DeepEqual`-able and neither `#878`'s `equalQueued` comparator nor its `sampleQueueTS` has a counterpart here.

**The daemon-side producer (#1867):** `retainedModelLists(convReg, pool)` (`cmd/pyry/session_model_list.go`), tested in `cmd/pyry/session_model_list_test.go` against the existing `resolveBoundModelList` (#1857) fixtures — no new fixture type. Two properties of a skip-and-continue enumerator turned out to need a specific fixture *order*, not just fixture *presence*, to be reachable by mutation:

- **A `break`-instead-of-`continue` mutant needs the contributing row LAST.** `Registry.List` returns insertion order, and the enumerator loop's only lever a test has over which mutants are reachable is that create order. A refusal test that creates the one contributing conversation *before* the refusing ones leaves that mutant green — the loop has already appended the survivor by the time it hits a refusal and stops early, so "one payload came back" holds either way. Creating the contributor last makes the same mutant sole-red.
- **"Archived rows contribute" has exactly one home.** Every other fixture in the file builds unarchived rows, so a `List(ListFilter{IsArchived: &f})` narrowing that would silently exclude archived conversations is invisible to all of them — only the one test that arms an archived, list-bound row can catch it. Confirmed sole-red by overlay mutation. Worth stating explicitly because the property reads like an incidental choice in the diff otherwise — nothing at the call site says `List()` was chosen over a filter on purpose.

`retainedModelLists` is `resolveBoundModelList`'s first production caller — the resolver shipped in #1857 with none, reachable only from its own tests. #1868 is the cross-process e2e capstone, the same split `OutstandingModals`/`OutstandingQueues` used for #903/#904; see [e2e-harness.md](e2e-harness.md) for the test's own design (including the live-lane race noted above, which its mutation run surfaced).
