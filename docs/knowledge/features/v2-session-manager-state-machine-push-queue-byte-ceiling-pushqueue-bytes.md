# Push-queue byte ceiling (#1505) — `pushQueue.bytes` + `pushQueueByteCeiling` + `handlePushOverflow`

The soft-overflow branch above (`at cap, all control | control | admit past nominal cap`) had **no ceiling of any kind** — only `pushQueueCap` (256) bounds the other three drop-policy branches. Reachable two ways: [the #874 transport-down hold](#transport-down-hold-on-the-push-drain-874--connected-probe--transportdown) parks `drainOnce` at its first statement while the #632 interactive emitter keeps pushing `tool_result`/`tool_use`/`turn_state`/`turn_end` — all control-class, all never-droppable — so a multi-minute outage mid-turn grows the queue to thousands of envelopes, freed only when the 15-minute idle sweep (`idleTimeout`, [§ Idle-session teardown](#idle-session-teardown-774--per-session-idle-timer--in-repo-sweep)) fires; and one oversized [debug bundle](#debug-bundle-streaming-812--streambundle--bundleenvelopes--reassemblebundle), since `debugbundle.Assemble` caps nothing and `StreamBundle` turns a large `.cast` archive into `ceil(len/bundleChunkBytes)` never-droppable control envelopes in a single handler call. The old soft-overflow comment credited #911's per-conn in-flight gate for bounding this; #911 only rejects a *repeat* `request_debug_bundle` while one is already queued — it says nothing about the #874 case, where there is no request to reject.

**`pushQueue` gains two fields.** `bytes int` is the retained-payload total, `Σ len(item.env.Payload)` over `items` — the fixed per-envelope fields (`Type`/`ID`/`TS`/`EventID`) and the `queuedEnv` slot itself are deliberately not charged, since they're O(10²) B against a payload spanning ~100 B–64 KB and charging them would turn a byte ceiling back into a partial count cap. `overflowed bool` is a one-way latch set when the ceiling rejects an envelope — **never cleared** (see below). Both fields are maintained only inside `pushQueue` methods: `enqueue`'s three append sites and one evict site, plus a new `popHead()` that `drainOnce` now calls instead of hand-rolling the pop, so the counter can't drift from a caller outside the type.

**`pushQueueByteCeiling = 32 << 20` (32 MiB)**, checked in exactly one place — the soft-overflow branch. The other two drop-policy branches leave `len(items) <= pushQueueCap`, whose retained bytes can never reach the ceiling: `256 × 65519 B ≈ 16 MiB` (the v2 application-envelope cap, `docs/protocol-mobile.md` § Application-envelope size cap), and 32 MiB is ~2× that. This buys two things — the ceiling can *never* trip on a queue within the nominal count cap (so "behaviour below the ceiling is unchanged" is structural, not empirical, and survives a future bump of `pushQueueCap` or the envelope cap), and it sits ~4× above the single-digit-MB a realistic multi-minute outage accumulates, so no realistic outage trips it. The bound is `>`, not `>=`: an envelope landing exactly on the ceiling is admitted. A legitimate bundle **can** still trip it — an archive past roughly 25 MB ends the conn instead of riding the old unbounded soft overflow — a chosen, tested outcome (see Tests below), not an accident; if it bites in practice, the fix belongs in `debugbundle.Assemble` (cap the `.cast` member), not here.

**Off-Run → Run signal mirrors `modalTimeout`, not `armIdleTimer`.** `enqueue` runs off the Run goroutine under `pushMu`; only `Run` may call `closeWith`. `V2SessionManager` gains `pushOverflow chan string`, constructed exactly like `modalTimeout` (`make(chan string, wakeBufferSize)`), with one new `Run` select arm. Inside `Push`'s existing `pushMu` hold it captures the *level* (`overflowed`) and the *edge* (`justTripped := overflowed && !before`); after unlocking it sends `connID` on `pushOverflow` **non-blocking** (`select`+`default`, the `drainCh` idiom) if latched, logs one `Warn` (`v2.push.ceiling`) only on the edge, and — unchanged — still returns `nil` promptly. Non-blocking is the deliberate divergence from `armIdleTimer`'s blocking send: that callback blocks a throwaway `time.AfterFunc` goroutine, but `Push` runs on the *producer's* goroutine, where blocking would break the very never-blocks-the-producer contract this queue exists to uphold. Level-triggered compensates: the latch is never cleared, so a full `pushOverflow` buffer dropping one send is simply re-driven by the next `Push` — an operator still sees exactly one `Warn`, because the log is edge-triggered.

**`handlePushOverflow(ctx, connID)`** runs only on the Run goroutine (reached from `Run`'s new select arm), so its `m.sessions` read and `closeWith` call sit under the package's single-owner invariant — the same shape as `handleWake`'s `wakeIdleTimeout` arm. No-op if the session is already gone (its queue went with it) or has left `V2StateOpen`. Otherwise: one `Warn` (`v2.push.ceiling.teardown`), then `closeWith(ctx, s, StatusQueueOverflow, nil)` — **nil frame, deliberately**. The trip condition is typically a parked drain, i.e. a down transport, so sealing an error envelope would burn a Noise send-nonce for a frame that can't arrive and gap the phone's recv nonce — the same #912 hazard the idle sweep already avoids by also closing with `nil`. It does **not** re-check whether the queue has since drained below the ceiling: `Run`'s select is unordered, so several `drainOnce` passes (and even a transport recovery) can land between the signal and this arm, but envelopes were already discarded when the latch tripped, and only the re-handshake this teardown forces replays them — [#647 replay](#reconnect-replay-647--hellolast_event_id--ring-replay--resync) from `hello.last_event_id`, plus [`reconcileModals`](#connect-time-modal-reconcile-877--outstandingmodals-seam--reconcilemodals) / [`reconcileQueues`](#connect-time-queue-reconcile-878--outstandingqueues-seam--reconcilequeues), none of which fire on transport recovery alone. A "kinder" re-check would leave a surviving session with a permanent silent gap in the phone's turn stream and nothing to reconcile it.

**`StatusQueueOverflow websocket.StatusCode = 4413`** — new close code, echoing HTTP 413 (Content Too Large), consistent with the existing 44xx←HTTP convention. Deliberately not a reuse of `StatusIdleTimeout` (4408): that would mislabel an overflow as an idle session, the same class of mistake #912 documented when a transport outage surfaced as `noise.rekey_failed`. Added to `docs/protocol-mobile.md` § Error codes with the same recovery note the idle-sweep row already carries — a phone whose transport was down never sees the `4413` close frame either (`closeWith`'s send is best-effort over a transport that may be exactly the thing that's down); it learns on its next inbound frame, which lands on a session the daemon no longer has, and re-handshakes.

**Producer contract unchanged.** `Push` still returns `nil`, promptly, when it trips the ceiling — the overflow is not the producer's failure, and both production callers ([#632](../codebase/632.md), [#589](../codebase/589.md)) only debug-log a `Push` error anyway. Pushes after the teardown find no queue and get the pre-existing `ErrConnNotFound` — no new error value ever reaches a producer.

**The #911 in-flight gate note above is now half-superseded.** It still correctly bounds the *retry* axis for debug bundles (a single conn can't stack multiple bundles' worth of chunks). What it does **not** bound — a single oversized bundle, or the #874/#632 live-turn growth path — is what `pushQueueByteCeiling` now bounds instead, by tearing the session down rather than retaining unboundedly.

**Security review verdict: PASS** (self-review, `docs/specs/architecture/1505-push-queue-byte-ceiling.md` § Security review). No new trust boundary — the ceiling measures `len(env.Payload)` on envelopes the daemon itself produced; push is server→phone only, so a phone can't drive control-event volume directly except indirectly via `request_debug_bundle`, where the archive size is the daemon's own `.cast` recording, not requester-supplied. One accepted residual: a paired phone can trip the ceiling on *its own* conn by requesting an oversized bundle and can repeat that — bounded three ways (per-session; #911 still prevents stacking bundles on one conn; hot-looping handshakes is already cheaper for an adversarial phone). The `nil`-frame teardown is a load-bearing positive for the #912 nonce hazard (see above). Logs carry only content-free discriminants (`event`, `conn_id`, `bytes`, `ceiling`, `close_code`, `env.Type`) — no payload bytes. No new goroutines or locks; `pushMu` stays a leaf lock.

Tests: `internal/relay/v2session_test.go` — `TestPushQueue_Enqueue_ByteCeilingBoundary` (both sides of the boundary: the envelope landing exactly on the ceiling admits, the next byte rejects and latches `overflowed` without touching `dropped`), `TestPushQueue_Enqueue_ByteCeilingIsBytesNotCount` (far more than `pushQueueCap` small control envelopes, total under the ceiling, all admitted — pins bytes-not-count), `TestPushQueue_PopHead_AccountingRoundTrip` (enqueue a mixed-size mix, pop every one, `bytes` returns to exactly 0), `TestPushQueue_Enqueue_EvictionDecrementsBytes` (the evict site decrements by the evicted delta's payload length), and `TestV2Session_Push_ByteCeilingTearsDownSession` (AC2/AC3 end-to-end: drain parked via the #874 `Connected` seam, a bounded loop of full-size control `Push` calls crosses the ceiling, every `Push` still returns `nil`, the session leaves `V2StateOpen` and its queue is deleted, the close frame is `4413`/nil, and a subsequent `Push` gets `ErrConnNotFound` — with `idleTimeout` left at its production 15 minutes so the teardown provably isn't the pre-existing idle sweep). `internal/relay/v2session_debugbundle_test.go` — `TestV2Session_DebugBundle_JustUnderCeilingStreams` (an archive sized just under the ceiling streams to completion with no teardown, then round-trips once the transport recovers) and `TestV2Session_DebugBundle_PastCeilingTearsDownConn` (an archive past it tears the conn down at 4413 instead of retaining it unboundedly; `StreamBundle`'s own return value is deliberately not asserted — it returns the first `Push` error, and which push observes the teardown first is racy). `TestPushQueue_Enqueue_AllControlSoftOverflow` and every `TestV2Session_DebugBundle_*` predating this ticket pass unmodified — the ceiling sits ~2× above what those fixtures ever approach.
