# Connect-time slash-command-list reconcile (#2006) — `RetainedSlashCommandLists` seam + `reconcileSlashCommandLists`

`security-sensitive` — the fifth Mode B instance of the reconcile-on-connect mechanism (umbrella #829), and [model-list reconcile](#connect-time-model-list-reconcile-1863--retainedmodellists-seam--reconcilemodellists)'s direct twin: same `initialize` reply, sibling frame, identical guard/marshal/push shape. A freshly interactive-open conn is unicast one `slash_command_list` envelope per retained payload on the handshake's success tail, so a client attaching to a long-running daemon gets a correct command menu without waiting for a turn that may never come. `SlashCommandListPayload` otherwise reaches a live conn only on the interactive-turn lane, with the same loss points the model-list twin has — **re-derived and corrected by #2010's docs pass, which found the model-list description's own attribution imprecise for two of the three.** The bootstrap child's report is lost unconditionally, but by `startStreamTurnDrainV2`'s active-session gate (see [streamsup-package-draining-turnevents-into-the-interactive-emitter.md](streamsup-package-draining-turnevents-into-the-interactive-emitter.md) § "The per-event session gate" and its rotation-gap note), not by any early return inside the emitter itself — the drain drops the event before `Handle` is ever called. `forwardEnvelope`'s `last_event_id` dedup is **not** a loss point here: its watermark is clamped to the newest id at handshake, so a later frame for the *same* conversation always carries a higher id, and the reconcile's own frame is immune regardless (`EventID` is nil, never in the ring). The `droppableCap` classification is the one loss point the twin's description gets right unchanged.

**The model-list twin's live-lane race transfers unmodified to this variant — confirmed by #2009's e2e capstone, not assumed from the shared code path.** `(*interactiveTurnEmitterV2).Handle`'s cursor read and `sessionRouter.Route`'s cursor stamp are unordered by any lock or channel for `slash_command_list` exactly as they are for `model_list`, so a freshly-minted conversation's own minting conn sees the live-lane frame 0 *or* 1 times across otherwise-identical runs — never a fixed value. #2009's own mutation run (AC 4) is what surfaced this for this variant specifically: the green run measured the minting conn at 1, contradicting a first-draft assumption of guaranteed 0 that would have carried over from the model-list twin's original (later-corrected) prediction. Treat any spawn-time-emitter count on a minting conn as a logged diagnostic in this family, never an assertion — see [model-list reconcile](#connect-time-model-list-reconcile-1863--retainedmodellists-seam--reconcilemodellists) for the full unordered-goroutine mechanism.

**`RetainedSlashCommandLists func() []protocol.SlashCommandListPayload`** is the fifth optional `V2SessionConfig` seam (nil ⇒ no reconcile). Production wires a non-nil closure as of #2007: `cmd/pyry/session_slash_command_list.go`'s `retainedSlashCommandLists(convReg, pool)`, built at the composition root in `main.go` and assigned straight through the `relayWiring` struct — not wrapped in a closure at the assignment site, since a wrapper is non-nil even when the underlying value is nil and would silently defeat the seam's `nil ⇒ no reconcile` contract. **Enumerate-all, not conversation-keyed**, same reasoning as `RetainedModelLists`: a `V2Session` carries no conversation id, so there is nothing to key on at connect time — the seam takes no argument and returns every retained payload, each self-identifying by its own `conversation_id`. This was a deliberate trap when the seam shipped: #2005 shipped `resolveBoundSlashCommandList` (`cmd/pyry/session_slash_command_list.go`), a **conversation-keyed** resolver that is the obvious thing to reach for here and is the wrong shape — #2007 is what bridges the two, by enumerating the registry and calling the resolver once per row rather than keying off it directly.

**`reconcileSlashCommandLists(ctx, s)`** is `reconcileModelLists`'s structural twin, `protocol.TypeSlashCommandList`/`SlashCommandListPayload` substituted, in its own file (`v2session_slashreconcile.go`) for the same one-letter-from-a-neighbour readability reason the model-list and question reconciles give for theirs. Guard, snapshot-then-early-return, one shared batch timestamp, `EventID` left nil (out of the turn-event replay ring, and inert against `forwardEnvelope`'s dedup) — all identical to the model-list twin. The marshal branch is defensive and unreachable by fixture (`SlashCommandListPayload` is a closed `string`/`[]SlashCommand`/`int` struct, both custom `MarshalJSON`s delegate to `json.Marshal` over closed types) and never echoes `err`, since `encoding/json` quotes input bytes and a workspace-authored command name would land in the record; the push branch may echo `err` only because `Push` returns `ctx.Err()` or `ErrConnNotFound` and nothing else.

**Call site:** last in `handleNoiseInit`'s success tail, after `reconcileModelLists`. Ordering is immaterial to correctness (five distinct payload types, none reads another's effect), but the tail is sorted by time-sensitivity — permission prompt first — and a command menu is the least time-sensitive of the five.

**Being last is safe for a structural reason, not a lucky one.** `pushQueue.enqueue` marks an envelope droppable only when its type is `protocol.TypeAssistantDelta`, so every reconcile's frame — this one included — is control-class and the nominal-cap drop policy can never shed it. That is what makes "position in the tail is immaterial to correctness" a provable claim rather than an assumed one; a droppable classification would have made fifth-of-five the worst spot in the family, not a neutral one.

**Aggregate cardinality is unbounded on this path, and the two bounds that make it safe live in different packages.** The reconcile applies no cap of its own — a second cap here could silently disagree with the producer's. The producer bounds one payload's serialised `commands` array via `maxSlashCommandListBytes`, keeping the marshalled envelope under the 65519 B v2 application-envelope cap (worst case measured at 63224 B, 96.5% of cap). The relay-side backstop is `pushQueueByteCeiling` (32 MiB) over a queue that is *fresh* at this call site (created a few statements earlier in the same `handleNoiseInit`), so tripping it from a cold start needs roughly 512 worst-case retained lists across all five reconciles combined — the deterministic, already-tested `StatusQueueOverflow` teardown, not unbounded growth. Neither number is visible from the reconcile itself; a reader who checks only one package will not find the other half of the argument.

**A "zero envelopes" assertion cannot pin AC5's context-teardown branch.** With an already-cancelled context, nothing is pushed whether the branch `return`s after the first failed `Push` or `continue`s past it — the four analogue reconciles ship this branch untested, so there was no fixture to copy. What distinguishes "stops the batch" from "skips one and continues" is the **count of `push_err` log records**: exactly one with the early return, one per remaining payload without it. Confirmed sole-red by a `go test -overlay` mutant (3 records for 3 payloads against the expected 1) — worth carrying into any future reconcile that adds a teardown-stops-the-batch clause, since the natural assertion (envelope count) is vacuous for this specific branch.

**Security review verdict: PASS** (`docs/specs/architecture/2006-slash-command-list-connect-reconcile.md` § Security review). Same two structural gates as the other four — authentication (post-handshake, post-token-validation) and capability (`!s.interactive`) — plus the never-log-workspace-text discipline: `Name`/`ArgumentHint`/`Description`/every `Aliases` entry are workspace-authored untrusted text forwarded **unsanitised** (the client owns the render-boundary sanitisation; that is `SlashCommand`'s own documented decision, not an omission here) and never logged. `conversation_id` is the one identifier that does reach a log record, and it is safe to log because it is server-minted (`conversations.NewID()`), never a client-chosen value. Out of scope, same as the other four enumerate-all seams: no per-device confinement — a paired interactive conn sees every retained list, including conversations bound to other workspaces; that belongs to the Mode B umbrella (#829) if it's ever wanted, not to one instance.

Tests: `internal/relay/v2session_slashreconcile_test.go` — the model-list file's table-driven pattern, plus the AC5 teardown test the twins lack. Header records the marshal-branch coverage gap as a decision, not an oversight, same as the other four.

**The daemon-side producer (#2007):** `retainedSlashCommandLists(convReg, pool)` (`cmd/pyry/session_slash_command_list.go`) is `retainedModelLists`' body with the payload type substituted — enumerate `Registry.List()` unfiltered (archived rows contribute), call `resolveBoundSlashCommandList` per row, `continue` on refusal, append on success. The double lookup (re-`Get`ting a row instead of reading `CurrentSessionID` off the listed copy and calling `Pool.Lookup` directly) is a security control, not redundancy: the shortcut would fork the #678 guard where `Pool.Lookup("")` returns the bootstrap session, handing every unbound conversation the shared bootstrap child's menu stamped with its own `conversation_id`. One place the twin's *reasoning* does not transfer even though its conclusion does — no `len(Commands) > 0` filter — is already recorded generally in [`Runner` interface + `RunnerFactory`](sessions-package-key-types-runner-interface-runnerfactory.md) (§ "A twin's stated reason does not transfer just because its conclusion does"); the producer-sourced guarantee it relies on instead is `streamsup.emitSlashCommandList`'s early return on a zero-length list (#1877).

**The enumerator is the first caller to invoke the resolver twice within one result, which raises an aliasing question no single-call test can.** Two conversations bound to the *same* pool session: do their payloads share a backing array for `Commands`? No — `sessionSlashCommandHold.SlashCommandList` deep-copies per call and `turnbridge.MapEvent` allocates a fresh outer slice — but that property is only observable, and only wrong-able, from a fan-out caller, so the two-conversation isolation test is pinning it alongside the more obvious crossed-menu failure. Worth carrying into any future enumerator in this family: a twin's own resolver tests cannot cover this, only the first multi-row caller can.

**`Registry.Save`'s lock is released before the fsync**, which is what discharges the seam's BOUNDED TIME obligation rather than merely asserting it: it snapshots under `r.mu` and releases before `MkdirAll`/write/rename, so none of the enumerator's N per-row `Get` calls can queue behind a disk write.

`retainedSlashCommandLists` is `resolveBoundSlashCommandList`'s first production caller — see [sessions-package § no production caller](sessions-package-key-types-runner-interface-runnerfactory.md) for the #2005 shipped-with-none state this closes. #2009 is the cross-process e2e capstone, the inverse of #2008 (list exists first, observing phone connects after, drives no turn) — see [e2e-harness.md](e2e-harness.md) for the test's own design, including the minter-side race noted above, which its AC-4 mutation run surfaced.
