# `Pool.AdoptAnnouncedID` (#2135, sole announced-reset writer since #2137)

Where `RotateForNewSession` *drives* a rotation for a daemon-initiated `new_session`, `AdoptAnnouncedID` *adopts* one claude announced on its own stdout — the id already has a fresh `<id>.jsonl` claude opened itself, before this method is ever called. ([`sessions-package-key-types-pool.md`](sessions-package-key-types-pool.md) has the sibling re-key paths.)

**Trust-boundary promotion (#2137).** Until #2137, an announced `/clear` had two writers racing for it: this method, and the now-retired rotation watcher, which observed the same `/clear` on disk via an fsnotify CREATE + open-descriptor probe and usually won — real claude opens, appends, and closes its transcript within milliseconds, faster than this call typically reached the pool. `AdoptAnnouncedID` was "second writer, usually loses." #2137 deleted the watcher, so this method is now the **sole** writer of an announced re-key: every `conversation_reset` the pool ever applies goes through here. The two bounds that make trusting a child-authored id safe were re-verified against the tree rather than taken on faith from this doc, because a doc that assumed the watcher's presence is exactly the kind #2137 had to correct: the `ValidStem` shape gate upstream in `emitConversationReset` (anchored full match over lowercase hex — allowlist and length cap in one), and the `ErrSessionIDTaken` destination refusal below, checked inside the same `p.mu` hold as the mutation. Neither bound was ever supplied by the watcher, so promoting this method to sole writer weakened neither.

```go
func (p *Pool) AdoptAnnouncedID(oldID, newID SessionID) error
```

**Body shape is `RotateForNewSession`'s**: one `Pool.mu` hold covers every check *and* the mutation, rather than delegating to `RotateID`'s own locking. The reason is the collision check below — it must sit inside the same critical section as `rekeyLocked`, or checking then mutating is a TOCTOU.

Contract, in order:

- `oldID` absent → `ErrSessionNotFound`, no mutation, no transition. **Before #2137** this was the expected outcome whenever the (now-retired) rotation watcher won the race for the same `/clear`: it had already re-keyed, so `oldID` was gone by the time this call arrived, and both producers converging on `RotateID`/`rekeyLocked` under `Pool.mu` is what kept "exactly one `session_transition`" structural. **After #2137**, this sentinel's surviving producers are `RotateForNewSession` and `RotateBootstrapForSelfHeal` — both of which rotate `oldID` onto a **freshly minted** id, not the announced one. `rekeyPool` ([the reset follower](streamsup-package-announced-reset-follower.md)) still answers `nil` on this sentinel and lets the caller's tag stand on the announced id, which is sound only when the registry is actually there; when a minted-id rotation raced it instead, the tag and the registry can now diverge. That gap is filed as **#2176**, not fixed here — see the reset follower doc's `ErrSessionNotFound` section.
- `oldID == newID` → nil, **no re-key and no transition**. `RotateID`/`rekeyLocked` checks membership *first* and only returns nil for `oldID == newID` afterward; `AdoptAnnouncedID` mirrors that rather than rotating-then-notifying unconditionally, because an announced id arrives on every line of claude's own stdout and an equal-id announcement is a normal, frequent shape, not an edge case.
- `newID` already names a **different live session** → `ErrSessionIDTaken`, no mutation, no transition. `rekeyLocked` moves a map entry without checking the destination — that's fine for `RotateForNewSession`/`RotateBootstrapForSelfHeal`, whose inputs are trusted (a daemon-minted UUID), but an announced id is one stdout line away from a hostile or confused claude naming a session it doesn't own. Refusing here, inside the lock, is what stops that line from silently overwriting another session's registry entry. This is a distinct sentinel from `ErrSessionNotFound` on purpose — the caller logs the two at different severities (Debug for the ordinary race/minted-id case, Warn for a genuine collision), and folding them into one sentinel would bury the collision under the ordinary case's noise.
- Otherwise `rekeyLocked` + `saveLocked`, then `notifyTransition(ReasonClear)` off-lock — the same best-effort-durability posture as its siblings.
- Does **not** arm `Runner.BeginRotation` ([`streamsup-package-per-conversation-turn-busy-track-rotation-delivery-gate.md`](streamsup-package-per-conversation-turn-busy-track-rotation-delivery-gate.md)). That gate exists for a daemon-initiated restart where a child is about to be killed and every turn must be refused until a successor binds. Here no child is replaced and claude keeps running; arming it would refuse turns for no reason.

## The refusal is only half the boundary

`ErrSessionIDTaken` closes the **registry** half of a collision: `rekeyLocked` never runs, so no other session's entry is overwritten. It does **not** and structurally *cannot* close the other half, because the pool has no reach into it: the caller (`sessionResetFollower`, [`streamsup-package-announced-reset-follower.md`](streamsup-package-announced-reset-follower.md)) holds a live tag on the runner that stamps every later event with a session id, and that tag is not `Pool`-owned state.

The first security review of this ticket audited exactly the registry half and stopped there — the tag half was found only in a second pass, after the caller had shipped an *unconditional* tag rotation that ran the same regardless of what `AdoptAnnouncedID` answered. A caller that rotates its own state unconditionally and only conditionally rotates the pool's turns a clean pool-side refusal into a half-enforced one: the pool correctly refused to adopt a colliding id, but the caller's tag still pointed at it, so the runner's later events were stamped with — and, downstream, delivered into — a conversation this rotation was never allowed to touch. The lesson generalises past this ticket: **a refusal returned across a package boundary is not a control until the caller's own state is unwound to match it.** An audit that stops at the refusing side has audited half a boundary.

## Testing

`transition_test.go` additions: known-id re-key fires exactly one `ReasonClear` transition with the right `PreviousID`/`NewID`; equal ids re-key nothing and fire nothing; unknown `oldID` returns `ErrSessionNotFound` with no mutation; a `newID` already owned by a different live session is refused with both sessions left exactly as they were.
