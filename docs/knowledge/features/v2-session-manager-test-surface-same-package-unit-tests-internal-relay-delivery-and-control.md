# Push delivery, replay and inbound-control tests

[Same-package test overview](v2-session-manager-test-surface-same-package-unit-tests-internal-relay.md) describes the shared harness.

Server-initiated push (#571; backpressure + drop policy #610) — all `t.Parallel()`, all `-race`-clean; the `buildMessageEnvelope(t, id, text)` helper builds the binary→phone `message` envelope (always on the test goroutine — `t.Fatalf` from a child goroutine is unsafe):

- `TestV2Session_Push_InterleavedWithReply_DecryptsUnderRace` — fires a `Push` from a separate goroutine while feeding an inbound sealed request that triggers a `dispatchAppFrame` reply; the push drain and reply path contend for the single `Run` goroutine. Decrypts all three outbound frames (`noise_resp` + reply + push) in capture order under the phone's `initRecv` — a clean in-order decrypt is the nonce-integrity proof. The pushed frame decodes through the SAME `decryptAppFrame` path to a valid `TypeMessage` envelope (AC#1 + AC#4 — no new wire shape). Order between reply and push is nondeterministic (`Run`'s `select`); asserts presence, not order. **Passes unchanged across the #610 buffered-enqueue rewrite** (`waitForEnvelopes` polls; every seal still happens on `Run` in FIFO order).
- `TestV2Session_Push_ConcurrentWithReplies_NoNonceCorruption` — the stress version: N=8 concurrent pushes + M=8 in-flight request/reply dispatches; all N+M outbound frames decrypt in capture order with no AEAD failure (AC#2 — the drain serialises every `s.send.Encrypt` onto `Run`, nonce never reuses). Also passes unchanged post-#610 (8 pushes are well under `pushQueueCap`, so none drop).
- `TestV2Session_Push_UnknownConn_ErrConnNotFound_OtherSessionUnaffected` — push to a never-seen `conn_id` returns an error satisfying BOTH `errors.Is(err, relay.ErrConnNotFound)` AND `errors.Is(err, control.ErrConnNotFound)`; an unrelated open session's subsequent solicited round-trip still decrypts (AC#3 — no mutation of another session's state).
- `TestV2Session_Push_NotOpen_ReturnsErrConnNotFound` (renamed from `…ReturnsErrSessionNotOpen` in #610) — a white-box non-open session has no queue, so `Push` now returns `ErrConnNotFound`. The companion `TestV2Session_forwardEnvelope_NotOpen_GateRefuses` pins the drain-side `V2StateOpen` security gate that moved to `forwardEnvelope`. (Pre-#610 this asserted `ErrSessionNotOpen` via `handlePush`'s state check.)
- `TestV2Session_Push_ClosedSession_ReturnsErrConnNotFound` — drives an AEAD-failure 4421 teardown (flips a ciphertext byte) that deletes the session (and its queue), then asserts a push to that `conn_id` collapses into `ErrConnNotFound`.
- `TestV2Session_Push_CtxCancelled_ReturnsCtxErr` — a `Push` with an already-cancelled ctx returns `ctx.Err()` without blocking; `Push` checks `ctx.Err()` before consulting `m.queues` (#610), so a cancelled ctx short-circuits deterministically.

\#610 backpressure tests (added): the drop policy is a pure unit surface — `TestPushQueue_Enqueue_*` (helpers `pqEnv` / `fillDeltas` / `assertQueue`) cover under-cap retention, drop-oldest-delta (AC#2), control-evicts-delta (AC#3), `message`-is-never-drop, control-never-dropped-when-deltas-present, order-preserved-across-drops (AC#4), and the all-control soft overflow. The end-to-end non-blocking guarantee (AC#1) is `TestV2Session_Push_NonBlockingUnderStall`: a stalling outbound double wedges the `Run` forward, every `Push` still returns within a tight deadline, the drop counter engages past `pushQueueCap`, and after release the survivors decrypt **in order** under the phone's `recv` state (proving drop-before-seal left no nonce gap). See [`codebase/610.md`](../codebase/610.md).

## Capabilities and connection enumeration

Capability negotiation (#626) — `buildHelloEarlyDataCaps` / `driveToOpenCaps` variants carry the advertised set without changing the `buildHelloEarlyData` (5 callers) / `driveToOpen` (30 callers) signatures; the handshake tests capture the hello_ack early-data (which `driveToOpen` discards) via `Initiator.ReadResp` → decode `Envelope` → `HelloAckPayload`:

- `TestNegotiateCapabilities` — table-driven AC#2/#3 matrix for the pure function: `[interactive]`→`[interactive]`; `[interactive, unsupported]`→`[interactive]` (drop); `[unsupported]`→`nil` (spoof); `nil`/`[]`→`nil` (advertise-nothing); `[interactive, interactive]`→`[interactive]` (dedup). `t.Parallel()`.
- `TestV2Session_Handshake_CapabilityNegotiation` — table-driven handshake-level: advertise `[interactive]` → ack echoes `[interactive]`; advertise nothing → ack has no `capabilities` key; spoof `[interactive, god-mode]` → ack echoes only `[interactive]`; `[god-mode]` only → ack has no capabilities.
- `TestV2Session_ActiveConns_MixedInteractive` — two open conns (one interactive, one not) → `ActiveConns` reports the correct flag per conn (white-box injection mirroring `TestV2Session_ActiveConns_OpenOnly`, below).
- `TestV2Session_CapabilitySpoof_TokenFail_NeverEnumerated` — the **security** test: a phone advertising `[interactive]` but failing the token is closed at 4401 and never appears in `ActiveConns`; the negotiated flag is never observable for an unauthenticated peer.

`TestV2Session_ActiveConns_{OpenOnly,TornDownSessionAbsent,ConcurrentWithDispatch_RaceClean,EmptyManager,CtxCancelled_ReturnsNil}` (renamed from `TestV2Session_ActiveConnIDs_*` in #1542, once #572's wire-up closed NOT_PLANNED and the now-dead `ActiveConnIDs` projection was deleted) — the same five #588 properties, retargeted directly onto `ActiveConns` rather than measured through the deleted projection: `OpenOnly` on an injected four-state map (`V2StateOpen` ×2, `HandshakeComplete`, `AwaitingInit`) only the two open sessions are reported; `TornDownSessionAbsent` a session torn down by an AEAD-failure 4421 close is absent from the next snapshot; `ConcurrentWithDispatch_RaceClean` snapshots taken in a tight loop under `-race` while sealed frames drive dispatch on the same open session never report a foreign conn id, and the solicited replies still decrypt in seal order; `EmptyManager` a started manager holding zero sessions returns `len 0` without blocking; `CtxCancelled_ReturnsNil` an already-cancelled ctx with `Run` never started returns `nil` without blocking.

`OpenOnly` deliberately stays separate from `MixedInteractive` above rather than folding in: it is the only test in the tree exercising the `V2StateAwaitingInit` arm of the `handleActiveConns` `V2StateOpen` security gate (`MixedInteractive` injects a `HandshakeComplete` session but no `AwaitingInit` one). Confirmed, not just asserted — a mutant widening the filter to `V2StateOpen || V2StateAwaitingInit` and run against the whole package reddens `OpenOnly` alone. `CtxCancelled_ReturnsNil` is similarly the **sole** killer of the enqueue-arm `ctx.Done()` mutant in `ActiveConns` (`m.snapshot` is unbuffered, so that arm is the only thing stopping an indefinite block when `Run` isn't draining): deleting the arm hangs the whole package to timeout, and the same mutant with only this test skipped passes `ok`. Both were proved by `go test -overlay` mutation, not inferred from the retarget compiling. A test-helper collapsing `[]ActiveConn` into `[]string` was considered and rejected before the retarget — walking the seven call sites (five here plus `MixedInteractive` and `Push_ByteCeilingTearsDownSession`) showed only `OpenOnly` actually wanted a sorted `[]string`; the rest wanted `len`, a nil check, or a contains-by-`ConnID` predicate, so a shared helper would have relocated the deleted method rather than removed it.

## Reconnect replay

Reconnect replay (#647) — `internal/relay/v2session_replay_test.go` (new): each drives a real Noise handshake whose hello carries `last_event_id` against a manager whose `SetReplaySource` was given a hand-populated `eventring.Ring` + a stub cursor, decrypts the forwarded frames, and asserts. `TestV2Session_Reconnect_ReplaysMissedTail` (3,4,5 ascending before any live frame), `…_CaughtUp_NoReplay` (`last_event_id` exactly at the newest id — the only caught-up position since #1494), `…_Gap_EmitsResync` (aged-out position → one `resync` with `conversation_id`), `…_BeyondNewest_EmitsResync` (#1494: `last_event_id` past the newest id, incl. `math.MaxUint64` → one `resync`, where it previously produced zero frames), `…_AbsentLastEventID_NoReplay`, `…_ScopedToCursorConversation` (cursor→B, ring holds A → zero A events, AC-5), `…_ReplayDisabled_NoReplay` (nil ring), `…_OtherConnsUnaffected`, `…_ForwardEnvelope_ReplayWatermarkGuard` (drops `EventID ≤ replayThrough`, forwards above, never drops `EventID == nil`). The #647 caught-up/out-of-range tests asserted only *no replay frames* and missed that the live stream was muted afterward; **#663 closes that gap** — `…_OutOfRangeLastEventID_LiveStreamDelivered` (incl. `math.MaxUint64`), `…_ClearRotation_LiveStreamDelivered`, and `…_SameConversation_DedupPreserved` push a live frame after the handshake and assert **delivery** (see [codebase/663.md](../codebase/663.md)). The first two now exercise the **gap** branch rather than the caught-up one (#1494): delivery comes from `replayThrough` being left untouched at `0`, not from the clamp, and each expects the `resync` ahead of its live frames. Only `…_SameConversation_DedupPreserved` (in-range `afterID=2` → replay branch) still runs the clamp end to end. Paced replay (#777) reworked the harness — `reconnectScenario` now polls `waitForEnvelopes(t, rec, wantEnvs)` for the final frame count instead of `waitConnOpen` + an open-instant snapshot (the tail drains over `Run` passes *after* the conn is enumerable), and the content-assertions above stayed green through the swap. Four new same-package tests pin the pacing (two direct-drive on an injected session via `offlineHandshake`/`newInjectManager`, two through the live `Run` select): `…_Paced_OnePerRunPass` (one `drainReplayOnce` pass forwards exactly ONE frame, advances `replayThrough` by one), `…_LiveGated_DrainOnceSkipsReplayingConn` (**AC #2**: `drainOnce` won't pop a replaying conn's buffered live events until its tail empties), `…_LargeReplay_DoesNotBlockOtherConn` (**AC #1**: conn B's `noise_resp` lands before conn A's final frame of a ~200-event replay — probability ≈ 2⁻²⁰⁰ of failing under a fair select), `…_LiveInterleave_OrderedAfterReplay` (**AC #2** end-to-end: a live push reaches the wire after every replay frame), and `…_PacedReplay_Race` (**AC #3**: `-race`-clean replay drained concurrently with off-`Run` `Push`es + a second conn's handshake; every `s.send.Encrypt` stays serialised on `Run`) (see [codebase/777.md](../codebase/777.md)).

## Complete live-state workload

`TestLiveStateRun` drives the hermetic manager's real `Run` loop with a snapshot
of `pushQueueCap*2` readings. Require every `pushQueueCap*2+2` routing envelope
(handshake, generated clear and all readings), then authenticate/decrypt all
`pushQueueCap*2+1` application frames in capture order with the same receive
cipher. After completion, `ActiveConns` must still report the authenticated
connection: a shortened snapshot could pass a count check while hiding overflow
that closes the peer.

One test-local eight-second absolute deadline starts before manager startup and
handshake admission and covers collection through the last application
decryption. Expiry is checked even with buffered frames and immediately after
decryption; progress never renews it. The shared `waitForEnvelopes` default stays
unchanged. Content-free checkpoints record first/halfway/final transport and
halfway/complete decryption, with timeout diagnostics reporting elapsed time and
both received/expected and decrypted/expected counts. Keep `TestLiveStatePacing`,
`TestLiveStateBounds`, `TestLiveStateOrdering` and retirement coverage beside this
complete-workload proof. See [current-state pacing](v2-session-manager-concurrency.md#supplied-current-state-delivery)
and [deadline measurements and failure controls](development-verification.md#diagnosing-reply-timeouts).

## Inbound controls

The resolver-side assertions (consume + keystroke + audit + no-body-leak) live in `cmd/pyry/modal_resolve_v2_test.go` (the relay can't import supervisor/audit/registry). See [codebase/727.md](../codebase/727.md).

Inbound interrupt (#707, widened #2103) — `internal/relay/v2session_interrupt_test.go`: a `fakeInterrupter` (mutex-guarded call recorder of the ids it was handed + injectable error, mirroring `fakeModalResolver`; `SendEsc` gained the `conversationID` parameter for #2103), driving everything through the real `Frames`/`Run` loop with the #727 helpers. The fire-and-forget no-reply handler is synced with a **barrier conn opened after the interrupt frame** — the single FIFO `Frames` + single `Run` goroutine guarantees the interrupt is fully handled before the barrier opens, so the recorder is final (and works on the nil path: barrier-open is the no-panic/no-hang proof). `TestV2Session_Interrupt_RoutesEscByCapability` (table-driven both paths: interactive → exactly one Esc, non-interactive → zero — AC-2/AC-4), `…_NilInterrupterInert` (nil seam → zero Esc, no panic, manager keeps serving), `…_SendEscErrorTolerated` (`SendEsc` error → still one attempted call, no crash/close — best-effort). **Since #2103**: a table-driven test drives named / bare / undecodable-body frames through the same loop and asserts the exact string that reached the seam, and `TestV2Session_Interrupt_NonInteractiveNeverDecodes` pins that naming a conversation is not a way around the capability gate — the decode now runs after that gate, so a non-interactive conn's bytes are never parsed. `activeInterrupter`'s own arm selection — turning a client-supplied id into a resolved runner — is untestable here (`internal/relay` can't see the registry or pool it resolves against); that composition test is new at `cmd/pyry/active_interrupter_test.go`, the seam's first unit test ever.
