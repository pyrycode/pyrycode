# Ticket #864 — ptyrunner: reap claude's descendant process groups on budget-hit and watchdog teardowns

Extends #565's descendant-group reap from the operator-cancel path (`cmd.Cancel`) to the two other teardown paths that kill claude mid-work — budget-hit and watchdog-fire — so claude's detached Bash process groups no longer reparent to init unbounded across wedged runs. Promoted from #565's documented "known same-shape gap" by wedge-corpus evidence: most abnormal teardowns kill claude mid tool-loop (last JSONL entry `tool_use`), exactly the in-flight-Bash moment. Wiring only — `reap.go`'s `reapDescendantGroups`/`descendantPGIDs` logic and its three load-bearing guards (`pgid<=1`, own group, `rootPid` group) are unchanged.

## Implementation

Confined to `internal/agentrun/ptyrunner`. No new exported symbols, no new deps.

- **Test seam** (`reap.go`): `var reapDescendantGroupsFn = reapDescendantGroups`. All three reap call sites — existing `cmd.Cancel`, new budget hook, new trailing defer — route through this var instead of calling `reapDescendantGroups` directly. Production behaviour is byte-identical (var defaults to the real function); tests swap it non-parallel and restore via `t.Cleanup`.
- **Two new chokepoints, chosen by *when claude gets signalled*, not by which path fires** (`runner.go`):
  - **Budget `Terminate` hook** (~line 478) — reap is the **first statement inside the hook, before its own SIGTERM**. The hook signals claude itself, so a trailing defer would race an already-reparented orphan (claude may be mid-exit by the time a defer runs); the in-hook reap mirrors #565's `cmd.Cancel` reap-before-signal ordering, where claude is guaranteed alive (just finished a turn).
  - **Trailing defer, registered immediately after `defer sess.Close()`** (~line 386) — `defer func() { reapDescendantGroupsFn(cmd.Process.Pid, logger) }()`. LIFO fires this *before* `sess.Close()`'s SIGTERM, so it also reaps a live tree on watchdog-fire (which only cancels `runCtx`, never signals claude directly) and on normal end-of-turn teardown. Must stay ordered right after `sess.Close()`'s registration — reordering it would let `sess.Close()`'s SIGTERM run first and the walk would miss the reparented group.
- **Redundant reaps are intentional, not a bug**: on the budget path the trailing defer also fires later (claude likely dead by then → empty walk); on the operator path `cmd.Cancel` reaps live, the trailing defer fires later as a no-op. `reapDescendantGroups` already tolerates `ESRCH`/already-exited groups, so the second call costs one `ps` snapshot and does nothing.
- Teardown-latency note: the trailing defer now runs a `ps` snapshot (`reapPSTimeout` = 2s bound) on **every** Run teardown, not only abnormal ones — a clean run's descendant set is normally empty, so no kills, no log line.

## Testing

Two new non-parallel unit tests in `runner_test.go`, each cloning the sibling behavioural test's harness rather than modifying it in place (keeps the existing parallel `TestRun_*` assertions untouched):

- `TestRun_MaxTurnsExhaustion_ReapsDescendantGroups` — clones the `jsonl_exit143` / `MaxTurns:1` harness; swaps the seam to a mutex-guarded recorder (mirrors `loggerSyncWriter`); asserts `Run` returns nil and the recorder captured ≥1 call with `rootPid > 1` (not `==1` — the trailing defer may add a second, harmless call).
- `TestRun_WatchdogFires_ReapsDescendantGroups` — clones the `TestRun_WatchdogFires` config; same ≥1-call assertion, exercising the trailing-defer chokepoint.

Both confirmed RED before wiring, GREEN after. `reap_test.go`'s four guard subtests are unchanged and their continued passing is AC-4's evidence — no new guard tests were added. `go test -race ./...` (41 pkgs) and `go vet ./...` clean.

## Lessons learned

- **The two abnormal teardown paths needed different chokepoints because they signal claude at different times**, not because of any other distinction between them. The budget hook signals claude itself → reap must run inside the hook, before its own SIGTERM. The watchdog only cancels `runCtx` → a trailing defer ordered before `sess.Close()` reaps a still-live tree. A single trailing defer covering both would have silently missed the budget path's orphan (claude often already exiting by the time a deferred reap fires after its own SIGTERM). When wiring a reap/cleanup hook into multiple teardown paths, always check *who signals the target process* on each path before picking one chokepoint for all of them.
