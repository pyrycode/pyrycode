# Ticket #956 — Close the fakeclaude JSONL-rotation create-before-content race

`TestE2E_StartRotation_PrimitiveWiresFakeClaude`
(`internal/e2e/fakeclaude_test.go`) intermittently failed under full-suite
`-race` load with `rotated jsonl … is empty; fake-claude payload missing`.
Root cause: fake-claude's `openSession` makes the rotated `<uuid>.jsonl`
**name** visible via `os.OpenFile` before it writes the `{}\n` payload; the
consumer `waitForRotatedJSONL` returned the instant a matching name appeared
in `os.ReadDir`, with no content check. When the poll won that race, the
test body's `os.Stat(rotated).Size()` observed a zero-byte file and the
line-59 sanity assertion failed. `-race` doesn't catch it — it's a
create/write ordering gap, not a shared-memory data race.

Confirmed pre-existing (not a regression) by the #950/PR #955 attribution
work. Fix is **consumer-side, by construction**: fold a `Size() > 0` gate
into `waitForRotatedJSONL`'s poll success condition. Zero production code
change — same shape as the sibling flake fix in
[#584](584.md), but at the harness-consumer layer (`fakeclaude_test.go`)
rather than the binary's own unit test (`main_test.go`).

Spec: [`docs/specs/architecture/956-fakeclaude-rotation-nonempty-gate.md`](../../specs/architecture/956-fakeclaude-rotation-nonempty-gate.md).
Feature doc updated: [`features/e2e-harness.md` § Rotation Primitive](../features/e2e-harness.md#rotation-primitive-startrotation-fakeclaude_testgo-123) (steps 5–6).

## Implementation

One file, `internal/e2e/fakeclaude_test.go`, ~18 lines changed in
`waitForRotatedJSONL` — signature and every other caller unchanged:

- Where a `<uuid>.jsonl` stem previously matched and returned immediately,
  the candidate is now `os.Stat`'d and the function returns only if
  `info.Size() > 0`. A zero-byte or transiently-unstattable candidate falls
  through to the next 50 ms poll tick instead of returning.
- No timeout change, no `time.Sleep` beyond the existing poll interval.
- The line-59 `Size()==0` sanity assertion in the caller is left in place
  verbatim — it now documents an invariant the wait guarantees rather than
  racing it.

**Why `Size() > 0` is a sufficient, monotonic gate:** `openSession` opens
the rotated file `O_WRONLY|O_APPEND|O_CREATE` and never truncates it
afterward (only appends: the initial `{}\n`, later
`appendTurnGrowth`/`emitStructuredJSONLIfTriggered`). So "size > 0" is a
one-way latch — once true it stays true — which is what makes the caller's
later `os.Stat` at line 54 also deterministically non-empty.

**Alternative considered and rejected (architect's call):** producer-side
write-then-rename (`CreateTemp` → write → `Sync` → `Close` → `Rename`) so
the rotated file is never observable empty under its final name.
Rejected because `openSession` returns an open append fd that the main
loop keeps writing to — an atomic rename would force a reopen-for-append
post-rename, doubling the syscall count and complicating fd lifecycle for
both the initial and rotated opens, and would touch production-adjacent
harness-producer code (`internal/e2e/internal/fakeclaude/main.go`) that
the consumer-side fix leaves untouched.

## Patterns established

- **Gate a poll's success condition on the full post-condition, not on a
  partial observable (name-only) with a separate single-shot assertion
  after the loop breaks.** Identical shape to [#584](584.md)'s
  trigger-gone fold-in — same bug class recurring at a different layer of
  the same test double's consumer stack (binary's own unit test vs. the
  e2e harness primitive test).
- **When a producer's file is append-only and never truncated under its
  final name, "size > 0" is a monotonic latch** safe to poll on without a
  TOCTOU concern — once observed non-empty, it cannot regress to empty.

## Lessons learned

- The fakeclaude create-before-content race recurs at every layer that
  polls `os.ReadDir`/`os.Stat` against the double's rotated file: #584
  fixed it in the binary's own `main_test.go` (folding the trigger-removal
  post-condition into the break gate); #956 fixes the *same class* of gap
  one layer up, in the e2e harness's `fakeclaude_test.go` consumer, which
  had re-introduced a name-only match with no content check. Any future
  poll against this double's directory should gate on non-empty content
  from the start rather than re-deriving this fix a third time.

## Security review

**Not security-sensitive.** Test-harness-only timing fix; no auth/crypto/
untrusted-input surface, no production code touched.
