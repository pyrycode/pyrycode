# Ticket #796 — wire the outbound turn-event stream for `pyry acp`

The **composition-root wiring** that gives [#750](https://github.com/pyrycode/pyrycode/issues/750)'s
`acpTurnStream` sink its **first non-test caller**. Constructs a
[`turnbridge.Producer`](../features/turnbridge-package.md) per addressable ACP
session to tail that session's transcript and feed the sink, so `session/update`
notifications — assistant text (`agent_message_chunk`), reasoning
(`agent_thought_chunk`), tool activity (`tool_call` / `tool_call_update`) — flow
to the host **as a turn progresses**. Before this ticket nothing in the `pyry acp`
composition root drove the sink, so no turn event ever reached the host. Epic
[#600](https://github.com/pyrycode/pyrycode/issues/600) T6, the ACP analogue of
the mobile leg's `startInteractiveTurnStreamV2` — but **far thinner**: one host,
one fixed session per stream, no capability fan-out, no replay ring, no
follow-active cursor.

Full package documentation:
[features/acp-package.md § Outbound streaming adapter](../features/acp-package.md#outbound-streaming-adapter-acpturnstream-750)
(the "Producer wiring (#796)" subsection).

## Implementation

**2 production files** (one new, one edited), plus one new test file and a
two-call-site test update. **No new package, no new exported type** — pure
within-`cmd/pyry` wiring of pre-built primitives.

- **`cmd/pyry/acp_turn_streams.go` (new, ~160 LOC)** — `acpTurnStreams`, an
  unexported **per-process** manager owning one `turnbridge.Producer` goroutine per
  addressable session id. Surface:
  - `newACPTurnStreams(ctx, pool, dir, logger)` — `ctx` is `serveACPWithPool`'s
    `runCtx`, the parent of every producer goroutine.
  - `attach(t *acp.Transport)` — stores the transport the producers `Notify` on.
    Called as the **first line** of the `register` closure; the acp
    "register-before-Serve" invariant runs it before any handler dispatch, so
    `transport` is set-once and happens-before every `start` — **no lock**.
  - `start(id sessions.SessionID)` — idempotent; spawns exactly one producer for
    `id`. Returns early on `dir == ""` (streaming disabled), or if a producer for
    `id` is already running (a repeated `session/load`, or `session/new` +
    `session/load` of one id, must not double-start). Then `pool.Lookup(id)` →
    `sess.Supervisor()` (the `turnbridge.SessionHost`), builds the fixed resolver +
    subscriber + sink + producer, `wg.Add(1)`, and `go prod.Run(m.ctx)`.
  - `wait()` — `wg.Wait()`; join every producer. Called after `cancel()`, so each
    producer has already observed cancellation.
  - `unmark(id)` — drops `id` from `started` on a soft failure (Lookup miss / build
    error) so a later `start` may retry. Both callers are on unreachable defensive
    paths; keeping `start` retryable is the honest invariant.

- **`cmd/pyry/acp.go` (edit)** — `runACP` computes
  `claudeSessionsDir := sessions.DefaultClaudeSessionsDir(trustedWorkdir)` and
  passes it into `serveACPWithPool` (new trailing `claudeSessionsDir string`
  param). `serveACPWithPool` constructs `streams` after `newPromptHolds`, calls
  `streams.attach(t)` first in `register`, threads `streams` into
  `newSessionHandler` / `loadSessionHandler`, and on return does
  `cancel()` → `streams.wait()` → `<-poolErr` (join consumers, then the pool;
  ordering isn't load-bearing — both respond to the one `cancel()`). Each handler
  calls `streams.start(id)` after a successful `pool.Create` / `pool.Activate`.

### The fixed-target resolver

Each stream serves **one fixed session id** — the degenerate constant case of the
mobile `resolveTarget`. Inlined as a closure in `start`:

```go
resolve := func(ctx) (turnbridge.Target, error) {
    return turnbridge.Target{
        Host:    host,                               // this session's supervisor
        Resolve: resolveBoundSessionJSONL(dir, id),  // fresh per (re)subscription
        Switch:  nil,                                // one fixed session; never re-keyed
    }, nil
}
```

- `resolveBoundSessionJSONL` is **reused verbatim** from `interactive_turn_stream_v2.go`
  (same package, [#679](https://github.com/pyrycode/pyrycode/issues/679)), built
  **fresh inside the closure** so its per-subscription cold/warm offset state
  resets on each re-subscription (the [#671](https://github.com/pyrycode/pyrycode/issues/671)
  rule, per bound session) — the in-flight reply is not skipped on a cold-start file.
- `Switch: nil` — `NewTargetSubscriber` treats a nil `Switch` as "session-end and
  parent-ctx cancel are the only teardown triggers" (the pre-#679 single-host
  behaviour). ACP never re-keys a stream onto a different session, so there is no
  active-conversation cursor to follow.
- A **fresh `tuidriver.NewTracker` per session** (not shared) mirrors the mobile
  path's one-tracker-per-stream and avoids cross-session parse-state races.

### The claude-sessions directory (and the watcher NOT enabled)

Every ACP session spawns in `trustedWorkdir` (`buildSession` sets `WorkDir` there;
no caller cwd reaches the spawn until #762+), so one fixed directory serves every
stream. `DefaultClaudeSessionsDir(trustedWorkdir)` names the exact directory
`claude` writes `<session-id>.jsonl` into — **coherent by construction** (the dir
is byte-identical to claude's launch cwd). `dir == ""` (unresolvable `$HOME`)
disables streaming: the process serves without live streaming rather than failing
(effectively unreachable — `confineWorkdirToHome` would already have failed).

The dir is passed **only** to `serveACPWithPool` for the streams, and is
**deliberately NOT set** on `sessions.Config.ClaudeSessionsDir`. Setting it there
would enable the pool's **rotation watcher**, which `RotateID`s a session on a
`/clear` — breaking the host-held session-id addressing that `session/prompt` and
`session/cancel` rely on. The pool's behaviour stays byte-unchanged; the stream's
dir is computed independently.

### Data flow

```
claude PTY + <session-id>.jsonl
  → NewTargetSubscriber(fixed Target: host=supervisor, resolveBoundSessionJSONL(dir,id), Switch=nil)
  → turnbridge.Producer.Run ──mapEvent──▶ OnEvent(turnevent.Event)
  → acpTurnStream.Handle ──MapUpdate──▶ transport.Notify("session/update", {sessionId:id, update})
       ├─ TurnEnd → onTurnEnd==nil → debug no-op (#751 flips this)
       └─ Stall   → stderr (Warn, content-free), never a notification
```

### Concurrency & lifecycle

- **One producer goroutine per session**, parented on `runCtx`, started from
  `session/new` / `session/load` handlers (which dispatch **serially** inside
  `Serve`), torn down by `cancel()` at shutdown, joined by `wait()`.
- `started` map + `wg` are touched by `start` (read-loop-only) and read by `wait`
  (after the read loop ends); the `mu` guard is **belt-and-suspenders** against a
  future off-loop caller, exactly like `promptHolds.begin`.
- **Re-subscribe per turn:** the producer runs for the session's *lifecycle*, not a
  single turn — `Producer.Run`'s outer loop re-subscribes after each `sess.Events`
  channel close (claude restart / turn boundary), so a session that outlives a turn
  keeps streaming (satisfies AC-2's "not a single turn").
- **No frame interleaving:** `acp.Transport.Notify` serialises on `writeMu` against
  handler replies, so producer notifications and request responses never corrupt
  each other on stdout.

### The #751 seam (left nil)

`start` builds the sink with `newACPTurnStream(m.transport, id, nil /* onTurnEnd */, logger)`.
`TurnEnd` is a logged **debug no-op** here. [#751](https://github.com/pyrycode/pyrycode/issues/751)
flips `nil` → a `holds`-derived resolver (`func(reason){ holds.end(string(id), reason) }`)
at this exact construction site — the manager will then need a `promptHolds`
reference. Left as a one-line seam, not pre-built.

## Patterns established

- **"Ship the consumer unit-tested, wire it in the lifecycle ticket" — closed.**
  #769 shipped the pure mapper, #750 shipped the scripted-tested sink with **zero
  non-test callers**, and #796 is the lifecycle ticket that stands up the live
  producer over a real session and feeds the sink. The same split as
  [#632](632.md)/#642; this ticket is the "wire it" half for the ACP outbound leg.
- **Fixed-target resolver = the degenerate one-host case of follow-active.** Where
  the mobile leg's `resolveTarget` follows the active conversation (a live `Switch`
  channel, bootstrap-vs-bound), ACP inlines a constant `Target` with `Switch: nil`.
  The same `turnbridge.NewTargetSubscriber` machinery serves both; ACP just never
  exercises the re-key path. `resolveBoundSessionJSONL` is reused **verbatim**
  across both legs — the by-id JSONL tail is surface-agnostic.
- **Compute the streaming dir independently; do NOT enable the pool watcher.** The
  turn stream needs the JSONL directory, but wiring it via
  `Config.ClaudeSessionsDir` would enable the id-rotating rotation watcher and break
  host-held addressing. Deriving the dir separately (from `trustedWorkdir`) and
  passing it only to the stream keeps the pool byte-unchanged — the wiring reads the
  same directory without inheriting its side effects.
- **Additive-by-file keeps the next ticket a one-line flip.** All new production
  logic is a single new file + a param and ~6 wiring lines in the composition root.
  No existing structure is touched, and the `onTurnEnd` nil argument is the exact
  seam #751 flips — [architecture](../features/acp-package.md) stays stable across
  the T6→T7 hand-off.

## Lessons learned

- **Enabling streaming must not enable the rotation watcher.** The obvious way to
  give the stream a JSONL dir — set `sessions.Config.ClaudeSessionsDir` on the pool
  — has a hidden cost: it turns on the `/clear` rotation watcher, which `RotateID`s
  the session and **breaks the host-held id addressing** that `session/prompt` /
  `session/cancel` depend on. Compute the dir independently from `trustedWorkdir`
  and pass it only to the stream; the pool stays byte-unchanged.
- **Build the by-id resolver fresh inside the closure, not once.**
  `resolveBoundSessionJSONL` carries per-subscription cold/warm offset state
  (`resolvedOnce` / `sawEmpty`). Constructing it once and reusing it across
  re-subscriptions would carry stale offset state into the next turn; building it
  fresh per (re)subscription resets it so the in-flight reply on a cold-start file
  is never skipped (#671).
- **One `Tracker` per session, never shared.** A shared `tuidriver.Tracker` across
  streams would race on parse state; a fresh `NewTracker` per producer mirrors the
  mobile one-tracker-per-stream discipline.

## Testing

`cmd/pyry/acp_turn_streams_test.go` (package `main`), `-race`-clean, reusing the
mobile fixtures (`streamEntry`, `jsonlStreamEvent`, `endOfTurnEvent`,
`scriptedSubscriber`, `waitClosed` from `interactive_turn_stream_v2_test.go`) and
the sink harness helpers (`newStreamHarness`, `frames`, `assertNotification`,
`discriminant` from `acp_turn_stream_test.go`).

- **`TestACPTurnStreams_ScriptedTurnEmitsOrderedFrames` (AC-1 / AC-4)** — the "e2e"
  twin of `TestInteractiveTurnStream_EventsReachHandle`. Drives
  `thinking`/`text`/`tool_use`/`endOfTurn` through a real `turnbridge.Producer` +
  the sink over a real `acp.Transport`, and asserts exactly the ordered
  `agent_thought_chunk` → `agent_message_chunk` → `tool_call` frames (each a
  well-formed `session/update` addressed to the session id), that the terminal
  `endOfTurn` (→ `TurnEnd`, nil resolver) emits **no** frame, and that the assistant
  text survives the real `mapEvent` + `MapUpdate` path intact. Exercises the wiring,
  not just the sink.
- **`TestACPTurnStreams_StallSurfacesOnStderrNotWire` (AC-3)** — a `Stall` driven
  through the wired producer surfaces on stderr (`acp_turn.stall`) and **never** on
  the notification stream (0 frames) — proving the
  `mapEvent(EventKindStallDetected) → turnevent.Stall → sink` path end-to-end.
- **`TestACPTurnStreams_LifecycleTeardownJoinsProducer` (AC-2 + idempotency)** —
  over a running `newFakeClaudePool`, `Create` a session, `start(id)` **twice**
  (asserts `started` stays size 1 — no duplicate producer), then `cancel()` the
  manager ctx and assert `wait()` returns within a deadline (the producer goroutine
  exits and is joined — **no leak**). The producer parks in `WaitForPTY` /
  resolve-retry since the fake claude writes no JSONL.
- **`TestACPTurnStreams_EmptyDirDisablesStreaming`** — `start` with `dir == ""` is a
  no-op (nil pool never dereferenced; returns before `Lookup`); `wait()` returns
  immediately.
- **`TestACPTurnStreams_NoAppContentLogLeak`** — mirrors
  `TestInteractiveTurnStream_NoAppOutputLogLeak`: drives secrets through the wired
  chain against a **failing transport writer** (so the sink's `notify_err` debug
  branch fires for every content event) and asserts none of the thought /
  assistant / tool-title / tool-input secrets reach the log buffer at any level.

`acp_test.go`'s two `serveACPWithPool(ctx, pool, …)` call sites pass `""` for the
new `claudeSessionsDir` param — those tests don't exercise streaming, and `""`
disables it, keeping their behaviour byte-unchanged.

## Out of scope (deferred)

- **Resolving the held `session/prompt` call on `TurnEnd`** —
  [#751](https://github.com/pyrycode/pyrycode/issues/751) (T7) flips the `onTurnEnd`
  seam this ticket leaves nil (`nil` → `holds.end`), at the `newACPTurnStream`
  construction site; the manager will then hold a `promptHolds` reference.
- **`/clear` mid-session rotation follow.** The fixed-id resolver tails
  `<session-id>.jsonl`; a `/clear` that rotates claude to a new UUID transcript
  leaves the stream on the stale file. Accepted by the ticket ("one fixed session
  per stream, no `Switch`") and the reason the rotation watcher stays disabled. A
  separate ticket if ACP ever needs it — not built now (no observed failure).
- **Per-session teardown before process exit.** ACP sets no `IdleTimeout` and
  exposes no `session/close` verb, so a pool session never ends independently of
  process shutdown; "session ends" collapses to "process shuts down", handled by
  `cancel()` + `wait()`. A future `session/close` / idle-eviction path would need a
  per-id child ctx per producer — deferred (evidence-based; no such path exists).
