# Ticket #1006 — e2e: `request_debug_bundle` over the v2 wire (stream + decode + error no-leak)

Split from #962 (the 2026-07-15 review-gap batch, oversized four-verb
parent — never itself shipped/documented). Fake-daemon e2e
proving `request_debug_bundle` end-to-end over the encrypted v2 wire, not just
at the `handleDebugBundleRequest` unit tier ([`v2session_debugbundle_test.go`](813.md)):
the happy-path stream/decode of a known archive, and — the load-bearing half,
given the `security-sensitive` label — the error path that must leak neither a
recording path nor the wrapped assemble error onto the wire or into the
daemon's logs. Rides the shipped [#811](811.md) (producer) + [#812](812.md)
(transport) + [#813](813.md) (request verb) + [#911](911.md) (in-flight gate)
seams; introduces one small net-new production seam of its own.

## Implementation

One new production file + 3 wiring lines + one new e2e test file:

- `cmd/pyry/debug_bundle_fake.go` (new) — `fakeDebugBundler() (func() ([]byte,
  error), bool)`. Gated on `PYRY_ALLOW_INSECURE_RELAY=1` (the daemon's existing
  test/insecure marker); returns `(nil, false)` otherwise, leaving the real
  `debugbundle.Assemble` path byte-identical. Two modes, FILE beats ERR:
  `PYRY_FAKE_DEBUG_BUNDLE_FILE=<path>` serves the file's bytes as the "known
  archive" (happy path); `PYRY_FAKE_DEBUG_BUNDLE_ERR=<sentinel>` returns
  `errors.New(sentinel)`, mimicking the real assembler quoting a recording
  path in a read error (error path). Same runtime-knob shape as the shipped
  `PYRY_CLAUDE_BIN` / `PYRY_ALLOW_INSECURE_RELAY` overrides.
- `cmd/pyry/main.go:867` — 3 additive lines right after the real `debugBundler`
  closure is built: `if fake, ok := fakeDebugBundler(); ok { debugBundler =
  fake }`. No consumer bypasses the override — it lands before the single
  construction site consumed once at `relay.go:517` (`DebugBundler:
  w.debugBundler`).
- `internal/e2e/relay_v2_debug_bundle_test.go` (new, `//go:build e2e`) —
  `TestRelayV2_DebugBundle` with two subtests, both riding
  `bundleHarness` (pair → spawn with `PYRY_ALLOW_INSECURE_RELAY=1` +
  `PYRY_MOBILE_V2=1` + the fake env → `driveHandshakeToOpenDaemon` → open,
  **non-interactive** conn — pairing alone authorizes the bundle, matching the
  unit tier's deliberate choice) and a bare `request_debug_bundle` envelope
  (no payload; the handler ignores it, mirrors `TypeInterrupt`):
  - `stream_decode_known_archive` (AC-1) — wires `PYRY_FAKE_DEBUG_BUNDLE_FILE`
    to a 120000-byte position-dependent archive (> `bundleChunkBytes=48000`,
    so it's genuinely multi-chunk: 3 chunks + done). Reads frames in strict
    arrival order (`decryptInnerEnvelope` with `initRecv` advances the Noise
    recv nonce once per frame), asserting **non-maskably**: `chunk[i].Seq ==
    len(chunks)` checked *before* the append (an emission-order bug fails here
    rather than being hidden by a later sort), `done.Total == len(chunks)`,
    and `bytes.Equal(bytes.Join(chunks, nil), known)` — arrival-order concat,
    never sorted by `Seq`. Chunk/done frames are pushes; the test asserts
    `InReplyTo == nil` on them rather than skipping the check.
  - `error_path_no_leak` (AC-2) — wires `PYRY_FAKE_DEBUG_BUNDLE_ERR` to a
    distinctive recording-path sentinel. Asserts the reply is the FIXED
    `TypeError` / `protocol.CodeServerBinaryOffline` / literal `"debug bundle
    unavailable"` (the const is unexported in `internal/relay`, so the e2e
    hardcodes the string) / `Retryable: true`. **Non-vacuity gate:** before the
    negative assertion, it polls `h.Stderr` for the positive
    `v2.bundle.assemble_err` event — proving both that the assemble-error
    branch actually ran and that daemon-log capture is live, so "sentinel
    absent from logs" can't pass merely because the buffer is empty. Only
    then does it assert the sentinel appears in neither the re-marshalled
    reply frame nor `h.Stderr.String()`.
  - AC-3 (`#911` in-flight gate) — **deferred at the e2e tier**, per the AC's
    explicit "if not cheap, note" clause: forcing a stable "prior bundle
    undrained" window over a real websocket has no deterministic barrier
    (`StreamBundle` drains as fast as the fakephone reads the socket). Already
    covered deterministically in-package by
    [`v2session_debugbundle_test.go`](813.md), which inspects the push queue
    directly.

## Patterns established

- **A non-deterministic production seam forces a fake-seam-of-last-resort,
  not a config surface.** The ticket's Technical Notes preferred "the
  harness's existing daemon-config surface" over a new production seam, but
  the real `debugBundler` closure (`func() { debugbundle.Assemble(dir,
  logRing.Snapshot()) }`) is genuinely byte-unpredictable out-of-process —
  `logRing.Snapshot()` tees every daemon log line (timestamps, conn-ids,
  durations) and a present recording contributes a timestamped name. No
  config surface can inject exact bytes into that path. The spec's Context
  section documents overriding the ticket's stated preference with this
  reasoning up front, rather than silently deviating — worth reading before
  assuming "prefer existing surface" is unconditional guidance for a
  similarly non-deterministic seam elsewhere.
- **Non-vacuity for a "logs must not contain X" assertion needs a positive
  poll first.** Asserting a sentinel is *absent* from `h.Stderr` is vacuously
  true if log capture never ran or the assertion races the daemon's
  `os/exec` pipe-copy. Polling for a *known-present*, content-free log event
  (`v2.bundle.assemble_err`) before the negative check proves the negative is
  meaningful — the same non-vacuity discipline as
  [[po-content-free-logging-is-preservation-not-sec-surface]], applied to a
  security-sensitive absence check rather than a presence check.
- **Reassembly assertions must stay non-maskable by construction.** The
  `Seq` check happens *before* the append and the final compare concatenates
  in arrival order — sorting first (a natural refactor) would silently mask
  an emission-order regression. Matches the standing guidance in
  [[po-chunk-stream-reassembly-ac-must-be-nonmaskable]] from the architecture
  spec for this same ticket.

/ NIT all empty) — see PR [#1020](https://github.com/pyrycode/pyrycode/pull/1020).

## Lessons learned

- The production `DebugBundler` closure is non-byte-predictable
  out-of-process (`logRing.Snapshot` tees every daemon log line + a
  timestamped recording name), so AC-1's "exact known archive bytes" is
  unreachable via the real path — an env-gated fake seam is required, not the
  harness's config surface. Gate it behind the existing
  `PYRY_ALLOW_INSECURE_RELAY` marker (same shape as `PYRY_CLAUDE_BIN`) so a
  stray fake var is inert in production.
- Make a "no-leak" negative log assertion non-vacuous by first polling the
  daemon logs for the corresponding positive event: that proves the
  error-path branch actually ran *and* that log capture is live, so "sentinel
  absent from logs" isn't passing merely because the buffer is empty.
