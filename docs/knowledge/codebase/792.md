# Ticket #792 — Live e2e capstone: inbound queue drains in order + dequeue a queued message

The **[EPIC #597] Phase 3 live exit gate** for the inbound queued-backlog feature
(split from [#708], mirrors the Phase 2 capstone [#642] and the [#723] deterministic
dequeue test). Over **one daemon + a real (fake) claude that goes busy → free**, it
confirms **live** what [#705] (wire types) / [#721] (`send_message`→queue wiring) /
[#722] (`queue_state` producer) / [#723] (`dequeue_message` handler) proved
**deterministically** upstream: phone messages typed while claude is busy **queue**
(not interleave), a queued message dropped from the phone via `dequeue_message`
**never reaches claude**, and the survivors **drain to claude in send order** once the
turn frees. It **confirms; it does not re-prove** — the correctness oracle stays
upstream ([#722]/[#723]). **Test/harness only** — the queued-backlog production code
already shipped and was security-reviewed there.

**`security-sensitive`** — the adversarial question is not "does this introduce a
vuln" but **"could this test PASS while the guarantee is broken?"** Architect
spec-stage self-review verdict **PASS, no MUST FIX**; code-review **PASS** (no MUST /
SHOULD / NIT).

## Single flow — no split on the "+"

The title reads as two things ("drains in order + dequeue"), but it is **one e2e
scenario**, not two tickets. The dequeue (AC3) is exercised *inside* the drain flow —
populate the backlog with three messages, drop the middle one before the turn frees,
then let the survivors drain. AC3's "dropped message never reaches claude" **negative
is meaningless unless the queue provably populated and drained in the same run** (the
vacuous-pass guard), so there is no clean seam to split along. This is the
[[po-plus-title-capstone-is-one-flow]] shape the PO flagged at intake — the "+" is a
vacuous-pass coupling, not a split boundary. One test, one ticket, held at **S**.

## What was missing over #723

[#723]'s `TestRelayV2_DequeueMessage_RemovesQueuedBeforeDrain`
(`internal/e2e/relay_v2_dequeue_test.go`) uses `/bin/sleep 99999` as the child —
claude is **never idle**, so the queue **never drains**. It proves enqueue +
dequeue-of-a-non-head + surviving-order, but the head is *perpetually* in flight and
**no message ever reaches claude**. #792 proves the **drain**: claude busy → messages
queue → claude frees → survivors reach claude **in send order**, and the dropped one
never does. That requires a child that transitions **busy → idle on command** and
records what it receives — which `/bin/sleep` cannot, but fakeclaude can with one tiny
additive extension.

## Implementation

The entire delta is **one production-source file** (fakeclaude, ~15 LOC of logic +
doc) + **one new test file**. No `pyry` runtime change, no new exported types, **no
`harness.go` change** (the `extraEnv` seam already existed — the [#642] precedent).

### fakeclaude: `PYRY_FAKE_CLAUDE_IDLE_TRIGGER` — a controllable busy window

The pre-#792 fakeclaude is **single-turn**: TUI mode emits the idle glyph `❯` at
startup (idle immediately) and the spinner `✻` once on the first stdin bytes (then
wedges "thinking" — a second `WaitReady` blocks forever). That gives no controllable
busy window and cannot drain a second message. The new mode inverts the startup posture:

- **When unset (default): byte-identical to today.** Every existing caller unperturbed.
- **When set:** fakeclaude starts **busy** — it emits **no** startup idle glyph and
  **never** the thinking spinner, so tui-driver's `IsIdle` stays false and the
  supervisor's `WaitReady` blocks (claude is "busy", exactly like the `/bin/sleep`
  child but under fakeclaude). It watches the trigger path in the **existing poll
  loop**, mirroring the `rotated` one-shot; on the file's **first appearance**
  `emitIdleIfTriggered` writes the idle glyph `❯` **once** (→ `IsIdle` true →
  `WaitReady` returns) and removes the trigger. Thereafter claude stays idle for every
  subsequent turn — **nothing overwrites the bottom status region** (the delivered
  prompt is not echoed to stdout), so `WaitReady` returns immediately for each queued
  message and the backlog **drains back-to-back**.
- **Per-turn commit is unchanged.** The idle-trigger mode does **not** itself enable
  the stdin reader — it relies on `PYRY_FAKE_CLAUDE_STDIN_LOG` being set (which
  `StartRotationWithRelay` does, so `logPath != ""` opens the reader). The reader sets
  `turnPending` on each delivered turn; the main loop's existing `appendTurnGrowth(f)`
  grows the JSONL, which the supervisor's `confirmViaTranscriptGrowth` ([#673]/[#668])
  observes as the commit. No spinner is needed on this path — the relay bootstrap sets
  `ResolveTranscript`, so commit is growth-based, not the TUI chip heuristic.

**Mutually exclusive with `PYRY_FAKE_CLAUDE_TUI`** — TUI mode's startup `❯` and
stdin-spinner would defeat the busy window and wedge the second turn. This test sets
only the idle-trigger. The evergreen mode reference is
[fakeclaude-binary.md § Idle-trigger mode (#792)](../features/fakeclaude-binary.md).

**Substrate-guard unchanged.** The idle glyph `❯` (`idleGlyph`) was already declared
in `main.go` and the file is already on the `cmd/substrate-guard` allowlist (#603);
the mode introduces **no new glyph**, so the seal is untouched. The new test file
carries only JSON + synthetic ASCII markers — clean.

### The test choreography (`TestRelayV2_QueueDrainsInOrder_AfterBusyTurn`)

Lifts [#723]'s structure verbatim where possible (`sealSend`, `nextEnv`
single-deadline decrypt-drain skipping non-`noise_msg` frames, the
`QueueStatePayload` FIFO decode). Three ASCII markers (`e2e-792-msg1/2/3`) chosen so
none is a substring of another. The bracketed-paste wrapping ([#749]) means the test
matches the marker **substring** on the stdin log, never the whole log.

1. **Seed the two-phone/relay harness** as [#723]: `RunBareIn(... "pair" ...)` →
   `decodePairPayload`; `seedBoundConversation(home, knownConvID, initialUUID)` (so
   `send_message`'s `router.Route` resolves and frames enqueue rather than rejecting
   pre-enqueue, [#678]); align `sessionsDir = <HOME>/.claude/projects/encode(HOME)`,
   `MkdirAll` it, and **pre-create `<initialUUID>.jsonl`** (`{}\n`) so
   `reconcileBootstrapOnNew` rotates the bootstrap to `initialUUID`. `fakerelay.New`.
2. **Start busy:** `StartRotationWithRelay(..., "PYRY_MOBILE_V2=1",
   "PYRY_FAKE_CLAUDE_IDLE_TRIGGER="+idleTrig)` with `neverRotate` (never created),
   `idleTrig`, `stdinLog` distinct paths under `home`. Claude comes up **busy** (no `❯`).
3. `waitBinaryHello`; `fakephone.Dial`; `driveHandshakeToOpenDaemonInteractive`
   (grants `interactive`, the capability `queue_state` requires).
4. **Enqueue three** `send_message` frames (m1/m2/m3, distinct `MessageID`s). Each
   acks immediately ([#721] enqueue-and-ack); the drain picks m1 → `WriteUserTurn(m1)`
   → `WaitReady` **blocks** (busy). m1 is the in-flight (draining) head; m2, m3 stay
   queued at idx 1, 2.
5. **[Vacuous-pass positive #1]** Drain `queue_state` until it shows **all three** in
   FIFO order (skip acks / partial snapshots); `t.Fatal` on the ~20 s deadline (the
   harness-produced-no-queue mode). Assert `ConversationID == knownConvID` and
   `Queued[0..2].Text == msg1/2/3`; capture `msg2ID := Queued[1].QueuedMsgID`.
   **Assert `stdinLog` is byte-empty** — nothing delivered mid-turn (**AC1**; a
   non-existent log file counts as empty).
6. **Drop the middle** (m2, idx 1 — removable; the head m1 would be an un-removable
   no-op): send `dequeue_message{knownConvID, msg2ID}`. Drain `queue_state` until
   `[m1, m3]` (len 2, m2 absent, order preserved). A valid dequeue never produces an
   error envelope ([#723] AC-2) — an error here is a `t.Fatal`.
7. **Free claude:** `os.WriteFile(idleTrig, ...)` → fakeclaude emits `❯` →
   `WaitReady` returns → m1 delivers + commits (growth) → drain advances → m3 delivers
   + commits. Drain `queue_state` until **empty** (`Queued` len 0).
8. **[Vacuous-pass positive #2 → the negative]** Read `stdinLog`. **Require msg1's
   marker AND msg3's marker with `Index(msg1) < Index(msg3)`** (**AC2**: survivors
   drained in send order); `t.Fatal` if either absent — the drain did not run, so the
   m2 negative would be vacuous. **Only then** require `stdinLog` does **NOT** contain
   msg2's marker (**AC3**: the dropped message never reached claude).

**Assertion order is load-bearing:** the two positives (three queued; two drained in
order) are hard preconditions of the m2-absent negative.

### Data flow

```
phone ──3× send_message (busy claude)──> daemon ──enqueue+ack──> msgqueue [m1,m2,m3]
   drain picks m1 → WriteUserTurn(m1) → WaitReady BLOCKS (no ❯)     │ queue_state → phone (FIFO)
phone ── dequeue_message{msg2ID} ──────> Remove(convID, m2)  ──────> msgqueue [m1,m3]
   test writes idleTrig ──> fakeclaude emits ❯ once ──> WaitReady returns
   m1 → DeliverPrompt → PTY (stdin log) → growth-commit → drain advances
   m3 → DeliverPrompt → PTY (stdin log) → growth-commit ──────────> msgqueue []
   stdin log = [ ...m1... , ...m3... ]  (m2 absent)                 │ queue_state{empty} → phone
```

## Patterns established

- **Withholding the idle glyph is the controllable busy window — and it is ~10 LOC.**
  tui-driver v1.6.0's `IsIdle` = `❯` present in the bottom status region AND no
  spinner there. The load-bearing fact this mode exploits: **withholding `❯` keeps
  claude "busy" (`WaitReady` blocks); emitting `❯` once flips it idle and it stays
  idle** — nothing overwrites the bottom region because the delivered prompt is not
  echoed to stdout. So a single glyph write releases the *whole* backlog to drain
  back-to-back; no spinner, no scroll/redraw emulation, no per-turn cycling. This is
  the counterpoint to [#642]'s TUI mode (which emits `❯` at startup): the same glyph,
  withheld, is a busy gate. Recorded at intake as
  [[architect-live-drain-e2e-fakeclaude-busy-gate]].
- **An empty `queue_state` is a happens-after fence for the stdin log.** An item
  leaves the msgqueue only on a **confirmed commit**, and a commit implies its prompt
  was already `DeliverPrompt`-written and fsynced into the stdin log. So reading the
  log *after* observing the empty snapshot needs **no polling** for the drain-order
  assertion — the fence is structural, not a sleep. (PR Lessons-learned #2.)
- **"Busy claude" makes a byte-empty stdin log a sound AC1 oracle.** During the busy
  window the drain parks on the head in `WaitReady` *before* `DeliverPrompt`, so
  nothing is written to the PTY. Asserting the stdin log is **byte-empty** (not merely
  marker-absent) is a valid, non-flaky "nothing delivered mid-turn" check — verified
  across `-count=3`. (PR Lessons-learned #1.)
- **The vacuous-pass guard is two *ordered* positives gating one negative** — the
  `security-sensitive` headline requirement. Same shape [#642] established: the
  live-confirmation negative ("dropped message absent") is meaningless unless the
  positive path (queue populated *and* drained in the same run) is observed first,
  each with a dedicated `t.Fatal` naming its failure mode. The ~7 s runtime is itself
  evidence the transition fired — a non-draining run would burn the 20 s drain-to-empty
  deadline and fail, so a vacuous pass is not reachable.
- **Serial per-conversation drain makes "in order" hold by construction; the stdin log
  only witnesses it.** [#704]/[#721]'s one-in-flight-at-a-time invariant (`WriteUserTurn`
  returns/commits before the next is peeked) is what serializes m1 then m3; the test
  adds no ordering machinery, it observes the shipped engine's. The head is un-removable
  while draining; idx ≥ 1 removals are always safe ([#719] `Remove`), which is why the
  test drops the **middle** (m2), never the head.
- **Harness reuse over harness build — the [#642] `extraEnv` seam pays off again.**
  The whole proof rides the *shipped* production stack (supervisor + relay + msgqueue +
  producer/handler); the only new harness surface is the ~15-LOC fakeclaude idle-trigger.
  `StartRotationWithRelay` already appends `extraEnv` verbatim, so **no `harness.go`
  change**. The build-vs-reuse call was the architect's ([[po-plus-title-capstone-is-one-flow]]
  / #642 reuse note); reuse held.

## Lessons learned

*(Lifted from the PR #804 **Lessons learned** — the developer flagged two non-obvious
oracle properties; both are captured as Patterns above and restated here as the
transferable lesson.)*

- **`confirmViaTranscriptGrowth` gates the PTY write on `WaitReady`, so a byte-empty
  stdin log is a sound AC1 oracle.** The drain parks in `WaitReady` *before*
  `DeliverPrompt` during the busy window — nothing hits the PTY — so asserting the log
  is byte-empty (stronger than marker-absent) is valid and non-flaky. Held across
  `-count=3`.
- **An empty `queue_state` is a happens-after fence for the stdin log.** An item
  leaves the msgqueue only on a confirmed commit, and a commit implies its prompt was
  already fsynced into the stdin log — so reading the log *after* the empty snapshot
  needs no polling for the drain-order assertion.

## AC4 (flight recorder) — scoped out of CI, mirrors #791 AC5

AC4 ("The run is recorded by the flight recorder for the audit trail") is **not
assertable by this test in any variant**, and the scoping is an architect
clarification, **not PO rework** — the sibling [#791] already resolved the identical
AC this way:

- The flight recorder (`.cast` capture) lives in
  `internal/agentrun/ptyrunner/runner.go`, gated on `PYRY_RECORD_DIR`, reached **only**
  from `cmd/pyry/agent_run.go` (the `pyry agent-run` / dispatcher path). The
  queued-backlog flow is a **mobile-relay** flow: claude is hosted by
  `internal/supervisor` (tui-driver `Session`), which does **not** read
  `PYRY_RECORD_DIR` or wire `SpawnOpts.RecordTo` (verified: no such reference in
  `internal/supervisor` or the relay bootstrap). The two code paths are **disjoint** —
  no single run is both "a queue drain" and "recorded by the flight recorder."
- [#791]'s AC5 was already scoped to "live-stack variant only … not applicable to the
  fakeclaude-replay variant." Per [[po-audit-artifact-ac-check-harness-reachability]],
  the architect scopes the AC to the variant whose import reaches the artifact — here,
  **none** on the mobile path.
- **Disposition:** the CI test asserts **AC1–AC3**. AC4 is deferred to the operator
  live run ([mobile-live-e2e-runbook.md](../features/mobile-live-e2e-runbook.md)),
  consistent with #791. It is **not** a developer deliverable and required no test code.

**Genuine in-CI audit capture** would require wiring `PYRY_RECORD_DIR`/`RecordTo` into
the supervisor-hosted path — a **production change**, surfaced but **not built**
(Evidence-Based Fix Selection: no observed need, and #791 already deferred the same
AC). Recommend the PO track it as an **epic-#597 follow-up**, not fold it here.

## Testing

One new `//go:build e2e` test asserting AC1–AC3 in a single run; **no production test
added** (the production change is a default-off test-only fakeclaude mode).

- **AC1** (queue while busy, not delivered mid-turn) — step 5: all three in
  `queue_state` FIFO **and** `stdinLog` byte-empty during the busy window.
- **AC2** (drain in send order once free) — step 8: `stdinLog` contains msg1 then msg3
  (`Index(msg1) < Index(msg3)`) after release; `queue_state` reaches empty.
- **AC3** (dropped message never reaches claude; surviving order holds) — step 6
  (`queue_state` → `[m1, m3]`, order preserved) + step 8 (msg2 marker **absent**).
- **Vacuous-pass guard** — the two positives are hard preconditions of the negative,
  each with a dedicated `t.Fatal`.

Gates green (developer + code-review): `go build ./cmd/pyry`, `go vet ./...`,
`staticcheck ./...`, `go test -race ./...`, `make substrate-guard`, and
`go test -tags=e2e -race -count=3 -run TestRelayV2_QueueDrains ./internal/e2e/...` →
**3/3 green (~7.4 s each)**. Code-review ran the e2e itself (QA does **not** compile
`-tags=e2e`, so code-review is the first place it builds — the [#642]/[#680] CI
coverage-gap note). Verdict **PASS**, no findings.
