# Ticket #1312 — Probe instrument: prove the sighting carrier reports the miss bound, measured against a first-poll miss (offline)

Adds the one row #1309 shipped without: proof that `finSighting.BoundFrom`
(the trailer-sighting carrier `finGatherReadings` returns, added #1309) reports
`trailBoundFromMiss` — the discriminator that actually bounds something — when
measured against a poll that genuinely misses before the trailer arrives, not
just `trailBoundFromStart`, which every pre-seeded row in the file reaches and
whose own doc says it BOUNDS NOTHING. Split from #1310 (closed; sibling half is
#1313, blocked on this ticket). Touches one file, no production `.go` change, no
new type, no call-site change.

## Implementation

- **`TestFinGatherSightingReportsTheMissBound`, the file's first row that
  leaves the buffer unseeded.** Built inline (not via `finGatherNegativeInputs`,
  which seeds the buffer at `finGatherSeed` — the one thing this row exists not
  to do) against a fresh `probeSyncBuffer`. Mirrors `finGatherNegativeInputs`'
  non-`Stdout` fields so the row differs from the file's base fixture in
  exactly one dimension.
- **Goroutine split, mirroring `TestTrailWaitForTrailer`'s first subtest
  (`result_trailer_observation_test.go:529-569`) rather than inventing a new
  shape.** `finGatherReadings(in)` runs on a spawned goroutine (it takes no
  `*testing.T`, so nothing inside it can call `t.*`); the test goroutine sleeps
  500ms (past two 200ms poll ticks), appends `trailFixtureTrailer` in a
  **single** `probeSyncBuffer.Write` call (torn-line avoidance — `Write` holds
  the mutex for its whole body), then blocks on `<-done`. Every assertion runs
  after the channel close, which is the happens-before edge for the three
  `finGatherReadings` returns.
- **The contrast: a second, direct `trailWaitForTrailer` call over the same
  buffer, not a second `finGatherReadings`.** By then the trailer is already in
  the buffer, so the first poll matches and the bound comes back
  `trailBoundFromStart` — proving, over these exact bytes, what a carrier
  filled from a re-scan would have reported instead of the miss bound.
- **Only the discriminator is bound — the observation itself never is.**
  `trailWaitForTrailer(&stdout, finGatherTrailerWait).BoundFrom` is read off
  the call directly; no `trailObservation` variable ever exists in scope. That
  value carries `.Line` (verbatim, OPERATOR-REVIEW-BEFORE-PASTE model output)
  and the decoded `*resultTrailer` pointer, both forbidden from failure
  messages by the file header. `trailFixtureTrailer` carries no needle, so a
  stray `%v` of the observation would trip no sweep and fail silently — the
  structural form (nothing to print) replaces what would otherwise be a bare
  discipline. This is the file's own doctrine (`:211-212`): prefer the shape
  that cannot be got wrong over the discipline that must not be.
- **Assertion order: premise, miss bound, agreement, contrast.** The premise
  (`sighting.State == trailSeen`) is checked before the bound is read at all,
  so a poll that never matched fails by naming itself rather than surfacing as
  a bare bound mismatch — mirrors `TestFinGatherSightingComesFromTheClassifiedPoll`'s
  same check. The agreement check (`readings.BoundFrom == sighting.BoundFrom`)
  extends the shipped #1309 check onto the one bound value that actually bounds
  something. The contrast uses `t.Errorf`, not `t.Fatalf` — it corroborates,
  it isn't a premise for anything below it.
- **Wall clock, deliberately.** ~600ms: polls at 0/200/400ms miss, the append
  lands at ~500ms, the poll at ~600ms hits with the bound measured from the
  400ms miss. This file's first row that costs wall clock — the cost the miss
  bound requires. No new tick constant; the 200ms `probePollInterval` is
  expressed as a local sleep past two ticks, following the shipped precedent.
- **Three doc edits, no code otherwise touched:**
  - The `finGatherTrailerWait` constant's "NO ROW EVER WAITS IT OUT" claim is
    re-stated on three reasons instead of one (pre-seeded rows hit on the
    first poll; this row's trailer arrives well inside the 10s wait; the
    aborted row returns immediately because abortion is monotone) — the old
    single-reason claim no longer described the file once this row landed.
  - `TestFinGatherSightingComesFromTheClassifiedPoll`'s doc, which had handed
    the miss-bound proof forward as "#1310's", now names this row by name.
    #1310 was split into this ticket and #1313 and is closed, so the forward
    pointer would otherwise resolve to a ticket that no longer exists as work.
  - The one dangling cite at `TestFinGatherSightingCarriesTheDecodedScalars`'s
    doc — `(:129-135)` for "abortion is monotone", which had drifted onto the
    import block — is corrected to `(:148-150)`, the constants block's new
    (post-E1) location. Re-measured *after* writing E1, since E1 changes that
    block's own length. Deliberately not swept further: the sibling stale cite
    at `:1272` (`(:413-423)`) and the `#1310` reference inside
    `TestFinGatherSightingCarriesTheDecodedScalars`'s own doc are both #1313's,
    which is blocked on this ticket and lands after it.

## Tests

`TestFinGatherSightingReportsTheMissBound` is the only new test. Verification:
`go vet -tags e2e_realclaude ./internal/e2e/realclaude/...` clean;
`go test -race -tags e2e_realclaude ./internal/e2e/realclaude/...` → PASS/SKIP
split (live-claude specs skip without credentials); `-run '^TestFinGather' -v`
confirms the new row runs ~0.6-0.8s wall clock, the tell that it's genuinely
measuring a miss rather than winning a race against the first poll.

## Patterns established

- **Proving a carrier reports a "measured, not copied" value requires paying
  the wall clock the underlying mechanism actually costs** — there's no
  cheaper route to `trailBoundFromMiss` than a real poll miss, and every
  pre-seeded fixture in this family structurally cannot reach it.
- **Bind only the discriminator off a forbidden-to-print value's constructor
  call, never the value itself**, when a `%v` leak would otherwise trip no
  sweep (unlike named-key fields, this file's forbidden-key walk can't catch a
  raw struct dump inside a hand-written message).

## Lessons learned

- **A split ticket's child can lose the parent's stated mechanism if it
  rewrites the body standalone.** The PO's review of this ticket (recorded in
  memory as `po-1312-a-split-drops-the-parents-mechanism`) caught that an
  earlier draft of the AC dropped the parent (#1310)'s explicit "the second
  observation is a *direct* `trailWaitForTrailer` call" — without it, a costlier
  reimplementation (a second `finGatherReadings` call, re-running the argv and
  attribution legs) would also have satisfied the AC as worded. Fixed by
  restoring the direct-call requirement explicitly in both the ticket and the
  architecture spec's D2. When splitting a ticket, diff each child's ACs
  against the closed parent's own notes, not just against each other.
- **In a doc-edit ticket where the edit itself changes line numbers a sibling
  cite depends on, measure that cite last, after the edit lands** — the
  architecture spec called this out explicitly (E1 changes the constants
  block's length, so E3's target moves under the same diff) and the developer
  followed a `grep -n` recipe to re-measure post-edit rather than trusting the
  spec's pre-diff numbers. No stale self-cite shipped, unlike #1309's own
  (see `codebase/1309.md`'s lessons).
