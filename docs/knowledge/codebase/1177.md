# Ticket #1177 — realclaude/stream: resume after idle eviction against live claude

Adds the real-claude proof that an idle-evicted interactive **stream** session
resumes via `--resume` with prior context intact — closing the last
uncovered rung of the streamrunner plan's "restart after eviction" risk.
Idle-evict + respawn was covered end-to-end only against fakeclaude and only
on the PTY/bootstrap runner (`TestE2E_IdleEviction_RespawnsOnSendMessage`,
#396); the stream path's `TestE2E_PerConversation_IdleEvictsAndReactivates`
(#680) proves lifecycle/routing but explicitly deferred content-recall to
"realclaude's domain" — this ticket is that deferred work. First stream
real-claude spec to *enable* the idle timer; every prior one
(#1153/#1154/#1172/#1173/#1176) disables it. Split from #1083 (T9); sibling
leaves are #1173 (multi-turn continuity), #1174 (new-session rotation), #1175
(permission DENY), #1176 (interrupt).

## Implementation

- `internal/e2e/realclaude/interactive_stream_resume_after_eviction_test.go`
  (new file, `//go:build e2e_realclaude`, PR #1185). Test-only, zero
  production files, no edits to any existing file.
- `TestInteractiveStreamResumeAfterEviction` transcribes #1153's
  `TestInteractiveStreamLiveness` setup verbatim (stream-json config toggle,
  pair without `--allow-remote-permissions`, seed bootstrap + bound
  conversation, handshake), then:
  1. **Plant turn** — instructs claude to remember a per-run-unique token
     (`PYRYRESUME<hex nanosecond>`) and reply `ok`. Drained with #1153's
     `drainForCompletedTurn` (reused verbatim) — blocking until
     `turn_state{idle}` is the synchronization point that guarantees the
     token committed to the transcript **before** eviction.
  2. **Force + observe eviction** — the daemon is spawned with the idle
     timer *enabled* (`-pyry-idle-timeout=30s`, via the new
     `spawnBootstrapDaemonWithIdle`), and the test polls the daemon's
     captured stderr for the `session.idle_eviction` WARN
     (`waitForIdleEvictionWARN`) before sending the resume turn — the
     deterministic gate that makes the continuity assertion non-vacuous (a
     never-killed child would trivially retain context).
  3. **Resume turn** — asks for the token back. Drained with the new
     `drainForResumedTurnText`, which returns the concatenated
     `assistant_delta` text.
  4. **Assert continuity** — `strings.Contains(strings.ToUpper(recallText),
     strings.ToUpper(token))`. A true `--resume` reloads the transcript and
     recalls the token; a forked fresh spawn would not.
- Three new same-file helpers, all distinct-named to avoid same-package
  collision:
  - `spawnBootstrapDaemonWithIdle` — a near-copy of `spawnBootstrapDaemon`
    whose sole delta is `-pyry-idle-timeout=<idleTimeout>` instead of the
    hardcoded `=0`. Kept self-contained (not a parameter added to the shared
    helper) to avoid a shared-file merge surface with in-flight siblings
    #1173–#1176 — the established realclaude-family discipline.
  - `drainForResumedTurnText` — a fork of `drainForCompletedTurn` (same
    M1 non-empty-delta → M2 terminal-idle milestones, same in-order
    noise-decrypt discipline) that accumulates every matching delta's text
    instead of stopping at the first. Distinct name from #1173's
    `drainForCompletedTurnText` (not yet on `main` when this ticket branched;
    a shared name would redeclare once #1173 lands).
  - `waitForIdleEvictionWARN` — polls `bootstrapDaemon.stderr` for
    `event=session.idle_eviction`, `session_id=<bootstrapUUID>`,
    `bootstrap=true`. Pins the `session_id` **value**, not just the key
    (stronger than #396's key-only pin) — sound because the stream path's
    `buildArgs` passes `--session-id <id>` on the first spawn (no fork), so
    the bootstrap pool id equals the on-disk transcript stem and stays
    stable across `--resume`.
- Fixed ticket-encoded UUIDs (`11770000-0000-4000-8000-000000000001`/`…02`)
  — single-char-repeat stems were exhausted in the package by prior
  siblings.
- `D = 30s` (`-pyry-idle-timeout`) is the standing coupling constraint: the
  idle timer arms once at session activation and never resets per-turn
  (`internal/sessions/session.go` `runActive`), so `D` must exceed the
  wall-clock from daemon start to plant-turn completion or the plant drain
  REDs loudly (never a false green).

## Patterns established

- **Enabling a previously-always-disabled knob for one spec is a coupling
  constraint, not a flake risk to hide.** Every prior stream real-claude spec
  disables idle eviction; this one needs it on, which introduces a genuine
  wall-clock race (plant-turn completion vs. timer fire) that no amount of
  code can fully eliminate against real-claude latency variance. The right
  response is to document the constraint in-file (which knob, why, what a
  RED at that specific drain means) rather than pad the timeout defensively
  — a documented, loud, diagnosable RED beats a silent retry-until-green.
- **Value-pinning beats key-pinning when the identifier is provably
  stable.** #396's PTY-path WARN poll pins only the `session_id=` key
  because claude mints its own uuid on that path (#854); the stream path's
  `--session-id`-first `buildArgs` (no fork) makes the pool id and the
  on-disk stem the same stable value across `--resume`, so pinning the
  value is sound and a stronger assertion. Don't default to key-only pinning
  without checking whether the identifier is actually stable on the path
  under test.
