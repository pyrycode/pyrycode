# Ticket #982 — e2e: `recent_workspaces` over the v2 wire

The 2026-07-15 verb-coverage review (#960) found `recent_workspaces`
(`internal/relay/handlers/recent_workspaces.go`, #888) covered only by handler
unit tests — no e2e at any tier. Split from #961. Unlike its two sibling
workspace verbs (#980 `change_workspace`, #981 `create_workspace_folder`),
`recent_workspaces` is the **NOT-security-sensitive** member of the family: it
consumes no untrusted input (the request payload is empty by spec), touches no
filesystem, and has no error path — an empty registry yields
`"workspaces":[]`, not an error, and a conversation with an empty `Cwd`
contributes no entry. This ticket proves the fold/dedup/sort holds **over the
actual wire** — fakephone → fakerelay → spawned daemon, with the handler
already wired at `cmd/pyry/relay.go:420` — closing the same gap shape #949,
#974–#976, #980, and #981 closed for their verbs, and the group's first
read-verb e2e.

## Implementation

Test-only, one new file, no production code:

- `internal/e2e/relay_v2_recent_workspaces_test.go` (new, 285 LOC, build tag
  `e2e`) — `TestRelayV2_RecentWorkspaces` with two independent subtests, each
  owning its own pair → spawn → seed → Noise_IK handshake, modeled on the
  merged #974 rename / #980 change_workspace templates but diverging in two
  ways the spec called out explicitly: no not-found subtest (no error path),
  and no on-disk reassertion block (a pure read that Saves nothing, so there
  is no registry mutation to read back).
  - `testV2DaemonRecentWorkspacesOrderedDeduped` (AC #1, #2, #3, + empty-`Cwd`
    facet of AC #4) — direct-seeds four `conversations.json` rows: two sharing
    `/ws/alpha` at distinct timestamps (proving dedup keeps the newer
    `LastUsedAt`, not first-seen), one at `/ws/beta`, and one with an
    **empty** `Cwd` carrying the **newest** timestamp of the four. Seeding the
    empty-`Cwd` row newest makes the exclusion check non-vacuous: were it not
    skipped, it would sort first and break both the `len==2` and
    `Workspaces[0].Path=="/ws/alpha"` assertions. Asserts
    `recent_workspaces_list` correlated via `InReplyTo`, `len(Workspaces)==2`,
    most-recent-first ordering (alpha before beta), and
    `Workspaces[0].LastUsedAt.Equal(T3)` — the newer of the two alpha rows.
  - `testV2DaemonRecentWorkspacesEmptyRegistry` (empty-registry facet of AC
    #4) — seeds `{"conversations":[]}` and asserts the reply is a **success**
    `recent_workspaces_list` (not `TypeError`) with `Workspaces != nil &&
    len(Workspaces) == 0` — pinning the always-non-nil-slice contract
    (`"workspaces":[]`, never `null`).
  - Two spawns, one per subtest, matching the family's per-subtest isolation
    convention.

### Seeding: direct write, not `createConversationViaPhone`

Same architect call as #980/#981: the ticket's Technical Notes offered
`createConversationViaPhone` as an option, but the ordering/dedup assertions
need **known, controlled** `Cwd` strings and `LastUsedAt` timestamps that a
live-spawned session (which bumps `LastUsedAt` to *now* and sets a daemon
default `Cwd`) can't provide. Direct-seeded `Cwd` values are opaque strings
here — unlike the sec siblings, `recent_workspaces` never resolves or confines
them, so the test seeds literal paths (`/ws/alpha`, `/ws/beta`) with no
`os.MkdirAll` / `EvalSymlinks` involved.

## RED-on-regression

If `TypeRecentWorkspaces`'s registration at `cmd/pyry/relay.go:420` were
removed, the verb would fall through to the no-handler `protocol.unsupported`
arm and the ordered/deduped subtest's `want recent_workspaces_list` assertion
would fail. The test is a live guard on that wiring, same as the rest of the
family.

## Security review

**Not security-sensitive.** No production code change — the handler is
already wired; this ticket only adds a caller. No untrusted input is
consumed (empty request payload), no filesystem path is touched, and there is
no error path to certify a no-leak property against. Code review confirmed
PASS with no findings, including a note that `RunSweepLoop`'s ticker has no
eager startup tick, so the seeded (deliberately old, unpromoted) rows survive
the test window without racing a sweep-driven deletion.
