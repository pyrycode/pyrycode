# Ticket #813 — Serve the debug bundle to a paired client on request

The **capstone** of the debug-bundle feature (split from #803): a new inbound v2
control verb `request_debug_bundle` that a paired desktop/mobile client sends to
get the current session's evidence — the recent daemon log ring plus the newest
terminal recording when debug capture was on — over the already-encrypted channel,
without SSHing into the host. This slice **wires together** the two previously
unwired siblings: it assembles the bundle via #811's `debugbundle.Assemble`
(injected as a closure) and streams it back via #812's `(*V2SessionManager).StreamBundle`.
Authorization is **pairing**, enforced structurally at the Noise IK handshake (an
unpaired device is refused with WS 4401 and never reaches the handler) — **no new
authorization gate** is added. `security-sensitive`: this is the first
wire-reachable path that emits the recording to a remote client.

## Implementation

- **Wire type — `internal/protocol/codes.go`.** One new v2-only const,
  `TypeRequestDebugBundle = "request_debug_bundle"`, in its own const block beside
  the #812 `TypeDebugBundleChunk`/`TypeDebugBundleDone`. It is a **bare control
  frame — no payload struct, no response type**: the bundle is daemon-global by
  construction (the whole 200-line log ring, which has no per-session key, plus the
  newest recording across all sessions — per #811), so there is no `conversation_id`
  or any other field an attacker could use to select another session's data. It
  mirrors `TypeInterrupt`, which is also payload-less. The response is the existing
  `debug_bundle_chunk*` + `debug_bundle_done` stream; the manifest (recording
  present/absent) travels **inside** the archive as `manifest.json`, not out-of-band.
- **Protocol partition drift — `internal/protocol/compat_test.go`.** The new v2
  control type forces the three drift-detector edits (build fails otherwise): the
  `-rejected` case in `TestIsV1Compatible` (`IsV1Compatible` must reject it), the
  `v2OnlyTypes` map, and the `TestTypeConstants_V1V2Partition` `all` list. **MUST
  NOT** be added to `v1TypeSet` — a leak would route this inbound control envelope
  to the v1 handler chain.
- **Config seam + handler — `internal/relay/v2session.go`.**
  - `V2SessionConfig.DebugBundler func() (archive []byte, err error)` — a new
    optional seam beside `Snapshotter`/`QueueRemover`. The closure returns **only**
    `(archive, err)`, never the `Manifest`, so `internal/relay` never imports
    `internal/debugbundle`. `nil` ⇒ the verb replies with a deterministic
    unavailable error (foreground / v1 / unwired), never a silent drop.
  - `dispatchAppFrame` gains one `case protocol.TypeRequestDebugBundle:` arm in the
    control-type probe switch that runs **before** `dispatch.Route` — the same
    interception seam `request_snapshot` / `interrupt` / `dequeue_message` use.
  - `handleDebugBundleRequest(ctx, s, env)` — the structural twin of
    `handleRequestSnapshot`. Runs on the manager's single Run dispatch goroutine.
    Contract: nil bundler → error reply; `DebugBundler()` error → log the failure
    **event only** (never the wrapped err, which could quote a recording path) at
    warn, error reply; else `StreamBundle(ctx, s.connID, archive)` (a
    `ErrConnNotFound`, unreachable for an open `s`, is debug-logged and dropped);
    on success one **content-free** info log (`conn_id` + `len(archive)` byte count
    only). Every branch enqueues one stream or sends exactly one error reply.
  - `debugBundleReplyError` — sends one `TypeError` reply correlated on `InReplyTo`
    via the same `m.forwardEnvelope` seal-and-forward path `handleRequestSnapshot`
    uses, with a **fixed** `CodeServerBinaryOffline` + `retryable: true` + the
    static `msgDebugBundleUnavailable` message constant. The only failure this verb
    reports is "unavailable", so no per-cause (attacker-influenced) text is needed.
- **Wiring — `cmd/pyry/main.go` + `cmd/pyry/relay.go`.** `main.go` builds the
  closure `func() ([]byte, error) { archive, _, err := debugbundle.Assemble(dir,
  logRing.Snapshot()); return archive, err }` and threads one new `debugBundler`
  parameter through `startRelay` → `startRelayV2` (the v1 leg ignores it — debug
  bundle is v2-only), where it is set as `DebugBundler:` in the `V2SessionConfig`
  literal. The recordings dir is resolved by `cmd/pyry`'s existing
  `resolveRecordingsDir()` **independent of the `DebugCapture` flag** — old
  recordings persist and stay readable after capture is turned off, and `Assemble`
  marks the recording absent when the dir is empty.

## Patterns established

- **Manager-state verbs intercept in `dispatchAppFrame`, not the `Handlers` map —
  and this ticket is the canonical example of *why*.** The ticket's Technical
  Notes said "register on the `Handlers` seam" AND "do not use the 8-frame
  synchronous reply path" AND "deliver via `StreamBundle`" — mutually exclusive. A
  `dispatch.Handler`'s only reply path is `c.Send` → the 8-slot `handlerOutboundBuf`
  drained *after* the handler returns, so the 9th chunk of a multi-chunk bundle
  deadlocks forever; and a `Handlers` closure cannot reach `StreamBundle` (which
  lives on `*V2SessionManager`, constructed *with* the `Handlers` map). Any verb
  needing manager state uses the `dispatchAppFrame` interception (snapshot needs
  `Snapshotter`, interrupt needs `Interrupter`, this needs `StreamBundle`). The
  wiring the ticket referenced ("in `cmd/pyry/relay.go`") is still accurate — the
  new `DebugBundler` config field is set there.
- **Static error-message constant — never echo the assembly/decode error text.**
  `msgDebugBundleUnavailable` is the only string on any error reply, because the
  wrapped assembly error could quote a recording path or filename. Mirrors
  `snapshotReplyError`'s `MsgInvalidToken` / `handleDequeueMessage`'s never-echo
  discipline.
- **Capture-off *withholds* the recording structurally, not by a flag the client
  could ignore.** With debug capture off (empty recordings dir), `Assemble`
  produces an archive with **no `recording.cast` member** — there is nothing to
  withhold, so the recording cannot leak regardless of how the client reads the
  manifest. This is the strict ticket requirement (a) met by construction.
- **Content-free logging end-to-end (AC #4).** `handleDebugBundleRequest` logs
  only `conn_id` + a byte *count* on success and the failure *event* on error;
  `Assemble` makes zero `slog` calls by construction (#811); `StreamBundle`/`Push`/
  `drainOnce`/`forwardEnvelope` are already content-free. No bundle byte reaches
  any log — strict ticket requirement (b).
- **No new authorization gate, and — unlike `interrupt`/`dequeue_message` — NOT
  gated on the `interactive` capability.** Any device that completed the Noise
  handshake (reached `V2StateOpen`) is a paired device, which is the authorization
  the ticket specifies; a non-interactive paired client (e.g. a desktop diagnostic
  tool) can request a bundle. The bundle reaches only the requesting conn
  (`StreamBundle(ctx, s.connID, …)`), never a broadcast.

## Lessons learned

Lifted from the PR body's "Lessons learned" section (developer-flagged,
non-obvious — both are about writing the AC #4 "encrypted-only" test correctly):

- **The "encrypted-only" sentinel scan for a gzip'd bundle is vacuous unless it
  targets an *uncompressed* field.** A plaintext-sentinel scan of the raw
  `noise_msg` wire passes even *without* encryption, because the recording/log
  sentinels are gzip-compressed inside the archive — gzip alone hides the ASCII, so
  the test would give a false sense of confidentiality. The gzip-independent proof
  is that the *inner envelope Type* string (`debug_bundle_chunk`/`_done`, which
  lives in the sealed envelope JSON, **not** in the compressed payload) is absent
  from the raw frame and only recoverable via `decryptAppFrame`.
- **A Noise `CipherState` advances its recv nonce on every `Decrypt`, so each
  captured frame must be decrypted exactly once, in arrival order.** Poll-and-
  re-decrypt loops desync the nonce and fail. The test waits for a fixed frame
  count, then decrypts each once (`decodeNoiseMsg` is nonce-free and safe to call
  repeatedly for raw-ciphertext inspection). This is why `reassembleFromFrames`
  takes the frames plus one `*noise.CipherState` and walks them in order.

## Test surface

New same-package file `internal/relay/v2session_debugbundle_test.go`, reusing the
`openSession` harness (`driveToOpen`, `sealAppFrame`, `decryptAppFrame`,
`waitForEnvelopes`) with a `reassembleFromFrames(t, msgs, recv)` helper that
decrypts each captured frame once in order and feeds them to `relay.ReassembleBundle`
+ gunzip/untar. Non-vacuous: it byte-compares real member bodies and decodes
`manifest.json`, not merely asserting a non-empty archive.

- `TestV2Session_DebugBundle_CaptureOn` (AC1) — recordings dir with one sentinel
  `.cast` → archive contains `recording.cast` (sentinel bytes), `logs.txt`, and
  `manifest.json` with `recording_present: true`.
- `TestV2Session_DebugBundle_CaptureOff` (AC2) — empty recordings dir → **no**
  `recording.cast` member; `logs.txt` present; manifest `recording_present: false`.
  Proves structural withholding.
- `TestV2Session_DebugBundle_UnpairedRefused` (AC3) — unpaired token → refused at
  the handshake; a `DebugBundler` with a `called` flag is **never invoked**.
- `TestV2Session_DebugBundle_NeverLogsContentEncryptedOnly` (AC4) — seeded sentinel
  never appears in the captured log output, and never *unencrypted* on the raw
  routing-frame channel (see Lessons learned for the two subtleties).
- `TestV2Session_DebugBundle_ErrorReplies` — nil bundler and assembly-error branches
  each yield exactly one `TypeError` reply with the static message and matching
  `InReplyTo`, no bundle chunks, no content in the log.

## Notes

- **No ADR** — following the #811/#812 sibling precedent. The interception-seam
  choice (dispatchAppFrame over the `Handlers` map) is fully captured by the spec's
  design section + the `codes.go` const-block comment; it is not a net-new
  cross-cutting convention (it *reaffirms* the established snapshot/interrupt
  pattern).
- **Code review: PASS, no findings.** The `code-review` commit re-committed only the
  unrelated golden-file churn (`permission_protocol_v2.1.199.json` — the known,
  non-defect auto-commit churn), not any implementation change.
- **Out of scope (deferred, no observed need):**
  - **Large-recording Run-goroutine hold** — `Assemble` runs inline on the Run
    dispatch goroutine, so a multi-hundred-MB recording's copy briefly blocks *this
    conn's* dispatch (same posture as `handleRequestSnapshot`'s inline render).
    Moving `Assemble` behind a bounded worker is a follow-up only if a real stall is
    observed.
  - **Bundle memory under the control-never-drop policy** — a large archive admits
    many control-class chunks past the `pushQueue` soft cap (peak ≈ archive × ~4/3
    base64 until drained). Inherited from #811/#812's "not a remote DoS vector"
    finding — a paired client cannot inflate what the local session already produced.
  - **Per-request rate limiting / duplicate-request handling** — each `StreamBundle`
    is a self-contained `seq 0..N-1` + `done{N}`; per-conn FIFO preserves order.
    Degenerate client behaviour, not an AC.
