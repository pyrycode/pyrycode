# Ticket #1484 — msgqueue: advance the head by id, not position

`advanceLocked` dropped index 0 of a conversation's FIFO unconditionally. Both call sites decided "the head is still mine" in an *earlier* `q.mu` hold and never re-checked under the hold that actually spliced — so a `dequeue_message` landing during an in-flight delivery either spliced away the message queued *behind* the head (backlog `[A,B]` → `B` silently lost, violating the package's "No silent drop" invariant) or panicked on the nil slice `shrinkLocked` had already left behind (backlog `[A]` → `slice bounds out of range [1:0]`, killing the daemon). The regression traced to #1085, which narrowed `Remove`'s head gate from `draining` to `committing` and deliberately made a merely-waiting head droppable, without updating the blind splice that assumption had protected.

## Implementation

- `internal/msgqueue/queue.go`: `advanceLocked` now takes the id it is advancing past (`func (c *convQueue) advanceLocked(id uint64) bool`) and drops the front only when the FIFO is non-empty **and** the front still carries that id — the exact mirror of `commitGate`'s reject condition, asked in the lock hold that splices instead of an earlier one. Returns whether it dropped anything; on `false` it mutates nothing. The emptiness check must short-circuit before the id comparison — on backlog `[A]`, `shrinkLocked` has already set `items = nil`, so the id comparison alone would panic.
- Both advance sites now read the return value:
  - **Success path** (`drain`'s `err == nil` branch): `advanced := c.advanceLocked(head.id)`; `notify(convID)` fires only when `advanced` is true. A `false` return means a `Remove` took the head during its own delivery — a cancellation `Remove` already notified about — so `firstFailedAt` still resets and the loop `continue`s to re-peek.
  - **Give-up path**: `giveUp` now returns `bool` and runs the guarded advance *before* its `Warn`, not after. `true` ⟺ it abandoned the head ⟺ `draining` was cleared ⟺ the caller `return`s (unchanged shape). `false` ⟺ the head was dequeued inside the failure window ⟺ nothing dropped, nothing logged, `OnGiveUp` never fired, `draining` stays set, and `drain` resets `firstFailedAt` and `continue`s with a fresh clock instead of returning.
- `Remove` itself is unchanged — the ticket's alternative (widen `committing` across the confirm-to-advance window) was rejected as a behaviour regression against #487/#1085, not a hardening.
- New test file `internal/msgqueue/head_advance_test.go` (four functions, not collapsed): success `[A,B]` (B survives), success `[A]` (no panic, drain exits cleanly, a later enqueue still delivers), give-up `[A]` (no panic, no give-up report), give-up `[A,B]` (B survives, no give-up report for A). All four fail on pre-fix `main`.
- `docs/knowledge/features/msgqueue-package.md`: the three stale regions named in AC-5 (the `Remove` bullet, the TOCTOU bullet, the give-up bullet) were rewritten in the same commit as the fix to state the id-checked `advanceLocked` condition instead of the retired `draining`-based safety argument.

## Patterns established

- **Mirror an existing accept/reject predicate instead of inventing a parallel one.** The guard is written as the same check `commitGate` already uses to accept or refuse a write, just asked in the lock hold that splices rather than the one that merely decided. The fix note in the code explicitly says so — the defect was that the predicate lived at one site and not the others, not that a new predicate was needed.
- **A boolean return welded to a specific invariant, stated as an equivalence in the doc comment.** `giveUp`'s `true ⟺ draining was cleared ⟺ the caller returns` is written as a three-way equivalence precisely so a future edit that decouples any one side reads as breaking a stated contract, not just missing a subtlety. See [[architect-a-never-fires-ac-needs-a-different-clock]] for the same "name the substitute happens-after signal" instinct applied to detecting the *absence* of an event in tests.
- **Reordering a log line ahead of a guard, not adding a new branch, is how you make an event unconditionally suppressible.** Moving the give-up `Warn` to *after* the guarded advance (rather than after gating on a separately-computed flag) means the not-abandoned path physically cannot reach the log call — no separate "and don't log" condition to keep in sync.

## Lessons learned

From the PR body (developer-flagged, non-obvious):

- **`Config.Pending` cannot dequeue the head on its *first* call and still reach give-up.** The drain sets `firstFailedAt` *after* `Pending` returns, so a removal fired on call one leaves the elapsed window at ~zero — it never crosses `GiveUpAfter`. Firing on the second call works, and making that deterministic (no sleep) needs `RetryInterval` set **wider** than `GiveUpAfter` (250ms vs 50ms in the test): `sleepCtx` returning `true` then guarantees the second failure is past the bound.
- **The two rows that leave the FIFO empty (give-up `[A]`, success `[A]`) have no delivery left to observe, and for the give-up rows `OnGiveUp` is exactly the event under test never firing.** Their only happens-after signal for "the advance has actually happened" is the `draining` flag the drain clears on its way out, read under `q.mu`. Without gating on that flag, a test's follow-up `Enqueue` can land *before* the advance completes, silently turning the nil-slice row into a duplicate of the two-message row — the row goes green under the id-only half-guard alone, and the matrix stops discriminating between the two guard defects it's designed to catch.

## Testing

`go test -race` on `internal/msgqueue` (plus `-count=20` on the four new rows: 80/80 pass, counted from `=== RUN` lines, not the exit code) and `go vet ./...` pass; `staticcheck`, `make cite-guard`, and `go build ./cmd/pyry` are clean. Code review (PASS) independently reproduced the half-guard matrix via `-overlay` mutants carrying a single conjunct each — length-only reddens rows 1 and 4, id-only reddens rows 2 and 3, confirming no conjunct is redundant — and confirmed `advanceLocked`/`giveUp` have no call sites left unconverted. One SHOULD FIX was raised and left for a follow-up (not blocking): `head_advance_test.go`'s "no give-up warning names it" assertion is a negative pin only — nothing in the package positively asserts the give-up warning message text, so a rename of the production string would go undetected by this suite.
