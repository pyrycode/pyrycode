# Ticket #881 — `archive_conversation` + `unarchive_conversation` wire verbs

Adds the two wire verbs that flip the durable manual-archive flag #880 shipped:
`archive_conversation` sets `Conversation.IsArchived`, `unarchive_conversation`
clears it. Both reply with the reused `conversation_updated` record so the
requesting client updates its own row without a re-list. Split from #821
alongside #880 (durable state) — this ticket is the wire-verb half, and is
#880's `SetArchived` primitive's first (and, as of this writing, only)
production caller.

## Implementation

Six production files touched, one new (`archive_conversation.go`), ~500 total
LOC — all daemon primitives (`SetArchived`, `Get`, `Save`,
`CodeConversationNotFound`, `ConversationUpdatedPayload`) pre-existed from
#880 or earlier, so the net-new surface is vocab + handler only, same shape as
#820/#822:

- `internal/protocol/codes.go` — `TypeArchiveConversation =
  "archive_conversation"` / `TypeUnarchiveConversation =
  "unarchive_conversation"`, in the conversations block after
  `TypeConversationDeleted`.
- `internal/protocol/conversations_write.go` — one shared
  `ArchiveConversationPayload{ConversationID string}` (id-only, serves both
  verbs; deliberately not a `DeleteConversationPayload` reuse despite the
  identical shape). Extends `ConversationUpdatedPayload` with `IsArchived bool
  json:"is_archived"` — **no** `omitempty`, placed right after `IsPromoted` to
  mirror `ConversationSummary` — so a client reads the flag on active rows too
  and can't confuse "restored" with "old daemon."
- `internal/protocol/envelope.go` — both constants added to `v1TypeSet` (a v1
  `dispatch.Route` write verb, not a v2 control frame; "wire message" in the
  title names the encrypted v2 transport, not the type partition).
- `internal/relay/handlers/archive_conversation.go` (new, ~135 LOC) — **one
  parameterized factory** `ArchiveConversation(reg ConversationArchiver,
  registryPath string, logger *slog.Logger, archived bool) dispatch.Handler`,
  registered twice (once per `archived` value) rather than two near-identical
  handlers. Flow: decode → `reg.SetArchived(id, archived)` (miss →
  `conversation.not_found`) → `reg.Get(id)` to snapshot the post-flip record
  for the reply (a `Get` miss — a concurrent `delete_conversation` racing
  between the flip and the read — also folds into `conversation.not_found`) →
  eager best-effort `reg.Save` → reply `conversation_updated` built from the
  snapshot.
- `internal/relay/handlers/rename_conversation.go` — one-line populate,
  `IsArchived: cv.IsArchived`, in the `Update` closure's reply-snapshot
  literal. Required because the shared `ConversationUpdatedPayload` gained a
  field: without this, renaming an archived conversation would silently reply
  `is_archived: false`, corrupting a client's archived/active partition.
- `cmd/pyry/relay.go` — four lines, both verbs in both the v1 `d.Register`
  block and the v2 `Handlers` map, reusing `convReg` and
  `resolveConversationsRegistryPath(instanceName)`.

`ConversationArchiver` is the consumer-declared minimal interface
(`SetArchived` + `Get` + `Save`) `*conversations.Registry` satisfies
structurally — same pattern as `ConversationRenamer` (#820) /
`ConversationDeleter` (#822) — see
[features/relay-package.md](../features/relay-package.md).

### Snapshot via `SetArchived` + `Get`, not an `Update` closure

`rename_conversation` snapshots inside a single `Update(id, fn)` closure under
one lock. This handler deliberately does **not**: #880 shipped `SetArchived`
as a dedicated single-field mutator specifically so the flip goes through code
that structurally cannot touch another field — stronger than a closure
convention. The handler therefore flips via `SetArchived`, then reads the
record back via `Get` for the reply. The two are separately-locked ops; the
only interleaving with an observable effect is a concurrent
`delete_conversation` removing the row between them, which surfaces as `Get`
returning `ok=false` and is handled as a `not_found` reject (the flip
committed but the record is gone, so there's nothing to project into
`conversation_updated`).

### Security-sensitive divergence from the rename template

Carries `security-sensitive`, copied verbatim from `delete_conversation.go`
(#822): the malformed branch logs `conn_id` **only** — never the decode `err`
(`*json.SyntaxError` can embed offending input bytes) and never
`conversation_id` (a decode failure leaves the struct partially populated, so
the field may hold raw attacker bytes). The not_found and success branches log
`conversation_id` as a structured slog field — by then it's either a
proven-real registry key (`SetArchived` returned hit) or never reached the
wire. Every reject replies with a fixed static string. The verb label used in
log/error strings is `env.Type`, a trusted dispatch-validated constant, never
attacker bytes.

Unlike delete, archive is **reversible** (unarchive restores it) — the
architect's security review notes this as strictly lower stakes than the
delete twin it clones logging discipline from; no elevated per-device gate
beyond pairing.

## Testing

- `internal/relay/handlers/archive_conversation_test.go` (new, ~404 LOC) —
  clones `rename_conversation_test.go`'s harness. Exercises both `archived=true`
  and `archived=false` registrations of the shared factory: archive success +
  persistence-across-reload, unarchive success, archive idempotent, unarchive
  idempotent, not-found for both verbs (registry unmodified, no id echo on the
  wire — including a path-injection-shaped id asserting no reflection),
  malformed for both verbs (`TestArchiveConversation_Malformed_DoesNotLeakPayloadBytes`
  asserts via a slog test handler that the malformed record carries no
  `err`/`conversation_id` field).
- `internal/protocol/conversations_write_test.go` — round-trip test for
  `ArchiveConversationPayload` against two envelope fixtures
  (`testdata/archive_conversation.json` / `unarchive_conversation.json`,
  differing only in `type`); `TestConversationUpdatedPayload_RoundTrip`
  extended with an `IsArchived` assertion, `testdata/conversation_updated.json`
  updated in lockstep with the new `is_archived` key.
- `internal/protocol/compat_test.go` — both types added to all three type
  lists; hardcoded v1 count bumped 19 → 21.

`go test -race ./...`, `go vet ./...`, `staticcheck ./...` pass.

## Lessons learned

- **Extending a shared reply payload obliges an audit of every existing
  producer, not just the new one.** `ConversationUpdatedPayload` had exactly
  one production producer before this ticket (`rename_conversation.go`).
  Adding `IsArchived` to the shared type without also patching that producer
  would have shipped a silent regression: renaming an archived conversation
  would reply `is_archived: false`, and a client trusting the reply over a
  re-list would misclassify the row as active. Code review explicitly checked
  for a third unpatched producer (`promote_conversation` has no handler) and
  confirmed both existing producers set the field correctly — this is a
  general pattern worth watching whenever a ticket extends a payload type it
  doesn't otherwise touch.

## Out of scope

- **Live fan-out to other connected clients**, same posture as rename/delete:
  the `conversation_updated` reply goes only to the requester; other clients
  see the change on their next `list_conversations`.
- **Reconciling manual archive with auto-archive `Sweep`.** `Sweep` still
  hard-deletes idle conversations via `Registry.Delete`, unrelated to this
  soft-state flag — see [codebase/880.md](880.md) and
  [features/conversations-auto-archive.md](../features/conversations-auto-archive.md).
