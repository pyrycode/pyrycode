# Ticket #1154 — Real-claude e2e: permission round-trip under `interactive_runner: "stream-json"`

Adds `TestInteractiveStreamModalResolution`, the stream-json variant of #1030's
real-claude permission round-trip — the desktop#483 scenario on the real
stream stack. It drives a live `claude --model haiku` to a genuine Bash
permission modal under `interactive_runner: "stream-json"`, answers
`allow_once` from a phone paired `--allow-remote-permissions`, and asserts the
turn observably resumes to completion. Per the always-a-real-claude-gate
policy (2026-07-08), this is the third rung after the fake-tier stream
round-trip (#1139) and the real-tier PTY round-trip (#1030): it proves the
stream-json cutover target end-to-end against live claude before the Mac
daemon is flipped.

It is a **sibling** of #1030's `TestInteractiveModalResolution`, not a
replacement — #1030 stays on the default PTY runner; this test sits alongside
it as the stream-path proof (desktop#483 is exactly PTY-red vs. stream-green).
Scope is answer-only (approve); the cancel phase (#1030 Phase B) is out of
scope.

## Implementation

- `internal/e2e/realclaude/interactive_stream_modal_resolution_test.go` (new
  file, `//go:build e2e_realclaude`, PR #1162). Test-only, zero production
  files — pure composition of two already-shipped real-claude tests.
- `startStreamModalResolutionHarness(t) (*perConvHarness, string)` — an inline
  copy of #1030's `startModalResolutionHarness` with exactly one inserted
  line: `writeStreamInteractiveConfig(t, home)` (#1153) before
  `spawnPermissionDaemon` — the stream-vs-PTY differentiator and the entire
  reason this file exists. Everything else is identical to #1030's harness:
  pairs the phone WITH `--allow-remote-permissions` (the answer-side device
  gate — without it `ResolveAnswer` denies and the turn never resumes), seeds
  the bootstrap pool id + a bound conversation, spawns via
  `spawnPermissionDaemon` (no `--dangerously-skip-permissions`, so real claude
  actually raises the modal), drives the handshake.
- Fresh seed constants `streamModalBootstrapUUID` /
  `streamModalConvID` (`7777…`/`5555…`, valid UUIDv4 shape) — distinct names
  and literals from both #1030's (`liveModalBootstrapUUID`/`liveModalConvID`)
  and #1153's (`streamBootstrapUUID`/`streamConvID`) fixtures, so no file in
  the package redeclares a name.
- `TestInteractiveStreamModalResolution` — #1030 Phase A (answer only) on the
  stream stack: raises a real permission modal via `raiseRealPermissionModal`
  (#1030, reused verbatim — owns the AC1/AC2 non-vacuity gate:
  `modal_shown{Class:"permission"}` + non-empty `ModalID` asserted before the
  answer is sealed), seals the `allow_once` answer envelope (lifted from
  #1030's Phase A shape), then drains via `drainForCompletedTurn` (#1153) —
  M1 non-empty `assistant_delta` followed by M2 terminal `turn_state{idle}` —
  instead of #1030's `drainForAssistantReply` (M1 only). This is the AC3
  upgrade: "modal answered but the turn never resumed" now fails loud at M1,
  "delta but never idle" fails at M2, neither greens vacuously.

## Patterns established

- **Composing two prior real-claude tests with zero new production surface
  and zero edits to existing files** is a stable idiom once both source
  tickets exist: reuse every symbol verbatim (harness shape, trigger, drain),
  add only the one line that differs, and give the new file its own seed
  constants. No new package-private helper was needed here — #1153's
  `writeStreamInteractiveConfig` being a standalone config-writer (not folded
  into a spawn wrapper) is exactly what made this composition a one-line
  delta instead of a fork.
- **Inline the harness copy rather than parameterize the sibling's shipped
  helper.** Adding a "write stream config" hook to #1030's
  `startModalResolutionHarness` would edit another ticket's test file
  (file-overlap risk) for a one-line difference. Confirmed again after #1153
  set the precedent — every real-claude test in this package inlines its own
  setup sequence rather than branching a shared harness.
