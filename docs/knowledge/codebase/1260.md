# Ticket #1260 — capture, verbatim, every stream-json line the daemon drops on the interactive surface

Adds `internal/e2e/realclaude/dropped_line_capture_test.go` (env-gated
`PYRY_PROBE_DROPPED_LINE_CAPTURE=1`) plus its committed capture,
`testdata/dropped_lines_v2.1.220.json`. Four downstream tickets (#1261–#1264)
need to map claude's `system/*` and `rate_limit_event` messages, and until
this ticket nobody had ever read one — the record was type names and counts,
taken on the headless surface, not the interactive one that matters (#1218
already proved the two surfaces don't share subtype rates). This ticket
changes no drop behaviour; it reads what is already on the wire and writes it
down. Spec: `docs/specs/architecture/1260-dropped-line-capture.md` (includes
the architect's security review, PASS after one FAIL round with 4 MUST FIX).
PR: #1349 (branch `feature/1260`). Zero production files, zero modified
files.

## Implementation

- **The tap is production's own parser slot, not a hand-rolled `exec.Cmd`.**
  The probe drives `streamsup.Runner` in process and installs `dropcapRecorder`
  as `Config.Stdout` — the exact slot `cmd/pyry/streamsup_runner.go:117`
  assigns `streamsup.NewParser(...)` in production. "Upstream of the parser"
  is structural, not argued, and the argv comes from production's own
  `buildArgs`, never transcribed.
- **`spawn_shape` is observed, not transcribed.** A `slog.Handler` that writes
  nothing and keeps only the argv from the runner's own `spawning claude` log
  record doubles as the explicit discard handler `Config.Logger: nil` would
  otherwise skip (`runner.go:233-235` falls back to `slog.Default()`, which
  would leak lifecycle lines into CI output). This is the standout idea code
  review called out: the recorded argv cannot drift from the shape it claims
  to measure.
- **Classification asks the shipped parser, never mirrors `ignoredLineTypes`.**
  `parseOne(t, line)` (fresh parser per line, licensed by the parser's
  documented turn-statelessness) decides drop vs. surface; zero events and a
  non-`{assistant,user,result}` type means `ignored-line-type`, zero events on
  a `user` line means `user-block-suppressed`, zero events on `assistant`
  means `empty-message`. Control rows (`result`, an `assistant`/`text` line)
  keep the zero-event assertions from passing vacuously.
- **Three outcomes, only one licenses an absence claim.** `fired` requires the
  pre-rendezvous `fifoLiveRead` to read `no-reader`, the rendezvous to fire,
  and the turn-end read to be `reader-present` — the pre-read control is what
  makes the post-read non-vacuous. `did-not-fire` is a legitimate published
  result per AC1, not a failed test. `instrument-broken` licenses no claim of
  any kind. `absence_claim_valid` is its own boolean tied to `outcome=="fired"`.
- **Two unbounded-input caps, both non-silent.** The partial-line accumulator
  is capped at 4 MiB (same value and reason as `defaultMaxParseBuf`,
  `parser.go:13-19`) — past it the partial is dropped and counted into
  `partials_dropped`, never grown without bound. Total capture is capped at 8
  MiB, dropping whole lines only (never mid-payload) and counting into
  `lines_dropped_over_cap`/`bytes_dropped_over_cap`. Both closed a MUST FIX in
  the architect's first security-review round (the first draft capped only
  the total).
- **Payload encoding is decided per entry, never blanket.** Valid UTF-8 goes
  in as `payload` (`payload_encoding: "json-string"`); anything else is
  base64 (`payload_b64`, `payload_encoding: "base64"`) — `truncateRaw`'s
  `strings.ToValidUTF8(…, "")` silent-mutation trap, the exact failure mode
  the ticket calls out, is what this sidesteps. No payload is ever truncated
  or stripped of invalid bytes without the record saying so.
- **Redaction is two mechanisms with different fabric.** (a) `dropcapRedact`
  — a declared substitution table (temp `$HOME`, operator `$HOME`,
  `os.TempDir()`, artifact dir, workdir, FIFO path, session UUID, prompt
  nonce; each path class carries both its raw and `filepath.EvalSymlinks`
  form) applied to **every** string that enters the record, not only
  payloads — `fifoLiveOutcome.Path`/`.Detail`, `spawn_shape`,
  `outcome_detail`, and every `t.Logf` all leak an absolute path with no
  payload involved otherwise. (b) `dropcapDenyScan` — a fail-closed scan over
  the whole marshalled record, checked against credential env values (never
  stored, never logged, needles only), `sk-ant-`, and path-prefix literals,
  both raw and JSON-escaped. A hit is `t.Fatalf` naming only the class and
  entry index — never the payload or matched value — and no file is written.
  Substitution is best-effort and declared; the scan is the deterministic net
  behind it.
- **Minimum-needle-length rule, scoped to dynamic needles only.**
  `bytes.Contains(x, []byte(""))` is always true, so an empty/short
  credential value would match nearly everything; needles under 16 bytes are
  skipped and reported via `credential_scan_applied: false` so a
  non-running arm can never read as a clean arm. Fixed literals (`sk-ant-`,
  `/Users/`, 7 bytes) are exempt from the floor — code review's first round
  found this distinction stated only for dynamic values in the spec but
  applied blanket in an early draft; it now applies only where the hazard
  actually is (a value unknown at authoring time).
- **Teardown order is load-bearing and was wrong in the spec's first draft.**
  `t.Cleanup` runs LIFO, so the record-writing cleanup registers **first** so
  it runs **last** — the architect's own spec text had the arrows backwards
  (a code-review MUST FIX on the spec, not the code) and would have led a
  developer to lose the evidence on a mid-test `t.Fatalf`.

## What the capture found

Committed capture, claude 2.1.220, `outcome: fired`,
`absence_claim_valid: true`: 49 lines captured, 39 dropped —
`system/init` ×1, `system/thinking_tokens` ×33, `system/task_started` ×1,
`system/task_updated` ×1, `system/background_tasks_changed` ×1,
`rate_limit_event` ×1, and the suppressed `user`/`text` harness-nudge block
×1. `task_notification` is named explicitly in `expected_absent` — a stated
measurement, not a silent zero. The nudge block matched `harnessNoOutputNudge`
byte-exactly (`harness_nudge.matches_shipped_constant: true`) — the second
confirmed observation that constant's doc comment (#1247) asks for before
promoting it from a lone string to a set; that promotion is out of scope here
(Open question 4 in the spec).

`task_started` carries `task_id`/`tool_use_id`/`description`/`task_type`,
`task_updated` carries `patch:{is_backgrounded:true}`,
`background_tasks_changed` carries the `tasks[]` array, `rate_limit_event`
carries `rate_limit_info{status,resetsAt,rateLimitType,overageStatus}` — real
mapping material for #1261–#1264.

The capture is one turn on `--dangerously-skip-permissions` (the YOLO
session bit) with `--model haiku`; `spawn_shape_delta` states the absent
`--mcp-config`/`--permission-prompt-tool`/`--settings` flags production adds
on the non-yolo arm, so this `system/init` is the yolo variant and cross-shape
parity is unmeasured (AC5/Open question 1).

## Patterns established

- **A recorder that taps a production seam beats one that transcribes a
  production shape.** Reusing `Config.Stdout` and `buildArgs` made "upstream
  of the parser" a structural claim; observing `spawn_shape` through the
  runner's own log line rather than re-typing the argv is the same
  discipline applied a second time in one file.
- **A redaction pass over payloads only is not a redaction pass.** Every
  metadata field that carries a rig-controlled path (`fifoLiveOutcome`,
  `outcome_detail`, log lines) needs the same substitution as the payload
  bytes; a boundary defined as "the payload" undercounts the boundary that
  actually matters ("everything that reaches a public artefact").
- **A deny-scan needle must never be shorter than the class's own metadata
  key.** See Lessons learned — `credential_scan_applied` shipping inside the
  same record it describes is the general shape: a fail-closed net's own
  bookkeeping is part of what it scans.

## Lessons learned

From the PR body and the code-review round (FAIL, 3 SHOULD FIX, no MUST FIX —
all three fixed before merge, no re-capture needed since the committed
capture has zero base64 entries):

- **A deny class must not contain its own needle.** `credential_scan_applied`
  ships inside the record keyed by class name; a class literally spelled
  `"sk-ant-prefix"` made the scan hit its own metadata — a fail-closed net
  that can never pass, indistinguishable from a real leak. Caught by the
  first live run, not by review. `TestDropcapDenyClassNamesDoNotCarryTheirNeedle`
  is the guard.
- **A path leaks in spellings a path table does not enumerate.** claude's
  `system/init` carries `memory_paths.auto` with every `/` and `_` rewritten
  to `-`. Neither the raw/`EvalSymlinks` substitution rules nor the
  slash-bearing deny needles could see the slug form, so a per-user
  `$TMPDIR` component was one commit away from a public fixture. Fixed on
  both sides: slug spellings added to the substitution table, and ≥16-byte
  path *segments* (not just full paths) added as deny needles, since a
  segment survives any re-spelling that keeps it contiguous.
- **The minimum-needle-length rule has to be scoped to dynamic needles.**
  Applied blanket it would have disabled the fixed literals (`sk-ant-`,
  `/Users/` are both under 16 bytes) while reporting them as "not applied" —
  the hazard the floor exists for is a value unknown at authoring time, not
  shortness per se.
- **Two SHOULD FIX findings were holes in the base64 arm of the deny-scan
  specifically** — `HarnessNudge.PayloadB64` was omitted from both the live
  rescan loop and the offline fixture-validation scan, despite the function's
  own doc comment claiming full coverage. Any field added to a record after
  the "scan everything" helper was written needs an explicit check that the
  helper actually reaches it; a doc comment asserting completeness is not
  evidence of it.
- **A redaction kept-list needs to name the largest operator-derived class,
  not just claude-generic categories.** The committed `system/init` payload
  carries the operator's local MCP server names, slash-command names, skill
  names, and agent names — code review's third SHOULD FIX was that the
  `redaction_rationale` prose didn't say so, leaving the person deciding
  whether to paste the record into a public issue with no signal that this
  class exists at all.
- **One diagnostic command was denied mid-run** (`rm -rf` plus a direct
  `claude` invocation in the scratchpad, to locate the first deny-scan hit)
  and wasn't needed — the hit was localised by reasoning and the probe
  itself. `dropcapLocateHits` now names the class and entry index on a hit so
  the next operator doesn't need that detour.

## Deliberately not built here

- **Promoting `harnessNoOutputNudge` to a set.** The second confirmed
  observation this ticket delivers is exactly what the constant's doc
  comment (#1247) asks for before that promotion, but the promotion itself
  is a `internal/streamsup/parser.go` change and stays a follow-up ticket
  (Open question 4).
- **A non-yolo-arm capture**, to measure whether `--dangerously-skip-permissions`
  changes the `system/task_*` set (Open question 1) or the census is
  model-dependent beyond haiku (Open question 2). Both stated as unmeasured
  limitations, not assumed away.
