# Ticket #1495 — chunk the coalesced `assistant_delta` under the v2 envelope cap

`flushDelta` emitted the whole coalesced `deltaBuf` as one `assistant_delta` with no byte bound. The coalescer concatenates every `TextChunk` sharing a `MessageID`, and a stream-json line is bounded only by `defaultMaxParseBuf` (4 MiB), so one flush could seal a `protocol.Envelope` past the 65519-byte v2 application-envelope cap (`docs/protocol-mobile.md` § Application-envelope size cap). A spec-conforming phone rejects the over-cap frame while `turn_state`/`turn_end` arrive normally — a completed, empty turn — and the `eventring` retains the oversized event so every reconnect replay re-fails identically. This ticket caps the wire, not the buffer: `flushDelta` now loops over rune-safe chunks of the flushed text, each under the cap, with `seq` advancing once per emitted envelope.

## Implementation

- `maxDeltaTextBytes = 10000` (`cmd/pyry/interactive_turn_v2.go`, next to `coalesceWindow`) bounds **raw input text**, not the envelope — named deliberately unlike `maxDeltaEnvelopeBytes` so nobody "corrects" it toward 65519. Sized against the true worst case: `encoding/json`'s default `SetEscapeHTML` turns `<`, `>`, `&`, and unescaped control bytes into six-byte `\uXXXX` forms — 6× is the ceiling because the cut is a **byte** cut; multi-byte runes are not the worst case (Go emits them raw, so a 4-byte emoji stays 4 bytes). `10000 × 6 = 60000` B of escaped text + a 512 B budget for everything else (payload keys/punctuation, `conversation_id`/`turn_id` as 36-byte UUIDs, `seq` digits, the envelope's `id`/`type`/`ts`/`payload`/`event_id` frame) = 60512 B, ~7.6% under the cap. Same shape as `internal/relay/v2bundlestream.go`'s `bundleChunkBytes`: the constant is the belt, the per-frame cap test is the suspenders (different fabric), and the comment says explicitly — if the cap test ever fails, **lower** this constant, never raise it.
- `splitDeltaText(s string, max int) []string` — pure, package-level splitter. Chunks are substrings of `s` (no copy, no re-encoding), so `strings.Join(chunks, "")` reproducing `s` byte-for-byte is structural, not hoped-for. Cut points back up from the stride boundary to the nearest `utf8.RuneStart`; a degenerate guard (cut at the unadjusted stride instead) covers the case where `max` consecutive continuation bytes would otherwise walk the cut back to `start` and hang the loop on claude-controlled input — defence in depth, since `e.Text` already reaches here through `encoding/json`'s decode, which substitutes U+FFFD for invalid UTF-8.
- `flushDelta` captures `text`/`convID`/`msgID` into locals before the loop (the trailing reset clears the struct fields), then for each `splitDeltaText` chunk: builds a synthetic `turnevent.TextChunk{MessageID: msgID, Text: chunk}`, calls `emitMapped`, then `e.seq++` — **inside** the loop, after each emit, because `emitMapped` reads `e.seq` off the struct. A buffer that fits emits exactly one chunk, one `emitMapped`, one `seq++` — byte-identical to pre-#1495 behaviour, which is why #609's coalescing/seq tests stay green unmodified.
- No `ctx.Err()` check between chunks (deliberate) — abandoning remaining chunks on teardown would turn a shutdown race into silently truncated assistant text; `emit` already returns early inside its `Push`-error branch, bounding the wasted work to one conn snapshot per remaining chunk.
- No new log field. The chunk loop adds no `slog` call; a tempting `"chunks", len(chunks)` field would leak assistant-text length, which the emitter's existing "lengths-free discriminants" rule excludes.
- New test file `cmd/pyry/interactive_turn_v2_chunk_test.go` (344 lines): `TestSplitDeltaText` (table test on the splitter alone, including CJK/emoji fills chosen so stride boundaries land mid-rune), `TestInteractiveTurnEmitterV2_OversizedDeltaFitsEnvelopeCap` (ascii/html/cjk/mixed fills, asserts every emitted `protocol.Envelope` — not just the payload — marshals under a test-local `maxV2AppEnvelope = 65519`, and that concatenating `Text` in emission order reproduces the fed buffer byte-for-byte), `TestInteractiveTurnEmitterV2_UnderCapDeltaEmitsExactlyOne` (pins the `maxDeltaTextBytes`/`+1` boundary), `TestInteractiveTurnEmitterV2_OversizedDeltaNoLogLeak` (marker-absence check with `pushErr` forcing the log-heavy path on every chunk).

## Patterns established

- **A conservative raw-byte constant plus a deterministic per-frame cap test, comment-documented "lower never raise."** Second instance of the `bundleChunkBytes` shape in this repo — the pattern for capping a wire frame against `encoding/json`'s worst-case HTML-escaping expansion (6×, driven by `<`/`>`/`&`/control bytes) rather than the more common but wrong assumption that multi-byte UTF-8 is the worst case.
- **Cap the flush, not the source.** The fix landed at the one point that sees the concatenated size (`flushDelta`), not at the parser (`parser.go`, sees one block) or the mapper (`turnbridge.MapEvent`, sees one block) — both were explicitly left untouched so the limit is decided in exactly one place.

## Lessons learned

- The spec's mutant→red-row matrix named `<`→`<=` "in the stride comparison" as a row-C mutant. Taken literally on the loop guard (`start < len(s)`) it is an **equivalent mutant** — the `end >= len(s)` arm `break`s, so the guard is never re-evaluated after the final chunk and no trailing empty chunk can form. The off-by-one that row C actually pins is the stride *width* (`end := start + max` ± 1) and the bound the flush passes; those redden as specified. Worth re-deriving a surviving mutant before reading it as a coverage hole rather than an equivalence.
- The 512-byte non-text envelope budget in the constant's comment is ~2.3× the observed cost (~220 B measured against the test's small ids/UUIDs). Recording measured-vs-budgeted explicitly in the comment (rather than just the derived total) lets a future reader see which number is headroom and which is fact — the measured worst case (the `<` fill) is 60220 B, 91.9% of the cap.
