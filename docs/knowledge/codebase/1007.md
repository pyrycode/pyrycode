# Ticket #1007 — session_error wire vocabulary (v2-only type, terminal code, conversation-scoped payload)

Wire-vocabulary half of the split at #1001's second seam: `internal/msgqueue`'s bounded persistent-failure drain (#1000) gives up via the `OnGiveUp` seam, but until this ticket that give-up produced no client-visible frame. This ticket adds the dedicated v2-only `session_error` type, the terminal `session.blocked` code, and the conversation-scoped `SessionErrorPayload` — the vocabulary a later producer (blocked-by-this sibling #1008) will use to surface the give-up as a typed frame a client attaches to the right session and never mistakes for a transient retry. Ships **unwired**: no producer, emission, or consumer this ticket.

## Implementation

- `internal/protocol/codes.go`:
  - `CodeSessionBlocked = "session.blocked"` added to the existing "Session errors" group (alongside `CodeSessionNotFound`) — terminal, distinct from the transient `CodeServerBinaryBusy` (`server.binary_busy`).
  - `TypeSessionError = "session_error"` in its own trailing const block, mirroring the `TypeSessionTransition` precedent (own block, own doc comment, MUST-NOT-join-`v1TypeSet` instruction, sibling-ticket producer pointer).
- `internal/protocol/messaging.go`: `SessionErrorPayload{ConversationID, Code, Message}` next to `QueueStatePayload` / `SessionTransitionPayload`. All three fields are plain `string`, no `omitempty` — always present on the wire. Deliberately **no** `Retryable` / `RetryAfterS`: their structural absence, not a runtime check, is what prevents a client reading the frame as transient.

## Patterns established

- **Wire vocabulary → producer is a two-ticket granularity, and the "unwired" ticket still touches guard/partition tests.** Consistent with #720→#722, #844→#845, #656→#657: the vocabulary-only ticket is never *just* the new type + payload — it also has to satisfy every existing totality/drift guard that enumerates `Type*` constants. A new v2-only `Type*` const trips **two** independent guards in this repo, not one: `internal/protocol/compat_test.go`'s `TestTypeConstants_V1V2Partition`, and `cmd/pyry/relay_guard_test.go`'s `excludedTypes` map (which forces classifying the new type as `"push"`, since it's outbound-only). Both must be updated together or CI fails even though nothing is wired yet.
- **Unsolicited terminal give-up needs its own type, not a reused `TypeError`.** `TypeError`/`ErrorPayload` is v1-compatible and always `InReplyTo`-correlated to a client request; a give-up has no such request. The distinguishing structural signal for "don't retry" is the *absence* of `Retryable`/`RetryAfterS` fields on the payload type itself, not a runtime flag — same posture the codebase already uses for `TypeStall` vs. a real error.
