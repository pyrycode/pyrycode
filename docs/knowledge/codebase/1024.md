# Ticket #1024 — move `set_session_settings` handler out of `v2session.go`

Fourth slice of the [#964](https://github.com/pyrycode/pyrycode/issues/964)
split of `internal/relay/v2session.go`, chained after
[#1021](1021.md) (handshake), [#1022](1022.md) (rekey), and [#1023](1023.md)
(modal+queue). Carves the `set_session_settings` verb handler — the
interactive settings-update path (#845) — plus its static reply-message
constants and its `validModel`/`validEffort` validators into a new file in
the same `package relay`. Pure mechanical move: no exported-API change, no
behaviour change, and because everything stays in-package, zero call-site
changes anywhere in the tree.

## Implementation

New file `internal/relay/v2session_settings.go` (239 lines) now owns five
declarations, moved verbatim with their doc comments: the `msgSettings*`
static reply-message `const` block, `handleSetSessionSettings`,
`settingsReplyError`, `validModel`, and `validEffort`. `v2session.go` drops
by 221 lines, from 2307 to 2086.

The cut was a single clean span (1434–1653 pre-move), bounded above by
`bundleInFlight` and below by `SetReplaySource`, with nothing
settings-unrelated interleaved — confirmed by the diff, which touches only
that one contiguous block.

The `SettingsUpdate` struct + `SettingsUpdater` seam interface and the
`V2SessionConfig.SettingsUpdater` field **stay in core**, per the ticket's
Technical Notes — they're shared seam types owned by a later
seam-interfaces slice. The moved handler references them by unqualified
name; the reference resolves in-package with no edit needed. Two stay-put
references were confirmed untouched: the sole call site
`m.handleSetSessionSettings(ctx, s, probeEnv)` (`v2session.go:1045`, inside
`dispatchAppFrame`'s pre-`dispatch.Route` interceptor) and a comment at
`v2session.go:359` mentioning the handler by name (prose, not a symbol).

Imports were **compiler-forced to zero net change**, exactly as the spec
predicted: `v2session.go`'s import block is byte-identical pre/post-move
(diff shows only the 221-line deletion, no import hunks) — `context`,
`encoding/json`, `errors`, `time`, and `internal/protocol` are all still
used elsewhere in the 2086-line file. The new file imports the same five
packages for its own use.

## Patterns established

None new — the fourth consecutive confirmation of the #964 pure-move
discipline. This slice's notable variant: unlike #1022/#1023 (where the
move forced an import off the donor file), here the donor file's import
set needed **no edit at all** — every import the moved block used was also
used elsewhere in `v2session.go`. Confirms the #1022/#1023 lesson from the
other direction: "does this import stay" is answered by checking every
remaining `pkg.Ident` call in the donor file, not by assuming a move always
orphans something.

## Lessons learned

None — the move went exactly as scoped in the architecture spec, with no
surprises in the cut boundary, the stay-put references, or the import
delta. Worth reconfirming the recurring theme across all four #964 slices:
the strongest security lineage yet (untrusted model/effort validation, the
argv-injection defense from #845) still correctly stayed **not
security-sensitive** — a pure same-package move carries zero new design to
audit, no matter how sensitive the moved code's original design was.

## Verification

`go build ./internal/relay/...` clean. The diff touches exactly the two
intended files (`v2session.go`, `v2session_settings.go`) plus this ticket's
architecture spec — no other file in the tree changed, and
`v2session_settings_test.go` (pre-existing, from #845) was left
byte-for-byte untouched, confirming the move is transparent to it.
