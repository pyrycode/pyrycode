# Ticket #1379 — Make the realclaude mirror of the parser's ignored types subtype-granular

`parserIgnoredTypes` (`internal/e2e/realclaude/ptyrunner_byte_equivalence_test.go`) mirrors `internal/streamsup`'s drop behaviour so `extractShapes` can filter the runner-equivalence **sequence** comparison down to the alphabet the shipped parser actually maps ([`codebase/1218.md`](1218.md) built this filter). It was keyed by top-level stream-json type only, so the entire `system` family was dropped from the comparison. Since #1380/#1381 the parser maps three `system` subtypes (`task_started`, `task_updated`, `background_tasks_changed`) into background-task events — the mirror kept dropping those too, so the two runners could diverge on any of them with the gate green. Test-only fix, no production file touched.

## Implementation

- **`parserIgnoredTypes` changed shape**: `map[string]struct{}` → `map[string]parserMappedSubtypes` where `parserMappedSubtypes = map[string]struct{}`. `system` now carries `{"task_started", "task_updated", "background_tasks_changed"}` as its mapped (surviving) subtypes; `rate_limit_event` carries `nil` (no exceptions — the whole type still drops). The outer key set is unchanged (`system`, `rate_limit_event`), which is what let the member-has-fixture and orphan-fixture checks keep working unmodified.
- **`parserDropsShape(typ, subtype string) bool`** — new predicate, placed right after the mirror. Type absent from the map → survives (`false`). Type present, subtype in its mapped set → survives. Otherwise → dropped. Directly reproduces `streamsup.consumeLine`'s drop branch: the top-level `ignoredLineTypes` gate first, then `emitSystemSubtype`'s case arms carving mapped subtypes out from inside it.
- **`shapeFilterTypes()`'s flat three-table union replaced by `shapeFilterDrops(typ, subtype string) bool`.** The two one-sided allowlists (`expectedPtyRunnerOnly.Events`, `expectedStreamRunnerOnly.Events`) are still looked up by type alone — one-sidedness is a property of the type, and those tables also govern the SET check (`additiveDriftViolations`), which never consults `parserIgnoredTypes`. Only the third table's lookup gained the subtype parameter, via `parserDropsShape`. `extractShapes` lost its `filter := shapeFilterTypes()` prelude; `env.Subtype` was already decoded (`:233`), just previously discarded at the filter lookup.
- **`TestExtractShapes_FiltersParserIgnoredTypes`** — fixture extended with a mapped-subtype line (`system/task_started`, placed before `assistant` to exercise survivor order) and a never-seen-subtype line (`system/some_unmapped_future_thing`). `want` gains `{Type: "system", Subtype: "task_started"}` as its first element. The survivor assertion (`:944`) re-keyed from `parserIgnoredTypes[sh.Type]` to `parserDropsShape(sh.Type, sh.Subtype)` — forced by the new fixture, since the old expression would fire on the surviving `task_started` shape.
- **`TestParserIgnoredTypesMatchesStreamsupParser`** — three new fixtures added to `parserIgnoredTypeFixtures["system"]`, each a bare `type`+`subtype` line (minimal, so no field beyond those two can trip an emitter's undecodable arm). The expectation per fixture line is now **derived**, not declared: a new `fixtureShape` helper decodes the line's subtype (also pinning it under the map key it's filed under), and the test asks `parserDropsShape(typ, subtype)` — dropped lines assert 0 events, mapped lines assert ≥1. A new mapped-subtype-has-fixture check (mirrors the existing member-has-fixture check one level down) fails if any subtype in a type's mapped set has no fixture line declaring it — closes the hole where a future fourth mapped subtype ships with nothing exercising it against the real parser.
- **Three stale "system is ignored wholesale" comments corrected**, each pointing at `streamsup.emitSystemSubtype` as the enumeration site rather than restating the mapped set (per the mirror's own doctrine: an unexported enumeration site in another package forces the mirror's *data* to restate, but prose must point — restating goes stale silently, the mirror's restatement doesn't because the pin test fails a build on drift):
  - `ptyrunner_byte_equivalence_test.go:941-942` — was asserting the *opposite* of this ticket's design ("a subtype-grained filter would leave system/init standing, which is the mistake this test exists to catch"). Rewritten to state the actual hazard: a composite `type/subtype` key would invert the open-set default and let every unwritten `system` subtype through (`system/thinking_tokens` alone fires ~10×/turn) — the never-seen-subtype fixture line is what trips this loop if that ever happens.
  - `interactive_stream_unrecognized_test.go:8-9` — `"system/*"` stays silent was false for three subtypes; corrected to state most `system` subtypes plus `rate_limit_event` stay silent, three map to background-task events.
  - `dropped_line_capture_test.go:1511` — `why: "system is ignored wholesale (parser.go:80-83)"` was false on both halves (the claim, falsified by #1380/#1381; the cite, stale since `ignoredLineTypes` moved to `parser.go:247-250` in the same tickets). `dropcapClassify` itself needed no change — it already runs every line through the real parser and is subtype-correct by construction; only its prose row was stale.

## Patterns established

- **A mirror's *data* may legitimately restate an unexported enumeration site that its prose must only point at.** The distinguishing fact isn't which package the code lives in — it's whether drift **fails a build**. `TestParserIgnoredTypesMatchesStreamsupParser` pins the mirror against a real `streamsup.Parser`, so a stale mapped set goes red; the four prose comments carry no such backstop (two of them were already stale before this ticket), so they may only point at the one enumeration site (`streamsup.emitSystemSubtype`) rather than restate it.
- **An expectation *derived* from the table under test, rather than declared alongside each fixture, makes a vacuity trap self-detecting.** `emitBackgroundTask*`'s undecodable-payload arm returns "consumed" with zero events — a fixture that trips it would be green before *and* after a naive fix, proving nothing. Because the pin test asks `parserDropsShape` what a fixture *should* do rather than hard-coding "expect 0", a fixture that decodes wrong is classified MAPPED by the mirror and fails the `>= 1` assertion outright — it cannot ship silently, and the RED run's job shifts from "prove the fixture isn't vacuous" to "prove the fixture discriminates" (a green RED run is still a failed experiment, not an early finish — see Lessons learned).
- **The ignored side of a drop table must stay an open set when the drop-worthy alphabet is unenumerable.** A composite `type/subtype` key looks like the obvious generalization from a type-keyed one but inverts the default: everything not written down starts surviving. The correct generalization enumerates only the **exceptions** to a type's drop (`parserMappedSubtypes`), keeping "unlisted subtype" mean "still dropped."

## Lessons learned

(From the PR body — developer's notes, lightly trimmed. Independently reproduced by code review.)

- **A mutation that fails to apply reads exactly like a fixture that doesn't discriminate.** The first RED run came back all-PASS; the cause wasn't the fixtures but a `sed` pattern building the mutant that didn't match the target line's trailing comma, so the "mutant" was a byte-identical copy of the green tree. Reading that output as a genuine negative result would have sent debugging toward the fixtures instead of the harness. Fix made standard: `diff` the mutant against source and require the expected changed-line count before running it, so an all-PASS overlay run can only mean the subject is actually green.
- **The vacuity trap is self-detecting under the derived-expectation design, but that's a different property than "the RED run proves the fixture is good."** A fixture that fails an emitter's inner decode emits zero events, which the mirror (correctly) classifies as MAPPED — so it fails the `>= 1` assertion in the GREEN run and can't ship silently. That protection is *why* a bad fixture never ships, but it does not mean the RED run is optional: RED is what proves the fixture *discriminates between mirror states*, a property the GREEN-run self-detection alone doesn't establish.

- Three NITs, none requiring a fix: `parserDropsShape`'s two-bare-string signature (correct as built — both call sites hold `typ`/`subtype` before any `envelopeShape` value exists); the subtype-collision `t.Run` tiebreaker from the spec's open question is wired only for the empty-subtype case (Go auto-suffixes `#01` on a name collision, so it degrades gracefully); **`docs/knowledge/codebase/1218.md:7,18` names `shapeFilterTypes`, which this PR renamed to `shapeFilterDrops`** — left unedited per the per-ticket-file convention (never edit a sibling ticket's file); this paragraph is that cross-reference.

## Out of scope (deliberately not touched)

- `internal/streamsup/parser.go`'s `ignoredLineTypes` — stays top-level-keyed by design; that's what keeps `emitUnrecognized` structurally unreachable from any `system` line regardless of subtype. Different table, different job, no production change.
- The two one-sided additive-drift allowlists (`expectedPtyRunnerOnly.Events`, `expectedStreamRunnerOnly.Events`) and `additiveDriftViolations` — untouched; they answer "is this one-sided emission tolerated?", a type-level question, and adding `system` to either would be factually false (both runners emit `system/init`).
