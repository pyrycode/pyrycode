# Ticket #1448 — Separate a sighting route that was never staged from one whose premise failed and one whose pid read did not answer (offline)

`trailClassifyRun`'s `trailGateAbsentOwesNone` arm consults #1440's pinned-pid
sighting route (wired by #1446) and, after #1447 took the measured refutation
off it, still published one value — `trailOutcomeVoidPathOwesNoReason` — for
three materially different runs: the route was never staged (every run that
exists today), the ordering was measured and a premise failed, or the pid
read did not answer. The first two were indistinguishable **even in the
route's own reason**, since `trailEstablishSighting`'s ordering guard fires
before the verdict switch and folds an unfilled ordering into the same
`sighting-reason-ordering-uncertified` a real premise failure produces. This
ticket gives the never-staged case a value of its own and gives the run-level
record a field that carries the route's own reason, so a reader separates all
three from the published bytes without parsing the Detail's prose.

PR [#1451](https://github.com/pyrycode/pyrycode/pull/1451). Split from #1444
(itself split into #1446 → #1447 → #1448). Blocked by #1446 (merged) and
#1447 (merged, `45806e6`) — both closed before this ticket reached an
architect. Security-sensitive (architect self-review PASS). One code-review
FAIL round, entirely on the count-and-cite sweep tail; the separation itself
was never faulted.

## Implementation

- **A pre-decision about the classifier's own inputs, before the route is
  consulted.** Inside `case trailGateAbsentOwesNone`, a guard on
  `readings.Ordering.Value == ""` fires *before* `trailEstablishSighting` is
  called. The test is deliberately single-sided: `trailSightingReasonPidReadFailed`'s
  own doc already names the unfilled pin's zero `""` as a correct member of
  its space, so no guard is owed on that side; `trailSightingReasonOrderingUncertified`
  names only #1439's three `trailOrderVoid*` values, so an unfilled ordering
  has no home there and is the only side that needed a guard at all. An `&&`
  guard would have been worse than redundant — it falls through to the false
  "premise failed" reason on a half-staged pair. The route is still consumed
  whole and never re-decided: the guard reads `Ordering.Value` and answers
  before the predicate is called, re-litigating nothing the predicate
  returned.
- **The new value: `trailOutcomeVoidSightingRouteNotStaged =
  "run-void-sighting-route-not-staged"`**, inserted after
  `trailOutcomeVoidPinnedPidDidNotEstablish`. Its doc argues three separations
  in the family's house idiom: deliberately not `trailOutcomeVoidPathOwesNoReason`
  (that one is now "the route was staged and reported it could measure
  nothing"; this one is "there was nothing to read"); deliberately not
  `trailOutcomeOutOfContract` (an unfilled input on a gather that never
  stages it is a routine reading, not a caller's bug — the #1417 collapse,
  one value along, and the reason the no-C10 note stays a comment rather than
  a check); deliberately not a `run-`-prefixed transform of any sighting-space
  value (equality-only union-map comparison is blind to containment).
  `Route` and `RouteReason` are both `""` on this value — argued, not
  defaulted: no evidence class produced the verdict, its absence did.
- **The new field: `trailRunOutcome.RouteReason string
  \`json:"evidence_route_reason,omitempty"\`**, immediately after `Route`.
  Carries `sighting.Reason` through whole on both remaining sighting-void
  arms — `out.RouteReason = sighting.Reason` added beside each existing
  `out.Route = trailRouteSighting`. Published invariant, asserted on **every**
  row of `TestTrailClassifyRun`, not just the sighting ones: `RouteReason !=
  "" ⟺ Route == trailRouteSighting`, and when non-empty it is a member of
  `trailIsSightingReason`. The biconditional holds because `trailAdmitResult`
  (the reap-log route) is a two-field record with no reason space at all, so
  `trailRouteReapLog` can never publish one. `trailRunCase` gains a
  `wantReason` column rather than folding this into a `map[value]reason` —
  two rows reach the *same* value under two different reasons, which a
  value-keyed map cannot express and is the whole point of the ticket.
- **`Route`'s doc, discharged rather than left delegating.** `:441-454`
  previously read "#1448 owns whether those remaining cases ever name a
  route." Rewritten: the fall-through's value now *means* "the route was
  staged, was consulted, and reported it could measure nothing" once the
  never-staged case has a value of its own, so the route is named there too —
  `""` moves to the arm where no route was staged at all.
- **Detail budgets rendered, not read, and the split is the exchange.**
  `go test -overlay`, no worktree writes: the pre-split arm rendered 461 B /
  51 B headroom. Post-split: the never-staged arm renders **453 B** (59 B
  headroom), the remaining fall-through **459 B** (53 B) — both *shorter*
  than the arm they replace, because each new arm says one thing where the
  old one said two. Neither interpolates `PinnedPid.Verdict` or
  `Ordering.Value` — both prohibited explicitly in the spec, not just by
  omission, since `PinnedPid` is the one input this classifier has no
  contract check over and interpolating an unvalidated string would make
  this the first run-level arm to publish one.
- **Two new fixtures, both driving the real producers.**
  `trailRunSightingOrderingUncertifiedReadings()` (ordering measured and
  refused via `trailCertifyOrdering(false, true, true)`, pid deliberately
  **running** so the row proves ordering outranks the verdict rather than
  passing by keying on the pin) and
  `trailRunSightingPidReadFailedReadings()` (ordering certified, pid
  `pinStateInstrumentFailed`). Two new `trailRunCases()` rows reach
  `run-void-path-owes-no-reason` under the two different reasons — the pair
  that makes `RouteReason` non-vacuous, since a build publishing one fixed
  reason on the arm would pass with either row alone. The existing unstaged
  row (`trailRunAbsentOwesNoneReadings()`) is re-pointed to the new value; its
  doc is corrected from "leaves both zero and is the row that proves it" (now
  false — it's the never-staged fixture, not a mixed one).
- **Two new no-captured-bytes sweep blocks**, reusing the existing `sweep`
  helper verbatim. Block 4 (never-staged) plants the needle in
  `Ordering.Detail`, `PinnedPid.Detail`, `PinnedPid.ToolStderr`, **and in
  `PinnedPid.Verdict` itself** — the deterministic net for the Verdict
  prohibition above, reachable here because the guard fires on
  `Ordering.Value` regardless of what `Verdict` holds. Block 5
  (ordering-uncertified) carries the same four-way plant, added in the
  rework round once review noted the ordering guard fires regardless of
  verdict on *both* remaining arms, not just the never-staged one — and that
  `trailEstablishSighting` folds `pin.Verdict` verbatim into `sighting.Detail`,
  putting the captured string one dereference from that arm too. Block 4's
  premises (`Route == ""`, `RouteReason == ""`) assert record shape, not an
  anchor — both fields are `omitempty` and empty there, so its walked key set
  is a strict subset of blocks 2/3/5's; that is recorded in place so a later
  edit doesn't mistake block 4 for replacing the anchoring premises those
  blocks carry.
- **Registration, three sites plus the union map:** `trailIsRunOutcome`,
  `trailRunOutcomeValues()` (`len` assertion `!= 15` → `!= 16`), the union
  closure map, and `trailRunCertifiesNothingArms()` — the new value forecloses
  a finish-instant claim on the same certifies-nothing grounds
  `trailOutcomeVoidPathOwesNoReason` does, growing that list **five → six**,
  a *second* set the same commit moved that the architect's own count-cascade
  table did not enumerate (it only listed the fifteen → sixteen headline
  set). `finding_trailer_evidence_test.go`'s union `len(distinct)` assertion:
  `!= 22` → `!= 23`.

## Patterns established

- **A single-sided guard, read off the sibling reason constants' own docs
  rather than chosen.** When two inputs feed one predicate and only one of
  them has a documented "unfilled maps here" clause, testing the other input
  too is not caution — it produces a false positive on the half-staged case
  the extra test was meant to rule out. Read the reason space's docs for
  which side already absorbs the empty case before writing the guard.
- **A biconditional between a new field and an existing discriminant, checked
  on every row rather than just the rows expected to exercise it.** `RouteReason
  != "" ⟺ Route == trailRouteSighting"` running over the *whole* table (not a
  filtered subset) is what catches a future arm publishing a reason beside a
  route with no reason space, and it costs nothing on rows where both sides
  are trivially false.
- **A split-not-append Detail budget goal: both children should render
  shorter than the parent, not merely under cap.** Each new arm says one
  thing where the old arm said two; if a split renders longer than the
  original on either child, the split absorbed the wrong clause somewhere.
  [[po-1290-ac-mandates-unimplementable-and-false-prose]] is the sibling
  lesson for checking a budget claim against the shipped string rather than a
  draft; this ticket's contribution is checking it against the *pre-split*
  baseline too.

## Lessons learned

From the PR body's own "Lessons learned" section (developer):

- **A cite re-point is verifiable, not just mechanical.** Mapping old→new
  lines from `git diff -U0` is only half of it; the checkable invariant is
  that a cite names a *line of text*, so `old[old_line] == new[new_line]`
  must hold after the map is applied. That check re-pointed 130 cites and
  left exactly the 6 it could not prove — of which 4 were not cites at all
  (pids, ports, byte caps) and 2 were real ranges into rewritten code needing
  a human read.
- **Bare `(:NNN)` inheritance is same-line, left-to-right.** Tracking the
  last-named file per *line* rather than per *match* mis-attributes any bare
  cite sharing a line with a filename. Fixing it to update mid-line found 2
  more cites; the content check is what stopped the mis-attributed ones from
  being silently rewritten.
- **A symbol-anchored cite does not inherit the last-named file.**
  `trailRunOutcome:436 and finOutcomeResult (:198)` — the bare `(:198)`
  belongs to `finOutcomeResult`'s file, not to the one named earlier in the
  paragraph. A file-inheritance rule alone would have re-pointed it into the
  wrong file.

From code review (one FAIL round, one rework, then PASS):

- **A count-word sweep needs a sense table per hit, not a global replace —
  and per *set*, not per commit.** `trailRunCertifiesNothingArms()` grew five
  → six in this same commit whose headline cascade was fifteen → sixteen; the
  architect's spec table enumerated only the headline set, so seven sentences
  across two files describing the certifies-nothing carrier list still said
  "five" after the rework's first pass. Fixed by sweeping "five"/"six" **by
  sense** across both files, confirming each protected sense individually
  (the sighting predicate's own five-value set, "five obligations", the five
  reason-carrying rows, five blocks in the leak sweep, an ordinal "fifth")
  rather than trusting a bare grep. When one commit moves two sets, sweep
  once per set whose cardinality moved —
  [[code-review-sweep-derived-sets-not-just-the-headline-set]].
- **A "no fourth block" claim can be falsified by the fourth block 19 lines
  below it**, and a "two blocks" scope word by the same cascade that grew a
  count elsewhere in the same doc comment — both this ticket's version of the
  #1447 "route set on the finding alone" staleness pattern: a provenance or
  scope claim needs re-reading whenever the set it quantifies over grows,
  not just re-counting.
- **The `PinnedPid.Verdict` plant belongs on every arm the ordering guard
  reaches, not just the one it was first written for.** The spec argued the
  plant was "only possible" on the never-staged arm; code review's NIT (taken
  in rework) showed the ordering guard fires regardless of verdict on the
  fall-through too, and `trailEstablishSighting` folds `pin.Verdict` verbatim
  into `sighting.Detail` there — one dereference from the captured string.
  Verified with matched `go test -overlay` mutants (fall-through
  interpolating `readings.PinnedPid.Verdict`, and interpolating
  `sighting.Detail`): both die on the leak assertion, not the truncation
  marker, and block 5 is the sole RED for both.
- **The recurring cite trap in this family is the bare `(:NNN)` that inherits
  its filename from the previous line, across a line break the rework itself
  introduces.** The rework's own +10-line insertion staled a bare cite in
  `finding_trailer_evidence_test.go:62` that its own 139-cite machine check
  did not cover — the checker paired cites into the *edited* file but missed
  one bare ref inheriting into it from a neighboring line. Two siblings
  pointing at the same symbol (`finding_staging_gate_test.go:69`,
  `finding_attribution_fanout_test.go:135`) were caught and re-pointed; this
  third one, sharing the same symbol, was not. Recorded rather than routed
  back — under the 3+-SHOULD-FIX rubric this did not hold the merge.
- Verification, final round: `go test -race -tags e2e_realclaude -run
  '^TestTrail|^TestFin' ./internal/e2e/realclaude/` — **99 top-level tests,
  411 subtests, 0 failed, 0 skipped**, run with no credentials (`make check`
  does not compile these files). Cites re-run against HEAD across three
  files that changed line count (`trail_run_outcome_test.go` +354,
  `trailer_admissibility_test.go` +18, `trail_run_instant_clause_test.go`
  +8): 169 pairs content-checked, one real miss (the bare-cite finding
  above). `gofmt -l` and `go vet -tags e2e_realclaude` clean on all touched
  files.
