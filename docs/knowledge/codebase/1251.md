# Ticket #1251 — Teardown-liveness probe: does a backgrounded Bash command survive pyry's teardown, and by whose hand does it die?

Adds `internal/e2e/realclaude/teardown_liveness_probe_test.go` (1252 lines) and widens
`internal/e2e/realclaude/teardown_liveness_test.go` (+259/−40) — the live rig that keeps
#1231's hand-verified answer (backgrounded Bash command dies with pyry, killed by the
reaper, 3/3 reps on 2026-07-30) true against future teardown refactors. No production
code. Split from #1231; blocked by and calls #1250's classifier/record and #1235's/#1239's
liveness instruments as code, not evidence.

## Implementation

- **The core problem this rig solves is a manufactured pass, not a missed leak.** The
  expected reading (`dead`, `count=1`, held pgid in the reap line) is published in a public
  GitHub comment, and the pipeline's own real-claude suite SKIPs without credentials (a skip
  exits 0). So the record has to be produced by code that is shown to work, not composed by
  hand — the design's load-bearing idea is `tdnBeforeFault`: the same liveness classifier
  that reports the after-teardown verdict is run at the before-snapshot too, and a run whose
  before-liveness isn't uniformly `pinStateRunning` is voided (recorded as a staging/instrument
  fault) rather than read as clean. An instrument hard-wired to `dead` would still pass a live
  run without this gate.
- **Three readings of "dead after pyry exited", two structural discriminators.** Reaper-killed
  vs. finished-on-its-own vs. died-alongside-claude. The still-held FIFO (`holdProbeFIFO`,
  released only in `t.Cleanup`, so releasing it happens strictly after the test body's
  SIGTERM → wait → after-snapshot) rules out "finished on its own"; a pgid appearing in the
  reap line rules out "died alongside claude", because `reap.go:56-62` skips `ESRCH` *before*
  the append — membership in that list proves `kill(2)` succeeded.
- **`tdnRecord` widened, not duplicated.** `HeldPID int` → `HeldPIDs []int` (`tdnPinHeld`
  refuses to resolve "the" pid — #1230's live run matched two rows, the `zsh -c` wrapper and
  `cat`, on the same needle). Single `ArgvScan`/`Liveness`/`FIFO` members replaced with
  `Before *tdnSnapshot` / `After *tdnSnapshot` (never both old and new — an unlabelled member
  in a published artifact is itself an ambiguity). Four new provenance fields:
  `ClaudeVersion`, `TeardownPath` (a constant string naming the exact SIGTERM path),
  `RunnerFromEnv` (documentation — which env var was set) and `RunnerFromArgv` (the evidence
  — read from claude's own argv). `Before.Liveness`/`After.Liveness` are index-aligned with
  `HeldPIDs` as an asserted invariant, not a trusted convention — each `pinStateOutcome`
  carries its own `PID` so the artifact is self-checking.
- **The join rule that keeps a zombie from reading as pid reuse (`tdnDecideAfter`).** AC3
  asks that a recycled pid be caught by re-running the content match against the FIFO
  needle. But a zombie *also* fails that match — the kernel replaces a defunct process's
  argv (`<defunct>` on Linux, `(cat)` on macOS). So the content re-match is dispositive
  **only when the after-liveness verdict is `pinStateRunning`**; for
  `pinStateExitedNotReaped` / `pinStateNoSuchProcess` the needle's absence carries no
  information — it was consumed at the before-snapshot and never has to survive.
- **Disposition is a positive allowlist, one red arm.** `tdnDispositionReaperKilled`
  (`"dead-by-reaper"`, strong pass), `tdnDispositionDeadUnattributed`
  (`"dead-not-attributed-to-the-reaper"`, weaker pass — reap classifier said
  `no-reap-line`/`reap-line-without-held-pgid`), `tdnDispositionLeaked` (`"leaked"`, the
  *only* `t.Errorf` arm — an after-liveness verdict of `running` whose content re-match still
  carries the FIFO path), `tdnDispositionSkipped` (everything else, folded through
  `tdnFinish`). Either classifier reporting `instrument-failed` records-and-skips — never a
  leak finding manufactured out of the instrument's own breakage.
- **Cleanup-ordering trap inverted on purpose.** `runReachProbe`'s precedent releases the FIFO
  *before* registering the pyry-exit cleanup, deliberately, so pyry gets a real chance to
  finish the turn on its own. Copying that here would silently destroy the measurement: `cat`
  reaches EOF and exits by itself, giving the exact clean-but-unearned reading (2) this ticket
  exists to rule out. This rig does the SIGTERM, the wait, and the after-snapshot *inside the
  test body*, and registers the artifact-write cleanup first (LIFO: runs last) so a structural
  `t.Fatalf` still leaves evidence on disk.
- **Runner label is a fresh function, not a reused one** (`tdnRunnerFromArgv`). The obvious
  reuse candidate, `reachRunnerPathFromArgv`, keys on `--append-system-prompt-file` and calls
  it "the ptyrunner-shape marker" — but `buildStreamRunnerClaudeArgs`
  (`cmd/pyry/agent_run.go:372`) emits the identical flag, so the helper would mislabel every
  stream-path record with nothing going red. `tdnRunnerFromArgv` discriminates on
  `--session-id` (ptyrunner-only) vs. `--input-format` (streamrunner-only) instead, with an
  `"indeterminate"` arm for zero/both markers.
- **The inherited SHOULD FIX repaired** (`teardown_liveness_test.go:529-540` in #1250's
  numbering). The "two reap lines, held pgid only in the second" fixture row didn't
  discriminate its own claimed mutation — both fixture lines actually carried the held pgid.
  Fixed by swapping the concatenation order so line 1 contributes one pgid and the held pgid
  appears solely in line 2; a first-line-only union implementation now fails on the
  **verdict** (`held-pgid-in-reap-line` → `reap-line-without-held-pgid`), not just on
  `LineCount`/`Count` bookkeeping. Verified by deliberate mutation (patched to first-line-only,
  confirmed red, reverted, `git status --porcelain` clean before commit).
- **A ninth reject branch beyond the spec: the teardown-provenance guard.** If pyry had
  already exited on its own before the rig's SIGTERM, every downstream reading (command
  dead, pgid in the reap line) would still be *correct* — normal completion reaps too — but
  attributed to a teardown path (`TeardownPath`) that never ran. Guarded by reading the
  `pyryExited` channel before sending the signal: an already-`Wait`ed process refuses the
  signal cleanly, so the guard is read-then-signal rather than signal-then-check.
- **Test naming keeps the offline suite's zero-SKIP property truthful.** #1250's file header
  advertises `go test -run '^TestTdn'` as 22-subtests-zero-SKIP; a live, credential-gated test
  named `TestTdn…` would join that suite and add a SKIP, silently falsifying the claim. The
  live test is `TestRealClaude_TeardownLiveness` (additionally gated on
  `PYRY_PROBE_TEARDOWN_LIVENESS=1` even on a credentialed machine); the three offline
  self-checks that legitimately belong to `^TestTdn` are `TestTdnRunnerFromArgv`,
  `TestTdnDecideAfter`, and `TestTdnPinHeld` — the last one beyond the spec's two, added
  because `tdnPinHeld`'s anti-first-match, multi-pgid-voids-the-run behavior is the one
  genuinely new function in the diff and is load-bearing for AC1.
- **48 subtests, zero SKIP** on `^TestTdn` (up from #1250's 22); full package
  `-tags e2e_realclaude -race`: 216 PASS / 44 SKIP (the 44 are every credential-gated live
  test in the package, unaffected by this PR). The live half itself has not been run — no
  claude login in the dispatch environment; ticket carries `needs-real-claude`.

## Patterns established

- **A record naming the cause of a state needs its own guard, not just the state.** The
  teardown-provenance guard is the sharpest instance in this family: a true reading
  (command dead, reaper's pgid in the log) can still be attributed to the wrong cause if the
  cause itself isn't checked. Sibling shape to #1236's lateness-witness lesson (blind to the
  reap because it watched the wrong step) and #1250's cited-handler finding (right reading,
  wrong instrument).
- **A content re-match cannot be dispositive for every liveness verdict** — it has to be
  scoped to the one verdict (`running`) that can actually produce a finding, or it misfiles
  every zombie as pid reuse. See the join rule above.
- **A shared helper's doc comment can encode a claim that was only ever true for its own
  ticket.** `reachRunnerPathFromArgv`'s "ptyrunner-shape marker" comment was accurate only
  because #1230 skips outright on the stream path; reusing the helper here (which does not
  skip on that path) would have silently mislabelled every stream-path record.
- **A byte-capped `Detail` cannot safely nest another classifier's `Detail` verbatim.** The
  instrument-failed reap arm's first draft quoted the reap classifier's own ~285-byte
  `Detail` inside a ~290-byte explanation and truncated under `reachCapCommand`'s 512-byte
  cap. Restating what a producer's `Detail` already says costs the producer's byte budget,
  not the consumer's.
- **A LOC overrun is defensible when none of the spec's cut items came back.** 1252 lines
  against the spec's ~750–850 projection (and ~1000 stop-and-route-back line). Code review
  checked the cut list (§ 0.3) explicitly and found nothing re-added; the comment-to-code
  ratio (0.46) matched the package's siblings (0.39/0.45/0.48/0.48). Same shape as #1250's
  own 988-vs-550 miss — this package's cost is concentrated in design commentary written in
  one or two `Write` calls, not scattered edits.

## Lessons learned

From the PR body (#1256) and code review (PASS, 1 SHOULD FIX + 1 NIT, both non-blocking,
neither folded into this PR):

- **[Deferred] SHOULD FIX** (`teardown_liveness_probe_test.go:632-636`) — the design comment
  on `tdnDecideAfter` overclaims for one of its two `instrument-failed` arms. It states,
  generally, that "the skip's Detail enumerates every after-verdict, so a leak-shaped reading
  alongside a broken one is still visible to an operator." True for the **liveness**
  `instrument-failed` arm (interpolates `tdnVerdictSummary`), but the **reap**
  `instrument-failed` arm deliberately omits it on byte-cap grounds (see the pattern above) —
  so a reap-`instrument-failed` skip message carries no after-verdicts at all. Low practical
  impact (`After.Liveness` is a structured artifact member either way — the gap is in the skip
  *message* only), but it is the exact defect class this PR was sent to repair (#1250's own
  `:529` row was a comment claiming a property the code didn't deliver). Fix is to narrow the
  comment's claim to the liveness arm, not to add the summary to the reap arm. Not picked up
  in this pass — left for a future touch on this file, per this family's established
  convention for non-blocking deferred findings (see #1250 → #1251 for precedent).
- **[Deferred] NIT** (`teardown_liveness_probe_test.go:599`) — `case rec.HeldPGID <= 1:`:
  `tdnPinHeld` only ever produces `0` as its void sentinel, so `<= 1` additionally (and
  incorrectly) catches pgid 1, for which the fired message ("do not resolve to a single
  process group") would be false — the rows would have resolved fine. Unreachable in
  practice (a detached Bash group is never in init's group); `== 0` matches the documented
  contract. Cosmetic, not picked up in this pass.
- **A rig can publish a true reading attributed to the wrong cause** — see Patterns
  established.
- **A content re-match cannot be dispositive for every liveness verdict** — see Patterns
  established.
- **A shared helper's comment can encode a claim true only for its own ticket** — see
  Patterns established.
- **`reachCapCommand`'s 512-byte cap is a real constraint on a `decide` detail that quotes
  another classifier's `Detail`** — see Patterns established.
- **The fixture record has exactly one literal member, by structural necessity.**
  `fifoLiveRead`'s positive arm (`reader-present`) is reachable only through a successful
  `open(2)`, so it has no pure constructor — producing one honestly would mean staging a live
  FIFO with a live reader inside an offline fixture file. Named explicitly in place
  (`tdnFixtureReaderPresent`) rather than left for a reviewer to notice; nothing gates on it,
  since FIFO readings are corroboration and never decide a verdict.
