# Ticket #1504 — stall watchdog arms from the send side, not from construction

`internal/streamsup`'s #1094 idle watchdog was lifted from `streamrunner`, whose runner *is* the send
side and so may assume an owed assistant turn the instant its tracker is constructed. `streamsup`'s
watchdog is constructed away from the send side: the interactive child spawns on `Activate`/
`RestartFresh` and emits `system`/`init` before any user turn exists — a message may not arrive for
hours. The inherited `awaiting: true` default treated that `init` as an owed turn, so a perfectly
healthy idle session tripped a false `OnStall` 240s after spawn, and again after every crash-mid-turn
respawn (the abandoned turn's `awaiting=true` outlived the child that owed it).

## Implementation

- `internal/streamsup/watchdog.go`: `newStallTracker` now starts `awaiting: false`. Two new
  unexported `stallTracker` methods, `turnSent()` and `childExited()`, join `consumeLine` as the
  third and fourth writers of `awaiting` — each takes the tracker's existing leaf mutex, no new lock.
  `turnSent` sets `awaiting=true` and restamps `lastEvent`; `childExited` sets `awaiting=false` and
  restamps `lastEvent`. Two new exported `*Watchdog` methods, `UserTurnSent()` and `ChildExited()`,
  forward to them 1:1. `shouldFire`'s predicate is unchanged — this slice moves its two inputs, not
  its logic.
- **Why starting `false` alone is not the fix.** Claude does not echo the delivered prompt back as a
  `user` line on this surface (measured, `docs/knowledge/features/streamsup-package.md` § "Two
  tiers"), so the only stdout lines that ever set `awaiting=true` are `user`/`tool_result` lines. A
  tracker that started `false` and took no send-side input would never arm before claude's first
  output — the false positive would become a silent false negative on the exact wedge (a turn that
  produces nothing at all) this component exists to catch. `UserTurnSent` is the explicit
  substitute for the missing echo.
- **Why `UserTurnSent` must restamp `lastEvent`, not just flip `awaiting`.** An idle child emits
  nothing, so `lastEvent` can be hours stale by the time a turn is finally sent. Arming without
  restamping would satisfy `now - lastEvent > Idle` on the very next poll tick and fire immediately —
  a false positive on the exact turn the user just asked for, strictly worse than the bug being
  fixed. Pinned by `TestWatchdog_UserTurnSentRestartsIdleClock` (`fakeClock` + a real ticker: the
  ticker fires on real time, only the elapsed comparison reads the fake, which is what makes
  "advance the fake clock, then wait real ticks" distinguish a stamping arm from a non-stamping one).
- **`UserTurnSent`'s contract names both refusal sentinels.** `Runner.WriteUserTurn` can return
  `ErrNoLiveChild` (no live child, or a `BeginRotation` gate) or `turncommit.ErrDropped` (gate deny) —
  both write zero bytes, and arming on either would reintroduce the same false stall by another
  route. The method takes no argument and returns nothing precisely so the delivered/refused decision
  stays at the one call site (the future wiring slice) that can see `WriteUserTurn`'s error. Control
  requests (`Interrupt`, `RevokeBypass`) do **not** arm — their acks land in ~40ms and they are not
  user turns.
- **One `Watchdog` per `Runner`, reset by `ChildExited`, not one per child.** `Config.Stdout` is fixed
  when `New` builds the `Runner` and the supervise loop never re-wires it, so a per-child watchdog
  would have no way to reach a respawned child's stdout. `ChildExited` also keeps exactly one poll
  goroutine and one `Start`/`Wait` pair for the runner's life, against a `Start` the #1094 review
  already noted has no double-call guard. It deliberately does **not** drop the tracker's partial-line
  remainder — the dead child's trailing partial concatenates with the new child's first line into one
  unparseable line, which `consumeLine` already treats as activity-only.
- Doc comments: `newStallTracker`'s comment no longer asserts the streamrunner premise ("the caller
  writes the opening user envelope before the child produces any output"); `Watchdog`'s type doc
  gained a second `DIVERGENCE from streamrunner` paragraph alongside the existing emit-not-kill one,
  naming the construction/send-side asymmetry and the no-echo measurement that makes it unavoidable.
- **No production caller added.** Composing `Writer()` into `Config.Stdout` via `io.MultiWriter`, and
  wiring `UserTurnSent`/`ChildExited` into `runner.go`'s `WriteUserTurn`/`Run`, stays with the
  still-unfiled wiring slice — adding it here would trip the "new API and its consumer" split rule.
  `NewWatchdog` still has no non-test reference in the tree beyond a doc-comment mention in
  `internal/turnevent`.

## Patterns established

- **A construction-time "owed turn" default is only sound when construction and the send side are the
  same event.** `streamrunner`'s one-shot runner gets this for free; any future receive-side tracker
  built ahead of its first send (a second interactive surface, a replay path) needs the same explicit
  lifecycle-signal treatment as this watchdog, not the inherited literal.
- **Re-anchoring a test that encodes a fixed bug means adding an arm, not deleting an assertion.**
  Four existing assertions (`TestStallTracker_AwaitingTransitions`,
  `TestStallTracker_LineBuffering` ×2) read `awaiting == true` for reasons unrelated to the initial
  value — they needed a `turnSent()` ahead of them to stay discriminating against a not-awaiting
  start, not removal. `TestWatchdog_GenuineIdleFires`'s scenario (arm via a lone `system` line) was
  the ticket's literal failure scenario asserted as correct; it now asserts no-fire, and the
  genuine-idle-fires intent moved to a `UserTurnSent()`-armed test.

## Lessons learned

(From the PR body, `#1619`.)

- **A shared test clock double becomes racy the moment it is used one level up.** `fakeClock` was
  single-goroutine-safe while only tracker unit tests used it directly; wiring it into
  `WatchdogConfig.now` puts the poll goroutine on the read side too, so it needed a mutex. Worth
  checking whenever an existing test helper crosses from a synchronous unit test into a test that
  starts a goroutine.
- **A fake clock plus a real ticker is what makes "when does the threshold start counting" testable
  at all.** `TestWatchdog_UserTurnSentRestartsIdleClock` distinguishes an arm-that-stamps from an
  arm-that-doesn't only because the ticker still fires on real time while the elapsed comparison
  reads the fake — advance the fake, then wait real ticks. A fully-real clock makes the two
  implementations differ by one tick (flaky); a fully-fake one gives the poll goroutine nothing to
  drive it.
- **Re-anchoring a test that encodes the bug means adding an arm, not deleting an assertion** (see
  Patterns established above — restated here because the PR called it out as the trap the ticket
  itself named: the cheapest way to keep `make check` green is to not fix the bug).

## Testing

`go test -race ./internal/streamsup/...` and `go vet ./...`. Every new assertion was mutation-checked
via `go test -overlay` (no worktree writes) against five production mutants: restoring
`awaiting: true`, stubbing `UserTurnSent`/`turnSent` to a no-op, and `childExited` either a no-op or
stamping without clearing `awaiting`. The six AC4 regression pins
(`TestWatchdog_InFlightToolSilence_NoFire`, `TestStallTracker_ContentFree`,
`TestStallTracker_LastEventAdvances`, `TestShouldFire`, `TestWatchdog_CleanShutdown_NoLeak`,
`TestWatchdogTickFor`) are byte-identical to pre-change `HEAD`.
