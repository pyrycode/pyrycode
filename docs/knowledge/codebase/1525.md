# Ticket #1525 — Probe transport-down in `forwardAppReply` before the seal

`security-sensitive` · extends [the #874 push-drain hold](../features/v2-session-manager.md#transport-down-hold-on-the-push-drain-874--connected-probe--transportdown) and [the #912 rekey-emit gate](../features/v2-session-manager.md#scheduled--manual-rekey-emit-gated-behind-transportdown-912) to the third and widest-window sealed-send path in `internal/relay`: a handler's reply to a phone request (umbrella #829 reconnect-reliability design).

Before this ticket, `forwardAppReply` sealed a handler reply under `s.send` with no transport-liveness probe ahead of the `Encrypt`. A reply sealed while the daemon's relay leg was down advanced the Noise send-nonce for a frame `send` then silently dropped (its `Outbound` error swallowed at Debug). Because relay↔binary carries no per-connection disconnect frame, the phone's recv `CipherState` stayed untouched by that drop, so the next frame that *did* arrive failed AEAD and tore down a session that was never actually broken, at `StatusProtocolMismatch` (4421) — permanently, since flynn/noise never rewinds a receive counter on decrypt failure. #874 deliberately deferred guarding this seal, reasoning that a reply landed microseconds after its inbound frame, too narrow a window for a blip to land inside. #965 moved handler execution onto a per-conn worker, widening that window to up to a full handler duration (as long as `createConversationMintTimeout`, 30s) — wide enough to hold an entire blip, and the #874 deferral sentence was never revisited against it. There was no live repro; the ticket was filed from code review against the widened window plus the two shipped precedents on the same hazard in the same file.

## Implementation

- **Guard placed inside `forwardAppReply`, after the `V2StateOpen` gate and before `s.send.Encrypt`** — the `drainOnce` (#874) shape, not the #912 call-site shape. #912 gated at its two call sites because they diverge after the check (a timer re-arm vs. a returned error); `forwardAppReply` has exactly one caller (`Run`'s `m.appReply` arm) and nothing diverges after the decision — the reply is simply dropped, with no timer to re-arm and no error to report — so the call-site indirection #912 needed buys nothing here. Ordering after the state gate is load-bearing exactly as it was in #912: the pre-existing not-open drop keeps its exact text and position in every transport state.
- **The branch:** `if m.transportDown() { … return }` — seals nothing, marshals nothing, forwards nothing, buffers nothing, mutates no session state. One Debug log line, `event=v2.app_reply.dropped_transport_down` + `conn_id` only — no payload, inner envelope type, `InReplyTo`, ciphertext, plaintext, or key bytes, matching `forwardEnvelope`'s no-AEAD-bytes-in-logs discipline.
- **Dropped, not parked.** The reply was undeliverable either way — `send` already discarded it — so the guard only stops paying a nonce for a non-delivery, it does not make the reply arrive. Parking for post-recovery delivery would need a new buffer, an eviction policy, and an ordering rule against the push queue; named out of scope by the ticket. Nothing is held, so unlike #874's push head, the down→up edge needs no flush trigger.
- **TOCTOU and byte-identity, same posture as #874/#912.** The probe is a plain read of `m.cfg.Connected`, an immutable-after-construction func field, on the `Run` goroutine (the single owner of `s.send` and sole writer of `s.state`) — no lock, no atomic, no new goroutine. The residual single-frame up→down transition race carries over unchanged from both precedents and is explicitly not defended further. `transportDown()` reads "up" when `Connected` is nil, so every existing test that doesn't wire it took the pre-change path unmodified — no existing test needed editing.

Files touched: `internal/relay/v2session.go` (+35/-1), `internal/relay/v2session_appframe_test.go` (+190, two new tests). Single production file, as sized (S).

## Patterns established

- **A single-caller, no-divergence sealed-send site gates *inside* the primitive; a multi-caller, diverging one gates at the *call site*.** #1525 and #874 both hold inside because nothing downstream of the check differs by caller; #912 gates outside because its two callers need to do different things after a "down" verdict. When extending `transportDown()` to a new seal in future work (`drainReplayOnce` #1490, the seven inline `forwardEnvelope` reply seals #1526), check caller count and post-decision divergence first — that answers placement before any code is written.
- **A wrapper-counter, not the recorder itself, is what proves "nothing was sealed" when the recorder's own down-path behavior already reads empty.** `gatedRecorder.outbound` records nothing *and* returns an error while down, so "the recorder observed zero envelopes" is true both under a correct guard and under a wrong implementation that skips the seal but still hands the raw unsealed frame to `send`. The test wraps `Outbound` in a closure that increments an `atomic.Int64` *before* delegating, outside the up/down branch — that counter is what actually discriminates a correct guard from the #446 never-emit-unsealed violation it's meant to catch.
- **A same-caller ordering AC (state gate vs. new guard) is asserted by a direct, unstarted-`Run` call, not a driven scenario.** Driving a torn-down-mid-handler scenario would race `forwardToRun`'s `select`, which has an `s.done` arm alongside the `m.appReply` send — with `s.done` already closed, Go picks among ready cases at random, making a driven version of this test flaky by construction. Calling `forwardAppReply` directly on a hand-built `&V2Session{connID, state: V2StateClosed}` with `Run` never started has no concurrency and pins exactly which check runs first.

## Security review

Architect self-review (full text in `docs/specs/architecture/1525-appreply-transport-down-gate.md` § Security review) verdict: **PASS**. Same class as #874/#912: the change only ever *skips* a seal, so it cannot cause nonce reuse — the failure mode it fixes is a nonce *gap*, and a skipped seal cannot create one. `rekeyComplete` replaces `s.send` wholesale, so a skipped seal neither strands nor corrupts a re-key swap. `transportDown()` is manager-global rather than per-conn — a false reading suppresses replies on every conn — but the relay leg genuinely is shared, so when it reads down no conn's frame reaches anyone regardless; no cross-conn amplification beyond what the transport already imposes. The residual single-frame up→down TOCTOU is out of scope, carried over unchanged from #874/#912 and documented on the `Connected` seam itself.
