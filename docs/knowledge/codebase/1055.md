# Ticket #1055 — mark `docs/specs` tree historical + banner nine superseded stream-json specs

The 2026-07-15 docs review flagged the `docs/specs/` tree as the tree's biggest hazard: per-ticket
architect specs are write-once build artifacts, but nothing marked them as such, so a stale spec
could surface to an assistant or pipeline agent with the same apparent authority as current-state
truth. Worst offender: `docs/specs/architecture/392-agentrun-delete-pty-drive-code.md` instructs
deleting the PTY-drive code that `ptyrunner` cutover (#470, confirmed default in #473) made the
default runner.

## Implementation

- `docs/specs/README.md` — appended a "point-in-time artifacts, not current-state authority"
  section. Existing content untouched.
- `docs/specs/architecture/README.md` — new file, same point-in-time statement scoped to
  architect-output specs, plus a pointer to `docs/knowledge/` as the maintained current-state
  source.
- Nine stream-json-era specs under `docs/specs/architecture/` each got a two-line prepend above
  the original content — nothing else in these files changed:
  ```
  > **Superseded by #470/#473 — ptyrunner is the default runner.**

  ```
  Files: `332-agent-run-spawn-drive.md`, `337-agent-run-scaffold.md`,
  `353-jsonl-surface-all-kinds-raw-usage.md`, `354-agent-run-streamjson-emitter.md`,
  `373-realclaude-runpyryagentrun.md`, `375-agentrun-selfcheck-stream-json.md`,
  `390-streamrunner-primitive.md`, `391-agent-run-wire-streamrunner.md`,
  `392-agentrun-delete-pty-drive-code.md`.
- Verified strictly additive: `git diff --numstat` against `main` shows `2\t0` for each of the nine
  files (0 deletions) and append-only diffs for both READMEs — no original line touched, banner
  em-dash (U+2014) intact.
- Docs-only; no production code, no `docs/knowledge/` feature/architecture/decision doc created by
  this ticket (the two touched READMEs live under `docs/specs/`, not `docs/knowledge/`), so no
  `INDEX.md` entry applies here.

## Patterns established

- **Write-once artifact tree needs an explicit non-authority banner.** Any future per-ticket spec
  directory (or similar build-artifact tree) that sits beside `docs/knowledge/` should carry the
  same "point-in-time, not current-state authority" framing from the start, rather than waiting for
  a review to flag it as a hazard.
- **Superseded-spec banner form**: a bold blockquote line with the exact reviewer-supplied text,
  prepended above the original H1, followed by a blank line. Wrapping markup (`>`, `**`) sits
  outside the pinned literal so `grep -F` on the exact banner text still matches regardless of
  markdown wrapping choice.
