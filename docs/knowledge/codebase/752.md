# Ticket #752 — ACP permission proxy via `session/request_permission`

The **highest-risk seam in epic [#600](https://github.com/pyrycode/pyrycode/issues/600)** (T8,
[ADR 027](../decisions/027-acp-mapping.md) divergence 2). When claude hits a tool that needs
approval, the supervised interactive session raises an on-screen permission modal and blocks. ACP
models that as a *blocking agent→client call*: `acpPermissionProxy` issues `session/request_permission`
to the host, blocks until it answers, then routes the host's choice back into claude's live prompt as
the correct keystroke — the interactive path, introducing **no** `claude -p` and **no** Agent SDK
permission mechanism (the ADR 025/026/027 hard cost invariant). Host-sourced approvals are
**default-safe**: an unanswered, errored, cancelled, or mismatched request resolves to deny (ESC),
never a silent grant.

**security-sensitive** — an architect security pass ([spec](../../specs/architecture/752-acp-permission-proxy.md)
§ Security review pass, verdict **PASS**) and a code-review security-goggles pass both cleared the
routing of host-sourced approvals and the default-safe posture. Full package documentation:
[features/acp-package.md § ACP permission proxy](../features/acp-package.md#acp-permission-proxy-sessionrequest_permission-752).

## Implementation

**Two new files in `cmd/pyry` (package `main`), fully additive — zero modification to any existing
file, 0 new exported types** (mirrors the `acpTurnStream` / `interactiveModalEmitterV2` posture):
`cmd/pyry/acp_permission.go` (adapter + local ACP wire types), `cmd/pyry/acp_permission_test.go`.

### Where permission surfaces — not the turnevent stream

A permission modal is a **tui-driver PTY-state event** (`tuidriver.EventKindPtyModalShown` /
`…Hidden` with `ev.Modal == tuidriver.ModalClassPermission`), **not** a `turnevent.Event` —
`turnbridge.mapEvent` drops modal kinds. So the adapter takes its **own** modal-event subscription
off the live session; `tuidriver.Session.Events(...)` mints a fresh channel + merge goroutine per
call, so it does not contend with T6/T7's turn-event subscription
([#750](750.md)/[#751](https://github.com/pyrycode/pyrycode/issues/751)).

### The adapter — two goroutines, one atomic arbiter

- **`Handle(ctx, ev)`** is the modal-event sink, called serially on the **drain goroutine** (the
  deferred wiring's). A permission-class `ModalShown` → `handleShown` (start a round-trip); any
  `ModalHidden` → `retireInflight`; everything else (a non-permission `ModalShown` included) → no-op.
  `screenText` is deliberately **not** a parameter — `session/request_permission` carries no prompt
  body and the option set is class-fixed, so the wiring never has to source `Supervisor.ScreenSnapshot`.
- **`handleShown`** builds the four-option set via
  [`modalbridge.PermissionRequestForClass(ev.Modal, "")`](../features/modalbridge-package.md) (reused
  so option order and the ACP `kind`s share one source of truth), defensively retires any stale
  `inflight`, stores a `permissionRoundTrip`, and **spawns one round-trip goroutine**. Spawning the
  `Call` on a fresh goroutine is the "off the Serve read loop" guarantee (AC-5) — the read loop is
  the only reader of the `Call` response, so a `Call` on it would deadlock.
- **`runRoundTrip`** blocks in `caller.Call`, then claims the one-shot
  (`rt.resolved.CompareAndSwap(false, true)`) and routes **at most one** keystroke. If retirement
  already won the CAS (a `Hidden` cancelled the `Call`), it routes nothing. `defer rt.cancel()`
  releases the deadline timer on every exit.
- **`retireInflight`** (drain goroutine) claims and clears the outstanding round-trip; if it wins the
  CAS it cancels the in-flight `Call` `ctx`, so `runRoundTrip` unblocks, sees the failed CAS, and
  routes nothing (AC-4: "a reply for an already-retired modal falls back to deny").

`inflight` is drain-goroutine-confined (no lock); the sole cross-goroutine state is the
`atomic.Bool` one-shot and `rt.cancel` (written before spawn). `-race` clean.

### Default-safe resolution switch (`route`)

The **only** path to an allow keystroke is a decoded `outcome:"selected"` whose `optionId` is a
member of the daemon-built option set → `Answer(digit)`, where `digit = strconv.Itoa(idx+1)` is the
1-based display-order position (the index is the single source of truth for both wire option order
and the keystroke digit — exactly `classifyAnswer`'s discipline over the neutral
`[]turnevent.PermissionOption`). Every other path routes deny (`SendEsc`): call error / ctx-deadline
timeout / teardown-cancel (`call_err`), undecodable body (`decode_err`), `outcome:"selected"` with a
forged/unknown `optionId` (`forged_option`), `outcome:"cancelled"` (`cancelled`), unknown/empty
outcome (`unknown_outcome`). **Deny is the failure mode, not a branch.**

### Routing seam — keystrokes, not `turnevent.PermissionResponse`

The host's selection is routed via the supervisor **keystroke seam** (`modalKeystroker`:
`Answer(choice)` / `SendEsc()`; `*supervisor.Supervisor` satisfies it, [#726](726.md)). There is
**no** `turnevent.PermissionResponse` consumer — the neutral type exists but stays unwired; the
adapter does **not** construct one. This refines [ADR 027](../decisions/027-acp-mapping.md)
divergence 2, whose prose sketched a `PermissionResponse` feed-back; the built adapter routes the
keystroke directly (the ADR row is the neutral vocabulary, not the ACP adapter's path).

### Correlation — transport-owned, doubly guarded

`Transport.Call`'s pending map matches reply↔request by outbound id and drops a reply with no waiter,
so a stale/replayed/mismatched id never reaches the adapter (AC-4). The `atomic.Bool` one-shot adds
the modal-retirement guarantee on top — belt-and-suspenders, **both deterministic**. The
`session/request_permission` `Call` takes its own outbound id space and cannot resolve or touch the
held inbound `session/prompt` ([#749](https://github.com/pyrycode/pyrycode/issues/749)/[#765](https://github.com/pyrycode/pyrycode/issues/765)),
which resolves only on `TurnEnd` (AC-5).

### ACP wire types (consumer-owned)

`requestPermissionParams{sessionId, toolCall?, options[]}` with `permissionOption{optionId, name,
kind}`, mirroring `acp_turn_stream.go`'s locally-owned params. `toolCall` is **omitted** (`omitempty`)
— the modal-event path yields no gating tool-call id (`PermissionRequestForClass` leaves it empty);
reserved for a future ticket that correlates the gating `ToolStart` from the turn stream. The
response decodes the **nested** `{"outcome":{"outcome","optionId"}}` form; the decode is default-safe
(any shape mismatch leaves `Outcome` zero ⇒ deny), so a wrong guess fails **closed**, never open.

### Trust class is out of scope (evidence-based)

`pyry acp`'s composition root pre-trusts the workdir (`runACP` → `trustMark`), so a trust modal does
not surface. The adapter gates on `ModalClassPermission` only; a `ModalClassTrustFolder` (or any
other class) `ModalShown` is a no-op — avoiding an untested trust→ACP mapping for a modal that cannot
appear, and keeping every emitted ACP option carrying one of the four valid kinds. `AcceptTrust` is
therefore unused. Additive follow-up if a trust modal is ever observed in ACP mode.

## Patterns established

- **Two-goroutine one-shot as the sole cross-goroutine arbiter.** A drain-goroutine-confined
  `inflight` pointer plus a per-round-trip `atomic.Bool` (CAS wins exactly once) coordinate the drain
  and round-trip goroutines with **no mutex**. Whoever wins the CAS resolves; the loser no-ops. Every
  first-answer-wins race (host answers then Hidden; Hidden first then late reply; simultaneous)
  resolves safely — route the answer into a still-showing modal, or route nothing. This is the
  deterministic safety net (real code, not a second stochastic guard) behind the transport-owned id
  correlation.
- **Default-safe as structure, not a branch.** The resolution switch has exactly one allow arm
  (decoded `selected` + membership-valid `optionId`); every other outcome funnels to `deny`. A forged
  `optionId` is simply not locatable in the daemon-built set, so it can never route an allow — safety
  falls out of the data model, not a guard that could be forgotten.
- **Retire on _any_ `ModalHidden` (vs the mobile surfacer's class-match).** An `inflight` round-trip
  only ever exists for a `ModalClassPermission` modal, and tui-driver's single-modal invariant means
  no unrelated `Hidden` can fire while it shows — so the simpler unconditional retire fails safe
  (retire ⇒ deny).
- **Fourth thin ACP adapter over the neutral core, permission half.** Like the outbound streaming
  sink ([#750](750.md)), the entire consumer is far thinner than its mobile analogue
  (`interactiveModalEmitterV2` — broadcast + nonce registry): one blocking `Call` in place of the
  whole broadcast/registry/timeout machinery, reusing `PermissionRequestForClass`, the
  `modalKeystroker` seam, and the `classifyAnswer` index→digit discipline.

## Code review

**PASS** — [PR #773](https://github.com/pyrycode/pyrycode/pull/773). Security-goggles pass clean: no
host `optionId` in any log field (proven by the `NoOptionIDLeak` canary), no file ops / subprocess /
crypto / new listener, no `claude -p` / SDK path. All six spec security findings verified as actually
implemented (silent-grant / replay / cross-prompt confusion / wedge / content-leak / held-prompt).
`make check` green (vet + `-race` + staticcheck + substrate-guard); real-claude e2e green
(`ok internal/e2e/realclaude 149.598s`).

- **[NIT, not actioned]** the nested response decode (`{"outcome":{"outcome","optionId"}}`) is a
  documented guess (spec Open question #4). It is default-safe (shape mismatch ⇒ `Outcome` zero ⇒
  deny), so a wrong guess fails **closed**. Worth verifying against a reference ACP host when the
  deferred wiring lands — already tracked, no action here.

## Lessons learned

- **Log the content-free resolution decision _before_ actuating the keystroke.** Doing so makes the
  keystroke the round-trip goroutine's last observable action on the success path, so a
  keystroke-recording channel (`syncKeystroker.waitRouted`) becomes a valid happens-before barrier
  for reading the log buffer **race-free — no `syncBuffer` needed** (contrast the `internal/acp`
  `liveTransport` tests, which do need a mutex-guarded buffer). *(Lifted from the PR body.)*
- **The "routed nothing" negative assertion is sound without joining the goroutine.** A round-trip
  that loses the CAS can never route, so timing only affects how long you wait to confirm — the
  retirement test can assert no keystroke without a join. *(Lifted from the PR body.)*
- **The neutral `turnevent.PermissionResponse` is declared-but-unwired vocabulary — don't build a
  consumer for it.** The ADR 027 divergence-2 prose sketches feeding the answer back as a
  `PermissionResponse`, but the real routing seam is the supervisor keystroke API. Grep for a
  consumer before trusting a neutral type is "the path" (same trap as the `turnevent.Cancel`
  declared-vocabulary note in [#753](753.md)).

## Testing

`cmd/pyry/acp_permission_test.go` (package `main`), table-driven, stdlib `testing`, `-race`-clean.
Doubles: `fakePermissionCaller` (scripts the `Call` as a response body / error / block-until-signalled
for the timeout & retirement cases) and `syncKeystroker` (records `Answer`/`SendEsc`, signals a
channel used as the happens-before barrier).

- **`TestACPPermissionProxy_RequestShape`** (AC-1) — a permission `ModalShown` → a `Call` for
  `session/request_permission` with `sessionId` set, `toolCall` omitted, and exactly four `options`
  carrying `optionId`/`name`/`kind` = `allow_once, allow_always, reject_once, reject_always` in
  display order.
- **`TestACPPermissionProxy_SelectedRoutesKeystroke`** (AC-2) — `outcome:"selected"` for each of the
  four `optionId`s → `Answer("1".."4")` (digit = display index+1), no `SendEsc`.
- **`TestACPPermissionProxy_DefaultSafeDeny`** (AC-3) — `cancelled`, a `Call` error, an undecodable
  body, and a `Call` that blocks past a short `timeout` each → exactly `SendEsc`, no `Answer` (no
  silent grant).
- **`TestACPPermissionProxy_ForgedOptionDenies`** — `selected` with an `optionId` never in the
  surfaced set → `SendEsc`.
- **`TestACPPermissionProxy_RetiredModalRoutesNothing`** / **`_SecondResolutionIgnored`** (AC-4) —
  `ModalShown` then `ModalHidden` before releasing the scripted response → no keystroke; a second
  resolution attempt is ignored (one-shot).
- **`TestACPPermissionProxy_NonPermissionModalNoOp`** — `ModalClassTrustFolder` and other classes →
  no `Call`, no keystroke.
- **`TestACPPermissionProxy_KeystrokeErrorTolerated`** — a keystroke error is Warn-logged and
  tolerated (round-trip already resolved, nothing to roll back).
- **`TestACPPermissionProxy_NoOptionIDLeak`** — a canary `optionId` appears in **no** log line (the
  content-discipline proof).

## Out of scope (deferred)

- **Live wiring** — subscribing this adapter to `Session.Events()` and driving `Handle` per modal
  event in the `pyry acp` composition root is the modal-event wiring follow-up
  ([#751](https://github.com/pyrycode/pyrycode/issues/751) T7 territory; `turnbridge.NewTargetSubscriber`
  yields the raw `<-chan tuidriver.Event`, the wiring filters modal kinds). Ships unwired exactly as
  [#708](https://github.com/pyrycode/pyrycode/issues/708) defers `interactiveModalEmitterV2`'s wiring.
- **`toolCall` correlation** — the gating tool-call id comes from the turn stream's `ToolStart`, a
  cross-subscription concern; the field is `omitempty`-reserved.
- **Trust modal in ACP mode** — pre-trusted workdir means it should not surface; a trust arm is an
  additive follow-up if one is observed.
- **Timeout tuning** — `timeout` is a constructor param; a generous default (~2 min suggested) is
  picked at wiring time. This ticket only requires the timeout-⇒-deny path to exist.
