# Ticket #1109 — stream-json `RunnerFactory`: construct & inject `*streamsup.Runner` at both pool sites

The first `streamsup.New` caller tree-wide. Adds `streamRunnerFactory` — a
[`sessions.RunnerFactory`](../features/sessions-package.md) that maps an incoming `supervisor.Config` to a
`streamsup.Config`, calls `streamsup.New`, and wraps the result in the existing `streamRunner` adapter
([#1097](1097.md)) — to `cmd/pyry/streamsup_runner.go`. Consumes the construction-safe `supervisor.Config.SessionID`
seam ([#1108](1108.md)). Does **not** wire the factory into production: the `interactive_runner` selection that
assigns it to `sessions.Config.RunnerFactory` is [#1081](1077.md), still unlanded, so `streamRunnerFactory`'s only
caller today is its own construction tests.

## Implementation

- **`streamRunnerFactory(cfg supervisor.Config) (sessions.Runner, error)`** — exactly the `sessions.RunnerFactory`
  signature. Body: `streamsup.New(mapStreamsupConfig(cfg))`, wrap any error
  (`fmt.Errorf("cmd/pyry: stream runner: %w", err)`) and return `(nil, err)` — a **genuine nil**, never a typed-nil
  trap — or wrap the runner in `streamRunner{r: r}` on success.
- **No PTY fallback, by construction.** The function has no branch that calls `supervisor.New`; a `streamsup.New`
  failure (missing binary, absent work dir, empty `SessionID` — the last one impossible at the pool sites per
  #1108) always surfaces as an error. Substituting a PTY supervisor here would silently diverge the bootstrap —
  the session `pyry attach` drives — from the operator's stream-json intent.
- **`mapStreamsupConfig(cfg supervisor.Config) streamsup.Config`** — the primary tested surface (pure, every
  output field directly inspectable). Copies `ClaudeBin`/`WorkDir`/`SessionID`/`Logger`/`BackoffInitial`/
  `BackoffMax`/`BackoffReset` verbatim; maps `ClaudeArgs → Args` (streamsup's argv field has a different name)
  through `stripSessionIDFlags`; leaves `Stdout`/`Stderr`/`Env` nil (`Stdout` is #1098's scope — an unconsumed
  child stdout goes to `/dev/null` and never blocks the child; `Stderr`/`Env` have no `supervisor.Config`
  analogue). Seven PTY-only fields (`ResumeLast`, `ResolveSessionID`, `Bridge`, `ValidateConversation`,
  `ResolveTranscript`, `RecordDir`, `helperEnv`) are deliberately not mapped — streamsup owns its own id-flag
  inversion and has no PTY bridge, transcript binding, or `.cast` recorder.
- **`stripSessionIDFlags(args []string) []string`** — returns a fresh slice (never mutates the input, which is
  aliased into the pool's `spawnBase`) with every `--session-id`/`--resume` occurrence removed, handling the
  two-token form (`--session-id`, `<value>`), the joined form (`--session-id=<value>`), and a dangling flag with
  no following token. Required at the per-session site (`Pool.buildSession` bakes `--session-id <id>` into
  `ClaudeArgs`) to prevent `streamsup.buildArgs` double-injecting the id flag on top of its own re-injection; a
  harmless no-op at the bootstrap site (`Pool.New`'s `ClaudeArgs` carry no id flag).
- Comment fix: the stale `cmd/pyry/streamsup_runner.go` doc comment ("the factory arm... is #1081's scope") now
  points at #1109 as the ticket that delivers the factory, with #1081 correctly scoped down to the selection
  that injects it.
- Tests extend `cmd/pyry/streamsup_runner_test.go`: a `stripSessionIDFlags` table (nil/empty, no-id-flag passthrough,
  two-token, joined, dangling, no-mutation-of-input), `mapStreamsupConfig` against both pool shapes (bootstrap:
  strip is a no-op; per-session: asserts `.Args` carries no residual `--session-id`/`--resume`/bare id token — the
  AC-2 no-double-inject proof), and `streamRunnerFactory` construction at both shapes (`os.Args[0]` as a resolvable
  `ClaudeBin`, `t.TempDir()` as `WorkDir`) plus an error-propagation case (a guaranteed-absent `ClaudeBin` — chosen
  because `supervisor.New` doesn't `LookPath` at construction, so a regression to a PTY fallback would return
  `(non-nil, nil)` and fail the assertion).

## Patterns established

- **Factory-constructs-error-propagates-no-fallback** is now the concrete shape for a `sessions.RunnerFactory`
  arm that must not silently degrade to the PTY default: return `(nil, wrapped-err)`, never branch to
  `supervisor.New`. Any future non-PTY `RunnerFactory` arm should follow the same "no fallback branch exists in
  the code" structural guarantee rather than a runtime check.
- **Pure mapper as the tested surface, opaque runner as the thin shell.** `mapStreamsupConfig` carries all the
  interesting logic (field mapping + strip) and is fully inspectable; `streamRunnerFactory` itself is a two-line
  call-and-wrap. Confirms the pattern from #1097/#1094: push logic into a pure, directly-assertable function and
  keep the function that touches an opaque type (`*streamsup.Runner`) minimal.

## Lessons learned

- Code review (PR #1115, PASS) flagged one non-blocking NIT: there's no `var _ sessions.RunnerFactory =
  streamRunnerFactory` compile assertion sitting next to `streamRunnerFactory`, unlike the existing
  `var _ sessions.Runner = streamRunner{}` for the adapter. AC-1's "injectable on `sessions.Config.RunnerFactory`"
  is proven only by matching signature today; the actual assignment (and thus real compile-time proof) is
  deferred to #1081's wiring. If #1081 turns up unexpected friction here, add the one-line assert to this file
  first — it's cheap and would have pinned the seam a ticket earlier.
- QA's initial `make check` run showed a red `TestPool_Supervise_AfterRunReturns_ReturnsErrPoolNotRunning` in
  `internal/sessions`, unrelated to this PR's diff (which touches only `cmd/pyry`). Isolated re-runs on both PR
  HEAD and the merge-base confirmed a pre-existing timing flake (same family as #823/#924/#949/#1024), filed
  separately as #1116. Nothing to change here — noted so a future doc pass doesn't rediscover the same flake as
  if it were new.
