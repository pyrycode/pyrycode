# Ticket #1209 — An exit lane on the turn-busy fan-in

Split from #1207 (itself the last child of the original #1198→#1203 crash-clear lineage), alongside open
sibling #1210. #1201/#1202 clear the turn-busy tracker on a `TurnEnd` or a pool transition, but neither
fires when a child crashes mid-turn and the runner respawns it — no `result` line for the abandoned turn,
no pool transition. #1206 gave the runner a way to *observe* that exit (`Config.OnChildExit func()`), but
its own contract says it is not a drain barrier: bytes the dead child already wrote may still be in flight
in the fan-in when it fires. This slice is the lane only — a way to carry that exit signal on the same
FIFO, single-reader channel the events already ride, so a clear derived from it cannot overtake events the
crashed child already pushed. It ships unfired: #1210 is the wiring slice that assigns `OnChildExit`.

## Implementation

- **`cmd/pyry/stream_turn_drain.go`**: `streamTurnEnvelope` gained an explicit `exit bool` field —
  deliberately not a nil `turnevent.Event` sentinel, since a nil `ev` would both need re-checking at every
  consumer and would make `eventKind(nil)` reachable (`"unknown"`, not a failure). The struct's one
  construction site is a keyed composite literal, so the field is additive with zero call-site cascade.
  `streamTurnSink.exitFor(sessionID string) func()` mirrors `sinkFor`'s non-blocking `select`/`default`
  send but is a deliberately separate closure, not a shared-helper parameterisation: the common part is one
  `select` statement, the divergent part is the entire diagnostic. On drop it logs at **`Warn`** (siblings
  are `Debug`) with exactly `event: "stream_turn.exit_sink_full"` and `session_id` — no `kind`, matching the
  existing content-free shape `clear_unresolved` already established. The drain's `sink.ch` arm handles
  `env.exit` as its **first** statement: `busy.clearForSession(env.sessionID); continue` — ahead of
  `observe`, the active-session gate, and `emitter.Handle`. Each position matters: before `observe` because
  an exit carries no event to route; before the gate because the gate would otherwise drop a background
  conversation's exit and it would never clear; before `Handle` because that (combined with the explicit
  field) is what keeps `Handle` structurally unable to receive a non-event.
- **`cmd/pyry/stream_turn_busy.go`**: comment-only. `clearForSession`'s doc now names two callers (the
  #1202 teardown observer and this drain's exit arm) instead of one, and its synchronous-execution
  paragraph extends to cover the drain goroutine — same "must not block" requirement, but from the drain's
  own contract (a stalled clear wedges the whole fan-in) rather than #659's observer contract. No code in
  this file changed; `ImportsStayMinimal` stays green.
- **`cmd/pyry/stream_turn_drain_test.go`**: `dropWatcher` widened with an optional `recs chan slog.Record`
  forwarded alongside the existing `kinds` channel — a nil channel inside a `select`/`default` still takes
  the default, so every pre-existing `dropWatcher{kinds: ...}` construction is unaffected. Five new tests:
  `TestStreamTurnDrainV2_ExitClearsOpenTurn` (AC2, non-active session, `WaitIdle` barrier, with a mid-test
  `Busy` assertion to rule out the vacuous-idle case), `TestStreamTurnDrainV2_ExitDoesNotClearALaterTurn`
  (AC3, exit-then-opener, `Busy` true plus a bounded `WaitIdle` deadline expecting
  `context.DeadlineExceeded`), `TestStreamTurnDrainV2_ExitClearsInlineBeforeTheNextEnvelope` (the mutation-
  tested replacement for a same-order deferred-clear check — see Lessons learned), `TestStreamTurnDrainV2_
  ExitProducesNoEmitterTraffic` (AC4, nil tracker no-op, exit produces neither a push nor a not-active
  drop), `TestStreamTurnSink_ExitDropWhenFull` (AC1, buffer of 1, no drain started, asserts level/fields on
  the captured record with no drain reader to race against).
- **`cmd/pyry/stream_turn_busy_test.go`**: supporting scaffolding for the tracker-state assertions used by
  the scenarios above (real `turnBusyTracker`, `stubBusyResolve`-style session→conversation resolution),
  alongside the drain-tier tests.
- **Ships unfired**: `grep -rn 'OnChildExit' cmd/pyry/ --include='*.go' | grep -v '_test.go'` → 0;
  `grep -rn '\.Busy(\|\.WaitIdle(' cmd/pyry/ internal/ --include='*.go' | grep -v '_test.go'` → 0 (same
  count as on `main` pre-slice). `git diff --name-only main...HEAD` is exactly the four files above. No v2
  wire frame changed; the five `internal/e2e/relay_v2_stream_*_test.go` files pass unchanged.

## Patterns established

- **Ride the existing fan-in instead of calling out from the exit seam directly.** #1206's `OnChildExit` is
  explicitly not a drain barrier — `cmd.Wait` joins the stdout copier and `Parser.emit` is synchronous, so
  every event the dead child produced has been *pushed* by the time the callback fires, but not necessarily
  *drained*. A clear delivered on any lane other than the channel those events are queued on could land
  before the drain has processed buffered openers, re-marking the conversation busy with the clear already
  spent. The fan-in's FIFO-with-one-reader property is what makes an in-band signal immune to that, and is
  the reason this slice exists as a lane rather than a direct call.
- **An explicit discriminant field, not a sentinel value, when the type already carries a "no value" that a
  consumer treats leniently.** `eventKind(nil)` silently returning `"unknown"` rather than panicking is
  exactly what would make a nil-`ev` sentinel a silent-failure hazard instead of a loud one; a bool field
  keeps "this envelope carries no event" a type-level fact checkable by grep (`env.exit`), not a runtime
  branch on `env.ev == nil`.
- **Placement inside an existing `select` arm is provable via mutation, not just via the AC prose.** Each
  of the three things the exit arm precedes (`observe`, the active-session gate, `Handle`) has a test that
  fails if the arm is moved below it — the non-active-session fixture in particular exists specifically to
  make the gate-placement decision load-bearing, since an active-session-only test can't distinguish the two
  placements.
- **`Warn` vs `Debug` is the entire diagnostic value of an otherwise-identical drop path**, not decoration.
  Both drops ride the same drop-newest-on-full sink behaviour; the level is what tells an operator "missed
  clear, permanently degraded" apart from "missed delta, self-heals on the next event."

## Lessons learned (from PR#1211 — code review PASS, 0 MUST/0 SHOULD + 3 NITs; and the developer's own PR body)

- **A doc comment can break a name-shaped unfiredness grep.** AC5's ships-unfired gate is
  `grep -rn 'OnChildExit' cmd/pyry/ --include='*.go' | grep -v '_test.go'` → 0. An early draft of
  `exitFor`'s doc comment named the seam it mirrors by symbol, which pushed that count to 2 with zero
  actual wiring — the grep cannot distinguish prose from use. Fixed by citing the seam as
  `internal/streamsup/runner.go:105-143` plus its role instead of the bare symbol, with a note in the
  comment recording *why* the symbol is absent so a later reader doesn't "helpfully" restore it. General
  shape: when a mechanical gate greps for a name, prose about that name reads as use of it.
- **`[exit, opener]` → busy does not, by itself, catch a goroutine-dispatched clear.** The architecture doc
  offered that ordering as the assertion that forbids a deferred/async design (AC3). Mutation-tested by
  swapping the inline call for `go busy.clearForSession(...)`: it still passes, because with the exit
  arriving *first* the deferred clear fires while the conversation is still idle — a harmless no-op
  regardless of scheduling. The assertion with teeth inverts the order and barriers on a *later* envelope:
  `[opener A, exit A, opener C]`, then assert `Busy(A) == false` at C's drop log — an inline clear has
  provably taken effect by that barrier (same goroutine, FIFO), so a correct implementation never flakes
  while the async mutant fails reliably. Shipped as
  `TestStreamTurnDrainV2_ExitClearsInlineBeforeTheNextEnvelope`. General rule: to forbid asynchrony, barrier
  on work the *same goroutine* did afterwards, not on the absence of an effect.
- **A line citation can be invalidated by its own commit, not just by prior ones.** Two
  `stream_turn_busy.go:NNN` citations written into this slice's own new comments went stale from ~14 lines
  the same diff added above them (`:200-206` → `:213-219`, `:216-219` → `:229-232`). Caught by extracting
  every `\.go:[0-9]+` from `git diff | grep '^+'` and re-checking each against the post-edit tree, rather
  than trusting the number written at drafting time.
- **Mutation-testing a placement contract is cheap insurance.** Moving the exit arm below the
  active-session gate, and separately deleting the `clearForSession` call, both fail
  `TestStreamTurnDrainV2_ExitClearsOpenTurn` — confirming the non-active-session fixture (rather than the
  test author's intent) is what actually makes placement load-bearing.
