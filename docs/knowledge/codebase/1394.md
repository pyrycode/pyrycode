# Ticket #1394 — emit the background-task frames to a mobile client

Joins the three background-task `turnevent` variants — `BackgroundTaskStarted`, `BackgroundTaskUpdated`, `BackgroundTaskRoster` (produced by `internal/streamsup/parser.go` since #1380–#1382, given v2 wire shape by #1393) — to the mobile wire. Before this ticket `internal/turnbridge/outbound.go`'s `MapEvent` returned `ok == false` for all three, so a phone had no way to distinguish #1240's symptom (`turn_end`/`end_turn`, state `idle`, while a command claude started is provably still alive) from a genuine finish. Split from #1377; blocked-by #1393.

## Implementation

- **`internal/turnbridge/outbound.go`** — three additive `MapEvent` arms, inserted after `turnevent.Unrecognized` and before `default:`. Each carries **conversation identity only**: `tc.TurnID`/`tc.Seq` are ignored (the payloads have no field for either) because a background task outlives the turn that spawned it. The mapping is 1:1 and total — every event field crosses verbatim, `ConversationID` is the only field the bridge adds, and nothing is re-capped (the producer already bounded every string at construction). The roster arm loops `e.Tasks` into `[]protocol.BackgroundTask` and — the one deliberate subtlety — leaves a nil `Tasks` as nil rather than pre-allocating, so `protocol.BackgroundTaskRosterPayload.MarshalJSON` (#1393) owns the nil→`[]` normalisation instead of the bridge hiding it. `DroppedTasks` (the roster's only truncation report — not named `truncated_fields`, and the payload has no top-level field of that name) rides through unconditionally.
- **`cmd/pyry/interactive_turn_v2.go`** — one handler `case` covering all three variants, taking the same two-line body as the `Stall`/`ApiRetry`/`Compacting`/`Unrecognized` peers: `flushDelta` then `emitMapped`. No `startTurnIfNeeded`/`transitionTo`/`endTurn`, so `inTurn`/`turnID`/`currentState` are untouched — opening a turn on a background task would wedge the conversation on work orthogonal to it, the same failure mode the `stream_turn_busy.go` opener whitelist already guards against (left untouched, by construction its `default:` returns before `resolve`/`setBusy`).
- **`cmd/pyry/interactive_turn_v2.go`'s `eventKind`** — three one-line arms returning the variant name only (`background_task_started`/`_updated`/`_roster`), never a claude-derived field (`TaskID`, `ToolCallID`, `Description`, `TaskType`, `Patch` are all claude-derived and this function feeds log fields). `eventKind` is shared across 7 call sites in 4 files, so the arms also stop `stream_turn_busy.go`/`stream_turn_drain.go`/`acp_turn_stream.go` logging `kind=unknown` for these events — a log-discriminant side effect only, not desktop wiring (the ACP wire lane itself, `internal/acpbridge/outbound.go`, was deliberately left untouched — that's #1262).
- **`docs/protocol-mobile.md`** — three new `####` sections under § Interactive events (v2, capability-gated), placed *before* `session_transition` (load-bearing: `session_transition` explicitly excludes itself from the "N turn-stream events" count, so the new sections had to land above it to keep both count literals — § opener and inside `session_transition` — counting the same set). Recounted rather than trusting the ticket's own cited "thirteen": nine `####` frame headings pre-existed at HEAD (both literals had drifted to a stale "eight"), so 9 + 3 = **twelve**. Also corrected a stale "none of the four mapped `system` subtypes reach the wire" claim in the `unrecognized_message` two-tier explanation, now false for three of the four (`thinking_tokens` still stops at the daemon boundary — no `MapEvent` arm for `ThinkingProgress` exists), and added the three missing rows to the application-message-types table ~250 lines above the section (`api_retry`/`compacting` had shipped without rows there in #1074 — the doc's own changelog named the gap).
- **Test coverage** — `internal/turnbridge/outbound_test.go` gained table rows including a non-zero `DroppedTasks` row (a zero-value row would pass against a mapping that never reads the field) and a separate byte-level test asserting `MapEvent(turnevent.BackgroundTaskRoster{}, tc)` marshals to `"tasks":[]`, run on the value `MapEvent` actually returned rather than a payload the test constructed (which would only prove #1393's marshaller works). `cmd/pyry/interactive_turn_v2_test.go` gained: fan-out/field-round-trip tests, a no-lifecycle-mutation test covering all three (mirroring the existing `…StatusPeersNoLifecycleMutation` shape), a `…RosterMidTurnDoesNotDisturbOpenTurn` test driving past the one mutation a bare-events test alone wouldn't catch (`endTurn()`-shaped no-op on an already-closed turn), an ordinary-turn-gains-no-traffic assertion paired with the non-suppression assertion above (so "absent" reads as "unproduced," not "filtered"), a log-leak test carrying a distinct marker in every claude-derived field under the log-heavy `pushErr` branch, and a positive `kind=background_task_*` assertion against an empty-cursor drop (a leak-only assertion would pass against a missing `eventKind` arm entirely).

## Patterns established

- **A status-peer arm's shape (conversation-identity-only, `flushDelta` then `emitMapped`, no lifecycle mutation) generalizes cleanly to a multi-variant `case`.** Three new `turnevent` types took one two-line handler body and one `MapEvent` insertion block each — no new abstraction, no signature change, confirming the #1074 (`api_retry`/`compacting`) template scales to N variants without modification.
- **A doc section's count literal is load-bearing for insertion order, not just accuracy.** Placing new `####` sections before vs. after an excluded peer (`session_transition`) changes which of two count literals goes stale — the fix and the insertion point are the same decision, not two.
- **`eventKind` fan-out is a free correctness improvement across lanes a ticket doesn't otherwise touch.** Because the function is shared (7 call sites, 4 files), adding arms for the mobile lane's sake also fixed `kind=unknown` logging on busy/drain/ACP lanes — worth checking whether a shared discriminant function is being extended for one caller while silently helping others.

## Lessons learned

From the PR body (#1397) and code review (verdict PASS, one NIT):

- **The doc's own changelog named the omission this ticket was about to repeat.** The `2026-07-27` entry records that #1074 shipped `api_retry`/`compacting` without rows in the application-message-types table (~250 lines above the section an author is actually editing) — a second, easily-missed registry of every frame. The three background-task types had the same gap; fixed. Worth checking that table whenever any `####` frame section is added.
- **A count literal's stale value can decide where new content goes, not just what number to write.** Both "eight turn-stream events" literals count the *same* set, and `session_transition` excludes itself from it by its own sentence — so the new sections had to land *before* `session_transition` to keep the two literals in agreement; landing them after would have made one read twelve and the other nine, re-opening the drift the recount was fixing.
- **A "nothing reaches this wire" doc claim ages the moment a mapping lands.** `unrecognized_message`'s two-tier explanation asserted none of the four mapped `system` subtypes reach the wire because `MapEvent` had no case for any of them. This PR falsified that for three of the four; corrected in place. Prose describing the *absence* of a mapping is a forward reference to whichever ticket adds one — worth flagging as such when writing it, so the next ticket knows to check.
- **[NIT, unfixed]** `cmd/pyry/interactive_turn_v2.go:335-338` — `emitMapped`'s doc comment still enumerates the old unreachable-drop set (`TextChunk`/`ToolStart`/`ToolUpdate`/`TurnEnd`/`Stall`/`ApiRetry`/`Compacting`) without the three new variants that now route through it. Mostly pre-existing debt (the parenthetical's "only `ThoughtChunk` and nil drop" claim was already stale independently of this PR, since #1385's `ThinkingProgress` also falls to `default:`), not worth a rework cycle — worth a line whenever the function is next touched.
