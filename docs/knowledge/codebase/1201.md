# Ticket #1201 — A per-conversation turn-busy tracker fed from the stream-json turn fan-in

A self-synchronised, per-conversation `turnBusyTracker` (`cmd/pyry/stream_turn_busy.go`) answers "is a
turn currently running for conversation X?" on the `stream-json` path — a question the existing
`interactiveTurnEmitterV2` lifecycle fields cannot answer, being unguarded (single-goroutine only), a
scalar rather than per-conversation, and populated only for the conversation the active-conversation
cursor points at. This is the first of three split children of #1198 (turn-busy signal); its siblings,
#1202 (session-teardown clear) and #1203 (mid-turn-respawn clear), must land before any consumer reads
this signal. See [streamsup-package.md § Per-conversation turn-busy tracking](../features/streamsup-package.md#per-conversation-turn-busy-tracking-1201)
for the full mechanism writeup; this file covers what shipped and what the next two children need to know.

## Implementation

- **New file**, `cmd/pyry/stream_turn_busy.go`: `turnBusyTracker` — one mutex guarding one
  `map[string]struct{}` (membership only, never event content) plus a `chan struct{}` generation
  broadcast, closed-and-replaced under the same lock as any mutation. `Busy(conversationID) bool` and
  `WaitIdle(ctx, conversationID) error` are exported-shaped (capitalised, callable from any goroutine) on
  purpose — no consumer interface is declared here, that's the next slice's job. `observe(sessionID, ev)`
  is the unexported feed, called only from the drain goroutine.
- **`cmd/pyry/stream_turn_drain.go`**: `startStreamTurnDrainV2` gains a `busy *turnBusyTracker` parameter
  and calls `busy.observe(env.sessionID, env.ev)` as the first statement of the `sink.ch` arm — one line
  before the existing `activeSession()` gate. That ordering is the whole point: the gate's identity
  source (`env.sessionID`) differs from what `emitter.Handle` reads internally (the cursor), so feeding
  before the gate is what makes a non-active conversation's turn still report busy.
- **`cmd/pyry/relay.go`**: constructs `busy := newTurnBusyTracker(resolve, logger)` in the stream branch
  (between the emitter build and the drain start) using the same `conversationForSession(w.convReg, sid)`
  closure the `session_transition` producer already uses (`relay.go:756`), and passes it to the drain.
  Deliberately a local variable, not a `relayWiring` field — nothing outside this branch reaches it yet.
- **7 pre-existing drain-test call sites** (`cmd/pyry/stream_turn_drain_test.go`) each took a bare `nil`
  for the new parameter — `observe`'s nil-receiver no-op is what makes that a one-token edit instead of
  each test constructing a tracker it doesn't assert on.

## Patterns established

- **Whitelist over blacklist for an opener set, justified by the producer's growth path, not a live
  event.** `observe` opens on exactly the four openers (`ThoughtChunk`, `TextChunk`, `ToolStart`,
  `ToolUpdate`) and closes on `TurnEnd`; everything else — including `Stall`, which cannot reach this
  tracker through the real sink at all — is a no-op default. The justification lives in the parser's
  `default:` tolerate-and-drop arm: `rate_limit_event` is dropped today and becomes a wired `ApiRetry` the
  day someone adds it, and a blacklist ("anything that isn't `TurnEnd` opens a turn") would silently wedge
  a conversation on that day. When an AC asks for a whitelist over the *set of variants a real pipeline
  can currently deliver*, the assertion that matters is a direct unit-tier feed of the excluded variant —
  not something drivable through a parser or a live runner, and the test comment must say so explicitly
  so a future reader doesn't "simplify" it into a parser-driven test that can never fail.
- **Feed a signal from the same fan-in, before the gate that would make it vacuous** — not a second
  detector, not a tap on already-gated state. The general shape: when an AC requires a signal to be
  observable for state a downstream gate would otherwise filter out, the derivation point is wherever in
  the pipeline gate and identity haven't yet been fused — here, `streamTurnEnvelope.sessionID` upstream of
  `activeSession()`, not `interactiveTurnEmitterV2`'s cursor-resolved fields downstream of it.
- **Existence-oracle discipline enforced by the method signature, not a runtime branch.** `Busy` returns a
  bare `bool` — no error, no second `found bool`. Code review should check the signature stays that way; a
  later `(bool, error)` widening would reintroduce a "does conversation X exist" oracle silently, invisibly
  to any test written against today's boolean-only shape (#1101 posture, `screenSnapshotterOrNil`,
  `relay.go:395-410`).
- **A typed-nil-safe parameter is the concrete pointer, never an interface.** `busy *turnBusyTracker`
  (not some `turnBusyObserver` interface) is what lets `observe`'s nil-receiver guard actually work — a
  typed nil boxed into an interface is non-nil at the interface level and would route straight past a
  nil check into a nil-map read.
- **Lock discipline for a check-then-wait primitive:** capture the wait channel and check membership under
  *one* lock acquisition (splitting them reintroduces a lost-wakeup race), do the close-and-replace under
  the same lock as the mutation it accompanies (atomicity for the first invariant), and call any resolver
  with side effects (registry scans, other locks) *outside* the lock, never under it (avoids establishing
  an arbitrary lock order for no benefit). This is the same shape `internal/eventring`'s package doc
  argues for a self-synchronised per-conversation store.

## Lessons learned

- **A "grep to prove it's unwired" check must use a reader-shaped pattern, not a name-shaped one.** The
  spec's own unwired-ness grep undercounted call sites in the safe direction because of a substring
  collision (`newTurnBusyTracker` contains `turnBusyTracker`, so a naive name grep double-counts the
  constructor as a "use"). The fix that generalizes: when a spec hands down a grep meant to *prove a
  negative* (no consumer reads this yet), run it against the exact count it predicts first, and if the
  predicate is a bare type/function name, replace it with a pattern that matches the *read* usage
  specifically (here, `\.Busy\(|\.WaitIdle\(` in non-test files) rather than any substring of the type
  name. A name-shaped check can pass by coincidence; a reader-shaped check can't.

## Follow-ons (not this ticket)

- **#1202** — session torn down under a busy conversation (`/clear` rotation, idle/cap eviction) never
  fires a `TurnEnd`, so the tracker's clear needs a teardown-driven path too. Also owns the narrower
  rotation edge: because the write-side resolver matches `SessionHistory`, a retired session's late
  `TurnEnd` can clear a turn its successor opened (fails open — reports idle when busy).
- **#1203** — a child that dies mid-turn and is respawned fires no pool transition and emits no `result`
  line for the abandoned turn, so the tracker never sees a close for it either.
- **Where the tracker gets hoisted for a consumer.** The delivery path (`msgqueue` deliver →
  `deliverViaSession`) will need it reachable outside the stream branch — a `relayWiring` field or a
  `main.go` construction, the `streamSink` precedent (`main.go:1027`, `relay.go:245-253`). That hoist
  belongs in the diff that adds the reader, not here.
- **Transition logging for #1202/#1203's debugging.** Not built in this slice (no AC, nothing to debug
  while unwired) — when the consumer slices need it, the log level is load-bearing: Debug is invisible on
  a daemon running at the default `LevelInfo`, which is exactly the daemon a wedge would need debugging on.
