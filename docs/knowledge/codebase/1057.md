# Ticket #1057 — backfill the protocol-mobile message table with the ten missing shipped types

The 2026-07-15 docs review found the `## Application message types` table in `docs/protocol-mobile.md`
silently missing ten shipped `protocol.Type*` constants — the table had drifted below the wire
vocabulary in `internal/protocol/codes.go`. Split from #970, alongside #1055 (specs-tree banner) and
#1056 (Phase-0 entry-doc banners) from the same review.

## Implementation

- Added ten rows to the table as a contiguous block between `conversation_updated` and
  `register_push_token` (`docs/protocol-mobile.md:421-430`): the six conversation verbs
  (`rename_conversation`, `delete_conversation` + reply `conversation_deleted`,
  `archive_conversation`, `unarchive_conversation`, `change_workspace`) and the four workspace verbs
  (`create_workspace_folder` + reply `workspace_folder_created`, `recent_workspaces` + reply
  `recent_workspaces_list`) — mirroring `codes.go`'s `Conversations` → `Workspace` block adjacency,
  each reply immediately after its request.
- All ten are `inboundAppTypeSet` members (v1-lineage, `internal/protocol/envelope.go:113-143`), so
  they render as **plain** rows like `create_conversation`/`promote_conversation` — no bold, no
  "New in v2." prefix, no v2-section link — even the three `binary → phone` replies. That convention
  is reserved for `v2OnlyTypes` members below `rekey_request`.
  "Carries handshake early-data?" is `no` for all ten (only `hello`/`hello_ack` ride early-data).
- Direction and Notes were transcribed from the per-constant doc comments in `codes.go` (not
  guessed), each confirmed against its cited line range during review. Notes document
  request/reply pairing, mirroring the existing `set_session_settings` → `session_settings_updated`
  precedent.
- Docs-only, `git diff --name-only` touches only `docs/protocol-mobile.md`; no `.go` file changed.
- Restores the invariant **{table `Type` values} = {`codes.go` `Type*` constants}**: 48 = 48,
  verified with a whitespace-tolerant re-extraction (see Patterns established below) —
  `comm -3` on the two sorted sets prints nothing.

## Patterns established

- **The spec's AC3 completeness grep is fragile under `gofmt` alignment and must be re-extracted,
  not trusted as written.** The spec's `grep -oE 'Type[A-Za-z]+ = "[a-z_]+"'` assumes a single space
  around `=`, but `gofmt` right-aligns consecutive const declarations with multiple spaces —
  against the actual file this undercounts to 29 matched constants instead of 48, which would
  spuriously report 3 fabricated "missing from table" entries via `comm -3`. The whitespace-tolerant
  form (`Type[A-Za-z]+\s*=\s*"[a-z_]+"`) is required before treating a `comm -3` non-empty result as
  a real gap. This is a durable gotcha for any future doc-completeness ticket that verifies a table
  against `codes.go` by grep — re-extract whitespace-tolerantly before trusting a spurious FAIL.
- **v1-lineage vs. v2-only classification is a table-formatting decision, not just a content one.**
  A reply-direction type (`binary → phone`) is not automatically v2 — membership in
  `inboundAppTypeSet` vs. `v2OnlyTypes` (`internal/protocol/envelope.go` /
  `internal/protocol/compat_test.go`) is the actual discriminator for plain-vs-bold rendering, and
  was flagged as the classification trap to verify at PO time as well as review time.
- Docs-only backfill with no new `docs/knowledge/` feature/architecture/decision doc — no
  `INDEX.md` entry applies, same as [#1056](1056.md).
