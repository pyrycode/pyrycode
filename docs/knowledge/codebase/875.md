# Ticket #875 — relay: flush held v2 push queues immediately on relay reconnect

Not `security-sensitive`. Layer 2 of the reconnect-reliability design (umbrella #829), follow-up to [#874](874.md).

## Implementation

#874 made the v2 push drain hold queued control envelopes unsealed while the relay transport is down, but a held envelope only re-flushed on the *next* `Push`-driven `drainCh` signal. #875 adds an eager trigger: wake the drain the instant the transport reconnects, with no intervening `Push`.

Three production files, ~70 lines, no new goroutine, no new lock, no wire-format change:

- **`internal/relay/connection.go`** — `Connection` gains a `reconnected chan struct{}` field (cap-1, drop-on-full), initialised in both `Connect` and `connectWithClient`. In `run()`'s existing `case <-c.client.Connected():` arm, right after the "conn established" log and before the blocking `forwardFrames` call, a non-blocking send pokes `reconnected`. The new `(*Connection) Reconnected() <-chan struct{}` accessor exposes it — the edge-triggered sibling of the #874 level-poll `Connected() bool`.
- **`internal/relay/v2session.go`** — `V2SessionConfig` gains an optional `Reconnect <-chan struct{}` field (nil ⇒ no new wake source, byte-identical to pre-#875). `Run` gains one select arm that, on fire, re-signals `drainCh` via the same non-blocking cap-1 idiom `Push`/`drainOnce`/`drainReplayOnce` already use — it does **not** call `drainOnce` directly, so the existing drain arm keeps sole ownership of the pop path and its FIFO self-re-signal.
- **`cmd/pyry/relay.go`** — `startRelayV2`'s `V2SessionConfig` literal wires `Reconnect: conn.Reconnected()` beside the #874 `Connected: conn.Connected`.

**Design decision (from the architecture spec, followed as specified):** the ticket's AC4 literally said "wire the new seam to `transport.Client.Connected()`." That would be unsafe — `transport.Client.Connected()` is documented single-observer, and `relay.Connection.run()` is already its sole consumer (re-entering `forwardFrames` on each fire); a second observer would steal connect signals from the connection's own frame-forwarding loop. The fan-out instead happens one layer down, at `relay.Connection`, which re-broadcasts its own already-consumed edge to the manager.

## Patterns established

- **Fan out a single-observer channel one layer down, don't share it.** When a lower-layer channel is documented single-observer and already has a consumer, a second interested party gets a *new* channel that the existing consumer re-broadcasts on, not a second reader on the original. Mirrors the #874 shape (`transport.Client.IsConnected()` → `relay.Connection.Connected()` → `cmd/pyry`) with an edge-signal sibling (`Connected()` → `Reconnected()`).
- **A wake-only arm re-signals the pump, it doesn't run the pump.** The new `Run` arm re-signals `drainCh` rather than calling `drainOnce` directly, so the pre-existing drain arm remains the single place that pops, seals, and self-re-signals. Keeps the eager (#875) and lazy (pre-#875 `Push`-driven) wake sources structurally identical from the drain's point of view — same idiom applies to `V2SessionConfig.Reconnect` as to any future additional wake source.

## Security review

Code review: **PASS**, no MUST FIX / SHOULD FIX (one harmless NIT: `connection_test.go`'s `TestCloseConn_BeforeConnect` builds a bare `&Connection{}` that leaves `reconnected` nil, harmless since that test never spawns `run()` nor reads `Reconnected()`). Confirmed nil-safe wake source, wakes-never-seals, FIFO cascade from one signal, fan-out at the Connection layer (not the transport), no new goroutine/lock, purely additive blast radius. Not security-sensitive per the spec: the change is wake timing only — every Noise send-nonce increment stays gated by the #874 `Connected`/`transportDown()` probe downstream, and the reconnect signal carries no attacker-influenceable data.
