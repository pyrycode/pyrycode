# Ticket #1191 — A minted per-conversation PTY interrupt oracle

Fills a fake-tier coverage gap: every green PTY-arm interrupt test
(`TestRelayV2_InterruptStopsRunningTurn`, #794) drove the **bootstrap** session, so
#1121's routing fix — `activeInterrupter.SendEsc` → `resolveBoundRunner` → the bound
runner's own `*supervisor.Supervisor` — had no coverage on the path it actually changed.
PR #1200 adds `TestRelayV2_PerConversationInterruptStopsRunningTurn`
(`internal/e2e/relay_v2_perconv_interrupt_test.go`), green on unmodified `main`, proven
non-vacuous by mutation. **Zero production files changed.** Full design:
`docs/specs/architecture/1191-minted-perconv-interrupt-oracle.md`.

The ticket was filed as a suspected live regression ("interrupt never quiesces a minted
PTY turn"). The live gate (2026-07-29, claude 2.1.220) falsified that: the daemon routes
correctly and claude honours Esc in 65 ms. The real defect is in *reporting* a turn-end
for an interrupted turn — split out as [#1229](https://github.com/pyrycode/pyrycode/issues/1229),
which this ticket's test file is now the extension substrate for.

## Implementation

- **Topology, copied from #1195's `relay_v2_perconv_turn_end_test.go`**: mint a
  conversation over the wire, `send_message` to stamp the active cursor onto it, then
  interrupt. `PYRY_FAKE_CLAUDE_SESSION_ID_FROM_ARGV=1` + `PYRY_FAKE_CLAUDE_JSONL_TRIGGER_DIR`
  (both #1195) are what let the minted child's transcript be the file the daemon tails
  and let a mid-turn line be aimed at one child only.
- **`PYRY_FAKE_CLAUDE_ESC_ENDS_TURN=1`** (new use, existing knob) is set **daemon-wide**,
  so both the minted *and* bootstrap children get an ESC→`end_turn` handler. That is
  deliberate: it turns the bootstrap transcript from a blind spot into a mis-route
  detector — a pre-#1121-style redirect would append the canned end-turn line to
  `<sharedDir>/<initialUUID>.jsonl`, which Phase 5 asserts against directly.
- **Three independent oracles, each covering the next one's blind spot**: the wire
  `turn_end{ConversationID}` (weak alone — the id is stamped from the active cursor, not
  derived from which file changed), the on-disk transcript pair (`mintedID.jsonl` has
  the needle, `initialUUID.jsonl` does not — closes the wire oracle's blind spot), and a
  bare-ESC count over the shared stdin log (`before == 0` at Phase 4, `after == 1` at
  Phase 5 — sound for global absence even though one shared log can't attribute *which*
  child received a byte).
- **Structural, not stop-reason, causality.** The PTY tier can't assert
  `StopReason == "cancelled"` — `EventKindJsonlEndOfTurn` only ever reports `end_turn`
  (`internal/turnbridge/mapper.go:25-30`), so tui-driver can't distinguish an
  interrupt-stop from a clean one. The design instead makes the bare ESC the *only*
  thing in the test that can append an end-of-turn line to the minted transcript: the
  mid-turn kicker's line (`perConvMidTurnLine`) carries no `stop_reason`, and
  `fakeclaude`'s other write on that path (`appendTurnGrowth`) writes `{}\n`.
- **Phase 0 (AC4 wiring negative)**: an `interrupt` sealed before any `send_message`,
  while `CurrentConversation()` is still `""`. Its count read is deferred to Phase 4
  rather than timed with a settle-timer, so the negative doesn't smuggle in a timing
  assumption — Phase 4/5's `before == 0` / `after == 1` pair is what proves the oracle
  can see an ESC when there is one.
- **AC3 mutation-of-record**: temporarily rewrote the production wiring closure at
  `cmd/pyry/main.go:1017` to the pre-#1121 `pool.Lookup("")`, which took the test red at
  the scoped-`turn_end` phase (Phases 1 and 3 still green), then reverted. Chosen over
  mutating `activeInterrupter.SendEsc` directly because it reproduces the historical
  wiring defect end-to-end rather than simulating its effect.
- **`hasBareESC` (#794) deliberately not refactored** to share `countBareESC`'s body —
  editing a shipped live-gate capstone test for a ~10-line dedup was judged not worth
  the merge-surface risk. `countBareESC`'s doc comment records this as a decision.

## What was falsified, and why it matters beyond this ticket

The spec originally treated the diagnosis as a two-way disjunction: *the daemon
mis-routes* **XOR** *claude ignores Esc*. A green PTY-tier result would exonerate
routing and point at claude. The live gate found a third, unenumerated arm: **both work,
and the result is never reported.** That arm was invisible from this tier for a
structural reason — `fakeclaude` defines ESC→`end_turn` *by fiat*, so modelling the
actuation as an end-of-turn also models away the reporting step where the real defect
lives.

**General lesson**: a hermetic oracle that stubs the mechanism whose failure you're
trying to localize cannot narrow the field to two. Bound what a green *proves* to what
the test *actuates* ("the daemon put a bare ESC on the right child's PTY"), not to an
inference about the stubbed mechanism's real-world behavior.

## Patterns established

- **A knob set daemon-wide can turn a bystander into a detector.** Scoping
  `PYRY_FAKE_CLAUDE_ESC_ENDS_TURN` to only the minted child would have looked tidier and
  silently deleted the test's strongest red (the bootstrap-transcript mis-route check).
- **A shared log barred as an attribution oracle is still sound as a global count.**
  One shared stdin log can't say *which* child got an ESC, but pairing a `== 0`
  negative with a later `== 1` positive from the same run proves the oracle isn't just
  blind.
- **Deferring a negative's read past a natural settle beats timing it.** No settle-timer
  needed when the read is deferred to a point downstream work has already reached.

## Known limitation, not fixed on this ticket

Code review (PR #1200) flagged — SHOULD FIX, non-blocking, left as-is — that the
mis-route detector described above is unreachable in the actual mis-route world: Phase
4's `t.Fatalf` (no `turn_end` observed) preempts Phase 5 before the on-disk check runs,
so under a real pre-#1121-style redirect the test still fails correctly but with a
generic timeout message rather than the more specific "ESC actuated the shared
bootstrap claude instead." Left open for whoever next touches this file.
