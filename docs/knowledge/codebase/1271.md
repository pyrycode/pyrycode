# Ticket #1271 — Classify one probe run's outcome from a closed set of named outcomes

Adds `internal/e2e/realclaude/trail_run_outcome_test.go` (1233 lines, purely
additive) plus a bounded ~70-line edit to `trailer_admissibility_test.go`. The
run-level classifier that consumes [#1270](https://github.com/pyrycode/pyrycode/issues/1270)'s
two admissibility predicates and maps one probe run's raw observations onto
exactly one outcome from a closed, eleven-value set — so a run that measured
nothing is recorded as having measured nothing instead of falling through to a
finding. Split from [#1267](https://github.com/pyrycode/pyrycode/issues/1267);
offline, `e2e_realclaude` build tag, no live claude or credentials. Blocks
[#1268](https://github.com/pyrycode/pyrycode/issues/1268), which stages the
classifier against real processes.

## Implementation

- **Eleven outcomes: three answers, eight voids.** `trailOutcomeRunningAtTrailer`
  (an admissible attribution proves the group was alive when the trailer was
  written — the finding), `trailOutcomeMatchedUnattributed` (a row matched,
  nothing was attributed — never "it exited"), `trailOutcomeNoRowMatched` (the
  scan ran over well-formed rows and none matched — a statement about the scan,
  not about the command). Voids: `VoidBudgetFired`, `VoidNoTrailer`,
  `VoidTrailerScanAborted`, `VoidPyryDidNotExit`, `VoidArgvScanErrored`,
  `VoidNoRowsParsed`, `VoidLivenessInstrument`, plus `trailOutcomeOutOfContract`
  for an input value outside the closed set its own producer documents. String
  values carry a third prefix, `run-`, distinct from the scan's own input states
  (`trailAbsent`/`trailAborted`) and #1270's `gate-`/`admit-` result spaces —
  three namespaces now mean nearly the same words, so a copy-paste between them
  has to be a visible mistake rather than a plausible line.

- **`trailClassifyRun(trailRunReadings) trailRunOutcome` is pure: no exec, no
  clock, no filesystem, no `*testing.T`.** Same contract as `trailGate`,
  `trailAdmitAttribution`, `tdnClassifyReapLog`, `pinReadState` and
  `fifoLiveRead` — an instrument failure observed mid-turn is a datum to
  publish, not a reason to abort the turn.

- **A nine-check contract block guards the top, C1–C9, each returning
  `trailOutcomeOutOfContract` with a distinct `Detail`.** C1/C3 call #1270's
  shipped membership predicates (`trailIsGateValue`, `trailIsAdmitValue`) rather
  than re-deriving them; C7 calls `pinIsVerdict` (#1235) instead of a fresh
  switch. C2 re-checks #1270's own certified-reason invariant as a check on the
  *fixture* (a hand-built `trailGateResult{Value: trailGateUsable}` with no
  reason), not on reality. C4 and C5 are the composition contract:
  `TestTrailGateThenAdmit`'s test-level obligation ("the predicate is invoked
  only through a certifying gate") made a **checked contract** at the layer that
  holds both values, closing the false-proof path in both directions — a
  certifying gate must carry a classified attribution (C3/C4), and a proof can
  only come from a usable gate (C5). C8/C9 reject `pinScan` count pairs
  `pinPartition`/`pinScanArgv` cannot emit, including the errored-scan-with-
  nonzero-counts pair that would otherwise let a hand-typed fixture reach an
  answer.

- **No alignment check between `len(Liveness)` and `MatchCount`, deliberately.**
  `tdnDecideAfter` needs one because it indexes liveness against a pinned-pid
  list; this classifier never indexes, so a mismatch degrades only the
  corroboration summary and cannot mislabel a decision. Evidence-based: no
  observed failure, no defence built for it.

- **Decision order, eight steps, no default arm on the gate switch.** (1) An
  unusable gate answers first — structural, forced by C5 having already made a
  proof unreachable from any of those values. (2) An admissible attribution
  (`trailAdmitProof`) is **the finding**, consulted before any point-in-time
  reading, because those readings are expected to be late and must never be
  what the verdict rests on. (3) Pyry not exiting voids everything below it —
  every remaining reading is staged after teardown. (4) argv scan errored. (5)
  scan parsed no rows at all (reachable only with `!ArgvScanErrored` — AC4's
  separation). (6) a liveness read that failed as an instrument. (7) a match
  with nothing attributed. (8) otherwise: scan ran, no row matched. The gate's
  five-case switch has **no `default`**: C1 already proved membership, so the
  five cases are total, and a sixth gate value added to #1270 but not handled
  here would fall through to step 2 rather than hit a bottom-of-function
  catch-all — named as an open question (Q2 below), not papered over.

- **Why the proof outranks the pyry-exit void, against `tdnDecideAfter`'s own
  ordering.** `tdnDecideAfter` voids the run when pyry misses its exit grace,
  correctly, because *its* verdict rests on an after-teardown snapshot. This
  classifier's proof does not — it rests on an ordering argument internal to the
  run's own logs (trailer written, then the reaper named the group), so voiding
  it for a staging failure would suppress a finding the run genuinely
  established. The proof arm's own preconditions rule out the confusion a
  still-running pyry could introduce: a second agent run's reap pushes
  `LineCount` to 2, which `trailAdmitAttribution` answers with
  `trailAdmitVoidNotOneReapLine`, never proof.

- **The input record carries discriminators and already-publishable records
  only — no captured bytes, nothing from which `trailScanResult.Trailer` is
  reachable.** `trailGateResult`/`trailAdmitResult` whole (documented trap-free
  by #1270); `BoundFrom string` rather than the `trailObservation` that *embeds*
  `trailScanResult` (taking the observation would promote `.Trailer` straight
  back into reach); `MatchCount`/`RowsScanned` ints plus `ArgvScanErrored bool`
  rather than `pinScan.Matches`' verbatim argv; `[]pinStateOutcome` for
  liveness, which carries no command column by construction
  (`pinStateColumns` is `pid=,ppid=,stat=` with its own enforcing test).
  `Staleness` is not an input at all — the strongest form of AC3's "corroboration
  discriminates on `BoundFrom`, never on `Staleness != 0`" is a classifier that
  could not read a staleness if it wanted to. `.Trailer` appears nowhere in the
  new file (census: 15 + 4 in the two files entitled to it, 0 here, re-verified
  at documentation time with `--untracked`).

- **The outcome record carries no command string either — symmetric with the
  input side.** Counts, not rows; a rendered `LivenessSummary` via
  `tdnVerdictSummary` (`pid=N verdict` pairs, no command column reachable) reused
  rather than rebuilt.
  `TestTrailRunOutcomeCarriesNoCapturedBytes` places `trailNeedle` in four
  input strings (`Gate.Detail`, `Admit.Detail`, a `pinStateOutcome`'s `Detail`
  and `ToolStderr`) and asserts it appears nowhere in the marshalled outcome,
  plus a structural check that no `command`-shaped key exists.

- **Folds in #1270's parked SHOULD FIX, at both layers.** `trailAdmitAttribution`
  itself now rejects `certified == ""` before its budget check (a false-proof
  fixture that reached `trailAdmitProof` with nothing certifying it), returning
  `trailAdmitOutOfContract` — no new constant, no existing test row changes
  value. `trailClassifyRun`'s C4/C5 are the same class of defect caught as a
  *pair* at the composition layer, one level up. Belt-and-suspenders with
  different fabric only in placement, not in kind — both are deterministic code,
  stated as such rather than claimed as a stochastic/deterministic split that
  isn't there.

- **Test coverage — fourteen `TestTrail`-prefixed top-level functions, 82
  subtests, 0 SKIP** (re-verified at documentation time,
  `go test -race -tags e2e_realclaude -run '^TestTrail' -v ./internal/e2e/realclaude/`).
  `TestTrailAdmissibilityConstantsAreClosed` (#1270's file) extends its existing
  union map from eighteen to twenty-nine constants rather than starting a third
  closure test, plus a `zeroRun trailRunOutcome` pin (`Bounded == false`,
  `BoundFrom == ""` — an unbounded record must never read as bounded).
  `TestTrailClassifyRun` is table-driven with one row per outcome, an ordering
  regression pair (proof outranks the pyry-exit void; the pyry-exit void
  outranks the argv-scan-errored void), a late-read row (proof holds even when
  every liveness read is `pinStateNoSuchProcess` and claude still reads
  `pinStateRunning` — the systematic-false-negative case made executable), and
  one row per C1–C9. `TestTrailRunCorroborationNeverFlips` sweeps `ClaudeState`,
  `BoundFrom` and the three non-instrument-failed liveness verdicts across a
  cross-product and asserts `Value` never moves. `TestTrailRunComposesWithGateCases`
  sweeps `trailGateCases()` (#1270) building readings the way a correct consumer
  would, asserting no fixture reaches out-of-contract via C3/C4.
  `go vet`, `gofmt -l` on the two touched files, and the `--untracked` `.Trailer`
  census all clean.

## Patterns established

- **A composition obligation a sibling test already states
  (`TestTrailGateThenAdmit`) can be promoted to a checked contract at the layer
  that holds both values, rather than left as a test-only property.** C3/C4/C5
  are that promotion: the test still exists and still passes, but the pairing
  rule ("a certifying gate always carries a classified attribution"; "proof
  requires a usable gate") is now enforced for every future caller, not only
  for the rows in that one table.
- **Fold a parked SHOULD FIX in at both the layer it was found and the layer
  that composes it, when the defences are genuinely different rather than
  redundant.** The single-parameter contract check
  (`certified == ""` → out-of-contract) and the pair check (C4/C5) catch
  overlapping but not identical input shapes; recorded as belt-and-suspenders
  with the note that both are deterministic code — "different fabric," not a
  stochastic/deterministic split that isn't there.
- **A third value space that means nearly the same words as two existing ones
  needs a third, load-bearing prefix, verified free by census before use.**
  `trailOutcome*`/`run-` follows #1270's own precedent (`gate-`/`admit-`); the
  census recipe (`git grep -cP '\btrailOutcome'` against a `tdn` control) is
  reusable for the next value space in this family.
- **Extend a shipped closure test rather than starting a sibling.** AC5's own
  wording ("extending `TestTrailAdmissibilityConstantsAreClosed`") is the
  general form: one union map across every space in a family catches a
  cross-space collision no single-space closure test can see, and adding an
  eleven-entry block plus one zero-value pin is cheaper than a third test with
  its own copy of the same loop.

## Lessons learned

- **A `.Trailer` census run without `--untracked` is a vacuous pass on a new
  file** — #1270 hit this and named the fix; #1271 is the first ticket to
  actually depend on it (the new file is the thing being checked for absence).
  Re-run at documentation time as `git grep --untracked -cF '.Trailer' --
  internal/e2e/realclaude/`: 15 in `result_trailer_observation_test.go`, 4 in
  `trailer_admissibility_test.go`, 0 in the new file — matches the spec's
  predicted counts exactly.
- **`gofmt -l` stays dirty on `main` for three unrelated files in this
  package**, per the architecture spec's own warning; scoping the check to the
  two touched files (as the spec's verification recipe does) is what keeps the
  check meaningful rather than a pre-existing-failure red herring.
- **The size-decision table in the architecture spec (six comparable
  single-file `internal/e2e/realclaude` tickets, all landed in one developer
  run) held**: this ticket shipped in one run despite tripping both the
  ~600-line and ~10-branch red lines, the same calibration gap
  [[architect-1267-lifting-seams-does-not-shrink-an-outcome-table]] and
  #1270's own spec already recorded. Still a rules-calibration observation, not
  a per-ticket argument — repeating it here for the next ticket in this family
  that trips the same red lines.
