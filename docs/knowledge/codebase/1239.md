# Ticket #1239 — FIFO reader-presence liveness read, with its offline self-check

Adds `internal/e2e/realclaude/fifo_reader_liveness_test.go`: a helper, `fifoLiveRead(path)`,
that answers "is some process currently holding this FIFO's read end?" with **no pid and no
`ps`** — closing a defect class this probe family has now shipped twice (#1230's MUST FIX,
re-derived on #1235): an instrument whose failure mode reads identically to the result it
claims. `holdProbeFIFO` (`background_trigger_probe_test.go:663`) proves a command **could not
finish**; it says nothing about whether the command is still **alive** — a killed command
leaves the same held write end. `fifoLiveRead` closes that gap directly via
`open(path, O_WRONLY|O_NONBLOCK)`: success iff a reader holds the read end, `ENXIO` iff none
does. Zero production code — one new test file, no edit to any existing file, no `go.mod`
change. #1240 (the staged interactive-surface probe) is natively blocked on this ticket and
calls `fifoLiveRead` at the instant it records `turn_state{idle}`.

## Implementation

- **Three-valued outcome, never a bare boolean.** `fifoLiveOutcome{Verdict, Detail, Path, Mode,
  Errno, ErrnoName}` — `Verdict` is one of `fifoLiveReaderPresent` / `fifoLiveNoReader` /
  `fifoLiveInstrumentFailed` (kebab-case string consts, matching the package's
  `probeFiredBackground`-style idiom). `Detail` is prose naming which arm fired; `Mode` carries
  the `Lstat`-observed file mode so evidence shows what the gate actually admitted, not what was
  assumed.
- **Positive allowlist gate, not a blacklist, and it runs before the open.** `Lstat` first
  (surfaces `ENOENT` and any other stat failure as `instrument-failed` before the open is ever
  attempted), then `info.Mode().Type() != os.ModeNamedPipe` rejects everything except a FIFO.
  This closes the inverting failure on the **success** arm that errno discrimination cannot
  reach: a bare `open(O_WRONLY|O_NONBLOCK)` on `/dev/null` (a character device) or a regular
  file succeeds with no reader anywhere — a blacklist would read that as "reader present." The
  `/dev/null` case is the one that discriminates a positive `ModeNamedPipe` gate from a
  regular-file blacklist; the architecture spec measured the bare `open` succeeding on it before
  design and the shipped test asserts that measurement as a table row.
- **`ENXIO` is the only input that yields `no-reader`.** Everything else from the open —
  `EACCES`, `EINTR`, `EPERM`, unmapped errnos, non-`syscall.Errno` errors — yields
  `instrument-failed`, classified by a pure `fifoLiveClassifyOpenErr(err error) fifoLiveOutcome`
  driven with synthetic `*os.PathError{Err: syscall.EACCES}`-shaped values in the test, not real
  opens. This sidesteps two otherwise-unreachable arms: `EACCES` needs a `mkfifo(path, 0o000)`
  FIFO, which **succeeds** as root, so a real-open case would silently flip to `reader-present`
  under a root CI runner; `EINTR` cannot be produced from a real open on demand at all.
- **Errno names come from a hand-rolled `map[syscall.Errno]string`, not
  `golang.org/x/sys/unix.ErrnoName`.** `x/sys` is an indirect dependency (`go.mod`); calling
  `ErrnoName` would promote it to direct — a `go.mod` edit the ticket's Must-NOT-build list
  forbids. `syscall.Errno.Error()` was also rejected: it returns the platform's message text,
  which differs between Darwin (`"device not configured"`) and Linux (`"no such device or
  address"`) for the same `ENXIO`. Unmapped errnos fall back to `errno(N)` — the number is never
  dropped.
- **`Kill()` does not flip the read — `Wait()` does.** Measured during design: five consecutive
  reads taken after `cmd.Process.Kill()` and before `cmd.Wait()` all returned `reader-present`.
  The kernel closes the child's fds (releasing the FIFO read end) at reap time, not at signal
  delivery — `Wait()` is the barrier, not a tidiness step. The shipped flip test
  (`TestFIFOReaderLiveness_FlipsAcrossOneReaderLifetime`) calls both and comments the ordering as
  load-bearing; a test that reads between `Kill()` and `Wait()` would fail on *every* run, not
  intermittently, and would misdirect a future maintainer into debugging the read instead of the
  missing reap.
- **Four tests, one shared helper, deliberately not combined.** AC1's flip test kills its reader
  mid-test (no reader-exit cleanup registered — the reader is already reaped by the time the
  body ends); AC4's non-perturbation test needs a reader that survives to cleanup so `:1123`'s
  release-ordering assertion still means something. The two want opposite lifetimes from their
  reader and stay as separate tests sharing `holdProbeFIFO`.
- **Non-perturbation relies on `holdProbeFIFO`'s persistent write end, not a hand-rolled one.**
  Each `fifoLiveRead` call opens and immediately closes a second, transient write end. POSIX
  delivers EOF to a FIFO reader only when the *last* writer closes, so while `holdProbeFIFO`'s
  write end stays open the transient one closing is invisible to the reader — proven empirically
  in `TestFIFOReaderLiveness_RepeatedReadsDoNotPerturbReader` (three reads, reader still blocked
  after), not cited as a POSIX fact.
- **Symbol and test-name prefixes (`fifoLive`, `TestFIFOReaderLiveness_`) were grepped for
  collisions by name** across `main` and every in-flight sibling branch touching this package
  (`feature/1174`, `feature/1219`, `feature/1230`) — a branch-diff overlap check alone does not
  catch same-package identifier collisions.

## Patterns established

- **Prove an offline gate by inversion, not just by having it pass.** The developer temporarily
  inverted the mode gate into a regular-file blacklist (`mode.Type() == 0`) and pasted the
  resulting failures into the PR body before restoring it. The inverted run failed in **three
  different directions**, and only one was the actual inverting defect: `/dev/null` flipped to
  `reader-present` (the real defect the gate exists to close); a symlink-to-FIFO flipped to
  `no-reader` (because `open` follows the link — the errno arm confidently answered a question
  the gate itself never vetted); a directory produced an unmapped `errno(21)`/EISDIR detail.
  Asserting `verdict != reader-present` **and** `verdict != no-reader` **and** a per-row `Detail`
  substring is what makes all three visible — any one assertion alone would have hidden two of
  them. Reusable recipe for any ticket in this family: write the final gate, confirm green,
  invert it into the specific wrong-but-plausible shape the AC exists to reject, paste the
  failure, restore.
- **A killed-but-unreaped process is the recurring trap in this probe family.** `ps` lists
  zombies as alive (#1230, #1235); here the same shape shows up as "the observable hasn't
  synchronized yet" rather than "the process is gone" — `Wait()`/reap is the actual releaser in
  both cases. Any future liveness read in this package should ask explicitly what barrier
  separates "signalled" from "state visible."
- **`t.TempDir()` doubles as the directory test row** — no `os.Mkdir` needed, and the row stays
  free of setup that could itself fail (code review NIT-adjacent observation, folded into the
  shipped test).

## Lessons learned

From the PR body (#1242) and code review (PASS, 0 MUST FIX / 2 SHOULD FIX / 1 NIT — both SHOULD
FIX findings shipped **unfixed**, deliberately, under the 3-finding merge threshold; worth
picking up on #1240's branch since that ticket both extends and depends on this file):

- **[unfixed] `fifo_reader_liveness_test.go:141` — the `Lstat` failure arm's errno recording has
  zero assertion coverage.** AC3 requires a failing `Lstat` (including `ENOENT`) to record the
  errno both numerically and by name; `fifoLiveRecordErrno(&out, err)` does that at the `Lstat`
  branch, but the only test row that reaches it (`missing path`) asserts just `wantDetail:
  "lstat"` and `wantMode: false` — deleting line 141 leaves the whole suite green. The shipped
  behavior is correct (measured: `os.Lstat` on a missing path yields `*os.PathError` →
  `errors.As` extracts `ENOENT`/2), but unproven, which is precisely the defect class this
  ticket exists to close. Fix identified but not applied: add `wantErrno: int(syscall.ENOENT)`,
  `wantErrnoName: "ENOENT"` to the `missing path` row.
- **[unfixed] `fifo_reader_liveness_test.go:138` — the `Lstat` failure `Detail` stutters the op
  and the full path.** `os.Lstat`'s own `*os.PathError` already formats as `lstat <path>:
  <cause>`; wrapping it again with `fmt.Sprintf("lstat %s: %v", path, err)` doubles both,
  producing `"lstat /tmp/…: lstat /tmp/…: no such file or directory"`. Matters here specifically
  because the type's doc comment says consumers record `Detail` **verbatim into published
  evidence**, and #1240 is specified to do exactly that. Fix identified but not applied: drop the
  path from the format string (`fmt.Sprintf("lstat: %v", err)` or bare `err.Error()`) while
  keeping the `"lstat"` substring the missing-path row's assertion matches on.
- **[unfixed, NIT] `fifo_reader_liveness_test.go:439-442` — a `reader-present || no-reader`
  disjunction guard is unreachable dead code**, shadowed by an earlier `t.Fatalf` on
  `Verdict != instrument-failed` that already aborts the subtest on both directions. Coverage is
  unaffected (the earlier check plus the detail-substring check still catch what the comment
  describes); the block just reads as load-bearing when it isn't.
- **A blacklist-vs-allowlist gate needs a case that only the correct implementation passes, not
  just a case both would pass.** `/dev/null`'s bare `open(O_WRONLY|O_NONBLOCK)` succeeding with
  no reader anywhere is what makes the character-device row discriminate; a regular-file-only
  test would not have caught a blacklist gate.
- **`Kill()` before `Wait()` reads as "reader present" every time, not intermittently** — see
  § Implementation. Confirmed exactly as the architecture spec's pre-implementation measurement
  predicted.
