# Ticket #943 — interactive session-pool claude spawn pre-approves project MCP servers

The mobile/desktop remote-head daemon spawns its per-conversation claude through `internal/sessions` with only `--session-id` plus the model/effort/YOLO flags from `claudeSettingsArgs`. It never passed `enableAllProjectMcpServers`, so when the operator has any MCP server configured (user-level `~/.mcp.json` or a project `.mcp.json`), claude 2.1.199 renders its "N new MCP servers found in this project" startup modal, the PTY readiness check reports `tuidriver: unexpected dialog at startup`, and every live turn wedges. Agent-run already carried this fix, un-gated, since `d10ce87` — this ticket ports it to the session-pool spawn path, which is what the phone and desktop remote heads actually drive.

## Implementation

- New `internal/sessions/settings.go`: `writeMCPSettings() (string, error)` writes `{"enableAllProjectMcpServers":true}` to an `os.TempDir()` tempfile (`pyry-session-settings-*.json`) and returns its path. Deliberately not a reuse of `internal/agentrun/settings.WriteSettings` — that writer always stamps `permissions.defaultMode:"dontAsk"` and requires non-empty `allowedTools`, both wrong for an interactive session that must keep normal tool-prompt behaviour (AC #2). ~15-line duplicate of the tempfile + best-effort-cleanup-on-error discipline, consistent with the project's established "resist over-DRY on duplicated primitives" convention.
- New `Session.settingsPath string` field (`session.go`), immutable post-construction, same lock discipline as `spawnBase` (read without a lock).
- `--settings <path>` is appended into `spawnBase` — **not** `claudeSettingsArgs` — at both construction sites:
  - `Pool.New` (bootstrap, `pool.go:401`): `base := append(slices.Clone(cfg.Bootstrap.ClaudeArgs), "--settings", settingsPath)`.
  - `Pool.buildSession` (minted, `pool.go:1209`): appended right after the existing `--session-id` append.
  - Because `Session.spawnArgs` (the #842 live-restart recompose) and a backoff restart's re-exec both derive from `spawnBase`, this one seam covers bootstrap + minted + restart with no extra wiring.
- Write failure at either construction site is a hard error (`sessions: write mcp settings: %w`) — a daemon that started anyway would silently wedge every turn on the modal.
- Cleanup is best-effort `os.Remove`, run only after the child is confirmed dead:
  - Minted: `Pool.Remove`, right after `sess.Evict(ctx)` returns.
  - Bootstrap (never `Remove`-d): a `defer` in `Pool.Run`, fires on ctx cancel / shutdown.
- Full design, data flow, and the enumerated accepted-leak cases: `docs/specs/architecture/943-interactive-spawn-mcp-settings.md`.

## Patterns established

- **Immutable per-session config belongs in `spawnBase`, not `claudeSettingsArgs`.** `claudeSettingsArgs` recomputes from mutable `SessionSettings` on every call; anything that's fixed at session-construction time and must survive every recompose (backoff restart, live settings-restart) goes into `spawnBase` instead. Same seam #842 established for the settings-restart recompose; this ticket confirms it generalizes to a second, unrelated fixed-content file.
- **Build, don't reuse, when the existing writer's defaults are wrong for the new caller.** `internal/agentrun/settings` and `internal/sessions/settings.go` now both write MCP-enable settings files with deliberately divergent shapes (deny-default headless vs. no-permissions-change interactive) — see the cross-reference in [agentrun-settings-subpackage.md § Related](../features/agentrun-settings-subpackage.md).

## Lessons learned

- **A change to a shared spawn-composition seam fans out beyond its home package.** The ACP-embedded pool (`cmd/pyry acp`, #761) spawns through the same `buildSession`, so three ACP argv-equality tests (`TestACP_SessionNew_SpawnsOneInteractiveClaude`, `TestACP_SessionLoad_ResumesExistingClaude`, `TestACPConformance_FullSessionDrive`) broke on the new `--settings <path>` pair and needed a `stripMCPSettingsPair` test helper before they'd assert the `--session-id`-only interactive-path shape again. Before assuming a change to `internal/sessions`' shared spawn base is scoped to one package, check `cmd/pyry` for argv-equality assertions (or run `codegraph_impact` on `buildSession`) — the blast radius follows every caller of the seam, not the package boundary.
