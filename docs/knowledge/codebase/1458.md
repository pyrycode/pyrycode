# Ticket #1458 — Probe instrument: `finGatherReadings` carries the pinned-pid sighting route's pid read from its caller (offline)

`trailClassifyRun`'s `trailGateAbsentOwesNone` arm consults the pinned-pid
sighting route #1440 built, but the route reads two `trailRunReadings` fields —
`Ordering` and `PinnedPid` — that no shipped gather filled. This ticket ships
the pid-read half: `finGatherInputs` gains a `PinnedPid pinStateOutcome`
field, staged by the one live caller (`finExitRunProbe`) from a `pinReadState`
taken over the caller's own pinned pid set *after pyry exited*, and carried
through the gather whole. The ordering half is #1457's; the arm's guard reads
`Ordering` before consulting the route and is single-sided by design, so with
only the pid staged the arm still answers `run-void-sighting-route-not-staged`
— **no outcome moves.** Offline throughout: no live claude, no credentials.

PR [#1460](https://github.com/pyrycode/pyrycode/pull/1460). Spec:
[`docs/specs/architecture/1458-gather-carries-the-pinned-pid-reading.md`](../../specs/architecture/1458-gather-carries-the-pinned-pid-reading.md)
(architect self-review PASS). Five code-review rounds — FAIL ×4 then PASS —
all on the comment-citation tail, never on the implementation (see below).

## Implementation

- **`finGatherInputs` gains an eighth field, `PinnedPid pinStateOutcome`**,
  appended at the end after `RunnerPath`. Its doc carries the field's full
  contract: the one admissible producer is `pinReadState`, over a pid from the
  caller's own pinned set, read after pyry exited — never `trailSightingPin`
  (a fixture constructor whose own doc says it sets no `StateColumn`/
  `ToolStderr`, exactly the shape a live failing read *does* produce) and
  never the gather's own per-matched-pid loop (different operand, different
  instant). The selection rule lives on the field, not only at the caller:
  the pinned set is a slice and this field is one outcome, so the caller reads
  the first entry when non-empty and takes no read at all when empty. The
  zero `pinStateOutcome` (`Verdict ""`) is the honest report for that empty
  case — `trailSightingReasonPidReadFailed`'s doc already names it among the
  shapes the route answers for, so no C10 contract check is owed over it. It
  travels **whole**, never narrowed to `.Verdict`, because narrowing would
  leave #1459's future gather-tier captured-bytes sweep no route to travel.
- **The pass-through, in `finGatherReadings`:** `readings.PinnedPid =
  in.PinnedPid` — whole value, no default, no normalisation, no `pinIsVerdict`
  call, beside the existing `PyryExited`/`ClaudeState` tail. The existing
  per-matched-pid `pinReadState` loop over `scan.Matches` is untouched, and no
  second `pinReadState` call was added inside the gather — that loop's
  operand (live argv-scan matches, gather time) differs from this route's
  operand (a caller pid, post-exit) in both value and instant.
- **The caller, `finExitRunProbe` (step 3b):** `var pinnedPid
  pinStateOutcome; if len(h.Pin.PGIDs) > 0 { pinnedPid =
  pinReadState(h.Pin.PGIDs[0]) }`, taken immediately after the exit wait and
  staged into the `finGatherInputs` literal beside `Pinned`/`RunnerPath`. The
  first entry is not an arbitrary pick: `finLivePinReduce` projects one entry
  per FIFO-matched row with duplicates deliberately intact, so a healthy run's
  `h.Pin.PGIDs` carries two entries naming one detached group
  (`finLivePinWantRows == 2`, per `TestFinLivePinReduce`'s raw-projection
  subtest) — not the `len == 1` a stale, out-of-scope parenthetical elsewhere
  in the tree claims. No dedupe or cardinality assertion at this line; that's
  `finOutcomeStaging`'s count arm's business.
- **Four traps, all avoided** (the spec's own framing, each answered where a
  developer meets it):
  1. Reusing the gather's in-body `pinReadState` loop — wrong operand, wrong
     instant.
  2. Landing the reading on `Liveness` instead of `PinnedPid` — type-correct
     (`pinReadState` returns exactly `Liveness`'s element type) and silently
     wrong, since `Liveness` feeds the published verdict summary and goes
     blind once claude exits. `TestFinGatherPinnedPidDoesNotReachTheLiveness`
     is the deterministic net.
  3. Reusing `claudeState`'s outcome or re-reading `h.ClaudePID` — that's
     claude's own pid, not a member of the pinned set this route is about.
  4. Calling `pinReadState(0)` to represent "no read" on an empty set —
     `pinReadState` with a non-positive pid returns
     `pinStateInstrumentFailed`, which claims an instrument ran and failed;
     the zero `pinStateOutcome` says no instrument was there. Only the
     explicit `len(...) > 0` guard is honest.
- **Two new offline tests in `finding_run_gather_test.go`:**
  `TestFinGatherPinnedPidDoesNotReachTheLiveness` (AC2) mirrors
  `TestFinGatherRunnerPathDoesNotReachTheScan`'s shape — a shared
  `finGatherInputs` base with rows varying only the reading's shape (zero,
  running-with-`StateColumn`, instrument-failed-with-`ToolStderr`/`Detail`),
  asserting whole-value equality on `PinnedPid` and `len(Liveness) == 0` on
  every row. `TestFinGatherHalfStagedRouteMovesNoOutcome` (AC3) drives the
  shipped classifier over two gathers differing only in `PinnedPid`,
  premise-asserts both reach `trailGateAbsentOwesNone`, and asserts
  whole-`trailRunOutcome` equality — catching a pass-through that defeated the
  single-sided `Ordering` guard through `Route`, `RouteReason` or `Detail`,
  not just `Value`. Both proven RED→GREEN in code review via `go test
  -overlay` mutants: append-to-`Liveness`, narrow-to-`.Verdict`,
  drop-the-pass-through, and an `&&`-guard defeat (AC3 reddens, AC2 correctly
  stays green).
- **AC4 comment sweep, three groups:** 7 sites in `trail_run_outcome_test.go`
  (the `trailOutcomeVoidSightingRouteNotStaged` family, the no-C10 note, the
  `trailRunAbsentOwesNoneReadings`/`trailRunSightingEstablishedReadings` docs,
  a `trailRunCases` row, a `TestTrailRun...` doc) went outright false —
  "no shipped gather fills either input" is now false for the pin — and were
  corrected. 6 sites the sweep's `gather` anchor couldn't reach needed interim
  wording rather than a false-to-true flip: two paragraphs (the
  `TestTrailRunOutcomeCarriesNoCapturedBytes` scope note and the
  `trailClassifyRun` `&&`-guard note) survive *literally* but their *basis*
  moved — live `ps` bytes now really do enter `PinnedPid`, non-rendering is
  the only thing standing between them and a public artifact — and both now
  name **#1459** as the ticket that owes the gather-tier captured-bytes sweep;
  the `TestFinGatherReturnsNoCapturedBytes` scope note similarly now names a
  third input with no plant added (deliberately — a new route gets its own
  sibling test, not a third plant on this one); three sites carry a stale
  field count (`finGatherInputs` 7→8 fields, "All three"→"All four" staged
  fields plus a fourth zero-polarity bullet, an 8-arg positional
  counterfactual). 3 sites were verified as correctly **unedited** — they're
  about the `Ordering` input (#1457's half) or unrelated symbols.
- **An out-of-scope commit was inherited and reverted before real work
  started.** The branch head this run inherited (`508fbf8`, an auto-commit)
  carried a repo-wide re-point of `file.go:NNN` citations across 79 files —
  75 of them outside this ticket's four. It was wrong, not merely
  out-of-scope: it re-pointed cites into files the commit never touched
  (`ptyrunner/runner.go`), and it rewrote fixture *data* that merely looked
  like line numbers (`"duration_ms":4210` → `4567`, a `"pgid":7930` → `8287`,
  and the shipped cap `line[:512]` → `line[:558]`). `cce4891` is the ticket's
  real implementation commit; `12aee0d` reverts the other 75 files to `main`.

## Patterns established

- **A field that opens a captured-bytes channel but has no downstream
  contract check needs its safety argued in three different-fabric places at
  once, not one.** No C10 exists over `PinnedPid` (the no-C10 note explains
  why), so the field's own doc naming the one admissible producer, a
  whole-value-equality test a narrowing edit can't compile past (AC2), and a
  whole-outcome-equality test that catches a pass-through defeating the
  ordering guard (AC3) are three independent nets, deliberately not reducible
  to one — the same lesson [`codebase/1452.md`](1452.md) recorded for
  `RunnerPath`, applied to a field the type system can't discriminate.
- **`pinReadState(pid <= 0)` is not a stand-in for "no read."** It returns
  `pinStateInstrumentFailed`, a member of the closed verdict space claiming an
  instrument ran and failed. Any caller representing "there was nothing to
  read" must guard explicitly and use the zero value, never call the producer
  with a sentinel pid.
- **A comment's stated cardinality is not ground truth for an index bound.**
  A pre-existing, out-of-scope parenthetical elsewhere in the tree claims
  `len(h.Pin.PGIDs) == 1`; the actual measured value (`finLivePinReduce`,
  `TestFinLivePinReduce`'s raw-projection subtest) is 2, undeduped by design.
  AC1's selection rule was built off the measurement, not the comment — and
  the comment was flagged, not "fixed," since correcting it was a different
  ticket's scope.

## Lessons learned

**From the PR body's own "Lessons learned" section** (developer, about the
inherited out-of-scope commit):

- **`cite-guard` being diff-scoped is a licence not to sweep, and reading it
  as an invitation to re-point the existing stock inverts the tax it exists
  to remove.** Its `changedLines` doc states the contract: stop the *inflow*
  of new citations, don't revalidate what's already there.
- **A bulk line-cite re-pointer cannot tell a citation from a number that
  merely looks like one.** `"duration_ms"`, `"pgid"` and a byte-cap slice
  literal are all four-digit-ish integers in comment-or-fixture context; any
  such sweep needs the target file's own diff as its authority.
- **Verify a re-point against a file the commit never touched.** The
  cheapest falsification was noticing cites into `ptyrunner/runner.go` had
  moved despite the file being absent from the commit's changed-file list.

**From five rounds of code review**, all on the AC4 comment-citation tail
(the implementation itself passed unchanged from round one):

- **The spec's own "the cite tail is empty" measurement was correct and
  wrongly scoped.** It measured the inbound tail of the file *gaining the
  field* (`finding_run_gather_test.go`) and found it empty — true. The file
  the AC4 sweep actually *grows* is `trail_run_outcome_test.go`, the most-cited
  file in the package (+51 lines, 185 endpoints across 18 files), and the
  spec never measured it. **Rule to carry forward: measure the inbound tail
  of every file the diff adds lines to, not the file the ticket is named
  after.** `cite-guard` cannot close this gap — it bans *new*
  symbol-replaceable cites, it does not detect existing ones going stale.
- **Three citation forms are in play, and a filename grep sees only one.**
  Explicit `file.go:NNN`, bare `(:NNN)` inheriting the nearest preceding
  reference (which can be a **symbol**, not only a filename), and
  `<Symbol>:NNN`. Rounds 2–4's residual misses were all the symbol-anchored
  or symbol-inherited-bare forms — invisible to a filename-only scan even
  when the file was already open in the same commit.
- **A displacement fix and a pre-existing-staleness repair are different
  operations, and conflating them is worse than doing nothing.** Round 5
  reversed a FAIL over two cites that were already broken on `main` before
  this branch existed; re-pointing them by content-preservation would have
  "laundered" a broken cite into a verified-looking one rather than fixed
  anything. Both belong to a seven-member pre-existing-stale family this PR
  surfaced (`C8`/`C9`, `C4`/`C5`, and three more found across the rounds); the
  recommendation is one cleanup ticket for all seven, not piecemeal fixes
  riding this PR. **No cleanup ticket number was assigned as of this
  writing** — worth filing.
- **The method that eventually converged:** build a two-sided line map from
  `git diff -U0 origin/main...HEAD`, validate every *unchanged* context line
  maps to byte-identical content first (this also confirms git's `-a,0`
  insertion-line convention is handled correctly), pair every citation
  occurrence across all three forms, then hand-verify content two-sidedly
  (`main`-content at the old number vs `HEAD`-content at the new number)
  rather than trust inference. The round-3 reviewer's own first pass returned
  zero suspects for the two residual sites — not because the tree was clean,
  but because a backtick-only symbol rule was blind to bare, unbacked symbol
  anchors; broadening the resolver is what surfaced them.
