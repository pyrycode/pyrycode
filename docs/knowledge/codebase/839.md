# Ticket #839 — Deterministic bootstrap `--session-id`: retire `--continue` restart heuristic and startup adopt-by-mtime

Split from #828. The bootstrap claude was spawned with `--continue` (resumes
the most-recent session in the working dir) and, at startup,
`reconcileBootstrapOnNew` adopted a bootstrap id by scanning the shared
`~/.claude/projects/<encoded-cwd>/` dir for the newest `<uuid>.jsonl`. Both
mechanisms let a second, unrelated claude process writing into the same
shared dir redirect which conversation the daemon resumes on restart — a
confused-deputy isolation gap. This ticket closes it: the bootstrap now
always spawns with an explicit `--session-id <bootstrapID>` resolved from the
daemon's own persisted id, and the startup adopt-by-mtime scan is deleted
outright. `security-sensitive` — architect security review PASS (net
isolation improvement, no new untrusted-input-to-argv path); see the spec's
security section for the full seven-category pass.

Unblocked by two merged prep tickets: [#861](861.md) (mechanical e2e
`seedBootstrapRegistry` migration, zero behavior change) and [#854](854.md)
(interactive-bootstrap deadlock fix, deliberately left the `--continue` spawn
shape for this ticket).

## Implementation

Three production files, two new exported symbols, per the spec's **pull, not
push** seam choice — the supervisor resolves `--session-id` from a
spawn-time provider closure rather than the pool pushing an argv swap when
`/clear` rotates the id:

- **`internal/supervisor/supervisor.go`** — new `Config.ResolveSessionID
  func() string` field, called at the start of every spawn in `Run`. A
  non-empty return appends `--session-id <id>` to argv and suppresses
  `--continue` (mutually exclusive). `buildClaudeArgs` gained a fourth
  parameter (`sessionID string`); `sessionID != ""` short-circuits the
  existing `--continue`-prepend logic entirely — the `firstRun`/`continueLast`
  branch is untouched when `sessionID == ""`, so every non-bootstrap caller
  (`ResumeLast`-only) is byte-identical.
- **`internal/sessions/pool.go`** — the bootstrap `supCfg` now sets
  `ResumeLast: false` and `ResolveSessionID: func() string { return
  string(p.BootstrapID()) }`. `p` is late-bound (`var p *Pool` declared
  before `supCfg`, `p =` instead of `p :=` at the `&Pool{...}` literal) so
  the closure can reference it before it exists yet — the resolver is only
  *called* at spawn time, long after `New` returns, mirroring the existing
  `bootstrapSup` late-bind pattern from #838. New `Pool.BootstrapID()
  SessionID` accessor mirrors `DefaultSettings()`'s RLock-and-resolve-fresh
  shape, deliberately reading `p.bootstrap` (not `Default().ID()`/`sess.id`)
  so no new reader of `sess.id` is introduced — preserves `RotateID`'s
  documented "no concurrent reader of `sess.id`" invariant. The
  `reconcileBootstrapOnNew(p, cfg.ClaudeSessionsDir, cfg.Logger)` call at the
  end of `New` is deleted outright (one fewer startup-fatal path: a
  shared-dir read error at construction no longer aborts startup).
- **`internal/sessions/reconcile.go`** — `reconcileBootstrapOnNew` deleted.
  `mostRecentJSONL`, `encodeWorkdir`, `DefaultClaudeSessionsDir`,
  `newTranscriptResolver`, `newProbePreferredTranscriptResolver` all stay —
  the first four still back `newTranscriptResolver`'s AC5 no-lsof fallback,
  the last is #838's growth-confirm resolver, both unrelated to startup
  adoption. Pruned now-unused imports (`errors`, `io/fs`, `log/slog`).

**`/clear` reconciliation falls out for free.** The rotation watcher's
existing `handleCreate → RotateID` seam already updates and persists
`p.bootstrap` when `/clear` rotates the session; `ResolveSessionID` re-reads
`p.bootstrap` on every spawn, so a post-`/clear` restart picks up the rotated
id with zero new wiring — no `onRotate` branch, no supervisor argv-swap
method. The watcher's existing `ref.ID == stem` guard
(`rotation/watcher.go:165-169`) already suppresses a misfire on claude's
first `<bootstrapID>.jsonl` CREATE, since `<bootstrapID>` is now always a
*current* id; `RegisterAllocatedUUID` was considered and deliberately not
added (no observed failure mode it would guard against — Evidence-Based Fix
Selection).

## Patterns established

- **Pull beats push for reconciling a fixed spawn value with a rotating
  source of truth.** When a value needs to be current-at-spawn-time and its
  source can change between spawns (here: `p.bootstrap` rotating on
  `/clear`), prefer a spawn-time provider closure the consumer calls fresh
  each time over wiring a push notification that updates a cached copy. Pull
  reuses whatever re-read-on-each-iteration seam already exists (`Run`'s
  loop here); push needs new plumbing (an `onRotate` handler, a
  swap-without-restart method) for a problem the re-read already solves.
- **Read the pool's canonical guarded field, not a derived one, when adding
  a new spawn-time reader.** `BootstrapID()` reads `p.bootstrap` under
  `p.mu`, not `Default().ID()` (which resolves through `sess.id`).
  `RotateID` mutates `sess.id` *without* `Session.lcMu`, under the
  documented invariant that `sess.id` has no concurrent reader — so a new
  reader must be routed around it, not through it, or that invariant quietly
  breaks.

## Lessons learned

- The e2e seed cascade this ticket would otherwise have needed (~15 test
  files depending on adopt-by-mtime to establish the bootstrap id) was
  already fully absorbed by #861's `seedBootstrapRegistry` migration, landed
  as a separate prep ticket specifically to keep this ticket's diff to the
  actual behavior change. `go test -tags e2e ./internal/e2e/...` needed no
  further test-file edits — confirms the spec's "developer's e2e job is to
  verify, not build" prediction held exactly.

## Testing

- `internal/sessions/pool_bootstrap_sessionid_test.go` (new) — drives `Pool`
  directly, no live claude: no-foreign-adoption with a newer foreign
  `<uuid>.jsonl` in `ClaudeSessionsDir` (proves adopt-by-mtime is gone),
  `/clear` reconcile via `RotateID` (next `BootstrapID()` returns the rotated
  id), and id stability across repeated reads / warm-start reuse.
- `internal/supervisor/args_test.go` — extended `buildClaudeArgs` table:
  `sessionID != ""` wins over `continueLast` on both `firstRun=true` and
  `firstRun=false`, no `--continue` ever appears alongside `--session-id`;
  `sessionID == ""` rows unchanged (regression); input-slice-not-mutated
  assertion extended to the new param.
- `go test -race ./...`, `go vet ./...`, `staticcheck ./...`,
  `go test -tags e2e ./internal/e2e/...` all green.
