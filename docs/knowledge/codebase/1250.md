# Ticket #1250 — Offline teardown-liveness instrument: reap-log classifier, real-`ps` premise, record writer

Adds `internal/e2e/realclaude/teardown_liveness_test.go` (`tdn*` prefix), the third and
last credential-free instrument #1251's live teardown-liveness rig depends on as **code,
not evidence**: a pure classifier over `agentrun.ReapDescendantGroups`'s own log line, a
real-`ps` proof of a fail-safe premise #1235 left unasserted, and the record + one-file
writer that composes all three readings (`pinStateOutcome`, `fifoLiveOutcome`, this
ticket's `tdnReapOutcome`). No production files, no live claude turn, no verdict about
pyry.

Split from #1231 before #1235 merged; #1235 shipped the per-pid liveness classifier this
ticket's original AC1–AC3 specified, so this ticket is the reap-log half plus one real-bytes
gap in the liveness half — see the ticket body's disposition table for the full struck-AC
accounting.

## Implementation

- **Reap-log classifier (AC1).** `tdnClassifyReapLog(stderr []byte, heldPGID int)
  tdnReapOutcome` is pure over bytes (no exec, no file read, no clock) and answers one of
  four values: `held-pgid-in-reap-line`, `reap-line-without-held-pgid`, `no-reap-line`
  (ambiguous by construction — `reap.go:64` guards the emit on `len(reaped) > 0`, so
  silence means "ran and reaped nothing" **or** "never fired," and the `Detail` spells out
  both readings rather than picking one), and the package-standard `instrument-failed`
  (a line whose `pgids=` cannot be parsed is never reported as "absent" — that would be a
  leak finding manufactured out of the instrument's own breakage). `heldPGID <= 1` is
  rejected before any scan (`reap.go:52` skips those pgids before killing anything, so no
  line could ever answer for them).
- **Anchor is the bare message text, a string literal** (`tdnReapMessage`), never a
  reference to anything `reap.go` defines and never including `msg="`, a level token, or a
  timestamp — because the two `slog` handlers in play render those differently, and the
  ticket body cited the wrong one (see Patterns established).
- **Membership over parsed integers, never a substring** (`tdnParsePGIDs` + `tdnAttrIndex`).
  A `pgids=[<held>]` substring probe is correct for one group and inverts to a false
  negative the moment `slog` quotes a second (`pgids="[A B]"`); its dual is a false
  positive (held `77` matches the text of `pgids=[7788]`). Both directions are fixture rows.
  `tdnAttrIndex` requires the attribute key to start the line or follow a space — closing a
  hole the spec didn't name: a handler's `WithAttrs` adding `reap_pgids=` would otherwise
  read as this line's `pgids=`.
- **Every anchored line scanned, pgids unioned, not first-match** (`out.LineCount`,
  `seen` map). `Count` carries `reap.go`'s own `count=` for cross-check against
  `len(PGIDs)`; disagreement is recorded in `Detail`, never escalated.
- **AC2 — the liveness read's fail-safe premise proved against real `ps` bytes**
  (`TestTdnRealPSMisinvocationsFailSafe`). Four arms (bad column with `=` suffix, bare bad
  column, illegal option, out-of-range pid) each assert the load-bearing premise —
  `len(exitErr.Stderr) > 0`, read from **`.Output()`'s own `*exec.ExitError.Stderr`**, the
  exact channel `pinReadState` consumes (`tdnRunPS`) — then feed the real bytes through
  `pinClassifyState` and require `pinStateInstrumentFailed`, never `pinStateNoSuchProcess`
  or `pinStateRunning`.
- **Arm A uses four requested columns, not the ticket body's three**, because `ps` drops
  the unknown column and prints the rest: three columns comes back as a two-field row
  `pinStateRow` rejects outright, proving nothing; four columns comes back as a
  three-field row (`1 0 Ss`) that `pinStateRow` parses **successfully** as a live-looking
  pid 1 — demonstrating that branch order alone, not the row shape, keeps a broken `ps`
  off a fabricated `running` verdict (`tdnAssertPartialRowIsStillNotAReading`).
- **Arm D confirms the rejection instead of assuming a constant.** The out-of-range
  threshold is platform-dependent — macOS: `ps -p 99999` is a clean absence, `100000` is
  the first rejection; Linux's default `pid_max` is 4194304, where `100000` is an ordinary
  unused pid. `tdnOutOfRangeLadder` escalates (`100000` → `4194305` → `2147483648` →
  `4294967296` → a string operand past `int64`) until one candidate actually produces
  non-empty stderr, `t.Fatalf`s naming every rung if none does, and routes through
  production `pinStateArgs` wherever the candidate fits an `int` so the arm also exercises
  the real argument-building path.
- **AC3 — the record and writer.** `tdnRecord` composes `pinStateOutcome` (#1235),
  `fifoLiveOutcome` (#1239), and this ticket's `tdnReapOutcome` — no new liveness type, no
  verdict synthesized across members; both live consumers (#1236 AC2, #1251 AC3) own their
  own pid/content join at the rig level. `ArgvScan` (`pinScan`) is the only member that can
  carry a command string, by design — `command` reaches the record from the content-first
  argv scan, never the narrow per-pid read `TestPinStateColumns_ReadsNoEnvironment` pins.
  `writeTdnArtifacts` mirrors `writeReachArtifacts` (`MarshalIndent`, `0o600`, `t.Errorf`
  not `Fatal`) and diverges in exactly one way: it emits **one** file (`teardown.json`),
  never a second verbatim `ps` snapshot — "the writer writes exactly one file" is itself
  the redaction assertion, checked by reading the directory.
- **22 subtests, zero SKIP** (`go test -tags e2e_realclaude -run '^TestTdn' -v`): no
  `WithWorktreeAuthenticated`, no `resolveClaudeBin` anywhere in the file.

## Patterns established

- **A subprocess-spawn boundary can silently swap the artifact a citation names.** The
  ticket body pinned the reap line's shape to `cmd/pyry/main.go:743`'s
  `slog.NewTextHandler`, but `runAgentRunPty` (`cmd/pyry/agent_run.go:299`) passes no
  `Logger` into `ptyrunner.Config`, so `ptyrunner.Run` falls back to `slog.Default()` —
  and every probe in this package spawns exactly `pyry agent-run`. An anchor built against
  the cited (wrong) handler would have returned `no-reap-line` on the only path that
  matters, with nothing going red. The architect caught this before code, not after; the
  general form — trace what a subcommand's `Config` actually receives, not just where the
  top-level handler is installed — is the same shape as #1236's lateness-witness lesson
  (blind to the reap because it watched the wrong step) and #1234's cited-handler finding.
- **A published rationale can be independently wrong and the design still correct.** Both
  the ticket body and the architecture spec asserted `pgid=` (`reap.go:59`'s singular Warn)
  is a prefix-substring of `pgids=` and would false-positive a naive `Contains` probe. It
  is not — `pgids=` does not contain `pgid=` as a substring in the direction claimed. The
  prescribed design (anchor on the message, then match `pgids=` at a key boundary) is
  correct regardless of whether that particular collision is real, and the fixture carrying
  the Warn still earns its place: it proves the held pgid appearing anywhere in the bytes is
  not itself an answer. Re-derive a cited fact before leaning on it, even when the
  conclusion built on it turns out fine.
- **A hazard needs enough columns to survive `ps`'s own error recovery.** `ps` silently
  drops an unrecognized `-o` column and prints the surviving ones rather than failing
  closed; a fixture with N columns where 1 is bad demonstrates the "parses as a shorter,
  live-looking row" hazard only when N ≥ 3 (2 remaining fields fails an exactly-three-fields
  parser outright). Undercounting the request proves nothing about the hazard it exists to
  show.
- **A platform-relative constant needs a confirmation ladder, not a literal.** "Obviously
  out of range" is not portable when the tested property is a platform ceiling (pid_max);
  the fix is escalate-until-rejected with the rejection itself asserted, not a single
  hard-coded value assumed to be past the limit everywhere the test runs.
- **Assert a fail-safe premise on the exact channel its consumer reads.** `pinReadState`
  calls `.Output()`; that call populates `*exec.ExitError.Stderr` only because it owns
  `cmd.Stderr` internally. A test helper that separately sets `cmd.Stderr = &buf` "to
  capture stderr for the assertion" leaves `ExitError.Stderr` empty — silently reproducing
  the exact failure mode (branch 5, unreachable-in-theory) the test exists to rule out.
  Verified here by deliberate mutation, not just reasoned about (PR body).

## Lessons learned

From the PR body (#1252) and code review (PASS, 1 SHOULD FIX deferred to #1251, 4 NIT):

- **The SHOULD FIX** (`teardown_liveness_test.go:529-540`) — the "two reap lines, held pgid
  only in the second" row does not discriminate the mutation its own name claims to guard
  against. Both fixture lines in the row actually carry the held pgid (`tdnFixtureDefaultTwo`
  carries it in the *first* line; nothing is unique to the second), so a first-line-only
  union implementation still passes the row's verdict assertion — only the `LineCount`/
  `Count` bookkeeping catches the truncation, not the answer a consumer reads. Verified by
  mutation (patched to first-line-only, `go test` still green, worktree restored — confirmed
  clean via `git status --porcelain`). The implementation is correct; the proof is weaker
  than the row's comment claims. Not blocking — folded into #1251's turn on this file, per
  the ticket's own convention for #1235's deferred SHOULD FIX.
- NITs (all non-blocking): the closing-quote-only-broken arm (`pgids="[A B]` — bracket
  closed, quote not) has no fixture row, though it's unreachable from a real `slog` handler
  (only from a truncated capture); `tdnCountAttr`'s `(0, false)` no-`count=`/non-integer
  return is never exercised (low value — feeds a cross-check field, never a verdict); the
  redaction fixture (`tdnFixtureRecord`) leaves `ToolStderr`/`ExitStatus` zero against the
  spec's "every field non-zero" instruction, which matters because the redaction scan's
  `"environ"` needle would fire on a real `ps: environ: keyword not found` and the fixture
  never exercises that path (the structural guard — `pinStateColumns` +
  `TestPinStateColumns_ReadsNoEnvironment` — is intact regardless, which is why this is a
  nit); `"eww"` in the forbidden-substring list subsumes `"-eww"` (both checked; harmless
  redundancy). One reviewer note, not a finding: AC2's "stdout-empty?" is recorded via
  `t.Logf` rather than asserted per-arm — read as the right call, since arm A's stdout
  shape is Darwin-specific and stdout adds nothing to the fail-safe argument (branch 1
  precedes branches 4 and 5 regardless of stdout content).
- **The wrong-channel stderr trap is real and inverts silently** (see Patterns established)
  — confirmed by deliberately mutating the ps helper to set `cmd.Stderr` and watching all
  four AC2 arms fail with "SILENT STDERR".
- **A bad column needs four requested columns, not three**, to demonstrate the
  parses-successfully hazard — the ticket body's three-column form returns a two-field row
  that `pinStateRow`'s exactly-three rule rejects outright, proving nothing.
- **Matching an `slog` attribute needs a key-boundary check, not `strings.Index`** — a
  handler's `WithAttrs` adding e.g. `reap_pgids=` would otherwise read as this line's
  `pgids=`. `tdnAttrIndex` requires start-of-line or a preceding space.
- **A cited rationale can be wrong even when the design built on it is right** — see
  Patterns established, `pgid=` vs `pgids=`.
- File landed at 988 lines against the spec's ~550–600 estimate — assessed as a spec-estimate
  miss, not scope creep: none of the items the spec's § 0 named as cut were added back, and
  the comment-to-code ratio (0.45) matches the package's siblings (0.39 / 0.48 / 0.48).
