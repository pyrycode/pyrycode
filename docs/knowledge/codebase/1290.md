# Ticket #1290 — The run verdict and its trailer evidence, read behind the discriminated optional

Adds `internal/e2e/realclaude/finding_trailer_evidence_test.go` (697 lines,
purely additive, offline, `e2e_realclaude` build tag). Builds the trailer half
of the probe's published record: `finTrailerRecord` carries one run's outcome
value together with the trailer evidence behind it, and `finTrailerBuild` is
the pure projection that produces it from a `trailObservation`. Split from
#1285; #1291 (out of scope here) embeds this record whole into the run
record, which is only safe because the record is trap-free by construction
rather than by an ordering discipline a later edit can break.

## Implementation

- **`finTrailerRecord` — ten scalars, no pointer, no slice, no embedded
  struct.** `Outcome`, `State`, `Bounded`, `BoundFrom`, `Staleness` (in that
  field order — `Staleness` sits immediately after `BoundFrom` so "never
  published without its discriminator beside it" is true *positionally* in
  the rendered JSON, not by convention), then `Subtype`, `IsError`,
  `TerminalReason`, `StopReason`, then `Detail`. Nothing in the type is
  reachable back to `trailScanResult.Line` or the `*resultTrailer` pointer.

- **No field carries `omitempty`, and that's a decision, not an oversight.**
  `wireFields`' `default` arm (`emitter.go:434-435`) returns
  `terminal_reason == ""` on a genuinely *seen* trailer; under `omitempty`
  that record would render byte-identically to a `trailAbsent` record's zero
  — collapsing "the trailer was read and its terminal reason is empty" into
  "there was no trailer," the exact collapse the nil-pointer design one tier
  down exists to prevent. Same argument kills `omitempty` on `IsError`
  (drops `false`) and `Staleness` (drops the honest zero paired with
  `trailBoundNone`).

- **Two different trap-freedom claims, kept apart on purpose.** The *type*
  is trap-free by construction (ten scalars, copy costs nothing, aliases
  nothing — `finAttributeEntry`'s sense). The *builder* is not: its input,
  `trailObservation`, carries the capped `Line`, so the no-leak property of
  `finTrailerBuild` is held by the Detail content rule plus the AC4 test —
  not by the shape of the input. Both claims are stated in-file so neither
  is read as covering the other.

- **`finTrailerBuild(outcome string, obs trailObservation) finTrailerRecord`
  is pure** — no exec, no clock, no filesystem, no `*testing.T`, never
  fails a test — the same contract as `trailScan`, `trailGate`,
  `trailClassifyRun`, `finOutcomeStagingGate`, `tdnClassifyReapLog` and
  `pinReadState`. One `if`, two Detail shapes, no third branch, no reject
  arm:
  - `Bounded = obs.BoundFrom == trailBoundFromMiss` and nothing else —
    never `Staleness != 0`, which would publish a non-bound wearing a
    bound's label.
  - `carriesTrailer := obs.State == trailSeen && obs.Trailer != nil` — the
    `State` operand is written **first** so Go's left-to-right `&&`
    short-circuit makes "State is consulted before the pointer is
    dereferenced" a property of the source, not of a comment. The nil
    check is kept alongside State (rather than State alone) because
    `trailGate`, this trap's first consumer, already answers the
    State/nil *pair* — the inconsistency only a hand-built fixture can
    produce, and hand-built fixtures are all this file ever sees.
  - `Outcome` is copied from the parameter **as handed** — no validation,
    no renaming, no re-derivation, no cross-check against `State`. The
    value comes from one of two closed sets built elsewhere
    (`trailClassifyRun`'s eleven, #1271; the staging-gate tier's seven,
    #1284) and both are caller-supplied.

- **Four tests, one per AC, all offline:**
  - `TestFinTrailerRecordCarriesTheBoundAndItsDiscriminator` (AC1) — four
    rows across all three `State` values and all three `BoundFrom` values.
    The two rows that bite carry a **non-zero `Staleness`** beside a
    discriminator that bounds nothing (`trailBoundFromStart` live,
    `trailBoundNone` synthetic — both `trailBoundNone` return sites leave
    `Staleness` zero in practice, so that row is a contract check on a
    builder pure over its inputs, not a claim such a run occurs, and the
    test says so).
  - `TestFinTrailerRecordReadsTheDecodedTrailer` (AC2) — a no-trailer
    observation returns rather than panics, with the four fields at their
    zero values (the load-bearing assertions, since outcome is an input);
    then `trailPaddedTrailer(2000)` proves the four fields survive on the
    **built record** even after the precondition — `Line` no longer
    contains `terminal_reason` — is asserted on the scan result itself.
  - `TestFinTrailerRecordOutcomeIsConsumedAsHanded` (AC3) — two
    *disagreement* rows (a staging value beside `trailAbsent`,
    `trailOutcomeVoidNoTrailer` beside `trailSeen`) are the only rows that
    bite, since an agreeing row would pin nothing. Separately sweeps all 18
    values (eleven `run-*` + seven `stage-*`) through both membership
    predicates to pin the two sets stay disjoint, calling
    `trailIsRunOutcome`/`trailRunOutcomeValues` and
    `finOutcomeIsValue`/`finOutcomeValues` rather than restating either
    set.
  - `TestFinTrailerRecordCarriesNoCapturedBytes` (AC4) — the non-vacuous
    leak proof. Plants `trailNeedle` via `trailPaddedTrailer(0)` (385
    bytes against the 512-byte cap, needle at offset 104–146) so the plant
    survives *inside* the cap — the family's habitual pad (2000,
    `trailOverlongPad`) would push it past the cap and pass vacuously
    against a record that kept the capped line. Asserts zero occurrences
    in the marshalled record and in `Detail` separately, plus per-row
    headroom (`reachMaxCommandBytes - len(rec.Detail) >= len(trailNeedle)`)
    so a leak would have fit inside the cap rather than being truncated
    away — the exact defect #1284 shipped and fixed.

- **Reuse, not rebuild.** `trailScan` and its fixtures
  (`trailFixtureTrailer`, `trailFixtureNoTrailer`, `trailNeedle`,
  `trailPaddedTrailer`, `trailOverlongPad`), the three `State` values and
  three `BoundFrom` values, `trailIsRunOutcome`/`trailRunOutcomeValues`,
  `finOutcomeIsValue`/`finOutcomeValues`, `trailDetail` (no `finDetail`
  twin — settled twice already, #1280/#1284), and
  `reachMaxCommandBytes`/`reachCapCommand` are all called, none
  re-derived. Prefix census: `finTrailer[A-Z]` 0 before, clean after;
  control `trail[A-Z]` non-zero.

- **AC5 (offline-only) discharged structurally**, same shape as the
  siblings: a header line stating no live claude / credentials / daemon /
  process-table read / env gate / `t.Skip`, checked by
  `grep -nE '\bt\.Skipf?\('` rather than the ticket's own looser recipe
  (which false-positives on the header's own prose "no ... `t.Skip`.") —
  see Lessons learned.

## Patterns established

- **A guard whose removal is observationally identical on every real input
  is a documented caller obligation, not a missing assertion.** Dropping
  the `State ==` operand from `carriesTrailer` and keeping only
  `obs.Trailer != nil` leaves the whole file green, because every fixture
  this file can build has `Trailer == nil` exactly when `State != trailSeen`
  — the two only diverge on a hand-built fixture no producer emits. The
  file states the ordering claim precisely ("a build that dropped the
  *guard* would panic," not "dropped *State checking* would panic") rather
  than overclaiming a test it doesn't have. Code review confirmed this by
  mutation and treated the disclosure as correct handling, not a gap to
  fix.
- **Mutation-test the redaction check with the plant *inside* the format
  string, not appended after it.** Code review re-ran the two AC4-adjacent
  leak mutations in stricter form than the spec required: interpolating
  `obs.Line` *inside* `trailDetail`'s format (so the 512-byte cap actually
  applies) rather than appending it after formatting (which would bypass
  the cap and prove nothing). Both reddened. A second mutation added a
  `Line`-holding field deliberately named `evidence` — chosen specifically
  to dodge a forbidden-key heuristic (`line`/`trailer_line`/`result`/`raw`)
  — and the marshal-and-sweep assertion caught it unaided, confirming the
  security property doesn't rest on a key-name list.

## Lessons learned

From the PR body (#1292) and code review:

- **A needle plant's non-vacuity is a property of the pad, and this
  family's habitual pad inverts it.** `trailNeedle` sits at offset
  `104 + pad` in `trailPaddedTrailer`, so the pads already planted with
  elsewhere (2000, `trailOverlongPad`) put it *past* the 512-byte cap —
  correct where the point is that only a full-line record leaks, but a
  green pass against a record that kept the *capped* line, which still
  publishes ~415 bytes of model-chosen text. `trailPaddedTrailer(0)` (385
  bytes, needle at 104–146) is the pad that actually exercises the claim,
  and the offset is asserted on the fixture rather than trusted, so a
  future fixture change surfaces as a failed precondition instead of a
  silently weaker test.
- **A spec's own prescribed grep recipe can false-positive on the file's
  own header prose.** The ticket's AC5 check,
  `grep -nE 't.Skip|os/exec|exec\.Command|...'`, matched line 11 — the
  file header's sentence "no env gate, no `t.Skip`." Code review verified
  the call-shaped grep (`\bt\.Skipf?\(`) returns nothing and treated the
  broader recipe's hit as the recipe's false positive, not a violation.
  Any ticket reusing this AC5 shape should discriminate the same way.
- **697 lines against the spec's ~500–600 projection** — roughly two
  thirds doc comments carrying the content rules and the argument for each
  row. Within the family's merged range (594–1301 at `size:s`) and the
  spec's own operator-calibration note; flagged in the PR body since the
  LOC projection was the only red line near its bound.

## Code review

**PASS**, two NITs, neither blocking:

- AC1's coverage maps (`seenStates`/`seenBounds`) are populated inside
  subtest closures and read after the loop — correct only because the
  subtests run sequentially; adding `t.Parallel()` later would race on the
  maps. Deriving them straight from the table would be immune to that.
- The guard-ordering disclosure in AC2 (see Patterns established) is
  precise rather than overclaimed; if #1291 wants the ordering itself
  pinned (not just the guard's existence), the row that would do it is a
  hand-built `State: trailAbsent` with a non-nil `Trailer` — out of scope
  here.

Independently verified in review: `go test -race -tags e2e_realclaude
./internal/e2e/realclaude/...` — 180 PASS / 0 FAIL / 4 SKIP (the 4 are the
pre-existing live-credential baseline, unrelated to this ticket); six
mutations run via `go test -overlay=` (four spec-mandated plus two stricter
variants), five red as designed, one green and disclosed (see above);
~30 line-citations spot-checked, all accurate, including two the developer
corrected against the ticket's own (slightly off) line numbers; both
security-review SHOULD FIX findings (naming `stop_reason` as the sole
uncapped model-influenced field; per-row Detail headroom) confirmed landed
in the code.
