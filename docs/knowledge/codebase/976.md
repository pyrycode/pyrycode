# Ticket #976 — e2e: `archive_conversation` / `unarchive_conversation` round-trip over the v2 wire

A 2026-07-15 full-repo review found eleven client-sendable v2 wire verbs whose
only coverage was package-level unit tests — the exact gap shape that let #949
ship a `promote_conversation` handler nothing exercised end-to-end. This
ticket closes that gap for `archive_conversation` / `unarchive_conversation`,
the last two of four conversation-lifecycle verbs split off the review epic
(#960); siblings cover `rename_conversation` (#974) and `delete_conversation`
(#975), and #963 is the realclaude capstone blocked by all of them. The two
verbs are inverse toggles of one durable `is_archived` flag through **one
shared handler** (the `archived` bool is baked into each registration), so —
unlike the rename/delete siblings' two independent subtests — this ticket is
a single archive → unarchive round-trip against one seeded row, plus its own
not-found subtest.

## Implementation

Test-only, one new file, no production code:

- `internal/e2e/relay_v2_archive_test.go` (new, 330 LOC, build tag `e2e`) —
  `TestRelayV2_Archive` with two independent subtests, each owning its own
  pair → spawn → Noise_IK handshake (copied call-for-call from the merged
  #974 rename test, per the spec's explicit no-shared-helper instruction):
  - `testV2DaemonArchiveRoundTrip` — seeds one promoted, named,
    timestamped conversation row (`is_archived: false`), completes the
    handshake **once**, then sends **both** `archive_conversation` and
    `unarchive_conversation` over the **same** transport cipher states — no
    re-handshake between them. Nonces stay in lockstep because request/reply
    strictly alternate (`Encrypt` advances the send nonce, `Decrypt` advances
    the receive nonce). Each decrypted `conversation_updated` reply is
    asserted for `in_reply_to` correlation, `IsArchived` toggling (`true`
    then `false`), and preservation of `IsPromoted` / `Name` / `Cwd` /
    `LastUsedAt` (compared with `.Equal`, never `==`) — the seeded
    promoted+named+timestamped row makes these preservation checks
    non-vacuous. After each frame, `conversations.json` is read back off
    disk and the row's `is_archived` is asserted directly (AC #1, #2) — the
    daemon eager-`Save`s before replying, so the post-reply disk read is
    race-free without polling.
  - `testV2DaemonArchiveNotFound` — sends `archive_conversation` (pinned;
    AC #3 allows either verb) for an absent id, asserts the decrypted reply
    is an `error` envelope carrying `conversation.not_found`, and reads the
    registry back to prove the seeded row was never mutated (the handler
    replies before any `Save` on a miss) — byte-for-byte the rename/delete
    not-found subtest shape with type/payload swapped.
  - Two spawns rather than one shared daemon, matching #974/#975: keeps the
    not-found subtest's seeded row pristine.
  - The on-disk `IsArchived` field is `omitempty` (unlike the wire payload,
    which is not) — after unarchive the key is absent from
    `conversations.json`. The read-back helper decodes into a plain `bool`
    and asserts the value, never key presence, so a missing key correctly
    reads as `false`.

## RED-on-regression

If either registration in `cmd/pyry/relay.go` (`TypeArchiveConversation` at
`:410`, `TypeUnarchiveConversation` at `:411`) were removed, that verb would
fall through to the no-handler `protocol.unsupported` arm and the round-trip's
`want conversation_updated` assertion would fail. The test is a live guard on
both lines, not just the shared handler body.

## Security review

Not security-sensitive: test-only, asserts observable behaviour (decrypted
wire frames, on-disk file state), no new production code or attack surface —
the handler itself (`ArchiveConversation`, #881) already carries its own
security reasoning and the `security-sensitive` label; this ticket only
observes it end-to-end. Code review confirmed PASS with no findings, including
an explicit check that the two-frames-over-one-channel contract holds (the
`InReplyTo == 62` assertion on the unarchive reply is what empirically proves
the archive step didn't desync the stream) and that `go test -race -tags e2e`
passes.
