# Ticket #1603 — streamsup: bypass revocation writer as a `set_permission_mode` control request

Adds the writer half of the in-band bypass drop #1595 measured live against claude 2.1.220:
`marshalBypassRevocationEnvelope` / `WriteBypassRevocation` / `(*Runner).RevokeBypass`, mirroring
the existing interrupt trio (`marshalInterruptEnvelope` / `WriteInterrupt` / `(*Runner).Interrupt`)
so the marshalled bytes stay assertable without spawning a child. PR
[#1612](https://github.com/pyrycode/pyrycode/pull/1612), code review **PASS**, no findings.
Split from #1596; blocks #1604 (session-layer wiring).

## Implementation

- **`controlRequestInner`** (`internal/streamsup/envelope.go`) gains a second field, `Mode
  string \`json:"mode,omitempty"\``, placed **after** `Subtype` so Go's declaration-order
  marshalling reproduces AC1's byte order. `omitempty` is load-bearing, not cosmetic: without it
  every interrupt line would grow `"mode":""`, breaking `TestMarshalInterruptEnvelope`'s existing
  byte-exact `want` — which stays **unmodified** in this diff, the shared-type decision's whole
  point.
- **`marshalBypassRevocationEnvelope(requestID string) ([]byte, error)`** builds the envelope with
  three fixed literals (`control_request` / `set_permission_mode` / `default`) plus the caller's
  id, `json.Marshal`s it, appends `'\n'`. Byte-identical to the line #1595 recorded as successful.
- **`WriteBypassRevocation(w io.Writer, requestID string) error`** mirrors `WriteInterrupt`
  exactly: nil-check first (`ErrNoLiveChild`, zero bytes), then marshal, then one `Write`, never
  closes `w`.
- **`(*Runner).RevokeBypass() error`** is one line: `WriteBypassRevocation(r.Stdin(),
  r.nextControlID())`. Concrete method, deliberately not on `sessions.Runner` (#1077 stays
  un-widened) — #1604 reaches it via a type assertion, same as `Interrupt`.
- **Neither exported entry point takes a mode.** No parameter, struct field, or option selects
  one anywhere on the added surface — the security property AC2 requires. The enable direction is
  structurally absent, not merely undocumented: `git grep -F '"bypassPermissions"' --
  'internal/streamsup/*.go'` returns no hits after the change (control-run both ways: unfiltered
  it finds 17–18 hits including the real Go literal in `set_permission_mode_probe_test.go:199`).
- **The interrupt id counter is reused and renamed**, not duplicated: `interruptSeq` →
  `controlSeq`, `nextInterruptID` → `nextControlID`. `request_id` must be unique across all
  in-flight control requests on one stream, not per subtype — two independent counters would both
  mint `"1"`, breaking a future ack-correlator keyed on `request_id`. Two Go call sites changed
  (`Interrupt`, and the renamed `TestRunner_NextControlID_Monotonic`); zero surviving references
  to the old names repo-wide.
- **No ack reader added, and none needed.** `(*Runner).Interrupt` never read the
  `control_response`, and this ticket keeps that discipline. #1500 already added a content-free
  `case "control_response"` arm to `(*Parser).consumeLine` that dispatches on top-level `type`
  alone and reads nothing beneath it — its test table already carries the revocation ack shape
  verbatim, so a revocation cannot regress the `unrecognized_message` frame #1500 exists to
  protect. `internal/streamsup/parser.go` is untouched by this ticket.
- **Tests** (`envelope_test.go`, `interface_test.go`): `TestMarshalBypassRevocationEnvelope`
  (byte-exact, single-newline, round-trip); `TestMarshalBypassRevocationEnvelope_RequestIDInjectionResistance`
  (8-row table mirroring `TestMarshalTurnEnvelope_InjectionResistance` — forged `result` lines,
  envelope breakout, embedded newlines/quotes/control bytes/unicode; every row still decodes
  `subtype`/`mode` as the fixed literals); `TestWriteBypassRevocation_NilRefusal` /
  `_WritesEnvelope` / `_WriteError` (reuses the existing `errWriter`); `TestRunner_RevokeBypass_NoLiveChild`
  / `_LiveChildDelivers` (spawns the `echo_lines` helper, additionally sends an `Interrupt` in the
  same test and asserts the two echoed `request_id`s differ — the shared-counter pin);
  `TestRunner_NextControlID_Monotonic` (the rename, assertions unchanged).

## Patterns established

- **A hazard test can be pinned on an existing, unmodified test rather than a new one, and that is
  not automatically vacuous.** AC3's whole enforcement is `TestMarshalInterruptEnvelope` staying
  green with its pre-existing `want` untouched. Code review mutation-tested this specifically
  (dropping `omitempty`) and found it reddens **that test alone** — the sole detector of the
  hazard, confirming the diff's choice not to touch it was correct rather than merely convenient.
- **An injection-resistance table can't always name the value it's defending against.** The
  natural adversarial row for the revocation's id-injection test would try to rewrite the mode to
  `bypassPermissions` — but writing that literal anywhere under `internal/streamsup` trips AC2's
  own grep. `acceptEdits` stands in as the attacker's substitute mode; the property under test (no
  id-supplied mode survives) is unchanged by which non-`default` string is used.
- **Renaming a shared field when its role widens is the honest cost of reuse, not adjacent
  refactoring.** `interruptSeq` minting revocation ids would have been the inconsistency a
  reviewer flags; the rename was scoped to exactly the two call sites the widened role touches.

## Lessons learned

From the PR body:

- A security AC's own grep can be tripped by the test written to defend it — when an AC forbids a
  literal repo-wide, an injection test's "attacker tries the forbidden value" row needs a
  substitute token, not the real one, or the test itself becomes the AC's only violation.
