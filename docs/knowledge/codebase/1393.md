# Ticket #1393 — give the background-task events their v2 protocol shape

Wire-vocabulary-only ticket: defines the v2 shape three `internal/turnevent` variants will map to, without wiring the mapping. `internal/turnbridge/outbound.go`'s `MapEvent` still returns `ok == false` for all three — nothing emits these frames yet. Split from #1377; #1394 (blocked-by this ticket) does the mapping + `docs/protocol-mobile.md` write-up.

## Implementation

- **New const block in `internal/protocol/codes.go`**: `TypeBackgroundTaskStarted` / `TypeBackgroundTaskUpdated` / `TypeBackgroundTaskRoster` (`background_task_started` / `_updated` / `_roster`), appended after the `TypeUnrecognizedMessage` block rather than folded into the six-member interactive block or the two-member status-peer block — each existing block's doc comment hand-counts its members ("these six", "these two"), and a new block costs nothing while an edit risks miscounting. `background_task_roster` is named for what the frame IS (a snapshot), not claude's trigger (`…_changed`), so a consumer can't misread it as a delta.
- **Four new types in `internal/protocol/interactive.go`**: `BackgroundTaskStartedPayload`, `BackgroundTaskUpdatedPayload`, `BackgroundTaskRosterPayload`, and the row type `BackgroundTask` (no `Payload` suffix — the `ConversationSummary`/`RecentWorkspace`/`ModalOption`/`QueuedItem` row-naming precedent). All four lead with `conversation_id` — present and bridge-filled-later, unset by this ticket — and carry no `session_id` (claude's session identity, not the daemon's conversation identity; no v2 payload carries it). No `omitempty` anywhere, per the file's standing doctrine.
- **`BackgroundTaskRosterPayload.MarshalJSON`** — the file's only custom marshaller. Substitutes `[]BackgroundTask{}` for a nil `Tasks` via the standard `type alias` indirection, so an empty roster always serialises `"tasks":[]`, never `"tasks":null`. `omitempty` was ruled out (AC #3 forbids eliding the key); between `null` and `[]`, `[]` is the better client contract (a non-optional array type, no branch). `truncated_fields` is deliberately **not** normalised the same way — nil and `[]` say the identical thing there ("nothing cut"), whereas `tasks`'s empty value is the frame's whole signal.
- **Four fixtures** in `internal/protocol/testdata/`: `background_task_started.json`, `background_task_updated.json`, `background_task_roster.json` (populated, mixed truncation), `background_task_roster_empty.json` (`"tasks":[]`, the AC's key case). Each round-trips via the existing `roundTripEnvelope` helper in `interactive_test.go`. A separate non-fixture test, `TestBackgroundTaskRosterPayload_NilTasksNormalises`, marshals a payload built with `Tasks == nil` directly — the fixture alone can't reach that path, since unmarshalling `"tasks":[]` yields a non-nil empty slice.
- **Envelope-cap test (AC #4)**: `TestBackgroundTaskPayloads_FitV2EnvelopeCap`, table-driven over all three payloads, fields filled to their producer caps (local mirrors of `internal/streamsup/parser.go`'s `maxTaskFieldID`/`maxTaskDescription`/`maxTaskPatch`/`maxTaskRosterEntries`/`maxTaskRosterDescription`, since `internal/protocol` is a stdlib-only leaf and can't import `internal/streamsup`) with `<` as the fill character, not `a`. Measured: roster (the binding case, 8 entries) 50 557 B / 77.2% of the local `65519`-byte cap constant; started 45.6%; updated 40.8%. An `a` fill would have measured 5.3× smaller and proven nothing — `encoding/json`'s default `SetEscapeHTML` turns each `<`/`>`/`&` into a 6-byte `\uXXXX` escape, and `Description` is a literal shell command line for the `local_bash` task type, so `<`/`>`/`&` is a realistic fill, not a contrived one.
- **Registrations for `make check`**: three sites in `internal/protocol/compat_test.go` (rejection table, `v2OnlyTypes`, the `TestTypeConstants_V1V2Partition` `all` list) and `cmd/pyry/relay_guard_test.go`'s `excludedTypes` (three `"push"` entries) — `TestEveryInboundV2TypeHasHandler` enumerates every `Type*` constant and fails the build on an unregistered new one.

## Patterns established

- **A behavioural decision (nil→`[]` normalisation) belongs on the payload type, not on the bridge that will construct it.** `turnevent.BackgroundTaskRoster.Tasks` is nil both for a genuinely empty roster and for an omitted key — the two are indistinguishable upstream, so #1394's future bridge mapping will hand this type a nil slice either way. `MarshalJSON` here is what turns AC #3 into a guarantee `make check` enforces, rather than a fixture-only convention #1394 could silently violate.
- **A round-trip fixture pins the type's marshalling, never the producer's construction.** The empty-roster fixture proves `background_task_roster_empty.json` round-trips; it cannot prove a nil `Tasks` slice marshals correctly, because unmarshalling `[]` always yields non-nil. Any type with a nil/empty-slice distinction needs a direct construct-and-marshal test alongside its fixture, not instead of one.
- **Per-field caps don't compose into an envelope guarantee — measure the aggregate, and fill with the character that costs the most to escape.** `maxTaskDescription` etc. bound one field each; nothing upstream bounds the serialised frame. The escape multiplier (6 bytes/byte for `<`/`>`/`&`/control bytes, vs 1 byte/byte for ASCII, vs raw pass-through for multi-byte runes) is the dominant term, so the worst-case fill is a fixture-realistic character (a shell command line's `<`/`>`/`&`), not the visually "worst" one.

## Lessons learned

From the PR body (#1395) and code review:

- **A hand-authored JSON fixture pinning Go's marshalling must carry the escapes literally.** `encoding/json` emits `<`/`>`/`&` as six-byte escapes (`SetEscapeHTML` on), and `json.Compact` (what the round-trip helper's `canonical()` uses to byte-compare) does not re-escape — a fixture typed with the raw characters fails the round trip. Escaping the file after writing it (a small `str.replace` pass) was more reliable than typing the sequences by hand.
- **The empty-roster fixture cannot exercise the nil-`Tasks` path.** Unmarshalling `"tasks":[]` yields a non-nil empty slice, so the fixture only re-proves the already-normalised value. The nil path — the one #1394's bridge will actually take, since `turnevent.BackgroundTaskRoster.Tasks` is nil both for empty and for omitted — is only reachable by constructing the payload directly, which is what `TestBackgroundTaskRosterPayload_NilTasksNormalises` is for. Generalizes: a fixture pins a type's marshalling, never a future producer's construction.
- **[unfixed, SHOULD FIX] `BackgroundTask`'s (the roster row's) `SECURITY:` doc comment claims to repeat the render-never-execute warning but doesn't state it.** The source it was ported from, `turnevent.BackgroundTaskStarted`'s doc, states the warning and *then* justifies repeating it ("a LIST of command lines is a more tempting shape…"); the port kept the justification clause and dropped the warning it justifies. Landed as-is (review verdict PASS, one-clause fix identified, not blocking) — `BackgroundTaskStartedPayload.Description` and `BackgroundTaskUpdatedPayload.Patch` both carry the warning in full; only the roster row's copy is short. Worth closing before or alongside #1394, since the roster row is the field a client renders N times per frame.
- **[unfixed, NIT] `interactive_test.go`'s envelope-cap test assigns `DroppedTasks: 1 << 31`, an untyped constant that overflows a 32-bit `int`.** Not live today — `Makefile`/`.goreleaser.yaml` target `linux/darwin` × `amd64/arm64` only — but would break the build if a 32-bit target were ever added. `math.MaxInt32` is equivalent for the width actually being exercised.
