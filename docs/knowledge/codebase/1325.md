# Ticket #1325 — Probe instrument: narrow the trailer record's evidence tests to what the sighting carrier still lets them prove (offline)

Since #1320 (merged at `eea9f91`), `finTrailerBuild` takes the gather's
`finSighting` carrier (eight scalars, no `.Line`, no `*resultTrailer`) in place
of a `trailObservation`. Three rows in `finding_trailer_evidence_test.go` were
written against the old channel and #1320 migrated them minimally, marking
each `SUPERSEDED BY #1320, RETIRED BY #1321 — NOT A LIVE GUARD` and leaving
the retirement argument for this ticket (renumbered from #1321 via #1323's
split). A row asserting the absence of a needle its input structurally cannot
carry is not a weakened test but a test of nothing — this family's doctrine is
that a green proof of a false claim is worse than no proof.

## Implementation

One file, `internal/e2e/realclaude/finding_trailer_evidence_test.go`, subtractive
plus prose. No signature, type or constant changed; no new sweep; `Bounded` keeps
its single source (`BoundFrom == trailBoundFromMiss`).

- **`TestFinTrailerRecordCarriesNoCapturedBytes`** was four checks in one test,
  and only two ever read `.Line`. Retired: the two in-cap preconditions, the
  detail-quotes-the-line check, and the marshalled-record containment check.
  Kept: the per-row `Detail` headroom assertion (#1284's fix) and the flat
  forbidden-key scan. The `bytes` import and the `line` local both became dead
  once the containment check was cut — dropped and inlined respectively.
  **The fixture is not repadded** — `trailPaddedTrailer(0)` stays, because it's
  what puts the build on the *filled* arm (the longer of the two `Detail`
  shapes), not because anything still reads the line.
- **The transported claim** (retired → where it now holds), each named by
  symbol in the source rather than argued in the abstract:
  - the in-cap needle claim → `TestFinGatherReturnsNoCapturedBytes`
    (`finding_run_gather_test.go`), which sweeps the carrier as the gather's
    third return and asserts the same in-cap precondition **in code** — the
    needle survives the 512-byte cap in the retained copy, so what it plants is
    something a leaking value would actually leak. Non-vacuous today; the
    retired checks here could only ever assert the absence of what the input
    can't carry.
  - the panic-on-unchecked-deref obligation → `TestFinSightingReachesNoScanType`
    (same file), **stronger**: it walks the carrier's type for all three scan
    types rather than one instance.
- **The headroom assertion's argument is re-stated, not carried over.** Both its
  comment and its own `t.Errorf` used to justify it by "the checks below" —
  exactly the checks retired above. The replacement is the argument
  `finTrailerRecord`'s own type doc already makes: the headroom is a type-level
  rule, the record embeds *whole* into `finRecordRun.Trailer` and from there
  into the artifact, and the byte sweeps one and two tiers up (the marshal
  sweep's "walks the embedded sub-records", the artifact's per-path headroom
  test) recurse into it — a Detail that ate its own budget would defeat them.
  Register is deliberately prospective: after #1320 the builder reaches no
  line, so nothing leaks into this Detail *today*; this guards a future edit,
  in the same register the surviving key scan already uses.
- **The "returns rather than panicking" subtest is deleted whole**, not kept for
  its zero-fields assertions — under the carrier those are tautological (an
  absent scan gives a false `CarriesTrailer` and four zero scalars, so the
  record publishes zeroes whether the builder guards or not). Its one
  non-tautological claim, `rec.State == trailAbsent`, was already covered by
  `TestFinTrailerRecordCarriesTheBoundAndItsDiscriminator`'s absent row under an
  executable coverage loop.
- **The "survives a cap" subtest keeps its fixture and precondition, re-stated
  onto `finTrailerSighting`.** The dead claim was "the projection reads Trailer
  not Line" — the builder reads neither. What the row still proves is that
  `finTrailerSighting` reads the full-line decode rather than the capped copy.
  Rewritten to assert on the `finSighting` the helper returns instead of on a
  built record, dropped the `finTrailerBuild` call, kept the literal expected
  values (deliberately not the sibling's `want := *scan.Trailer` form — here the
  helper is handed the very `scan` the test built, so a derived `want` would
  compare a value to itself). This row is the *only* executable pin on
  `finTrailerSighting`'s half of its agreement obligation with
  `finGatherReadings` — that obligation is otherwise held by comment and review
  only, since `finGatherReadings` execs `ps` and this file forbids exec.
- **The shell is settled, not left half-named.** `TestFinTrailerRecordReadsTheDecodedTrailer`
  had one child left after the panic subtest's deletion; a single-child `t.Run`
  is ceremony (the file's precedent is top-level tests), so it's deleted and its
  survivor promoted to top-level as **`TestFinTrailerSightingScalarsComeFromTheFullLineDecode`**
  — named to mirror `TestFinGatherSightingScalarsComeFromTheFullLineDecode`, so a
  grep for `ScalarsComeFromTheFullLineDecode` returns both halves of the
  agreement obligation without prose. This is the symbol #1326 cites.

## Tests

The deliverable *is* tests; verification is that the surviving set still bites
and the retired set is genuinely held elsewhere. `go vet -tags e2e_realclaude`
clean; `go test -race -tags e2e_realclaude` → 106 PASS / 46 SKIP (unchanged
split — the 46 are live-claude specs skipping for want of login, not a gate).
Three mutations, each graded independently via `go test -overlay` from a
scratchpad copy under its own `-run` so a co-firing check couldn't mask a
vacuous one:

| Mutant | Graded under | Result |
|---|---|---|
| `finTrailerSighting` fills the four from a re-decode of the capped `scan.Line` | `TestFinTrailerSightingScalarsComeFromTheFullLineDecode` | RED on all four scalars |
| the filled arm's `Detail` padded past the budget | `TestFinTrailerRecordCarriesNoCapturedBytes` | RED, naming the record |
| the carrier retains the capped line under a non-line-shaped key | `TestFinGatherReturnsNoCapturedBytes` | RED — confirms the transported in-cap claim actually bites at its new tier |

## Patterns established

- **A retirement mark that says "the argument is elsewhere" is not the same as
  the argument being findable.** When a surviving check's justification names
  the checks being retired — here, in *two* places: the comment and the
  check's own `t.Errorf` — both must be re-stated, or a developer reading
  "retire the needle checks" next to a headroom check whose only stated purpose
  is protecting them can reasonably (and wrongly) delete it too. Grepping only
  comments for pointers into a retirement set leaves the user-visible half
  (the failure message) stale.
- **A test's non-vacuity precondition and its no-literal fixture argument can
  travel together.** `trailScan` attaches `Trailer` in the same `return` that
  answers `trailSeen`, so `State == trailSeen` alone already implies
  `CarriesTrailer` — no separate `scan.Trailer == nil` clause is needed to
  justify measuring against the filled (longer) `Detail` arm.
- **Promoting a subtest to top-level de-indents its whole body, which is the
  moment to apply the file's current failure-message discipline to messages
  otherwise untouched.** The promoted row's precondition used to render `%q`
  of `scan.Line` (~512 bytes of model-shaped stand-in payload) into CI logs on
  failure; it now prints `len(scan.Line)` only, matching this family's rule
  (`finding_run_gather_test.go`).

## Lessons learned

(From the PR body and code review; see PR #1327.)

- A retirement can dangle a survivor's justification in two places at once,
  and the failure message — not the comment — is the one that gets missed
  when checking "does anything still point at what I'm deleting."
- The mis-labelling risk in a re-stated "the room keeps sweep X non-vacuous"
  argument is real and easy to introduce even when copying from a spec: code
  review found that citing the artifact's **Detail walk** as one of the "byte
  sweeps the room protects" is backwards — a budget-eating Detail turns that
  walk *red* (it's a second enforcer of the same headroom rule one tier up),
  not green. The correct second leg is the artifact's separate *file* byte
  sweep (`TestFinWriteArtifactsCarryNoCapturedBytes`), which truncation
  genuinely does defeat. Not blocking (the load-bearing marshal-sweep leg was
  correct and sufficient), but worth checking on the next touch: when an
  argument claims "check A and check B both go green under a defect," verify
  each named check actually *can* go green under that defect, not just that
  it exists.
- A mutation grading a "no captured bytes" claim should include a mutant that
  changes only the *field name/key shape* (not the value), to confirm a
  structural, key-based sweep still fires independently of a byte-content
  sweep — the third mutation here (non-line-shaped key) was added specifically
  to make the transported in-cap claim's new home executable rather than
  merely argued.
