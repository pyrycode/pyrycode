# Ticket #811 — Assemble a session debug bundle (recording + daemon logs)

Adds `internal/debugbundle`, a zero-dependency stdlib-only leaf that packages a
session's evidence — the most-recent `.cast` recording (when #802 debug capture
was on) plus a caller-supplied daemon log-ring snapshot — into a single in-memory
`tar`+`gzip` archive carrying a content-free `Manifest`. Pure content assembly: no
disk write, no wire, no pairing, zero `slog` calls. The **producer** of the
debug-bundle feature; ships unwired (0 non-test callers), with #813 (request verb)
its first caller over #812's chunked transport.

Full package doc: [features/debugbundle-package.md](../features/debugbundle-package.md).
Spec: [`811-assemble-session-debug-bundle.md`](../../specs/architecture/811-assemble-session-debug-bundle.md).

## Implementation

- **One file `internal/debugbundle/bundle.go`.** Exported surface:
  `Assemble(recordingsDir string, logs []string) ([]byte, Manifest, error)`, the
  content-free `Manifest` struct, and `DefaultRecordingsDir() (string, error)`.
  Private helpers: `newestRecording` (the AC1/AC2 selection seam), `writeBytesMember`,
  `writeRecordingMember`.
- **Recording source** = newest `*.cast` in the recordings dir, selected
  **by mtime** (not lexical stamp — same-UTC-second sessions share a stamp prefix
  and would need a tiebreak; mtime doesn't). A single non-recursive
  `filepath.Glob("<dir>/*.cast")` matches all three #802/#552 name forms
  (`<stamp>-<sid>.cast` in-flight, `-ok`/`-err` finalized). `DefaultRecordingsDir`
  **duplicates** `filepath.Join(home, ".local", "share", "pyry-recordings")` rather
  than importing `cmd/pyry`'s unexported `resolveRecordingsDir`.
- **Log source** = the caller-supplied `[]string` (the [`internal/control`](../features/control-plane.md)
  `RingBuffer.Snapshot()` that `pyry logs` returns). Passed as a parameter → no
  `internal/control` import → pure leaf. Whole-ring only: the ring is a flat
  200-line buffer with no per-session key, so per-session filtering is impossible
  and out of scope (unaffected by the `.cast` filename now carrying a session id).
- **Archive** = `gzip.Writer` → `tar.Writer` over a `bytes.Buffer`, three members
  with **hard-coded** names (`manifest.json`, `logs.txt`, `recording.cast`). tar +
  gzip over zip for the in-repo [`internal/update`](../features/update-package.md)
  precedent and streaming-friendliness. Recording streamed with `io.CopyN`, never
  held whole in a second `[]byte`.
- **No disk write at all** — every touch is read-only; the bundle lives solely in
  the returned `[]byte`. Cross-link: the recording source is
  [ptyrunner's flight recorder](../features/ptyrunner-package.md#session-flight-recorder-pyry_record_dir)
  (#552) gated on by #802.

## Patterns established

- **Fixed tar member names as an anti-injection seam.** Member names are constants,
  never derived from the on-disk basename, so a crafted filename in the recordings
  dir can never inject a traversal path into the archive structure. The real
  basename travels only as a JSON *value* in `manifest.RecordingName`. (Combined
  with the non-recursive `*.cast` glob, whose `*` never crosses a separator.)
- **`O_NOFOLLOW` on the recording read** hardens the stat→open TOCTOU: a symlink
  swapped in after selection fails the open rather than exfiltrating its target.
  Free defense-in-depth designed in, not deferred.
- **Content-free manifest + zero-`slog` package = AC5 by construction.** No log
  emission exists to leak into; the manifest exposes only name/size/count. The test
  seeds secret sentinels in the recording + log bodies and asserts they never appear
  in `manifest.json`.
- **Deterministic-in-tests via zero-value `ModTime`** on the in-memory members, so
  `Assemble` reads no clock. Only `recording.cast` carries a real mtime.
- **Read-failure honesty over a lying manifest.** A recording that is *selected* but
  cannot be read returns a wrapped error; only genuine zero-matches yields
  `RecordingPresent: false`. "Absent" must mean no recording exists.

## Lessons learned

Lifted from the PR body's "Lessons learned" section (developer-flagged deviations
from the spec's sketch):

- **`io.CopyN`, not `io.Copy`, when a tar member's header `Size` comes from a prior
  `stat` of a concurrently-written file.** The spec sketched `io.Copy(tw, file)`
  with the header `Size` set from the selection `stat`; those two are inconsistent
  for the **in-flight** (unsuffixed) recording, which tui-driver may append to
  between the `stat` and the read. A plain `io.Copy` would then write past the
  declared header size and trip `tar.ErrWriteTooLong`, turning "assemble a bundle
  while a session is live" into a hard error. `io.CopyN(tw, f, size)` writes exactly
  the declared prefix and preserves the header-size-from-stat invariant. This is the
  one deliberate deviation from the spec; `bundle.go`'s `writeRecordingMember`
  documents why.
- **Do not filter non-regular files in the recording *selector*.** `os.Stat` follows
  symlinks, so a symlink `.cast` looks regular and gets selected — and the
  `O_NOFOLLOW` open then rejects it as an honest error. Adding an `IsRegular` guard
  at selection would silently *skip* the symlink instead — the exact opposite of the
  intended "reject, don't read the target" behaviour.

## Notes

- **Out of scope (deferred, no observed need):** bundling several recordings /
  all-since-boot (AC fixes "exactly one, the newest"); per-session log correlation
  (needs a ring key that doesn't exist); any in-assembly size cap (no remote-driven
  input size — bounding under the 64 KB frame cap is #812's charter).
- **Code review** produced no findings that reshaped the implementation; the
  code-review commit only re-committed unrelated golden-file churn
  (`permission_protocol_v2.1.199.json` — a known, non-defect auto-commit churn).
- No ADR: the design choices (in-memory-only, newest-by-mtime, tar+gzip, fixed
  member names) are package-scoped and fully captured by the spec + feature doc, not
  a cross-cutting convention.
