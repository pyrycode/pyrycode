# Ticket #1582 — realclaude: prove a running child's model changed in-band, with no respawn

#1581 changed `Pool.UpdateSettings` to deliver a model/effort-only change by writing `/model <value>` as an
ordinary user turn on the stream already held open, instead of killing the child and respawning it. That
ticket proved the mechanism hermetically — its tests observe that no respawn happened and that the write was
issued — but a hermetic suite cannot tell "the daemon wrote the right bytes" from "the running child actually
changed model." This ticket supplies that second proof, from claude's own output, and changes no production
code.

## Implementation

- **`internal/e2e/realclaude/interactive_stream_inband_model_test.go`** (new, 635 lines, `//go:build
  e2e_realclaude`) — the only file this ticket touches besides its own architecture spec. One test:
  `TestInteractiveStream_InBandModelChange_LiveChildReportsNewModel`.
- **The tap.** `inbandTapRecorder` is wired into `streamsup.Config.Stdout` — the same `io.Writer` seam
  production fills with `streamsup.NewParser(...)`, upstream of it. It extracts exactly two things from
  claude's raw stdout and retains no payloads: the `model` field off every `system`/`init` line, in arrival
  order, and a count of top-level `result` lines. This is the only place the model announcement is reachable:
  `emitSystemSubtype` (`internal/streamsup/parser.go`) has arms for `task_started`, `task_updated`,
  `background_tasks_changed` and `thinking_tokens` only, so `init` falls through `ignoredLineTypes["system"]`
  and is dropped in silence — deliberately, per the #833 posture on `handleRequestSessionSettings` that keeps
  model/effort/YOLO values out of the daemon log at every level. Modeled on `dropcapRecorder`
  (`dropped_line_capture_test.go`, #1260) but deliberately not reused: that type retains every raw line for a
  committed fixture and exposes a one-shot result channel; this one needs three turn boundaries and nothing
  else. `spawnAndWait` re-sets `cmd.Stdout` from the same `Config` on every spawn, so the recorder installed
  once at construction also survives a respawn — the property that makes the pre-change evidence run a real
  red instead of a crash.
- **The spawn counter.** `inbandSpawnHandler`, an `slog.Handler` counting records whose message is `"spawning
  claude"` (streamsup's `Run` logs it exactly once per spawn). Same shape as `newDropcapArgvHandler`. Installed
  as `sessions.Config.Logger` and threaded through to `streamsup.Config.Logger`, so it also silently absorbs
  the pool's own log lines (it filters by message) and doubles as the discard handler that keeps a nil
  `Config.Logger`'s `slog.Default()` fallback out of test output.
- **The runner adapter.** `inbandRunner` wraps `*streamsup.Runner` to satisfy `sessions.Runner` — the same
  shape `cmd/pyry`'s `streamRunner` uses, needed because `(*streamsup.Runner).State()` returns
  `streamsup.State`, not `sessions.State`, and Go has no covariant return. The embedded runner is left
  exported-by-promotion on purpose, so the test body can call `Stdin()` directly (`sessions.Runner` doesn't
  carry it).
- **Pool wiring.** `sessions.New` with a `RunnerFactory` closure that builds the `streamsup.Runner` and
  captures it into a package-level `tap` variable; `RegistryPath` set to a `t.TempDir()` path (not empty) so
  `UpdateSettings`'s `saveLocked` performs a real write; base argv `[]string{"--dangerously-skip-permissions"}`
  with **no `--model`** (see below); `Pool.Run` is deliberately never called — only `go tap.Run(ctx)`, hoisted
  from what `runActive` would otherwise do, since the conversations sweep / idle timer / settings-file reaper
  aren't consulted by `UpdateSettings`. An instrument self-check (`pool.Default().Runner() != sessions.Runner
  (tap)` → `t.Fatalf`) guards against a future refactor silently handing the pool a different runner than the
  one the test observes.
- **Why the base argv carries no `--model`.** `spawnArgs` recomposes as `spawnBase + claudeSettingsArgs
  (merged)`; a base `--model` would make a respawn's argv read `--model haiku … --model <target>`. On the
  current tree that argv is only *installed*, never executed — harmless. On the pre-change tree it is
  *executed*, and whether claude last-wins on a duplicate flag is unmeasured; a crash there would turn a clean
  red into a muddy one. With no `--model` in the base, exactly one is ever emitted, on both trees. The starting
  model is instead **read** off turn 1's `init` line (`inbandPickTarget` returns the first table entry — of
  `{haiku, sonnet}` aliases resolving to `claude-haiku-4-5-20251001` / `claude-sonnet-5` on claude 2.1.220 —
  whose resolved id differs from the observed start), which means the test can neither skip nor assert a
  change that was already true, on any machine's default model.
- **Assertions**, read as first-vs-last off `initModels()`, never a fixed index (measured: the `/model` turn
  does emit its own `init`, still reporting the *old* model, so a healthy run produces three entries, not two):
  - A1 `last != first` — the model changed at all
  - A2 `last == resolvedID(alias)` — changed to the requested one
  - A3 `pidAfter == pidBefore` — same process served first and last turn
  - A4 `spawnCount == 1` — exactly one spawn over the run

## Patterns established

- **A wire-level observable that must never reach a daemon event is still testable — tap the seam upstream of
  the component that's forbidden to surface it.** `Config.Stdout` sits before the parser that must keep
  dropping `init`; a test-only `io.Writer` in that slot observes claude directly without adding the arm
  production must not have. This is the same shape `dropcapRecorder` established for #1260; this ticket is the
  second consumer and confirms it generalizes to a different assertion (model, not dropped-line inventory).
  See also `docs/knowledge/features/e2e-realclaude.md` § What's there today.
  Assertions that discriminate on different mutants must both ship, and the comment must say which is which.
  Here A1/A2 (model) are the sole red for a mutant that neuters the in-band `/model` send; A3/A4 (no teardown)
  are the sole red for the pre-change tree's unconditional restart. Neither is redundant; a reviewer or a
  future editor who drops one because it "looks covered" by the other would silently halve what the test
  proves.
- **When a base argv must exclude a flag the recompose will also emit, read the value the flag would have set
  from the live system instead of hardcoding it.** Reading `models[0]` rather than assuming a fixed starting
  model turned a correctness constraint (no duplicate `--model` on the executed respawn path) into the
  mechanism that also makes target selection version- and machine-independent.

## Lessons learned

From the PR body:

- The `/model` turn does emit its own `system`/`init` line, and it still reports the *old* model — this
  resolves the architecture spec's open question 1 (the spec's measurement table had omitted the row while its
  prose asserted the emission). Measured: `initModels()` is 3 entries, `[start, start, target]`. Confirms the
  first-vs-last assertion shape was the right call, not an overcautious one.
- A live test whose two assertion pairs redden on different trees needs both evidence runs, not one — the
  model pair is green on the pre-change tree too (the respawn's recomposed argv changes the model regardless),
  so running only the pre-change evidence would have left the model assertion's mutant-discrimination unproven.
- The in-band branch's absence of a `result` line for the settle wait is what makes that wait's timeout
  *correct* rather than a hang: a tree that restarts never closes a `/model` turn, so both red evidence runs
  pay the full 60 s settle budget before reaching their assertions — by design, and now recorded in the test's
  header so a future reader doesn't mistake the ~65 s red-run duration for a stall.

From code review (one round, PASS, one SHOULD FIX below the three-finding gate — **left unaddressed on this
branch**, flagged for whenever the file is next touched, not blocking):

- **The settle wait's target count is hardcoded (`inbandWaitResults(rec, 2, …)`) rather than captured relative
  to the result count at the moment `UpdateSettings` is called.** If turn 1 takes longer than
  `inbandResendAfter` (45 s against a measured 5.7 s full run — low-probability but real), `inbandSendTurn`
  resends it; the resend's own result satisfies the hardcoded target of 2 *before* the `/model` turn has
  closed, and turn 3 gets written and read back before the model change has actually landed — a false A1/A2 red
  on a healthy tree. The one-line fix (`settleTarget := rec.resultCount() + 1`, captured immediately before
  `UpdateSettings`) restores the one-turn-in-flight invariant regardless of duplicates. Not fixed here because
  it wasn't blocking and the precondition is rare; the `t.Logf` diagnostic dump (init sequence, spawn count,
  result count) gives an operator enough to diagnose it if it ever fires.
- Two doc-comment NITs were also raised and left as-is (non-blocking): a stale "one method mapped, four
  promoted" count inherited from `cmd/pyry`'s `streamRunner` doc (should be "one mapped, five promoted" since
  #1580 added `SetSpawnArgs`), and an overstated reason for not reusing `dropcapWaitForChild` (the embedded
  `*streamsup.Runner` is in fact reachable through `inbandRunner`'s promotion — the real reasons, a distinct
  spawn budget and a `bool` rather than `io.Writer` return, are the correct justification).

## Testing

`go vet -tags e2e_realclaude ./internal/e2e/realclaude/` clean (`make check` cannot see this package — it's
gated behind `e2e_realclaude` and never compiled by the standard gate). Three runs, all `-race`, all measured
2026-08-19 against claude 2.1.220:

- **Current tree — all four green.** `init models [claude-sonnet-5, claude-sonnet-5,
  claude-haiku-4-5-20251001]`, 1 spawn, pid unchanged, 3 results, 5.7 s.
- **Pre-change tree, `b047b9e^` (= `e282de4`, the commit immediately before #1581's implementation) — A3/A4
  red, A1/A2 green.** `init models [claude-sonnet-5, claude-haiku-4-5-20251001]`, 2 spawns, pid changed, 2
  results. `UpdateSettings` there ends in an unconditional `sup.Restart(newArgs)`; the model still changes via
  the respawn's recomposed argv, so the model pair discriminates nothing on this tree — only the no-teardown
  pair does. The file compiled unchanged: every API it touches (including `SetSpawnArgs`, #1580) predates
  #1581.
- **Current tree + `-overlay` mutant dropping the `if update.Model != nil` send from `deliverSettingsInBand` —
  A1/A2 red, A3/A4 green.** `init models [claude-sonnet-5, claude-sonnet-5]`, 1 spawn, 2 results. No `/model`
  ever reached the child; nothing was torn down. No worktree writes — `go test -overlay=<abs>/overlay.json`.

Code review: one round, PASS, one non-blocking SHOULD FIX (see Lessons learned) and two NITs, none reaching
the three-finding gate. QA: `make check` green, `make build` green, scope confirmed at 2 files changed
(architecture spec + the one test file), zero production code.
