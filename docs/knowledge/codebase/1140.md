# Ticket #1140 — fakeclaude stream-json mode + package unit test

Teaches the e2e `fakeclaude` binary a new mode, `PYRY_FAKE_CLAUDE_STREAM_JSON`: a
line-delimited stream-json I/O model that mirrors the daemon's `internal/streamsup`
wire, so the stream `interactive_runner` path (#1081, shipped) has a fake to drive
it end to end without a PTY. Split from #1135; the harness helper and first
`send_message` spec that ride this mode land in the sibling #1135 (blocked-by this
ticket).

## Implementation

- New `main.go` mode gate, checked **first** in `main()`, above every
  `mustEnv(envSessionsDir/…)` call: `if os.Getenv(envStreamJSON) != "" {
  runStreamJSON(os.Stdin, os.Stdout); return }`. One `if` makes three ACs fall out
  structurally rather than by a validation branch: byte-identical-when-unset (falls
  straight through), mutual exclusion with every PTY/TUI mode (the `return`
  short-circuits before any of them can also be gated on), and no sessions-dir/
  transcript binding (never reaches the `mustEnv` calls or the JSONL open).
- `runStreamJSON(r io.Reader, w io.Writer)` — the testable seam. `bufio.NewReader(r)`
  + `ReadString('\n')` (not `bufio.Scanner`, which token-caps long lines; a
  stream-json line carries a whole prompt). Per line: decode via `userTurnText`,
  skip anything that isn't `{"type":"user",…}` (a `control_request` interrupt line,
  a blank line, unparsable JSON), else mint `m<N>` (a local `int` counter, no
  `uuidV4()` needed) and call `writeStreamResponse`. Returns on `ReadString` error
  (EOF or read error) or the first write error — both treated as "the daemon's read
  end is gone," never `os.Exit` mid-turn.
- `writeStreamResponse(w io.Writer, msgID, text string) error` — marshals two local
  structs (`outAssistant`/`outResult`) via `json.Marshal`, never string-concatenated,
  so the echoed prompt (caller-controlled bytes) is escaped and each line is exactly
  one physical line regardless of content. `text` is the **echoed** inbound prompt
  (not a canned string) — free downstream value for the sibling `send_message` e2e,
  which can assert delta text == sent prompt. `session_id` is the fixed literal
  `"fake-stream"`: `streamsup.Parser.streamLine` never decodes it, so threading the
  daemon's injected `--session-id` through would be pure overhead the fake
  deliberately avoids (it never inspects `os.Args` at all).
- Inbound/outbound shapes (`inUserTurn`, `outAssistant`, `outAsstMessage`,
  `outTextBlock`, `outResult`) are hand-mirrored local structs, not imported from
  `internal/streamsup` — `streamsup.userTurn` is unexported there, and mirroring
  keeps the fakeclaude **binary** zero-dependency (same posture as the existing
  `interruptEndTurnLine` literal).
- Single goroutine, no new shared state, no raw mode (stream-json travels over a
  pipe, not a PTY — canonical line discipline / CR mapping don't apply here).

## Patterns established

- **Gate-above-the-`mustEnv`-calls as a structural AC satisfier.** Placing a new
  mode's early-return above the required-env validation, rather than adding an
  explicit "modes X and Y are exclusive" check, turns "no sessions dir" and "mutual
  exclusion" into properties of control flow instead of things a future edit could
  silently break. Same shape as [[architecture-fakeclaude-stream-mode-verify-through-real-parser]]
  (architect memory) — reuse this gate placement for any future fakeclaude mode that
  needs to skip the PTY/TUI machinery entirely.
- **Belt-and-suspenders via a different-fabric verifier.** The unit test doesn't
  hand-decode the fake's own output — it feeds the emitted bytes through the real
  `internal/streamsup.Parser`, so a shape-mirroring mistake shared between the fake
  and a hand-written test-decoder is still caught on the emit side. The test
  package deliberately imports `internal/streamsup`/`internal/turnevent` (a
  sanctioned deviation from the fakeclaude-test stdlib-only norm) while `main.go`
  itself stays zero-dependency — only the test binary links the parser.

## Lessons learned

- The output side is verified by feeding the fake's emitted bytes through the
  **real** `streamsup.Parser` (different fabric from the hand-mirrored input line),
  so a shape bug the fake and a hand-written test-decoder would share is still
  caught on the emit side. (From the PR body's Lessons learned section.)
