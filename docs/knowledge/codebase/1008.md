# Ticket #1008 — `session_error` producer: give-up → typed v2 wire frame + daemon wiring

Split-child B of #1001 (wire+producer half; blocked-by #1007, the vocabulary half A). Consumes the merged `internal/msgqueue` `OnGiveUp` seam (#1000, shipped unwired) and the merged v2 wire vocabulary (#1007, shipped unwired — `TypeSessionError` / `CodeSessionBlocked` / `SessionErrorPayload`) to close the loop: when the message queue gives up on a wedged conversation's head, the daemon now fans a typed, terminal `session_error` to capability-gated interactive phones instead of leaving a queued turn that silently never runs. `security-sensitive` — the security-review section in the spec verdicts PASS.

## Implementation

- `cmd/pyry/session_error_v2.go` (**new**, 208 LOC) — a structural near-clone of the `queue_state` producer ([#722](722.md)) **minus the queue reference**:
  - `giveUpNotice{convID, reason string}` — the hand-off value. Unlike `queue_state` (whose channel carries a bare `convID` because the consumer re-reads current state via `Snapshot`), the give-up `reason` is a one-shot edge value not recoverable by re-reading queue state, so it rides the channel alongside the id — same struct-channel shape as `sessionTransitionEmitterV2.in`.
  - `sessionErrorEmitterV2{in <-chan giveUpNotice, logger, nextID uint64}` — deliberately **no** `snapshot`/`*msgqueue.Queue` field (contrast `queueStateEmitterV2`). That absence, not a "don't log queued text" rule, is what makes AC-3 (no untrusted-content leak) a structural guarantee: the producer has no code path that could reach queued phone text.
  - `sessionErrorNotify(ch, logger) msgqueue.GiveUpFunc` — the `OnGiveUp` seam builder: non-blocking buffered send, drop-on-full with a content-free Warn (`event` + `conversation_id` only, **never** `reason`). Captures the channel, not the emitter.
  - `Run(ctx, bcast)` / `broadcast(ctx, bcast, n)` — drains the channel until ctx-cancel or close, one notice → one broadcast → one envelope per interactive conn. `Code` is always the fixed `protocol.CodeSessionBlocked` (the seam carries no code field); `Message` is the notice's `reason` verbatim. `EventID` left nil — a give-up is a one-shot edge, so it does **not** join the #647/#649 reconnect-replay ring and has no connect-time reconcile (a phone connecting after the give-up gets no replay — correct, since #1000 respawns the session, making a stale replay wrong).
  - `startSessionErrorStreamV2(ctx, see, bcast) func()` — starts `Run` on a goroutine, idempotent cleanup joins on `done`. Does not close `in` (a late send racing teardown drops harmlessly).
  - `const sessionErrorQueueSize = 16` — same rationale as `queueStateQueueSize`: give-ups need ≥2 min of persistent failure per head (#1000's `GiveUpAfter`), so the buffer is unreachable short of a simultaneous mass-wedge.
- `cmd/pyry/main.go` — parallel to the `queueChanges`/`qse` sequence: `giveUps := make(chan giveUpNotice, sessionErrorQueueSize)` created **before** `msgqueue.New` (same chicken-and-egg reason as `queueChanges`); `OnGiveUp: sessionErrorNotify(giveUps, logger)` added to the `msgqueue.Config` literal — this is the whole "wire it in", flipping #1000's seam from nil to live; `see := newSessionErrorEmitterV2(giveUps, logger)` built after; `sessionErr: see` threaded into the `relayWiring` literal.
- `cmd/pyry/relay.go` — `relayWiring` gains a `sessionErr *sessionErrorEmitterV2` field (next to `qse`); `startRelayV2` starts `streamSessionErrCleanup := startSessionErrorStreamV2(ctx, w.sessionErr, mgr)` where `mgr` (the broadcaster) exists, and the cleanup block calls `streamSessionErrCleanup()` before `<-mgrDone` (after `streamQueueStateCleanup()`) — stopping the producer before waiting on the manager keeps a fan-out from racing a winding-down manager.
- `cmd/pyry/session_error_v2_test.go` (**new**, 297 LOC) — same-package unit tests driving the producer through the reusable `fakeInteractiveBcast`/`recordedPush` doubles: fans one frame per interactive conn with incrementing env IDs, skips non-interactive conns, stamps the fixed terminal code regardless of notice contents, the reason round-trips into `Message` verbatim, a per-conn Push error doesn't abort the fan-out, `sessionErrorNotify` drop-on-full doesn't block and never logs the reason, `sessionErrorNotify` delivers the full `{convID, reason}` (guards a bare-convID regression), `Run` delivers from the channel end-to-end, `startSessionErrorStreamV2` cleanup joins on cancel and is idempotent, and a `-race` concurrent-notify test.

Purely additive over #1000/#1007: the give-up already fires `OnChange` (the #722 `queue_state` producer independently reflects the backlog shrink); this ticket adds only the new typed error frame and touches neither `internal/protocol` nor `relay_guard_test.go` (both already updated by #1007).

## Patterns established

- **A confidentiality AC can be enforced by construction, not by discipline.** The producer is a field-for-field near-clone of `queue_state_v2.go` with exactly one field deleted (`snapshot func(convID string) []msgqueue.QueuedMessage`). That deletion — not a "never log `head.text`" rule — is the entire proof that untrusted queued text is unreachable: there is no code path in the file that could read it. Mirroring a sibling producer while subtracting the confidential dependency is a cleaner guarantee than mirroring it while adding a new "don't touch X" convention.
- **A one-shot edge value needs a struct-carrying channel, not a bare id.** `queue_state`'s channel carries only `convID` because the consumer re-derives current truth via `Snapshot`. A give-up's `reason` has no such re-derivation source (#1000's `firstFailedAt` latch is gone the moment the head drops), so it must ride the channel alongside the id — same shape as `sessionTransitionEmitterV2.in chan sessions.SessionTransition`.
- **`EventID`-nil producers split into "recoverable state" vs. "one-shot edge."** `queue_state`/`session_transition` are `EventID`-nil because they're idempotent full-state (a missed change is superseded by the next one). `session_error` is `EventID`-nil for the opposite reason: it is *not* recoverable, and a reconnect-time replay would be actively wrong once #1000 has already respawned the session. Same absent field, different justification — worth checking which one applies before copying the pattern forward.

## Lessons learned

- The AC-3 "no untrusted-content leak" property is enforced *by construction*, not by discipline: the emitter struct simply has no `Snapshot`/`*msgqueue.Queue` field, so there is no code path that could reach queued text. Mirroring a sibling producer while deleting one field is a cleaner confidentiality guarantee than a "don't log X" rule.
