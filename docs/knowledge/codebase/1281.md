# Ticket #1281 — Probe instrument: parameterise the run-outcome gather on stderr and a pinned group set (offline)

Adds `internal/e2e/realclaude/finding_run_gather_test.go` (830 lines, purely
additive). `trailRigGather` (#1268) is the right composition wired to the
wrong two inputs: it passes a `nil` literal as the reap-log stderr and keys
attribution on the test process's own process group. Under those two
hardcodings, `tdnClassifyReapLog(nil, …)` can only reach `tdnReapNoLine`,
which `trailAdmitAttribution` answers with `trailAdmitVoidNoLine` — so
`trailAdmitProof`, and with it `trailOutcomeRunningAtTrailer` (the only
outcome that is a finding), is **structurally unreachable**. A probe built on
that gather would report a clean negative on every run, forever, with no
symptom. `finGatherReadings` is the same composition with those two inputs
turned into parameters, proven offline — from synthetic stdout and synthetic
stderr — to reach both the finding and a genuine negative through its own
producers. No subject process, no live claude, no credentials, no turn.
Split from #1277; consumes #1280's `finAttributeFanOut`; the live wiring
(a real held command, real staged process group) is #1282, the next ticket
in the chain.

## Implementation

- **`finGatherReadings(stdout *probeSyncBuffer, needles []string, stderr
  []byte, pinned []int) (trailRunReadings, finAttributeRecord)`.** Four
  parameters, three legs, two returns, nothing built by struct literal.
  Trailer leg: `trailWaitForTrailer` → `trailGate` over the *reused* embedded
  scan result (never re-scanned) fills `Gate` and `BoundFrom`; the
  observation itself is a function-local and is **never returned** — that is
  how `trailScanResult.Trailer`/`.Line` are kept structurally out of the
  caller's reach (AC5). Attribution leg: guarded on `Gate.Reason != ""`
  (exactly C3/C4's split); inside the guard, `finAttributeFanOut(stderr,
  pinned, Gate.Reason)` is called and `Admit` is set to `record.Selected`
  **only when** `!finAttributeHasCondition(record, finAttributeNoGroups)` —
  outside the guard the fan-out isn't called at all, and `record` stays the
  zero `finAttributeRecord`. Argv leg: one `pinScanArgv(needles, nil)` call
  feeds `ArgvScanErrored`, `MatchCount`, `RowsScanned` and one
  `pinReadState` per matched pid.

- **The pinned-group parameter is `[]int`, never `[]reachProc` or
  `[]pinMatch`.** Mirrors #1280's own signature argument: a
  `[]reachProc`-shaped parameter would carry `.Command` (verbatim argv) and
  reopen the credential channel that `[]int` closes structurally. A caller
  holding `pinScan.Matches` converts at its own call site, taking `.PGID`
  and nothing else — that conversion site is #1282's, not this ticket's, and
  code review on #1282 must check it (architect's security-review SHOULD
  FIX).

- **Two changed inputs because there are two roles.** `ptyrunner.Run`'s
  pinned teardown order runs the reap immediately after the trailer is
  written, in the time of one `ps` exec, so a scan taken *after* the trailer
  is observed matches nothing on a healthy run — the predicted reading, not
  a failure. The pgid therefore can't come from a post-trailer scan; it must
  be pinned *during* the turn while the hold guarantees the subject is
  alive. `pinned` is the during-turn pin (the join key into pyry's reap
  log); `needles` drives the post-trailer `pinScanArgv` (content join +
  corroboration). One scan cannot be both.

- **The empty pinned-group set is surfaced, never classified.** Both
  alternatives publish a falsehood (priced one layer down by #1280's
  `TestFinAttributeEmptySetAlternativesArePublishedFalsehoods`): an unset
  `Admit` under a certifying gate reaches `trailOutcomeOutOfContract` via
  C3, and `trailAdmitOutOfContract` has no classifier arm and falls to Step
  8's `trailOutcomeNoRowMatched` — a clean negative about a run whose
  attribution never happened. So the gather passes `finAttributeNoGroups`
  out through `record.Conditions` and leaves `Admit` zero; the caller
  branches. The outcome tier that names such runs is #1278's.

- **`terminal_reason` crosses into the readings twice, by design, and the
  needle must not go there.** `trailGate` splices `Reason` `%q` into
  `Gate.Detail` on both certifying arms; the gather also hands that same
  `Reason` to the fan-out as `certified`, which `trailAdmitAttribution`
  splices `%q` into `Admit.Detail` on the budget and proof arms. Following
  #1271's "plant in every string-bearing input" literally would put the
  needle in `terminal_reason` and redden against two shipped predicates
  nothing here may change. `finGatherNeedleTrailer()` is a new fixture
  (not `trailPaddedTrailer`, which is `max_turns`-budget-fired and would
  discard the needle-bearing line's classification before
  `trailAdmitAttribution` ever reads the verdict) rendering an ordinary
  `terminal_reason: "completed"` trailer with the needle inside the
  512-byte cap, in the `result` field.

- **Test coverage — four top-level functions, 0 SKIP**
  (`go test -race -tags e2e_realclaude -run '^TestFinGather' -v`).
  `TestFinGatherComposesTheFindingAndTheNegative` is a 3-row table (a
  *function*, `finGatherCases()`, not a package var, since rows carry
  slices) proving Step 2 (`trail_run_outcome_test.go:523`) outranks Steps
  4/5/7/8 — both the finding row and the negative row run at
  `MatchCount == 0` and still separate, differing in exactly the pinned
  pgid. `finGatherAssertContract` runs C2/C3/C4/C8/C9 on every row rather
  than once. `TestFinGatherEmptyPinnedSetIsNotAReading` covers `nil` and
  `{0, 1}` (every group unreportable via `reap.go:52`'s `pgid <= 1` skip) as
  two distinct routes to the same condition.
  `TestFinGatherReturnsNoCapturedBytes` plants `trailNeedle` on the reap
  log's anchored line (after the `]`) and in the trailer's `result` field,
  asserts three load-bearing premises first (gate read the line as
  ordinary/`"completed"`, the needle survives the cap in the retained scan
  line, `Admit.Value == trailAdmitProof`), then a **recursive**
  forbidden-key walk over both marshalled returns — closing the flat-only
  scan gap #1280's `TestFinAttributeRecordCarriesNoCapturedBytes` left open
  for nested fields (`Gate`, `Admit`, each `Liveness` entry). Lowercased
  keys (no json tags on `trailRunReadings`, so marshalled keys are Go field
  names) with two named exact-key exemptions: `argvscanerrored` (a bool
  discriminator, not the scan's content) and `tool_stderr` (carried whole
  from `pinStateOutcome`, admitted by #1271 — this file's rows leave
  `Liveness` empty so the collision is invisible today but was named rather
  than left a landmine). `TestFinGatherForbiddenKeyWalkDescends` is the key
  walk's own dedicated table.

- **Mutation-tested, not only asserted** (developer's PR testing notes,
  reconfirmed by code review via `go test -overlay`): reverting the stderr
  parameter to #1268's `nil` literal reddens both certifying rows at C3;
  moving the needle into `terminal_reason` reddens the AC5 premise by name;
  padding the needle past the 512-byte cap reddens the `trailScanResult.Line`
  premise; the needle-bearing stderr/stdout, appended or prepended to
  `Gate.Detail`/`Admit.Detail`, is caught by both the AC5 test and the C2/C3
  contract checks in isolation — the #1284 vacuity shape (house-style
  `Detail` prose eating the redaction budget) does not recur here.

- **Prefix census clean at spec time**: `finGather` = 0, `fin[A-Z]` = 52
  (all #1280's, matching the ticket's stated baseline), control
  `trail[A-Z]` = 880. Code review noted the `fin[A-Z]` baseline moves again
  once #1278's families merge — expected, not a defect.

## Patterns established

- **A caller-side guard can be correct and permanently untestable by
  mutation, and that is not a missing assertion.** `finGatherReadings`'
  `!finAttributeHasCondition(record, finAttributeNoGroups)` guard states the
  obligation `finAttributeRecord.Selected`'s doc comment names — but
  `finAttributeFanOut` already returns with `Selected` at its zero value
  exactly when `finAttributeNoGroups` fires, so `NoGroups ⟺ zero Selected`
  is a hard invariant of the shipped producer, and removing the guard is
  *observationally identical*. What a test can and should pin is the pair
  either way (condition surfaced via the shipped helper, `Admit` left
  zero), not the guard's own mutation-survival. See
  [`developer-1281-guard-whose-removal-is-observationally-identical`]
  in project memory.
- **A needle's plant position must be re-derived per layer, not
  inherited.** #1280 planted only in the stderr and could stop there; this
  gather also holds the gate, so the stdout plant needed its own home (the
  trailer's `result` field) and its own premise assertion that the plant
  survives `reachCapCommand`'s cap — reusing `trailPaddedTrailer` would have
  been silently vacuous (wrong `terminal_reason`, wrong cap side).
- **A forbidden-key substring list transplanted onto a new record can
  collide with an already-shipped, intentionally-whole field.** `stderr` is
  correct for the attribution record; `trailRunReadings.Liveness` carries
  `pinStateOutcome.tool_stderr`, admitted whole by #1271. Named as an
  exact-key exemption with its citation (not a prefix rule) rather than
  left as a landmine for the first row that fills `Liveness`.
- **The recursive forbidden-key walk fixes a real, not hypothetical, gap.**
  #1280's flat top-level-key-only scan was a code-review SHOULD FIX
  deferred to this ticket specifically because `finAttributeRecord` and
  `trailRunReadings` both nest (`Gate`, `Admit`, `Liveness[]`, `Entries[]`).
  Any future no-captured-bytes test on a nested record in this family
  should default to the recursive walk, not the flat one.

## Lessons learned

- **A caller-side guard can be correct and untestable at the same time.**
  (See "Patterns established" above — restated here because it changes how
  a reviewer should read a green mutation on this specific guard: not as a
  missing assertion, but as a distinction no input can express.)
- **The needle's plant position must be re-derived per layer, not
  inherited.** `trailPaddedTrailer` is wrong for this file twice over: it
  places the needle *past* the 512-byte cap by design, and it renders
  `terminal_reason: "max_turns"`, on which `trailAdmitAttribution` returns
  its structural void before reading the verdict at all — so a test built
  on it would go green even against a leak on the proof arm.
- **A forbidden-key substring list transplanted onto a new record can
  collide with a shipped field.** `trailRunReadings.Liveness` carries
  `pinStateOutcome`'s `tool_stderr`, admitted whole by #1271; the collision
  with a naive `stderr` substring match is invisible while `Liveness` is
  empty (as it is in every row of this file) and would only surface on the
  first row that fills it. Named as an exact-key exemption rather than left
  implicit.
- **Code review's two NITs, both non-blocking, both wording/coverage
  precision rather than defects:** `finGatherCases`' doc comment overstates
  "same needles" across the first two table rows (`t.TempDir()`-derived
  paths differ per subtest; the load-bearing claim — both match nothing,
  `MatchCount == 0` on every row — survives); and the `tool_stderr`
  exemption in `finGatherExemptKeys` has no dedicated positive-match test
  row (harmless — an exact-key map lookup fails toward false RED, never
  false GREEN — worth a row if the exemption map grows a third entry).

## Open item carried to #1282

`PyryExited` is still staged `true` and `ClaudeState` still staged `""`,
exactly as #1268 staged them and for the same reason (no pyry runs in this
offline rig). The same argument that condemned the `nil` stderr applies one
field over: fed a live pyry, a gather that hardcodes `PyryExited = true`
would never let Step 3's `trailOutcomeVoidPyryDidNotExit` fire, and a run
where pyry hung would report a scan-side answer — or the finding — instead
of the staging void. That's a false-*positive* direction, worse than the
false negative this ticket closes. #1282 must promote `PyryExited` (and
`ClaudeState`) to parameters or fill them from real producers before
feeding this gather a live pyry; it must not inherit the staged values
silently. Architect's spec states this explicitly (Open question 1) rather
than leaving it to be rediscovered.
