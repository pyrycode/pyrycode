# Ticket #782 — Daemon reloads the paired-devices registry at handshake

A device paired with `pyry pair` while the daemon is already running is now
accepted on its **next** connection with no service restart. The daemon
`devices.Load`ed the registry once at startup and validated every handshake
against that in-memory snapshot, so a device added to `devices.json` by the
separate `pyry pair` process afterwards was on disk but absent from memory and
rejected until restart (root-caused on the mobile real-device run 2026-07-03,
"Footgun 3"). Affects every relay client — mobile now, the desktop client next.

Chosen mechanism (architect's call, spec `docs/specs/architecture/782-devices-registry-reload.md`):
**(a) read-through reload at handshake time**, self-contained in the daemon, over
(b) having `pyry pair` signal a running daemon (which would couple a
daemon-independent operation to a running service). See
[ADR 029](../decisions/029-devices-registry-reload-at-handshake.md) for the full
decision.

## Implementation

- **`internal/devices/registry.go` — new `(*Registry).Reload(path) error` (9th export).**
  Reconciles the on-disk device set into the in-memory registry under `r.mu`,
  disk authoritative for **membership**. Reconciliation is keyed on `TokenHash`
  (pure helper `reconcileDevices(memory, disk)`): a hash present in both keeps the
  **in-memory** struct (survivor — preserves the un-persisted `LastSeenAt` bump
  and any in-flight push registration); disk-only is adopted (newly paired);
  memory-only is dropped (revoked → reflects `pyry pair revoke` for free).
  Membership after Reload == disk's exact set, so the accept set is never widened.
  Malformed/unreadable disk → wrapped error, **in-memory set unchanged** (fail
  closed).
- **`readDevicesFile(path) ([]Device, error)` refactor.** `Load`'s disk-read
  branch (ENOENT/zero-byte → `(nil,nil)`; malformed/other → `(nil, wrapped err)`;
  valid → `(devs,nil)`) extracted into a shared unexported helper. `Load` now
  constructs from it; `Reload` reconciles from it. Behaviour-preserving for
  `Load`.
- **Lock discipline mirrors `Save`** ([ADR 020](../decisions/020-devices-registry-snapshot-then-write.md)):
  the disk read happens **outside** `r.mu`; only the reconcile-and-assign takes
  the lock. No nested locks; concurrent `Reload`/`Validate`/`Save` serialise at
  the single `r.mu`.
- **Handshake wiring (`internal/relay/v2session.go`).** `V2SessionConfig` gains an
  optional `DevicesPath string`; `""` disables the reload (keeps existing tests
  byte-stable — the `claudeSessionsDir==""` opt-out idiom). Immediately before the
  sole production `Devices.Validate` call (`handleNoiseInit`, on the manager Run
  goroutine), if `DevicesPath != ""` the manager `Reload`s. On a reload error it
  logs at Warn and **proceeds to `Validate` against the retained set** (fail closed
  — accept set not widened, loaded devices not lost). `NewV2SessionManager` does
  **not** validate `DevicesPath` (optional field, no panic).
- **Write-path clobber guard (`internal/relay/handlers/register_push_token.go`).**
  Between `UpdatePushRegistration` and `Save`, a best-effort `reg.Reload(registryPath)`
  merges any device `pyry pair` added since startup into memory so the whole-file
  `Save` does not erase it. On a reload error it logs at Warn and **still `Save`s**
  the known-good in-memory state (self-heal — no worse than the pre-#782 blind
  Save). The dedupe early-return path (which does not `Save`) is untouched. This is
  the **only** in-daemon `Save` site (`Validate` never persists).
- **Startup wiring (`cmd/pyry/relay.go`).** The `V2SessionConfig` construction now
  passes `DevicesPath: resolveDevicesPath(instanceName)` — the same path startup
  `Load` and `register_push_token` use.
- **v1 out of scope (deliberate).** The deprecated v1 handshake leg is not wired
  for reload ("no shipping client speaks v1"); reviving it later is a one-line
  mirror in `authGate`. The `register_push_token` clobber guard lives inside the
  *shared* handler, so it covers v1's write path automatically.

## Patterns established

- **Reconciling read-modify-write for a two-writer file.** When both the daemon
  and an external process (`pyry pair`) rewrite a whole file via atomic rename
  (last-writer-wins), the daemon's read-through reload must **reconcile** disk
  into memory — never blind-swap — and must be applied at **both** the read
  (handshake) and write (`register_push_token` Save) sites. Reload-at-read alone
  trades the restart bug for a data-loss bug (the worked A/B scenario in ADR 029
  and the clobber regression test).
- **Keep-in-memory-survivor** reconcile: for fields the daemon is the sole writer
  of and hasn't persisted (`LastSeenAt`, push registration), memory wins on a
  `TokenHash` match; disk wins only for membership.
- **Two new reload-failure log sites deliberately differ**, and the difference is
  a security boundary:
  - Handshake reload log (pre-auth): `path` + `conn_id` + static reason **only** —
    no `device_name` (anti-enumeration, mirrors the handshake reject discipline).
  - `register_push_token` reload log (post-auth, the device is the operator's own):
    adds `device_name`, consistent with the adjacent `save_failed` log.
  - **Neither logs the wrapped `err`** — a `json.Unmarshal` error on a corrupt
    `devices.json` can echo file bytes carrying a `token_hash`. (Contrast: the
    adjacent `save_failed` log *does* include `err`, because a Save error is a
    write-side failure over known-good in-memory state, not a parse of untrusted
    disk bytes.) `Validate`'s non-leakage contract extends to every new site.
- **Optional config field as a byte-stable opt-out.** `DevicesPath == ""` disables
  the new behaviour so existing construction sites and fixtures compile and pass
  unchanged — the same idiom as the manager's other optional seams
  (`Snapshotter`/`Handlers`/`claudeSessionsDir`).

## Testing

- `internal/devices/registry_test.go` — `TestReload` (table: added-adopted,
  removed-dropped, missing→empty, empty-list→empty, malformed→fail-closed-no-loss,
  unreadable→fail-closed-no-loss; the unreadable case points `path` at a directory
  for a deterministic CI-safe `EISDIR`), `TestReload_PreservesInMemoryLastSeenAt`
  (survivor keeps the `Validate`-bumped timestamp over a stale disk record), and
  `TestReload_ConcurrentReloadValidate` (`-race` probe).
- `internal/relay/handlers/register_push_token_test.go` —
  `TestRegisterPushToken_ReloadPreventsClobberOfNewlyPairedDevice`: seed memory
  `[A]`, write `[A,B]` to disk (simulating `pyry pair`), run the handler for A,
  assert persisted file is `[A_push, B]` — **B not erased** (the core data-loss
  guard). An existing test also gained a disk-seed step so its post-#782 reload
  reconciles against a real file rather than the ENOENT→empty contract.
- `internal/e2e/relay_v2_handshake_test.go` (`//go:build e2e`) —
  `reload_picks_up_newly_paired` (AC1 end-to-end: seed `[A]`, rewrite disk to
  `[A,B]`, dial with token B → accepted) and `reload_malformed_fails_closed` (AC4:
  corrupt disk → unpaired token 4401-rejected, token A still accepted).

## Lessons learned

- **A single-symptom "reload" ticket hides a second, opposite bug when the reader
  is also a writer.** The obvious fix (reload at the handshake) makes the
  restart-rejection symptom disappear while silently arming a data-loss symptom on
  the write path. The PO/architect surfaced this ("trades the restart bug for a
  data-loss bug") and it became a required AC (AC4) + the clobber regression test.
  When adding a read-through reload, grep for **every** `Save` site of the same
  file first.
- The developer's implementation matched the spec with no code-review findings
  (the code-review stage produced only an auto-commit).
