# Ticket #1527 — stamp a redemption deadline on newly minted pairing records

Split from #1509; first of a three-slice sequence (#1527 stamp → #1528 record first redemption → #1529 enforce). Adds a durable "this pairing record has not been redeemed yet, and stops being acceptable at T" marker to `devices.json`, with a single writer and zero readers. Nothing in this slice can lock anyone out — that is deliberate, and pinned by tests.

## Implementation

- `internal/devices/device.go`: new field `RedeemBy time.Time `json:"redeem_by,omitzero"`` on `Device`, and `const RedemptionWindow = 15 * time.Minute`. `omitzero`, not `omitempty` — `encoding/json`'s `omitempty` is a silent no-op on a struct type (`time.Time`), so it would write `"redeem_by":"0001-01-01T00:00:00Z"` into every legacy record on the next `Save`. `omitzero` (Go 1.26.2+) consults `IsZero()` and keeps the zero off disk, same as the three sibling optional fields do for their own types.
- `cmd/pyry/pair.go` (`runPairDefault`, the sole non-test `Device`-construction site): hoisted the inline `time.Now().UTC()` to a local `mintedAt`, used for both `PairedAt` and `RedeemBy: mintedAt.Add(devices.RedemptionWindow)`. One clock read for both stamps makes `RedeemBy.Sub(PairedAt) == devices.RedemptionWindow` **exactly** true — the test asserts equality, not a tolerance window, which is what a single-clock-read contract buys over two separate `time.Now()` calls.
- Naming: `RedeemBy`, not `ExpiresAt`. The deadline bounds the *unredeemed* window only; a device that has already been redeemed keeps authenticating past it. `ExpiresAt` would misstate that once #1528/#1529 land.
- Inertness is structural this slice: `git grep -n RedeemBy -- '*.go' ':!*_test.go'` returns exactly two hits (the declaration, the stamp). `Validate`, `reconcileDevices`, `renderPairList`, `Remove`, `UpdatePushRegistration`, `FindByTokenHash`, and the v2 handshake are all untouched.
- No protocol impact — `devices.Device` is never marshalled across the wire, so this is a disk-schema-only change.

## Tests

- `internal/devices/device_test.go`: `TestDevice_RedeemByJSONShape` (table: set-deadline round-trips via `.Equal`; zero-deadline omits the `"redeem_by"` key — this second row is the `omitzero`-vs-`omitempty` tag pin) and `TestRedemptionWindow` (value pin, `== 15*time.Minute`).
- `internal/devices/registry_test.go`: `TestRegistry_RedeemByPersists` — `Save`→`Load` round-trip for a stamped and an unstamped record, plus a hand-authored pre-field `devices.json` envelope decoding to a zero `RedeemBy` with every other field (`TokenHash`, `Name`, `PairedAt`, `LastSeenAt`) individually asserted intact.
- `internal/devices/auth_test.go`: `TestRegistry_Validate_IgnoresExpiredRedeemBy` — a record with `RedeemBy` an hour in the past still authenticates through `Validate`. Also asserts the fixture's own precondition (`RedeemBy` non-zero and in the past) so the pin can't hold vacuously against an accidentally-zero fixture.
- `internal/relay/v2session_redeemby_test.go` (new file, not appended to the 4700-line `v2session_test.go`): `TestV2Session_ExpiredRedeemBy_StillHandshakes` — drives a real v2 handshake for a device with a back-dated `RedeemBy` to `open` via `openModalConn`, with the same non-vacuity re-check after.
- `cmd/pyry/pair_test.go`: `TestRunPairDefault_StampsRedeemBy` (end-to-end mint, exact `RedeemBy - PairedAt == RedemptionWindow`), `TestRenderPairList_RedeemByInvisible` (differential — same device rendered with/without `RedeemBy` set must be byte-identical output, immune to golden-string or tabwriter-padding drift), `TestRunPairRevoke_PreservesRedeemByOnSurvivors` (revoke one of two stamped records; survivor's `RedeemBy` and other fields intact).

## Patterns established

- **Single clock read for two derived stamps, to buy exact-equality tests.** When a test needs to assert `B - A == constant`, make the production code compute `A` once and derive `B` from it, rather than two independent `time.Now()` calls — the latter forces a tolerance-window assertion, which is both weaker and a flake source.
- **`omitzero` for optional `time.Time` fields, never `omitempty`.** `encoding/json`'s `omitempty` only omits empty scalars/maps/slices, never a struct — on a `time.Time` it silently does nothing. This is now the second field in `Device` where getting this right mattered (the JSON-shape test pins the tag directly, going red under `omitempty`).
- **A differential test beats a golden string for a "field surfaces nowhere in this output" claim.** `TestRenderPairList_RedeemByInvisible` renders the same input with and without the new field set and asserts byte-identical output, rather than hardcoding expected bytes — it can't be made to pass by someone updating the golden, and it doesn't care about tabwriter padding.
- **New test file over appending to a large shared one.** `v2session_redeemby_test.go` is new rather than appended to `v2session_test.go` (~4700 lines, already split by concern across several `v2session_*_test.go` files) — keeps the merge surface on that file at zero.

## Lessons learned

- A mutation-table row can be correctly unsatisfiable *because of* a design rule stated elsewhere in the same spec, not because a test is missing. Retuning `RedemptionWindow` reddens `TestRedemptionWindow` but not `TestRunPairDefault_StampsRedeemBy`, because the spec's own DRY rule ("the mint site and the test both derive from the constant rather than restating it") makes the two move together by construction. Restating the literal 15-minute value in the mint test to force it to fire independently would contradict that same design rule. Before routing a mutation-table row as a gap, check whether the spec's own § Design already explains why it can't fire.
- `omitempty` vs `omitzero` on a `time.Time` is only observable in the **encoded bytes**, never in a decode round-trip — both tags decode a missing key back to the zero value. A `Save`→`Load` persistence test alone cannot pin the tag choice; it takes a `json.Marshal` + key-presence assertion (`TestDevice_RedeemByJSONShape`'s zero row), separate from the round-trip test (`TestRegistry_RedeemByPersists`).
