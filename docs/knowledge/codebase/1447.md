# Ticket #1447 — A measured non-establishment reaches a run-level value of its own (offline)

`trailClassifyRun`'s `trailGateAbsentOwesNone` arm consults #1440's pinned-pid
sighting route (wired by #1446) and, since #1446, published everything the route
did not *establish* under a single value, `trailOutcomeVoidPathOwesNoReason`. Three
different things shared that value: the route measured a pinned pid and refuted
aliveness, the route measured nothing, or the route was never staged. This ticket
takes the first case off the blanket — a **measured refutation** is not the same
statement as "nothing was certified," and publishing it under a value whose Detail
says the route "was consulted and answered X" files a measurement under the name of
one that never happened. The remaining two cases stay on
`trailOutcomeVoidPathOwesNoReason` as #1448's work.

PR [#1450](https://github.com/pyrycode/pyrycode/pull/1450). Split from #1444
(itself split into #1446 → #1447 → #1448, wired natively so neither later ticket
reaches an architect until its predecessor closes). Blocked by #1446 (merged,
`7d5c6cf`); blocks #1448. Security-sensitive (architect self-review PASS). One
code-review rework round, entirely on the cite-renumbering pass — the design
surface itself was never faulted.

## Implementation

- **The new value: `trailOutcomeVoidPinnedPidDidNotEstablish =
  "run-void-pinned-pid-did-not-establish"`**, inserted immediately after
  `trailOutcomeVoidPathOwesNoReason` in the const block. Its doc argues, and its
  neighbours were corrected to agree: deliberately not
  `trailOutcomeVoidPathOwesNoReason` (that one is now "measured nothing or never
  staged"; this one is "a pid that *was* read"); deliberately not a
  `run`-prefixed transform of `trailSightingUnestablished` (`"run-sighting-not-
  established"` would *contain* the route's own value, and the union map's
  equality-only comparison is blind to containment — the same trap #1446
  documented); deliberately not `trailOutcomeVoidLivenessInstrument` (that is the
  argv scan's per-pid read failing *as an instrument*; here the read answered, it
  simply did not establish — landing it on the instrument-failure value would
  report a working instrument as a broken one).
- **Claim limit inherited verbatim, not restated.** The value's doc quotes
  `trailSightingUnestablished`'s own claim-limit sentence ("a statement about THIS
  EVIDENCE ROUTE, not about the command having been dead at the sighting — the
  read is late by construction... deliberately no 'exited before the sighting'
  value") word for word, and ties it to the run space's own precedent for the same
  discipline (`trailOutcomeNoRowMatched`'s doc, a statement about the scan and
  explicitly not about the command having exited). The Detail format string
  carries the same limit ("NEVER an it-exited verdict — the re-read is late by
  construction").
- **The arm gains a middle branch, kept total by construction.**
  `trailEstablishSighting` returns exactly three values.
  `sighting.Value == trailSightingEstablished` is unchanged (#1446's finding).
  `sighting.Value == trailSightingUnestablished` is new: `out.Route =
  trailRouteSighting`, then `decide(trailOutcomeVoidPinnedPidDidNotEstablish, ...)`.
  Everything else (`trailSightingVoid`) falls through to the existing
  `trailOutcomeVoidPathOwesNoReason` return — no third explicit `case` and no
  default arm, since an explicit case plus a defensive tail would add a return site
  no fixture can reach, the same totality argument the surrounding step-1 switch
  already makes.
- **A void publishes a route for the first time**, which falsified four prose
  claims and all four were corrected in this commit: the route space's header
  ("WHICH EVIDENCE CLASS PRODUCED A FINDING" → "…A VERDICT"), `trailRouteSighting`'s
  doc ("Set on `trailOutcomeAliveAtSightingByOrdering` alone" → "…and since #1447
  on `trailOutcomeVoidPinnedPidDidNotEstablish`"), `trailRunOutcome.Route`'s field
  doc (rewritten around "published exactly where the route's own measurement
  decided the value" — true on the new arm, false on the fall-through beside it,
  which keeps `Route == ""` because the verdict there rests on the gate reading
  alone), and `wantRoute`'s doc ("exactly the two values" → "three").
  `wantRoute` (`trail_run_outcome_test.go`) gained the one entry that makes this
  checkable rather than asserted.
- **The sibling void's Detail does not grow a "kept apart from" clause naming the
  new value — measured, not a style choice.** 461 B rendered / 51 B headroom, and
  the shortest honest clause naming a 37-byte value costs 60-80 B; a draft that
  appended one rendered 541 B and truncated the argument the Detail exists to
  make. The separation obligation is discharged for free elsewhere: in the two
  values' own doc comments, and in the new arm's Detail, which names
  `trailOutcomeVoidPathOwesNoReason` as what it is kept apart from. The sibling's
  format string is otherwise untouched — it still interpolates `sighting.Value`,
  now always `trailSightingVoid`, correct rather than stale (a future sighting
  value would be carried, not mislabelled).
- **The new arm's Detail is budgeted against the *longer* of two reasons, measured
  on the shipped format string rather than a draft of it.** Two verdicts reach this
  arm through the same `sighting.Value` (`sighting-not-established`) but different
  `sighting.Reason`s — `sighting-reason-pid-gone` (24 B) and
  `sighting-reason-pid-reaped-pending` (34 B, ten bytes longer). Final measured
  figures: **482 B / 30 B headroom** on the shorter reason, **492 B / 20 B
  headroom** on the longer — both under the 512 B `reachCapCommand` ceiling with no
  `reachTruncationMarker` on either row. An earlier draft phrasing the same five
  obligations (gate value, `sighting.Value`, `sighting.Reason`,
  `trailDeclaredFinishInstantClause`, the kept-apart clause) rendered 526 B / 536 B
  and silently lost its closing claim-limit clause to the cap — caught only by
  re-measuring the *shipped* string, not the spec's own figure (which was itself
  off by one operand's length; see Lessons).
- **Two rows, one re-pointed and one added, both mutation-proven.** The existing
  `sightingRefuted` row (`PinnedPid = trailSightingPin(pinStateNoSuchProcess)`) is
  re-pointed from `trailOutcomeVoidPathOwesNoReason` to the new value — no new
  fixture, per the architect's spec. A second row, `sightingRefutedPending`
  (`PinnedPid = trailSightingPin(pinStateExitedNotReaped)`), is added and reaches
  the arm's *worst-case* Detail. Overlay-run mutation checks (code review):
  keying the branch on `readings.PinnedPid.Verdict` instead of `sighting.Value`
  reddens **only** `sightingRefutedPending` — proving that row, not the re-pointed
  one, is what forces the branch to key on the route's own value rather than the
  raw pin verdict, since two different verdicts share `sighting.Value`. Dropping
  `out.Route = trailRouteSighting` reddens the `wantRoute` invariant and the
  re-pointed `Route` premise in the leak sweep. Splicing out
  `trailDeclaredFinishInstantClause` reddens
  `TestTrailRunCertifiesNothingArmsNameTheInstant` on both rows.
- **`TestTrailRunOutcomeCarriesNoCapturedBytes`'s REFUTED block is amended, not
  left alone** — it was deliberately RED before this ticket (#1446 pinned the two
  things this ticket moves): `:1970`-equivalent's expected value moves to the new
  constant, and the `got.Route == ""` premise moves to `got.Route ==
  trailRouteSighting`. **The `Route` premise is re-pointed, not deleted** — it
  anchors the sweep to the record's route-bearing key set, and after this change
  all three sweep blocks publish a route, so the swept set is a strict *superset*
  of what it replaced (`Route` is the only differing field and is `omitempty`) —
  coverage is preserved, and the amended comment says so rather than leaving the
  change to read as a hole.
- **Registration, five sites in one commit:** `trailIsRunOutcome`,
  `trailRunOutcomeValues()`, the union closure map
  (`trailer_admissibility_test.go`), `trailRunCertifiesNothingArms()` (the new
  value is its fifth carrier — not named in the ticket body, caught by the

  touches (three of them — `finding_staging_gate_test.go`,
  `finding_exit_path_probe_test.go`, `finding_attribution_fanout_test.go` — outside

  `finding_trailer_evidence_test.go`'s `len(distinct) != 21` → `!= 22`.

## Patterns established

- **A route field can be published on a void, once the void names a route-decided
  verdict rather than "route was consulted."** #1446 introduced `Route` under the
  rule "set on the two finding values"; this ticket generalizes it to "set exactly
  where the route's own measurement decided the value," which is a strictly wider
  and still-precise rule — a fall-through beside a route-consulting arm can
  legitimately keep `Route == ""` if the verdict there rests on something else
  (here, the gate reading alone). Four prose sites needed correcting in the same
  commit that changed the rule; grep for "alone" / "the two" near a provenance
  field's doc when a third case joins it.
- **Budget a Detail against every reason the arm can render, not the one the spec
  measured.** Two verdicts reaching the same arm through different `Reason`
  strings is enough to make a "measure the draft" headroom figure wrong by a full
  10 bytes — see Lessons. The fix pattern: add the row that exercises the *longest*
  reason as a first-class fixture, not just as a mental check, so a future
  format-string edit that overruns the cap fails a build rather than a review.
  [[po-1402-a-normaliser-blinds-the-byte-assertion]] is the sibling lesson for
  "the byte-level assertion has to actually reach the value," this is its "against
  which input" counterpart.
- **A void's Detail does not need a "kept apart from" clause for every value that
  could be confused with it, if the doc comments already carry the argument.**
  Prose separation has two homes — the rendered Detail (operator-facing, byte-
  capped) and the const's doc comment (reader-facing, uncapped) — and where the
  Detail has no headroom, the doc comment is where the obligation goes. #1446
  established this for the exchange-not-append case; this ticket extends it to
  "sometimes exchange nothing at all."

## Lessons learned

From the PR body's own "Lessons learned" section (developer):

- **A spec's Detail byte budget measures the draft, not the shipped prose.** The
  architect's spec measured 486 B / 496 B for the new arm from a draft phrasing;
  the format string as actually written rendered 526 B / 536 B and truncated
  silently at `reachMaxCommandBytes` = 512, cutting the closing claim-limit clause.
  Re-render the *shipped* format string against every value it can interpolate
  before trusting a headroom figure — here two reasons reach the arm and only the
  longer one (`sighting-reason-pid-reaped-pending`, +10 B) is the real budget.
  Final: 482 B / 492 B, worst-case headroom 20 B.
- **The row that makes a worst case fail the build is not optional.** The second
  row (`trailSightingPin(pinStateExitedNotReaped)`) is what turned the truncation
  into a red build rather than a quiet cut. Mutation-checked: it is also the
  *sole* killer of a build that keys the new branch on
  `readings.PinnedPid.Verdict` instead of `sighting.Value`.
- **A cite remap must resolve the target file from the named SYMBOL, not from
  last-named-file inheritance.** This was the rework-round failure (see below),
  and it produced cites that were *exact* at the base commit — PR-created
  staleness, not inherited debt. A bare `(:NNN)` inherits the last file named,
  which is often a **different** file two lines up, so remapping it through that
  file's line map silently points it over a hundred lines away.
- **Build the line map from EVERY hunk in the target file, not the one you were
  looking at.** `trailer_admissibility_test.go` had four insertion hunks
  (cumulative +1 / +5 / +6 / +7); the first remap pass captured only the
  map-literal hunk and shifted all eight inbound cites by +2 instead of the
  correct +5 or +7.
- **Verify cites by TEXT, and run two complementary passes.** Pair each cite with
  its base-tree counterpart on normalised prose (strip `:\d+`), then require the
  head cite to land on the line whose text the base cite pointed at — this catches
  cited blocks that *grew* (a range whose end now stops mid-sentence). Run an
  arithmetic pass through git's line map alongside it — this catches targets that
  are blank or that the PR itself edited, which the text pass cannot compare.
  Neither alone is sufficient; together they took 11 mismatches to 0 in rework.
- **A prose re-wrap that adds a line is a cite cascade.** Absorbing a longer
  symbol anchor by adding a 9th line to an 8-line comment would have shifted ~13
  downstream cites into that file. Rebalance the paragraph within its existing
  line count instead — trimming two redundant phrases was enough here.
- **Two count literals lived outside the architect spec's own enumeration.** The
  union map's running tally and its "one assignment per run-level answer" claim
  about route values both went stale — the latter because `trailRouteSighting` is
  now set on two values rather than one, which is itself the clearest argument for
  why the evidence class lives in a field rather than in a value suffix.

From code review (one FAIL round, one rework, then PASS):

- **Round 1 (FAIL) — the cite-renumbering pass was wrong in a systematic way, on
  cites exact at the blocker's merge commit.** Two failure classes, both
  PR-created rather than inherited: (1) a bare `:NNN` ref two lines below a
  different file's name was remapped through *that* file's line map instead of
  the line map of the file its named symbol actually lives in — one site landed
  121 lines away, inside unrelated fixture rows; (2) `trailer_admissibility_test.go`
  has three insertion hunks, and the remap captured only one, undercounting eight
  inbound cites by 3-5 lines each. A `+2` shift was applied where `+5` or `+7`
  was correct.
- **Rework — all findings fixed comment-only, 20 insertions / 20 deletions, line
  counts preserved in every file so nothing re-cascaded.** The wrong-file bare ref
  was re-pointed by symbol rather than by filename (spelling the filename would
  reset last-named-file inheritance forward and break the next correct neighbour)
  and the paragraph carrying it was rebalanced within its existing line count
  rather than grown. One additional site the review had not named
  (`finding_run_gather_test.go:1124`) was caught and fixed the same way — a
  cite left at zero shift while its own neighbour in the same file got the
  correct +54 delta.
- **PASS, with two named-but-unblocking findings: unrelated single-literal
  fixture drifts.** `finContainValuePlantedTrailer`'s `duration_ms` (`9001` →
  `9002`) and a `TestFinGatherForbiddenKeyWalkDescends` array-element `pgid`
  (`7788` → `7930`) both landed in the implementation commit rather than the
  auto-commit, read as leftover experimentation, and were both behaviour-neutral
  (reverted via `go test -overlay`, suite stayed green; neither value is asserted
  on). The `duration_ms` drift falsified a doc sentence claiming the fixture's
  wire values "keep their shipped values" — the sentence is about four *other*
  published values and was not itself falsified, but the drift is worth a glance
  in future reviews as a class: unrelated single-field literal edits riding along
  in an implementation commit, invisible to a diff review that only reads the
  named design surface.
- Verification, final round: `go test -race -tags e2e_realclaude
  ./internal/e2e/realclaude/` with the ticket's `-run 'TestTrail|TestFin'` filter —
  405 tests run, 0 skipped, 0 failed. Value string `run-void-pinned-pid-did-not-
  establish` swept both ways against 79 values across the union map,
  `trailRunOutcomeValues`, `finOutcomeValues` and `trailRunRouteValues`: 0
  collisions, 0 containments in either direction. Cite pass, final: 930 pairs
  machine-checked via a git-diff line map, 0 real mismatches (six initial flags
  were the checker's own resolver mis-attributing symbol-anchored and bare refs,
  each confirmed correct once checked against the symbol's defining file).
