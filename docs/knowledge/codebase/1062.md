# Ticket #1062 — Fan `turn_state` across a follow-active switch on per-conversation sessions

Split from [#1050](https://github.com/pyrycode/pyrycode/issues/1050) (the turn-phase
half; the `modal_shown` half is [#1063](https://github.com/pyrycode/pyrycode/issues/1063)).
A per-conversation interactive session streamed `assistant_delta` and `turn_end` but
never fanned `turn_state` (thinking/responding), so a remote client rendered the full
reply with no interrupt affordance, no observable queue window, and a false
"the turn seems to have stalled…" warning after a healthy reply.

## Root cause

The single long-lived `interactiveTurnEmitterV2`
([codebase/632.md](632.md)) keys its turn lifecycle (`inTurn`/`turnID`/`seq`/
`currentState`) to whichever conversation opened the turn, but recorded no owner.
The follow-active subscriber ([codebase/679.md](679.md),
[features/turnbridge-package.md § The follow-active subscriber](../features/turnbridge-package.md#the-follow-active-subscriber-newtargetsubscriber-679))
tears down the prior conversation's tail **mid-turn** on a switch, so its `TurnEnd`
never arrives: `inTurn` stays `true`, `currentState` stays `responding`. The next
conversation's first content event then hits two separate consequences of the same
missing owner: `startTurnIfNeeded` sees `inTurn==true` and returns early (no reset),
and `transitionTo(newConv, responding)` sees `currentState==responding` and
de-dups the emit away — while the delta still flushes via the non-de-duped
`emitMapped`. Fingerprint: deltas + turn_end fan, but no turn_state, exactly the
reported symptom.

## Implementation

One production file, `cmd/pyry/interactive_turn_v2.go`, ~15 lines:

- New field `turnConvID string` on `interactiveTurnEmitterV2` — the conversation
  that owns the currently-open turn. Set in `startTurnIfNeeded` alongside the
  existing `inTurn`/`seq`/`currentState` resets.
- A guard at the **top of `Handle`**, after the empty-cursor drop and before the
  type-switch: `if e.inTurn && convID != e.turnConvID { e.flushDelta(ctx); e.endTurn() }`.
  Flushing before ending is load-bearing — `flushDelta` emits against `deltaConvID`
  (captured when the abandoned turn buffered its text) using the abandoned turn's
  still-in-place `turnID`/`seq`, so the orphaned conversation's partial text keeps
  correct attribution. `endTurn` then closes the turn so the next event's
  `startTurnIfNeeded` re-mints a fresh `turnID`, resets `seq=0` and `currentState=""`,
  and records the new `turnConvID` — so `transitionTo` is no longer de-duped and the
  new conversation's opening `responding` fans.

No change to `interactive_turn_stream_v2.go` or the subscriber; the emitter's sole
construction site and `Handle` call site are untouched — zero consumer cascade.

## Patterns established

- **Explicit ownership beats implicit scoping for shared long-lived state.** The
  emitter's lifecycle fields were always "whichever conversation is active right
  now" by convention, never by record — the follow-active switch is exactly the
  case that convention doesn't survive. Recording `turnConvID` at open and
  comparing it on every `Handle` turns an implicit assumption into a checked
  invariant, at the cost of one field and one guard.
- **Compose existing no-op-safe primitives rather than add a new reset path.**
  The fix is `flushDelta` (already a no-op on an empty buffer) + `endTurn` (already
  just `inTurn=false`) — no new failure mode, no new lock, same single-goroutine
  contract as the fields it touches.

## Testing

- **Hermetic emitter oracle** (`cmd/pyry/interactive_turn_v2_switch_test.go`, new) —
  recovered from the abandoned `feature/1050` branch's `zz_repro_1050_test.go` and
  renamed off the scratch naming. Four cases:
  - `TestInteractiveTurnV2_SwitchWithOpenPriorTurn_EmitsResponding` — the AC4 oracle.
    RED on `main` (de-dup swallows B's `responding`), GREEN after the fix.
  - `TestInteractiveTurnV2_SwitchResetsTurnIdentity` — strengthened: no manual
    lifecycle reset (the fix's own guard does it); asserts B's delta carries a
    fresh `turn_id` (≠ A's) and `seq==0`.
  - `TestInteractiveTurnV2_SwitchFlushesAbandonedDeltaBeforeNewState` — AC3 scoping
    + wire ordering: A's abandoned delta flushes stamped A, strictly before B's
    opening `responding` stamped B.
  - `TestInteractiveTurnV2_CleanPriorTurnEndUnaffected` — control: a cleanly-ended
    prior turn (delivered `TurnEnd`) is unaffected by the guard. Passes on `main`
    and after the fix; isolates the defect to the open-prior-turn carryover.
- **Real-claude liveness rung** (`internal/e2e/realclaude/interactive_turn_state_liveness_test.go`,
  new, `//go:build e2e_realclaude`) — wired into `make e2e-realclaude`/`make preship`
  via the package glob, no Makefile change (mirrors #854/#997/#1031). Reuses the
  #997 per-conversation harness verbatim (`startPerConversationHarness`,
  `createConversationViaPhone`, `sealSendMessage`) and adds one drain helper,
  `drainForTurnState` (the `drainForAssistantReply` shape, decrypts every noise_msg
  in receive order, returns on a `thinking`/`responding` `turn_state` for the target
  conversation). Per #997's timing-race finding this is a **liveness** gate, not
  the deterministic RED — the switch-with-open-prior-turn precondition only fires
  when the producer is mid-backoff at the instant the switch lands, which a fast
  co-located harness rarely reproduces; the deterministic proof lives in the
  hermetic oracle above.

`go test -race ./...`, `go vet ./...`, `staticcheck ./...` green. Code review:
**PASS**, no findings.

## Not `security-sensitive`

`turn_state` carries only coarse daemon state (thinking/responding/idle), no
application content, fanned wire-direct. The cross-conversation scoping property
(AC3) is the pre-existing `conversation_id` stamp on `TurnStatePayload`
(`internal/protocol/interactive.go`), asserted here, not newly designed — see
[[security-sensitive-label-tracks-design-not-lineage]].
