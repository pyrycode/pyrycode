# Ticket #1488 — exempt `IsArchived` rows from the idle sweep

Reconciles the two archive mechanisms in `internal/conversations` that previously didn't know about each other: the destructive auto-archive sweep (`ShouldArchive` + `Sweep`, #219/#237/#242/#243 — hard-deletes unpromoted rows idle ≥30 days) and the recoverable manual soft-archive (`Conversation.IsArchived` + `Registry.SetArchived`, #880/#881). Before this ticket, a user who archived a conversation to keep it could lose it permanently 30 days after its last *activity* — `SetArchived` never bumps `LastUsedAt`, so archiving an already-idle row bought as little as one extra day. The reconciliation had been deferred in writing three times (`codebase/880.md`, `codebase/881.md`, `conversations-auto-archive.md` § Out of scope) with no tracking ticket until this one.

Decision encoded: **manual archive is durable until the user unarchives.** Auto-archive deletion now applies only to conversations the user has not archived; archived rows are retained indefinitely (unbounded registry growth is the accepted cost — see [conversations-auto-archive.md](../features/conversations-auto-archive.md) § Decisions).

## Implementation

- One new guard in `ShouldArchive` (`internal/conversations/archive.go`), placed after the existing `IsPromoted` short-circuit, as a **separate** `if c.IsArchived { return false }` block rather than folded into the first guard — keeps the `IsPromoted` line byte-identical and gives each guard its own one-line rationale comment and its own dedicated test row.
- `Sweep` needed no change — it delegates its entire decision to `ShouldArchive`, so there is no second decision site.
- Four comment sites updated to match the new predicate: `ShouldArchive`'s doc comment, `archiveIdleThreshold`'s doc comment, and `Conversation.IsArchived` / `Conversation.IsPromoted`'s field comments in `conversation.go`.
- `internal/sessions/pool_conv_sweep_test.go` (`TestPool_Run_RegistersSweepLoop_HappyPath`), the sole out-of-package caller of `ShouldArchive`, needed no edit — confirmed both by the architecture spec's blast-radius analysis and by code review: it seeds only non-archived rows.
- Two feature docs swept for every stale predicate/row-count/relationship claim: [`conversations-auto-archive.md`](../features/conversations-auto-archive.md) (six AC-listed sites plus a new § Decisions subsection recording the lifecycle rule) and [`conversations-registry.md`](../features/conversations-registry.md) (the `SetArchived` bullet and the § Related entry, both previously calling the sweep "unrelated"/independent).
- Full spec: [`docs/specs/architecture/1488-archived-rows-exempt-from-idle-sweep.md`](../../specs/architecture/1488-archived-rows-exempt-from-idle-sweep.md).

## Tests

- `TestShouldArchive` (`archive_test.go`) — new row `archived, very idle`: `IsPromoted: false`, `IsArchived: true`, `LastUsedAt: now-365d`, want `false`. `IsPromoted` must be `false`, or the pre-existing `IsPromoted` short-circuit absorbs the fixture and the row passes green even with the new guard deleted.
- `TestSweep` (`sweep_test.go`) — new row `archived-idle-row-survives`: two unpromoted rows both idle 31 days, one archived, one not; want count `1`. The count alone doesn't discriminate a correct guard from an *inverted* one (`if !c.IsArchived { return false }`) — both remove exactly one row. The row adds a `wantSurvivors []survivorSpec` identity assertion (keyed on the deterministic `/seed-<i>` `Cwd` the `mk` helper assigns) that pins *which* row survives; that's the only assertion the inverted-guard mutant fails.
- Both mutants (guard deleted, guard inverted) verified RED via `go test -overlay` before either row was called done — see code review's mutant table for both `TestShouldArchive` and `TestSweep`.

## Patterns established

- **Survivor-identity assertion, not just count, for exemption-style guards.** When a new predicate guard is tested by seeding one exempt + one non-exempt row with an otherwise-identical shape, the row count is blind to an inverted guard (wrong row survives, same count). Add an identity assertion on the survivor using whatever deterministic handle the test fixture already provides.
- **New guard rows must not be absorbed by an earlier short-circuit in the same function.** When adding a guard to a function that already short-circuits on another condition, the new test row has to be built so it reaches the new guard — set every earlier-guard field to the value that does *not* trigger it.

## Lessons learned

(From the PR's own "Lessons learned" section — both apply beyond this ticket.)

- A two-row fixture that differs only in the mutated field makes the count assertion blind: seeding one archived + one non-archived idle row means an inverted guard still deletes exactly one and still leaves a survivor the shipped predicate accepts, so `wantCount` and `len(List)` both stay green. Naming *which* row survived (here via the deterministic `/seed-<i>` `Cwd` the `mk` helper assigns) is the only assertion that discriminates. Worth checking, whenever a new row's expected count equals an existing row's, whether the count is doing any work at all.
- The exemption row's `IsPromoted: false` is load-bearing for the same reason: an earlier short-circuit in the same function will absorb a fixture and pass green with the new guard deleted. When adding a guard to a function that already has one, the new row has to be built to *reach* it.

## Code review

PASS, two non-blocking NITs, both doc-side:

- `conversations-auto-archive.md` § Decisions → *No zero-value `LastUsedAt` guard* stated a universal ("any unpromoted record older than 30 days archives") that was one conjunct short post-guard (an unpromoted **archived** row with a zero `LastUsedAt` now returns `false`). Fixed by this documentation pass — added the "non-archived" qualifier.
- `sweep_test.go`'s generic survivor diagnostic doesn't print `IsArchived`, so it no longer enumerates every field the predicate reads. Left as-is (test-code diagnostic, not a doc concern, and non-blocking).

## Out of scope (unchanged from spec)

The alternative fix direction — `Sweep` *sets* `IsArchived` instead of deleting, paired with a separate longer retention policy — remains a documented non-goal, not an unstated one. It changes what auto-archive means for every existing idle discussion and needs its own decision; see [conversations-auto-archive.md](../features/conversations-auto-archive.md) § Out of scope.
