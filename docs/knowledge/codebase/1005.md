# Ticket #1005 — e2e: `set_session_settings` over the v2 wire (persist + reply + reject-invalid)

Fake-daemon e2e for the `set_session_settings` v2 control verb, split from the
oversized four-verb #962 batch (the 2026-07-15 review gap). Test-only — no
production change — one new file, `internal/e2e/relay_v2_settings_test.go`
(`//go:build e2e`), `TestRelayV2_SetSessionSettings`. The production handler
(`handleSetSessionSettings`, `internal/relay/v2session.go:2745`) already
shipped in #845/#840/#833; this ticket proves its argv-injection defense end
to end over the encrypted wire, not just at the unit tier.

## Implementation

Confirms live, over one spawned daemon on one **interactive** conn, the path
the unit tier (`internal/sessions/pool_update_settings_restart_test.go`)
already proves deterministically: phone `set_session_settings{model, effort,
yolo}` → Noise decrypt → `dispatchAppFrame` → `handleSetSessionSettings` →
decode → `validModel`/`validEffort` (BEFORE persist) →
`SettingsUpdater.UpdateSettings` (atomic disk write) → reply
`session_settings_updated` correlated on `in_reply_to`. Unlike the
fire-and-forget verbs, this one is interactive-gated **request/reply**.

Two phases, one daemon, one conn (cheapest; strongest non-vacuity — the
invalid phase asserts against the *known* Phase-1 persisted state, not the
trivially-equal seeded default):

- **Phase 1 — valid (AC-1/AC-2):** sends `{Model: "opus", Effort: "high",
  YOLO: true}` for the pre-seeded bootstrap id, asserts the reply is
  `session_settings_updated` with `InReplyTo == reqID` and `SessionID` echoed,
  then polls `sessions.json` until the bootstrap row reads
  `opus/high/true` (matches `internal/sessions/registry.go`'s on-disk tags).
- **Phase 2 — invalid, table-driven (AC-3):** two cases, `model_argv_injection`
  (`Model: "--pyry-e2e-not-a-model"`) and `effort_out_of_set`
  (`Effort: "pyry-e2e-not-an-effort"`). Each asserts (a) `TypeError` /
  `protocol.CodeProtocolMalformed` / the literal fixed message
  `"malformed set_session_settings request"` (the constant is package-private
  to `internal/relay`, so the e2e pins the string, not the symbol); (b) disk
  still reads the Phase-1 values (a validator bypass would have written the
  sentinel); (c) the sentinel string appears in neither the reply frame/payload
  nor `h.Stderr.String()` (the daemon's captured logs).

### Non-vacuity is structural (the core of this ticket)

Both invalid values are well-formed JSON strings, so `json.Unmarshal` into
`*string` cannot fail — the decode step cannot be the rejector — and the conn
is interactive, so the capability gate cannot be the rejector either.
Therefore the rejection *must* originate at `validModel`/`validEffort`, the
argv-injection boundary. Phase 1 proves the same decode path admits a valid
model, so the divergence is provably at the validator. Two false-pass traps
called out explicitly (in code comments, not just the spec): a JSON *number*
for `model` would fail at decode (wrong stage, identical reply — false pass);
a shape-valid-but-out-of-set model like `"gpt-4"` would **pass** `validModel`
(a shape check, not an allowlist) and persist, failing the test outright
rather than false-passing. The developer's PR verified this directly by
bypassing `validModel` locally and confirming the reply flips from `TypeError`
to `session_settings_updated` — the mutation-testing check that the assertion
actually depends on the validator.

### `readSettingsReply`: drain-until-`InReplyTo`, not single-read

The Phase-1 `UpdateSettings` call fires a fire-and-forget bootstrap restart
(`#842`/ADR 031) that can emit an unsolicited `session_transition` (and,
on a stateful conn, `queue_state`/`modal_shown`) push with `InReplyTo == nil`
interleaved with the actual reply. Unlike the non-interactive promote/rename
e2e templates (single blocking read), `readSettingsReply` loops, decrypting
every frame it reads (keeping the Noise recv nonce aligned) and skipping any
frame whose `InReplyTo` doesn't match the request id, bounded by an overall
timeout. This is new relative to the promote/rename templates it otherwise
mirrors — worth knowing before copying this file as a template for another
async-side-effect verb.

### Local decode struct, not shared `registryEntry`

`restart_test.go`'s shared `registryEntry` lacks `Model`/`Effort`/`YOLO` and is
reused by other tests; per the spec, this ticket defines a local `settingsRow`
(mirroring `internal/sessions/registry.go`'s on-disk tags) instead of
extending the shared type — avoids a file-overlap/edit-collision risk on a
struct other tests depend on.

### Harness reuse

`StartRotationWithRelay(..., "PYRY_MOBILE_V2=1")` — the env var that wires the
v2 manager and therefore `SettingsUpdater` (`settingsUpdaterAdapter` over
`*sessions.Pool`, `cmd/pyry/relay.go:525`); without it the handler's nil-seam
guard replies `server.binary_offline`. No `PYRY_FAKE_CLAUDE_CLEAR_ROTATES` /
stdin-log machinery — this test never rotates. `driveHandshakeToOpenDaemonInteractive`
grants the interactive capability the handler requires and is what makes
Phase 2's non-vacuity hold (a non-interactive conn would short-circuit at the
capability gate instead of reaching the validators). `waitForBootstrapID`
before the first frame is the precondition that keeps `UpdateSettings` from
returning `ErrSessionNotFound`.

## Patterns established

None new — same "ride the frozen harness, add one local decode struct, don't
touch shared test types" discipline as #1003/#1004. The one reusable technique
worth naming for future request/reply verbs with an async side effect: a
drain-until-`InReplyTo` reply reader instead of a single blocking read,
whenever the handler's persist step can trigger an unsolicited push before the
correlated reply arrives.

## Testing

`make e2e` green under `-race` (~192s local run). Non-vacuity independently
mutation-verified: bypassing `validModel` flips the invalid-model case's reply
from `TypeError` to `session_settings_updated`, confirming the assertion is
load-bearing rather than incidentally green.
