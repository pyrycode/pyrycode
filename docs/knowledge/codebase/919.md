# Ticket #919 — wire `make e2e` into the `check` gate

`make check`'s prerequisite list grows a fifth leg: `check: vet test staticcheck
substrate-guard e2e`. The hermetic fake-daemon e2e suite (`internal/e2e`,
`-tags e2e -race -count=1`) now runs on every `make check`, so a core-daemon
regression fails the standard local gate instead of sitting red on `main`
unnoticed — the exact failure mode of [#918](918.md): eight #839-era
regressions accumulated silently because the suite ran in no standing gate.

Landed once its three native blockers closed: [#929](929.md), #930, and
[#257](257.md) (all #839-lineage e2e regressions). #870 (a documented flake in
the same suite) was flagged, not blocking, per the PO decision — confirmed
non-firing across repeated runs before this landed.

## Implementation

Makefile-only, no Go code:

- `check: vet test staticcheck substrate-guard` → `... substrate-guard e2e`.
  `e2e` appended last (not prepended) so the four fast legs still fail fast
  before the ~4-minute e2e leg runs.
- `preship: check e2e e2e-realclaude` → `preship: check e2e-realclaude` — the
  architect's call (delegated by the ticket): once `check` runs `e2e`, the
  explicit token in `preship` only double-ran the same ~4-minute hermetic
  suite for no added coverage. Per Evidence-Based Fix Selection, no defensive
  re-add "in case `check` drops it later" — that's an unobserved failure mode.
- Header comment block reworded at all three touched lines (`make check`,
  `make e2e`, `make preship`) to describe the new composition instead of the
  stale "not yet part of `check`" caveat.
- `CLAUDE.md`'s Build Commands section was confirmed to list raw `go`
  commands only (no gate enumeration) — left unchanged per the AC's
  conditional.

## Patterns established

- No new pattern. This is a gate-composition edit only; see
  [`features/e2e-harness.md`](../features/e2e-harness.md) § Build Gate for the
  evergreen description of what `make check` now runs and why the GitHub
  Actions matrix remains separately out of scope.

## Cost note

Every pipeline stage that runs `make check` (developer, code review, QA) now
pays the ~4-minute e2e leg — a ticket's wall-clock grows by roughly 8–12
minutes against the ~34 min/ticket average this repo was tracking at ticket
time. If that proves too heavy in practice, the documented fallback is running
`e2e` in one named pipeline stage instead of all of them — an evidence-based
call for later, not decided here.
