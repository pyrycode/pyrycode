# Ticket #1405 — Give the usage-limit event its v2 protocol shape

Wire-vocabulary-only ticket: declares `TypeRateLimited` and `RateLimitedPayload`, the v2 wire form of `turnevent.RateLimited` (#1404, merged as PR #1408), without wiring the mapping. `internal/turnbridge/outbound.go`'s `MapEvent` has no case for the variant — nothing emits this frame yet. Follows the background-task family's #1393/#1394 split rather than #1386's ship-together call. Split from #1264; #1406 (blocked-by this ticket) does the mapping and the live e2e. PR [#1409](https://github.com/pyrycode/pyrycode/pull/1409), code review **PASS** (two NITs, no MUST/SHOULD FIX).

## Implementation

- **New single-member const block in `internal/protocol/codes.go`**, after `TypeThinkingProgress`: `TypeRateLimited = "rate_limited"`. Own block rather than folded into an existing one — every block's doc comment hand-counts its members, and a new block costs nothing while an edit risks miscounting (#1393's stated reason, reused verbatim). The name is the daemon's own (`cmd/pyry/interactive_turn_v2.go`'s `eventKind` already returns `"rate_limited"` for this variant since #1404), not claude's `rate_limit_event` — `internal/protocol` cannot import `cmd/pyry`, so that agreement is prose in the doc comment, not a test.
- **`RateLimitedPayload`** appended to the end of `internal/protocol/interactive.go`: `ConversationID, Status, LimitType string; ResetsAt int64; TruncatedFields []string`, no `omitempty` anywhere (the file's standing doctrine), **no `MarshalJSON`**. Field order: `conversation_id` first (every payload in the family), then the three content fields in `turnevent.RateLimited`'s own declaration order, then `TruncatedFields` last.
  - `status` and `limit_type` are **forced** wire names, not chosen ones — `internal/streamsup/parser.go:1258-1259`'s two `bound()` calls construct the truncation report with exactly those literals, in that order. `resets_at` is free (an `int64` cannot be cut, so it never appears in the report) and is `ResetsAt`'s own name in snake_case.
  - `session_id` and `uuid` are absent for the family's #1380 precedent, structurally rather than by omission: neither ever enters `turnevent.RateLimited`'s decode target, so this payload cannot carry them even by accident. Same for the four `overage*` keys claude sends, two of which `#1404` found measured version-variable across the three captures on record.
  - `ResetsAt int64`, not `time.Time` — converting would invent a claim the bytes don't make. `Status`/`LimitType` plain `string`, not closed enums — the value set beyond the one measured-benign status is unmeasured.
- **No `MarshalJSON` nil-slice guard, deliberately.** The guard at `interactive.go:274-280` exists for `BackgroundTaskRosterPayload.Tasks`, where an empty roster is a meaningful positive statement and must serialise `[]`. `truncated_fields` is the opposite: `null` when nothing was cut is the correct wire value, and #1393's fixture lesson **inverts** here — the zero-value fixture (`rate_limited_zero.json`) actually reaches the nil path (`null` → nil → `null`), so no separate construct-and-marshal test is owed; the fixture itself is the enforcement mechanism. Confirmed by mutation (adding the guard turns `TestRateLimitedPayload_ZeroValue_RoundTrip` red).
- **Two fixtures** in `internal/protocol/testdata/`: `rate_limited.json` (populated; `status: "<unmeasured>"` — a value no capture on record carries, chosen so no client author could mistake a fixture value for a measured one, and its angle brackets double as the `encoding/json` HTML-escaping pin) and `rate_limited_zero.json` (every field at its zero value, pinning the no-`omitempty` rule and the `null`-not-`[]` truncation encoding).
- **Three new tests** in `internal/protocol/interactive_test.go`: `TestRateLimitedPayload_RoundTrip`, `TestRateLimitedPayload_ZeroValue_RoundTrip` (with byte-level guards that the fixture itself carries `"truncated_fields":null` and `"resets_at":0` rather than an elided key), and `TestRateLimitedType_IsNotClaudesVocabulary` (constant pin + payload-byte regression check against claude's key names and the excluded identity fields — modelled on `TestThinkingProgressType_IsNotClaudesSubtype`, but that sibling's exact substring check does **not** transfer: `strings.Contains("rate_limited", "rate_limit")` is true, so the discriminating word here is `"event"`, not `"rate_limit"`).
- **Registrations for `make check`**: three sites in `internal/protocol/compat_test.go` (rejection table, `v2OnlyTypes`, `TestTypeConstants_V1V2Partition`'s `all` list — deliberately **not** `TestInboundAppTypeSet_CoversAllExportedTypeConstants`'s v1-only `all` list, whose hard `len(all) == 23` a naive "append everywhere" edit would have broken) and `cmd/pyry/relay_guard_test.go`'s `excludedTypes["TypeRateLimited"] = "push"` — `TestEveryInboundV2TypeHasHandler` enumerates every `Type*` constant and fails the build on one it can't classify, mandatory from the moment the constant exists rather than from the moment #1406 emits it.
- **`docs/protocol-mobile.md`**, five edits + one deliberate non-edit, because #1406's Technical Notes disclaim the file — if the doc doesn't land here it lands nowhere (#1393 itself never touched this doc; that was #1394):
  1. Frame table row after `thinking_progress`, `**New in v2** (interactive, capability-gated)`.

  3. New `#### rate_limited` section (field table, not-emitted-yet note, why the gate is loud, the `status`-is-open-and-unmeasured client rule, the `resets_at`-is-claude's-number-unvalidated-both-directions hazard, `truncated_fields` load-bearing, SECURITY paragraph).

  5. Changelog entry dated 2026-08-09, recording both stale-count corrections.
  - **Non-edit**: `:651`'s "four `system` subtypes" stays four — `rate_limit_event` is a top-level line type, not a `system` subtype (the whole point of #1404), so it doesn't belong to that count. One clause added to the adjacent "known and deliberately ignored" bullet noting `rate_limit_event` now maps to `turnevent.RateLimited` and reaches the wire as `rate_limited`, without touching its true "never produces `unrecognized_message`" claim.

## Patterns established

- **A copied negative pin can invert on the new value — check before reuse.** `TestThinkingProgressType_IsNotClaudesSubtype`'s exact form (`!strings.Contains(name, "rate_limit")`) would have been red against the *correct* new constant, because `"rate_limited"` contains `"rate_limit"`. The lesson generalizes beyond this ticket: evaluate a copied exclusion predicate against the new value before specifying or writing it, not just against the old one it was lifted from.
- **A fixture-lesson can invert between siblings, and that inversion is itself worth stating rather than re-deriving.** #1393's empty-roster fixture *couldn't* reach the nil-`Tasks` path (unmarshalling `[]` always yields non-nil), forcing a separate construct-and-marshal test. #1405's zero-value fixture *does* reach the nil-`TruncatedFields` path (unmarshalling `null` yields nil), so the fixture alone is sufficient enforcement. Both are correct; neither generalises to the other without checking which direction the JSON/Go zero-value asymmetry runs for the specific field.
- **A wire-vocabulary-only ticket that owns `docs/protocol-mobile.md` disturbs count literals in more than one place** — the frame-table intro count and the next terminal-marker section's count are two independent copies of the same number, and both #1394 (thirteen→wrong) and #1386 (twelve→wrong) had already had to correct exactly these two before #1405 made it three-for-three. It is now an observed-failure pattern, not a hypothetical one, worth a standing check on any new interactive-stream frame.

## Lessons learned

From the PR body's own "Lessons learned" section (developer, verbatim) and the code-review comment:

- **A sibling's negative pin can invert on the new value.** `TestThinkingProgressType_IsNotClaudesSubtype`'s form does not transfer: `strings.Contains("rate_limited", "rate_limit")` is **true**, so the obvious copy — excluding claude's line-type prefix — would be red against the correct name. The discriminating word here is `event` (claude's, describing its line), not `rate_limit`.
- **#1393's fixture lesson inverts here, and that is what makes the second fixture the enforcement mechanism.** There, the empty-roster fixture could not reach the nil-`Tasks` path, so a separate construct-and-marshal test was owed. Here the zero-value fixture reaches exactly the path that matters (`null` → nil → `null`), so a `MarshalJSON` guard diverges the round-trip bytes and goes red — no extra test is owed; the fixture *is* the pin. Verified by mutation, not assumed.
- **The two `truncated_fields` members are wire names forced by the producer**, not a naming choice — `internal/streamsup/parser.go`'s two `bound()` calls literally name them `"status"` and `"limit_type"`. The round-trip test joins the slice rather than set-comparing it, so the producer's declaration order is pinned too.
- Code review ran eleven mutants via `go test -overlay` (no worktree writes) — every `omitempty` on all five fields, the forbidden `MarshalJSON` guard, a claude-vocabulary retag, both drift-detector removals, and the inbound-leak case — all RED against the expected test, confirming the test set discriminates rather than merely exists. `TestInboundAppTypeSet_CoversAllExportedTypeConstants`'s trap (`len(all) == 23`) was confirmed untouched.
- Two NITs landed unfixed, both cosmetic: an orphaned line-wrap in the inserted `docs/protocol-mobile.md` clause, and a redundant-but-harmless `"resets_at":0` fixture guard already subsumed by the round-trip's canonical-bytes comparison (kept because it makes AC4's "explicit 0, not elided" locally readable at the assertion site).
