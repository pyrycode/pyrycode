# Ticket #1320 — Probe instrument: `finTrailerBuild` takes the sighting carrier in place of the observation (offline)

Moves `finTrailerBuild`'s input from `trailObservation` (which embeds
`trailScanResult`, so `.Line` — verbatim, OPERATOR-REVIEW-BEFORE-PASTE model
output — and the `*resultTrailer` pointer are both in reach) onto `finSighting`
(#1309), the carrier `finGatherReadings` fills from the same poll that feeds
the run's outcome classification but had never handed anywhere. Before this
ticket the live composition had no way to build the published record from the
sighting it actually classified against; the workaround was a second
`trailWaitForTrailer`, which matches on its first poll over an already-filled
buffer and reports `trailBoundFromStart` — a discriminator whose own doc says
it bounds nothing — so a record built that way would understate exactly the
evidence the artifact exists to carry. Split from #1315 (itself split from
#1308). Sibling ticket #1321 retires the four rows this ticket only migrates
and marks.

## Implementation

- **Signature**: `func finTrailerBuild(outcome string, sighting finSighting) finTrailerRecord`.
  `trailObservation` disappears from the builder and from every fixture in
  the package — no test in these three files constructs one for the builder
  again. `Bounded` keeps its single source, `sighting.BoundFrom ==
  trailBoundFromMiss`, unchanged from before.
- **The guard**: `if !sighting.CarriesTrailer { ...zero the four, return... }`
  replaces `obs.State == trailSeen && obs.Trailer != nil` — the operand pair
  is unrecomputable from the carrier by design, since `CarriesTrailer`
  precomputes it one tier up (at the gather's fill, and now also at the
  fixture helper below) specifically so no pointer needs to survive into the
  builder's reach. On the false arm the four scalars are still zeroed rather
  than copied through, and under the carrier that stopped being a
  by-construction consequence: the scalars are separately settable now, so
  `CarriesTrailer: false` beside non-zero scalars is reachable for the first
  time, and it is the only input shape that separates a builder that drops
  from one that copies through. The argument for the drop lives in the arm's
  own `Detail`, which formats "the four trailer fields hold their zero
  values" — a builder that copied them through would contradict its own
  published Detail in the same breath.
- **`finTrailerSighting(scan trailScanResult, staleness time.Duration, boundFrom string) finSighting`**,
  new fixture-side helper, immediately after `finTrailerSeenScan`/
  `AbsentScan`/`AbortedScan`. It is a copy of `finGatherReadings`' carrier
  fill (`finding_run_gather_test.go:442-453`): same `State`-operand-first
  pair, same four scalars filled only behind it. All nine call sites migrate
  through it (six in `finding_trailer_evidence_test.go`, two in
  `finding_run_record_test.go`, one in `finding_artifact_write_test.go`) —
  each site's `trailObservation{...}` literal becomes one
  `finTrailerSighting(...)` call, taking the shipped `trailScanResult` the
  site already had rather than a hand-filled observation.
- **A function, not a package-level var**, for the same reason
  `trail_run_outcome_test.go:608-610` gives: a shared backing value would be
  reachable from every test in the package under `go test -race`'s parallel
  execution.
- **The developer deviated from the spec's suggested true-arm fixture, and
  argued it in place.** The architecture doc suggested `finTrailerSeenScan()`
  for the new both-arms test; the developer used `trailScan(trailPaddedTrailer(0))`
  instead, because `finTrailerSeenScan()` wraps `trailFixtureTrailer`, which
  renders `"is_error":false` — a zero value. Against it the false arm's
  `is_error` check would compare `false` to `false` and pass on a builder
  that copied the field through, and the test's own "all four scalars
  non-zero" precondition couldn't hold. `trailPaddedTrailer(0)` renders
  `error_max_turns` / `true` / `max_turns` / `end_turn` — all four non-zero,
  still a shipped scan in the file's idiom. Code review confirmed by mutation
  that `is_error` is among the fields the always-copy mutation catches.
- **The agreement obligation moved, and is held by comment plus review, not
  by an in-file pin.** `finGatherReadings`' fill is commented "deliberately
  identical to `finTrailerBuild`'s guard, because the two computations must
  agree." After this ticket the builder computes nothing, so that obligation
  now sits on `finTrailerSighting`, whose doc states it and cites the
  gather's fill by symbol. No deterministic pin is possible inside this file
  — `finGatherReadings` reaches `ps` via `pinScanArgv`/`pinReadState`, and
  this file forbids the process-table read that reaches it. Code review
  performed the field-for-field comparison by hand as the discharge of that
  obligation (state, bound-from, staleness, the operand-order pair, the four
  scalars filled only behind it — a faithful copy) and reported it as work
  done rather than a missing pin.
- **A fifth doc block went false beyond the spec's named four**, and the
  developer found it: the file header's "this record reads the four fields
  from the observation directly, under a guard whose FIRST operand is the
  State" (`:23-25`). The spec's AC5 said "four are known" without claiming
  the list was exhaustive — this one wasn't in its table. Re-stated in the
  same diff.
- **Four rows lose their claim and are migrated-but-marked, not retired**
  (that argument is #1321's): `TestFinTrailerRecordCarriesNoCapturedBytes`
  and #1286's Plant #3 (`finding_artifact_write_test.go:278`) both plant
  `trailNeedle` in a `.Line` the input no longer has; the "returns rather
  than panicking" subtest's panic claim is structurally unreachable with no
  pointer to deref; the "survives a cap" subtest's claim ("reads Trailer not
  Line") is dead because the builder reads neither — #1313 already shipped
  that claim one tier down. Each is marked `SUPERSEDED BY #1320, RETIRED BY
  #1321 — NOT A LIVE GUARD` rather than rewritten, per the spec's explicit
  "mark, do not rewrite" instruction.

## Tests

- **`TestFinTrailerRecordFillsTheFourScalarsOnlyBehindCarriesTrailer`**, new,
  top-level (not a row on the existing bound table) — drives the guard in
  both directions over one carrier and one flipped bit, closing a hole no
  existing row closed: before this ticket only two rows (both marked for
  #1321's retirement) exercised the always-zero mutation, and nothing in
  this file exercised the always-copy one.
  - Non-vacuity precondition asserted first and fatal:
    `seen.CarriesTrailer` true and all four scalars non-zero, or a broken
    helper would leave both arms comparing zero against zero.
  - The false arm's carrier (`dropped`) is *derived* from the true arm by
    flipping the single impossible bit (`dropped := seen; dropped.CarriesTrailer
    = false`), not typed in — a stronger reading of AC3's no-literal rule:
    everything a scan could produce still comes from the scan, and the two
    carriers differ in exactly one field, so nothing else can explain a
    difference between the two built records. Named `synthetic`, in the
    register the file already uses for the aborted row's contract-check
    string — this pairing is one no scan produces.
  - True arm asserts all four scalars cross; false arm asserts all four are
    zero and that `State`/`BoundFrom`/`Staleness`/`Bounded` still cross
    regardless — the void publishes under whatever state was handed rather
    than collapsing into "there was no trailer." A final check asserts the
    two Details differ (branch fired), deliberately not string-matching
    either one.
- **Existing tests** (`TestFinTrailerRecordCarriesTheBoundAndItsDiscriminator`,
  `...OutcomeIsConsumedAsHanded`, `...ReadsTheDecodedTrailer`,
  `...CarriesNoCapturedBytes`) all migrate their `trailObservation` literals
  to `finTrailerSighting(...)` calls with zero assertions, rows, or coverage
  loops dropped — confirmed by code review's row-by-row pass.
- **Downstream, unchanged**: `finRecordSeenTrailer`/`finRecordAbsentTrailer`
  (`finding_run_record_test.go`) and the trailer sub-record inside
  `finWriteInputs` (`finding_artifact_write_test.go`) migrate their call
  sites the same way; `TestFinWriteArtifactPublishesNoVerbatimModelOutput`
  (the surviving true-arm pin one tier up) stayed green unchanged, confirming
  the helper doesn't drop a scalar the gather would have carried.

## Patterns established

- **A guard moving from a computed boolean expression to a precomputed field
  on the input turns what was "by construction" into "a decision", and the
  new reachable input shape needs its own pin.** Here: `CarriesTrailer:
  false` beside non-zero scalars was unconstructible under `trailObservation`
  (no pointer meant no scalars to set) and became constructible under
  `finSighting` (the scalars are independently settable fields). The fix
  pattern — derive the synthetic row from the true arm by flipping exactly
  the one bit that's now reachable, rather than typing in a literal — is a
  stronger form of a project's existing "no hand-built fixture" rule and is
  reusable anywhere a type-narrowing makes a previously-impossible field
  combination reachable.
- **An agreement obligation between a fixture helper and the live path it
  stands in for, with no in-file deterministic pin available, is discharged
  by a named comment plus an explicit code-review field-for-field check —
  and the review should report doing that check, not just note the pin is
  missing.** Precedent for any future ticket adding a fixture-side stand-in
  for a composition step that reaches outside the test binary (here: `ps`
  via `pinScanArgv`/`pinReadState`).

## Lessons learned

(From the PR body and code review; see PR #1322.)

- **When a spec names both a suggested fixture and a "must be non-zero"
  precondition for a new test, check the fixture's actual field values
  against the precondition before writing the row — the precondition is the
  load-bearing half.** The spec suggested `finTrailerSeenScan()`, which
  renders `is_error: false` — a zero value that would have made a quarter of
  the true/false contrast vacuous (the false arm's `is_error` check would
  compare `false` to `false` and pass against a builder that copied the
  field through) and made the spec's own non-vacuity precondition
  unsatisfiable. The developer caught this and swapped to
  `trailScan(trailPaddedTrailer(0))`, whose four decoded fields are all
  non-zero; code review independently confirmed via the always-copy mutation
  that `is_error` is among the fields the swap makes catchable.
- **A ticket's own AC list can say "N are known" without claiming the list is
  exhaustive — check the surrounding prose for a doc claim the AC's own table
  missed.** AC5 named four doc blocks; a fifth (the file header,
  `:23-25`) also became false the moment the builder's input changed, and the
  developer found and re-stated it in the same diff rather than treating the
  AC's table as a closed set.
- **When a fixture-vs-live-path agreement obligation has no deterministic pin
  available (the live path execs and the test file forbids exec), the review
  step is the field-for-field comparison itself, performed and reported —
  not a note that "no pin exists."** Code review here explicitly walked
  `finTrailerSighting` against `finGatherReadings`' fill field by field and
  reported the match, rather than flagging the absence of a pin as a gap —
  worth recognizing on sight in future reviews rather than re-litigating each
  time a spec rules a property "held by comment and review."
