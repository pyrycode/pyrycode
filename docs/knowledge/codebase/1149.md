# Ticket #1149 — Family A (delivery-confirm resolver) migrated onto `internal/transcript`

Split from #973. Rewrites `newProbePreferredTranscriptResolver` and `newTranscriptResolver` in `internal/sessions/reconcile.go` — the inbound delivery-confirm growth-baseline resolver family (#838) — as thin adapters over the `internal/transcript` leaf (#1148). Mirrors the shape Family B (#1150) landed with, composed in Family A's own dispatch order and load-bearing `("", 0, nil)` no-baseline convention. Pure adapter swap behind the same `supervisor.Config.ResolveTranscript` signature: no consumer cascade, net deletion (227 insertions, 261 deletions across `reconcile.go`, `reconcile_test.go`, `pool.go`).

## Implementation

PR #1157, three files.

- Deleted the local `jsonlExt` const, `uuidStemPattern` regexp, and `mostRecentJSONL` — replaced by `transcript.Ext`, `transcript.ValidStem`, and `transcript.Newest`. `strings` import dropped (its only uses were both deleted).
- `newTranscriptResolver` now calls `transcript.Newest(dir)` directly and returns `(res.Path, res.Size, nil)` — the zero `Result` naturally yields `("", 0, nil)`.
- `newProbePreferredTranscriptResolver`'s pinned-id path: `transcript.ValidStem(id)` pre-check (the branch selector — routes a valid stem to `StatByID`, an empty/invalid one falls through to the probe) + `transcript.StatByID(dir, id)`, mapping its error to `("", 0, nil)` without falling through to the probe.
- Its probe path: `canonicalDir := transcript.CanonicalDir(dir)` computed once at construction, then per-resolve `res, _ := transcript.Probed(dir, canonicalDir, probe, pidFn())` — the `res, _` **swallows** `Probed`'s one surfaced error (a failing `probe.OpenJSONL`), collapsing it into the same `("", 0, nil)` sentinel. This is the convention inversion vs. Family B, which wraps that same error for its retry-on-error subscriber.
- The no-lsof AC5 branch (`!probeUsable(probe)` → delegate to `newTranscriptResolver(dir)`) is untouched — still the only returned closure that may emit a non-nil error, because it *is* today's newest-by-mtime behaviour.
- `probeUsable` / `availabilityReporter` stayed local (mirrors Family B's retained `bootstrapProbeUsable`) — probe-capability detection and the no-lsof→mtime delegation are Family A composition policy, not core resolution logic (#1148 kept `transcript.Probe` deliberately single-method).
- `pool.go`: comment-only trim at the `New` bootstrap block — no longer names the deleted `mostRecentJSONL`.

**One intentional micro-behaviour delta, in the safe direction** (per spec, confirmed in review): the old `newTranscriptResolver` stat'd twice (once inside the scan, once for size), so a file vanishing between scan and re-stat surfaced as a non-nil error. `transcript.Newest` stats once and returns Path+Size together, so that vanish-in-the-gap race now returns the already-captured size instead of an error — no test exercised the old error, the caller tolerates both as "no growth," and it's one fewer stat + one fewer TOCTOU window. Selection semantics (which file, which size) are unchanged, so AC5's byte-identity claim holds.

## Patterns established

- **The pinned-id `ValidStem` pre-check is the branch selector, not redundant with the primitive's own validation** — same pattern as Family B's `resolveBoundSessionJSONL` (#1150). A valid stem must route to `StatByID` (a miss there is no-baseline, no probe); an empty/invalid stem must fall through to the probe. `StatByID` alone can't distinguish "invalid stem" from "valid-but-missing" for that routing decision, so the caller-side pre-check carries meaning the primitive's internal check doesn't expose.
- **Composing `transcript.Probed` (the higher-level collapsed primitive) is correct here specifically because Family A carries no cold/warm state to protect** — contrast Family B (#1150), which composes `GuardProbedPath` directly instead of `Probed` because its `sawEmpty` bookkeeping is keyed per-branch in a way `Probed`'s single collapsed `(Result{}, nil)` would erase. Same leaf, two different composition choices, both correct for their caller's state shape.

## Lessons learned

None beyond what the spec and code review already anticipated (see #1148's noted NITs, both confirmed handled here: the single-stat behaviour delta, and preserving the pinned-id probe fall-through that `StatByID`'s own error doesn't give you for free).
