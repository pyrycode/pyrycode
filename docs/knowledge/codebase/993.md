# Ticket #993 — e2e: untrusted-cwd trust prompt forwards, accepts to run the turn, denies to a typed error

Split from [#992](992.md). Live end-to-end capstone certifying the #988 no-auto-trust consent gate over the v2 Noise wire, riding the shipped [#1013](1013.md) (hold-while-pending) and [#1014](1014.md) (give-up exemption + typed `"folder not trusted"` error) seams. It rides those seams and introduces no production behaviour — the only non-test code is a `fakeclaude` startup trust-dialog simulation used solely by this test, so #988's wedge (an untrusted cwd never auto-trusts, a queued turn never types into the consent gate) can never silently regress.

## Implementation

One production-adjacent file (a test-only harness binary) plus two test files:

- `internal/e2e/internal/fakeclaude/main.go` — new env-gated simulation behind `PYRY_FAKE_CLAUDE_TRUST_TRIGGER`, additive and byte-identical when unset (every new gate is `if <existing> || trustTrig != ""`, mirroring the sibling `PYRY_FAKE_CLAUDE_MODAL_TRIGGER` permission machinery):
  - `trustScreen` — a startup dialog satisfying `tuidriver.gridHasTrustDialog` (`"Quick safety check:"` header + a `❯`-marked numbered option row within 3 rows). This single screen shape drives **both** `WaitReady` → `Readiness.TrustModal` (the supervisor-side hold, #1013) **and** `DetectModalClass` → `ModalClassTrustFolder` (the producer surfacing `modal_shown{Class:"trust"}`) — one fixture, two consumers.
  - `trustClearScreen` — scrolls the header off the **whole** rendered grid (trust detection scans every row via `NewGrid`, unlike the permission modal's bottom-12-row window), with a trailing idle glyph as the non-blank last row so `IsIdle` goes true post-clear and the held turn can deliver. `trustClearScrollRows = 40` (full `DefaultPtyRows`), pinned by the untagged de-risk test below — a mis-sized scroll or a missing trailing glyph fails there in milliseconds rather than inside a slow live e2e.
  - **Accept-vs-deny discrimination (load-bearing).** The stdin reader signals a new `trustAcceptPending atomic.Bool` on any post-trust-modal keystroke that is **not** a bare ESC (reusing `containsBareESC`); the main poll goroutine clears the dialog only on that signal. `AcceptTrust()`'s `"1\r"` clears it (turn delivers); `SendEsc()`'s bare `0x1b` deny leaves the dialog up (turn stays held forever, no reply). This preserves the existing single-writer invariant — the reader only signals via `atomic.Bool`, the main goroutine remains the sole writer of `f`/stdout.
- `internal/e2e/relay_v2_trust_test.go` (`//go:build e2e`) — `bringUpTrustModalHarness`, copied from `relay_v2_modal_answer_test.go`'s `bringUpModalHarness` with two deltas: forwards `PYRY_FAKE_CLAUDE_TRUST_TRIGGER` via `StartRotationWithRelay`'s `extraEnv`, and seeds the conversation via `seedBoundConversation` before daemon start (AC-1's untrusted-cwd conversation). Two test bodies:
  - `TestRelayV2_UntrustedCwdTrustAccepted` (AC-1, AC-2, AC-3): `awaitTrustModalShown` reads `TypeModalShown{Class:"trust", Options:[proceed,exit]}` off the wire non-vacuously; `send_message`s the queued turn; asserts a **held-fence** (the turn marker absent from the stdin log while pending — proves the hold is real, not merely not-yet-delivered); answers `proceed` → `AcceptTrust` → `"1\r"` → fakeclaude clears → turn delivers + commits; drains `queue_state` to empty then asserts the turn marker now present in the stdin log.
  - `TestRelayV2_UntrustedCwdTrustDenied` (AC-1, AC-2, AC-4): same bring-up + held-fence; answers `exit` → `SendEsc` → bare ESC (dialog stays up) + `emitFolderNotTrusted` → `session_error`. Asserts `TypeSessionError{Code: CodeSessionBlocked, Message: "folder not trusted"}` off the wire (the **terminal** code, not the transient `server.binary_busy`); asserts the deny ESC reached the stdin log **before** asserting the turn marker never appears (a positive gates the negative, so "no delivery" isn't vacuously true because nothing happened); asserts `queue_state` stays non-empty (never drains).
  - Deny-by-**answer** is the only path exercised; deny-**on-timeout** (the ~2-min `modalDenyTimeout`) is deferred — already unit-covered by #1014's `modal_resolve_v2_test.go` and e2e-covered generically by `TestRelayV2_RemotePermissionDeniedOnTimeout`.
- `internal/e2e/internal/fakeclaude/trust_detect_test.go` (untagged, mirrors `modal_detect_test.go`) — fast fixture de-risk: `trustScreen` → `DetectModalClass == ModalClassTrustFolder` and `HasTrustModal == true`; `trustScreen + trustClearScreen` → both false/not-trust. Runs in ms, catches a mis-detecting fixture before the slow live e2e does.

## Patterns established

- **One fixture, two consumers.** `trustScreen`'s single screen shape is deliberately the exact input both `tuidriver.Readiness.TrustModal` (supervisor hold) and `DetectModalClass` (producer surface) key off — there's no separate "hold" fixture and "surface" fixture, because in production it's the same claude screen driving both code paths. Testing them against one fixture is what makes the capstone actually exercise the real coupling instead of two independently-plausible mocks.
- **Load-bearing behaviour must be mutation-falsifiable, not just asserted.** The accept/deny discrimination was verified by deliberately breaking it (clearing on ESC too) and confirming the test fails at "the denied turn ran (AC-4 violated)" rather than trusting the assertion shape alone. Per [[po-fairness-refactor-earns-sec-via-nonce-single-writer]]-style discipline: a security-sensitive non-vacuity claim earns real confidence only when the failure mode has been produced and observed, not inferred.
- **Whole-grid vs. windowed scan asymmetry is a real fixture hazard.** The permission modal's clear-scroll count (`modalClearScrollRows = 16`) is *not* transferable to the trust fixture — trust detection scans the full rendered grid (`NewGrid`), not the permission modal's bottom-12-row window, so a naive copy-paste of the permission clear machinery would under-scroll and leave `HasTrustModal` true. The untagged de-risk test is what catches this class of error cheaply; per [[architect-live-capstone-verify-producer-is-wired]]-style pre-verification, fixture shape assumptions for a live capstone should be pinned by a fast test, not asserted only in the slow e2e.

## Testing
