# Ticket #865 — session verbs lose their response after 5s: extend the conn write deadline before the long op

`pyry sessions new` / `pyry sessions rm` reported failure for a mutation that had actually succeeded. The control server's per-conn `handle` sets a 5s handshake deadline on every conn; `handleSessionsNew`/`handleSessionsRm` widened only an *internal* 30s ctx for `Pool.Create`/`Pool.Remove` and never touched that conn deadline. Once the op ran past 5s (routine on a cold claude spawn — documented 2-15s latency), the final `enc.Encode(Response{...})` failed with a silently-discarded deadline error and the client's read got EOF — an operator-visible orphan on `sessions.new`, a false failure on `sessions.rm`. `handleAttach` already avoided this by resetting its conn deadline before its long-running stream; the two session handlers didn't because they only received the encoder, not the conn. See [`control-plane.md` § Handshake Deadline](../features/control-plane.md#handshake-deadline-per-conn-timeout-and-the-session-verb-extend-865).

## Implementation

Confined to `internal/control/server.go`, package-internal only — no wire-shape change, no client change (the client already sent a 30s ctx; confirmed server-only).

- **Threaded `conn` into both handlers**, mirroring `handleAttach`'s shape: `handleSessionsNew(conn net.Conn, enc *json.Encoder, payload *SessionsPayload)` / `handleSessionsRm(conn net.Conn, enc *json.Encoder, payload *SessionsPayload)`. The two `handle` call sites (`VerbSessionsNew`/`VerbSessionsRm`) now pass `conn`.
- **Extend, don't clear.** Immediately before `s.sessioner.Create`/`Remove`, each handler does `conn.SetDeadline(time.Now().Add(sessionOpTimeout + sessionOpConnGrace))` (30s + 5s = 35s) — best-effort (`_ =`), matching `handleAttach`'s posture. `handleAttach` clears its deadline entirely (`time.Time{}`) because its stream is indefinite; a one-shot session verb has a bounded op, so it gets a bounded deadline strictly greater than the op ctx rather than no deadline at all — a genuinely stuck write still has an upper bound.
- **Two new package consts** replace the duplicated `30*time.Second` literal and name the invariant: `sessionOpTimeout = 30 * time.Second` (the handler ctx budget, unchanged value) and `sessionOpConnGrace = 5 * time.Second` (the margin the conn deadline sits above it, so the ctx — not the conn — is the binding budget on the normal path).
- **`handshakeTimeout` became an injectable per-`Server` field.** The former `const handshakeTimeout = 5 * time.Second` is renamed `defaultHandshakeTimeout`; `Server` gained an unexported `handshakeTimeout time.Duration` field that `NewServer` defaults to it, and `handle` now reads `s.handshakeTimeout` instead of the const. This is a test seam, not a behavior change — production callers of `NewServer` are unaffected. Same-package tests set the field directly before `Serve` starts (no exported setter; the field is write-once-then-read-only-per-conn, so no lock needed — same post-construction-override shape as `SetRekeyer`). Without this seam, a non-vacuous regression test would need the op to outlast the *production* 5s handshake, costing ~15s of wall-clock across the three ACs.
- Updated `handleSessionsNew`'s doc comment, which pre-fix explicitly claimed "reusing the conn's handshake deadline would race the 5s handshake timer" — that reasoning is now stale (the fix does reuse and extend the same conn deadline) and was rewritten to describe the extend.

## Testing

New file `internal/control/sessions_deadline_test.go`, three `t.Parallel()` tests, each dialling through the real client helpers (`SessionsNew`/`SessionsRm`) rather than calling the handlers directly:

- `TestServer_SessionsNew_OpOutlastsHandshake` / `TestServer_SessionsRm_OpOutlastsHandshake` (AC1/AC2) — server started with `handshakeTimeout=200ms`, `fakeSessioner{opDelay: 500ms}`. Non-vacuous: on pre-fix code the response write dies at 200ms and the client sees EOF/error; post-fix it reliably arrives (500ms op ≪ 35s extended deadline). Confirmed failing without the extend before landing the fix.
- `TestServer_SessionsVerbs_SlowClientStillTimedOut` (AC3) — dials a raw conn, sends nothing, and asserts the read returns promptly (not blocked to a 10s client-side read deadline) and is not a successful response. This is a *preservation* guard, not a regression guard — it passes on both fixed and unfixed code, since AC3's contract was never broken. Its non-vacuity instead comes from timing: the client read deadline is set strictly between the shrunk handshake (200ms) and the op budget (30s), so a prompt server-side EOF proves the handshake bound survived; only a regression that moved the extend *before* the request decode would let the read block out to the client deadline.
- `fakeSessioner` (`sessions_new_test.go`) gained `opDelay time.Duration`, slept at the top of `Create`/`Remove` when >0. `startServerWithSessioner` was split into a thin delegate over a new `startServerWithSessionerHandshake(t, resolver, sessioner, handshake)`, which sets `srv.handshakeTimeout` when `handshake > 0`. Existing call sites (`startServerWithSessioner`) are unchanged.
- `attach_test.go`'s pre-existing `TestServer_HandshakeTimeout` was updated only for the const rename (`handshakeTimeout` → `defaultHandshakeTimeout`); it deliberately keeps exercising the real 5s production default rather than the field override, since it's the end-to-end guard for that value.

`go test -race ./...` and `go vet ./...` clean.

## Patterns established

- **Extend, don't clear, when the op is bounded.** `handleAttach`'s indefinite stream earns a cleared deadline; a one-shot verb with a known ctx budget should get a deadline strictly above that budget instead, so a stuck write still terminates. Reach for this shape any time a handler widens an internal ctx for a long op but writes its response over a conn carrying an unrelated, shorter deadline.
- **Injectable per-`Server` timeout field for fast, non-vacuous timing tests.** Same shape as `SetRekeyer`: an unexported field defaulted in `NewServer`, overridden directly by same-package tests before `Serve` launches, no exported setter, no lock (write-once-then-read-only). Reuse this pattern before reaching for a multi-second `time.Sleep` in a regression test for any other conn-deadline-shaped bug.
