# Ticket #1304 — Fill the staging record from the run's own transcript, guarded against the first-match defect

Adds `internal/e2e/realclaude/finding_staging_fill_test.go`, the `finTranscript*` composition
that fills three of `finOutcomeStaging`'s eight fields (`BashIssued`, `IssuedCommand`,
`TriggerFired`) from a run's own JSONL transcript. `finOutcomeStagingGate` (#1284) already
decided all seven staging outcomes from synthetic inputs; nothing yet filled the input from a
real transcript, and the fill is where a #1223 code-review SHOULD FIX — `probeWaitForBashToolUse`
returns the **first** Bash `tool_use` regardless of `input.command` — could quietly reappear.
Purely additive, one new file, 602 lines, zero production change, zero consumer call sites.

## Implementation

- **The scan's unit is a pair, not a bare command.** `finTranscriptBashCall{ToolUseID, Command}`
  carries the id and the command together because the trigger reading is keyed off the id
  (`probeWaitForToolResult(<id>)`). A composition that selected the staged call for its command
  but kept the first call's id would move the same first-match defect one step downstream — the
  record would then claim "the staged command's trigger fired" about the decoy's `tool_result`.
  #1230 guarded the value-side of this defect caller-side already
  (`background_reach_probe_test.go:439-448`); this ticket generalises the guard to cover both
  sides, still without editing the shared rig.
- **The content guard (`finTranscriptSelect`) is pure over its input** — no `*testing.T`, no file
  read. It returns the call whose command exactly equals the staged one (byte equality, the same
  rule the gate's identity arm applies), else the first call, `ok` false only for an empty slice.
  Purity is what let AC2's mutation (delete the match loop, always return `calls[0]`) be run and
  graded without touching the worktree.
- **One shared deadline covers both the shipped wait and the selection poll.**
  `finTranscriptSelectBash` first waits (via the shipped `probeWaitForBashToolUse`) for *any*
  Bash call to exist — that answers `BashIssued` — then polls `finTranscriptScanBash` +
  `finTranscriptSelect` to the *same* deadline until the selection's command matches staged. The
  poll is not redundant with the wait: the shipped waiter returns as soon as any Bash `tool_use`
  lands, and its envelope "lags the subprocess by a couple of seconds" live, so a single scan at
  that moment would answer on flush *order* rather than on content — a decoy that flushed first
  would produce `stage-command-not-staged` about a run that staged correctly, the same wrong
  verdict by a different route. Offline, the transcript file is complete before the call runs, so
  the loop returns on its first pass; the mechanism only matters for the ticket's live successor.
- **The first-match id is unreferenceable, not just unused, below the wait.** In
  `finTranscriptSelectBash`, the id `probeWaitForBashToolUse` returns is bound inside the `if`
  statement (`if id, _ := probeWaitForBashToolUse(...); id == ""`) and goes out of scope
  immediately after — there is no name for it in the rest of the function body. That scoping is
  the key-side guard made structural rather than a discipline to remember.
- **`TriggerFired` is read from `timedOutAfterMs` presence alone, and only for the selected call.**
  Two deliberate omissions, both load-bearing: the handle-present boolean is not conjoined (a
  conjunction would make the reading depend on a second field the gate never asked for), and
  `tool_use.input.run_in_background` is not consulted even though it is present in the fixture for
  row 4 — it corroborates the *model-set* backgrounding path (`docs/knowledge/codebase/1223.md:87-88`),
  which is the exact path this probe exists to exclude from an expiry-triggered `stage-trigger-
  did-not-fire` verdict.
- **Nothing on the path trims, unquotes, splits, shell-lexes, path-resolves or executes either
  command.** The bytes `encoding/json` decoded are the bytes returned. AC5's fixture command
  (`finTranscriptAwkwardCommand`) carries leading/trailing whitespace, embedded double quotes and
  a backslash, built via `json.Marshal` rather than string concatenation so a hand-escaped literal
  can't quietly be wrong and make the round-trip row prove nothing.
- **Every envelope projection is reused, never re-derived.** `parseContentBlocks`,
  `probeToolUseInput`, `reachToolUseCommand`, `reachBackgroundHandle`, and both shipped waiters
  are called as shipped. The ordered scan across multiple Bash calls in a transcript is the only
  new reading; two `tool_use` blocks on one assistant line are two scan entries, in block order,
  proving the scan is ordered *within* a line as well as across lines (row 4).
- **No json tags on either new type**, mirroring `finOutcomeStaging`'s own rule
  (`finding_staging_gate_test.go:141-157`) and citing it rather than restating the argument:
  `Command` / `IssuedCommand` are verbatim, unreviewed model output, and a tag is the first step
  toward publishing a captured string into a public GitHub issue.
- **Failure-message discipline extends to this file.** No assertion interpolates
  `IssuedCommand`, `StagedCommand`, or a `finTranscriptBashCall.Command` — mismatches report byte
  lengths only, plus the row name and the `tool_use` id (which is printable, unlike either
  command). Same tier `finOutcomeResult.Detail` is held to one layer up.

## Testing strategy

Two tests, both offline, neither skips:

- **`TestFinTranscriptSelect`** — five synthetic rows over the pure guard: empty slice (not ok);
  one non-matching call (still "issued"); decoy-then-staged (selects the second — AC2's row);
  staged-then-decoy (selects the first, proving the guard is content-keyed both directions);
  two non-matching calls (falls back to the first, deterministically).
- **`TestFinTranscriptFill`** — six rows driven end-to-end through a real JSONL written by
  `writeFixtureLines` at the session's own path (`WithWorktree` + `t.TempDir()` HOME), asserting
  both the raw reading (`BashIssued`, `IssuedCommand`) and the gate verdict reached from it. A
  coverage sweep asserts all four reachable staging outcomes were hit and none of the three
  caller-side outcomes (`stage-rendezvous-incomplete`, `stage-pin-scan-errored`,
  `stage-pin-count-unexpected`) appeared — since every row's caller-side fields come from
  `finTranscriptStagedCaller` unchanged, any of those three appearing would mean the fill wrote a
  field it does not own.
- **Two mutations run and their red recorded** (`go test -overlay=<json>`, no worktree write):
  M1 (AC2) deletes the match loop in `finTranscriptSelect` → row 1 and the select-test's
  decoy-then-staged row go RED with `stage-command-not-staged`. M2 (AC5) wraps the command
  projection in `strings.TrimSpace` → row 5 goes RED with `stage-command-not-staged`.
- `finTranscriptTestDeadline = 10ms` keeps a waiter-finds-nothing row to one 200ms
  `probePollInterval` sleep instead of the live 30s/45s constants.

## Patterns established

- **When a shared rig has a known first-match defect that a prior ticket guarded on one axis
  (value), check whether the guard's own return value re-exposes the defect on a second axis
  (key/id).** #1230 fixed the command; the trigger reading here is keyed off a *different* field
  (the `tool_use` id) off the same envelope, and a guard that only fixes the command silently
  re-introduces the defect one field over. Scope a "guard the first-match defect" task per field
  that a first-match return value feeds, not per call site.
- **Bind a value meant to be unusable inside the narrowest scope that makes it unreferenceable,
  not just unused.** `finTranscriptSelectBash`'s `if id, _ := ...; id == ""` pattern turns "don't
  use the first-match id below this point" from a review discipline into a compile-time fact.
- **A poll loop layered under a shipped waiter is justified only when the waiter's own return
  timing can beat the property being measured.** Here: the waiter returns on *any* Bash call, but
  the correct verdict depends on which call it was, and live envelopes flush with lag. The loop
  costs nothing offline (returns on the first pass) and closes a live race; document why the
  loop isn't dead weight rather than assuming a reviewer will infer it.
