# Ticket #1235 — Probe instrument: content-first pid pinning and a four-valued liveness read

Adds `internal/e2e/realclaude/process_pin_liveness_test.go` (`pin*` prefix), a
credential-free instrument #1236 → #1237 depend on for one reading: *at the instant pyry
wrote its trailer, was the backgrounded Bash command still running?* No production files,
no live claude turn, no verdict about pyry — it is depended on as code, not as evidence.
Blocked by, and reuses, #1230's `reachMatchArgvRows`.

## Implementation

- **Exclusion-aware argv scan, a pure post-filter (AC1/AC2).** `pinPartition` splits
  `reachMatchArgvRows`' own `(matches, total)` output by a caller-supplied `exclude
  map[int]string`; `pinMatchArgvExcluding` drives it over bytes for the table tests,
  `pinScanArgv` wraps the live `reachScanArgv` exec. No second matcher, no second exec —
  `reachMatchArgvRows` and its test (`TestReachMatchArgvRows`) are untouched. Every matched
  row is retained (`MatchCount` can be `> 1`, visible in the record rather than resolved to
  the first); an excluded pid is recorded in `pinExclusion{PID, Reason, Command, Needles}`
  only when its argv genuinely matched — an exclusion that fires on nothing produces no
  entry.
- **Four-valued per-pid state read (AC3).** `pinReadState(pid)` execs
  `ps -p <pid> -o pid=,ppid=,stat=` (`pinStateColumns`, no `-E`/`-e`-env/`eww` anywhere) and
  hands `(stdout, err)` to the pure `pinClassifyState`, which resolves to exactly one of
  `pinStateRunning` / `pinStateExitedNotReaped` / `pinStateNoSuchProcess` /
  `pinStateInstrumentFailed`. Branch order is the contract, checked in this sequence:
  `pid <= 0` (guard, no exec) → stderr non-empty → non-`*exec.ExitError` (timeout, binary
  missing) → stdout non-empty alongside an error (never parsed) → stderr-and-stdout both
  empty with an error (the **only** path to `no-such-process`) → exit-0 with no usable row
  → zombie (`pinIsZombie`, first-rune `== 'Z'`, not equality) → running. `pinStateOutcome`
  carries `StateColumn` in the record itself, not only in the classifier.
- **No descendant requirement.** `ps -p <pid>` is a direct lookup; a target re-parented to
  pid 1 reads exactly like any other pid (fixture: `PPID == 1`).
- **AC5 — additive only.** `probeProcessSnapshot`/`probeDescendantsFromPS` (base `probe*`
  rig) and `reachMatchArgvRows`/`TestReachMatchArgvRows` (#1230's `reach*`) are unedited.
  Verified against the diff: two new files (this test file + the architecture spec), zero
  modified.
- **AC4 — all 5 tests PASS, 0 SKIP with credentials unset**, reproduced independently by
  both QA and code review:
  `TestPinMatchArgvExcluding`, `TestPinScanArgv_ExcludesTheInstrumentsOwnProcess`,
  `TestPinClassifyState`, `TestPinStateColumns_ReadsNoEnvironment`,
  `TestPinReadState_FlipsAcrossOneProcessLifetime`.
- **The flip test proves the exec wiring, not just the classifier.** `TestPinReadState_FlipsAcrossOneProcessLifetime`
  runs one `sleep` child across one lifetime: `Start` → `running`, `Kill` without `Wait` →
  `exited-but-not-yet-reaped` with a `Z`-prefixed `StateColumn` (this is the arm an
  equality check against `"Z"` would miss silently), `Wait` → `no-such-process`. `t.Cleanup`
  registers a best-effort `Kill`+`Wait` immediately after `Start` so a `t.Fatalf` mid-test
  can't strand a live child.
- **Security (`security-sensitive`, earned by the environment-read prohibition).** The
  per-pid column set is a package-level constant (`pinStateColumns`) asserted on directly
  by `TestPinStateColumns_ReadsNoEnvironment` — a deterministic tripwire behind the
  doc-comment rule, not a promise. `ToolStderr`/`Detail` are capped via the existing
  `reachCapCommand`. The only non-constant exec argument is `strconv.Itoa(pid)`, guarded by
  `pid <= 0` before the exec so `-1` can never be read as a `ps` flag.

## Patterns established

- **A "not found" read that must discriminate "gone" from "instrument broke" needs the
  error's *stderr*, never its exit status.** `ps -p <dead-pid>` and a `ps` given a bad
  column or an illegal flag both exit 1 with `*exec.ExitError`; only stderr (empty vs.
  populated) tells them apart, and a bad column additionally emits a **keyword list on
  stdout** — parsing whatever stdout arrived alongside an error reads that list as process
  rows. Branch order that checks stdout and stderr before the "no such process" default is
  what makes this trap structurally unreachable rather than merely handled.
- **A `CommandContext` timeout is byte-identical to a dead pid on stdout, stderr, and error
  type** — only the *sign* of the exit status (a real exit vs. a `-1` from a signalled
  kill) distinguishes them, and a loaded machine is this family's expected condition, not
  its exotic one. This is the third distinct way this family (see also #1224, #1230) has
  produced an instrument failure indistinguishable from its own negative verdict, and the
  first found on the error *type* rather than the output.
- **A zombie's state column is not a fixed string.** darwin reads `ZN` (nice-adjusted) or
  bare `Z`; Linux emits `Z+`. First-rune (`state[0] == 'Z'`), not equality, is the only
  check that covers all observed shapes — an equality miss falls through to `running`
  silently, the one direction this instrument must never fail in.
- **`os.ProcessState`'s fields are unexported, so an exit status cannot be forged.** A
  synthetic `&exec.ExitError{Stderr: ...}` has `ExitCode() == -1`, landing on the signalled
  arm rather than the plain-exit-1 arm it was meant to test. Borrow a real `ProcessState`
  instead: `exec.Command("false").Run()` for a normal exit 1, a killed `sleep` for a
  signalled one — both POSIX-portable, neither needing a deliberately broken `ps`.
- **A record struct gaining a slice field breaks a self-scan test's count assertion.**
  Matching on the instrument's own binary path can hit more than one row (the invoking
  shell's argv carries the same path) — a live self-scan test must assert per-pid
  membership, never `len(Matches) == 1`, or the assertion tests the harness rather than the
  instrument.

## Lessons learned

From the PR body (#1248) and code review (PASS, 1 SHOULD FIX deferred to #1236, 3 NIT):

- The SHOULD FIX (`process_pin_liveness_test.go:603-613`) flagged a subtest whose comment
  claims `pinPartition` "must not alias or truncate the matcher's" slice, but whose
  assertion re-derives a fresh slice by calling `reachMatchArgvRows` a second time — so it
  actually tests the matcher's determinism, not that the partition left its input alone.
  The property holds today (`pinPartition` appends into a nil slice, provably fresh), so
  this is a guard-quality gap rather than a bug; not blocking, left for #1236 to fold in
  when it next touches this file.
- NITs (all cosmetic, none blocking): `PPID int \`json:"ppid,omitempty"\`` silently drops a
  legitimate `0` (only pid 1 has ppid 0, so nothing is lost today, but the record's whole
  thesis is that absence must not read as a value — `ExitStatus` deliberately has no
  `omitempty` for the same reason); the redaction-tripwire doc comment overclaims coverage
  if a future call site ever prepends a flag ahead of `pinStateArgs(pid)...`; branch 1's
  detail string says "wrote to stderr" even when the process was signalled rather than
  exited, the wrong verb in one arm (verdict is `instrument-failed` either way).
- A full-suite `make check -race` run surfaced an unrelated `TestConnected_FiresOnEveryConnect`
  (`internal/transport`) flake on the first pass. Triaged per the mandatory baseline
  procedure before being dismissed: clean at the merge-base, 5/5 pass in isolation with
  `-count=5`, clean on a full re-run — confirmed a one-off `-race` package-contention
  timing flake, not caused by this PR's diff (which touches only the new test file and its
  spec). Not routed as a regression.
- TOCTOU on pid reuse (kernel reassigns a pinned pid between the content match and the
  later liveness read, reading `running` for an unrelated process) is a known, deliberately
  deferred gap: no single-pid lookup can detect it, which is exactly why AC3 demands four
  values rather than a boolean. The mitigation — joining on the content match as well as
  the liveness read — belongs to #1236, and is named here so the constraint is inherited
  explicitly.
