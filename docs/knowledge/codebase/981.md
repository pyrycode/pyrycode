# Ticket #981 — e2e: `create_workspace_folder` over the v2 wire

The 2026-07-15 verb-coverage review (#960) found `create_workspace_folder`
(`internal/relay/handlers/create_workspace_folder.go`, #887) covered only by
handler unit tests plus the path-confinement helper test
(`cmd/pyry/create_workspace_folder_dir_test.go`) — no e2e at any tier. Split
from #961. Like `change_workspace` (#980), this verb is
**security-sensitive**: it **writes to the host filesystem** a directory
named by two untrusted fields, `parent` and `name`, supplied by a
network-paired party, and holds two independent, fail-closed,
belt-and-suspenders (different fabric) guards — confinement to `$HOME` and a
name-shape "directly under parent" check (see [codebase/887.md](887.md)).
This ticket proves both hold **over the actual wire** — fakephone →
fakerelay → spawned daemon, with the production `resolveWorkspaceFolder`
resolver wired at `cmd/pyry/relay.go:419` — closing the same gap shape #949,
#974–#976, and #980 closed for their verbs.

## Implementation

Test-only, one new file, no production code:

- `internal/e2e/relay_v2_create_workspace_folder_test.go` (new, 401 LOC,
  build tag `e2e`) — `TestRelayV2_CreateWorkspaceFolder` with three
  independent subtests, each owning its own pair → spawn → Noise_IK
  handshake (copied call-for-call from the merged #980 change_workspace
  test; no shared helper, per the spec's explicit instruction). Unlike
  #980, this verb touches **no conversations registry** — nothing is
  seeded, and every post-condition is a filesystem assertion under the
  daemon's temp `$HOME`:
  - `testV2DaemonCreateWorkspaceFolderRoundTrip` (AC #1, #2) — creates an
    existing in-`$HOME` parent (`home/workspace`), sends
    `create_workspace_folder{Parent: parent, Name: "new-app"}`, and asserts
    the decrypted `workspace_folder_created` reply's `Path` equals
    `filepath.Join(filepath.EvalSymlinks(parent), "new-app")` — the confined
    **realpath**, never the raw `filepath.Join(parent, name)` (macOS temp
    dirs sit under a symlinked `/var`, so the two routinely differ). Then
    `os.Stat`s that path off disk to confirm the directory actually exists;
    the daemon creates it before replying, so the post-reply Stat is
    race-free.
  - `testV2DaemonCreateWorkspaceFolderRejectedNoLeak` (AC #3, #4) — the
    load-bearing security subtest. The escaping parent is `t.TempDir()`: an
    **existing, resolvable** sibling directory outside the daemon's `$HOME`,
    sent with a **clean, non-empty** name (`"new-app"`) so both the
    empty-parent guard and the name-shape guard pass and the reject is
    caused specifically by escaping `$HOME` — a vacuous variant (empty
    parent or bad name) would trip an earlier guard and prove nothing about
    the confinement bound. Asserts `protocol.malformed` with the static
    message `"workspace folder not allowed"`, `Retryable == false`, that
    **neither** the raw escaping parent **nor** its `EvalSymlinks` realpath
    appears anywhere in the decrypted reply payload bytes (the confine error
    names the *resolved* path, so both forms must be checked), and that
    `filepath.Join(escapingReal, "new-app")` does not exist on disk —
    deterministic, not racy, because `confineWorkdirToHomeCreating` runs
    containment check #1 before any `MkdirAll`.
  - `testV2DaemonCreateWorkspaceFolderBadName` (second guard,
    belt-and-suspenders) — certifies the **second, independent** fail-closed
    guard over the wire: a valid in-`$HOME` parent with `Name:
    "seg/INJECT_MARK"` (contains `/`) is rejected by the name-shape guard
    with its **own** static message, `"workspace folder name must be a
    single path element"` — distinct from the confinement message above,
    proving the two guards fire separately rather than one gate twice.
    Asserts the `INJECT_MARK` marker does not echo in the reply payload, and
    that `filepath.Join(parent, "seg")` was never created (the guard runs
    before the resolver, so nothing is joined or created).
  - Three spawns, one per subtest (not a shared daemon), matching
    #974/#975/#976/#980 — keeps every filesystem assertion reading a
    pristine temp `$HOME`.

## RED-on-regression

If `TypeCreateWorkspaceFolder`'s registration at `cmd/pyry/relay.go:419`
were removed, the verb would fall through to the no-handler
`protocol.unsupported` arm and the round-trip's `want
workspace_folder_created` assertion would fail. Code review empirically
confirmed this by observing the green happy path reach the real resolver —
the RED-on-main guard the spec claims is genuine.

## Security review

**Security-sensitive** — this is the second member of the write-verb family
(after #980) to certify a filesystem-write containment property over the
wire, and the first to certify **two independent** guards in the same
ticket. Test-only, no production code change; the production seam
(`resolveWorkspaceFolder` → `expandTilde` → `confineWorkdirToHomeCreating`)
is unchanged, this ticket only adds a caller. Non-vacuity was the explicit
design focus for both reject subtests: the escaping parent is non-empty and
existing (so the confinement reject is caused by escaping `$HOME`
specifically, not the empty-parent guard); the bad name is a clean parent
paired with a `/`-containing name (so the name-shape reject is caused
specifically by guard #2, not confinement). Code review confirmed PASS with
no findings, including a cross-check of the two guards' static messages
against the unexported handler constants.
