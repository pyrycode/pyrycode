# Ticket #754 — Zed conformance check for the generic-ACP shape

The **proof-of-correctness capstone** of epic
[#600](https://github.com/pyrycode/pyrycode/issues/600). One scripted ACP host
drives the whole `pyry acp` surface — `initialize` → `session/new` →
`session/prompt` + a scripted turn → a permission round-trip → `session/cancel` —
over the **real** [`internal/acp`](../features/acp-package.md) transport against a
deterministic fake claude (no live Zed, no network), and asserts the emitted wire
shape is the **generic Zed/spec dialect** ([ADR 027](../decisions/027-acp-mapping.md)),
not any single host's aliases. It is the one run where all six ADR 027 divergences
are observable **composing in a single session flow**.

Every surface it exercises had already landed and was unit-tested per-ticket; the
capstone adds exactly the two things nothing else provided — **integration** (the
divergences coexist in one session over one transport and one real session id) and
a **dialect lock** (the wire strings equal the *literal* ADR 027 values, a guard the
per-ticket tests cannot be — see below).

Test-only: **one new file, `cmd/pyry/acp_conformance_test.go`, zero production
files.** The last prerequisite, [#801](801.md) (live-wiring the permission proxy),
had to land first so divergence 2 was observable in a live run.

Spec: [`specs/architecture/754-acp-conformance-generic-shape.md`](../../specs/architecture/754-acp-conformance-generic-shape.md).
Feature doc:
[`features/acp-package.md` § Conformance capstone (#754)](../features/acp-package.md#conformance-capstone-754).

## Implementation

Two tests share one harness, all in the new file.

### `conformanceHarness` — the scripted ACP host

The harness **mirrors `serveACPWithPool`'s register-closure** (`acp.go`) with the
**same handler constructors** — a compile-time-checked mirror, so a constructor
signature change breaks this test rather than letting it drift. It cannot call
`serveACPWithPool` directly: that root hard-wires the production outbound path
(`streams.start(id)` → live `Session.Events()`) and does not expose its
`*acp.Transport`, and the fake claude is a sleeping shell script that writes no
`<id>.jsonl` and renders no PTY modal — so the real outbound path would park
forever and never emit. Two substitutions make scripted injection possible:

- **`dir == ""`** on `newACPTurnStreams(runCtx, pool, "", holds.end, logger)` —
  `newSessionHandler`'s internal `streams.start(id)` no-ops, disabling the real
  outbound so the *scripted* outbound (attached below) is the only producer/proxy.
- **`newRecordingDeliverer(false)`** as the `session/prompt` deliverer (not the pool
  session) — `WriteUserTurn` commits and the hold stays held until the *scripted*
  `TurnEnd` resolves it. A real fake-claude session would fail delivery and resolve
  the hold with an error first, breaking divergence 1.

The **real fake-claude pool still backs `session/new` / `session/cancel`**, so the
interactive-spawn argv proof (divergence 6 + cost invariant) is genuine and one real
session id ties the whole flow together.

### Concurrent frame classifier — the "extend the harness" crux

The existing `acpHarness.read()` decodes only replies; it has no case for an inbound
agent→client request or a `session/update` notification. This harness supplies that
as a **continuous reader goroutine** (`classify` / `dispatchFrame`) — the real ACP
host's read loop — that `ReadBytes('\n')`s each agent→host line and classifies by
shape (mirroring `acp.handleLine`):

- **reply** (`id`, no `method`) → buffered `replies` channel the test reads;
- **`session/update` notification** (`method`, no `id`) → appended to a mutex-guarded
  `notifications [][]byte` in wire order;
- **inbound `session/request_permission`** (`method` + `id`) → **auto-answered**: write
  a `{jsonrpc, id, result: selectedResp(answerOptionID)}` response back to
  `hostToAgentW`, echoing the request id so the transport routes it to the blocked
  proxy `Call`. `answerOptionID` is a harness field the test sets.

The continuous drain is **mandatory**: an unbuffered `io.Pipe` blocks each agent
write until read, and the producer's `Notify` and the proxy's `Call` write to
`agentToHostW` asynchronously — a send-all-then-read host would deadlock.

`attachScriptedOutbound(id)` (called after `session/new`) binds the scripted
outbound: a `turnbridge` producer (`scriptedSubscriber` + the `acpTurnStream` sink,
`onTurnEnd → holds.end`) on its own cancel, and a permission drain
(`scriptedSubscriber` + `newACPPermissionProxy(tr, kb, id, …)` where **caller = the
real transport**, so the proxy's `Call` goes over the wire to the classifier).
`waitDelivered()` blocks on the recording deliverer's `entered` signal so a scripted
`TurnEnd` never tries to resolve a hold that is not yet registered.

### Test 1 — `TestACPConformance_FullSessionDrive`

One host, one real session id, five sequenced phases (C and D do not interleave —
independent goroutines — keeping every assertion deterministic):

- **A — handshake (div 5).** The host offers `fs`+`terminal`; the `initialize` result
  requests neither (`protocolVersion == SupportedProtocolVersion`; the result bytes
  contain none of `"fs"`,`"terminal"`,`"readTextFile"`,`"writeTextFile"`).
- **B — session (div 6 + cost).** `session/new` mints a valid id, pins the single
  mode, and `waitOneClaudeArgv` == `["--session-id", <id>]` — the interactive-path /
  one-claude proof reused verbatim.
- **C — permission round-trip (div 2).** `answerOptionID = "reject_once"` (the **3rd**
  option, so `answer:3` proves index→digit is real, not "always 1"); the captured
  `session/request_permission` params carry the session id and the four
  `{optionId,name,kind}` options in fixed order, each kind
  `turnevent.PermissionOptionKind(kind).Valid()`.
- **D — turn + prompt return (div 1, 3; the generic dialect).** A held `session/prompt`,
  a scripted turn (thought, message, tool_use, a **dropped** `EventKindStallDetected`,
  end-of-turn). The held call returns `stopReason == "end_turn"`; **exactly three**
  `session/update` notifications arrive, discriminants `agent_thought_chunk`,
  `agent_message_chunk`, `tool_call` in order — no stall/busy/queue frame. Reading the
  return blocks until the reply drains, which is strictly after the three notifications
  (one producer `Run` goroutine emits notifications then `onTurnEnd`), so *exactly
  three at that point* proves both div-1 ordering and div-3 zero-extra-frames.
- **E — cancel + cancelled return (div 1, `cancelled`).** A fresh held prompt, a
  `session/cancel` notification (no reply), then — the producer already joined — the
  sink is fed `TurnEnd{cancelled}` **directly**; the held call returns
  `stopReason == "cancelled"`.

### Test 2 — `TestACPConformance_DialectLock`

Pure, no goroutines, no harness — the actual drift guard. Asserts the wire strings
equal the **literal** ADR 027 generic values: `MethodSessionUpdate == "session/update"`;
the four `acpbridge.SessionUpdate*` discriminants; the five `turnevent.TurnEndReason*`
`stopReason` strings; the four `turnevent.PermissionOptionKind*` kinds (each `.Valid()`);
and `methodSessionRequestPermission == "session/request_permission"` (the one
agent→client method). The eight client→agent method names have no named constants —
they are registered as literals and driven verbatim over the wire by Test 1 and the
per-ticket handshake/session tests.

## Patterns established

- **A dialect lock asserts against literals, because the per-ticket tests can't.**
  The per-ticket tests compare emitted frames against the `acpbridge.SessionUpdate*` /
  `turnevent.*` **constants**, so renaming a constant's *value* to an opencode alias
  would not fail them. The capstone writes the wants as **literal strings**, so any
  drift of a constant's value fails *here*. When a suite's job is to lock a wire string
  against future change, assert the literal, not the symbol.
- **Mirror the composition root's register-closure with the same constructors.** When a
  test needs the production wiring but must substitute one or two collaborators, re-use
  the *actual constructors* (`newSessionHandler`, `promptHandler`, …) rather than
  re-deriving the handler set — the mirror is compile-time-checked, so a signature
  change breaks the test instead of letting it silently diverge from the root.
- **Two levers disable the real outbound so scripted outbound can drive it:**
  `dir == ""` (no-ops `streams.start`) and `newRecordingDeliverer(false)` (delivery
  commits, hold stays held). Both are load-bearing; a gated/real deliverer resolves the
  hold with an error before the scripted `TurnEnd` can, breaking div 1.
- **A continuous frame classifier is mandatory over unbuffered pipes.** The scripted
  host must drain the agent→host stream continuously, because the outbound `Call` and
  `Notify` write asynchronously and a send-all-then-read host deadlocks. That drain *is*
  the real host read loop — auto-answering the inbound `session/request_permission` is
  the natural place for it.
- **Non-vacuity of a "no X on the wire" assertion is a count, not a label.** Div 3 is
  proven by asserting *exactly three* notifications (the fed stall produced zero extra
  frames), not by "no frame labelled stall."

## Code review

**PASS** — no blocking findings
([PR #806](https://github.com/pyrycode/pyrycode/pull/806)). A clean, well-constructed
test-only capstone. The reviewer verified: no deadlock (the permission `Call` is off
the Serve loop, the classifier drains continuously, writer interleaving is safe under
`writeMu`); no leak (every goroutine is `runCtx`-bounded and joined in `shutdown()`,
with an idempotent `t.Cleanup` net for a mid-test `t.Fatal`, and every blocking wait is
timeout-bounded so a wedge fails as a named timeout, not a hung `make check`);
divergence-1 ordering is structural; the `entered` counting-semaphore makes phase E's
second `waitDelivered()` wait on the id=4 delivery rather than racing a stale close;
the spawn argv proof is genuine. Ran `go test -race -run TestACPConformance -count=5`
locally — no ordering flake.

- **real-claude e2e red — flagged, not a regression.** `make e2e-realclaude` reds only
  on `TestPtyRunnerVsStreamRunner_StructuralEquivalence` — the **pre-existing,
  environmental `thinking_tokens` allowlist drift** already known-red on the parent
  commits (#792/#804). #754's diff touches only the new test file + the spec doc, **zero**
  files under `internal/e2e/realclaude` or the runner path, so the failing path is
  byte-identical to `main` — PASS + flag, not rework (per the [#789 lesson](789.md)).

## Lessons learned

- **The unbuffered `io.Pipe` transport pair makes a *continuous* host-side frame
  classifier mandatory.** The proxy's outbound `Call` and the producer's `Notify` write
  asynchronously, so a send-all-then-read host would deadlock. The classifier is the
  real host read loop, auto-answering the inbound `session/request_permission` off the
  drained agent→host stream.
- **`cancelled` cannot be produced through the scripted JSONL path.** The turnbridge
  mapper forces `end_turn` on `EventKindJsonlEndOfTurn`
  ([`internal/turnbridge/mapper.go`](../features/turnbridge-package.md)), so phase E joins
  the producer first and feeds the sink `TurnEnd{cancelled}` **directly** — the only way
  to observe the `cancelled` stopReason. (This is why the spec's "fold vs separate cancelled
  test" open question resolved to *fold*: the direct `sink.Handle` after the producer join
  is race-free and needs no second test.)
- **Div-3 non-vacuity is structural, not asserted by hand.** Reading the held-prompt
  return blocks until the reply frame drains, which is strictly after the three
  notification frames (one producer `Run` goroutine emits notifications then the return),
  so asserting *exactly three* notifications at that point proves both the ordering
  (div 1) and that the dropped stall produced zero extra frames (div 3) in one shot.
- **Resolve a hold only after it is registered.** A scripted `TurnEnd` that resolves a
  held `session/prompt` must wait for the delivery goroutine to enter `WriteUserTurn`
  (the recording deliverer's `entered` signal, a buffered counting semaphore) — otherwise
  it races the `holds.begin` insert. The counting semaphore (one token per entry) is what
  lets phase E's second delivery be waited on without racing a stale close.

## Testing

Both tests are package `main`, `-race`-clean under `make check`, and may run
`t.Parallel()` (each owns its harness / pool). The only I/O is the fake-claude pool +
in-memory pipes — no live Zed, no network; `make check` stays green. Run
`go test -race -run TestACPConformance -count=3 ./cmd/pyry/` to shake out any classifier
ordering flake. This ticket **reuses** existing package-level primitives with zero
shared-file edits: `newFakeClaudePool` / `waitOneClaudeArgv` / `assertPinnedModes`
(`acp_test.go`), `newSyncKeystroker` / `permissionShown` / `selectedResp` / `generousTimeout`
(`acp_permission_test.go`), `newRecordingDeliverer` / `promptFrame` (`acp_prompt_test.go`),
`scriptedSubscriber` / `streamEntry` / `jsonlStreamEvent` / `endOfTurnEvent` / `waitClosed`
(`interactive_turn_stream_v2_test.go`), and the production `runPermissionModalStream` seam
(#801) / `newACPTurnStream` sink (#750).

## Out of scope (deferred)

- **Real-Zed validation run.** A manual run against a real Zed GUI is worthwhile but
  deliberately not part of this automated ticket — proving the wire shape is generic is
  what makes the real-Zed run likely to pass. Follow-up, not a blocker.
- **Extracting the concurrent frame classifier.** The harness stays in the new file to
  hold the change to one file, zero shared-file edits, zero merge surface. If a later ACP
  test wants the classifier, extracting it to a shared helper is a follow-up refactor.
- **`toolCall` correlation across the two subscriptions** — inherited from #752/#801; the
  gating tool-call id is still `omitempty`-reserved. Not exercised here.
