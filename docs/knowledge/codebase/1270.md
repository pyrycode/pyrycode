# Ticket #1270 — Is a run's trailer and reap-log evidence admissible?

Adds `internal/e2e/realclaude/trailer_admissibility_test.go` (961 lines, purely additive
— nothing else in the repo edited, no production code touched). Two pure predicates that
decide whether a probe run's trailer and reap-log evidence can support a claim, so the
run-level classifier ([#1271](https://github.com/pyrycode/pyrycode/issues/1271), blocked
by this ticket) never has to. Split from
[#1267](https://github.com/pyrycode/pyrycode/issues/1267); offline, `e2e_realclaude`
build tag, no live claude or credentials.

## Implementation

- **The claim is proof on some teardown paths and void on others, with nothing in the
  captured bytes to tell them apart.** `ptyrunner`'s pinned teardown order
  (`runner.go:479-485`) writes the trailer (`emitter.Close()`) before the reap defer
  SIGKILLs claude's descendant groups — on that path, a process group named in the reap
  log was alive strictly after the trailer was written, and therefore alive when it was
  written: a deterministic proof where a point-in-time `ps` offers only a guess. But the
  budget's `Terminate` hook reaps *inside* the hook, **before** the trailer, and a third
  reap runs on operator-cancel. The reap line lands on stderr, the trailer on stdout —
  separate pipes, separate copiers, no ordering in the bytes. The one signal that tells
  the paths apart is the trailer's own `terminal_reason`: `max_turns` means the run was
  budget-fired, and on that path the attribution is void, not negative.

- **Two positive-allowlist value spaces, twelve values total — five for the gate, seven
  for the predicate, not the Technical Notes' six.** The ticket's own ACs yield the
  correction (`trailAdmitOutOfContract` plural in AC5); the architecture spec records it
  explicitly in its § Size decision. `trailGate(trailScanResult) trailGateResult` maps the
  trailer scan onto `trailGateUsable` / `trailGateNoTrailer` / `trailGateScanAborted` /
  `trailGateBudgetFired` / `trailGateOutOfContract`. `trailAdmitAttribution(tdnReapOutcome,
  certified string) trailAdmitResult` maps the reap attribution onto `trailAdmitProof` (the
  only admissible value) plus five named voids (`VoidBudgetFired`, `VoidInstrument`,
  `VoidNoLine`, `VoidGroupUnnamed`, `VoidNotOneReapLine`) plus `trailAdmitOutOfContract`.
  No value is a fall-through catch-all — see next point.

- **Validate, then decide: the out-of-contract value is a guard at the top, never a
  switch's default arm.** Both functions open with a contract block that rejects any
  input their documented producer cannot emit, before deciding anything. This is what
  makes every later arm's precondition true by construction, and it is what the ticket's
  "no value is the catch-all" language actually cashes out to in code. The gate's contract
  checks: `State` outside `{trailSeen, trailAbsent, trailAborted}` (catches the zero
  value); `State == trailSeen` with a nil `Trailer`; `State == trailSeen` with an empty
  `TerminalReason`. The predicate's: `Verdict` outside the four `tdnClassifyReapLog`
  documents (`tdnIsReapVerdict`, reused — see Lessons learned); `tdnReapNoLine` with
  `LineCount != 0`; `tdnReapHeldPGIDKilled`/`HeldPGIDAbsent` with `LineCount < 1`. Only the
  first check on each function is AC-mandated; the other two on each are that rule applied
  symmetrically to pairs the real producer cannot emit, on the reasoning that these tests
  are fixture-driven and an unfilled `LineCount` is exactly what a developer hand-types by
  accident.

- **The gate's nil-pointer discipline, and what it can and cannot guarantee.**
  `trailScanResult.Trailer` is nil unless `State == trailSeen` — a deliberate trap so a
  careless consumer panics loudly rather than reading `TerminalReason == ""` as real. The
  gate decides `State` before ever touching `Trailer`, and reaches `TerminalReason` only
  after confirming `Trailer != nil`, so it dereferences no nil pointer on any input,
  including a hand-built `trailSeen` record with `Trailer: nil`. It cannot be the trap's
  *last* consumer — `trailObservation` embeds `trailScanResult`, so anything holding an
  observation reaches `.Trailer` by field promotion, and shipped code already does exactly
  that. What it guarantees instead: its own output, `trailGateResult`, is trap-free by
  construction — no `*resultTrailer` reachable from it, directly or through an embedded
  field — so a consumer branching on the gate's value holds nothing to dereference.

- **A certification that could certify `""` would reintroduce the pointer trap's defect
  one layer up, and there is no live run to test it against.** `Close()`
  (`emitter.go:383-391`) substitutes the recorded detail or `"unclassified"` before
  marshalling, so a blank `terminal_reason` cannot reach the wire on today's pyry. The
  empty-`TerminalReason` contract check exists anyway, as a check on fixtures rather than
  on reality: a hand-built `resultTrailer{}` with an unfilled field is the likeliest
  accidental fixture, and a value space closed only because an `if` in another package
  holds is closed by coincidence, not by construction.

- **Two orderings inside the predicate, each with a doc-comment argument.** The budget
  void outranks every reap-side void (structural — the reap ran before the trailer on that
  path, so the reap record's contents are irrelevant, including whether they parsed;
  reporting an instrument void for a budget-fired run would falsely imply that fixing the
  instrument would yield proof). The contract block outranks the budget void (a caller
  handing an unproducible record has a bug that must surface regardless of which path the
  run took). `TestTrailAdmitAttribution` carries a dedicated row —
  `{tdnReapInstrumentFailed, LineCount: 1}` with reason `"max_turns"` → budget void, not
  instrument void — as the regression guard that makes the two orderings distinguishable.

- **`trailBudgetTerminalReason = "max_turns"` is a string literal with no executable pin to
  its producer, in the failure direction that matters.** `wireFields`
  (`emitter.go:428-437`) is unexported, so nothing in this package can assert the constant
  matches what pyry actually renders. A rename there would make budget-fired runs report
  `trailGateUsable` — a **false proof**, silently, with nothing going red. Named at the
  constant's own doc comment, in the architecture spec's Open Questions, and in the
  security review, rather than treated as a routine literal. Closing it needs either an
  exported mapping (a production change) or a captured budget-fired trailer (no such
  fixture exists) — both out of scope for a probe-family ticket that edits no production
  code. Handed to #1271 and the live probes as a known limit on what an
  admissible-vs-void answer rests on.

- **Reused, not rebuilt:** `trailScan` / `trailScanResult` / `trailObservation`, including
  the aborted state and the shipped fixtures `trailFixtureTrailer`, `trailPaddedTrailer`,
  `trailFixtureNoTrailer`, `trailOverlongPad` (#1266); `tdnClassifyReapLog` /
  `tdnReapOutcome` / `tdnIsReapVerdict` (#1253) — pyry's stderr is not re-parsed here;
  `resultTrailer` (`tool_loop_test.go:194`) and `reachCapCommand` (the cap). Identifier
  family `trail*`, sub-namespaced `trailGate*` / `trailAdmit*` with `gate-` / `admit-`
  string prefixes specifically so an input state (`trailAbsent`, `trailAborted`) and a
  result meaning something adjacent are not one tab-completion apart.

- **Test coverage — five `TestTrail`-prefixed functions, 50 subtests, 0 SKIP:**
  `TestTrailAdmissibilityConstantsAreClosed` (one union map over all eighteen constants —
  five gate, seven admit, six shipped — asserting non-empty and pairwise-distinct in one
  pass, plus the zero-value pin for both new records against all eighteen);
  `TestTrailGate` (routes its four main rows through the real `trailScan` over #1266's
  fixtures, not hand-built records, so the happy paths are pinned to what the shipped scan
  actually emits); `TestTrailAdmitAttribution` (one row builds its `tdnReapOutcome` via
  `tdnClassifyReapLog` over synthetic stderr rather than by hand); `TestTrailGateThenAdmit`
  (AC4's composition — asserts the predicate is invoked only through a gate value carrying
  a certified reason, i.e. never through `NoTrailer`/`ScanAborted`/`OutOfContract`, and
  that the budget-fired path reaches `trailAdmitVoidBudgetFired` through a real gate
  result rather than a hand-typed string); `TestTrailAdmissibilityRecordsCarryNoCapturedBytes`
  (a needle placed in both `trailScanResult.Line` and `tdnReapOutcome.Line`, `json.Marshal`
  asserted needle-free — proves neither result record copies or quotes either captured
  string).
  Run: `go test -race -tags e2e_realclaude -run '^TestTrail' -v ./internal/e2e/realclaude/`.

## Patterns established

- **Validate-then-decide as the mechanism for "no value is the catch-all."** A closed
  positive-allowlist result set is not enough on its own to keep a fall-through from
  quietly becoming the default; the contract block has to sit at the top of the function,
  ahead of every real arm, so the out-of-contract value is reached by an explicit guard
  and never by exhausting a switch. Applies to both functions in this file identically.
- **Sub-namespace result constants from the input states they're computed over, when the
  meanings are adjacent.** `trailGate*`/`gate-` vs. the scan's `trailAbsent`/`trailAborted`
  input states: a predicate whose whole purpose is refusing to collapse distinct things
  must not ship a namespace where an input state and a result are one tab-completion
  apart. The string-value prefix (`gate-`/`admit-`) makes a copy-paste mistake visible in
  a diff, not just in the identifier.
  See also [[architect-1267-lifting-seams-does-not-shrink-an-outcome-table]] on why the
  outcome count itself doesn't shrink — this ticket is the arithmetic playing out: twelve
  outcomes, one file, no seam to lift.
- **A value that "certifies" a piece of derived data must be provably unable to certify an
  empty one — and the check for that belongs on the *input* the fixture layer can
  mistype, not on a search for a live case that can't occur.** Same shape as #1266's
  nil-`Trailer` trap, one layer up: `TerminalReason == ""` is unreachable from real pyry
  output, but reachable from a hand-built fixture, so the contract check exists for the
  fixture, not for reality.

## Lessons learned

- **A code-review SHOULD FIX can survive to merge as a named, accepted gap — and the gap
  matches the file's own stated doctrine.** The review found that `trailAdmitAttribution`'s
  `certified string` parameter gets zero contract checks, while the sibling `reap
  tdnReapOutcome` parameter gets three (two beyond AC's mandate). `certified == ""`
  reaches `trailAdmitProof` — a false proof from a run the gate never certified, the same
  failure direction as the nil-`Trailer` trap and the empty-`TerminalReason` gate arm, both
  of which this same file exists to prevent. Neither this SHOULD FIX nor the sibling one
  (`trailReapLine` rebuilding a shipped fixture, `tdnFixtureDefaultOne`, in a slog handler
  shape the live path doesn't use) blocked merge, and neither was taken before merge — the
  code at `trailer_admissibility_test.go:356-415` still has no check on `certified`, and
  `trailReapLine` (`:510-513`) still exists. Recorded here rather than silently dropped:
  a future ticket touching this file should either fold in the four-line fix (reuse
  `trailAdmitOutOfContract`, no new constant, no existing test row changes value) or
  explicitly re-decline it with a reason, not let it re-surface as a fresh finding.
- **A file's stated doctrine ("each function opens with a contract block") is a claim
  that has to be checked per-parameter, not per-function.** The gate has one input and
  fully lives its own rule. The predicate has two inputs (`reap`, `certified`) and only
  one is contracted — the doctrine reads as satisfied at a glance because *a* contract
  block exists, but it only covers 3 of the function's 4 possible garbage-in classes.
  Worth checking on every multi-parameter function claiming this pattern.
- **`tdnIsReapVerdict` (`teardown_liveness_test.go:1176`) already existed and is exactly
  the predicate's first contract check** — the architecture spec's reuse inventory named
  `tdnClassifyReapLog` and `tdnReapOutcome` but missed this helper. A grep for existing
  membership checks before writing a fresh `switch` found it during implementation.
- **A mutation-test harness needs its applied-check run on the platform it will run on.**
  The first mutation sweep used `grep -qP` to confirm each mutation actually landed before
  trusting a red result as evidence; BSD `grep` has no `-P`, so all eight applied-checks
  errored and the harness correctly refused to report anything. `grep -qF` with a fixed
  string is the portable form. The asymmetry worth naming: an applied-check that errors
  fails safe; one that matches unconditionally would have reported eight green mutations
  as eight survived defences.
- **A verification recipe can be invalidated by the very file it verifies.** The
  architecture spec's `.Trailer` census (`git grep … | grep -v
  result_trailer_observation_test.go # must print NOTHING`) cannot hold once this file
  ships, because the gate itself reads `Trailer` and the spec requires the gate to live in
  the new file. It printed nothing during development only because plain `git grep` skips
  untracked files — a vacuous pass that would have flipped to a false failure the moment
  the file was committed. Re-run recipe: `git grep --untracked -nP '\.Trailer\b' --
  internal/ cmd/`, then exclude both `result_trailer_observation_test.go` (#1266's own
  tests, exempt) and `trailer_admissibility_test.go` (this file's contract-path reads) —
  the property that actually holds is "no hit in any *third* file," confirmed by
  code review at 15 + 4 hits, zero elsewhere.
