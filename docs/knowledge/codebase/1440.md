# Ticket #1440 — Aliveness-at-a-trailer-sighting from a certified ordering and a pinned pid (offline)

On the headless stream path (`PYRY_USE_STREAMJSON=1`) pyry writes **no reap log at
all** on a clean exit — `streamrunner` reaps only inside `cmd.Cancel`, which never
fires on a clean exit, unlike `ptyrunner`'s defer that fires on every teardown. That
leaves `trailClassifyRun`'s top-ranked evidence (an admissible reap-log attribution)
structurally empty on this path, not merely late. This ticket ships the offline
predicate that fills the gap with a different evidence class: given #1439's
certified ordering of three instants (trailer sighted → pyry exited → pid re-read,
under a held FIFO), a pid found alive after pyry's exit was necessarily alive at the
earlier sighting — lateness only strengthens that direction. It is the consumer half
of #1436's split; #1439 (merged, PR #1441) shipped the ordering certification this
ticket composes on top of.

PR [#1442](https://github.com/pyrycode/pyrycode/pull/1442). Split from #1436
(closed). Sibling: #1439 (merged). Security-sensitive (architect self-review PASS;
code review round 1 miscounted six same-cause cite sites as six findings and tripped
FAIL, corrected in a follow-up comment to PASS — see § Lessons).

## Implementation

- **One new file, one edited file, zero production Go touched.**
  `internal/e2e/realclaude/trail_sighting_liveness_test.go` (new, 1017 lines,
  `//go:build e2e_realclaude`) carries two value spaces, the record, the predicate,
  two membership helpers, fixtures and five tests. `trailer_admissibility_test.go`
  gains all eight new values in the union closure map plus corrected prose (space
  count, near-collision list, per-space consumer list, `zeroSighting` zero-value
  walk including its `Reason` field).
- **`trailEstablishSighting(ordering trailOrderResult, pin pinStateOutcome) trailSightingResult`**
  — both parameters are the shipped records **whole**, never their `Value`/`Verdict`
  strings. This cuts both ways from #1439's own enforcement: `pinStateOutcome`
  carries `Detail`/`StateColumn`/`ToolStderr`, all string-bearing and one
  (`ToolStderr`) a live raw-`ps`-stderr capture route, so narrowing the parameter to
  a bare verdict string would make the no-captured-bytes sweep unbuildable — there
  would be no route for a needle to travel. Pure: no exec, no clock, no filesystem,
  no `*testing.T`, never fails a test, consults no parentage, requires no reap line.
- **Naming defeats a live collision, not a hypothetical one.** The shipped
  `trailOutcomeRunningAtTrailer = "run-running-at-trailer"` documents itself as "an
  admissible attribution proves the process group was alive when the trailer was
  written. THE FINDING, and the only path to one" — the *same English sentence*
  this predicate establishes, from the evidence class the stream path lacks. The
  positive value is `trailSightingEstablished = "sighting-alive-by-ordering"`
  (different prefix, different noun, `-by-ordering` names the evidence class); the
  read-failure reason is `sighting-reason-pid-read-failed` rather than anything
  ending in `…liveness-instrument-failed` (the shipped
  `trailOutcomeVoidLivenessInstrument`'s tail), to keep the run space's phrasing out
  of this one. **Deliberately no `sighting-out-of-contract` value** — every
  off-space verdict already has a reachable, correct home (see below).
- **Three outcomes, five reasons, one precedence decision.** `trailOrderCertified` +
  `pinStateRunning` → established / pid-running. Certified + `ExitedNotReaped` or
  `NoSuchProcess` → unestablished. Any of the three `trailOrderVoid*` values → void
  / ordering-uncertified, **regardless of the pid verdict** — a premise failure is
  never re-litigated into evidence about the command. `pinStateInstrumentFailed`,
  under a certified ordering, also → void / pid-read-failed, never unestablished —
  an instrument failure must never read as a clean negative, the same collapse
  `trailOutcomeVoidLivenessInstrument`'s doc already refuses. Body shape: one guard
  on `ordering.Value != trailOrderCertified`, then a `switch pin.Verdict` whose
  `default:` arm (not a second explicit case) is the reachable home for both
  `pinStateInstrumentFailed` and any off-space verdict string, including the zero
  `""` — two fixtures reach it by different routes and both are covered.
- **The record carries no `PID` field.** `trailSightingResult{Value, Reason, Detail
  string}` — three keys, in `trailGateResult`'s Value+Reason+Detail shape. The pid
  reaches a reader through `Detail` as `%d`, keeping the marshalled surface and the
  sweep's forbidden-key walk over the smallest possible set.
- **`TestTrailSightingAllSixteenCombinations`** (AC2) — generates the cross product
  of `trailOrderValues()` × the four spelled `pinState*` verdicts rather than
  hand-writing sixteen rows, so a fifth ordering value lands in coverage
  automatically; carries #1439's `len(seen)` distinctness guard, but scoped to the
  **source lists**, not the rows (see § Lessons). Two extra rows outside the product
  cover `""` and a junk verdict string, both landing on void / pid-read-failed.
- **`TestTrailSightingPremiseRemovalNeverEstablishes`** (AC3) — three subtests, one
  per #1439 premise, driven off `trailOrderCertifiedPremises()` and `.certify()`
  rather than a hand-built `trailOrderResult{Value: trailOrderCertified}` — asserts
  the base certifies first, then that a `pinStateRunning` pin (the verdict that
  would otherwise establish) still lands on void, never established. This is what
  stops a caller bypassing the hold-as-precondition argument by fabricating a
  certification.
- **`TestTrailSightingValuesAgreeWithThePredicate`** (AC4) — both directions, counts
  asserted against the ticket's own enumeration (3 outcomes, 5 reasons), and
  cross-rejection: each space's predicate rejects the other's values, plus the two
  named collision strings (`trailOutcomeRunningAtTrailer`,
  `trailOutcomeVoidLivenessInstrument`) and every other family constant.
- **`TestTrailSightingResultCarriesNoCapturedBytes`** (AC5) — plants `trailNeedle`
  into `pin.Detail`, `pin.StateColumn` **and** `pin.ToolStderr` (all three
  string-bearing fields, not just the two the ticket body emphasised), plus
  `ordering.Detail` via a struct literal as a discipline against a future field
  rather than a live route (#1439 pinned that producer's inputs to three booleans,
  so no byte reaches `Detail` through it today). Premise-first: asserts
  `trailSightingEstablished` before marshalling. **Two halves, not one** — see
  § Lessons for why the marshalled-key walk alone was insufficient.
- **`TestTrailSightingVoidsNeverReadAsNegative`** — a short loop over every void
  cell of the 4×4(+2) asserting none reads as `trailSightingUnestablished` and none
  of their Details contain "declared finished" / "declared the turn finished". The
  only check that the *prose* half of the naming rule holds, not just the value
  half.
- **Closure-map join, six exact sites, not a seventh closure test.** Union map:
  43 → 51 entries (all eight new values); space-count/near-collision/consumer-list
  prose corrected in the same commit; `zeroSighting` added to both the zero-value
  walk (`Value` field) and a new `Reason`-specific check — the second record in the
  family to carry a `Reason`, so an unfilled reason reading as a filled one is the
  same failure mode as `zeroGate.Reason` already guards, on a field a consumer
  actually branches on.

## Patterns established

- **A parameter list can be the enforcement in either direction.** #1439 pinned its
  producer's inputs to three bare booleans specifically so no captured byte could
  reach its Detail; this ticket takes the **opposite** shape — two whole records
  instead of two bare strings — specifically so the no-captured-bytes sweep has a
  route to test at all. Same family, same instrument (parameter narrowing/widening
  as the enforcement), opposite direction, both load-bearing for the sweep each
  ships.
- **A `default:` switch arm is the reachable, non-defensive home for two distinct
  failure routes when they are the same statement.** `pinStateInstrumentFailed` and
  an off-space verdict string are folded into one arm on purpose — both mean
  "nothing was measured" — rather than split into a real case and a defensive
  fallback no fixture reaches. See [[a-defensive-default-arm-breaks-a-totality-claim]]
  for the failure mode this avoids; here the default *is* reached by two fixtures on
  two different routes, so it does not trip that instrument's concern.

## Lessons learned

From the PR body's own "Lessons learned" section (developer):

- **A marshalled-key walk cannot see an `omitempty` field before something fills
  it.** Adding `Argv string \`json:"argv,omitempty"\`` to `trailSightingResult` left
  the prescribed structural half (decode → `map[string]json.RawMessage` → refuse a
  `command`/`args`/`comm`/`argv`-shaped key) fully **green**, because an empty
  `omitempty` field emits no key at all — the control starts refusing a
  command-shaped key only once one already carries a value, the wrong end of the
  window for a check whose job is that the record stays pasteable *before* review.
  Closed by adding a second half that walks `reflect.TypeOf(trailSightingResult{})`'s
  own json tags — refused the moment a field is *declared*, not once it is
  *populated*. The mutant (adding the field) now reddens only on this reflect half,
  confirming it is not a duplicate of the marshalled walk. **The shipped per-record
  sweeps elsewhere in this family have the same hole** (they only walk the
  marshalled instance); they are not this ticket's records to change, but a future
  ticket touching any of them should add the same second half.
- **A generated cross product needs a distinctness guard over its *source lists*,
  not its rows.** #1439's `len(seen) != 8` guarded a hand-written table; the
  equivalent here guards `trailOrderValues()` × the four spelled verdicts, where a
  duplicate in either *source list* would shrink coverage while both `len()`s still
  read correct.
- **Delivered 1017 lines against the spec's own ~750 and the ticket's ~697**, on the
  same authoring pattern as the 618-line sibling #1439. The overrun is
  roughly proportionate to what doubled relative to #1439 (eight values not four,
  two membership spaces not one, sixteen-plus-two combinations not eight, both
  sweep halves not one) — a data point for the family's per-block cost model, not a
  scope surprise. Ratio to #1439: ~1.65× lines for ~2× surface.
- **Recorded, not chased:** the stream path leaves a backgrounded group unreaped
  where ptyrunner kills it. Noted in the file header; what survives teardown is
  #1231's question, out of scope here.

From code review (one comment superseded by a second, same PR, no rework round):

- **N sites of one omitted sweep is one finding, not N — and getting that arithmetic
  wrong flips PASS to FAIL on the wrong axis.** The first review comment counted six
  stale citations (all caused by this PR's own +6/+38 shift of
  `trailer_admissibility_test.go`, none pre-existing) as six separate SHOULD FIX
  findings and tripped the repo's three-finding FAIL threshold. A second comment
  from the same reviewer corrected this: six sites are one omitted cite sweep, cited
  against the repo's own scale precedent (#1417's 79-site sweep was the MUST-FIX
  scale; six sites across four files is not), and **every technical finding stood
  unchanged** — only the severity arithmetic and the routing changed, PASS with one
  SHOULD FIX rather than FAIL. Applied without a developer rework cycle, following
  #1420's precedent for the same shape of finding. One of the six sites was a bare
  chained reference (`(:2074-2079)` inheriting its filename from a citation two
  lines above) that a filename-anchored `grep 'trailer_admissibility_test.go:2074'`
  reports clean on — [[cite-sweeps-have-a-third-symbol-anchored-form]] and
  [[code-review-detect-bare-chained-cites-with-a-last-named-file-scan]] both apply
  directly; this is the same failure mode `codebase/1439.md` recorded one ticket
  earlier, reproducing in its own consumer.
- One NIT correctly held: a pre-existing stale cite
  (`finding_attribution_fanout_test.go:701` → `:1250`, actually `:2561`) was
  identified as **not** this PR's damage — its pre-PR gap (1273) matched no shift
  this PR made — and left unrepointed, the same gap-size-vs-shift-magnitude
  discrimination [[code-review-attribute-a-stale-cite-by-gap-size]] describes.
- Verification: `-run '^TestTrailSighting' -v` → 26 PASS / 0 SKIP / 0 FAIL; the full
  `^TestTrail` set → 200 PASS / 0 SKIP / 0 FAIL. Six overlay mutants, all killed
  (precedence inversion, `default:` returning unestablished, an arm dropping its
  instant clause, `pin.Detail` interpolated into the established arm, a certified-row
  reason swap, and the `Argv` field addition — the last reddening only the reflect
  half, confirming it is not a duplicate check).
