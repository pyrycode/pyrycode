# Ticket #831 — `new_session` v2 wire type + `/clear` relay routing (`SessionStarter` seam)

The **remote start-new-session** control ([EPIC #597] Phase 3, [ADR 025]): a paired
phone's equivalent of typing **`/clear`** at the local terminal. A phone sends a
bare `new_session` v2 control frame; the daemon gates it on the negotiated
`interactive` capability and routes it to the supervised claude as a `/clear`
through the sealed `supervisor.StartNewSession()` seam (#830). Split from #824;
structurally the `interrupt` (#707) shape one verb over — same inbound-control
interception, same capability gate, same fire-and-forget posture.

Every dependency already existed on `main`: the keystroke seam shipped unwired
in #830 waiting for exactly this consumer, and the client-observable outcome
(the `session_transition` boundary marker, `reason: "clear"`) is pre-existing
#656/#657 machinery. **This ticket builds no new emitter and no ack path.**
Held at **S**, no split — three production files, one new interface, zero
consumer-signature changes.

The one structural difference from `interrupt`: **no neutral `turnevent`
command.** #707 added `turnevent.Cancel` so the future ACP `session/cancel`
adapter would have a target. `new_session` has no announced ACP counterpart
requiring a neutral form, so it drives the relay seam directly — the same
shape `modal_cancel` uses to route straight to `ModalResolver.ResolveCancel`
without constructing a `turnevent` value.

### `handleNewSession` — the new logic (`internal/relay/v2session.go`)

Runs on the manager's **single Run dispatch goroutine**, so the `s.interactive`
read is lock-free under the package's single-owner invariant. Signature takes
**only `s`** (no `ctx`, no `env`) — the same documented deviation
`handleInterrupt` established: the frame carries no payload to decode and the
handler does no cancellable work. Order is load-bearing — **capability gate
first**:

1. **`if !s.interactive` → return** (no `/clear`). The inbound capability gate
   (AC #4 negative path) — a **one-line check, not a reusable abstraction**;
   `new_session` keeps its own bare check alongside `interrupt` /
   `dequeue_message`'s (CODING-STYLE over-DRY). `s.interactive` is
   server-authoritative (#626), set fail-closed from the daemon's
   `negotiateCapabilities`, never from the phone's raw advertisement.
2. **`if m.cfg.SessionStarter == nil`** → debug-log `v2.new_session.inert`
   (`conn_id`), return (foreground / pre-wire; mirrors `handleInterrupt`'s
   nil-seam guard). AC #5.
3. **`m.cfg.SessionStarter.StartNewSession()`** — best-effort. An error (no
   live claude / mid-teardown → `ErrNoLiveSession`) is `Warn`-logged
   (`v2.new_session.keystroke_err`, `conn_id` + the supervisor sentinel only —
   **never** payload bytes or the rendered screen) and tolerated; nothing to
   roll back, no reply owed (fire-and-forget, no broadcast). AC #5.

### Data flow

```
phone ── new_session (noise_msg, AEAD) ──> relay ── RoutingEnvelope ──> V2SessionManager.Run
  └─ handleFrame → handleNoiseMsg → dispatchAppFrame (probe decode, type-only)
       └─ case TypeNewSession → handleNewSession(s)
            ├─ !s.interactive              → return (inert)             [AC #4]
            ├─ cfg.SessionStarter == nil   → debug log, return          [AC #5]
            └─ cfg.SessionStarter.StartNewSession() → supervisor.StartNewSession()  [AC #3]
                 └─ ClearInputLine + TypePrompt("/clear") → claude /clear (#830)
                      └─ (pre-existing, async) rotation watcher → notifyTransition(ReasonClear)
                           └─ session_transition emitter → interactive conns   [client-observable]
```

The dashed lower half is pre-existing machinery this ticket does not touch.

## Testing

`internal/relay/v2session_newsession_test.go` (new) mirrors
`v2session_interrupt_test.go` line-for-line: a `fakeSessionStarter`
(mutex-guarded `startCalls` counter + injectable error), driven through the
real `Frames`/`Run` loop with the existing `startManager` / `openModalConn` /
`sealAppFrameConn` helpers, synced with the **barrier-conn-after-the-frame**
idiom (#707) — the single FIFO `Frames` + single `Run` goroutine guarantees the
`new_session` frame is fully handled before the barrier conn opens, so the
fake's counter is final and its arrival proves no panic/hang even on the nil
path.

- `TestV2Session_NewSession_RoutesClearByCapability` — table-driven both paths
  (AC #3/AC #4): interactive → exactly one `/clear`; non-interactive
  (`caps=nil`) → zero.
- `TestV2Session_NewSession_NilStarterInert` — nil `SessionStarter`, interactive
  `new_session` → zero `/clear`, no panic, manager keeps serving
  (foreground/unwired, AC #5).
- `TestV2Session_NewSession_StartErrorTolerated` — `StartNewSession` returns an
  error → still counts as one attempted call, manager neither crashes nor
  closes the conn (best-effort tolerance, AC #5).

## Patterns established

- **The `interrupt` shape generalizes to any bare inbound control verb that
  drives a sealed keystroke seam.** `new_session` is the second inbound frame
  whose authorization *is* the `interactive` capability (after #707) and the
  second consumer-declared one-method seam wired with a single `cmd/pyry`
  line — the template now has two load-bearing instances, reinforcing that a
  third such verb should follow the same shape without re-deriving it.
- **A verb can skip the neutral `turnevent` step when it has no announced
  cross-adapter consumer.** #707 added `turnevent.Cancel` because #600's ACP
  adapter needed a target; `new_session` has no such consumer today, so it
  routes directly from `dispatchAppFrame` to the seam — one fewer package
  touched, one fewer sealed sum-type member. If a future ACP `session/new`
  needs a neutral form, that's an additive later ticket, not a retrofit.
- **Actuator/consumer split (#830 → #831) repeats the #726 → #707 shape a
  second time.** The mechanical keystroke primitive ships first, unwired,
  carrying no trust decision; the wire verb that authorizes and invokes it
  lands as a separate, later ticket. Two-for-two now.

## Out of scope (flagged, not designed here)

- **Multi-phone / multi-session scoping.** Any interactive paired phone can
  start a new session on the single live claude — no per-conversation /
  per-connection binding, identical to `interrupt`'s open question. A future
  multi-session world scoping `new_session` to a specific conversation is a
  later ticket.
- **Confirmation semantics.** Fire-and-forget; the client learns of success via
  the pre-existing `session_transition` marker. A synchronous "your `/clear`
  was accepted" ack, if ever needed, is an additive later ticket.
- **The mobile consumer** — the phone-side new-session UI (pyrycode-mobile),
  which today stubs this action.
- **ACP `session/new`** — no neutral `turnevent` command exists for this verb
  (see above); adding one is out of scope until an ACP consumer needs it.
