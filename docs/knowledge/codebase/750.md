# Ticket #750 — ACP outbound streaming adapter: `turnevent.Event` → `session/update`

The **streaming consumer** of epic
[#600](https://github.com/pyrycode/pyrycode/issues/600) (T6) — the outbound
counterpart to [#769](https://github.com/pyrycode/pyrycode/issues/769)'s pure
mapper. A stateless `acpTurnStream` sink subscribes to one ACP session's neutral
[`turnevent.Event`](../features/turnevent-package.md) stream and turns each event
into a JSON-RPC `session/update` **notification** on the ACP transport (mapping
via `acpbridge.MapUpdate`), signals turn-end **out-of-band** to the
`session/prompt` owner ([#751](https://github.com/pyrycode/pyrycode/issues/751)),
and drops `Stall` to stderr. It is the ACP analogue of the mobile head's
`interactiveTurnEmitterV2`, but far thinner — ACP's host owns the spinner and
turn pacing, so none of the mobile emitter's lifecycle / coalescing / fan-out
machinery is carried over. [ADR 027](../decisions/027-acp-mapping.md) (divergences
1 & 3) is the mapping contract.

Full package documentation:
[features/acp-package.md](../features/acp-package.md) (`Transport.Notify` +
`§ Outbound streaming adapter`).

## Implementation

**Two production files, both fully additive — zero modification to any existing
file** (the branch-isolation posture that let #750 and the in-flight #765 both
touch `internal/acp` with no conflict: each adds a *new* file). **0 new exported
types.**

- **`internal/acp/notify.go` — `Transport.Notify(method, params) error`.** The
  write-only sibling of `Call`: marshal `params` first (nil ⇒ key omitted, a
  marshal failure returns a wrapped error and writes **nothing** — no partial
  frame), then one `writeMessage` under `writeMu`, the same leaf lock serialising
  `reply` and `Call`. Never awaits a response; safe from any goroutine. A
  **distinct unexported `notification` wire struct** is required because
  `jsonrpc.go`'s `request.ID` is a non-omitempty `uint64` and would always emit an
  `id` — which a notification must never carry. This is the `session/update` emit
  path; it has no other caller yet, so it ships with this wiring (~15 LOC, no
  separate ticket).

- **`cmd/pyry/acp_turn_stream.go` — the stateless `acpTurnStream` sink.** Its
  `Handle(ev turnevent.Event)` signature **is** `turnbridge.Config.OnEvent`
  exactly, so #751 wires `OnEvent: stream.Handle` with no closure. Dispatch:
  - `TurnEnd{Reason}` → **no** `session/update`; call `onTurnEnd(string(Reason))`
    (divergence 1). The ACP `stopReason` **is** `string(Reason)` by identity —
    `turnevent.TurnEndReason` values already are the ACP strings, no table.
  - `Stall{}` → **no** `session/update`; `logger.Warn` on stderr (divergence 3),
    content-free (`event`, `session_id` only).
  - `TextChunk` / `ThoughtChunk` / `ToolStart` / `ToolUpdate` →
    `acpbridge.MapUpdate(ev)`, then `transport.Notify(MethodSessionUpdate,
    sessionUpdateParams{sessionID, update})`.
  - nil / future variant → `MapUpdate` returns `ok == false` → a defensive
    `Debug`-logged drop (unreachable for the four above).
  - `sessionUpdateParams{SessionID, Update}` is the `{sessionId, update}` params
    wrapper — **this consumer's**, not `acpbridge`'s (the mapper is pure
    value-to-value; session addressing is the consumer's). The `sessionUpdate`
    discriminant rides *inside* `Update`, so there is no separate discriminant
    field here.

- **`TurnEnd` and `Stall` are type-switched explicitly BEFORE `MapUpdate`**,
  because `MapUpdate` collapses both to `ok == false` and the adapter must
  distinguish them (a turn-end signal vs a stderr drop). `MapUpdate` is therefore
  only ever reached for the four emit-able variants where `ok` is always true; the
  `!ok` guard is defensive against a future sealed-`Event` variant.

- **The `msgID` from `MapUpdate` is intentionally discarded (`_`).** ACP's
  `agent_message_chunk` carries content only — there is no per-message wire
  delimiter — so chunks sharing a `MessageID` stream as separate
  `agent_message_chunk` notifications **in arrival order** and the host
  concatenates them. AC-2's "grouping by message id" is realised by *arrival
  order*, not by coalescing; the adapter holds no `MessageID` state (contrast the
  mobile emitter's `MessageID`-keyed delta coalescing, #609, which ACP neither
  needs nor supports). An inline comment documents the discard so a developer
  reading #769's out-of-band `msgID` return understands why it is unused here.

### The T7 (#751) signal seam

`onTurnEnd func(reason string)` is the coordinated seam. It is invoked
**synchronously on the producer's single `Run` goroutine** when `TurnEnd` arrives.
#751 supplies a callback that resolves the held `session/prompt` call with
`reason` as the `stopReason`; **that callback must not block** the producer
goroutine (buffered hand-off or immediate resolve — e.g. #765's `Responder`). A
callback (not a channel) keeps #750 agnostic about #751's hold-and-resolve
mechanism. `onTurnEnd` is **nil-tolerant** (Debug-log + no-op) so the adapter can
be constructed for pure emit tests.

### Not built here — producer wiring is #751's

The adapter is a pure **sink**, tested against a scripted `turnevent.Event`
sequence — no live producer or claude. Standing up a `turnbridge` producer over a
session's supervisor and feeding this sink belongs to the `session/prompt` turn
owner (#751/T7), because per divergence 1 streaming happens *inside* the held
`session/prompt` call. This is the established "ship the consumer unit-tested,
wire it in the lifecycle ticket" posture ([codebase/632.md](632.md)).

**Flagged finding (recorded so #751 need not re-discover it):** the ticket asked
to verify the per-session `turnevent.Event` stream is exposed by the #761 embedded
ACP pool. **It is not** — #761's `session/new` just calls `pool.Create`; no
`turnbridge` producer is wired for ACP sessions (the producer is wired only for
the mobile head, in `runSupervisor`). This does **not** block #750 (the sink is
scripted-tested). Every building block #751 needs is already shipped: `sess.
Supervisor()` satisfies `turnbridge.SessionHost`; `turnbridge.NewTargetSubscriber`
with a fixed-session by-id `TargetResolver` (`Switch: nil` — ACP has no
active-conversation follow); `sessions.DefaultClaudeSessionsDir(bootstrapWorkdir)`
as the JSONL dir. The full recipe is in the spec (§ "Producer wiring is #751's").

## Patterns established

- **Third thin adapter over the neutral `turnevent` core, streaming half.** #769
  proved the *pure* second mapper (`acpbridge.MapUpdate` mirrors
  `turnbridge.MapEvent`); #750 proves its *stateful* consumer is trivially thin
  when the target surface owns turn pacing. The mobile emitter's coalescing /
  `turn_state` machine / capability fan-out / replay ring / conversation cursor
  are **all** N/A for ACP — the entire consumer is a stateless dispatch with no
  goroutine, no clock, no mutable per-event field. This is the ADR 025/027
  containment thesis realised end to end: one neutral model, two fully independent
  outbound surfaces, the second an order of magnitude cheaper to consume.

- **`Notify` = `Call` minus the id/pending machinery, in a new file.** A JSON-RPC
  notification is a request with no id and no response. Rather than overload
  `request` (whose non-omitempty `uint64` id would always serialise), a distinct
  `notification` wire struct + a `Call`-shaped method that reuses the `writeMessage`/
  `writeMu` seam unchanged. Putting both in a **new** `notify.go` (not editing
  `acp.go`) is the deliberate branch-isolation move that kept #750 conflict-free
  with the in-flight #765 — the same "new outbound concern → new file" precedent
  #765's `responder.go` set.

- **A signal seam expressed as a nil-tolerant callback, not a channel.** The
  turn-end hand-off to #751 is `func(string)`, so this adapter stays agnostic about
  #751's hold-and-resolve mechanism (the channel, if any, lives inside #751's
  callback) and can be built with `nil` for pure emit tests. The one constraint —
  the callback must not block the producer's `Run` goroutine — is documented, not
  enforced (evidence-based: #751 owns the resolve).

- **"Group by message id" without state, via arrival order.** When the target
  wire has no per-message delimiter, streaming each chunk as its own frame in
  arrival order *is* the grouping — the host concatenates. The out-of-band `msgID`
  is discarded, not coalesced. Coalescing is a mobile-only optimisation (#609),
  not a correctness requirement; ACP neither needs nor supports it.

## Code review

**PASS** — no findings, no MUST/SHOULD/NIT
([PR #771](https://github.com/pyrycode/pyrycode/pull/771)). Reviewer verified:
`Notify` is a faithful `Call`-minus-id/pending (nil-params omission, no partial
frame on marshal failure, one `writeMessage` under `writeMu`) with the distinct
`notification` struct justified; the `Handle` dispatch matches ADR 027 divergences
1 & 3 (both type-switched before `MapUpdate`); the `msgID` discard is correct for
ACP's delimiter-free wire and documented inline; the stateless adapter is race-free
on the producer's single `Run` goroutine; no application content logged at any
level (only `eventKind` discriminants + session id + error sentinel — `eventKind`
**reused** from `interactive_turn_v2.go`, not redefined); no `exec`/`claude -p`/SDK
path (AC-5); all four new symbols additive with no current consumers (wiring is
#751's). `make check` green (vet + staticcheck + `-race` + substrate-guard);
real-claude e2e clean (166s, no flake).

## Lessons learned

- **`request` cannot double as a notification frame — the id tag is non-omitempty.**
  The obvious reuse (send a `request` with a zero id and hope it's omitted) fails
  silently: `request.ID uint64` has no `omitempty`, so it always marshals
  `"id":0`, which a JSON-RPC notification must never carry. The fix is a separate
  three-field `notification` struct. `notify_test.go` decodes the frame as a
  generic map and asserts `id` is **absent** (not `0`) — the only assertion that
  actually catches the regression.

- **Discarding a value another ticket went out of its way to surface deserves a
  comment.** #769 returns `msgID` out-of-band precisely so a consumer *can* group.
  #750 discards it because ACP's wire has no message boundary. Without the inline
  rationale a future reader sees `update, _, ok :=` and assumes an oversight. The
  comment ties the discard to ADR 027's delimiter-free `agent_message_chunk` and to
  the #609 coalescing this adapter deliberately omits.

- **Test the sink against a real transport with an in-memory writer.** All five ACs
  are provable at the `Handle` level with no live producer or claude: construct a
  real `acp.Transport` over a `bytes.Buffer`, drive `Handle` with scripted
  `turnevent.Event` values, decode the buffer, and assert the frames (no `id`/
  `result`, correct `sessionUpdate` discriminant, arrival order). This is the same
  "consumer unit-tested now, wired in the lifecycle ticket" split as #632/#769.

## Testing

`cmd/pyry/acp_turn_stream_test.go` (package `main`) + `internal/acp/notify_test.go`
(package `acp`), stdlib `testing`, `-race`-clean. Each drives a real transport over
a `bytes.Buffer` and decodes the emitted frames.

- **`notify_test.go`** — `Notify` writes `{"jsonrpc":"2.0","method":…,"params":…}`
  with **no `id`** (asserted via a generic-map decode); nil params omit the key; a
  params-marshal failure returns a wrapped error and writes nothing.
- **AC-1 (emit)** — a scripted `[TextChunk, ThoughtChunk, ToolStart, ToolUpdate]`
  → four `session/update` notifications, each `{sessionId, update}` with the
  expected discriminant and content, in order, each with no `id`/`result`.
- **AC-2 (grouping)** — `[TextChunk{m1}, TextChunk{m1}, ToolStart, TextChunk{m2}]`
  → two contiguous `agent_message_chunk`, then `tool_call`, then a third
  `agent_message_chunk` — arrival order, no coalescing.
- **AC-3 (TurnEnd)** — writes no frame and calls `onTurnEnd` exactly once with
  `"end_turn"`; a nil-`onTurnEnd` sub-case → no panic, no frame.
- **AC-4 (Stall)** — writes no frame (the hard assertion is the empty transport
  writer; the stderr line is secondary).
- **AC-5 (no spawn)** — structural: neither new file references `exec`/`claude -p`/
  an Agent SDK path; imports are `acp`/`acpbridge`/`turnevent`/`slog` only.
- Plus a defensive nil-event drop.

## Out of scope (deferred)

- **Producer wiring + live turn delivery** —
  [#751](https://github.com/pyrycode/pyrycode/issues/751) (T7) stands up the
  `turnbridge` producer over the addressed session inside the held `session/prompt`
  call and feeds this sink; it also supplies the `onTurnEnd` callback that resolves
  the held call with the stop reason. #750 is the sink only.
- **Held-`session/prompt` resolution mechanism** — the hold-and-resolve primitive
  ([#765](https://github.com/pyrycode/pyrycode/issues/765)'s `Responder`) and its
  wiring live in #751; #750 only *signals* via `onTurnEnd`.
- **Explicit `agent_message_chunk` message boundaries** — ACP has no per-message
  delimiter today, so distinct claude messages within one turn concatenate
  host-side. The discarded `msgID` is the hook if a future ACP revision needs it;
  no AC asks for it.
