# Ticket #753 — `session/cancel` interrupt + `session/set_mode` / `session/set_config_option` single-mode pin

The **inbound control** surface for `pyry acp`. `session/cancel` now *actuates*
the interrupt onto the seam [#762](762.md) left as a resolve-then-discard stub,
and `session/set_mode` / `session/set_config_option` get defined, advertised
answers under a **single-mode pin** — resolving [ADR 027](../decisions/027-acp-mapping.md)
Open Item #1. The turn cancel interrupts runs on the one live interactive
`claude`; cancel routes a single ESC keystroke into it and introduces no
`claude -p` / Agent SDK path (the ADR 025/026 hard cost invariant).

Epic [#600](https://github.com/pyrycode/pyrycode/issues/600), T9. Blocked by
#762 (CLOSED, provided `resolveCancelTarget`). Not security-sensitive — inbound
control over local stdio to a co-located, user-launched host; no
auth/crypto/network/remote-frame surface. Spec:
[`specs/architecture/753-acp-cancel-mode-config.md`](../../specs/architecture/753-acp-cancel-mode-config.md).

## Implementation

**3 existing files touched, 0 new files, 0 new exported types** (every new
type/const is unexported in package `main`): `cmd/pyry/acp.go` (+54/−14),
`cmd/pyry/acp_handshake.go` (+66), `cmd/pyry/acp_test.go` (+148).

### `session/cancel` → actuate the interrupt (AC-1)

A consumer-declared one-method seam in package `main`, mirroring
[`relay.Interrupter`](../features/acp-package.md):

```go
type interrupter interface{ SendEsc() error } // *supervisor.Supervisor satisfies it (#726)
```

`cancelSessionHandler`'s signature changed from `(pool *sessions.Pool)` to an
**injected resolver** `(resolve func(json.RawMessage) (interrupter, error))`:

- resolve error → `return nil, err` — `dispatchNotification` logs it once and
  writes no response frame (unchanged from #762);
- success → `_ = intr.SendEsc()` **best-effort**, then `(nil, nil)`.

`resolveCancelTarget` is **unchanged** (still returns `*supervisor.Supervisor`).
The composition root (`serveACPWithPool` register closure) wires the resolver and
**returns a true `nil` interface on error** — `resolveCancelTarget`'s typed
`*supervisor.Supervisor` would otherwise wrap a nil pointer in a non-nil
`interrupter`. `SendEsc` is the interrupt lever ("cancel an in-flight turn",
[#726](726.md)), the same lever the mobile `interrupt` / `modal_cancel` frames
route through (`relay.handleInterrupt`).

**Why swallow the `SendEsc` error instead of returning it.** A `SendEsc` failure
(no live turn / mid-teardown → `ErrNoLiveSession`) is swallowed: there is nothing
to roll back and a notification owes no reply. Returning it would make
`dispatchNotification` log a *second* `"acp: notification handler error"` on the
known-id path whenever the fake-claude session isn't keystroke-ready — breaking
`TestACP_SessionCancel_NotificationEmitsNoResponse`'s existing `count == 1`
assertion and adding non-deterministic noise. Best-effort matches
`relay.handleInterrupt` and keeps the known-id path silent.

**Not routed through the neutral `turnevent.Cancel`.** That type ([#707](707.md))
is *declared vocabulary* whose consumers are told not to construct it; the
architect chose to call the concrete `SendEsc()` lever directly.

### Mode/config — single-mode pin (AC-2/AC-3, ADR 027 Open Item #1)

There is no neutral-model mode source and no tui-driver lever to toggle claude's
plan/edit mode (the [#726](726.md) keystroke seam is `SendEsc`/`Answer`/`AcceptTrust`
only). A real `set_mode` would need new tui-driver + supervisor surface — out of
scope, past size. **Decision: pin one mode.**

Unexported types + a pinned constant in `acp_handshake.go` (as "advertised
surface"):

```go
const pinnedModeID = "default"
type sessionModeState struct { CurrentModeID string; AvailableModes []sessionMode }
type sessionMode      struct { ID string; Name string }
func pinnedModeState() sessionModeState // {currentModeId:"default", availableModes:[{id:"default", name:"Default"}]}
```

- **`newSessionResult` gains one `Modes sessionModeState` field**, populated from
  `pinnedModeState()` at *both* construction sites (`session/new` **and**
  `session/load`). A single self-referential `availableModes` entry offers a
  compliant host no alternative to switch to — the faithful "not a switch that
  does nothing." (`acpReply.Result` already decodes the additive field; no
  existing test breaks.)
- **`setModeHandler`** (stateless, no pool — the pin is process-global): decode
  `{sessionId, modeId}`; unmarshal failure → `CodeInvalidParams` ("invalid
  params"); `modeId == pinnedModeID` → success with empty result (`setModeResult{}`
  → `{}`); any other `modeId` → `CodeInvalidParams` ("unsupported session mode").
- **`setConfigOptionHandler`** (stateless): always `CodeInvalidParams` ("no
  configurable options") — no params decode. Deliberate asymmetry with mode: pyry
  has a real, nameable *mode* but no real *config* surface.
- Both are ACP **requests** → `dispatchRequest` writes exactly one response (the
  empty result on accept, or the `CodeInvalidParams` frame on reject) — the
  "defined result" AC-2 requires.

**The `initialize` / `agentCapabilities` handshake is unchanged.** ACP carries no
mode flag there, so the ticket's `acp_handshake.go` *advertisement* pointer is
corrected: the pin surfaces in the **session responses**, not the handshake. (The
stateless mode/config *handlers* live beside the handshake handlers because they
need no pool.)

## Patterns established

- **Consumer-declared one-method seam → deterministic, two-halves cancel proof.**
  The `interrupter` seam (like `relay.Interrupter`) makes the actuation
  unit-testable with a double, while routing correctness stays in
  `resolveCancelTarget`'s own pointer-equality test ([#762](762.md)). Together the
  two halves prove "the interrupt reaches the *correct* session's supervisor"
  with **no brittle live-PTY keystroke observation** — belt-and-suspenders, both
  deterministic.
- **A notification's best-effort actuation swallows, never returns.** On the
  notification path a returned error double-logs via `dispatchNotification` and
  there is nothing to roll back — so `_ = intr.SendEsc()`. (Distinction worth
  noting: this is *silent-swallow*, whereas the mirrored `relay.handleInterrupt`
  `Warn`-logs before tolerating — the handler has no logger in scope and
  observability is deferred, evidence-based.)
- **Advertise a pin where the protocol carries the state, not where it's
  convenient.** ACP `initialize`/`agentCapabilities` has no mode flag; the pin
  belongs in `SessionModeState` on the `session/new`/`session/load` responses. One
  self-referential entry is the honest "no switch that does nothing."
- **Mode ≠ config asymmetry.** pyry answers `set_mode` with a real advertised mode
  but rejects `set_config_option` wholesale — it exposes no config surface, so
  there is nothing to advertise.
- **True `nil` interface on a resolver error.** Returning a typed
  `*supervisor.Supervisor` (even nil) wraps a non-nil interface value; the closure
  returns a bare `nil` so a future `intr == nil` check would be safe.

## Code review

**PASS** — [PR #772](https://github.com/pyrycode/pyrycode/pull/772). `make check`
green; real-claude e2e green (`ok internal/e2e/realclaude 153.703s`, no flake).
Two **NITs**, neither blocking, neither actioned:

- The closure comment says returning `sup, err` would "defeat the handler's err
  short-circuit." The handler actually branches on `err != nil` (not on
  `intr == nil`), so a typed-nil interrupter paired with a non-nil error would
  *still* short-circuit safely. The true-`nil`-interface return is good hygiene
  regardless (robust if a future refactor nil-checks `intr`) — only the comment's
  stated mechanism is slightly off.
- `_ = intr.SendEsc()` swallows silently, whereas `relay.handleInterrupt`
  `Warn`-logs before tolerating. Deliberate and spec-recorded (double-log
  avoidance, no logger in scope, observability deferred) — faithful to
  best-effort, noting only that it is silent-swallow, not log-and-tolerate.

## Lessons learned

- **Wiring the resolver closure must `return nil, err` explicitly, not the typed
  `*supervisor.Supervisor`.** A typed nil pointer wrapped in the `interrupter`
  interface is non-nil. *(Lifted from the PR body; reconciled with code-review
  NIT #1: the current handler branches on `err != nil`, so the guard is
  defensive hygiene for a future refactor — not load-bearing today, but correct
  to keep.)*
- **On the notification path, the best-effort `SendEsc` swallow is what keeps the
  `count == 1` log assertion green.** Returning the error would make
  `dispatchNotification` emit a second handler-error log on the *known-id* path
  whenever the fake-claude session isn't keystroke-ready — a real test break plus
  non-determinism. The swallow is a correctness decision, not just tidiness.
- **The ticket's advertisement pointer was wrong and had to be corrected.** It
  pointed at `acp_handshake.go` / `agentCapabilities` for the mode pin; ACP has no
  mode flag in `initialize`, so the pin lives in the `SessionModeState` of the
  session responses instead. Recorded in ADR 027 Open Item #1.

  package-`main` `fakeInterrupter{escCalls, err}` double. Table: resolved →
  `escCalls == 1`, `(nil, nil)`; resolve error → `escCalls == 0`, error returned

  swallow).
- **`TestResolveCancelTarget`** (kept from #762, unedited) — AC-1 routing half:
  params → the correct session's supervisor by pointer equality.
- **`TestACP_SessionCancel_NotificationEmitsNoResponse`** (unchanged) — the
  known-id cancel now calls `SendEsc` (swallowed, logs nothing); the `count == 1`

- **`TestACP_SetMode`** (new) — AC-2 mode half through the harness: `modeId:"default"`
  → success frame with `"result":{}`; `"plan"` / `""` / non-string / array params

- **`assertPinnedModes`** helper + AC-3 assertions folded into the existing

## Out of scope (deferred)

- **End-to-end cancel → `stopReason: cancelled`** → **#751** (T7). The held
  `session/prompt` call is resolved with the mapped stop reason on `TurnEnd`;
  there is no held prompt to resolve until #749/#765 land. This ticket asserts
  **only** that the interrupt reaches the supervisor.
- **A real per-session mode switch** — no tui-driver lever exists. If a future
  ticket makes mode per-session, `set_mode` would gain a `Pool.Lookup` like
  `resolveCancelTarget`.
- **Sourceless outbound `current_mode_update` / `config_option_update`** — never
  emitted under the pin (no mode/config ever changes); the synthesize-vs-omit call
  stays parked in [ADR 027](../decisions/027-acp-mapping.md) Open Item #2 (outbound
  cluster, #750/#769).
- **Observability of a swallowed `SendEsc` failure** — deferred, evidence-based
  (no observed need; the host learns the turn's real outcome via the outbound stop
  reason, #751).
