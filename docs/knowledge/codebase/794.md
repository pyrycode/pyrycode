# Ticket #794 — Live e2e capstone: phone interrupt stops the running turn

The **[EPIC #597] Phase 3 live exit gate** for the remote-interrupt feature (split
from [#708], mirrors the Phase 2 capstone [#642] and the sibling [#792] queue-drain /
[#791] modal live capstones). Over **one daemon + a real (fake) claude that is
genuinely mid-turn**, it confirms **live** what [#707] (the `interrupt` wire type +
`Interrupter` seam + Esc routing) and [#726] (the sealed `supervisor.SendEsc()`
keystroke) proved **deterministically** upstream: a phone-originated `interrupt`
reaches the supervised claude as an Esc and **causes** the running turn to stop, and
the daemon reports the turn stopped to the phone. It **confirms; it does not
re-prove** — the correctness oracle stays upstream ([#707]'s unit tests).
**Test/harness only** — the interrupt production path already shipped and is wired
live (`cmd/pyry/relay.go` sets `Interrupter: sup` on the `V2SessionConfig`).

**`security-sensitive`** — the adversarial question is not "does this introduce a
vuln" but **"could this test PASS while the guarantee is broken?"** Architect
spec-stage self-review verdict **PASS, no MUST FIX**; code-review **PASS** (one FLAG —
a pre-existing environmental realclaude red, not attributable to this diff — and one
NIT — an unavoidable detector duplication across the `package main` boundary; no
rework).

## Single flow — no split on the causal chain

AC1 (mid-turn), AC2 (Esc received), AC3 (turn stopped *by* the interrupt) are **one
causal chain in one run**, not three tickets. Splitting them produces vacuous halves:
a "turn stopped" with no proof it was ever running, or an "Esc received" with no proof
it did anything. The [[po-interrupt-live-capstone-cause-not-coincidence]] intake note
and [[po-plus-title-capstone-is-one-flow]] shape both apply — the AC boundaries are
vacuous-pass couplings, not split seams. One test, one ticket, held at **S**.

## What was missing over #707 / #726 / #642

[#707] proved the wire type + `interactive`-gated `handleInterrupt` + Esc routing with
**unit tests**; [#726] sealed `SendEsc()` as the one-lone-`0x1b` keystroke surface;
[#642] proved the live two-phone structured-receive machinery. What **none** proved is
the **live causal** behaviour: over one running daemon and a real supervised child
that is genuinely mid-turn, a phone `interrupt` reaches claude as an Esc and the
running turn ends **because of that Esc**. The naive way to build this — reuse [#792]'s
busy→idle-by-**file** flip — would pass **vacuously**: the idle would come from the
trigger file, not the interrupt. Making the **Esc byte itself** the cause is the one
real design decision this ticket lands (the PO flagged it at intake as the architect's
call; [[architect-interrupt-live-capstone-esc-drives-turnend]]).

### fakeclaude: `PYRY_FAKE_CLAUDE_ESC_ENDS_TURN` — the Esc *is* the cause

The mechanism that makes the interrupt the **cause** of the turn ending (not a
coincidental idle). When the flag is set:

- **Raw mode.** fakeclaude enters raw mode (`enterRawMode`, like modal mode) so the
  lone interrupt ESC is not withheld by the canonical line discipline — see the
  Lessons below; this is the non-obvious load-bearing detail.
- **Bare-ESC scan.** The stdin reader watches each `os.Stdin.Read` buffer for a **bare
  ESC** — a `0x1b` that is *not* the lead byte of a CSI/bracketed-paste sequence.
  `containsBareESC` rule: a `0x1b` at index `i` is bare iff `i == len(buf)-1` (last
  byte) **or** `buf[i+1] != 0x5b` (`'['`). In this harness the stdin stream carries
  exactly three ESC sources — bracketed-paste open (`ESC[200~`), close (`ESC[201~`),
  and the interrupt's lone `0x1b` — and **only the interrupt is bare** (the delivered
  prompt content is raw-ESC/C0-free per [#749]'s paste-content guard, so it
  contributes no `0x1b`).
- **Signal, don't write.** On the first bare ESC the reader sets `escPending
  atomic.Bool` (signal only — the reader **never** writes `f`, preserving
  single-writer-of-`f`, exactly like the shipped `turnPending`). The main poll loop,
  gated on the mode and a one-shot `escEnded` bool, does `if escPending.Swap(false) {
  appendTurnEnd(f); escEnded = true }`.
- **`appendTurnEnd`** grows the live session JSONL by one canned assistant `end_turn`
  line (`interruptEndTurnLine` = `{"type":"assistant","message":{"id":"interrupt-end",
  "stop_reason":"end_turn","content":[{"type":"text","text":"[interrupted]"}]}}`) and
  fsyncs — the exact shape `turnbridge`'s mapper needs for `EventKindJsonlEndOfTurn`
  (assistant + `stop_reason=="end_turn"` + non-empty text). The daemon's
  structured-turn producer tails it → `turnevent.TurnEnd` → `turn_end` envelope. **One
  shot** (a second Esc is inert — a re-interrupt of an already-ended turn is a no-op,
  matching claude).

**Coexists with `PYRY_FAKE_CLAUDE_TUI`** (unlike [#792]'s idle-trigger, which is
*mutually exclusive* with TUI). The two touch different bytes: TUI emits the startup
`❯` + one spinner on first stdin; the ESC detector scans for the bare ESC. This test
runs both ON — TUI so `WaitReady` confirms fast and the `send_message` ack is prompt
(the [#642] posture), Esc-ends-turn so the interrupt drives the flip. **No new glyph,
no `cmd/substrate-guard` allowlist change** — `interruptEndTurnLine` is inert JSONL
data, not a TUI substrate rune. The evergreen mode reference is
[fakeclaude-binary.md § Esc-ends-turn mode (#794)](../features/fakeclaude-binary.md).

### The test choreography (`TestRelayV2_InterruptStopsRunningTurn`)

Lifts [#642]'s structure: one interactive phone, one daemon, a real Noise session.

1. **Seed the harness as [#642]:** pair one interactive device →
   `decodePairPayload`; `seedBoundConversation(home, knownConvID, initialUUID)` (so
   `send_message`'s `router.Route` resolves and `WriteUserTurn`'s
   `ValidateConversation` gate passes → the supervisor cursor stamp lands, [#678]);
   align `sessionsDir = <HOME>/.claude/projects/encode(HOME)`, `MkdirAll` it, and
   **pre-create `<initialUUID>.jsonl`** (`{}\n`) so the producer resolves at a tiny
   offset at startup and every appended line lands in the tailed range (the [#642]
   cold-start recipe).
2. **Start fakeclaude TUI + Esc-ends-turn:** `StartRotationWithRelay(...,
   "PYRY_MOBILE_V2=1", "PYRY_FAKE_CLAUDE_TUI=1",
   "PYRY_FAKE_CLAUDE_JSONL_TRIGGER="+jsonlTrig,
   "PYRY_FAKE_CLAUDE_ESC_ENDS_TURN=1")` — `rotateTrigger` a path never created;
   `jsonlTrig`/`stdinLog` distinct temp paths.
3. `waitBinaryHello`; `fakephone.Dial`; `driveHandshakeToOpenDaemonInteractive`
   (grants `interactive` — the capability both the structured stream **and**
   `handleInterrupt` require).
4. **Start the turn:** send one **plain-ASCII** `send_message` and await its sealed ack
   (the [#642] fence — `WriteUserTurn` ran → the cursor is stamped → the emitter
   addresses envelopes). Plain-ASCII so its bracketed paste is atomic and contributes
   **no bare ESC** to the stdin log — only the later interrupt does.
5. **[AC1] Establish + observe the mid-turn window:** drop the JSONL trigger with a
   **single** assistant-text line (no `stop_reason` → `TextChunk` →
   `turn_state{State:"responding"}`). Drain phone A until a `turn_state` with
   `State != "idle"` — the turn is provably running / had **not** already ended.
   **Vacuous-pass guard #1:** `t.Fatal` (naming the "harness never started a turn"
   mode) if none seen before a ~20 s deadline.
6. **Interrupt:** seal `protocol.Envelope{Type: protocol.TypeInterrupt}` (no payload)
   with phone A's send `CipherState` and `sendNoiseMsg`. `dispatchAppFrame` intercepts
   it → `handleInterrupt` (interactive ✓) → `SendEsc()` → a lone `0x1b` to
   fakeclaude's stdin.
7. **[AC3] Observe the turn stop caused by the interrupt:** fakeclaude's detector fires
   on the bare ESC → `appendTurnEnd` → producer → `TurnEnd` → emitter → `turn_end`.
   Drain phone A until a `turn_end` (`ConversationID == knownConvID`). **Vacuous-pass
   guard #2 (structural causality):** the test **never** drops an end-of-turn line via
   the JSONL trigger, so the *only* source of a `turn_end` is fakeclaude's bare-ESC
   handler — observing it proves the Esc was received and processed. `t.Fatal` (naming
   the "interrupt did not stop the turn" mode) if none before a ~10 s deadline.
8. **[AC2] Direct keystroke oracle:** read `stdinLog` (short bounded poll for the
   residual cross-process fsync-visibility window) and assert a **bare ESC** — a
   `0x1b` not followed by `0x5b` (`hasBareESC`, the same rule as the detector). Every
   paste marker is `0x1b 0x5b`, so a bare `0x1b` is unambiguously the interrupt. This
   is fakeclaude's own byte record; the `turn_end` (step 7) is the daemon's independent
   wire report — **two oracles, different sources**.

**Assertion order is load-bearing:** AC1 (turn running) is a precondition of the
interrupt being sent, and AC3's `turn_end` can only come from the Esc, so the positives
gate the causal claim. Steps 7 and 8 are both post-interrupt and mutually reinforcing.

### Data flow

```
phone ── send_message (plain-ASCII) ──> daemon ──ack──> WriteUserTurn → cursor stamp
   test drops JSONL trigger (1 assistant text line, NO stop_reason)
   fakeclaude appends it → producer → TextChunk → emitter → turn_state{responding} ──> phone   [AC1]
phone ── interrupt frame (no payload) ──> dispatchAppFrame → handleInterrupt (interactive ✓)
   → supervisor.SendEsc() → lone 0x1b ──> fakeclaude stdin
   fakeclaude containsBareESC → escPending → appendTurnEnd(f) (canned end_turn line)
   → producer → EventKindJsonlEndOfTurn → TurnEnd → emitter → turn_end ──> phone              [AC3]
   stdin log = [ ...bracketed-paste(prompt)... , 0x1b ]   (bare ESC present)                  [AC2]
```

## Patterns established

- **The Esc byte itself drives the turn's end — structural, not temporal, causality.**
  This is the counterpoint to [#792]'s file-driven busy→idle flip and the crux the PO
  hoisted to AC1. Because fakeclaude's bare-ESC handler is the **only** source of an
  end-of-turn JSONL line — hence of the `turn_end` envelope AC3 asserts — and the test
  never drops an end-of-turn fixture, `turn_end ⟺ the Esc was received and processed`.
  A "the interrupt stopped the turn" pass over a turn that never ran, or a `turn_end`
  from any source but the Esc, is **impossible by construction**. Recorded at intake as
  [[architect-interrupt-live-capstone-esc-drives-turnend]].
- **Two ordered `t.Fatal` guards gate the causal claim.** A non-idle `turn_state` MUST
  be observed *before* the interrupt (the turn was running — AC1); a `turn_end` MUST be
  observed *after* it (the turn stopped because of the Esc — AC3). Same shape [#792]
  established for the queue-drain negative, applied to the interrupt causal chain.
- **Two oracles, different fabric.** AC3's `turn_end` is the daemon's wire report; AC2's
  bare ESC in the stdin log is fakeclaude's own byte record of what it received. The
  belt-and-suspenders is *different fabric* — one is the daemon-side structured stream,
  the other is the child-side raw keystroke log — not a second read of the same source.
- **A bare `0x1b` not followed by `0x5b` is unambiguously the interrupt.** tui-driver
  writes every bracketed-paste marker as `0x1b 0x5b …`, and the delivered prompt
  content is raw-ESC/C0-free ([#749]); `SendEsc` writes the lone `0x1b` as its own PTY
  write. So the two-arm rule (last-byte OR next `!= 0x5b`) discriminates the interrupt
  from paste markers with no ambiguity — the load-bearing fact both `containsBareESC`
  (detector) and `hasBareESC` (test oracle) key off.
- **Esc-ends-turn *coexists* with TUI mode; idle-trigger does not.** The two modes
  touch different bytes (TUI: startup `❯` + spinner; Esc-ends-turn: the bare-ESC scan),
  so a test can run both — which this one does. Contrast [#792]'s idle-trigger, whose
  withheld-startup-`❯` posture is *mutually exclusive* with TUI. When adding a future
  fakeclaude mode, check whether it fights TUI for the same bytes before declaring
  exclusivity.
- **Detector duplication across the `package main` boundary is structurally
  unavoidable.** `hasBareESC` (test) mirrors `containsBareESC` (fakeclaude) because
  fakeclaude is `package main` and the detector cannot be imported. Both are ~8 lines
  and each carries a comment noting the mirror; the code-review NIT flagged it as
  no-action. (Same shape as any `package main` helper an e2e sibling needs to
  re-derive.)
- **Harness reuse over harness build — the [#642] `extraEnv` seam pays off again.** The
  whole proof rides the *shipped* production stack (supervisor + relay + `Interrupter`
  seam + producer/emitter); the only new harness surface is the ~40-LOC fakeclaude
  mode. `StartRotationWithRelay` appends `extraEnv` verbatim, so **no `harness.go`
  change**. The build-vs-reuse call was the architect's (the [#642] reuse note); reuse
  held.

## Lessons learned

*(No **Lessons learned** section in the PR body; these are the non-obvious surprises
this ticket surfaced, captured here so a future reuse doesn't rediscover them.)*

- **A lone interrupt ESC is withheld by the canonical line discipline — the mode MUST
  enter raw mode.** TUI mode alone does **not** put stdin into raw mode; the default
  discipline buffers input until a newline, so a bare `0x1b` with no line terminator
  would sit unread indefinitely and the detector would never fire. So Esc-ends-turn
  extends the same raw-mode gate modal mode uses (`if modalTrig != "" || escEndsTurn {
  enterRawMode() }`). A naive "just add the scan to `startStdinReader`" would compile,
  run green on every *other* assertion, and silently never see the interrupt — the AC3
  `turn_end` would time out with no obvious cause. This is the load-bearing detail
  behind the whole mechanism.
- **The `turn_end` carries `StopReason == "end_turn"`, not `"cancelled"` — assert
  causality, not stop-reason semantics.** tui-driver v1.3.0's `EventKindJsonlEndOfTurn`
  cannot distinguish an interrupt-stop from a normal end
  (`internal/turnbridge/mapper.go:25-28`), so the mapper always yields `Reason:
  end_turn`. This is orthogonal to what the test proves — **causality** (the `turn_end`
  exists *only because* the Esc was received), not the reason string. The test asserts a
  `turn_end` is received and **does not** assert `StopReason` (that would fail on a
  tui-driver limitation, not a real defect). A distinct interrupt reason is an
  epic-#597 follow-up (§ Out of scope).
- **The `i == len(buf)-1`-is-bare arm relies on paste-marker write atomicity.**
  tui-driver writes each bracketed-paste marker as one `writeRaw` of the whole
  `ESC[200~…ESC[201~\r` unit, so a paste marker's `0x1b` is never the *last* byte of a
  read (its `[` always follows in the same read); `SendEsc` writes the lone `0x1b`
  standalone. The test keeps the prompt short and plain-ASCII to guarantee that. A
  future multi-KiB prompt whose paste could split across `os.Stdin.Read` buffers
  exactly on a marker's `0x1b` would need a one-byte cross-buffer carry — **not built**,
  but flagged in the detector comment so a larger-prompt reuse adds it rather than
  rediscovering the edge. (Note: a split would **fail**, not vacuously pass — `escEnded`
  is one-shot and the AC3 guard would fire.)

## AC4 (flight recorder) — scoped out of CI, mirrors #792 AC4 / #791 AC5

AC4 ("The run is recorded by the flight recorder for the audit trail") is **not
assertable by this test in any variant**, and the scoping is an architect
clarification, **not PO rework** — the siblings [#792]/[#791] already resolved the
identical AC this way:

- The flight recorder (`.cast` capture) lives in `internal/agentrun/ptyrunner`, gated
  on `PYRY_RECORD_DIR`, reached **only** from the `pyry agent-run` / dispatcher path.
  The interrupt flow is a **mobile-relay** flow: claude is hosted by
  `internal/supervisor`, which wires no `RecordTo`/`PYRY_RECORD_DIR`. The two code
  paths are **disjoint** — no single run is both "a mobile interrupt" and "recorded by
  the flight recorder." Per [[po-audit-artifact-ac-check-harness-reachability]], the
  architect scopes the AC to the variant whose import reaches the artifact — here,
  **none** on the mobile path.
- **Disposition:** the CI test asserts **AC1–AC3**. AC4 is deferred to the operator
  live run ([mobile-live-e2e-runbook.md](../features/mobile-live-e2e-runbook.md)),
  consistent with the siblings. It is **not** a developer deliverable and required no
  test code.

## Testing

One new `//go:build e2e` test asserting AC1–AC3 in a single run, plus one untagged
detector unit test; **no production runtime change** (the change is a default-off
test-only fakeclaude mode).

- **AC1** (mid-turn positive check) — step 5: a `turn_state` with `State != "idle"`
  decoded on phone A **before** the interrupt; `t.Fatal` on absence.
- **AC2** (Esc reaches claude) — step 8: a bare ESC (`0x1b` not followed by `0x5b`) in
  the stdin log; the direct keystroke oracle.
- **AC3** (turn ends *because of* the interrupt) — step 7: a `turn_end` on phone A whose
  only possible source is fakeclaude's bare-ESC handler (structural causality);
  `t.Fatal` on absence.
- **Vacuous-pass guard** — the two ordered `t.Fatal`s make an "interrupt stopped the
  turn" pass impossible over a turn that never ran or a `turn_end` from anywhere but the
  Esc.

Gates green (developer + code-review): `go build ./cmd/pyry`, `go vet ./...`,
`staticcheck ./...`, `go test -race ./...`, `make substrate-guard`, and
`go test -tags=e2e -race -run TestRelayV2_InterruptStopsRunningTurn ./internal/e2e/...`
→ **PASS (~2.8 s), non-vacuous** (AC1/AC2/AC3 log lines fired, not skipped).
Code-review ran the e2e itself (QA does **not** compile `-tags=e2e`, so code-review is
the first place it builds — the [#642]/[#680] CI coverage-gap note).
