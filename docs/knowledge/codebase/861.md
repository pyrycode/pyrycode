# Ticket #861 — e2e: centralize bootstrap-id seeding behind `seedBootstrapRegistry`

Prep for #839 (deterministic bootstrap `--session-id`, which removes the
startup adopt-by-mtime path). Roughly 15 e2e test files established the
daemon's bootstrap session id implicitly — pre-create `<initialUUID>.jsonl`,
let `reconcileBootstrapOnNew` rotate the cold-started bootstrap id onto it at
startup. #839 deleting that scan would break all of them at once; doing so
interleaved with the behavior change and a red-suite triage loop is what
timed out the developer stage on 2026-07-08. This ticket does the mechanical
migration up front with **zero production behavior change**, so #839 shrinks
to the actual behavior change.

## Implementation

One new helper, five call sites, no test bodies touched (S):

- **`internal/e2e/harness.go`** — new package-internal `seedBootstrapRegistry(t,
  home, bootstrapUUID)`. Mirrors the sibling `seedBoundConversation` idiom
  exactly: raw JSON string (not `restart_test.go`'s `registryFile` type —
  that's `e2e`-only, but `harness.go` also compiles under `e2e_install`, so
  referencing it would break that build), fixed past timestamp
  `2026-01-01T00:00:00Z`, `os.MkdirAll(0o700)` + `os.WriteFile(0o600)` into
  `<home>/.pyry/test/sessions.json`, `t.Helper()` + `t.Fatalf` on error.
  Writes a single `bootstrap:true, lifecycle_state:"active"` entry so
  `Pool.New`'s warm-start branch (`pickBootstrap`) picks it directly —
  `reconcileBootstrapOnNew` still runs afterward but no-ops (`mostRecent ==
  current` or empty dir), so post-startup state is identical to today's
  cold-start-then-reconcile path.
- **Call sites** — `seedBootstrapRegistry(t, home, initialUUID)` added
  immediately before the daemon spawn in `StartRotation`,
  `StartRotationWithRelay` (both `harness.go`), `startPerConvHarness`
  (`per_conversation_eviction_test.go`), `startEvictionHarness`
  (`respawn_after_eviction_test.go`), and inline before `StartInWithEnv` in
  `relay_v2_dequeue_test.go` (the one test with no shared rotation
  constructor). These four constructors plus the one inline site cover all
  ~14 dependent files — no test body edits needed.
- **`<initialUUID>.jsonl` pre-creates were left in place everywhere**,
  deliberately. In the growth-confirm relay tests they're still the
  delivery-confirm baseline (#668/#838); in the reconcile-only tests
  (rotation, per-conv, dequeue) they're now a redundant confirming no-op.
  Removing them would break diff uniformity for no benefit here — a natural
  cleanup for #839, which deletes `reconcileBootstrapOnNew` itself.

Zero production files touched. `reconcileBootstrapOnNew`, `mostRecentJSONL`,
`Pool`, `cmd/pyry` are all unchanged.

## Lessons learned

- **The spec's suggested build-tag verification (`go build -tags e2e_install
  ./internal/e2e/...`) does not compile on `main`, independent of this
  ticket.** `harness.go` (`e2e || e2e_install`) references `safeBuffer`,
  defined only in `auto_attach.go` (`e2e`-only); `auto_attach.go` in turn
  references a test-only helper. `go build` skips `_test.go` files, so the
  reference only resolves under the test compiler — meaning `go build
  -tags e2e_install` on this package is structurally impossible on *any*
  branch, not something #861 broke. Confirmed identical on `merge-base
  main`. The real hazard check (`seedBootstrapRegistry` must not reference
  `registryFile`, which is genuinely `e2e`-only) is satisfied — it uses
  only `os`/`filepath`/`testing`. **The correct compile-check for this class
  of hazard is `go test -tags e2e_install -count=0 ./internal/e2e/...`** (or
  plain `-tags e2e`), not `go build`; future specs touching `harness.go`
  should cite that form instead.
- **`TestRelay_Roundtrip_Appendix` is flaky under the full `-tags e2e` suite
  in parallel** (timing-sensitive, unrelated to bootstrap seeding — passes
  3/3 in isolation via `-run '^TestRelay_Roundtrip_Appendix$' -count=3`).
  Not one of this ticket's migrated call sites and not a regression; noted
  here since it surfaced during this ticket's full-suite QA run.
