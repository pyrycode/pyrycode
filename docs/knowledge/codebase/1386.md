# Ticket #1386 — carry thinking progress to a mobile client

Wires `turnevent.ThinkingProgress` (shipped unwired by #1385) to a mobile client as a new `thinking_progress` v2 frame. Before this ticket the event reached nothing: `turnbridge.MapEvent` returned `ok == false` for the variant and `cmd/pyry/interactive_turn_v2.go`'s type switch had no case, so it fell to `default:` and was debug-logged as `kind="unknown"`. A phone showing "thinking" for a long turn had no way to distinguish a slow answer from a wedged session — claude's `system/thinking_tokens` line is its only mid-turn proof of life on the stream-json surface. Split from #1263.

## Implementation

- **`internal/protocol/codes.go` / `interactive.go`** — new own const block `TypeThinkingProgress = "thinking_progress"` and `ThinkingProgressPayload{ConversationID, EstimatedTokens, EstimatedTokensDelta}`, all three fields always present (no `omitempty`), no `TruncatedFields` (the event carries no claude-authored text at all, so a permanently-nil field would claim a bound that does not exist). Named after the daemon's own variant, not claude's `thinking_tokens` subtype — `TestThinkingProgressType_IsNotClaudesSubtype` pins that with a substring check on the constant, not just an exact-literal match.
- **`internal/protocol/compat_test.go` / `relay_guard_test.go`** — the three standard drift-detector sites (`TestIsKnownAppType` rejected row, `v2OnlyTypes` entry, `TestTypeConstants_V1V2Partition`'s `all` slice) plus `relay_guard_test.go`'s `excludedTypes["TypeThinkingProgress"] = "push"`, landed in the same commit as the constant — `TestEveryInboundV2TypeHasHandler`'s Assertion #3 enumerates every `Type*` in `codes.go` and fails any unclassified one.
- **`internal/turnbridge/outbound.go`** — one additive `MapEvent` case after the `BackgroundTaskRoster` arm: conversation identity only, `tc.TurnID`/`tc.Seq` ignored (the payload has no field for either — a periodic reading of an inference request in flight is not a turn-scoped fact). Both ints cross verbatim including the zero value `{0,0}`, a legitimate reading exactly like `ApiRetryPayload`'s `{0,0}` "count unknown"; no second suppression filter, since one would silently diverge from the producer's own rate bound (`streamsup.minThinkingTokensPerEvent = 64`).
- **`cmd/pyry/interactive_turn_v2.go`** — one handler `case` taking the exact two-line shape of the `ApiRetry`/`Compacting`/`Unrecognized`/background-task peers: `flushDelta(ctx)` then `emitMapped(ctx, convID, ev)`, **no** `startTurnIfNeeded`/`transitionTo`/`endTurn`. Deliberate: thinking progress is a *reading*, not a state transition (the turn's thinking state is already reported by `turn_state: thinking`, driven by `ThoughtChunk`), and the parser emits these during an inference request that may not have produced any assistant content yet, so a turn opened on one would have no guaranteed end. One `eventKind` arm returns the variant name literal `"thinking_progress"` — feeds the log discriminant on the *other* 7 call sites (`acp_turn_stream.go`, `stream_turn_busy.go`, `stream_turn_drain.go`), not this file's own switch, which already claims the variant via the handler case above.
- **`docs/protocol-mobile.md`** — new `#### thinking_progress` subsection (field table + all five required consumer-hazard statements with their measured numbers, ported from `turnevent.ThinkingProgress`'s doc comment, the designated source of truth) placed after `background_task_roster` and before `session_transition`. Plus four correction sites the ticket's insertion table didn't name up front: both stale "twelve turn-stream events" literals (§ opener, `session_transition`'s own exclusion sentence) corrected to **thirteen**; the application-message-types registry row for `thinking_progress`; the `unrecognized_message` two-tier explanation's claim that `thinking_tokens` "still stops at the daemon boundary" — now false, rewritten to say all four mapped `system` subtypes reach the wire; and a dated changelog entry.
- **Test coverage** — `internal/turnbridge/outbound_test.go` gained `TestMapEventOutbound` rows including one asserting a populated `TurnID`/`Seq` appear **nowhere** in the payload (the "not turn-scoped" claim under test, not just comment). `cmd/pyry/interactive_turn_v2_test.go` gained: no-turn-open / mid-turn-with-buffered-text / drive-one-event-past-it rows mirroring the #1385 unpinned-accumulator-guard shape (the assertion that actually bites is the *next* event after the frame carrying the same `turn_id` and continuing the same `seq`, not a frame-local check that would pass even if the handler had called `endTurn`), and an ordinary-turn-gains-no-traffic row asserting the exact pushed-type sequence unchanged. `internal/turnbridge/mapper_test.go` gained `TestMapEvent_PtySurfaceNeverProducesThinkingProgress`, looping the full contiguous `tuidriver.EventKind` iota (`EventKindUnknown` … `EventKindError`, confirmed 19 members not the spec's stated 18 — see Lessons) and asserting no kind ever produces a `ThinkingProgress` event or a `TypeThinkingProgress` frame; the loop bound is explicitly not load-bearing since `mapEvent`'s own `default: return nil, false` covers any future enum growth.

## Patterns established

- **A single two-int frame with no producer dependency gap ships vocabulary and mapping in one slice**, the #1074 (`api_retry`/`compacting`) template rather than the background-task family's #1393/#1394 split. The split exists to let an independent producer ticket land first; when the producer (#1385) is already merged and the frame carries no free text needing separate truncation design, splitting buys nothing.
- **The "drive one event past the frame" test row is the one that actually falsifies a lifecycle-mutation regression.** A frame-local assertion (`inTurn`/`turnID` unchanged immediately after the frame) passes even against a handler that calls `endTurn()`, because the damage only becomes observable on the *next* event, when a fresh turn gets minted. This is now the second ticket (after #1385's own accumulator guard) to need this shape — worth reaching for by default whenever a handler case's contract is "touches no state."
- **A doc section can require *reversing* a neighboring section's own prior claim, not just adding new prose.** The `unrecognized_message` two-tier explanation asserted `thinking_tokens` "still stops at the daemon boundary" as of #1394's edit; this ticket's own change falsifies that sentence, so the doc site list included a rewrite of prose #1394 had just written, not only new content for this ticket's own subsection.

## Lessons learned

From the PR body (#1398) and code review (verdict PASS, one SHOULD FIX, several NITs):

- **A spec's enumerated-member count can be off by one from the library's actual export.** The architecture doc's AC4 test note stated `tuidriver.EventKind` has 18 members; it has **19** (`EventKindUnknown` = 0 … `EventKindError` = 18). Harmless here because the loop bound (`k <= EventKindError`) and the test's own comment don't hardcode the count — but worth an explicit re-count against the actual `const` block rather than trusting an inherited number, even one the architect measured directly, when a one-line verification is available.
- **`gofmt -l` repo-wide is not a clean-diff signal on this repo.** Dirty on `main` for ~25 files unrelated to this change — the same class of pre-existing baseline noise seen before in `internal/e2e/realclaude`. Scope any formatting check to the PR's own diff, not a repo-wide sweep.
- **[SHOULD FIX, unfixed]** `internal/protocol/interactive.go:307` — `ThinkingProgressPayload` is wedged between `BackgroundTaskRosterPayload.MarshalJSON` and `BackgroundTask`, splitting the #1394 family from its own row type and making the new payload's "unlike every sibling above" doc claim imprecise (`BackgroundTask.Description` is a text-carrying sibling now sitting *below* it). Moving the block after `BackgroundTask` is equally append-only and restores both properties. Left as-is: one placement nit, well under the review's three-finding gate.
- **[NIT, unfixed]** `cmd/pyry/interactive_turn_v2.go`'s `emitMapped` doc comment still enumerates the old unreachable-`ok==false` variant list without `ThinkingProgress` — pre-existing debt (the list was already missing `Unrecognized` and #1394's three background-task variants before this PR; see [codebase/1394.md](1394.md)'s own unfixed NIT on the same comment). Worth fixing the whole list in one pass whenever the function is next touched, rather than each ticket adding its own omission.
- **[handoff, discharged by this documentation pass]** Code review flagged that `docs/knowledge/features/turnbridge-package.md`'s `MapEvent` table listed neither `thinking_progress` nor #1394's three background-task rows — pre-existing drift the documentation phase's column. Fixed here: all four rows added.
