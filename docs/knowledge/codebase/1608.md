# Ticket #1608 — key the context-window usage reader by session id

Split from #1587. `snapshotUsageFor` (`cmd/pyry/snapshot_usage.go`) builds the relay's `SnapshotUsage` seam — the reader behind `used_tokens`/`window_tokens` on both the `screen_snapshot` and `session_settings` replies. It used to resolve its transcript by id, but closed over a construction-time bootstrap-id function, so one reader could only ever answer for the bootstrap session. This moves the id from that closure to a per-call argument — the prerequisite for reporting a resolved conversation's own occupancy instead of only the bootstrap's (that reporting itself is #1609's job, not this ticket's). No reported value moves and the wire stays byte-identical: the sole production call site still binds the bootstrap id.

## Implementation

- `snapshotUsageFor(dir string) func(id string) (usedTokens, windowTokens int)` — the by-id reader. Returns `nil` iff `dir == ""`. The nil-dir guard stays *inside* the reader rather than moving to the wiring point: with an empty `dir`, `transcript.StatByID` would `filepath.Join` a **relative** `<id>.jsonl` against the daemon's working directory, and a stray same-named file there would be read and reported as a session's occupancy. The guard is what prevents that, so it belongs where the join happens.
- `bootstrapSnapshotUsage(dir string, bootstrapID func() string) func() (usedTokens, windowTokens int)` — new wiring-point seam builder, mirroring the in-file `boundSessionIDForActive` precedent (a named, unit-testable resolver pulled out of otherwise-untestable wiring). Calls `snapshotUsageFor(dir)`, then returns `nil` if either the reader or `bootstrapID` is nil. The nil check happens at **build** time, before any closure exists, so no path can invoke a nil id source — structural, not a promise.
- `cmd/pyry/relay.go`'s `startRelayV2` now calls `bootstrapSnapshotUsage(w.claudeSessionsDir, w.bootstrapIDFn)` instead of `snapshotUsageFor(w.claudeSessionsDir, w.bootstrapIDFn)`. The `SnapshotUsage:` field, its comment, and `V2SessionConfig.SnapshotUsage`'s type are otherwise untouched; the comment was updated to name `bootstrapSnapshotUsage` as the builder and note the third nil condition (no id source).
- The three failure classes and their single fresh-session-report outcome are unchanged: empty/malformed id → rejected inside `ValidStem` before any filesystem access; transcript not yet written → `ENOENT`; resolved path stats clean but fails to read → `contextwindow.Read` error, recovered via `contextwindow.Read("")`. No error ever reaches the caller; neither the id nor the resolved path reaches a log line (the reader still takes no logger).

## Patterns established

- **Split a construction-time closure into a by-argument primitive plus a named wiring-point binder**, when the binder's own nil contract (a documented-optional func field) needs to survive the split. `bootstrapSnapshotUsage` is the second instance of this shape in the file — `boundSessionIDForActive` is the first — both pulled out of `startRelayV2`, which has no test of its own and cannot cheaply get one.
- **Decide a nil-func guard at builder time, not inside the returned closure.** Checking `bootstrapID == nil` before constructing the closure (rather than inside it, per call) turns "no path can invoke a nil id source" into a structural fact: no closure holding the nil ever exists, rather than a promise that the closure is never called uninitialized.
- **A reused-reader test strengthens when the id becomes a call argument.** `TestSnapshotUsageFor_SiblingTranscriptIsNeverRead` used to build a reader over one bound id and never ask about the sibling — proving only "no directory scan happens." Under the new shape it builds **one** reader and asks it for **both** ids, asserting each returns its own transcript's figures. That is the stronger property (a genuine cross-session confidentiality pin), and it is the sole red for two distinct mutants: an argument-ignoring reader that returns a captured id's figures for both calls, and a directory-scanning reader that returns the newest file's figures for both calls.
- **A deterministic stand-in for an undrivable race, justified by measurement.** The "stats clean but fails to read" recovery branch in `snapshotUsageFor` was uncovered before this ticket (`go test -covermode=count` reported it at count 0) because every existing test row failed inside `StatByID`, leaving `path` empty — and `contextwindow.Read("")` never errors. A genuine stat-then-open unlink race isn't drivable in a unit test, so the new row seeds a **directory** at `<dir>/<id>.jsonl` for an otherwise-valid uuid: `StatByID` succeeds (a directory stats clean), `contextwindow.Read` then fails with `EISDIR` on both Linux and macOS (no `chmod` needed, so it can't silently pass as root), and `Read`'s error path returns a **zero** `Usage` — including `WindowTokens: 0` — which is what makes the `window == defaultWindow` assertion the sole red for that branch.

## Lessons learned

From the PR body:

- A `t.Mkdir` at the transcript path is a portable, deterministic stand-in for the stat-then-open unlink race: a directory stats clean so the path resolves, `read(2)` on a directory fd is `EISDIR` on both Linux and macOS, and no `chmod` is involved so it cannot silently pass as root.
- That row discriminates only because `contextwindow.Read` returns a **zero** `Usage` alongside its error — `WindowTokens: 0`, not the default window. The `window == defaultWindow` assertion is what makes it red; a `used == 0` assertion alone would pass under the mutant.
- Deciding a nil-func guard at builder time rather than inside the returned closure turns "no path invokes a nil id source" from a promise into a structural fact — there is no closure holding the nil to invoke.

## Testing

`go test -race ./cmd/pyry/` + `go vet ./...` + `make cite-guard` pass; `internal/e2e.TestRelayV2_StreamRequestSessionSettings` stays green **unmodified** (`-tags e2e -race`) — it is the no-regression half of AC #4 only: stream-mode fakeclaude binds no sessions dir and writes no transcript, so its `used_tokens == 0` assertion is zero against zero and cannot discriminate which id reached the reader. The discriminating half lives in the new `TestBootstrapSnapshotUsage/wired_reports_the_bootstrap_session's_occupancy` subtest, which seeds two transcripts with different figures in the same directory and asserts the bootstrap id's own figure comes back.

Mutation-verified via `go test -overlay` (no worktree writes): recovery-branch removal, a directory-scanning reader, and an argument-ignoring reader are each killed by a distinct, predicted assertion (see Patterns established above).
