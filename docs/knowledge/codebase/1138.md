# Ticket #1138 — Stream e2e: queued sends drain in submission order under `interactive_runner:"stream-json"`

Adds `TestRelayV2_StreamQueueDrainsInOrder` — the stream twin of the PTY
`TestRelayV2_QueueDrainsInOrder_AfterBusyTurn`
(`internal/e2e/relay_v2_queue_drain_test.go`). Proves, live and end-to-end,
that three sends submitted to the same conversation while a turn is in
flight drain to the client in submission order under
`interactive_runner:"stream-json"`, against a real spawned fakeclaude. Rides
the fakeclaude stream-json mode (#1140) and the
`StartStreamInteractiveWithRelay` harness helper (#1141). Not
security-sensitive: test-only, extends #1141's single live send to three
ordered sends behind a startup hold.

## Implementation

- `internal/e2e/relay_v2_stream_queue_drain_test.go` (new, `//go:build e2e`).
  Skeleton copied from #1141's send test, extended:
  1. Pair, `seedBoundConversation(knownConvID → initialUUID)`, start the
     stream harness with `PYRY_FAKE_CLAUDE_STREAM_HOLD=<holdPath>` (trigger
     absent — the child holds at startup).
  2. Submit three `send_message` envelopes to the **same** `knownConvID`,
     distinct markers (`e2e-1138-msg1/2/3`), back-to-back.
  3. **Vacuity gate #1:** collect all three acks before touching the
     trigger — proves the queue actually populated while the child was
     held; a missing ack before the 15s deadline is `t.Fatal` (enqueue
     rejected, not a real backlog to drain).
  4. Release: write the hold trigger. The child begins consuming stdin.
  5. **Vacuity gate #2 → ordering assertion:** drain the phone stream,
     collecting `assistant_delta` texts in arrival order (ignoring
     `turn_state`/`queue_state`/`stall`) until 3 are seen or a 20s deadline.
     Assert the three texts contain `msg1`, `msg2`, `msg3` in that order —
     out-of-order is the guarded failure (a reordering drain/pipe/emitter).
  6. Terminal close: after the third delta, a `turn_state{idle}` for
     `knownConvID` closes the test.
- `internal/e2e/internal/fakeclaude/main.go` (small additive change): a new
  env-gated, default-off startup hold, `PYRY_FAKE_CLAUDE_STREAM_HOLD=<trigger-path>`.
  When set, the stream-mode child blocks — via `waitForTriggerFile`, an
  `os.Stat` poll mirroring the existing `emit*IfTriggered` pattern — **before**
  it starts consuming stdin, at the call site immediately above
  `runStreamJSON`. `runStreamJSON`'s signature and body are unchanged, so
  `stream_detect_test.go`'s 7 call sites and the #1136/#1137/#1140/#1141
  stream specs are unaffected; env unset ⟹ byte-identical. Full detail:
  [features/fakeclaude-binary.md § Stream-path startup hold](../features/fakeclaude-binary.md#stream-path-startup-hold-pyry_fake_claude_stream_hold-1138).

## The load-bearing production fact (why a startup hold, not a msgqueue backlog)

`streamsup.WriteTurn` (`internal/streamsup/envelope.go`) writes the user-turn
envelope to the child's held-open stdin and returns `nil` on **write** — no
`WaitReady`, no commit confirm (contrast the PTY path's
`supervisor.WriteUserTurn`). So `newInboundDeliver`'s `WriteUserTurn` call
returns on write, not on turn completion, and the msgqueue's serial
per-conversation drain empties as fast as it can write bytes into the pipe.
A `queue_state` depth of N is therefore **not reliably observable** on the
stream path, unlike the PTY sibling (whose idle-trigger blocks `WaitReady`
and parks the drain so `queue_state` shows `[m1,m2,m3]`).

Submission order is instead preserved structurally by a chain of FIFO/serial
stages: FIFO drain → FIFO held-open stdin pipe → serial claude reader →
FIFO stdout → serial parser → serial emitter. The test proves this chain
directly rather than asserting on `queue_state`. Holding the child before it
starts its read loop (rather than holding an in-flight turn's *response*
open) is the only way to make accumulation deterministic here: an in-turn
hold can't create a backlog (`WriteTurn` returns regardless of whether the
child is reading), and holding multiple turns' responses open at once would
coalesce them into one turn cycle at the emitter (no `turn_end` between
echoes).

## Patterns established

- **Structural-chain proof in place of a queue-depth assertion.** When the
  production path under test doesn't pace on commit, don't try to force a
  queue-depth observable — identify and assert on the FIFO chain that
  actually guarantees order (here: pipe → reader → parser → emitter), and
  gate the assertion with an explicit vacuity positive (all sends acked)
  before it runs.
- **Startup hold as the stream-path analog of idle-trigger mode (#792).**
  Where the PTY fake models busy→free via a screen glyph, the stream fake
  models it via a pre-read-loop `os.Stat` poll at the call site — same
  "come up busy, release on trigger" shape, adapted to a pipe protocol with
  no screen to read.
- **Hold-at-call-site keeps the tested seam pure.** Same discipline as
  #1137's stdin tee: env-gated behavior wraps the call to `runStreamJSON`
  rather than changing its signature, so unrelated call sites and specs
  stay byte-identical and untouched.
