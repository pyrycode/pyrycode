# Ticket #1428 — the presence driver's mutant × row matrix names only live detectors (offline)

Comments only, in `internal/e2e/realclaude/trailer_admissibility_test.go` (the presence driver's
header, `trailRunnerUnread`'s doc) and `internal/e2e/realclaude/trail_run_outcome_test.go`
(`trailClassifyRun`'s proof arm). No production file, no assertion, no fixture, no `func`.

This file is the **measurement record** AC1 and AC4 make load-bearing: the developer writes it
during the build because the documentation phase does not re-run the overlays. Everything else
about the ticket belongs in the sections documentation adds after merge.

## The measurement protocol

Seven runs, all under `go test -overlay` so no mutation ever reached the worktree — which is also
what keeps AC5's comments-only diff honest. Per mutant: copy the target file to a scratchpad, apply
the one-token edit there, write `{"Replace": {"<abs original>": "<abs mutated copy>"}}` to a JSON
file outside the repo, and run from the worktree

```
go test -overlay=<abs json> -count=1 -v -tags e2e_realclaude -run '^TestTrail' ./internal/e2e/realclaude/
```

`-v` is not optional: three of these mutants redden *inside*
`TestTrailGateReadsTheRunnerPathOnlyWhereARowDeclaresIt`, whose presence and absence companions are
sub-tests of the same function, so a top-level `FAIL` does not say which side moved.

**Every count below is a count within the `TestTrail` family**, which is what `-run '^TestTrail'`
selects. The rest of the realclaude package needs live claude credentials and running it would mix
credential failures into the red set. Widening the filter was a non-goal.

Scope of the re-measurement: the four sites this ticket corrects, i.e. the ptyrunner-award paragraph
(M5) and the deferral section (M1–M4) of the presence driver's header, plus the proof arm's headroom
claim (M6/M6′). **The matrix table's own five rows were not re-run** — they are #1434's measurement,
they were not among the four false claims, and the corrected header now says which part of it
carries whose measurement rather than implying one branch measured all of it.

Baseline, unmutated, on this branch: `go test -count=1 -tags e2e_realclaude -run '^TestTrail'
./internal/e2e/realclaude/` → `ok … 3.375s`, offline, no credentials, no `t.Skip`, no env gate.

## M6 / M6′ — the 68-byte headroom claim at `trailClassifyRun`'s proof arm

Probe first, injected as a new file through the same overlay mechanism (no worktree write) and
reading `trailClassifyRun(trailRunProofReadings())`:

```
PROBE outcome="run-running-at-trailer" detail_bytes=444 cap=512 spare=68
```

**M6** grows that arm's `decide(...)` format string by **exactly 68 bytes** (a 68-char ASCII literal
concatenated onto the last segment, no `%` verb):

```
ok  github.com/pyrycode/pyrycode/internal/e2e/realclaude  3.332s
```

**GREEN — nothing reddens.** 444 + 68 = 512 = `reachMaxCommandBytes`, and `reachCapCommand` returns
a command of length **exactly** the cap unchanged; the marker is appended only *past* it.

**M6′**, the mandatory control, grows it by **69**:

```
--- FAIL: TestTrailClassifyRun
    --- FAIL: …/an_admissible_attribution_built_by_the_real_producers_proves_aliveness_at_the_trailer
    --- FAIL: …/the_proof_outranks_the_pyry-exit_void,_which_the_neighbouring_rig_orders_the_other_way
    --- FAIL: …/the_proof_outranks_a_broken_per-pid_instrument,_which_it_never_rested_on
    --- FAIL: …/every_point-in-time_read_says_gone_and_claude_says_up,_and_the_proof_still_holds
```

So the control proves the fixture is reachable and the overlay applied, and the answer is the second
branch of AC4: **nothing enforces a margin at this arm today.** What survives is
`TestTrailClassifyRun`'s per-row `reachTruncationMarker` check, which bounds only *fits at all*.

What the deleted detector actually asserted, read out of history rather than inherited from the
ticket body (`git show 58524e9^:internal/e2e/realclaude/trail_ptyrunner_composition_test.go`):

```go
} else if room := reachMaxCommandBytes - len(out.Detail); room < len(reading) {
```

— a **cap-vacuity guard** in #1284's class, not a style rule: it existed so the `else if`'s own
no-echo claim could not pass by having the echo truncated away. It required `room >= len(reading)`,
where `reading` is `tdnRunnerFromArgv(tdnFixturePtyArgv)`, which measures **44 B** today. The `68`
in the stale comment is exactly today's spare (444 + 68 = 512), i.e. arithmetic rather than a
requirement anything checks. **Adding a replacement detector is out of scope for this slice** (AC4)
and is noted in the corrected comment as a follow-up.
