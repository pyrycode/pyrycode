# Ticket #1338 — Probe rig: reduce a during-turn pin scan to the FIFO-needle row count, pgid set, matched rows and claude argv

A later ticket stages one live `pyry agent-run` turn — a `cat` held on a FIFO,
pinned mid-turn by full argv — and that turn is spent once. This ticket ships
the pure reduction from that pin's `pinScan` to the four values the staging
record consumes, so every way of filling them wrong is caught offline instead
of costing a live turn per attempt. New file only:
`internal/e2e/realclaude/finding_live_pin_test.go` (`//go:build e2e_realclaude`,
514 lines). No existing file edited, no production code, no live scan, no `ps`
exec, no `pyry` spawn, no caller.

## Implementation

- **`finLivePinReduce(scan pinScan, fifoPath string) finLivePinReading`** —
  pure, one pass over `scan.Matches`, no exec/clock/goroutine/error return.
  Membership is `reachMatchedNeedle(m, fifoPath)` over the row's recorded
  needle list, never a re-scan of `.Command` — `reachMatchArgvRows` matches
  the *uncapped* line but stores the *capped* one, so a FIFO path past
  `reachMaxCommandBytes` is genuinely matched while the retained `Command` no
  longer contains it. `ClaudeCommand` is `tdnClaudeCommand(scan)` run over the
  full scan, not over the FIFO-filtered rows (claude's row carries only the
  claude needle, so filtering first would always return `""`).
- **`finLivePinReading{Rows []reachProc, RowCount int, PGIDs []int, ClaudeCommand string}`**
  — no json tags, by the same rule as `finOutcomeStaging`: an
  intermediate carrying verbatim ambient-process argv must not be
  marshallable into a published record by accident. `RowCount` is assigned
  exactly once, as `len(Rows)`, mirroring `pinPartition`'s own
  `MatchCount = len(Matches)` idiom. `PGIDs` is raw — one entry per matched
  row, unsorted, duplicates intact, no dedup — since its consumer
  `finAttributeFanOut` dedupes and sorts internally and pre-reducing here
  would destroy the raw evidence.
- **`finLivePinWantRows = 2`** — the count of rows carrying the FIFO needle,
  not pids, not process groups. Basis: #1230's live measurement (the `zsh -c`
  wrapper and the forked `cat`), corroborated but not primarily sourced from
  #1268's rig-staged mutation test. Two prohibitions live at the constant:
  never fill from `scan.MatchCount` (3 on a healthy run — one scan carries
  both the FIFO and claude needles) and never fill from the distinct-pgid
  count of the FIFO rows (1 on a healthy run — claude isolates the Bash
  command into one detached group). `trail_run_rig_test.go:563` is explicitly
  *not* cited as corroborating "2" — it asserts only `MatchCount > 1`.
- **Fixture** — a synthetic four-column `ps` table built as **bytes** and
  turned into a `pinScan` through the real `pinMatchArgvExcluding` (never a
  hand-built `pinScan`, or the truncation asymmetry the trap depends on is
  skipped entirely). Four rows: claude (pgid 200, carries
  `--append-system-prompt-file`, no FIFO path), the `zsh -c` wrapper (pgid
  300, argv padded — the repeat count derived from `reachMaxCommandBytes`,
  never a literal 512 — past the cap so the FIFO path sits only beyond byte
  512), the `cat` (pgid 300, FIFO path within the cap), and an unrelated
  daemon (pgid 500, neither needle, keeps `RowsScanned` 4 apart from
  `MatchCount` 3). The pad token carries neither needle and no second FIFO
  occurrence, so it can't make `tdnClaudeCommand` ambiguous or re-hide the
  truncated path.

## Tests

`TestFinLivePinReduce` — counted rows in scan order; the truncation pair (row
300 is matched *and* its retained `Command` does not contain the FIFO path,
which is what makes the membership rule red rather than decorative); the
`PGIDs` projection has two equal, positionally-compared entries (proves
duplicates survive — a deduping implementation yields one); claude's pgid and
pid appear in neither `PGIDs` nor `Rows`; `ClaudeCommand` matches the fixture's
claude row exactly; the zero scan reduces to a fully nil/zero reading; an
empty `fifoPath` matches nothing.

`TestFinLivePinCountIsNeitherWrongCandidate` — pins all three candidate values
off the same scan (`scan.MatchCount == 3`, deduplicated group-set size `== 1`,
`RowCount == finLivePinWantRows == 2`) and asserts them **pairwise distinct**,
so a fixture edit that collapses any two candidates together fails loudly
instead of silently disarming the trap.

Verification: `go test -race -tags e2e_realclaude -run '^TestFinLivePin' -v
./internal/e2e/realclaude/` green; `go vet` (plain and tagged) clean; `gofmt`
clean; `go build ./cmd/pyry` OK. Mutation evidence via `go test -overlay`
(scratchpad copies, no worktree writes) — five mutants, each red on exactly
its target assertion: `strings.Contains(m.Command, fifoPath)` membership →
both truncation-pair halves plus `RowCount` 1≠2; dedup `PGIDs` inside the
reduction → projection assertion only; `tdnClaudeCommand` over `Rows` instead
of `scan` → claude-argv assertion; drop the fixture's claude row →
`MatchCount` 2≠3 *and* the pairwise-distinctness guard; shrink the wrapper row
under the cap → the truncation pair's vacuity-guard half.

PR: [#1341](https://github.com/pyrycode/pyrycode/pull/1341).

## Patterns established

- **A count gets exactly one producer.** `RowCount = len(Rows)`, assigned
  once, mirroring `pinPartition`'s `MatchCount = len(Matches)` — never
  computed a second way, so there is nothing for the two fills to disagree
  about.
- **Wrong candidate values are pinned as asserted numbers, not prohibited in
  prose.** Both plausible-wrong fills for a count are named, asserted equal
  to their actual wrong value, and checked pairwise-distinct from the correct
  one — so a regression to either wrong fill, or a fixture edit that
  accidentally collapses two candidates together, is red rather than silent.
- **A `[]int` projection is built at the reduction site, not left to the
  consumer**, continuing #1280/#1281's credential-channel-closed-by-signature
  pattern: a caller holding `pinScan.Matches` converts to `[]int` at its own
  call site, never handing `[]reachProc` further downstream than it has to.
- **Membership over a capped-but-matched-uncapped field needs a truncation
  pair, not a single assertion**: prove the row is counted *and* prove its
  retained value no longer contains the thing that matched it — the second
  half is what keeps the first from going vacuous as soon as a fixture drifts
  under the cap.

## Lessons learned

(From the PR body; see PR #1341.)

- **A single-file ticket can still earn its RED by mutating the
  implementation under `go test -overlay` from the scratchpad, rather than
  staging a commit that doesn't compile.** This keeps the worktree clean and
  turns "which assertion is load-bearing for which defect" into a table of
  observed failures instead of a claim in a comment.
- **`strings.Contains(s, "")` is `true`**, so the membership-re-scan mutation
  incidentally also flips the empty-`fifoPath` case from "matches nothing" to
  "matches everything" — the empty-needle assertion the spec called
  comment-only work is a real second witness for the same defect.
- **A vacuity-guard assertion needs its own mutation to prove it guards
  anything.** The truncation pair's second half (retained `Command` must
  *not* contain the FIFO path) only earns its place once a mutant that
  shrinks the fixture below `reachMaxCommandBytes` turns it red; asserting
  the first half alone stays green under exactly the fixture drift it exists
  to catch.
