# Ticket #1414 — The gathers' constant runner reading is a property, not unclaimed work

Three shipped comments described the two gathers' runner-path reading (`trailRunnerUnread()`, always
fed to `trailGate`'s `RunnerPath`) as `UNOWNED — no ticket holds it`. True, but a misframing: the
reading is constant by construction and its closure is forbidden with a stated reason one file away,
not an open gap. A reader meeting "UNOWNED" reasonably concludes there is a gap worth filing. This
ticket rewrites all three sites to state the property, name the one clause that makes it true, and cite
the canonical paragraph `trail_ptyrunner_composition_test.go:19-26` (written by #1415) for the full
reason, instead of restating it three times.

Comment-only — no new symbols, no new tests, no behaviour change. PR
[#1425](https://github.com/pyrycode/pyrycode/pull/1425). Carved out of #1368; re-refined 2026-08-09
against `main` at `ce0d768` after #1415/#1416/#1417/#1419/#1420 landed, which satisfied two of the
original four ACs (no live `#1374` reference survives; `trailGateCase.in`'s doc was already correct)
and left the "UNOWNED" misframing as the sole remaining, lower-severity finding —
see [[po-1414-a-blocked-ticket-premise-expires]].

## Implementation

- **Three sites, three prose shapes, one line-count budget each** (`git diff --numstat`: `6 6`, `5 5`,
  `4 4` — exact). `trailer_admissibility_test.go:805-810` (doc of `trailRunnerUnread`, subject is the
  *gathers' use* of it), `finding_run_gather_test.go:546-550` (inside `finGatherReadings`), and
  `trail_run_rig_test.go:157-160` (inside `trailRigGather`) each keep their line count unchanged, so no
  cross-file cite into any of the three (~25 across ten files, several bare and one inside a
  `t.Fatalf` string at `finding_stage_held_group_test.go:576`) goes stale. Exact neutrality was a
  hard constraint, not a target — see [[architect-1414-line-count-neutrality-forced-by-ac-deadlock]].
- **Site 3 does not cite `finding_exit_path_probe_test.go:264-272`.** That prohibition ("no
  `finLivePinReduce`, so claude's needle cannot be added") is scoped to the finding gather's own scan
  and does not govern `trailRigGather`, which takes its needles as a parameter from independent
  callers. Site 3 instead carries the rig's own structural reason: it runs no claude process at all
  (`trail_run_rig_test.go:40`), so there is no producer for any argv scan to read regardless of what
  needles it were given.
- **Bare-cite ordering.** A bare `(:NNN)` inherits the last filename named in its comment; site 3's
  bare `(:40)` sits on the line above the first cross-file filename for exactly this reason. The other
  two sites write only fully-qualified cross-file cites.
- Two developer judgment calls, confirmed correct in review: dropping "the fixture rows keep this
  helper regardless" from site 1 (duplicated three lines above at `:801-803`, against house style),
  and scoping site 1's "forbids" clause to "the finding gather's scan" rather than both gathers — more
  precise than the canonical paragraph itself, which #1415 left slightly loose on this point (its own
  correction is out of scope here, deferred to #1415's text).

## Lessons learned

From the PR body's own "Lessons learned" section:

- **A bare `(:NNN)` must precede the first cross-file filename in its comment, or it silently
  retargets** to that file. Confirmed load-bearing at site 3, which cites both a same-file line and a
  cross-file file in one block.
- **Two long filename cites inside a 4–6 line comment budget cost more than their character length.**
  A 39- and a 41-character filename cite each force a line wrap that strands ~20 columns of otherwise
  usable budget — a block that arithmetically fits its line count can still fail to wrap into it.
  Budget the wrap loss, not just the character count, before deciding what prose survives the cut.

From code review (PASS, one NIT, non-blocking, left open):

- Site 1 dropped the clause "the gate is correct about WHICH absence fired when the path is known" —
  present in the old text, no in-comment replacement in the new one. The fuller statement lives at
  `trail_ptyrunner_composition_test.go:33-34`, just outside the `:19-26` canonical range this comment
  cites. Not fixed: the line budget was hard, the spec didn't list the clause as must-keep, and
  widening the cite would have pulled in a different paragraph than the canonical one.
