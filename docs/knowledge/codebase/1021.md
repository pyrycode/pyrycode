# Ticket #1021 — move Noise handshake/hello out of `v2session.go`

First slice of the [#964](https://github.com/pyrycode/pyrycode/issues/964)
split of `internal/relay/v2session.go` (3744 lines / ~76 top-level decls,
flagged as the largest readability liability in the 2026-07-15 full-repo
review). Carves the inbound Noise session-establishment concern — the
initiator handshake and hello/capability negotiation — into a new file in
the same `package relay`. Pure mechanical move: no exported-API change, no
behaviour change, and because everything stays in-package, zero call-site
changes anywhere in the tree.

## Implementation

New file `internal/relay/v2session_handshake.go` (440 lines) now owns:
`maxNoisePayloadBytes`, `decodeInnerFrameV2`, `InnerFrameV2Decoded`,
`supportedV2Capabilities`, `negotiateCapabilities`, `handleNoiseInit`,
`handleNoiseMsg`. `v2session.go` drops from 3744 to 3323 lines.

`handleRekeyInit` sits physically between `handleNoiseInit` and
`handleNoiseMsg` in the original file and **stays in `v2session.go`** — it's
a later #964 slice's concern. The move was therefore three cut operations
(a const block, the handshake/negotiation block, `handleNoiseMsg`), not one
contiguous range. The app-frame router (`dispatchAppFrame`, `handleFrame`),
the shared seal/marshal helpers (`sealError`, `marshalInnerFrameV2`), and the
manager core also stay put.

No imports went stale in `v2session.go` (`slices` and `internal/noise` both
retain other users there). The new file's import list needed two additions
beyond the spec's illustrative sketch — `encoding/base64`
(`decodeInnerFrameV2`) and `time` (`handleNoiseInit`) — both already used
elsewhere in `v2session.go` too, so nothing there went stale either.

## Patterns established

None new — reconfirms the pure-move discipline from
[`codebase/452.md`](452.md)/[`453.md`](453.md)/[`454.md`](454.md) (same-package
carve-out ⇒ zero call-site edits) one level up, this time as a deliberate
first slice of a large-file split rather than an orphan-spec salvage.

## Lessons learned

- A spec's "expected import list" for a moved file is best treated as
  illustrative, not exhaustive, when the moved code has sub-dependencies the
  spec author didn't enumerate line-by-line (here: `base64` inside
  `decodeInnerFrameV2`, `time` inside `handleNoiseInit`). The spec anticipated
  this ("let the compiler be the source of truth") — worth keeping as the
  default framing for future pure-move slices instead of asking the architect
  to hand-verify every transitive import.

## Verification

`make check` (vet, `go test -race ./...`, staticcheck, substrate-guard, e2e)
green. Code review confirmed byte-identical move via set-diff of removed vs.
added lines (all 421 removed lines reappear verbatim in the new file); diff
touches exactly the two files AC#3 requires.
