# Ticket #1153 — Real-claude e2e: stream liveness under `interactive_runner: "stream-json"`

Adds the real-claude counterpart of the fake-side stream liveness proof (#1141): a
real-claude e2e that starts the interactive daemon under the production
`interactive_runner: "stream-json"` toggle against a live `claude` and asserts one
real turn streams end-to-end — a non-empty `assistant_delta` followed by the
terminal `turn_state{idle}`, never a canned reply. Per the always-a-real-claude-gate
policy (2026-07-08), the stream-json interactive runner (#1081) was proven against
fakeclaude only (#1141 + the #1136/#1137/#1138/#1139 riders) until this ticket. This
is the shared-harness slice of the #1083 real-claude gate: the permission-flow rider
**#1154** (blocked-by this ticket) composes the same config-toggle helper with
`spawnPermissionDaemon` instead of `spawnBootstrapDaemon`.

## Implementation

- `internal/e2e/realclaude/interactive_stream_liveness_test.go` (new file, `//go:build
  e2e_realclaude`, PR #1156). Test-only, zero production files.
- `writeStreamInteractiveConfig(t, home)` — writes `<home>/.pyry/config.json =
  {"interactive_runner":"stream-json"}` (mkdir `.pyry` at `0o700`, file at `0o600`)
  before the daemon spawns (`resolveConfigPath` reads it once at startup).
  Transcribed from the fake harness `StartStreamInteractiveWithRelay`
  (`internal/e2e/harness.go:388-406`, #1141). ~8 lines, `t.Helper()`.
- `drainForCompletedTurn(t, phone, cs, convID, timeout)` — the stronger two-milestone
  drain AC #2 requires ("delta(s) followed by turn completion"), where #854's
  `drainForAssistantReply` stops at the first delta. Mirrors #1141's fake-side drain
  loop (`relay_v2_stream_send_test.go:149-217`) with one real-claude adaptation: **no
  echo/content assertion** — real claude's words are non-deterministic, so M1 only
  asserts a non-empty `assistant_delta` for the driving conversation. M2 is the
  terminal `turn_state{idle}` for the same conversation, observed after M1
  (`turn_state{responding}` leads the delta and is ignored until `sawDelta`).
  Milestone-specific `t.Fatalf` on timeout names the likely cause (a bootstrap-id /
  bound-conversation UUID mismatch drops every event at the drain gate).
- `TestInteractiveStreamLiveness` — transcribes #854's `TestInteractiveBootstrapLiveness`
  daemon body (pair → seed bootstrap registry + bound conversation → spawn →
  handshake) verbatim, with three deltas: (1) `writeStreamInteractiveConfig` before
  spawn, (2) drives **one** turn (AC #2 / #1141 parity) instead of #854's two, (3)
  drains to completion via `drainForCompletedTurn` instead of stopping at the first
  delta. Prompt is a short deterministic instruction with a `time.Now().UnixNano()`
  nonce (defeats caching without asserting on content).

## Patterns established

- **Config-writer, not a spawn wrapper.** The stream-json toggle is orthogonal to the
  permission mode (`config.json` vs. argv), so the reusable unit is a standalone
  helper composed with whichever spawn helper the caller needs:
  `spawnBootstrapDaemon` (`--dangerously-skip-permissions`, this ticket) or
  `spawnPermissionDaemon` (no skip, #1030/#1154). A spawn wrapper delegating to
  `spawnBootstrapDaemon` could not have served #1154.
- **Fresh package-private constants per file, not shared file-private ones**, when two
  test files share a package + build tag. #854's `liveBootstrapUUID`/`liveConvID` are
  file-private; this ticket declares distinct `streamBootstrapUUID`/`streamConvID`
  literals rather than reusing them (would be a redeclaration in the same namespace).
  From the PR body's Lessons learned — applies to any future `internal/e2e/realclaude`
  file that seeds its own bootstrap/conversation pair.
