# Ticket #848 — Populate `screen_snapshot` with the session's model / effort / YOLO

Split B of #835 (split A, #847, shipped the two unwired leaves this ticket
consumes: `Pool.DefaultSettings()` and the three zero-value `model`/`effort`/`yolo`
fields on `ScreenSnapshotPayload`). Wires the read path: `handleRequestSnapshot`
now reports the bootstrap session's actual persisted settings instead of the
zero values, so the desktop Status sheet (pyrycode-desktop#156) can render the
current model / reasoning-effort / permissions posture before offering to
change it (the change path is #841/#845's `set_session_settings` write verb).
Read-only — no new inbound verb, no relay-protocol change. Not
`security-sensitive`: reflects an existing, non-secret control back to an
already-paired, AEAD-authenticated client that already receives the full
rendered screen text under the same seal.

## Implementation

Four files, ~65 production LOC + ~66 test LOC, no edit fan-out beyond the two
threaded call sites the spec predicted:

- **`internal/relay/v2session.go`** — new optional field on `V2SessionConfig`:
  `SnapshotSettings func() (model, effort string, yolo bool)`, alongside
  `Snapshotter` / `KnownConversation`. Primitive-typed closure, not a struct —
  three scalars, no presence semantics to carry (nil-vs-set is the closure
  field itself being nil). `handleRequestSnapshot` reads it on the success
  path only — after the `live` check, immediately before `json.Marshal` — with
  a nil-guard that leaves `model, effort, yolo` at `"", "", false` when unset.
  The `ScreenSnapshotPayload{…}` literal at the marshal site gains
  `Model: model, Effort: effort, YOLO: yolo` beside `Text` / `TS`. No reject
  branch, offline branch, or error path touched.
- **`cmd/pyry/main.go`** — the `snapshotSettings` closure, built beside the
  existing `debugBundler` closure, wraps `pool.DefaultSettings()`: `ok == false`
  (no bootstrap) collapses to `("", "", false)`, otherwise unpacks
  `SessionSettings.{Model,Effort,YOLO}`. This is where the `internal/sessions`
  dependency lives — the closure decodes `SessionSettings` into three
  primitives here, so the value crossing into `relay.go` is a bare
  `func() (string, string, bool)`. Same discipline as `debugBundler` (#813)
  and `settingsUpdaterAdapter` (#845); see the `transitionObserverSink` doc
  comment (`cmd/pyry/session_transition_v2.go:20-27`) for why `relay.go` stays
  free of an `internal/sessions` import.
- **`cmd/pyry/relay.go`** — `snapshotSettings func() (model, effort string, yolo bool)`
  threaded as a new trailing parameter through `startRelay` → `startRelayV2`,
  assigned to `V2SessionConfig.SnapshotSettings` in the config literal beside
  `Snapshotter` / `SettingsUpdater`. The v1 dispatch path builds no
  `V2SessionConfig` and is untouched.
- **`internal/relay/v2session_test.go`** — extended the existing
  `TestV2Session_OpenState_RequestSnapshot` table (reused `driveToOpen` /
  `v2Recorder` / `sealAppFrame` / `decryptAppFrame` verbatim, no new harness)
  with a `settings` field and `wantModel`/`wantEffort`/`wantYOLO` assertion
  columns. Three new rows: injected non-default settings (`opus`/`high`/`true`),
  all-defaults via a nil seam, and all-defaults via a seam that explicitly
  returns `("", "", false)` — proving the nil case and the no-bootstrap
  collapse are wire-indistinguishable. Existing error/offline rows pass
  `settings: nil` unchanged (those branches never reach the settings read).

## Testing

`go test -race ./internal/relay/... ./internal/protocol/... ./internal/sessions/...`
and `go vet ./...` pass. Code review: no findings.

## Design invariant (AC-3)

Settings-source == snapshot-source == the bootstrap session, by construction:
`Snapshotter` renders the bootstrap child's screen (conversation-agnostic) and
`Pool.DefaultSettings` reads that same bootstrap session's persisted settings.
No runtime cross-check is possible or needed. Documented, not asserted in code
— a future multi-session snapshot would key `Snapshotter` and
`SnapshotSettings` together rather than inventing an independent keyed seam.

## Out of scope

- A conversation-keyed settings accessor — deliberately not added, per the
  invariant above.
- Any change to the write path (`set_session_settings`, #841/#845) or to
  `Pool.DefaultSettings()` / the wire fields themselves (#847, unchanged here).
