# Ticket #1253 — Reap-log classifier driven by bytes captured from a real reap

`internal/e2e/realclaude/teardown_reap_capture_test.go` (new, 713 lines, `e2e_realclaude`
tag, `tdn*` prefix). #1250's `tdnClassifyReapLog` shipped tested only against hand-written
string constants headed "measured 2026-07-30" — nothing executing asserted that the real
reaper still emits those bytes, and the failure shape if that drifted is the worst
available: a matcher that finds nothing answers `no-reap-line`, a consumer reads "the
reaper never fired," and nothing goes red. This ticket builds real two-level process
trees, runs a real `agentrun.ReapDescendantGroups` over them, captures what
`slog.Default()` emits via `log.SetOutput`, and drives the merged classifier with those
bytes — no constant in the middle. Split from #1236; the reader this ticket originally
asked for shipped as #1250 while the ticket sat in Backlog, so its four ACs are entirely
about proving that classifier against real bytes rather than building a second one.

## Implementation

- **One new file, deliberately not an edit to `teardown_liveness_test.go`.** That file's
  own header declares its contents "pure over bytes: no exec, no file read, no clock";
  this harness spawns real trees, redirects a process-global writer, and issues real
  SIGKILLs, so editing it would falsify the header. Independently, #1251
  (`done:code-review` at filing time) has a +259/−40 diff to that file with hunks inside
  `TestTdnClassifyReapLog`'s table — exactly where a new fixture row would land. Neither
  file touches the other; both branches merge in either order.
- **The tree, and why it's two levels deep.** `descendantPGIDs` walks from the root's
  *children* down, and `reap.go:52` excludes `pgid == rootPid`, so a killable group must
  sit two levels below the test. The intermediate process must call `setpgid` on its own
  children, which rules out a shell (no portable `setsid`, and a background job in a
  non-interactive `sh` stays in the shell's group) — so it's the test binary re-exec'd via
  `-test.run=^TestTdnReapTreeHelperProcess$`. Leaves need no role of their own: whether a
  child leads a fresh group is decided by its *spawner's* `SysProcAttr`, so leaves route
  through the package's existing `PYRY_E2E_FAKE_MODE=sleep` fake-pyry mode
  (`fixtures_test.go:366`) and the re-exec depth is 2 and terminal — bounded against the
  package's documented 2026-05-16 fork-bomb `TestMain` guard.
- **The report file is treated as a trust boundary, not a convenience.** Every pid
  `tdnStartTree` learns about becomes a `syscall.Kill` target and one becomes the walk
  root. `tdnKillTree` refuses `pid <= 1`, `os.Getpid()`, and `syscall.Getpgrp()` before
  either kill — `syscall.Kill(-0, …)` is `kill(0, …)`, which signals the *caller's own*
  process group. `tdnParseTreeReport` is all-or-nothing: requires a trailing newline and
  exactly `fresh+same` well-formed `<kind> <pid>` lines before accepting, because a short
  read on a multi-line file is syntactically valid but incomplete (unlike
  `reap_test.go:164`'s single-pid `waitReport`, which can treat any partial read as "not
  ready yet").
- **`tdnCaptureReap(t, rootPID) []byte`** — saves `log.Writer()`, redirects to a fresh
  buffer, calls `agentrun.ReapDescendantGroups(rootPID, slog.Default())`, restores via
  `defer`, returns the bytes. Fatals if `rootPID` is the test process or `<= 1` — the
  guard is code, not a comment, because a walk rooted at the test process would sweep
  every fresh-group descendant of the whole binary, including sibling specs' real
  `pyry agent-run` and `claude` processes. `log.SetOutput` is process-global and not
  reentrant, so nothing in this file runs under `t.Parallel`.
- **`TestTdnRealReapCapture`**, four sequential subtests sharing outer-scope byte slices:
  - one group killed + a same-group sibling spared → `held-pgid-in-reap-line`;
    `tdnAliveThroughout` proves the spared leaf is *still alive* at the moment its pgid is
    read as absent from the line (the unearned negative the instrument exists to refuse —
    without it, "excluded from the line" and "already exited" are indistinguishable);
  - a childless walk root → no line emitted at all → `no-reap-line`, proving the capture
    path can go silent rather than always carrying the message;
  - two groups killed → both in `PGIDs` (asserted as a set, since `reap.go:51` ranges a
    map), quoted rendering `pgids="[A B]"`;
  - the two captured byte slices asserted to differ: unquoted `pgids=[N]` only in the
    single-group capture, quoted `pgids="[` only in the multi-group one — the regression
    surface a matcher proven only on the single-group form would invert on.
- **`TestTdnClassifyReapLogSubstringMembership`** closes the untested suffix direction of
  the substring hazard: held `88` against `pgids=[7788]` must read `held-pgid-absent`, not
  a match. Carries the already-covered prefix case (`77`) alongside it for legibility,
  with a comment naming the sibling fixture row's location so neither half can be dropped
  without the other being findable.
- `tdnClassifyReapLog`, `tdnReapMessage`, the four verdicts, `tdnIsReapVerdict`, and
  `tdnEqualInts` are called and none are redeclared. Zero production files touched;
  `ReapDescendantGroups`'s three `reapDescendantGroupsFn` seams and
  `internal/agentrun/reap_test.go`'s own subtests are untouched.
- Verification: `gofmt -l`, `go vet -tags e2e_realclaude`, `go test -tags e2e_realclaude
  -run '^TestTdn' -v` (32 PASS, zero SKIP, up from #1250's 22), `-race -count=3` on the
  capture test clean. `make e2e-realclaude` deliberately not run for this ticket — fully
  offline, and that target spends real credentials on ~40 unrelated live specs.

## Patterns established

- **A blocking read on a multi-line report file needs a completeness check a
  single-pid version doesn't.** `reap_test.go:164`'s `waitReport` treats any partial read
  as "not ready" because it reads exactly one pid; with N lines a short read is
  syntactically valid but incomplete, and a truncated final line can parse cleanly into a
  pid that's a *prefix* of the real one — a well-formed integer naming some other process.
  Require a trailing newline plus an exact line count and re-poll rather than accept.
- **A `kill(-0)` guard belongs at the kill site, not only at the parse.** Any pid reaching
  a kill call can arrive via a variable left at its zero value regardless of what the
  parse already checked, so the kill helper re-guards independently.
- **Decide what needs re-exec by asking what needs `setpgid` on its own children, not by
  matching an existing shared fixture.** `reap_test.go`'s process-tree helper is
  unexported in `package agentrun` and not importable from a build-tagged test in another
  package; the role is small enough (leaves need no logic at all, only the intermediate
  parent) that rebuilding it in reduced form is more elegant than adding a non-test
  package purely to share it.
- **A file-overlap check against an in-flight sibling branch is worth running before
  deciding where new content lands**, not just before naming new symbols. The
  architecture doc ran `git show origin/feature/1251:<path> | grep -E '^(func|type|const|
  var) '` against both of #1251's files, confirmed zero symbol collisions between its 48
  declared identifiers and this ticket's 24, and used the same check to justify a new file
  over an edit to a file #1251 was mid-diff on.

## Lessons learned

From the PR body (#1257) and code review (PASS, 2 NIT, both optional and non-blocking):

- **[NIT]** `TestTdnRealReapCapture`'s multi-group subtest names its loop variable `first`
  but it's reassigned every iteration and ends up holding the *last* outcome. Zero
  behavioural impact — every iteration classifies the same byte slice, so `.Line` is
  identical across iterations — but the name reads as a claim the code doesn't make.
  `last` or `outcome` would be accurate. Not fixed in this PR; harmless.
- **[NIT]** The comment-level claim that a same-group leaf's pgid equals `RootPID`
  ("the spared leaf's pgid IS `RootPID`") is *reasoned*, not *measured* — the one place in
  the file that rests on the same kind of unverified claim the ticket exists to convert
  into a capture. The reviewer's own counter-argument: POSIX guarantees a forked child
  inherits its parent's process group, and the failure mode is already loud from the other
  side — a same-group leaf that somehow led its own group would not be excluded by
  `reap.go:52`, would get SIGKILLed, and `tdnAliveThroughout` would catch it (confirmed by
  the developer's deliberate-mutation run, which caught the equivalent failure in 70ms).
  Not raised to blocking; a future tightening could have the parent role report
  `syscall.Getpgid(pid)` alongside each pid to make it a measurement.
- **Both halves of the ticket's core claim were verified by deliberate mutation, not just
  reasoned about**, mirroring #1250's discipline: `tdnCaptureReap` patched to return a
  throwaway buffer → subtest A fails with `no-reap-line`, exactly the drift shape the
  ticket exists to make loud; `reap.go:52`'s `pgid == rootPid` exclusion removed → the
  spared leaf dies and `tdnAliveThroughout` catches it in 70ms. `git status --porcelain`
  confirmed clean after both, restoring the mutation.
- **`-test.run=^TestTdnReapTreeHelperProcess$` composing with the package's existing
  `TestMain` was an open question in the spec (§10) and was verified before the tree logic
  was built on top of it** — `TestMain` falls through to `m.Run()`, the filter admits
  exactly one test, that test plays its role and never returns. The role-unset path
  returns rather than `t.Skip`s, preserving the package's zero-SKIP property across
  `^TestTdn`.
- **`gofmt -l` is dirty on `main` for three files in this package, unrelated to this
  diff** — baseline noise flagged and filtered by both QA and code-review passes rather
  than reported as a finding. Consistent with the standing note in
  `code-review-realclaude-baseline-noise` project memory.
- File landed at 713 lines against the spec's ~430–500 projection (with an explicit note
  that #1250's sibling file undershot its own estimate by 1.65×) — under the spec's stated
  fallback ceiling (~700), so no scope was cut.
