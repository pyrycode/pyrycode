# Ticket #888 — `recent_workspaces` v2 wire message

Adds the `recent_workspaces` read verb so mobile's "Recent workspaces" list
(previously silently empty — no daemon feed existed) and desktop's Workspace
Picker sheet can show recently-used workspace folders. Split from the #825
daemon-wire epic; independent of the sibling `create_workspace_folder` (#887).
No new store: the handler derives the list entirely from the conversations
registry's existing `Cwd` / `LastUsedAt` fields — the distinct set of
workspace paths, deduped, ordered most-recent-first. Direct sibling of
`list_conversations` (#255) in shape (registry read → project → sort →
reply), diverging only in the fold-and-dedupe step, the descending sort, and
the new reply type.

## Implementation

Five production files touched (the canonical wire read-verb footprint — Type
consts, `v1TypeSet` membership, payload, handler, two registration sites),
one new file, ~450 total LOC:

- `internal/protocol/codes.go` — `TypeRecentWorkspaces = "recent_workspaces"`
  (request) + `TypeRecentWorkspacesList = "recent_workspaces_list"` (reply),
  after `TypeWorkspaceFolderCreated`.
- `internal/protocol/workspace.go` — appended (not a new file; same domain as
  #887's workspace payloads): `RecentWorkspacesPayload{}` (empty request, so
  the dispatcher decodes a concrete value), `RecentWorkspacesListPayload
  {Workspaces []RecentWorkspace}`, `RecentWorkspace{Path string, LastUsedAt
  time.Time}`. Neither `Path` nor `LastUsedAt` carries `omitempty` (reply-side
  discipline: the client reads both on every row).
- `internal/protocol/envelope.go` — both new consts added to `v1TypeSet`. A
  v1 `dispatch.Route` read verb, not a v2-only control frame — mirrors the
  `TypeListConversations`/`TypeConversations` pair.
- `internal/protocol/compat_test.go` — both consts added to all three v1
  enumerations; hardcoded count bumped 24 → 26.
- `internal/relay/handlers/recent_workspaces.go` (new, ~77 LOC) —
  `RecentWorkspaces(reg RecentWorkspacesReader) dispatch.Handler`. Flow:
  `reg.List()` (no filter — archived conversations included by design, see
  below) → fold into `map[Cwd]maxLastUsedAt`, skipping `strings.TrimSpace(Cwd)
  == ""` rows → materialize into a non-nil `[]protocol.RecentWorkspace` →
  `sort.SliceStable` descending by `LastUsedAt` (`!Equal`-guard + `.After`,
  the round-trip-safe comparator per PROJECT-MEMORY's `time.Time` discipline),
  tie-break `Path` ascending → `c.Reply(...)`. Request payload is empty by
  spec and ignored, mirroring `ListConversations`.
- `cmd/pyry/relay.go` — two wiring lines, `d.Register(protocol.
  TypeRecentWorkspaces, handlers.RecentWorkspaces(convReg))` (v1 block) and
  the matching v2 `Handlers` map entry. The registry is passed **directly**
  (no `cmd/pyry` adapter, unlike #887's `resolveWorkspaceFolder`) — a pure
  read verb needs no filesystem-confining seam.

`RecentWorkspacesReader interface { List(filter ...conversations.ListFilter)
[]conversations.Conversation }` is a fresh consumer-defined narrow interface
rather than a reuse of `ConversationLister` (the identical shape) — the
per-handler narrow-interface convention in this package is deliberately kept
even at the cost of one line of duplication, to keep the two read handlers
decoupled.

### Design decisions (from the architect spec, both open questions in the ticket)

- **(a) Archived-only workspaces are included.** `reg.List()` is called with
  no `IsArchived` filter. A workspace is a folder, not a conversation;
  archiving a conversation doesn't "un-use" its folder. A folder whose only
  conversations are archived simply carries an older `LastUsedAt` and sinks
  to the bottom of the recency order — the ordering already degrades stale
  folders gracefully, so a hard exclusion would be scope creep beyond the
  literal ACs. Pinned by `TestRecentWorkspaces_IncludesArchivedOnlyWorkspace`;
  a future reversal must edit that test deliberately.
- **(b) No daemon-side cap.** The daemon returns all distinct workspaces; the
  client caps for display (mobile design shows ~5). A handful of short path
  strings creates no memory/bandwidth pressure, and capping is a display
  concern the daemon shouldn't own.

### Not security-sensitive

No untrusted input drives a filesystem operation: the request payload is
empty, and the reply is derived entirely from `Cwd` values the daemon already
stored (each a `$HOME`-confined realpath written by `create_conversation` /
`change_workspace`). Contrast the sibling `create_workspace_folder` (#887),
which writes to disk from an untrusted `{parent, name}` and is
security-sensitive.

### Size-gate override (documented, not silent)

The architect's spec explicitly overrides the ≥5-production-file self-check
at exactly 5 files, on direct empirical evidence: the merged sibling #887
touched the **same 5 production files** at 852 insertions, carrying a
security-review pass, a `cmd/pyry` resolver adapter, and reject-path guards
that #888 has none of — and shipped clean as one S with no `max_turns` hit.
#888 is strictly thinner on every axis. Splitting into a vocab/handler pair
(à la #841) would produce an unwired, unbuildable-as-tested child — the
override avoids manufacturing that anti-pattern for a change thinner than the
precedent it's measured against.

## Testing

- `internal/relay/handlers/recent_workspaces_test.go` (new, ~235 LOC) —
  dispatcher-harness pattern reused from `list_conversations_test.go`
  (`runListConvDispatcher`, `recvOutbound`). Covers: empty registry (byte-exact
  `{"workspaces":[]}`, non-nil slice); single conversation; dedupe-by-`Cwd`
  keeping max `LastUsedAt`; most-recent-first ordering across 3 distinct
  workspaces; `Path`-ascending tie-break on equal `LastUsedAt`; archived-only
  workspace still appears (pins design decision (a)); empty-`Cwd` conversation
  contributes no entry. All `time.Time` comparisons via `.Equal`.
- `internal/protocol/workspace_test.go` — two new round-trip tests
  (`TestRecentWorkspacesPayload_RoundTrip`, `TestRecentWorkspacesListPayload_RoundTrip`)
  against new fixtures `testdata/recent_workspaces.json` (empty request) and
  `testdata/recent_workspaces_list.json` (two-entry ordered reply).
- `compat_test.go` stays green with both consts added to all three
  enumerations and `len(all)` bumped 24 → 26.

`go test -race ./...`, `go vet ./...` pass. Code review (PR #890): **PASS**,
no findings — confirmed no missed registration/enumeration site, handler fold
and sort correctness, both design decisions honored by their pinning tests,
and the size-gate override well-justified against the #887 precedent.

## Out of scope

- **Live subscription / push feed** that re-emits when the recent set
  changes — explicitly deferred; file a follow-up if a client needs it. This
  ticket is one-shot request/response only, like `list_conversations`.
- **Creating workspace folders** — sibling `create_workspace_folder` (#887),
  independent.
- **Daemon-side list-length cap** — design decision (b); client owns display
  capping.
