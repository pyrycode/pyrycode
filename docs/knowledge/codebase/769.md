# Ticket #769 — pure outbound mapper: `turnevent.Event` → ACP `session/update`

Adds **`internal/acpbridge`**, the outbound half of the `pyry acp` adapter (epic
[#600](https://github.com/pyrycode/pyrycode/issues/600)). `MapUpdate` is a pure,
exhaustive, table-testable function mapping each neutral `turnevent.Event` to its
ACP `session/update` payload (or "no notification"), so the streaming adapter
([#750](https://github.com/pyrycode/pyrycode/issues/750), this ticket's consumer,
still blocked) can emit spec-correct frames without embedding the mapping in its
I/O loop. It is the ACP mirror of the mobile head's `turnbridge.MapEvent`
(#627) — same neutral source, ACP framing. Split from #750;
[ADR 027](../decisions/027-acp-mapping.md) is the mapping contract.

Full package documentation: [features/acpbridge-package.md](../features/acpbridge-package.md).

## Implementation

**1 new package, 2 new files (`internal/acpbridge/outbound.go` +
`outbound_test.go`), 0 changes to any other package.** Additive; zero call-site
blast radius (codegraph clean on `MapUpdate`).

- **7 exported wire types** — `AgentMessageChunk`, `AgentThoughtChunk`,
  `ContentBlock`, `ToolCall`, `ToolCallUpdate`, `ToolCallLocation`,
  `ToolCallContent` — flat structs with `omitempty`, ACP camelCase JSON tags
  verbatim. Plus the four `SessionUpdate*` discriminant consts and
  `MethodSessionUpdate = "session/update"`.
- **`MapUpdate(ev turnevent.Event) (update any, msgID string, ok bool)`** — an
  exhaustive type switch over the sealed `Event`. `TextChunk`/`ThoughtChunk` →
  `agent_message_chunk`/`agent_thought_chunk` (id returned out-of-band as `msgID`);
  `ToolStart` → `tool_call` with `status:"pending"` and no content; `ToolUpdate` →
  `tool_call_update`; `TurnEnd`/`Stall`/nil → `(nil, "", false)`.
- **Two pure helpers**: `mapToolContent` (exhaustive over the sealed `ToolContent`
  — text/diff/terminal/nil) and `mapLocations` (nil for empty).
- **Imports only `internal/turnevent` + `encoding/json`** — no `internal/acp`
  (sealed transport floor), no `internal/protocol` (mobile wire).

Design decisions (all resolved in the spec, no new ADR — this mirrors #627, which
also carried none):

- **Message id out-of-band.** ACP has no `messageId` wire field, so the neutral
  `MessageID` is returned as `MapUpdate`'s third value, not marshalled into the
  payload. Keeps every emitted `update` spec-correct ACP.
- **New package `internal/acpbridge`**, not `internal/acp`. The transport floor is
  sealed stdlib-only and method-agnostic; `session/update` method payloads (and a
  `turnevent` import) would break that seal. Sibling to `turnbridge`/`modalbridge`.
- **Kind/status are identity**, not a translation table — `turnevent`'s enum
  values already ARE the ACP strings.
- **`TurnEnd` → `session/prompt` stopReason return** (divergence 1), **`Stall` →
  stderr** — both the consumer's job; `MapUpdate` reports "no notification".

## Patterns established

- **Second thin adapter over one neutral model, proven.** `acpbridge` is the exact
  structural mirror of `turnbridge`'s outbound `MapEvent` — same sealed-switch,
  same pure value-to-value discipline, same "keep everything stateful in the
  consumer" seam. The two adapters now demonstrate the ADR 025/027 containment
  thesis concretely: one `turnevent` model, two independent outbound framings
  (mobile v2 envelope / ACP `sessionUpdate`), neither constraining the other. The
  one deliberate divergence between them — ACP **maps** `ThoughtChunk`
  (`agent_thought_chunk`) where mobile **drops** it — is the adapter-per-surface
  decision the model is designed to allow.
- **Out-of-band return for a semantic-but-not-wire field.** When the neutral model
  carries data (the `MessageID`) that has no home on the target wire but the
  consumer still needs it, return it as an extra value rather than inventing a
  non-spec wire field. A golden-JSON test proves the field is absent from the
  marshalled payload.
- **Exported-type count is domain-variant count, not size.** Seven wire structs is
  the ACP taxonomy, and the type/consumer seam was already split (this ticket =
  types + mapper; #750 = consumer), so the slice held S past the `>5 exported
  types` red line — the sanctioned data-model-taxonomy exception (precedent
  `turnevent` #606).
- **Keep the sealed-switch `default` arm even when the type is sealed.** Both
  `MapUpdate` and `mapToolContent` keep a `default` so a future producer variant
  surfaces as a visible drop, never a silent vanish — same posture as the
  `turnbridge` template.

## Code review

**PASS** — no findings ([PR #770](https://github.com/pyrycode/pyrycode/pull/770)).
Reviewer verified exhaustiveness over the sealed `Event` (all six variants +
nil/unknown default, zero-value safe), `ToolStart`'s `pending` default, verbatim
kind/status pass-through with the required comment, `ThoughtChunk` mapped (the
mobile divergence reversed), `TurnEnd`/`Stall` reporting no notification with the
stopReason correctly deferred, `mapToolContent` exhaustive over `ToolContent`, and
the out-of-band `msgID` with the golden-JSON test proving no `messageId` on the
wire. Import discipline honoured; new package is the right home. `make check`
green (`go vet` + `staticcheck` + `go test -race` + substrate-guard);
`make e2e-realclaude` green (157s).

## Lessons learned

- **The wire-shape golden test is the real drift guard for the JSON tags.** A
  `reflect.DeepEqual` struct table asserts the Go values but **cannot** catch a
  wrong `json:"..."` tag (a typo'd `toolCallId` still deep-equals). So
  `TestMapUpdate_WireShape` `json.Marshal`s one update per variant and
  string-compares against a golden JSON literal — that is what locks
  `sessionUpdate`/`toolCallId`/`rawInput`/`oldText`/`terminalId` and proves
  `agent_message_chunk` carries no `messageId`. Its correctness relies on the
  inputs containing no `<>&`, so default `json.Marshal` HTML-escaping is a no-op
  (noted in the test).

## Testing

Same-package table tests in `outbound_test.go`, mirroring
`turnbridge.TestMapEventOutbound`. `t.Parallel()` on the test and each subtest;
`reflect.DeepEqual` on the payload struct (the payloads hold a `json.RawMessage`
slice, so `==` won't work).

- **`TestMapUpdate`** — the exhaustiveness assertion (AC-4): one case per sealed
  variant + drops. `TextChunk`/`ThoughtChunk` with `msgID` out-of-band; `ToolStart`
  asserting `status:"pending"` (AC-2) with `rawInput` preserved verbatim and one
  location mapped; `ToolUpdate` × {completed+text, failed+nil (status-only, content
  omitted), completed+diff, in_progress+terminal} exercising every `mapToolContent`
  arm; `TurnEnd`/`Stall`/nil → `(nil, "", false)`. Loop invariant asserted every
  case: `!ok ⇒ update == nil && msgID == ""`.
- **`TestMapUpdate_WireShape`** — golden-JSON per mapped variant, locking the
  camelCase field names and proving `agent_message_chunk` has no `messageId`.

## Out of scope (deferred)

- **The streaming consumer** ([#750](https://github.com/pyrycode/pyrycode/issues/750))
  — subscribes to the session `turnevent` stream, wraps each `update` in a
  `session/update` notification, holds `session/prompt` open for `TurnEnd`, writes
  `Stall` to stderr, and owns all chunk grouping. Blocked on this ticket.
- **The `{sessionId, update}` params wrapper** and **`TurnEnd`'s stopReason
  return** — the consumer's (this ticket defines `MethodSessionUpdate` but not the
  params struct; `TurnEndReason` values are already ACP strings, mapped by the
  consumer with `string(e.Reason)`).
- **ACP `image` / `resource` content blocks** — `turnevent` builds only
  text/diff/terminal today (ADR 027 open item); `ContentBlock` stays text-only.
