# Ticket #1410 — Emit the usage-limit frame to an interactive v2 mobile client

Joins #1404's producer to #1405's wire shape: one additive `turnevent.RateLimited` arm in
`turnbridge.MapEvent` and one additive `case` in `cmd/pyry`'s interactive turn emitter, so claude's
usage-limit report reaches an interactive v2 mobile client instead of dying at the daemon boundary. Every
field crosses verbatim, `conversation_id` the bridge's only addition — this slice is translation, not
policy, since `emitRateLimit`'s three-rung gate already decided upstream whether the report is worth
telling a person. Also falsifies the six sites that stated the frame is never emitted. PR
[#1412](https://github.com/pyrycode/pyrycode/pull/1412), code review **PASS** (one SHOULD FIX, below
threshold; two NITs).

## Implementation

- **`internal/turnbridge/outbound.go`** — one `case turnevent.RateLimited:` inserted between the
  `ThinkingProgress` arm and `default:`. Five payload fields, four verbatim from the event
  (`Status`, `LimitType`, `ResetsAt`, `TruncatedFields`), `ConversationID` from `tc` and nothing else;
  `tc.TurnID`/`tc.Seq` ignored, as for every non-turn-scoped peer. No clamp on `ResetsAt`, no re-cap on
  either string, nil `TruncatedFields` passed straight through — and here that nil is what puts
  `"truncated_fields":null` on the wire, the opposite of the roster arm two cases up, whose
  `BackgroundTaskRosterPayload.MarshalJSON` normalises nil→`[]`. `RateLimitedPayload` has no
  `MarshalJSON` on purpose (nothing-was-cut is an absence), so an allocating mapper would silently
  change the wire and present claude's cut text as complete.
- **`cmd/pyry/interactive_turn_v2.go`** — one `case turnevent.RateLimited:` in `Handle`'s type switch,
  body `flushDelta` then `emitMapped`, matching every other non-turn-scoped variant. No
  `startTurnIfNeeded`/`transitionTo`/`endTurn`; `inTurn`/`turnID`/`currentState` untouched. The
  variant-specific reason: a usage limit is a condition of the *account*, not the turn — claude emits its
  line once per run regardless of turn state, so the frame may legitimately arrive with no turn open at
  all.
- **`eventKind` (`:501-509`) was not touched** — it already returned `"rate_limited"` since #1404. This
  ticket adds `TestInteractiveTurnEmitterV2_RateLimitedEventKindNamesTheVariant`, the test #1404's code
  review flagged as a SHOULD FIX gap.
- **AC1's byte-level pin inverts its own template's polarity.**
  `TestMapEventBackgroundTaskRosterEmptyTasksOnTheWire` is the only structural precedent for "assert on
  what `MapEvent` returned, not a test-built payload," but it *demands* `"tasks":[]` and *forbids* `null`
  because that payload owns a nil→`[]` `MarshalJSON`. `RateLimitedPayload` has none, so the new
  `TestMapEventRateLimitedTruncatedFieldsOnTheWire` takes the shape and inverts the assertion: `want`
  `"truncated_fields":null`, `notWant` `"truncated_fields":[]`, with a populated-and-ordered control row
  so the nil row passes for the right reason.
- **AC3's log test drops `slog.TimeKey` via `ReplaceAttr`** rather than picking needles around it. The
  `ThinkingProgress` template's `strings.Contains` negative haystack includes slog's own `time=` attr;
  measured at 200k samples, the digit needle `"37"` collides with the timestamp 2.15% of the time, and a
  needle like `"-1"` is only safe on a `+03:00` host (an offset at UTC−10..−12 contains `-1` itself). The
  new test suppresses the entire false-positive source instead of relying on host-dependent sentinel
  naming; the existing `ThinkingProgress` test keeps its latent flake, out of scope here.
- **Doc sweep (AC4)** — all six enumerated stale-claim sites corrected in the same commit as the code
  (`ca2b07e`): `internal/protocol/codes.go`, `docs/protocol-mobile.md` (frame table row + the
  not-emitted-yet paragraph, `:931-933`), `docs/knowledge/features/protocol-package.md` (four sites,
  including the self-contradicting heading that split #1405's shape from #1410's mapping and correctly
  re-pointed the still-open silence sentinel at #1411 rather than claiming it landed), and
  `docs/knowledge/features/turnbridge-package.md`'s `MapEvent` table, which gained the `RateLimited` row.
  The two "fourteen turn-stream events" literals and the dated changelog entry were left untouched, as
  specified — emitting an already-documented frame changes no count.
- **A seventh stale-claim site surfaced only in code review**:
  `docs/knowledge/features/streamsup-package.md:288-290` said `turnbridge.MapEvent` "correctly drops it
  through its existing `default:` arm" and "no protocol type and no bridge route exist yet" — both false
  after #1405/#1410, in a phrasing (`"drops it through its existing default: arm"`) that evaded all three
  of the developer's shape needles (`no producer wired` / `nothing emits` / `not emitted`). Fixed by the
  documentation phase in this pass; `acpbridge.MapUpdate` and `stream_turn_busy.go`'s claim in the same
  sentence stayed true and was left alone.

## Patterns established

- **A copied byte-level pin can be green on exactly the bug it exists to catch.** When the only
  structural template for "assert on the mapping's own output" comes from a payload with the opposite
  `MarshalJSON` polarity, copying its `want`/`notWant` rows verbatim ships a test that passes against an
  allocating mapper. Check whether the template's type and the new type agree on `MarshalJSON` before
  reusing its assertion polarity — see [`codebase/1405.md`](1405.md)'s identical lesson from the
  producing side; this is the consuming side hitting the same trap.
- **A stale-claim sweep scoped to an enumerated site list, plus a shape-grep for the claim's known
  phrasings, can still miss a claim that uses a different verb.** The developer's sweep caught six sites
  using `no producer wired` / `nothing emits` / `not emitted`; a seventh, phrased as `"drops it through
  its existing default: arm"`, survived both the enumeration and the grep. Worth widening the shape-grep
  vocabulary on future frame-emission tickets, and worth remembering that a claim's *evidence* (naming a
  specific fallback arm) can go stale even when its *headline* doesn't repeat the tell-tale words.

## Lessons learned

From the PR body's own "Lessons learned" section (developer, verbatim) and the code-review comment:

- A copied byte-level pin can be green on the bug it exists to catch — see Patterns established above.
- `slog`'s own `time=` attr is part of a `strings.Contains` haystack and is a host-dependent digit
  source; suppressing it via `ReplaceAttr` is more robust than needle selection.
- AC1's "distinct value per string field" and AC3's "no fixture value is a substring of the log"
  reinforce rather than compete: one conspicuous-sentinel-per-field set discharges both.
- The AC4 sweep's shape-grep (`no producer wired` / `nothing emits` / `not emitted`) found two sites the
  line-number enumeration missed but is not exhaustive on its own — code review found an eighth-phrasing
  survivor in `streamsup-package.md` that none of those three needles matched (fixed above, by the
  documentation phase).
