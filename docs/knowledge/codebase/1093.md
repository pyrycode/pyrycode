# Ticket #1093 — `internal/streamsup`: turncommit gate on `WriteTurn` send

Ports the turncommit gate from the PTY path (`supervisor.deliverViaSession`) onto the stream-json send
site, [`streamsup.WriteTurn`](../features/streamsup-package.md#turn-io--envelope-write--stdout-parser-1088)
(#1088). A queue head dropped during the wait for claude to become ready must never be delivered — this
slice makes `WriteTurn` claim the same gate, at the same point in the send sequence, that the PTY path
already claims.

## Implementation

- `WriteTurn` gains a `ctx context.Context` first parameter:
  `func WriteTurn(ctx context.Context, w io.Writer, prompt []byte) error`.
- Body order: `w == nil` → `ErrNoLiveChild` (unchanged, still first, no claim consumed) → gate claim
  (`if gate := turncommit.From(ctx); gate != nil && !gate() { return turncommit.ErrDropped }`) → marshal +
  write (unchanged). The claim sits *before* `marshalTurnEnvelope`, so a false claim writes zero bytes —
  verified by observing the sink (`bytes.Buffer.Len() == 0`), not merely that the call errors, and by
  driving the same false gate over an `errWriter` to prove the write path is never entered.
- `turncommit.ErrDropped` is returned **bare**, matching `deliverViaSession` — the queue keys
  drop-handling on `errors.Is(err, turncommit.ErrDropped)`, so it is not wrapped with `%w` context the
  way the marshal/write failures are.
- A nil gate (`turncommit.From` on a plain `context.Background()`) delivers unconditionally — the
  non-queue, direct single-turn send path.
- Two new imports in `envelope.go`: `context`, `internal/turncommit`.
- 4 call sites updated to the new signature: 3 in `envelope_test.go`, 1 in `roundtrip_test.go`'s
  multi-turn integration test. `WriteTurn` had zero production callers at merge time (verified via
  `codegraph_impact`) — this is a pure additive-guard slice with no consumer cascade. The eventual
  runner wiring (T4/T7) will call it from the msgqueue delivery seam, which already carries the gate on
  `ctx`.

## Patterns established

- **Nil-check-before-claim ordering.** The `w == nil` check precedes the gate claim so a no-live-child
  send stays retryable (`ErrNoLiveChild`) rather than permanently consuming the claim as a false
  `ErrDropped`. Claiming the gate marks a queue head un-droppable; doing that before there's a live
  child to write into would prematurely lock a head the caller still needs to be able to drop cleanly
  during the `ErrNoLiveChild` retry window. Pinned by `TestWriteTurn_NilWriterWinsOverFalseGate`, which
  asserts both the sentinel *and* that the gate closure's call counter stays at zero.
  This is the same "faithful mirror, adapted for the surrounding contract" move #1088's parser made
  against `mapper.go` — copy the reference idiom verbatim, then let the local pre-existing contract
  (here, `ErrNoLiveChild`'s retryability) decide ordering the reference implementation didn't have to
  choose.
- **Gate-consulted-exactly-once as its own test.** Beyond the false/nil/ordering cases, a dedicated
  counter-closure test (`TestWriteTurn_TrueGateDeliversOnce`) asserts the gate is called exactly once on
  a true claim — guards against a future refactor accidentally double-claiming or skipping the claim,
  independent of whether the envelope content assertion would catch it.
