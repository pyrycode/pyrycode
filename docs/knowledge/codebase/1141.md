# Ticket #1141 — Stream e2e harness helper + `send_message` liveness spec

Adds the shared harness for the stream-json interactive e2e suite: a helper
that opts a daemon into `interactive_runner:"stream-json"` via the production
config toggle, plus the first integrated spec proving one turn drains
end-to-end through a live relay round-trip. Split from #1135; blocked-by
#1140 (merged) for the fakeclaude stream-json mode this harness drives. The
rider specs (#1136–#1139) and the real-claude capstone (#1083) all ride the
helper this ticket adds.

## Implementation

- `StartStreamInteractiveWithRelay(t, home, initialUUID, relayURL, extraEnv...) *Harness`
  (`internal/e2e/harness.go`, beside `StartRotationWithRelay`). Writes
  `<home>/.pyry/config.json = {"interactive_runner":"stream-json"}` as a raw
  JSON string literal — **before** spawn (`resolveConfigPath` is read once at
  daemon startup) and **not** via an `internal/config` import, keeping
  `harness.go` import-lean under its `e2e || e2e_install` build tag (mirrors
  `seedBootstrapRegistry`'s existing raw-JSON convention). Then
  `ensureFakeClaudeBuilt` + `seedBootstrapRegistry(initialUUID)` +
  `spawnWith` with `PYRY_ALLOW_INSECURE_RELAY=1`, `PYRY_MOBILE_V2=1`,
  `PYRY_FAKE_CLAUDE_STREAM_JSON=1`, then `extraEnv...`. Deliberately sets
  **none** of `SESSIONS_DIR` / `INITIAL_UUID` / `TRIGGER` / `STDIN_LOG` —
  stream-mode fakeclaude (#1140) short-circuits above its `mustEnv` calls, so
  those envs are dead weight that would misrepresent the child's needs.
  `ClaudeSessionsDir` is left unset (stream mode opens no transcript).
- `internal/e2e/relay_v2_stream_send_test.go`
  (`TestRelayV2_StreamSendMessageDrainsTurn`, `//go:build e2e`). Lifts the
  pairing + `seedBoundConversation` + handshake + send + ack-await shape
  verbatim from `relay_v2_new_session_test.go`, then replaces the on-disk
  rotation assertion with an ordered two-milestone event drain (shape lifted
  from `relay_v2_interrupt_test.go`):
  - **M1** — `assistant_delta` with `ConversationID == knownConvID` whose
    `Text` contains the echoed prompt (`"e2e-1141-user:ping"`) — the
    non-vacuity guard proving the full
    phone→daemon→fakeclaude→daemon→phone round-trip, not merely "some text".
  - **M2** — terminal `turn_state{State:"idle"}` with
    `ConversationID == knownConvID`, observed *after* `sawDelta` (a leading
    `turn_state{responding}` arrives before the delta and is ignored until
    then).
  The ack (awaited first, 15s) is accept-into-backlog, not delivery —
  `streamRunner.WriteUserTurn` can return the retryable `ErrNoLiveChild`
  while the child is between spawn and stdin-ready, so the drain (20s) is
  the real completion signal, not the ack.

## The id-alignment invariant

The drain gate (`startStreamTurnDrainV2`, #1098) forwards an event only when
its sink tag equals `activeSession()`. The sink tag is the stream runner's
construction-time `cfg.SessionID` — the bootstrap **pool id**, pinned by
`seedBootstrapRegistry(t, home, initialUUID)`. `activeSession()` resolves the
active conversation to its bound session id, set by
`seedBoundConversation(t, home, knownConvID, initialUUID)`. Both calls must
share the same `initialUUID`. A mismatch drops every event at the gate and
hangs the drain — surfacing as an M1 timeout, not a clean failure at the seed
call. This is the single most likely mistake for a future caller (the rider
specs #1136–#1139 repeat this exact pairing).

## Patterns established

- **Config-file injection as an e2e harness pattern.** Every prior harness
  helper opts into daemon behavior via CLI flag (`extraFlags`) or env
  (`extraEnv`). This is the first to write `<home>/.pyry/config.json` before
  spawn, because the production toggle (`selectInteractiveRunner`) only reads
  the on-disk config, not a flag. Future config-driven toggles should follow
  this shape: raw JSON literal, written before `spawnWith`, exercising the
  same `config.Load` overlay path production uses.
- **Subtract, don't extend, when mirroring a template.** The spec description
  explicitly frames `StartStreamInteractiveWithRelay` as
  `StartRotationWithRelay` *minus* the sessions-dir/trigger/stdin-log
  machinery, not as a superset with new fields bolted on — a minimal-cost env
  is easier to reason about (and to review) than one that carries unused
  legacy plumbing forward.

## Lessons learned

- The spec's defensive `os.MkdirAll(claudeSessionsDir(home))` — flagged as an
  open question in the spec (does the daemon's rotation watcher need the
  transcript dir to exist under stream mode?) — proved unnecessary. Under
  stream mode the daemon comes ready without it: the rotation watcher
  tolerates an absent dir, and stream-mode fakeclaude binds no sessions dir
  at all. The belt line was dropped after validating green on first run.
  (From the PR body's Lessons learned section.)
