# Ticket #755 — `internal/acp`: JSON-RPC 2.0 line-delimited transport + method dispatch table

The **inbound transport floor** for the Agent Client Protocol (ACP,
Zed-stewarded) — the first slice of epic
[#600](https://github.com/pyrycode/pyrycode/issues/600) (`pyry acp`). A
greenfield `internal/acp` package owning line-delimited JSON-RPC 2.0 framing over
one `io.Reader` (inbound) + `io.Writer` (outbound) plus a method dispatch table.
It ships **no subcommand** ([#756](https://github.com/pyrycode/pyrycode/issues/756)),
**no outbound-request primitive** ([#757](https://github.com/pyrycode/pyrycode/issues/757)),
**no claude driving**, and **no real ACP method** — later tickets register
handlers against the dispatch table this ticket builds.

Split from #746, sub-issue of #600.
Spec: [`docs/specs/architecture/755-acp-transport.md`](../../specs/architecture/755-acp-transport.md).
Evergreen feature doc: [`features/acp-package.md`](../features/acp-package.md).
Not security-sensitive (a local editor speaks over stdio — no auth/crypto/network/untrusted-remote surface).

## Implementation

Greenfield package, 3 files, +808 LOC, **zero consumers** (nothing downstream to
break). Stdlib-only — imports no repo packages, and deliberately **not** the
mobile-wire `internal/protocol` envelope types (ACP's JSON-RPC 2.0 shape ≠ the
mobile custom envelope).

- **`internal/acp/acp.go`** — package doc (incl. the hard cost invariant + batch
  decision), `Handler` func type, `Transport`, `New`/`Register`/`Serve`, the
  `bufio.Scanner` read loop, `handleLine` classify+dispatch, and the
  `writeMu`-guarded write helpers.
- **`internal/acp/jsonrpc.go`** — the `Code*` constants, the exported `Error`
  type + `NewError`, and the unexported wire types: one **decode-by-shape**
  `rpcMessage` (inbound) + `successResponse` / `errorResponse` / `rpcError`
  (outbound).
- **`internal/acp/acp_test.go`** — 18 table-driven tests (see feature doc).

### Exported surface — 3 types (under the 5-type sizing line)

`Transport`, `Handler`, `Error` — plus `New` / `NewError` and the five `Code*`
constants (`-32700/-32600/-32601/-32602/-32603`). Holding to three types is what
kept the ticket **S**; the lever was a **single decode-by-shape `rpcMessage`**
over separate request/notification/response structs.

### Classify-and-reply (`handleLine`)

Each trimmed line is classified in order: `json.Valid` gate → first-byte peek
(`[` = batch reject, non-`{` = invalid) → typed `json.Unmarshal` → presence
switch on `method`/`id`/`result`/`error`. Requests dispatch and get **exactly one**
response with the echoed id; notifications dispatch and get none; **response
frames are tolerated** (dropped, logged debug) as the [#757 seam](#757-response-frame-tolerance-seam);
parse/invalid/batch produce the matching JSON-RPC error frame with id `null`. The
handler contract returns `(result, err)`: a `*Error` controls the wire code, any
other error maps to `-32603` with a generic message (real detail logged to
stderr, never leaked). Full decision table in
[`features/acp-package.md`](../features/acp-package-classification-decision-table-the-core-mechanism.md#classification-decision-table-the-core-mechanism).

### Concurrency

One read-loop goroutine dispatching handlers **serially, inline**. Writes go
through one `writeMu`-guarded `writeMessage` over a `*json.Encoder` bound to `w`
(`SetEscapeHTML(false)`). Register/Serve ordering is an `atomic.Bool` `started`
flag — the handler map is write-once-before-`Serve`, read-only during, so it
needs no lock. Mirrors [`internal/dispatch`](../features/dispatch-package.md#register-before-run-is-enforced-not-advisory).

## Patterns established

- **Decode-by-shape over a struct-per-frame-kind.** A single `rpcMessage` whose
  `*string` / `json.RawMessage` fields are classified by nil-ness collapses
  request/notification/response detection into one type — holding the exported
  surface under the sizing line. The whole classifier's input is
  absent-vs-present-`null`: an absent JSON key leaves the field nil, a present
  key (even literal `null`) leaves it non-nil.
- **A redundant leaf mutex placed as a named future seam.** `writeMu` is
  redundant under today's single-goroutine dispatch, but installing it now means
  #757's outbound-request writer adds an agent→client caller with **no rework of
  the write path**. Documented at the field as the seam it is, not as
  present-tense concurrency.
- **State the invariant at the layer it constrains, even when this ticket can't
  violate it.** The interactive-claude cost invariant (drive real interactive
  `claude`, never `claude -p` or the metered Agent SDK) is recorded in the
  package doc comment though #755 drives no claude — so the constraint is visible
  to every later ACP-method ticket that does.
- **A narrower-than-stdlib trim when it changes the accept set.** A local 4-byte
  `trimSpace` (space/tab/CR/LF only) is used instead of `bytes.TrimSpace`, which
  also strips Unicode whitespace and would silently widen the accepted framing to
  inputs strict JSON rejects — the same `TrimSuffix`-over-`TrimSpace` discipline
  `internal/identity` follows.
- **No-content-logging on a transport carrying user prompt material.** An ACP
  request's `params` may carry user prompt content, so diagnostics log method
  names, error kinds, and structural facts only — never line bytes or `params`.
  Mirrors `internal/agentrun/jsonl`.

### #757 response-frame tolerance seam

A well-formed JSON-RPC response frame (id + result/error, no method) is
**dropped with no writer output**, not rejected as invalid request — the single
observable ([`TestTransport_ResponseFrameTolerated`](../features/acp-package.md#test-surface-internalacpacp_testgo))
#757 will replace with response routing when it makes the transport bidirectional.
This is a deliberate scope boundary between the two tickets, pinned by a test now
so #757 changes behaviour against a known baseline.

### Batch rejection (recorded in the package doc comment)

A top-level JSON array is rejected with a **single** `-32600` (id `null`);
batching is unsupported. ACP does not use JSON-RPC batching, so the deviation
from the spec's per-element handling is inert and keeps the transport a strict
one-frame-per-line reader.

## Code review

**PASS**, two non-blocking NITs (not applied — style suggestions):
1. `TestTransport_ContextCancelledBetweenFrames` reuses one `bytes.Buffer` for
   both the writer and the diag sink (harmless — the cancel-before-first-frame
   path writes nothing to `w`).
2. The `scanner.Bytes()` retention comment could state the load-bearing reason
   more directly: `json.Unmarshal` **copies** `json.RawMessage` fields out of the
   scanner buffer (so `params` never aliases the reused buffer); handlers running
   inline before the next `Scan` is the secondary guard.

All five ACs satisfied; blast radius nil (greenfield, zero consumers); real-claude
e2e suite green.

## Lessons learned

- **Verify `json.RawMessage`'s absent-vs-present-`null` semantics empirically
  before building a classifier on it.** Unmarshalling `"id":null` leaves the
  field **non-nil** (bytes `null`), while an absent key leaves it nil — that is
  exactly what separates a null-id *request* (dispatched, response id `null`)
  from a *notification* (no id, no response). This edge is load-bearing for the
  whole decode-by-shape design; it was verified empirically before coding and is
  pinned by `TestTransport_Request_NullIDIsARequest`. Worth a fixture if the
  classifier is ever refactored.
- **`bytes.TrimSpace` is the wrong tool when the trim set is part of a spec
  contract.** It strips Unicode whitespace (e.g. a non-breaking space), which
  would silently accept framings strict JSON rejects. The 4-byte local
  `trimSpace` keeps the accept set spec-matching — the same reasoning behind
  `internal/identity`'s `TrimSuffix`-over-`TrimSpace` choice.

## Out of scope (deferred)

- **Subcommand wiring** (#756) — real stdio, the `internal/control` `SlogTee` +
  `NewRingBuffer` stderr wiring, and the closer that unblocks a blocked stdin
  read on shutdown (a `Read` already blocked can't be unblocked by ctx alone —
  Go limitation; #755 is tested against in-memory pipes that EOF naturally).
- **Outbound-request primitive** (#757) — makes the transport bidirectional;
  replaces the response-frame drop with response routing; reuses `writeMu`.
- **Concurrent dispatch** — serial-inline chosen for simplicity; moving to a
  worker needs no wire-contract change. Deferred until observed need.
- **Real ACP methods** — every `session/*` handler is a later ticket's pure
  registration against this dispatch table.
