# Ticket #1150 — Family B (outbound turn-stream resolvers) migrated onto `internal/transcript`

Split from #973. Rewrites `resolveLatestSessionJSONL`, `resolveOwnBootstrapJSONL`, `resolveBoundSessionJSONL`, and the `resolveBootstrapJSONL` dispatcher in `cmd/pyry/interactive_turn_stream_v2.go` as thin adapters over the `internal/transcript` leaf (#1148). Mirrors the merged Family A shape (#1149, spec merged, implementation on `feature/1149` at the time this shipped — see Lessons learned). Behaviour-preserving: no public signature changes, no consumer cascade, net deletion of duplicated logic.

## Implementation

PR #1158, two files, net +144/-89 lines (`cmd/pyry/interactive_turn_stream_v2.go`, `interactive_turn_stream_v2_test.go`).

- Deleted the local `jsonlStreamExt` const and `jsonlStemPattern` regexp (and the now-unused `regexp`/`strings` imports) — replaced by `transcript.Ext` / `transcript.ValidStem`.
- `resolveLatestSessionJSONL`'s inline `os.ReadDir` + newest-by-mtime loop → `transcript.Newest(dir)`.
- `resolveOwnBootstrapJSONL`'s construction-time `EvalSymlinks`/`Clean` → `transcript.CanonicalDir(dir)`; its inline confidentiality guard → `transcript.GuardProbedPath(open, canonicalDir)`, called **directly** (not via `transcript.Probed`) so the resolver keeps its own per-branch pid/probe/empty/stat orchestration.
- `resolveBoundSessionJSONL`'s inline `filepath.Join` + `os.Stat` → a local `ValidStem` pre-check (branch-selector) followed by `transcript.StatByID(dir, sessionID)`.
- `resolveBootstrapJSONL` dispatcher: one predicate swap, `jsonlStemPattern.MatchString(id)` → `transcript.ValidStem(id)`.
- `bootstrapProbeUsable` / `availabilityReporter` stayed local per AC1 (mirrors Family A's retained `probeUsable`) — probe-capability detection and the no-lsof→mtime delegation are Family-B composition policy, not core resolution logic.

Both load-bearing conventions were preserved verbatim:

- **Error-on-not-found** (inverted from Family A): every no-result branch (dir unreadable, no matching file, `pid <= 0`, probe error, empty open path, guard reject, by-id file absent, invalid stem) still returns a non-nil error so the subscriber retries — never `("", 0, nil)`.
- **Per-subscription cold/warm offset rule** (`resolvedOnce` / `sawEmpty`): unchanged across all three stateful resolvers.

**Why `GuardProbedPath` directly, not `transcript.Probed`, for the probe resolver:** `Probed` collapses every benign no-result (`pid <= 0`, empty open, guard reject, vanished-before-stat) into one `(Result{}, nil)`, which would force `sawEmpty` onto the guard-reject branch — a behaviour change, since the pre-migration code sets `sawEmpty` on some no-result branches (`pid <= 0`, empty open path, vanished-before-stat) but not others (probe call error, guard reject). Keeping the per-branch orchestration local and adopting only `CanonicalDir` + `GuardProbedPath` preserves the exact `sawEmpty` table.

**The one intentional micro-delta (cosmetic):** the old guard had two reject branches with distinct error strings ("probed jsonl outside sessions dir" / "…is not a session jsonl"); `GuardProbedPath` returns a single `ok bool`, so both collapse to one `!ok` branch with one error string. Neither string ever logged the probed path either before or after.

## Patterns established

- **A migrating adapter can diverge from its sibling's core-vs-adapter split when their stateful conventions differ**, even while sharing the same primitives. Family A composes `transcript.Probed` and swallows its error (no cold/warm state to protect); Family B composes `GuardProbedPath` directly because its `sawEmpty` state is keyed per-branch in a way `Probed`'s collapsed result would erase. Both are correct adapters over the same leaf — "call the higher-level primitive when available" is not a universal rule once caller-side state enters the picture.
- **A `ValidStem` pre-check ahead of a primitive that also validates internally is not redundant** — it is the branch-selector that keeps an invalid-stem input out of the `sawEmpty`-setting error branch the primitive's own validation would otherwise route it through. Same role in both `resolveBoundSessionJSONL` here and Family A's pinned-id path (#1149).

## Lessons learned

(From the PR #1158 body.)

- Migrating a resolver family whose sibling (Family A, #1149) has a merged *spec* but not-yet-merged *implementation* is fine: the shared leaf (`internal/transcript`) is what you actually depend on, so mirror the spec's described shape rather than the sibling's on-disk code.

## Out of scope (named in the ticket, unchanged)

- The owned-fd tail-API adoption (offset semantics change) — offset derivation stays caller-side in this ticket; sequenced as a downstream sibling so the resolver file isn't churned twice.
- Family A (`internal/sessions/reconcile.go`) — separate ticket (#1149).
- The dead-wired modal `resolveTarget` (screenOnly since #1070) — left as-is.
- `internal/sessions/rotation/watcher.go`'s local `uuidStemPattern` — out of scope, untouched.
