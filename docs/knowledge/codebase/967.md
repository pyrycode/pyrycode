# Ticket #967 — remove the dead `backfill_since` wire flow

`backfill_since` was allowlisted (`v1TypeSet`) and documented but had no
handler on either v2 dispatch surface — the same latent class as #949
(`promote_conversation`), but the **opposite** resolution: #949 had live
shipping-client senders and was *implemented*; the whole backfill flow
(`backfill_since` → `message_chunk*` → `backfill_done`) had zero emitters
and zero handlers anywhere (cross-repo pre-verified against
`pyrycode-mobile` / `pyrycode-desktop`, re-confirmed in-repo), so it was
*removed*. The v2 reconnect path (`request_snapshot` + `hello.last_event_id`
bounded-ring replay, ADR 025 / #646/#647) replaced backfill entirely; no
message-history store exists that a handler could have read from. #913
("Remove the v1 relay dispatch branch") was CLOSED/shipped and had already
removed the v1 dispatch code but left these three orphaned type constants
behind — this ticket is the cleanup #913 didn't cover.

## Implementation

Pure, compiler-and-guard-enforced dead-code deletion, `927face`, ~11
insertions / 167 deletions across 12 files. No new types, no logic:

- **`internal/protocol/codes.go`** — deleted the `// Backfill.` comment
  block and the three `Type*` consts (`TypeBackfillSince`,
  `TypeMessageChunk`, `TypeBackfillDone`).
- **`internal/protocol/envelope.go`** — deleted the three `v1TypeSet`
  entries. This *tightens* the untrusted wire accept-set: a client sending
  `backfill_since` now rejects one step earlier, at `IsV1Compatible` as
  `ErrUnknownType`, instead of falling through to `protocol.unsupported`.
- **`internal/protocol/messaging.go`** — deleted the three payload structs
  (`BackfillSincePayload`, `MessageChunkPayload`, `BackfillDonePayload`).
- **`internal/protocol/messaging_test.go`** — deleted the three round-trip
  tests; `testdata/{backfill_since,message_chunk,backfill_done}.json`
  removed via `git rm`.
- **`internal/protocol/compat_test.go`** — dropped the three types from all
  three lists (`:21`, `:119`, `:202`) and the hardcoded type-list count
  `26 → 23`. The `TestTypeConstants_V1V2Partition` union check
  (`len(v1TypeSet)+len(v2OnlyTypes) == len(all)`) is self-balancing under
  the removal — no magic number there.
- **`cmd/pyry/relay_guard_test.go`** — deleted the three `excludedTypes`
  "v1-legacy" entries in `TestEveryInboundV2TypeHasHandler`. This is the
  **removal-direction twin** of the known "new `Type*` trips the second
  totality guard" pattern: the guard's inverse assertion (classified name
  has no matching constant) trips if the `excludedTypes` entries are left
  behind after the `codes.go` consts are deleted, so the two files must be
  edited in lockstep.
- **`docs/protocol-mobile.md`** — removed the three verb names from the
  inline type list, the three descriptor-table rows, the deferred-handler
  clause, and the Mode-A backfill bullet. The `## Reconnect / Backfill
  semantics` heading was **kept verbatim** — it also documents the live
  ring-replay reconnect mechanism, and preserving it kept the
  `#reconnect--backfill-semantics` anchor resolvable for its ~4 other
  referrers without having to touch every one.
- **Four stale comment cross-refs repaired** (the non-obvious part of the
  ticket — two were named in the AC, two were only caught by the
  completeness grep):
  - `settings.go:23` — dropped `BackfillSincePayload` from the sibling
    `*string`-no-`omitempty` precedent parenthetical, leaving
    `SessionTransitionPayload`.
  - `handshake.go:27` — re-cited `§ Backfill semantics` as
    `§ Reconnect / Backfill semantics` (the surviving heading). The live

  - `messaging.go:52-53` — reworded the `SessionTransitionPayload.WorkspaceCwd`
    comment to describe the `*string`-no-`omitempty` idiom directly instead
    of citing the now-removed `BackfillSincePayload.ConversationID`.
  - `messaging_test.go:204` — reworded `(mirrors backfill_since's guard)` to
    name no removed symbol.

## Patterns established

- **Allowlisted-but-unhandled wire verb is a class, not a one-off.** #949
  and #967 are the same latent-gap diagnosis (`v1TypeSet` member with no
  dispatch entry) reaching opposite resolutions purely on sender evidence:
  live shipping-client senders → implement; zero senders anywhere → remove.
  A future instance of this class should be triaged the same way before
  picking a resolution.
- **Removing a `Type*` constant requires touching `relay_guard_test.go`'s
  `excludedTypes` in the same change**, not just `codes.go` — the guard's
  inverse assertion (every classified name still maps to a real constant)
  fails otherwise. This mirrors, in the removal direction, the existing
  "new `Type*` trips the second totality guard" gotcha.
- **A literal `grep` AC for "no trace of X remains" needs word-boundary
  anchoring**, not a plain substring match. `message_chunk` /
  `MessageChunk` are substrings of the live, unrelated ACP bridge vocabulary
  (`agent_message_chunk` / `AgentMessageChunk`); a naive grep will always
  report false positives there. The spec's `[[:<:]]`/`[[:>:]]` form is BSD
  grep syntax and matches nothing under `ugrep`/GNU grep (which this repo's
  `make check` actually runs) — use `\b` instead on those tools. Separately,
  `\bBackfillSince\b` does not match glued identifiers like
  `TypeBackfillSince` / `BackfillSincePayload`, so a boundary grep is at
  best a coarse completeness check; the real enforcement is `go build`
  (a dangling const reference won't compile) plus the guard test's inverse
  assertion.

## Lessons learned

- **A dead-code-removal ticket's doc-cleanup obligation extends beyond the
  ticket's own ACs.** This ticket's AC #1 scoped the grep-verified cleanup
  to `internal/`, `cmd/`, and `docs/protocol-mobile.md`; it did not (and
  per the code-review's read of the AC, could not literally) reach into
  `docs/knowledge/features/` — those evergreen docs cited the removed types
  by name in several places, including as the **canonical precedent
  example** for a still-live idiom (`*string` without `omitempty` for a
  wire-null sentinel). Reconciling those citations to point at
  `SessionTransitionPayload.WorkspaceCwd` instead (mirroring exactly what
  the code changes did at `settings.go:23` / `messaging.go:52-53`) was left
  to this documentation pass, per PR #1036's code-review NIT findings.
- **A chronological "extended by ticket" narrative embedded in an INDEX.md
  entry accumulates numeric claims (partition sizes, type counts) that go
  stale the moment a later ticket changes the base count without a matching
  edit.** The `protocol-package.md` INDEX.md entry's `19 + 25 == 44`
  partition-size claim (originally written when landing #1007) was already
  wrong at the time it was written — #822/#881 had already pushed the real
  v1 count past 19 — and removing three more types here only compounds an
  already-stale figure. Fixed the two immediate consequences of *this*
  ticket's removal (`protocol-package.md`'s own `19→16`/`44→41`
  restatement, kept internally self-consistent) but did **not** attempt a
  full reconciliation of the pre-existing undercount (the workspace/archive
  verb family — `TypeArchiveConversation`, `TypeUnarchiveConversation`,
  `TypeChangeWorkspace`, `TypeCreateWorkspaceFolder`,
  `TypeWorkspaceFolderCreated`, `TypeRecentWorkspaces`,
  `TypeRecentWorkspacesList` — was never added to `protocol-package.md`'s
  "Envelope types" table/count) — that's a separate, larger gap unrelated
  to backfill removal, flagged here for a future doc pass rather than
  folded into this ticket's scope.
