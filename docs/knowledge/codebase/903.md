# Ticket #903 — e2e: a modal missed while disconnected is re-delivered exactly once and answerable exactly once on reconnect

The **modal half of #829**'s end-to-end acceptance slice (ADR 025 → "Backpressure /
replay"), split alongside the queue half (#904, open at the time of writing). #829
itself is now **closed**, superseded by this split. Test-only — no production change —
one new file, `internal/e2e/relay_v2_modal_reconnect_test.go` (`//go:build e2e`), proving
the cross-layer contract that unit tests alone couldn't: a real fake client,
disconnected then reconnected over a fresh Noise handshake, sees a permission modal
raised in its absence exactly once and can answer it exactly once, with a genuinely
driven second answer observed rejected.

## Implementation

Four additions, all test-local, reusing the frozen `#791` modal e2e patterns
(`relay_v2_modal_answer_test.go`) rather than mutating them (the established
deliberate-duplication house pattern from `relay_v2_two_head_modal_test.go`):

- **`bringUpReconnectModalHarness`** — mirrors `bringUpModalHarness` through pairing
  (`phone-a` **with** `--allow-remote-permissions` — without it the reconnected
  answer denies at the #702 device gate and the AC3 negatives go vacuous), sessions-dir
  alignment, and the `PYRY_MOBILE_V2=1` + `PYRY_FAKE_CLAUDE_MODAL_TRIGGER` fakeclaude
  spawn, but deliberately stops short of dialing a phone — the test owns
  connect/disconnect/reconnect itself.
- **`openInteractivePhone`** — factors the `sealSend`/`nextEnv` closures (previously
  inlined in `bringUpModalHarness`) into a reusable seam bound to a fresh
  `fakephone.Dial` + `driveHandshakeToOpenDaemonInteractive` handshake. A reconnect is
  `old.phone.Close(); ps := openInteractivePhone(t, h, "phone-a")` with the **same**
  token — same device identity, brand-new `conn_id` + fresh Noise `CipherState`s. This
  is the only reconnect shape `fakephone`/`fakerelay` can express (fresh `conn_id` per
  `/v1/client` upgrade, no 30 s grace — `fakerelay.go:33`), and it is exactly the
  fresh-attach path `reconcileModals` (#877) fires on.
- **`assertModalShownFor(t, ps, wantID)`** — drains for a `modal_shown`, asserts
  non-empty `modal_id` (equal to `wantID` when given), `Class == "permission"`, and the
  fixed four option IDs. Used twice: to capture the true original `modal_id` from
  phone #1's live raise-time delivery, and to assert the re-delivered id from phone #2's
  reconcile matches it.
- **`TestRelayV2_ModalReconcileOnReconnect`** — six-step flow, each step a hard
  precondition of the next (assertion order is load-bearing): (1) phone #1 connects,
  trips the modal trigger, observes the live `modal_shown`, captures the original
  `modal_id` X; (2) `phone.Close()` — disconnect, modal stays outstanding; (3) phone #2
  reconnects with the same token — fresh handshake → `reconcileModals`; (4) phone #2
  observes a re-delivered `modal_shown` with `modal_id == X`; (5) phone #2 answers
  `allow_always` — asserts `modal_dismissed` and exactly one `"2\r"` keystroke (not the
  default `"1\r"`) in the fakeclaude stdin log, proving the reconnected conn's answer
  actually routed; (6) phone #2 sends a **second** `modal_answer` for X — asserts no
  second `modal_dismissed`, no `TypeError`, and a byte-for-byte unchanged stdin log.

## Patterns established

- **AC1's "both reconnect modes" collapses to one daemon-observable path, and that
  collapse is a design fact, not a coverage gap.** `reconcileModals` is grace-agnostic —
  it fires on every fresh interactive handshake regardless of how long the client was
  away, reading current registry truth. The product's "within grace / same session"
  mode is #874's hold + #875's flush (a *surviving* conn), which `modal_shown` never
  rides because it's raised while the conn is absent and carries no `EventID`. So
  "within grace" for the modal signal is #874/#875's contract; "after grace / fresh
  attach" is #877's — and this ticket's. A cosmetic "within grace" subtest over a
  graceless harness (`fakerelay` implements none) would be exactly the
  false-certification this security-sensitive ticket exists to prevent, so it's named
  as an Open Question rather than faked.
- **Isolation via strict happens-after, not a mechanism stub.** Phone #2 dials *after*
  the modal is Recorded (fenced by phone #1's live observation), so
  `broadcastInteractive` (raise-time-only fan-out) structurally cannot have targeted
  it — reconcile is provably the *only* delivery path exercised. This is what makes a
  green test mean "reconcile works," not "some broadcast got lucky."
- **"Positives gate the negative" (from #791) extended across a reconnect.** Step 5
  (dismissal + exactly one chosen keystroke) must `t.Fatal` before step 6 sends the
  double-answer — otherwise "no second dismissal" could pass vacuously for a modal that
  was never actually re-answerable. Same doctrine as the #791 replay-rejection test,
  now proven to survive a real disconnect/reconnect in between.
- **A reusable bring-up factored out of a frozen fixture, not a mutation of it.** The
  `sealSend`/`nextEnv` closure bodies are copied verbatim from `bringUpModalHarness`
  (byte-frozen since #791) rather than exported from it — keeping the original
  single-connect fixture's contract untouched while giving this reconnect-shaped test
  its own bring-up. Anticipated reuse: #904 (the queue twin) can lift
  `openInteractivePhone` verbatim.

## Security review

`security-sensitive` (per split rationale — this ticket carries the security-*property*
test of the #829 split; the correctness-only proof is out of scope here). Architect
self-review verdict: **PASS**, re-confirmed at code review. The crux question for a
test-as-artifact review is not "does this open an attack surface" but "can this test
pass while the guarantee it certifies is broken" — addressed by the load-bearing
assertion order (step 5 gates step 6) and the happens-after isolation (phone #2 cannot
receive a raise-time broadcast). No new production surface: the reconnect is
`Close()` + `Dial()` on the in-process `fakerelay`; auth is the daemon's real Noise_IK
handshake and the real `--allow-remote-permissions` device gate, neither stubbed nor
weakened. `AnswerToken` is a client-minted test literal on the inbound payload only; the
outbound re-sent `modal_shown` carries none. Full findings: spec §"Security review"
(`docs/specs/architecture/903-modal-missed-while-disconnected-redelivered-e2e.md`).

Code review additionally cross-checked the test's claims against production
(`internal/relay/v2session.go:2222`'s `reconcileModals`): confirmed it unicasts the
same `ModalShownPayload`/`modal_id` and arms no timer/resolve path, backing the test's
AC2 (same-nonce) and AC3 (deny-clock-not-reset, structural) claims independently of the
test's own assertions.

## Testing

`go test -tags e2e -run TestRelayV2_ModalReconcileOnReconnect -race -count=1
./internal/e2e/...` — PASS, 4.87s, non-vacuous (real modal raised, real answer routed,
real second answer observed rejected). `go vet -tags e2e ./internal/e2e/...` clean (the
build-tagged file sits outside the untagged QA gate's `go vet ./...`, so code review ran
it directly). `go build ./cmd/pyry` OK. Full `go test -race ./...` green except the
pre-existing `#905` msgqueue deadlock (`TestQueue_SnapshotAll_RaceWithEnqueueAndDrain`,
from #878), unrelated to this test-only change.

## Lessons learned

- **zsh does not word-split an unquoted `$var` holding a newline-separated `go list`
  result** (unlike bash) — it reaches `go test` as one malformed import path
  (`invalid char '\n'`). Use `go list ./... | xargs go test`, not `go test $PKGS`, when
  running package lists from zsh. This exact artifact stalled the original dev-agent
  run into a permission-denial salvage (an intermediate WIP commit was auto-preserved
  by the dispatcher; the re-run completed clean under `xargs`). See
  [[env-zsh-golist-var-not-word-split]].
