# Ticket #1192 — Record the interrupt route's three signature-stable inert arms

Split child A of #1190 (itself split from the earlier #1188). The interrupt route
is silent on success and on almost every failure, so a live daemon log showing
nothing after an inbound `interrupt` frame is equally consistent with four
different faults: the frame never arrived, the conn was not interactive, the
route went silently inert, or the keystroke actuated and claude ignored it — each
with a different fix. A live desktop run on 2026-07-24
(`real-claude-interrupt`, pyrycode-desktop#483) burned 2m10s on exactly this
ambiguity before teardown. This ticket instruments the three arms reachable
**without changing any function signature**; the remaining two (successful
actuation, and the `interruptRunner` arm where the resolved runner exposes
neither interrupt method) need a signature change and are #1193's.

## Implementation

- Three new `Info`-level records, one per arm, sharing the pre-existing
  `v2.interrupt.*` event naming (`v2.interrupt.inert`, `v2.interrupt.keystroke_err`):
  - `v2.interrupt.non_interactive` — `internal/relay/v2session_modal.go`,
    `handleInterrupt` step 1 (`!s.interactive`). Carries `conn_id` only. Emits
    with the whole `*V2Session` in scope; `s.peerStatic` (identity-bearing,
    MUST NOT be logged per the package's no-key-in-logs discipline) and
    `s.device` are both in scope at that point and neither is included.
  - `v2.interrupt.no_active_conv` — `cmd/pyry/main.go`, `activeInterrupter.SendEsc()`
    when `currentConv() == ""`. No fields beyond the event — there is no
    conversation id to carry, so the record's information is its existence.
  - `v2.interrupt.no_bound_runner` — same method, when `resolveRunner(convID)`
    returns `!ok`. Carries `conversation_id` (the house key used elsewhere in
    `cmd/pyry`, e.g. `interactive_turn_v2.go`), not `conv_id`.
- **Level is `Info`, not `Debug`, and this was load-bearing, not stylistic.** The
  daemon defaults to `slog.LevelInfo`; `Debug` needs `-pyry-verbose`. A `Debug`
  record would have reproduced the exact 2026-07-24 failure mode: reproduce,
  read the log, see nothing, for an intermittent live failure that may not
  recur on the re-run. The pre-existing `v2.interrupt.inert` (nil interrupter)
  stays at `Debug` and is untouched — it reports a foreground/pre-wire
  configuration, not a live-daemon runtime state.
- `activeInterrupter` (`cmd/pyry/main.go`) gained an optional `log *slog.Logger`
  field plus a nil-normalizing `logger()` accessor (falls back to
  `slog.Default()`, not a discard handler). The struct is a constructor-less
  bag of injected seams built as a named-field literal at 5 sites; a mandatory
  field would mean every literal that omits it panics on first use of a
  rarely-hit inert arm — in this case a remotely-driven relay-path panic. The
  accessor makes that hazard structurally impossible instead of relying on
  every call site remembering to set it. Production wiring
  (`cmd/pyry/main.go:996`) gained one line: `log: logger`.
- No control-flow change anywhere: every arm returns exactly what it returned
  before (arm 1 `return`s, arms 2/3 return `nil`). The `resolveBoundRunner`
  `conv.CurrentSessionID == ""` guard (#678 cross-conversation isolation
  enforcement) is untouched, as is `interruptRunner` itself.

## Patterns established

- **An AC naming a test vehicle is only satisfiable if the vehicle is in the
  same package as the emission.** Arm 1 lives in `internal/relay`; the other
  two in `cmd/pyry`. Each package already had the logger-assertion helper it
  needed — `bufferLogger()` / `waitForLogContains` (relay, `TextHandler`,
  mutex-guarded because the manager emits on its own Run goroutine) and
  `auditLogger()` (`cmd/pyry`, `JSONHandler`, plain buffer — `SendEsc` runs
  synchronously on the test goroutine in `TestActiveInterrupter`, so no
  synchronization is needed). No new shared test infrastructure was required;
  a package boundary on the emission side means one vehicle per package, not a
  shared one.
- **Negative log assertions in a family of records must name the specific
  event, never the shared prefix.** `#1193` adds a record to the interrupt
  route's success path under the same `v2.interrupt.` family; a prefix-wide
  absence assertion in this ticket's tests would go red the moment #1193
  lands. Every negative assertion here names `v2.interrupt.non_interactive`,
  `v2.interrupt.no_active_conv`, or `v2.interrupt.no_bound_runner` explicitly.
- **A log-hygiene assertion has to be made per record line, not over the whole
  buffer.** The relay handshake in the same test buffer legitimately emits the
  device name (`device_name=v2-test-phone`), so a buffer-wide "must not
  mention the device" check would fail for the wrong reason.
  `slog`'s `TextHandler` emits one line per record, which is what makes a
  per-line hygiene check possible; a 6-line local line-finder was added to
  `internal/relay/v2session_interrupt_test.go` rather than promoted to shared
  infra, since nothing else needs it.
- **Nil-normalizing accessor over mandatory field, for a constructor-less
  seam-bag struct built at multiple named-field-literal sites.** Same shape as
  package `main`'s existing `stream_turn_drain.go` nil-logger idiom, moved
  from a constructor to point-of-use because `activeInterrupter` has no
  constructor to put it in.

## Lessons learned

(from the PR body, PR#1194)

- A log-hygiene assertion has to be made **per record line**, not over the
  whole buffer: the relay handshake legitimately emits `device_name=v2-test-phone`
  into the same test buffer, so a buffer-wide "must not mention the device"
  check fails for the wrong reason. `slog`'s `TextHandler` emits one line per
  record, which is what makes the per-line form available.
- Negative log assertions in a family of records must name the **specific**
  event, never the shared `v2.interrupt.` prefix — a prefix-wide absence check
  here would go red the moment #1193 adds its success-path record.

## Interim gap (closed by #1193)

After this ticket, an empty `v2.interrupt.*` log still did **not** prove an
interrupt frame never arrived: the successful actuation and the
`interruptRunner`-neither-method inert arm both stayed silent (both live
behind `interruptRunner`, whose signature had to change to reach them). This
was recorded as an explicit interim caveat in the route's doc comments
(`cmd/pyry/main.go` `SendEsc` doc, `internal/relay/v2session_modal.go`
`handleInterrupt` doc) and in
[`features/v2-session-manager.md` § Inbound interrupt](../features/v2-session-manager.md#inbound-interrupt-707--interrupter-seam--esc-routing).
**#1193 closed the gap**: both doc comments and the feature doc now state the
invariant instead of the caveat — see [`codebase/1193.md`](1193.md).
