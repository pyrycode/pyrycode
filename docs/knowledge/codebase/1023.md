# Ticket #1023 — move modal lifecycle + queue reconcile out of `v2session.go`

Third slice of the [#964](https://github.com/pyrycode/pyrycode/issues/964)
split of `internal/relay/v2session.go`, chained after
[#1021](1021.md) (handshake) and [#1022](1022.md) (rekey). Carves the modal
lifecycle and the queue reconcile/dequeue handlers — cohesive because both
reconcile per-session state on reconnect (`reconcileModals` and
`reconcileQueues` sit adjacent in the file) — into a new file in the same
`package relay`. Pure mechanical move: no exported-API change, no behaviour
change, and because everything stays in-package, zero call-site changes
anywhere in the tree.

## Implementation

New file `internal/relay/v2session_modal.go` (586 lines) now owns 16
declarations: the queue types/const (`queuedEnv`, `pushQueue`,
`(*pushQueue) enqueue`, `pushQueueCap`), `modalDenyTimeout`,
`ModalDismissal`, and the ten methods `ArmModalTimeout`,
`handleModalCancel`, `handleModalAnswer`, `handleModalTimeout`,
`broadcastModalDismissed`, `reconcileModals`, `reconcileQueues`,
`handleInterrupt`, `handleNewSession`, `handleDequeueMessage`.
`v2session.go` drops by 568 lines to 2307.

The `ModalResolver` seam interface and the `V2SessionConfig.ModalResolver`
field **stay in core** — `ModalResolver`'s method signatures reference the
moved `ModalDismissal` type, which resolves in-package with no edit needed;
the seam interfaces are their own later slice per the ticket's Technical
Notes. Every other seam interface (`ScreenSnapshotter`, `Interrupter`,
`SessionStarter`, `QueueRemover`, `SettingsUpdater`) and all interleaved
neighbours (`idleTimeout`, the `Err*` sentinels, the `wakeKind` iota block,
`V2SessionState`, `V2Session`, `V2SessionManager`) stay untouched.
`v2session_handshake.go` (#1021) calls `reconcileModals`/`reconcileQueues`
at lines 333/343; those resolve same-package to the new file with no edit
required there — confirming AC#3.

The `slices` import was dropped from `v2session.go`: its only *code* use in
the whole file was `slices.Delete` inside `pushQueue.enqueue`, which moved
with the carve-out, orphaning the import. The compiler forced the removal.
`base64`'s only user (`marshalInnerFrameV2`) stayed in core, so that import
was untouched — the delta is exactly one import, squarely within AC#2.

## Patterns established

None new — the third consecutive confirmation of the #964 pure-move
discipline: same-package carve-out with the stay/move boundary (here,
`ModalDismissal` moves but `ModalResolver` stays) resolved entirely at spec
time via line-range analysis of the interleaved-neighbour boundaries, then
verified incrementally via `go build ./internal/relay/`.

## Lessons learned

- (From the PR body.) The single mechanical import delta was `slices`,
  decided the same way #1022 flagged: by code usage, not doc-comment prose.
  `pushQueue.enqueue` (line 181) was the sole code caller of
  `slices.Delete` in the donor file, so moving that one method
  compiler-forced the import off `v2session.go` and onto the new file. No
  other import (including `base64`, whose only user stayed in core) was
  affected — reconfirming the #1022 lesson that "does this import stay" is
  answered by the real `pkg.Ident` call pattern, with the compiler as final
  arbiter, not by scanning doc-comment prose for a package name.

## Verification

`make check` (vet, `go test -race ./...`, staticcheck, substrate-guard,
hermetic `-tags e2e`) green. Code review confirmed all 16 declarations moved
verbatim (bodies + doc comments unchanged), the `ModalResolver` interface
and its config field stayed in core, and the diff touches exactly the two
intended files (`v2session.go`, `v2session_modal.go`).

A stale pinned line reference in
[`v2-session-manager.md`](../features/v2-session-manager.md) (the `Push`
non-blocking `drainCh` idiom, previously cited as `v2session.go:2933`) was
corrected to its new location (`v2session.go:1955`) as part of this
ticket's documentation pass — `Push` itself did not move, only the 568
lines above it did.
