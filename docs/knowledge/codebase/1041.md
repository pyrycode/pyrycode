# Ticket #1041 — re-scope `v1TypeSet`/`IsV1Compatible` to their v2-only meaning

Split from #966. `internal/protocol.IsV1Compatible` and its backing `v1TypeSet`
were named for the Mobile Protocol v1 path, removed by #913/#966/#1039. They
were nonetheless still load-bearing — the sole live caller, `dispatch.Route`,
validates every decrypted inner app frame against this set before dispatch.
This ticket renames the gate to say what it does today, without touching
membership: `IsV1Compatible` → `IsKnownAppType`, `v1TypeSet` →
`inboundAppTypeSet`.

Not security-sensitive: behaviour-preserving rename + doc-comment edits, both
explicit carve-outs from the security label. No new input path, trust
boundary, or policy decision — the accepted/rejected type partition is
unchanged, pinned deterministically by `compat_test.go` and
`cmd/pyry/relay_guard_test.go`.

## Implementation

`9979e12` (spec) + `9c1c18e` (dev), confined to 5 files
(`internal/protocol/envelope.go`, `internal/protocol/codes.go`,
`internal/protocol/compat_test.go`, `internal/dispatch/dispatch.go`,
`cmd/pyry/relay.go`):

- **`envelope.go`** — the two identifier-bearing sites. Function body and
  set-literal membership (23 entries, `TypeHello`…`TypeRegisterPushToken`)
  untouched; check order (`PayloadEncrypted` first → `ErrUnsupported`,
  `Type` second → `ErrUnknownType`, stricter rejection wins) preserved
  bit-for-bit. Doc comments got a **substantive rewrite**, not a token swap
  — "acceptable under wire-protocol v1" → "a decrypted inbound app frame …
  a known inbound app-frame type", since the whole point of the ticket is
  that the old wording was stale.
- **`dispatch.go`** — the sole live call site (`Route`, was `:162`) plus 3
  package/func doc references, updated to the new name.
- **`codes.go`** — ~38 doc-comment references, a straight
  `v1TypeSet`→`inboundAppTypeSet` token `replace_all`. Per spec, the
  conceptual "v1 application type" / "v2 control frame" / "v1/v2 partition"
  framing was **left intact** — it still accurately describes the real
  architectural asymmetry (app-frame types that flow through `Route` vs.
  types intercepted by the v2 session manager, or push-only). `v2OnlyTypes`
  (test-local, `compat_test.go`) was **not** renamed — out of scope.
- **`compat_test.go`** — both identifiers renamed in code + comments, plus
  the two embedded test-function names (`TestIsV1Compatible` →
  `TestIsKnownAppType`, `TestV1TypeSet_CoversAllExportedTypeConstants` →
  `TestInboundAppTypeSet_CoversAllExportedTypeConstants`). Assertions
  themselves (accepted set, rejected set, size tie, disjoint partition)
  unchanged.
- **`relay.go`** — independent AC #5 fix, no identifier overlap: corrected
  the stale `startRelayV2` doc comment ("registering the same three relay
  handlers as the v1 path" — wrong on both counts, 12 handlers and no v1
  path exists) to describe the actual handler set.

Grammar polish (`a inboundAppTypeSet member` → `an …`, introduced by the
blind token `replace_all` in `codes.go`) was **correctly declined** per the
spec's explicit call-out — a partial fix across wrapped comment lines risks
inconsistency. Code review: PASS, one NIT flagged for completeness (this
grammar point), non-blocking. `make check` green including real-claude e2e.

## Patterns established

- **Token-only `replace_all` vs. substantive doc rewrite is a per-file
  call, not a blanket rule.** The file whose doc comments were the actual
  target of the ticket (`envelope.go`) got a real rewrite; files that only
  reference the identifier in passing (`codes.go`) got a mechanical token
  swap. Preserving the surrounding conceptual framing (the v1/v2 partition
  narrative) in the token-swap file avoided scope creep into re-explaining
  an architecture that didn't change.
- **`.md` hits from a code-identifier grep-zero AC are out of scope by
  construction** (AC #1 said "code or comments", scoped to `*.go`) but are
  real staleness the documentation phase should still clean up — this run
  updated `docs/knowledge/features/dispatch-package.md`,
  `docs/knowledge/features/protocol-package.md`, and
  `docs/knowledge/architecture/system-overview.md`, which quoted the old
  identifier names in prose describing live code. Historical per-ticket
  files under `docs/knowledge/codebase/*.md` that predate this rename
  (e.g. `255.md`, `307.md`, `967.md`) were **left untouched** — they are
  frozen snapshots of what was true at the time, same as git history.
