# Ticket #1195 — Let a minted per-conversation PTY session write the transcript the daemon tails

Before this ticket, conversation-scoped turn lifecycle (`turn_state`, `turn_end`,
assistant output) was observable on **zero** PTY-tier e2e tests, structurally: a
`turn_end` exists on exactly one code path (`tuidriver.EventKindJsonlEndOfTurn`,
transcript-derived), and for a **minted** (non-bootstrap) conversation the daemon
tails `<convDir>/<mintedSessionID>.jsonl` while `fakeclaude` — which parses no
argv — always wrote `<sharedDir>/<PYRY_FAKE_CLAUDE_INITIAL_UUID>.jsonl`, a
process-wide value every child of one daemon inherits identically. The two
stems could never agree, so the subscription for a minted conversation never
opened. Two default-off `fakeclaude` knobs close the gap; no daemon-side code
changed. Full design: `docs/specs/architecture/1195-minted-perconv-pty-transcript-substrate.md`.
PR #1197, merged. Feature doc: [fakeclaude-binary.md § Argv-derived stem mode](../features/fakeclaude-binary-argv-derived-stem-mode.md#argv-derived-stem-mode-1195) and [§ Per-child JSONL trigger mode](../features/fakeclaude-binary.md#per-child-jsonl-trigger-mode-1195).

## Implementation

- **`PYRY_FAKE_CLAUDE_SESSION_ID_FROM_ARGV`** — resolves the initial transcript
  stem via `argvSessionID(os.Args[1:])` (the value after the *last*
  `--session-id` or `--resume`, since #1164 emits either depending on whether
  the transcript already exists) instead of `PYRY_FAKE_CLAUDE_INITIAL_UUID`.
  Falls back to the env var on no match or an unsafe value — never fatal.
- **`PYRY_FAKE_CLAUDE_JSONL_TRIGGER_DIR`** — watches
  `<dir>/<this child's own initial stem>.jsonl.trig` in parallel with the
  existing shared `PYRY_FAKE_CLAUDE_JSONL_TRIGGER`, reusing
  `emitStructuredJSONLIfTriggered` unchanged with a per-child path. Necessary
  because the shared trigger's claim protocol is sound only for one poll
  goroutine — with a bootstrap child polling the same path, whichever claims
  first wins, a coin flip.
- **`TestRelayV2_PerConversationTurnEnd`** (`internal/e2e/relay_v2_perconv_turn_end_test.go`) —
  mints a conversation over the wire, routes one `send_message` to move the
  active cursor (`resolveTarget` re-keys on it), then re-drops an `end_turn`
  JSONL line on a 250ms ticker at the minted child's own trigger path (the
  #929 subscription-offset kicker — the producer subscribes at EOF after a
  settle delay, so a single-shot drop can land below the tailed range) until
  the drain observes a `turn_end` whose `ConversationID` matches. Non-vacuity
  is asserted **on disk**, not just on the wire: the marker text must be
  present in `<sharedDir>/<mintedID>.jsonl` and absent from
  `<sharedDir>/<initialUUID>.jsonl` — a `ConversationID` match alone would
  also pass in a world where the daemon tailed the wrong file while the active
  cursor happened to point at the minted conversation, since the field is
  stamped from the cursor, not derived from the file.
- Not built on the interrupt route — #1191 (blocked on this ticket) owns the
  minted-interrupt oracle; driving `turn_end` here via the interrupt would make
  that ticket's test a duplicate.

## Patterns established

- **A per-child env-derived signal must come from argv, not a new env var,
  when the value differs per spawn.** `PYRY_FAKE_CLAUDE_INITIAL_UUID` is
  process-wide by construction (`cmd.Env` is set once for the whole daemon);
  there is no way to give one child a different env value than its siblings
  without a production change to the spawn config. Argv is the one channel
  that already varies per spawn, because the daemon puts a per-session id
  there. Reach for this shape again before adding a per-session `Env` on
  `supervisor.Config` — that was explicitly rejected here as a production
  change made to serve a test fake.
- **A shared trigger-file protocol doesn't generalize to a multi-child
  process tree.** `PYRY_FAKE_CLAUDE_JSONL_TRIGGER`'s single fixed path +
  `<path>.consuming` sidecar is sound only under "one process, one poll
  goroutine" — the moment two children of the same daemon poll it, first-claim
  wins arbitrarily. The fix pattern is keying the path on the child's own
  identity (the same stem argv already gives), not adding locking.
- **An argv parser that also serves as a security boundary needs the guard
  inline, not imported.** `argvSessionID`'s stem guard (reject `/`, `\`, `.`,
  empty) is a 3-line inline predicate rather than an import of
  `internal/transcript` for `ValidStem`, to keep the test binary
  near-zero-dependency. This is a deliberate trade-off, not an oversight —
  revisit only if a second stem-validating site appears in this file.
- **Belt-and-suspenders with different fabric, applied to test assertions.**
  The wire assertion (`turn_end.ConversationID`) is the stochastic-ish
  end-to-end signal; the on-disk `strings.Contains` pair is a plain
  deterministic check of the same property from a different angle. Reach for
  this shape whenever a wire field is stamped from ambient state (here, the
  active cursor) rather than derived from the artifact the test actually cares
  about — the wire field alone tests what the emitter *believed*, not what
  actually happened on disk.

## Lessons learned

- **A doc comment that calls a guard the "mirror" of a named function must be
  checked against that function, not just against the security property it
  needs to hold.** `argvSessionID`'s original comment called its stem guard
  "the fake-side mirror of `internal/transcript.ValidStem`." `ValidStem` is a
  full UUID regex; the guard here is the much laxer "non-empty && no
  `/\.`" — the security goal (can't escape `filepath.Join`) still holds, so
  this was a NIT not a correctness bug, but `--session-id foo` *is* adopted by
  the fake and *is* rejected by the daemon, which is exactly the divergence
  "mirror" claims doesn't exist. Same shape as the ToLower-const rule from
  [codebase/1192.md](1192.md): resolve the named symbol before crediting the
  claim in a doc comment or a PR description.
- **`docs/lessons.md:256` ("`Pool.Create` appends `--session-id`, breaking
  naive claude stand-ins") is stale post-#839.** Its third bullet still reads
  "Bootstrap-only e2e tests don't hit this because `Pool.New`'s bootstrap path
  uses `tpl.ClaudeArgs` verbatim (no `--session-id` append)." Since #839,
  `Pool.New` sets `ResolveSessionID` unconditionally for the bootstrap
  supervisor, and `buildClaudeArgs` appends `--session-id`/`--resume` to
  *every* spawn, bootstrap included. That false premise is precisely what
  would tempt the design this ticket explicitly rejects — keying the fake's
  stem behavior on "argv carries a session id" as if that alone marked a
  child as minted. `lessons.md` is frozen (2026-05-11), so the correction
  lives here rather than there; a reader who hits that stale bullet should
  cross-check it against `sessions.buildSession`/`supervisor.buildClaudeArgs`
  before trusting it.
- **A QA comment that's a stub ("baseline `make check` still running") is not
  evidence, even when the routing label (`done:qa`) has already been
  applied.** The label is still the correct signal to act on, but before
  crediting the ticket's tests as green, run the ticket's own oracle directly.
  Here that was `go test -tags e2e -run TestRelayV2_PerConversationTurnEnd`,
  which passed in 3.66s with a genuinely divergent minted stem
  (`c515158c-…`) vs the bootstrap stem (`77777777-…`), confirming the
  file-targeting assertion has teeth rather than passing by coincidence.
