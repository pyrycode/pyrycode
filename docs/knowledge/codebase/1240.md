# Ticket #1240 — does the interactive surface report a turn idle while a backgrounded command is still alive?

Adds `internal/e2e/realclaude/interactive_background_idle_probe_test.go` — one env-gated
probe (`PYRY_PROBE_INTERACTIVE_BG_IDLE=1`) that stages a single turn on the production
stream-json interactive daemon around a Bash command claude backgrounds on timeout expiry,
records every frame the phone received in receive order, and classifies the run into one of
five outcomes. Zero production change, zero consumer call sites. **The probe has been run
live and the answer is yes**: `turn_state{idle}` is emitted while the backgrounded command
is still alive — see § The finding below.

## Implementation

- **The recorder (`bgIdleRecordTurn`) is the only genuinely new code.** Both existing drains
  in the package (`drainForResponding`, `assertNoIdleWithin`) discard every frame; this one
  transcribes their decrypt discipline (every `noise_msg` decrypted in receive order, a
  non-`noise_msg` control frame skipped *without* decrypting so the nonce doesn't desync) and
  terminates on exactly two conditions — terminal `turn_state{idle}` for the conversation, or
  a 120s budget — so a did-not-fire outcome is representable, not just a positive one.
- **One extraction allowlist, not a habit.** `bgIdleFrameFromEnvelope` is the single site that
  unmarshals payloads: a five-arm switch (`turn_state`, `tool_use`, `tool_result`, `turn_end`,
  `assistant_delta`) plus a default that decodes into an anonymous one-field struct that *can
  hold nothing but `conversation_id`* — stronger than the spec's "`Type`-only default" because
  it keeps `unrecognized_message.Raw` (claude's verbatim offending message) out by construction
  rather than by care. `assistant_delta.text` is recorded as length only, never the text.
- **AC2's flip is re-proven in this rig, not inherited from #1239's self-check.** Two
  `fifoLiveRead` calls on the same FIFO path across one command's lifetime: pre-rendezvous
  (must read `no-reader`, ENXIO, and does not perturb the parked writer) and at the instant
  `idle` is recorded (`atIdle` closure, synchronous, on the test goroutine). A read wired to
  the wrong path or a FIFO something else holds would produce the same lone `reader-present`;
  the pre-rendezvous read is what rules that out.
- **AC3(c) attribution is closed by counting recorded frames, not a third pid matcher.**
  `bgIdleCountFIFONaming` counts Bash `tool_use` frames whose `input_summary` contains the FIFO
  path (`matched`) versus ones truncated at exactly 201 runes ending `…` that might have cut
  the path off (`truncatedCandidates`, unresolved not non-match). Attribution is sound only at
  `matched == 1 && truncatedCandidates == 0`.
- **`IsError *bool`, not `bool`.** `is_error: false` on the background path is the *same*
  `false` a clean success carries (`outbound.go:84`), so `omitempty` on a plain bool would have
  erased the load-bearing value.
- **`EnvDelta` is a fixed literal, never harvested.** `[]string{"BASH_DEFAULT_TIMEOUT_MS=5000"}`
  — the file never calls `os.Environ()` or reads a child's environment; this closed the
  architect's security-review MUST FIX (a field literally named "env delta" would otherwise be
  the natural place to dump `CLAUDE_CODE_OAUTH_TOKEN` into a public artefact).
- **`PayloadDecodeFailed bool`, not the error string.** A `*json.SyntaxError` message echoes a
  byte of the offending payload; in a record destined for a public issue that's a leak through
  the error channel, so the flag is boolean.
- **Redaction is one choke point.** `bgIdleWriteRecord` marshals, replaces `realHome` with
  `$HOME` in the bytes, then writes `0o600` and logs the same redacted bytes — with an explicit
  `realHome == ""` guard (an unguarded `strings.ReplaceAll(s, "", "$HOME")` inserts `$HOME`
  between every character).
- **Two SHOULD FIX findings from code review shipped unfixed** (PASS, 0 MUST FIX / 2 SHOULD FIX
  / 2 NIT, under the 3-finding threshold) — read before #1241 extends this recorder:
  - `:356` — `rec.ClaudeVersion` is read via `probeClaudeVersion(resolveClaudeBin(t))`, which
    honours `PYRY_CLAUDE_BIN`. The daemon actually runs the binary `startStreamRunningTurnHarness`
    resolved via `exec.LookPath("claude")`. With `PYRY_CLAUDE_BIN` set to something else, the
    published finding names a version for a binary that produced none of the recorded frames.
    One-line fix identified, not applied: resolve the version the same way the harness resolves
    the binary.
  - `bgIdleClassify` records `FramesDropped` and `PayloadDecodeFailed` but neither gates the
    verdict. A second FIFO-naming `tool_use` past `bgIdleMaxFrames` (2000) is invisible to
    `matched`, and a `PayloadDecodeFailed` `turn_state` leaves `State` empty so the terminal
    idle is never detected and the drain runs to budget — both low-probability, both would let
    an anomalous run assert a clean headline outcome.

## The finding

Run by hand on 2026-07-30, three reps, claude 2.1.220, model haiku, stream-json interactive
runner (comment: [issuecomment on #1240](https://github.com/pyrycode/pyrycode/issues/1240)).
Production untouched — the rig spawns its own bootstrap daemon.

**Yes: `turn_state{idle}` was emitted while the backgrounded command was still alive.** Rep 3
classified `early-idle` with clean attribution (`matched=1, truncated_candidates=0`):
`tool_result.is_error=false`, `turn_end.stop_reason="end_turn"`, terminated on the terminal
idle frame (not budget). The AC2 liveness pair on that rep: pre-rendezvous `no-reader` (ENXIO),
at-idle `reader-present` — a flip on one path across one command's lifetime, so the command was
alive and had not been killed.

**All 3 of 3 reps showed the same underlying shape**; only the attribution bookkeeping
differed. Reps 1 and 2 classified `unresolved` (`matched=1, truncated_candidates=1`) because a
second, truncated `tool_use` — a `Read` of the background task's own output file, not the FIFO
— tripped the discriminator. The design's own mitigation (recording `Name` verbatim rather
than gating the match on it) is why this was visible as a decoy rather than a silent
misattribution; the conservative "unresolved, not asserted" call is correct behaviour, not a
defect.

**Bearing on #1241 (still in Backlog): the answer looks like no.** `turn_end.stop_reason` was
`"end_turn"` in the early-idle rep — byte-identical to a turn that genuinely finished with
nothing left running. Nothing in the recorded frame sequence distinguishes the two cases; a
client has no field to key on. #1241 inherits this recorder and this finding as its starting
point.

**Side finding, filed as a separate ticket:** an `unrecognized_message` frame appeared in all
3 of 3 reps, ~10.2s after send, immediately after the backgrounding `tool_result` and before
the turn resumed. The 2026-07-27 unrecognized-message work reported 8/8 stream specs green
with zero unrecognized rows, but none of those specs exercised the background-timeout path —
this looks specific to backgrounding. The recorder stores frame `Type` but not `Kind`/`Raw` by
design (§ Implementation), so the frame could not be named from these artefacts.

**Runner-path attribution (AC4) took the honest second arm**, as specced:
`interactive_runner: "stream-json"` is a rig-authored value with no non-authored corroboration
recorded — `selectInteractiveRunner` never logs its choice, and a clean daemon start proves
only that the value parsed (both runner names start fine).

## Patterns established

- **A proven flip does not transfer across rigs — re-prove it on the path and lifetime that
  matters.** #1239 proved `fifoLiveRead` flips in its own self-check; this ticket took a
  *second*, pre-rendezvous read on the same path before the subject existed, rather than
  trusting the single post-rendezvous read to mean what #1239 proved elsewhere. Reusable
  whenever an instrument's self-check and its consuming rig are different code.
- **Close a pid-shaped attribution gap by counting frames already in hand, not by adding a
  matcher.** `bgIdleCountFIFONaming` answers "was the FIFO holder the command that was
  backgrounded" from the recorded `tool_use.input_summary` set, explicitly declining a third pid
  matcher (the package already has `probeDescendantsFromPS`, #1235 was building another). The
  live run then validated the design's own worst case — a decoy tool naming the same path — by
  actually producing one.
- **RED-by-inversion works even for a zero-production-code instrument.** With nothing for a
  test to fail against, the developer temporarily broke the AC3(c) discriminator two
  wrong-but-plausible ways (dropped truncation arm; byte-length instead of rune count) and
  confirmed each failed *only* the truncation row before restoring — the same recipe #1239 used
  for its mode gate.
- **A record meant for a public issue needs one non-negotiable extraction allowlist**, not
  scattered field-by-field care. `bgIdleFrameFromEnvelope`'s five named arms plus a default that
  structurally cannot hold anything but `conversation_id` is what makes "no model-authored text
  reaches the artefact outside the five sanctioned fields" a compile-time property instead of a
  reviewer's checklist item.

## Lessons learned

From the PR body (#1245), code review, and the operator's live-run comment:

- **A "record every frame" contract and a "never publish this field" contract pull in opposite
  directions — the resolution is the default arm.** AC1 wants every frame including
  `unrecognized_message`, whose `Raw` is claude's verbatim (possibly malicious) input echoed
  back; unmarshalling it to preserve `conversation_id` would leak exactly the field that must
  never be published. Decoding the default arm into a struct that can hold nothing else
  resolves both demands structurally.
- **`json.Unmarshal`'s own error text is a payload leak.** A `*json.SyntaxError` echoes a byte
  of the offending input; a public record needs a boolean anomaly flag, not the error string.
- **`omitempty` on a `bool` erases the one value the ticket needs** whenever the *false* case is
  the finding, not the default. Worth checking on any JSON record where a boolean carries a
  result rather than a flag.
- **[unfixed] Version-prober and daemon-spawner can silently disagree** when one honours
  `PYRY_CLAUDE_BIN` and the other resolves via `exec.LookPath` — see § Implementation. The
  package had already written the rule down once (`mcp_smoke_test.go:252-256`) and this file
  is the one place it wasn't followed.
- **[unfixed] Anomaly flags recorded but not consulted by the classifier** — `FramesDropped`,
  `PayloadDecodeFailed` — can let a run with a broken recording still assert a clean headline.
  Low probability in practice (2000-frame cap, self-produced JSON), but #1241 inherits the
  recorder and should close this before trusting an aggregate across many runs.
- **A design's own conservative fallback (don't gate on model-authored `Name`) paid for itself
  on the very first live run** — reps 1–2's decoy `Read` tool_use is exactly the shape the
  design anticipated and handled by returning `unresolved` rather than a false positive.
- **`turn_end.stop_reason` carries no signal for this defect** — measured, not assumed (Open
  question 3 in the spec is now closed): `"end_turn"` on the early-idle path is byte-identical
  to a genuine finish. This forecloses the cheapest possible client-side fix for #1241 before
  that ticket starts.
