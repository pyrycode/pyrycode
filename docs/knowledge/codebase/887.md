# Ticket #887 — `create_workspace_folder` v2 wire message

Adds a `create_workspace_folder` request/reply verb so mobile and desktop
clients can create a new workspace folder on the daemon host — confined to
the operator's `$HOME` — without shell access. Split from the #825 daemon-wire
epic; the sibling `recent_workspaces` (#888) is independent. This is the
**leanest** handler in the conversation-write-verb family (`create` #666,
`rename` #820, `delete` #822, `archive`/`unarchive` #881, `change_workspace`
#823): it touches **no conversations registry** at all — it creates a
directory and returns its path, nothing more — and replies with a **new**
type, `workspace_folder_created`, rather than reusing `conversation_updated`.

## Implementation

Five production files touched, three new, ~480 total LOC (matches the
architecture spec's `## Scope / size note` false-positive: raw file count
trips the ≥5-file gate but the LOC/type/consumer-cascade counts stay well
inside the S band):

- `internal/protocol/codes.go` — `TypeCreateWorkspaceFolder =
  "create_workspace_folder"` (request) + `TypeWorkspaceFolderCreated =
  "workspace_folder_created"` (reply), in a new `// Workspace.` sub-group
  after `TypeChangeWorkspace`.
- `internal/protocol/workspace.go` (new) — `CreateWorkspaceFolderPayload
  {Parent, Name string}` / `WorkspaceFolderCreatedPayload{Path string}`. A
  new file, not an addition to `conversations_write.go`: this verb names no
  conversation and carries no `conversation_id`.
- `internal/protocol/envelope.go` — both new consts added to `v1TypeSet`. A
  v1 `dispatch.Route` write verb (reached via `Handlers`/`d.Register`), not a
  v2-only control frame intercepted by `dispatchAppFrame` — the "v2 wire
  message" in the title names the encrypted v2 *transport*, not the v1/v2
  *type partition*.
- `internal/protocol/compat_test.go` — both consts added to all three v1
  enumerations; hardcoded count bumped 22 → 24.
- `internal/relay/handlers/create_workspace_folder.go` (new, ~201 LOC) —
  `CreateWorkspaceFolder(resolve WorkspaceFolderResolver, logger *slog.Logger)
  dispatch.Handler`. Flow: decode → empty-parent guard (must precede resolve
  — an empty parent joins to the name alone, which the confiner would
  resolve against the daemon's process cwd, possibly inside `$HOME`,
  silently passing) → name-shape guard (`validWorkspaceFolderName`: rejects
  empty, absolute, containing a path separator, or containing `..`) →
  `resolve(p.Parent, p.Name)` (bare `err != nil` check, not gated on
  `errors.Is` — the resolver's contract wraps every failure and every
  failure is deterministic/non-retryable) → reply
  `workspace_folder_created{Path: created}`.
- `cmd/pyry/relay.go` — the new `resolveWorkspaceFolder` adapter
  (`expandTilde(parent)` → `filepath.Join(parent, name)` →
  `confineWorkdirToHomeCreating`, wrapping every failure with
  `handlers.ErrWorkspaceFolderRejected`) plus two wiring lines (v1
  `d.Register` block at `:268` and the v2 `Handlers` map at `:460`),
  mirroring `change_workspace`.

`WorkspaceFolderResolver func(parent, name string) (created string, err
error)` is the consumer-side injected seam (same pattern as
`change_workspace`'s `WorkspaceResolver` / `create_conversation`'s
`SessionCreator`), so `internal/relay/handlers` stays free of `cmd/pyry`
imports. No new parameter threaded through `startRelay`/`startRelayV2` — the
resolver has no external state, so `relay.go` references it directly at both
sites.

### The confine adapter: a deliberate hybrid

`resolveWorkspaceFolder` (`cmd/pyry/relay.go`) combines the two existing
adapters, both choices load-bearing:

- Uses the **creating** `confineWorkdirToHomeCreating`, like
  `resolveSpawnDir` and unlike `resolveWorkspaceDir`'s strict, non-creating
  confiner — this verb's whole purpose is to create the folder. The creating
  confiner's containment check runs **before** `MkdirAll`, so an escaping
  target is rejected with nothing created; `MkdirAll` is idempotent on an
  existing folder; it returns the post-creation `EvalSymlinks` realpath.
- Does **not** call `trustMark`, like `resolveWorkspaceDir` and **unlike**
  `resolveSpawnDir`. Creating a folder is not spawning into it —
  trust-marking auto-accepts claude's workspace-trust modal and is a spawn
  concern; marking an empty folder that may never host a session would
  prematurely auto-trust it. The eventual `create_conversation` into this
  folder re-runs `resolveSpawnDir` → `confineWorkdirToHomeCreating`
  (idempotent on the now-existing realpath) + `trustMark` then.

### Two independent deterministic gates, different fabric

The security centrepiece is two distinct properties, both fail-closed:

1. **`$HOME` confinement** — `confineWorkdirToHomeCreating` rejects any
   target escaping `$HOME` after symlink resolution, before any directory is
   created.
2. **Directly-under-parent** — the handler's `validWorkspaceFolderName`
   guard rejects a name that isn't a single clean path element.
   Confinement alone does **not** give this: a name like `sub/dir` stays
   inside `$HOME` yet is not directly under the parent, so it needs an
   independent deterministic string check, not a second pass of the same
   path-confinement gate.

### Uniform no-leak logging

Stricter/simpler than `change_workspace`'s per-branch divergence: because
**both** decoded fields (`parent`, `name`) are attacker-controlled path
components, there is no safe-to-log structured field except `conn_id` — not
even `parent`/`name` themselves, unlike `change_workspace` which could
safely log the opaque `conversation_id`. All four reject branches, and the
success branch, log `conn_id` + a static `event` name only. Two traps
avoided (called out in the handler's doc comment so a future editor doesn't
"fix" them back by pattern-matching the siblings): the malformed branch does
not log the decode `err` (`create_conversation.go:122` and
`rename_conversation` do — `json.Unmarshal` errors can embed offending input
bytes); the rejected branch does not log the confine `err`
(`create_conversation.go:177` does, and it names the offending path).

## Testing

- `internal/relay/handlers/create_workspace_folder_test.go` (new, ~332 LOC)
  — hermetic fake `WorkspaceFolderResolver` closures (no real filesystem
  touched). Covers: success replies the created path; resolver-rejected →
  malformed with no leak (the security-critical assertion — no marker,
  parent, name, path, or `err` in the log record); empty parent rejected
  before `resolve` is ever called; a 9-entry bad-name table (`a/b`, `../x`,
  `x/..`, `/abs`, `..`, ``, `  `, …) each rejected without calling `resolve`;
  malformed payload → no leak; no-echo assertion that an injected-looking
  parent/name never appears in any reject reply message.
- `cmd/pyry/create_workspace_folder_dir_test.go` (new, ~125 LOC) — real
  temp-`$HOME` filesystem tests for `resolveWorkspaceFolder`: creates +
  returns realpath; idempotent on an existing folder; escape (symlink
  pointing outside `$HOME`) rejected *and* creates nothing; tilde-parent
  resolves under the real `$HOME`.
- `internal/protocol/workspace_test.go` (new, ~69 LOC) +
  `testdata/create_workspace_folder.json` / `testdata/workspace_folder_created.json`
  — golden round-trip tests, mirroring `TestCreateConversationPayload_RoundTrip`.
  Unlike `ChangeWorkspacePayload` (#823's documented lessons-learned gap),
  this slice does not skip the round-trip fixture.

`go test -race ./...`, `go vet ./...`, `staticcheck ./...` pass. Code review
(PR #889): **PASS**, no findings.

## Out of scope

- **Starting a conversation in the new folder.** That is
  `create_conversation`'s job, which independently re-confines + trust-marks
  its spawn dir on the next fresh spawn.
- **Trust-marking the folder** — deferred to that first spawn (see above).
- **Recent-workspaces / listing** — sibling #888, independent.
- **Live fan-out to other connected clients** — reply goes only to the
  requester, matching the family.
