# Ticket #1309 — Probe instrument: return the trailer sighting's measurement from the run-outcome gather as a leak-free carrier (offline)

Changes one existing file's body plus a one-token call-site fix in a sibling
(no new file, zero production `.go` change): `finding_run_gather_test.go` and
`finding_stage_held_group_test.go`. `finGatherReadings` classifies against a
`trailObservation` and drops it, so the only way downstream to recover the
sighting was a second `trailWaitForTrailer` — which matches on its first poll
over an already-filled buffer and reports `trailBoundFromStart`, a
discriminator whose own doc says it bounds nothing. That is a mis-report, not
a cost. This ticket makes `finGatherReadings` hand back what the sighting
*measured*, on a third return, without handing back the sighting itself.
Nothing consumes the new value yet — `finTrailerBuild` keeps its present
signature and callers; #1308 moves it onto the carrier. Split from #1307.

## Implementation

- **`finSighting`, a new 8-field type beside the gather.** Filled from the
  same `obs` (a `trailObservation`) that already fills `readings.BoundFrom`
  and feeds `trailGate` — one `trailWaitForTrailer` call, no second scan, no
  second wait, no clock reading of the gather's own. Fields: `State`,
  `BoundFrom`, `Staleness` (all copied straight off `obs`), `CarriesTrailer`
  (`obs.State == trailSeen && obs.Trailer != nil` — the operand order matches
  `finTrailerBuild:218` deliberately, since #1308 moves that builder onto this
  computation and the two must agree), and the four decoded scalars
  (`Subtype`, `IsError`, `TerminalReason`, `StopReason`), copied only when
  `CarriesTrailer` is true and left at their zero values otherwise.
- **No `Bounded`, no `ObservedAt`, no `Detail`.** `Bounded` stays derived
  solely from `BoundFrom == trailBoundFromMiss` at `finTrailerBuild`
  (`finding_trailer_evidence_test.go:209-215`) — the carrier supplies the
  discriminator that derivation reads, not a second source. `ObservedAt` has
  no reader (`finTrailerBuild` doesn't use it) so it's omitted, per the
  one-way constraint: the carrier holds what its consumer needs, nothing
  more. `Detail` is omitted deliberately, and the omission is what discharges
  #1284's per-row headroom rule *structurally* — with no formatted string on
  the carrier there is no budget for a leak to hide behind.
- **`Staleness` travels as published evidence, not as a classifier input.**
  `trailRunReadings` still has no field for it
  (`trail_run_outcome_test.go:211-214`); carrying it on the carrier doesn't
  admit it as a classifier input, and the two types stay separate for that
  reason.
- **`CarriesTrailer` records the outcome of a pair, not a `State` value.**
  Once the carrier is forbidden the `*resultTrailer` pointer, `State ==
  trailSeen && Trailer != nil` is unrecomputable downstream from `State`
  alone — a `trailSeen` scan with a nil `Trailer` is exactly the case the
  pair exists to separate. No reachable sighting produces that inconsistent
  pair today (`trailWaitForTrailer` fills `Trailer` on every `trailSeen`
  result), so every test row here is a fill check, not proof of which
  expression the implementation wrote — the pair is the shape that stays
  correct if a later scan learns to return one without the other.
- **`StopReason` is the one model-influenced field, named explicitly as
  crossing uncapped.** `Subtype`/`IsError`/`TerminalReason` all derive from a
  single `ExitReason` (`wireFields`, `emitter.go:428-437`) — one value
  rendered three ways, not three corroborating reads. `StopReason` alone is
  forwarded from the model's last message unvalidated (`emitter.go:210`),
  exactly as it already crosses `finTrailerRecord`
  (`finding_trailer_evidence_test.go:114-124`). Capping it is out of scope
  here and there; naming it in the doc is what keeps a future sweep author
  from planting a needle in a field the carrier must carry verbatim.
- **JSON tags mirror `finTrailerRecord`'s keys, no `omitempty` anywhere.**
  Tags because `encoding/json` renders a `time.Duration` as a bare
  nanosecond count. Mirrored keys so #1308's move onto the carrier is a
  rename-free projection. No `omitempty`, for `finTrailerRecord`'s own
  reason: dropping a `false` `IsError` or an honest zero `Staleness` would
  collapse distinctions the type exists to keep.
- **Signature appends, doesn't reorder.** `func finGatherReadings(in
  finGatherInputs) (trailRunReadings, finAttributeRecord, finSighting)` — all
  seven call sites take one more token; six discard it with `_`, and
  `TestFinGatherReturnsNoCapturedBytes` (`:964`) takes it because AC4 sweeps
  it. `finding_run_gather_test.go:204`'s doc-comment prose (the positional
  form the struct replaced) was correctly left untouched — it's illustration,
  not a call site.
- **The file header's Fatalf-content licence extended in the same change
  that extends the sweep granting it.** The rule at `:107-113` licensed
  printing "a whole readings or record" because
  `TestFinGatherReturnsNoCapturedBytes` proved it; it's now extended to cover
  "a whole sighting" in the same sentence, since that test now sweeps all
  three returns. The MAY-name list grew to include the sighting's own
  scalars, with `StopReason` called out by name so the exposure is inherited
  knowingly.
- **The "what it returns, and what it deliberately does not" doc block was
  re-stated clause by clause, not replaced wholesale** — only the `"nothing
  here [needs Staleness]"` clause was false; the function-local-intermediate
  claim and the "not a classifier input" claim both stayed true and were
  extended rather than inverted. See the ticket body's own § for the
  clause-by-clause verdict table; the developer followed it exactly.

## Tests

- `TestFinGatherSightingComesFromTheClassifiedPoll` (AC1) — one gather call
  over a pre-seeded buffer; the carrier's `BoundFrom` agrees with
  `readings.BoundFrom`, and `Staleness` is pinned non-zero and below
  `finGatherTrailerWait` (the only claim available since `trailRunReadings`
  has no staleness field to agree with). Deliberately does **not** attempt
  the stronger claim (bound-from-miss over a buffer that misses a poll
  first) — that fixture and its wall clock are #1310's.
- `TestFinGatherSightingCarriesTheDecodedScalars` (AC2) — two arms, neither
  costing wall clock: a decoded trailer (`trailFixtureTrailer`, first poll
  hits) and the shipped aborted-scan row (`trailPaddedTrailer
  (trailOverlongPad)`, returns immediately because abortion is monotone).
  Expectations are recomputed through `trailScan` over the same bytes rather
  than typed in, following the file's own C2 idiom. Over the shipped in-cap
  fixture this is explicitly a fill check, not proof of which of the capped
  copy or the full line the implementation read — that discrimination is
  #1310's.
- `TestFinSightingReachesNoScanType` (AC3) — reuses `finRecordInputReaches`
  (no second walker written) to prove `finSighting` reaches none of
  `trailObservation`, `trailScanResult`, `resultTrailer` by walking the type,
  not by asserting a single instance.
- `TestFinGatherReturnsNoCapturedBytes` extended (AC4) — one more row in the
  existing `{what, value}` slice; the sighting is marshalled, needle-checked
  and key-walked alongside the readings and the attribution record, using
  the same fixture and premises already in the file.

## Verification

`go vet -tags e2e_realclaude ./internal/e2e/realclaude/...` clean; `go test
-race -tags e2e_realclaude ./internal/e2e/realclaude/...` → 103 PASS / 46
SKIP (the live-claude specs skip without credentials — the expected
PASS/SKIP split, not all-PASS); `go vet ./...` and `go build ./cmd/pyry`
clean. Went RED first against an unfilled carrier (AC1 and both AC2 arms
failed on assertions; AC3 and AC4 passed structurally, as the spec
predicted), then GREEN on the fill. Four `go test -overlay` mutations, each
graded under `-run '^Test…$'` alone so no co-firing check could mask it:
dropping `Staleness` from the fill (AC1 reddened), not copying `StopReason`
(AC2 reddened), adding a `*resultTrailer` one level down inside a nested
struct (AC3's type walk reddened, the byte sweep stayed green), and
`sighting.Evidence = obs.Line` — a direct leak (AC4's new row reddened on the
needle, the type walk stayed green). The last two mutations together showed
the two no-leak checks are non-overlapping: a pointer leak one level down is
invisible to the byte sweep (marshals as `null` unfilled) and a string leak
is invisible to the type walk.

## Patterns established

- **A carrier's doc comment enumerates what it deliberately does NOT carry,
  with the reason for each omission, not just what it does.** Precedent for
  any future ticket adding a similarly-scoped projection type in this
  family.
- **Reuse the family's one type walker (`finRecordInputReaches`) rather than
  writing a second one** — the increment when adding a third forbidden type
  is the type list, not a new traversal.

## Lessons learned

(From the PR body and code review; see PR #1311.)

- **The three no-leak checks on a carrier like this are non-overlapping —
  prove it with a mutation pair, don't assume one implies the other.** A
  `string` leak is invisible to the type walk and caught only by the
  byte/key sweep; a pointer leak one level down is invisible to the sweep
  (it marshals as `null` when unfilled) and caught only by the walk. Adding
  one check and calling the other redundant would silently drop a whole leak
  shape.
- **`rg -c '<pattern>' . --no-filename` summed is line-counting, not
  identifier-counting, and a bare-identifier check catches what a prefix
  pattern (`finSight[A-Z]`) cannot.** The re-run control (`trail[A-Z]`) moved
  from 2193 to 2228 purely from the spec doc landing between measurements —
  expected drift, not a defect. But the identifier that actually mattered,
  `finSighting`, was 0 in code and correctly claimed so, while
  `finSight[A-Z]` (the prefix-pattern recipe the ticket prescribed) can't see
  it at all, since the character after the prefix is lowercase. Run the bare
  identifier as well as the prefix pattern when a ticket's own control recipe
  is built around a capital-letter boundary.
- **In-file self-citations go stale the moment your own diff lands, even
  though external citations don't.** Code review found four in-file `(:NNN)`
  line-number citations in the new prose that pointed at the spec's
  pre-change line numbers, now landing on unrelated text (an import block, a
  signature, a type decl) after the file grew by ~148 lines total. All
  sixteen *external* citations in the same prose (into `emitter.go`,
  `tool_loop_test.go`, `finding_trailer_evidence_test.go`, etc.) verified
  exactly, because those files didn't move. Left as a single SHOULD FIX
  (one missed re-measure, not four separate defects) since it didn't block
  merge — but the fix for next time is: self-cites need a second pass
  *after* the diff lands, external cites don't.
- **Code review found `finRecordInputReaches` has no positive control
  anywhere in the package** — every existing call site (including this
  ticket's AC3 test) asserts it returns `false`. The mutation run exercised
  it as a control for the first time in the family's history and it caught
  the planted violation correctly, but the walker itself had never been
  proven to fire before this ticket. Inherited gap from #1290; not this
  ticket's to close, flagged for whichever ticket next touches that walker.
