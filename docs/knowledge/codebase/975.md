# Ticket #975 — e2e: `delete_conversation` over the v2 wire

A 2026-07-15 full-repo review found eleven client-sendable v2 wire verbs whose
only coverage was package-level unit tests — the exact gap shape that let #949
ship a `promote_conversation` handler nothing exercised end-to-end. This
ticket closes that gap for `delete_conversation`, one of four
conversation-lifecycle verbs split off the review epic (#960); siblings cover
`rename_conversation` (#974, merged) and the `archive`/`unarchive` round-trip,
and #963 is the realclaude capstone blocked by all of them.

## Implementation

Test-only, one new file, no production code:

- `internal/e2e/relay_v2_delete_test.go` (new, 291 LOC, build tag `e2e`) —
  `TestRelayV2_Delete` with two independent subtests, each owning its own
  pair → spawn → Noise_IK handshake (copied call-for-call from the merged
  #974 rename test, per the spec's explicit no-shared-helper instruction):
  - `testV2DaemonDeleteRoundTrip` — seeds **two** conversation rows (the
    delete target plus a non-targeted survivor), seals a
    `delete_conversation` frame over the encrypted channel, and asserts the
    decrypted `conversation_deleted` reply: `in_reply_to` correlates to the
    request id, payload `ID` equals the target id. Reads `conversations.json`
    back off disk and asserts exactly one row remains — the survivor, by id
    and name — proving a *selective* hard delete. The two-row seed makes the
    "row gone" assertion non-vacuous: a single-row seed would let a
    truncate/wipe bug pass `len == 0` just as easily as a correct delete; a
    soft-delete-that-flags bug would instead leave 2 rows. Only correct
    selective hard delete leaves exactly the survivor.
  - `testV2DaemonDeleteNotFound` — targets a conversation id absent from the
    registry, asserts the decrypted reply is an `error` envelope carrying
    `conversation.not_found`, and reads the registry back to prove the
    seeded row was never mutated (the handler replies before any `Save` on a
    miss) — byte-for-byte the rename not-found subtest with type/payload
    swapped.
  - Two spawns rather than one shared daemon, matching #974: keeps the
    not-found subtest's seeded row pristine.
  - Unlike rename/promote, `delete_conversation`'s success reply is
    `conversation_deleted` carrying only the deleted id (no
    name/cwd/last_used_at projection, since the record is gone) — so no
    `time.Time` `.Equal` handling was needed, unlike #974's `LastUsedAt`
    comparison.

## RED-on-regression

If the handler's `TypeDeleteConversation` registration at
`cmd/pyry/relay.go:409` were removed, the verb would fall through to the
no-handler `protocol.unsupported` arm and the happy-path
`want conversation_deleted` assertion (a `t.Fatalf`) would fail. The test is
a live guard on that registration, not just the handler body — closing the
same #949 gap shape end-to-end.

## Security review

Not security-sensitive: test-only, asserts observable behaviour (decrypted
wire frames, on-disk file state), no new production code or attack surface.
Code review confirmed PASS with no findings; also ran `go test -race -tags e2e
-count=2` clean (no flake) and `make e2e-realclaude` green.
