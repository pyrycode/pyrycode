# Ticket #838 — Probe-prefer `newTranscriptResolver` (delivery-confirm tail baseline) in a shared sessions dir

Split from #828, follow-up to #827 (`88b2e1e`). #827 made the interactive
**turn/modal stream** resolver probe-preferred so a second claude in the same
shared `~/.claude/projects/<encoded-cwd>/` dir can't redirect it. It
deliberately deferred the *other* live-child bootstrap-transcript consumer:
`newTranscriptResolver`, wired as `supervisor.Config.ResolveTranscript`
([#668](668.md)'s delivery-confirm growth baseline). This ticket rewires that
consumer the same way: it now tails the `<uuid>.jsonl` the daemon's own
bootstrap claude child holds open (probe + live child PID) instead of the
newest file by mtime, so a second claude's newer transcript can no longer
become the growth-confirm baseline and false-confirm or hang a turn.
`security-sensitive` (shared-dir file-selection confidentiality guard).

## Implementation

Three files, self-contained in `internal/sessions` plus one wiring site.

- **`internal/sessions/reconcile.go`** — new `availabilityReporter` interface
  + `probeUsable(probe rotation.Probe) bool` (mirrors the `cmd/pyry` local
  copy from #827) and `newProbePreferredTranscriptResolver(dir, probe,
  pidFn) func(ctx) (string, int64, error)`. `newTranscriptResolver` /
  `mostRecentJSONL` / `reconcileBootstrapOnNew` are untouched — the first two
  stay as the AC5 no-lsof fallback, the third stays out of scope (its
  `ChildPID == 0` at call time, so the probe can't disambiguate there; sibling
  ticket owns it).
- **`internal/sessions/pool.go`**, `New` — the `ClaudeSessionsDir != ""` block
  now builds a `probe := newProbe(cfg.Logger)` and a `pidFn` closing over a
  new `var bootstrapSup *supervisor.Supervisor` declared just above it, and
  wires `supCfg.ResolveTranscript = newProbePreferredTranscriptResolver(...)`.
  Right after `supervisor.New(supCfg)` returns, `bootstrapSup = sup` late-binds
  the live-PID source. This is the answer to the ticket's flagged wiring
  subtlety: `supCfg` is copied by value into the supervisor *before* the
  holder is ever read (the only reader, `WriteUserTurn`, runs on a goroutine
  created long after `New` returns), so the assignment ordering is
  correct-by-construction, not by a lock.
- **`internal/sessions/reconcile_test.go`** — table-driven tests mirroring the
  existing `TestNewTranscriptResolver_*` idiom, with a scriptable `stubProbe`
  (records call count) and `constPID(n)` fake. Covers: probe-preferred
  selection beating a newer-mtime foreign sibling (AC1+AC2); `pid <= 0` (both
  `0` and `-1`) short-circuiting before the probe is even called (AC3); empty
  probe result, probe error, guard rejections (outside dir, non-UUID stem,
  missing `.jsonl` suffix), and vanished-before-stat all collapsing to
  `("", 0, nil)` with an explicit `err == nil` assertion on the probe-error
  case (AC3 — the convention-inversion vs the `cmd/pyry` sibling); and a
  no-lsof `unavailableProbe` producing byte-identical output to
  `newTranscriptResolver` across newest-pick/empty-dir/missing-dir fixtures
  (AC5).

## Patterns established

- **The no-baseline convention is consumer-specific, not probe-specific.**
  Copying `resolveOwnBootstrapJSONL`'s guard *logic* (never-mtime-fallback,
  `pid <= 0` check, confidentiality dir/stem gate) was correct; copying its
  *return convention* (non-nil error on not-found) would have been wrong here.
  That sibling's turn-stream subscriber retries on error; this consumer's
  caller (`confirmViaTranscriptGrowth`) diverts to a stochastic fallback on
  any non-nil error. Same guard shape, inverted signal — dictated by what the
  specific caller does with the result, not by what "no baseline" abstractly
  means.
- **Late-bound holder for a live value needed before its source exists.**
  When a config struct is copied by value into a constructor before the
  object that will supply a live-updating field exists, close the config's
  callback over a mutable holder (declared before the constructor call,
  assigned right after it returns) rather than trying to reorder the
  assignment — reordering can't work once the copy has already happened.
  Safe without a mutex here because the only reader runs on a goroutine
  created strictly after the assignment (goroutine-creation happens-before).

## Out of scope (named in the ticket, unchanged)

- `reconcileBootstrapOnNew` startup adoption + the deterministic
  `--session-id`/`--continue` restart-resume identity hazard — sibling ticket
  split from #828. That call site runs before the child spawns
  (`ChildPID == 0`), so the probe can't disambiguate there.
- `mostRecentJSONL` stays in use by `reconcileBootstrapOnNew` — not deleted.

## Testing

`go test -race ./internal/sessions/...`, `go vet ./...`, `staticcheck ./...`
all green. No existing pool/session test regressed — nothing drives
`ResolveTranscript` through a live pool today, so the switch is exercised only
by the new unit tests and the real growth-confirm path.
