# Ticket #1176 — realclaude/stream: interrupt stops a running live-claude turn

Adds the real-claude counterpart of the fakeclaude interrupt proof
(`TestRelayV2_StreamInterruptStopsRunningTurn`, #1136): puts a genuinely-running
live turn in flight under the production stream-json interactive runner, sends
a phone-originated interrupt, and asserts the turn stops **cancelled** —not
run-to-completion— with the session still usable afterwards. Closes the
fake-green/real-red gap (#949) on the interrupt path: the primitives
(`streamsup.Runner.Interrupt()` #1120, per-conversation routing via
`activeInterrupter → resolveBoundRunner` #1121, and the parser's
`error_during_execution → cancelled` classification #1120) were shipped and
unit-tested, but never proven to run together live against a real `claude`.
Split from #1083 (T9); natively `blocked-by` #1172, which shipped the reusable
running-turn trigger this spec composes.

## Implementation

- `internal/e2e/realclaude/interactive_stream_interrupt_test.go` (new file,
  `//go:build e2e_realclaude`, PR #1184). Test-only, zero production files, no
  edits to any existing file.
- `TestInteractiveStreamInterruptStopsRunningTurn` composes the #1172 seam
  verbatim — `startStreamRunningTurnHarness` + `driveRunningTurn` +
  `drainForResponding` — plus #1153's `drainForCompletedTurn` for the health
  turn. No new package-level constants: reuses `runningTurnConvID` (via the
  harness return), `runningTurnHold`, `perTurnReplyBudget`. reqIDs 2/3/4 are
  function-local literals.
- Sequence: `driveRunningTurn` sends a 40s foreground-Bash-loop prompt (reqID
  2) → `drainForResponding` blocks until `turn_state{responding}` (AC1; by
  in-order-drain construction no terminal `idle` has been observed yet) →
  immediately sends a payload-less interrupt (`protocol.TypeInterrupt`, reqID
  3) — routes to the *active* conversation (stamped by the send above) →
  `resolveBoundRunner` → the bootstrap runner running the live turn →
  `streamsup.Runner.Interrupt()` (AC2) → `drainForCancelledTurnEnd` asserts
  `turn_end{StopReason:"cancelled"}` (AC3) → a trivial fourth turn
  ("Reply with a single short word", nonce-suffixed) drained via
  `drainForCompletedTurn` to a terminal `turn_state{idle}` proves the session
  stayed usable (AC4).
- New helper `drainForCancelledTurnEnd(t, phone, cs, convID, timeout)` — reads
  `noise_msg` frames in receive order (decrypts every one to keep the
  CipherState nonce in sync, skips non-`noise_msg` control frames without
  decrypting — same discipline as `drainForResponding`), returns on the
  **first** `turn_end` for `convID`. This is the vacuous-pass guard mirroring
  the fakeclaude analog: `StopReason == "cancelled"` → success;
  `StopReason != "cancelled"` (a spontaneous natural end reports `"end_turn"`)
  → `t.Fatalf` immediately, since the running loop *will* complete naturally
  at ~40s if the interrupt no-ops. Deadline → `t.Fatalf` naming the likely
  cause (interrupt never routed to the bound runner, or real claude never
  emitted `error_during_execution`).
- Routing scope is deliberately bootstrap-bound, not a minted conversation
  (unlike the fakeclaude analog, which mints a separate target to prove
  cross-conversation isolation). AC2 only requires the interrupt to reach the
  *running turn's* bound runner, which the #1172 harness's bootstrap-bound
  conversation already gives for free; minting would require a second runner
  and a second real-claude child spawn. Cross-conversation routing isolation
  stays unit-owned by #1121 (`interrupt_routing_test.go`) — the belt; this e2e
  is the different-fabric suspenders proving the wired path runs live.
- No content/echo assertion anywhere — assertions are on `turn_state`/
  `turn_end` transitions and the `StopReason` value only, per the package
  convention (#1172/#1153/#1136).

## Patterns established

- **A drain retargeted from one milestone to another is a distinct helper,
  not a parameterized shared one, and the vacuous-pass guard is the reason
  the retarget is worth writing at all.** `drainForCancelledTurnEnd` is
  structurally `drainForResponding` retargeted from `turn_state{responding}`
  to `turn_end`, but it exists as its own function because its entire value
  is the `StopReason` check — a generic "drain until envelope type X" helper
  would still let a spontaneous `end_turn` false-pass silently. Any future
  spec that needs to distinguish two ways an event can look superficially
  similar (interrupted vs. completed, denied vs. timed-out, etc.) should
  write the discriminating assertion into the drain itself, not bolt it on
  at the call site.
