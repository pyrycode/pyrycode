# Ticket #1027 — move seam interfaces + `V2SessionConfig` out of `v2session.go`

Final slice of the [#964](https://github.com/pyrycode/pyrycode/issues/964) split of
`internal/relay/v2session.go`, chained after [#1026](1026.md) (snapshot/replay). Lifts the
manager's dependency contracts and configuration — six seam interfaces, one value type, one
sentinel, and the `V2SessionConfig` struct — into a new file in the same `package relay`. Pure
mechanical move: no exported-API change, no behaviour change, zero call-site changes.

## Implementation

New file `internal/relay/v2session_seams.go` (390 lines) now owns nine declarations, moved
verbatim byte-for-byte from `v2session.go:287-652`: the interfaces `ScreenSnapshotter`,
`Interrupter`, `SessionStarter`, `QueueRemover`, `SettingsUpdater`, and `ModalResolver`; the value
type `SettingsUpdate`; the sentinel `ErrSessionUnknown`; and the ~260-line `V2SessionConfig`
struct. `v2session.go` drops by 368 lines, from 1558 to 1190 — under the #964 split's original
~1000-line-per-file aspiration but the ticket explicitly deferred chasing that further (see Open
follow-up below).

Unlike [#1026](1026.md)'s two-cut move, this was a **single contiguous span** — all nine decls
were already adjacent in source order with no interleaved manager-core code between them, so the
move was one cut, not a stitched-together set of blocks.

The one non-mechanical step: `"log/slog"` became an unused import in `v2session.go` after the cut
and was removed. `slog` had exactly one residual reference in the donor file — `V2SessionConfig.Logger
*slog.Logger` — and that field moved with the struct, so the import lost its sole user. Every other
import in `v2session.go` stayed (`errors`, `time`, `protocol`, `dispatch`, `devices`, plus
`context`, `encoding/base64`, `encoding/json`, `fmt`, `sync`, `websocket`, `control`, `eventring`,
`noise`) — all still referenced by the residual manager core. The new file imports the six packages
its moved block actually uses: `errors`, `log/slog`, `time`, `devices`, `dispatch`, `protocol`.

`ModalDismissal` — named in the ticket's own Technical Notes as adjacent to `ModalResolver` — was
correctly left untouched in `v2session_modal.go`, where an earlier #964 slice had already relocated
it; the `ModalResolver` methods reference it across files within `package relay` with no import
needed.

## Patterns established

None new — this closes out the #964 split with the same pure-move discipline as its five
predecessors ([#1021](1021.md) handshake, [#1022](1022.md) rekey, [#1023](1023.md) modal+queue,
[#1024](1024.md) settings, [#1025](1025.md) debug-bundle, [#1026](1026.md) snapshot/replay):
write-new-file-then-delete-source-span, verify by byte-diffing the moved span against the original,
one declaration site per symbol, import hygiene driven strictly by residual usage rather than the
ticket's own "what to move" list.

## Lessons learned

None — code review found zero deviation from spec. Worth noting as a category confirmation: when a
carve-out's decls are already one contiguous span (no interleaved unrelated code, unlike #1026's
`snapshotReq` and `armIdleTimer`/`wakeKind` exclusions), the move genuinely has no design surface to
second-guess — the only judgment call left is import hygiene, and that's compiler-verified, not
architect-judgment-verified.

## Verification

`go build ./internal/relay/` clean after the cut; `make check` green (vet, `-race` test incl.
`internal/relay`, staticcheck, substrate-guard, hermetic e2e, and `make e2e-realclaude` run
separately by code review). Code review: PASS, no findings — verified the byte-identical move (diffed
`main:v2session.go:287-652` against the new file's decl section), confirmed one declaration site per
symbol, confirmed import hygiene (`slog` zero residual refs, every kept import still live), and
confirmed only the two intended files changed as code.

## Open follow-up

`v2session.go` is 1190 lines post-move — still above the #964 split's ~1000-line target. Per the
ticket's own scope note, the residual (outbound `send`/drain path + connection-registry helpers) is
a cheap standalone follow-up, deliberately not chased by this slice.
