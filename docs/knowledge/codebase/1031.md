# Ticket #1031 — session-control (`new_session` + `set_session_settings`) real-claude liveness gate

Adds `TestInteractiveSessionControlLiveness` to `internal/e2e/realclaude/`
(new file `interactive_session_control_liveness_test.go`,
`//go:build e2e_realclaude`) — the first real-`claude` coverage of the two
session-control verbs that respawn the live claude child. Split from #963
per the PO split-per-family convention; last child of #963 (siblings
#1028/#1029/#1030 covered the other verb families).

## Implementation

Drives a sequential spine (the #1028 shape) on ONE freshly-spawned daemon,
ONE seeded bound conversation, over the same Noise v2 encrypted channel,
against real `claude --model haiku`:

turn 1 (liveness) → `new_session` rotate → turn 2 (liveness) →
`set_session_settings{Model:"haiku"}` respawn → turn 3 (liveness).

Both control verbs tear down and re-establish the live claude child; the
operator-facing risk is that **the reply bridge fails to rebind past the
respawn** — the same failure class #854 guards on a cold bootstrap session.
Because a pure-liveness assertion would be vacuous (a silently no-op'd
rotate/respawn would still answer from the un-rotated/un-restarted session),
each verb pairs its liveness send with a deterministic on-disk anchor:

- **`new_session`** — a bounded ~1s-cadence fire-and-forget re-send loop
  (mirrors #1004's design) until the `sessions.json` bootstrap-row id
  changes away from a baseline read *after* turn 1 settles. Structural
  causality: real claude only rotates its JSONL on `/clear`, so an
  observed id change in the bounded window can only be the driven
  `/clear`.
- **`set_session_settings`** — a request/reply exchange
  (`drainForReply`-correlated on `InReplyTo`, the #997 generalised
  control-verb seal/drain pair) asserted against the persisted `Model`
  field on the bootstrap row (mirrors #1005's design, matched by
  `Bootstrap==true` so it stays correct even if the restart itself
  rotates the id).

Turn 1 is load-bearing, not decorative: it binds the reply bridge and
attaches the tui-driver session (so `new_session` isn't silently dropped
on a detached session) and gives claude an established transcript (so
`/clear` produces a genuine rotation, not a no-op). Without it, turns 2/3
would be first-binds, not rebinds — a strictly weaker proof.

Test-only — zero production files touched. Reuses the #854/#1028 harness
(`spawnBootstrapDaemon`, `driveHandshakeInteractive`, `seedBootstrapRegistry`,
`seedBoundConversation`, `sealSendMessage`, `drainForAssistantReply`) and
the #997 generalised control-frame helpers (`sealEnvelope`, `drainForReply`,
`perTurnReplyBudget`) verbatim. The only new code is the on-disk
`sessions.json` reader family: `bootstrapRow`, `readBootstrapRow(IfPresent)`,
`waitBootstrapID`, `waitBootstrapIDSettled`, `waitBootstrapModel` (~90
lines total) — mirrors #1028's `readConversationIDsOnDisk` and #1005's
`settingsRow`/`readBootstrapSettings` shape one layer up the stack.

## Why `Model: "haiku"` (credential-safe respawn)

The seeded bootstrap settings start with `Model == ""`. `claudeSettingsArgs`
appends a session's `Model` setting as `--model <v>` *after* the daemon's
own base `--model haiku` spawn arg — last-wins, so the effective model
stays haiku, the one model this harness has already proven live. `"" →
"haiku"` is still a genuine change: `UpdateSettings` persists it and does
a real live-restart (a true no-op update writes nothing and does not
restart), so the on-disk anchor and the respawn are both real. This
deliberately avoids the credential/rate-limit risk of spawning a
*different* real model (opus/sonnet) in a pre-ship gate — the fake tier
(#1005) already proves the settings mechanism end-to-end with `opus`.

## Real-vs-fake rotation difference (the settle-before-next-turn guard)

Unlike fakeclaude's one-shot `PYRY_FAKE_CLAUDE_CLEAR_ROTATES`, real claude
rotates its transcript on **every** `/clear` and on every settings-driven
restart. A bounded re-send loop can therefore leave more than one rotation
in flight (a re-sent frame lands after the first `/clear` already fired).
`waitBootstrapIDSettled` polls until the bootstrap id has been unchanged
for a full quiesce window before the test proceeds to the next
`send_message` — otherwise a straggler rotation could tear down that
turn's in-flight claude mid-stream and flake the liveness assertion. This
is genuinely new relative to #1004 (fakeclaude's rotation is one-shot, so
the fake tier never needed a settle step).

## Patterns established

None new — reconfirms #1028's "reuse frozen harness verbatim, add one
small on-disk reader" discipline one layer up (session-control verbs
instead of conversation-management verbs), and reconfirms `UpdateSettings`
→ `Supervisor.Restart` is non-blocking (the reply returns before the
respawn completes), so a persisted-value read-back — not the reply itself
— is what proves a respawn genuinely happened.

## Lessons learned

(From the PR body's Lessons learned section — see PR #1034.)

- Real claude rotates its transcript on **every** `/clear` and on every
  settings-driven restart, unlike fakeclaude's one-shot
  `PYRY_FAKE_CLAUDE_CLEAR_ROTATES`. A control-verb re-send loop can
  therefore leave a rotation in flight; the test settles the on-disk
  bootstrap id to a stable value before each post-control `send_message`
  so a straggler rotation can't tear down that turn's in-flight claude
  mid-stream.
- `Pool.UpdateSettings` → `Supervisor.Restart` is non-blocking (signals the
  Run loop), so the `session_settings_updated` reply returns before the
  respawn completes — the persisted-Model read-back, not the reply, is
  what proves the respawn is genuine.

## Verification

Gate is code-review's responsibility (`make e2e-realclaude`, `claude` on
PATH + credentials present). Code review PASSed on PR #1034: tagged
`go vet` clean, and the test's clean-skip behaviour (AC #3) verified
directly in a credential-less environment (`--- SKIP` → `PASS`/`ok`,
matching `WithWorktreeAuthenticated`'s `t.Skipf` contract) plus a
handler/protocol cross-check standing in for the unreachable live path.
The live rotate/respawn/liveness path itself was **not** exercised in
that review environment (no `claude` creds) — the reviewer flagged this
explicitly and asked the operator to run `make e2e-realclaude` against a
creds-present, tui-driver-v1.10.0-compatible host to close the gate. Did
not run locally in the dev pipeline stage either (same credential-less /
PTY-blocked constraint). `go build`/`go vet`/gofmt clean under
`-tags e2e_realclaude`.
