# Ticket #847 — `Pool.DefaultSettings()` accessor + model/effort/yolo fields on `screen_snapshot`

Split A of #835 (split B is #848, blocked on this). Ships the two zero-dependency
read-only leaves a settings-aware screen snapshot needs — both **unwired**: a
locked accessor for the bootstrap session's persisted `SessionSettings`, and
three always-present `model`/`effort`/`yolo` fields on `ScreenSnapshotPayload`.
Nothing reads either leaf at runtime yet; #848 wires them into the snapshot
handler. Not `security-sensitive` — read-only reflection of existing,
non-secret session config.

## Implementation

Two production files, ~40 LOC combined:

- **`internal/sessions/pool.go`** — `Pool.DefaultSettings() (SessionSettings, bool)`,
  placed adjacent to `Default()` and mirroring its lock discipline exactly:
  `p.mu.RLock()`, resolve `p.sessions[p.bootstrap]` fresh (not cached), return
  `(SessionSettings{}, false)` on a nil session (no bootstrap — the embedded
  evicted-bootstrap host, or a zero-value `&Pool{}` map-miss), else
  `(sess.settings, true)`. `SessionSettings` is a value type, so the return is
  a snapshot copy with no aliasing of the pool's live field. Resolving
  `p.bootstrap` fresh on each call (rather than caching the session) is what
  keeps the accessor correct across a `RotateID` (which flips `p.bootstrap`
  under the write lock).
- **`internal/protocol/snapshot.go`** — three fields appended to
  `ScreenSnapshotPayload` **after** `TS`, **no `omitempty`**: `Model string`,
  `Effort string`, `YOLO bool`. Empty `Model`/`Effort` = inherited daemon
  default (no per-session override); `YOLO: false` = permissions enforced
  (fail-safe default). All three always present on the wire so a consumer can
  distinguish "unset" from the zero value.

**Field order is load-bearing.** `roundTripEnvelope` compares `json.Compact`ed
bytes, which preserves key order, and Go marshals struct fields in declaration
order — so appending after `TS` fixes the wire order to
`conversation_id, text, ts, model, effort, yolo`, and the fixture
(`internal/protocol/testdata/screen_snapshot.json`) had to be regenerated in
that exact order carrying representative non-default values
(`model:"opus"`, `effort:"high"`, `yolo:true`) rather than just appended at
the end.

The existing keyed-literal snapshot handler
(`internal/relay/v2session.go:1719`) keeps compiling untouched and now
serializes the three new fields at their zero values — wire-valid, no live
desktop consumer depends on them until #848.

## Testing

- **`internal/sessions/pool_default_settings_test.go`** (new): known-settings
  round-trip via the existing `helperPoolWithSettings` test helper (asserts
  `got == want` value equality plus the existence bool `true`), and a
  no-bootstrap case on a zero-value `&Pool{}` (asserts `(SessionSettings{}, false)`).
- **`internal/protocol/snapshot_test.go`** (extended): `TestScreenSnapshotPayload_RoundTrip`
  asserts the three fields against the fixture's non-default values before the
  existing `roundTripEnvelope` canonical-byte pin; new
  `TestScreenSnapshotPayload_ZeroSettingsFieldsPresent` marshals a zero-value
  payload and asserts `"model":""`, `"effort":""`, `"yolo":false` all survive
  (not dropped) — the "distinguishable from unset" contract #848 relies on.

`go test -race ./internal/sessions/... ./internal/protocol/...` and
`go vet ./...` pass. Code review: no findings ([PR #850](https://github.com/pyrycode/pyrycode/pull/850)).

## Docs

`docs/protocol-mobile.md` § `screen_snapshot` table gains three rows for
`model`/`effort`/`yolo` with the same semantics stated above. Per project
convention, `protocol-mobile.md` is the wire contract and ships as part of the
feat commit, not a doc-phase evergreen doc.

## Out of scope

- Wiring either leaf into the snapshot handler — sibling #848.
- A conversation-keyed settings accessor — deliberately not added; the
  snapshot source is always the bootstrap session (the `Snapshotter` renders
  the bootstrap, conversation-agnostic), so settings-source == snapshot-source
  by construction and a keyed variant would invent a seam neither side has.
