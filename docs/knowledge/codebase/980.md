# Ticket #980 — e2e: `change_workspace` over the v2 wire

The 2026-07-15 verb-coverage review (#960) found `change_workspace`
(`internal/relay/handlers/change_workspace.go`, #823) covered only by handler
unit tests plus the path-confinement helper test
(`cmd/pyry/change_workspace_dir_test.go`) — no e2e at any tier. Unlike its
rename/delete/archive siblings (#974/#975/#976), `change_workspace` is the one
**security-sensitive** member of the family: it stores an untrusted
**filesystem path** supplied by a network-paired party, confined to `$HOME`
(fail-closed, symlink-resolved) before it is persisted. This ticket proves
that confinement holds **over the actual wire** — fakephone → fakerelay →
spawned daemon, with the production `resolveWorkspaceDir` resolver wired at
`cmd/pyry/relay.go:412` — closing the same gap shape #949 (promote) and
#974–#976 (rename/delete/archive) closed for their verbs.

## Implementation

Test-only, one new file, no production code:

- `internal/e2e/relay_v2_change_workspace_test.go` (new, 487 LOC, build tag
  `e2e`) — `TestRelayV2_ChangeWorkspace` with three independent subtests, each
  owning its own pair → spawn → seed → Noise_IK handshake (copied call-for-call
  from the merged #974 rename test; no shared helper, per the spec's explicit
  instruction):
  - `testV2DaemonChangeWorkspaceRoundTrip` — seeds one promoted, named,
    timestamped conversation row via **direct `conversations.json` write**
    (not `createConversationViaPhone` — see below), creates a real target
    directory under the daemon's `$HOME`, sends `change_workspace`, and
    asserts the decrypted `conversation_updated` reply's `Cwd` equals
    `filepath.EvalSymlinks(target)` — the confined **realpath**, never the
    literal string sent (macOS temp dirs sit under a symlinked `/var`, so the
    two routinely differ). `IsPromoted`/`IsArchived`/`Name` are asserted
    preserved and `LastUsedAt.Equal(seededTime)` (metadata edit, not bumped;
    `.Equal`, never `==`). `conversations.json` is read back off disk to
    confirm the same realpath persisted — the daemon eager-`Save`s before
    replying, so the post-reply read is race-free without polling.
  - `testV2DaemonChangeWorkspaceRejectedNoLeak` — the load-bearing security
    subtest (AC #3, #4). The escaping target is `t.TempDir()`: an
    **existing, resolvable** sibling directory outside the daemon's `$HOME`
    (not an unresolvable or empty path — non-vacuity requirement from the
    Technical Notes, so the reject is caused specifically by escaping
    `$HOME`, not short-circuited by the empty-path guard). Asserts the reply
    is `protocol.malformed` with the static rejection message, **and** that
    neither the raw escaping path nor its `EvalSymlinks` form appears
    anywhere in the decrypted reply payload bytes — the confine error names
    the *resolved* path, so both forms must be checked. Asserts the on-disk
    `cwd` is unchanged from the seeded (different) value.
  - `testV2DaemonChangeWorkspaceNotFound` — sends `change_workspace` for an
    absent conversation id but with a **valid, in-`$HOME`** target directory,
    since confinement runs before the registry lookup — a rejected target
    would return `protocol.malformed` first and mask the not-found branch
    entirely. Asserts `conversation.not_found` and that the seeded row is
    untouched.
  - Three spawns, one per subtest (not a shared daemon), matching
    #974/#975/#976 — keeps every on-disk assertion reading a pristine
    registry.

### Seeding: direct write, not `createConversationViaPhone`

The ticket's Technical Notes suggested `createConversationViaPhone`
(`internal/e2e/per_conversation_eviction_test.go`) as the seed path; the spec
overrode this to the rename template's direct `conversations.json` write. The
architect's reasoning: `createConversationViaPhone` mints a live claude
session (`Pool.Activate`, 15s budget), bumps `LastUsedAt` to *now*, and sets
`Cwd` to the daemon default — none of which is controllable, and two
assertions here need a **known** seed value (`LastUsedAt.Equal(seededTime)`
on the happy path; a known old `Cwd` to diff against on the reject path).
Direct-seed needs no claude spawn and is the closest-template path — a
direct-seeded row is a fully valid registry row the daemon loads on boot, and
`change_workspace` only edits the recorded `Cwd`, so no live session is
required for faithfulness.

## RED-on-regression

If `TypeChangeWorkspace`'s registration at `cmd/pyry/relay.go:412` were
removed, the verb would fall through to the no-handler `protocol.unsupported`
arm and the round-trip's `want conversation_updated` assertion would fail.
The test is a live guard on that wiring, same as the rename/delete/archive
templates guard theirs.

## Security review

**Security-sensitive** — this is the one member of the rename/delete/archive
family that certifies a path-confinement containment property over the wire.
Test-only, no production code change; the production seam
(`resolveWorkspaceDir` → `confineWorkdirToHome`) is unchanged, this ticket
only adds a caller. Non-vacuity was the explicit design focus: the escaping
target is non-empty and existing (so the reject is caused by escaping `$HOME`
specifically, not a different guard); the seeded old `Cwd` deliberately
differs from the escaping path (so a validate≠store bug would flip the
on-disk assertion); and the no-leak check covers both the raw and
`EvalSymlinks`-resolved forms of the escaping path (the confine error names
the *resolved* path, so checking only the raw form would miss a regression
that echoed the wrapped error — the exact divergence #823's handler doc
warns against). Code review confirmed PASS with no findings.
