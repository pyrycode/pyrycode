# Ticket #1014 — exempt the pending trust window from the give-up bound, surface a typed "folder not trusted" session error

Split from [#992](992.md); blocked by [#1013](1013.md) (landed first). Closes the two queue behaviours left in #988 defect 1: once #1013 stopped `deliverViaSession` from clobbering claude's startup trust-folder modal with a queued turn, the held head still burned the msgqueue's 2-minute give-up bound like a real failure, and a trust deny/timeout left the client with nothing but a silent retry loop.

## Implementation

Two independent mechanisms at two sites — deliberately not coupled into one:

- **AC-1 (give-up exemption), `internal/msgqueue/queue.go`.** New injected predicate `PendingFunc func(error) bool` on `Config.Pending` (mirrors the existing `DeliverFunc`/`OnChange`/`OnGiveUp` seam style; `msgqueue` stays a leaf package that never imports `internal/supervisor`). In `drain`'s `if err != nil` block, *before* the existing `firstFailedAt` bookkeeping: if `q.pending(err)` is true, reset `firstFailedAt = time.Time{}` (identical reset semantics to the confirmed-delivery path), log at Debug (content-free: `conversation_id`/`queued_msg_id`/`queued_at`, never `head.text`), and retry the same head via the existing `sleepCtx`+`continue` — without calling `giveUp`. The pre-existing real-failure path (`ErrNoLiveSession`, `ErrTurnNotCommitted`, ctx timeouts) is untouched. Wired in `cmd/pyry/main.go` as `Pending: func(err error) bool { return errors.Is(err, supervisor.ErrTrustModalPending) }`.
- **AC-2/3 (typed error), `cmd/pyry/modal_resolve_v2.go`.** Two nil-default fields added to `modalResolverV2` — `activeConv func() string` and `notifyBlocked func(convID, reason string)` — set only at the single production call site (`relay.go:479`), leaving all 18 existing `newModalResolverV2` test call sites and the constructor signature unchanged. A new `emitFolderNotTrusted()` helper calls `notifyBlocked(activeConv(), "folder not trusted")` (a compile-time constant, AC-3) when both seams are set. Wired into the two resolution paths: `ResolveTimeout` on the winner path when `out.Class == classTrust` (a local const duplicating modalbridge's unexported wire string, mirroring the existing `optProceed`/`optExit` pattern), and `ResolveAnswer` when `out.Class == classTrust && outcome == devices.OutcomeDeny` (i.e. `exit`; a trust `proceed`/accept does not emit). Both reuse the #1008 `giveUps` channel → `sessionErrorEmitterV2.broadcast` → `TypeSessionError{CodeSessionBlocked}` frame path via one shared closure (`main.go`'s `blocked := sessionErrorNotify(giveUps, logger)`), used as both `msgqueue.Config.OnGiveUp` and `relayWiring.blockedNotify`.
- **AC-4 (no auto-trust):** holds by construction — no `internal/agentrun/trust` import, no `trust.MarkWorkdirTrusted` call, no `internal/sessions.buildSession` change in the diff.
- Tests: `internal/msgqueue/giveup_exempt_test.go` (NEW file, package `msgqueue` — deliberately not `queue_test.go`, see Patterns below) covers held-never-gives-up→accept-runs, non-pending-still-gives-up, reset-across-streaks, and the nil-`Pending` regression guard. `cmd/pyry/modal_resolve_v2_test.go` gets added table-driven cases: trust-timeout-emits, permission-timeout-no-emit, trust-answer-deny-emits/proceed-no-emit/permission-no-emit, loser-no-emit, nil-seam-safe.

## Patterns established

- **Two independent mechanisms at two sites, not one coupled fix.** A deny is *not* observable as a distinct terminal state at the msgqueue drain: ESC on claude's trust dialog = exit → supervisor respawns → untrusted cwd again → trust modal again → `ErrTrustModalPending` again. From the drain, "denied then re-pending" is indistinguishable from "still pending." The deterministic signal that a trust prompt was refused exists only at the resolver (`ResolveTimeout`/`ResolveAnswer`), where the class and outcome are known. So the give-up exemption lives at the drain and the typed error lives at the resolver — pulled from the PR's own "Lessons learned."
- **Nil-default fields over constructor params when a seam has a wide test fan-out.** `newModalResolverV2` has 18 test call sites; adding required constructor params would force a mechanical edit across two test files. Two nil-default fields set only at the single production site (`relay.go`) keep every existing test — and the constructor signature — untouched, following the same "nil disables the optional seam" convention already used by `OnChange`/`OnGiveUp`/`ModalResolver`/`DebugBundler`/`SettingsUpdater`.
- **New test file to structurally dissolve an in-flight-PR overlap.** PR #935 (test-only flaky-fix touching `queue_test.go`) was open concurrently. Rather than edit `queue_test.go` and risk a merge conflict, the new AC-1 tests went into a NEW file `giveup_exempt_test.go`. Different files never merge-conflict — this dissolves the overlap by construction rather than by sequencing or coordination.
- **Reuse the give-up frame path exactly, including its label.** The `session_error` frame the client receives on a trust deny/timeout is byte-identical in shape to a real give-up (`TypeSessionError{CodeSessionBlocked}` via the same `giveUps` channel and `sessionErrorEmitterV2`); the same shared `blocked` closure feeds both `OnGiveUp` and the resolver's `notifyBlocked`. Code review flagged (NIT, no action taken) that the closure's internal drop-on-full log line still reads "give-up queue full" even when driven by a trust deny — cosmetic only, unreachable in practice given the 16-deep buffer and ~2-min emission cadence.
