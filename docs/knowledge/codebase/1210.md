# Ticket #1210 — Fire the turn-busy exit lane from the runner's child exit

Split sibling of #1209 (itself the last child of the #1207→#1203→#1198 crash-clear lineage). #1209 shipped
the exit lane fully built but unfired: the fan-in envelope gained an `exit` discriminant, the drain gained
an arm that clears the tracker inline, and the per-runner producer closure `(*streamTurnSink).exitFor`
shipped ready to install. This slice supplies **only the binding** — one assignment in
`newStreamRunnerFactory` — plus the six forward-reference comments across five files that the assignment
falsifies. After this ticket, no reachable sequence leaves a conversation reported busy forever: `TurnEnd`
closes the normal turn, the #1202 pool transition closes a rotated or evicted one, and this lane closes a
crashed one.

**Correction (#1496):** that claim held for every *clear-side* feed named above, but not for a precondition
none of them touched — whether the fan-in (`streamTurnSink`) ever let a `TurnEnd` reach `observe` in the
first place. `sinkFor`'s pre-#1496 drop-newest was class-blind: on a saturated 256-slot channel it could
discard the newest `TurnEnd` outright, wedging the conversation regardless of how correct this ticket's exit
lane was. #1496 reserves fan-in capacity for closing-class envelopes, restoring the claim up to a documented,
`Warn`-visible reserve headroom. See [`codebase/1496.md`](1496.md).

## Implementation

- **`cmd/pyry/streamsup_runner.go`**: `scfg.OnChildExit = sink.exitFor(cfg.SessionID)`, one line below the
  existing `scfg.Stdout = streamsup.NewParser(sink.sinkFor(cfg.SessionID), cfg.Logger)`. Both installs bind
  from the one `cfg.SessionID`, which is what lets the drain's exit arm clear exactly the conversation whose
  events it is ordered behind — read as a pair, not derived. `exitFor` is installed rather than

## Patterns established

- **A program-order argument beats a timing argument for an ordering AC, and is worth chasing into the
  runtime to confirm.** AC2's "not overtaken, does not overshoot" guarantee rests on the exit fire
  (`runner.go:487-489`) sitting above the next `spawnAndWait` on the same goroutine — true regardless of
  the backoff duration, so the immediate-restart path that skips backoff (`drainRestart()` → `continue`)
  can't invert it. The reverse direction (no event from the dying child arrives *after* the exit) looked
  like it might depend on `cmd.WaitDelay`'s bounded-wait timeout cutting the join short; verified against
  `$GOROOT`'s `exec.(*Cmd).awaitGoroutines` that the timeout arm still blocks on the copier goroutine after
  force-closing the pipes, so the join is unconditional and the timeout path can only lose unread bytes
  outright, never reorder them. Prefer tracing the actual callee/runtime over trusting a plausible-sounding
  timing claim, especially on a security-sensitive ordering guarantee.
- **Install the shipped closure rather than re-deriving its behavior**, even when re-deriving it would be
  one line. `exitFor` (#1209) is the sole owner of the non-blocking-send + `Warn`-drop contract that
  `OnChildExit` requires; a hand-rolled callback that reimplements that contract passes the AC's *behavior*
  test but fails its *provenance* test the moment the shipped closure's diagnostic contract changes and the
  hand-rolled copy silently drifts from it.
- **Third ≥5-modified-files architect ruling, and the first with a degenerate remedy.** The architect
  logged this as hitting the ≥5-production-file gate at exactly 5, but ruled against a split: the only
  candidate seam (behaviour now, comments later) is the exact shape #1207's split already rejected, because
  a comment-only child would land first and its comments would say "nothing fires this" above code that
  already does. When every available seam has already been ruled invalid by a prior split decision on a
  sibling ticket, the correct move is to commit at the count and flag it, not to re-litigate the seam.

## Lessons learned (from PR#1212 — code review PASS, 1 SHOULD FIX + 3 NITs; and the developer's own PR body)

- **A production-wired end-to-end test often can't assert the pre-state a unit test could, because
  production pushes the two envelopes back-to-back.** #1209's unit tests pushed the exit envelope by hand,
  so asserting `Busy` before it was trivial. Here the same fake child's opener and its own exit hit the
  fan-in microseconds apart under the real runner, so an assertion ordered strictly after the opener's
  drop-log barrier races the clear nondeterministically — it would pass with a dead exit lane as often as it
  would fail with a live one. Fix: make the *child* the synchronization point instead of the test's own
  timing — the fake claude prints its opener, then blocks on a marker file the test creates only *after*
  asserting `Busy`. The child is provably still alive at the assertion, so the pre-state is deterministic
  rather than timed. General shape: when production coalesces two events a unit test could previously drive
  independently, move the barrier into something the test controls (a file, a channel) rather than trying to
  observe timing.
- **A shell builtin's flush-before-block behavior is worth measuring, not assuming from a different
  fixture's precedent.** The existing `fakeClaudeScript` precedent writes to a PTY (line-buffered by
  default); this ticket's fixture writes to a pipe (potentially block-buffered), so "the precedent already
  proved this pattern works" wasn't actually evidence. Verified empirically (~6ms) that `sh`'s builtin
  `printf` flushes to a pipe before the script blocks, and confirmed on `/bin/sh`, dash and bash — not a
  Linux-CI-only behavior.
- **An insertion invalidates `file.go:NNN` citations tree-wide, including in files the diff never touched.**
  Code review's one SHOULD FIX: this diff's doc-comment insertions (in `streamsup_runner.go`,
  `stream_turn_busy.go` ×2, `stream_turn_drain.go`, `relay.go`, `runner.go`) shifted six in-tree line
  citations by their own insertion length, and two of the six point at files this diff never edited
  (`session_transition_v2.go:229` → `relay.go:845`, now `:847`; `relay.go:742` → `relay.go:779`, now
  `:781`). The worst case pointed at the evidence line for a security-relevant UNREACHABLE claim
  (`stream_turn_busy.go:45` → `streamsup_runner.go:105`, now `:117`, landing on unrelated prose that doesn't
  self-report as wrong). Not merge-blocking here — no behavior change, and the same class of drift was
  already present on `main` before this diff — but the sweep is cheap and should run after any doc-comment
  insertion: `grep -rnoE '<edited-file>\.go:[0-9]+' --include='*.go' .` for each file touched, then diff the
  cited line against what's actually there post-edit.
- **`gh pr checks` reporting no checks on a feature branch means every gate in the review was verified
  locally only.** Recorded as a NIT — infra, not this diff's defect — but worth remembering when reading a
  PASS verdict on this branch: CLAUDE.md's "CI runs on every push and PR" did not actually run here.
