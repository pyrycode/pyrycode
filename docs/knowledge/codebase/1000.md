# Ticket #1000 — bound the interactive msgqueue drain retry with a give-up seam (engine-side, unwired)

Engine-side half of the deterministic safety net for the startup-dialog design (belt-and-suspenders: a deterministic backstop under stochastic dialog handling), split from [#991](991.md). Before this ticket, `internal/msgqueue`'s `drain` retried a persistently-failing FIFO head every `RetryInterval` **forever** — a claude child parked at startup (unanswerable dialog, wedged readiness gate, network stall) looped on a head that never drained and never failed, leaving the client with a message that neither ran nor errored. This ticket adds a bounded give-up plus a `GiveUpFunc` notification seam that mirrors the existing `OnChange` seam, while preserving the survive-respawn property that makes the retry loop lossless. Ships **unwired** (`OnGiveUp` stays `nil` in production) — a later ticket (#1001) wires it over the v2 wire.

## Implementation

One production file, additive-only (no signature change to any existing exported symbol):

- `internal/msgqueue/queue.go`:
  - `defaultGiveUpAfter = 2 * time.Minute` — a tuning-knob const, chosen to exceed the supervisor's max backoff window with margin (`BackoffMax=30s`, `BackoffReset=60s`, `internal/supervisor/supervisor.go`).
  - `GiveUpFunc func(convID, reason string)` — new type, mirrors `ChangeFunc` exactly: fired off-lock, non-blocking, nil disables.
  - `Config.GiveUpAfter time.Duration` and `Config.OnGiveUp GiveUpFunc` — two new additive `Config` fields, resolved in `New` with the same default-resolution idiom as `RetryInterval`/`MaxQueuedPerConversation`.
  - `Queue.notifyGiveUp(convID, reason string)` — mirrors `notify`, nil-safe.
  - `drain`: a new `drain`-local `var firstFailedAt time.Time` tracks the current head's consecutive-failure streak. On a delivery error it's set on first failure and reset to zero on the next successful delivery (a fresh bound per head — the loop cannot distinguish transient-respawn errors from a persistent wedge by type, so the bound separates them by elapsed time instead). Once `time.Since(firstFailedAt) >= q.giveUpAfter`, `drain` calls the new `giveUp` helper and **returns** (exits the goroutine) instead of `continue`-ing to the next `sleepCtx`/retry cycle.
  - `Queue.giveUp(convID, c, head, elapsed, err)` — new helper: builds a `reason` from only daemon-generated values (`elapsed.Round(time.Second)` + `err.Error()` via `fmt.Sprintf`, **never** `head.text`), logs a give-up warn line with the same field discipline as the existing retry-warn log, then under `q.mu` drops the head (`c.advanceLocked()`) and clears `c.draining = false`, unlocks, and fires `q.notify(convID)` then `q.notifyGiveUp(convID, reason)` off-lock in that order.

Why `giveUp` **exits** the drain rather than continuing to the next head: the wedge is a session parked at startup, so every subsequent head would fail identically — continuing would burn one full `giveUpAfter` window per head and emit N give-up events for one wedge. Exiting drops only the wedged head, emits exactly one give-up notification, and returns the conversation to a clean idle state. Any items still behind the dropped head stay queued in the FIFO; because `draining == false` with `len(items) > 0` is exactly `maybeSpawnDrainLocked`'s respawn precondition, the next `Enqueue` respawns the drain — the same lifecycle the pre-existing empty-exit path already uses.

`notify(OnChange)` fires on give-up (a head left the backlog) in addition to `notifyGiveUp`, keeping the wired `queue_state` producer's view correct after the drop without waiting on #1001.

## Patterns established

- **Elapsed-time bound, not error-identity bound.** `Deliver` errors (`ErrNoLiveSession`, `ErrTurnNotCommitted`, PTY write errors) are indistinguishable by type between an ordinary respawn and a persistent wedge — the only way to separate "will clear" from "give up" is a per-head elapsed-time deadline wide enough to exceed the caller's own backoff ceiling.
- **Per-head, not per-session, latch.** `firstFailedAt` is a `drain`-local variable, reset on every successful delivery — a wedge that clears for one message doesn't poison the bound for the next.
- **Seam ships unwired, disabled means `nil`, and the abandonment is still real.** Same engine-first rhythm as msgqueue's original #704 landing (mechanism first, wired later): `OnGiveUp == nil` in production this ticket, but the bound, head-drop, and clean exit all still happen — the give-up is real even when unobserved.
- **Give-up reason built only from daemon-controlled values.** `elapsed` + `err.Error()`, never any `head` field except the daemon-minted `head.id` — extends the package's pre-existing `NEVER log head.text` discipline to the new log line and to the seam payload.

## Testing

`internal/msgqueue/queue_test.go` (+216 LOC), placed immediately after `TestQueue_LosslessRetry_SurvivesRespawn` (mid-file, deliberately not at end-of-file — an unrelated in-flight branch for flake #934/#935 touches the trailing function, and that branch's fix is already superseded on `main`, so the mid-file placement keeps any residual conflict structurally impossible). `fakeDeliver` gained a `permaFail map[string]bool` + `setPermaFail(convID, on)` toggle to model a wedged session that never commits, alongside the pre-existing `failTimes` transient-failure countdown.

Five new tests: `TestQueue_GivesUpAfterPersistentFailure` (AC1+AC3 — permanent failure trips `OnGiveUp` once with a non-empty reason, head dropped, message never delivered), `TestQueue_TransientFailure_NoGiveUp` (AC2 — a 3-fail-then-clear transient failure delivers and never fires `OnGiveUp`, the existing survive-respawn scenario extended with the seam wired to a recorder), `TestQueue_DefaultGiveUpAfter_ExceedsBackoffWindow` (AC2 regression guard — pins `defaultGiveUpAfter >= 2*time.Minute` as a numeric literal since the supervisor's backoff defaults are unexported, not exported consts, so there's no clean cross-package symbol to reference), `TestQueue_GiveUp_NoUntrustedContentLeak` (AC4 — a distinctive `SUPER_SECRET_PHONE_TEXT` marker asserted absent from both the captured `OnGiveUp` reason and the `slog` text-handler log buffer), `TestQueue_GiveUp_CleanTeardownAndRespawn` (AC5 — empty snapshot after give-up, a second `Enqueue` after clearing the wedge delivers, and cancelling proves `Run` returns `context.Canceled` with no leaked drain goroutine).
