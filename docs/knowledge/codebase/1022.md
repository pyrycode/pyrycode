# Ticket #1022 — move Noise rekey machinery out of `v2session.go`

Second slice of the [#964](https://github.com/pyrycode/pyrycode/issues/964)
split of `internal/relay/v2session.go`, chained directly after
[#1021](1021.md)'s handshake move. Carves the Noise rekey lifecycle — the
periodic timer-driven rekey plus the operator-triggered manual rekey — into
a new file in the same `package relay`. Pure mechanical move: no
exported-API change, no behaviour change, and because everything stays
in-package, zero call-site changes anywhere in the tree.

## Implementation

New file `internal/relay/v2session_rekey.go` (466 lines) now owns: the
`rekeyInterval` / `rekeyReplyTimeout` / `rekeyRetryInterval` package vars,
the `manualRekeyReq` type, `rekeyComplete`, the three arm-timer methods
(`armRekeyTimer`, `armRekeyReplyTimer`, `armRekeyRetryTimer`),
`handleRekeyInit`, `handleRekeyRequest`, `emitRekeyRequest`, `Rekey` (with
its `var _ control.Rekeyer = (*V2SessionManager)(nil)` satisfaction anchor
moved alongside it), and `handleManualRekey`. `v2session.go` drops from
3323 to 2875 lines (448 pure deletions).

`armIdleTimer`, the `wakeKind` iota block, and the three `Err*` sentinels
all sit interleaved with the moved code in the original file and **stay in
`v2session.go`** — idle-timeout is a distinct concern, the iota block would
fracture if split, and the sentinels are shared with non-rekey callers
(outbound send). `v2session_handshake.go` (#1021) references
`handleRekeyInit`/`armRekeyTimer`; those resolve same-package to the new
file with no edit required there — confirming AC#3.

The `bytes` import was dropped from `v2session.go`: its only *code* use in
the whole file was `bytes.Equal` inside `handleRekeyInit`, which moved with
the carve-out, orphaning the import. The compiler forced the removal (every
other import retained a core user in the staying ~2875 lines). This is a
mechanically-forced consequence of the move, not a logic change, and squarely
within AC#2.

## Patterns established

None new — reconfirms the pure-move discipline from [#1021](1021.md) one
slice further into the #964 split: same-package carve-out with an
interleaved-neighbour boundary (idle timer / iota block / shared sentinels
must stay) resolved entirely at spec time, leaving the developer only the
exact line-range judgement call, verified incrementally via
`go build ./internal/relay/`.

## Lessons learned

- A spec's "expected import list" for a moved file should be read as a
  floor, not a ceiling, on **both** ends — #1021 found the new file needed
  *more* imports than the spec sketched (transitive deps the spec author
  didn't enumerate); this ticket found the *donor* file needed **one fewer**
  import than the spec assumed. The spec here explicitly reasoned "every
  package the moved code uses also has many other users in the staying
  core" and predicted no import would go stale — that reasoning held for
  every import except `bytes`, whose only code occurrence turned out to be
  inside the very method being moved. Every other `bytes.` hit in the file
  was comment prose ("...bytes." at a sentence end), not code — so a plain
  substring grep over-counts usages. When verifying "does this import stay,"
  grep for the real `pkg.Ident` call pattern, not the bare package name, and
  treat `go build`/`go vet` as the authority over prose enumeration in
  either direction (spec already called this out as the fallback; this
  ticket is the case where the fallback actually fired).

## Verification

`make check` (vet, `go test -race ./...`, staticcheck, substrate-guard,
`-tags e2e`) green, including the real-claude e2e suite. Code review
confirmed byte-identical relocation of all 11 declarations (zero orphans,
each present exactly once in the new file including doc comments) and that
the diff touches exactly the two intended files.
