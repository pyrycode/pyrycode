# Ticket #1417 — The trailer gate admits an absent `terminal_reason` from a runner path that owes none (offline)

`trailGate`'s absence arm (`trailer_admissibility_test.go`, split three ways by #1420) answered
`trailGateOutOfContract` for all three absence sub-cases — including the one that is a healthy
streamrunner run's documented shape, not a caller's bug: `streamrunner.Run` tees claude's stdout for
the watchdog and passes the bytes through unchanged (`internal/agentrun/streamrunner/runner.go:177-179`),
synthesising a trailer of its own only when the idle-stall watchdog fired **and** claude emitted no
result (`:250-253`). Every healthy headless `PYRY_USE_STREAMJSON=1` run's trailer is therefore claude's
own `result` line, owing no `terminal_reason` by construction — and feeding that reading into
`trailClassifyRun`'s step-1 arm, whose whole documented purpose is that a caller's bug must not read as
a measured void, inverted exactly that: a genuine measurement filed as an instrument defect, with no
verdict about pyry reached at all.

This ticket flips exactly the owes-none absence sub-case to `trailGateAbsentOwesNone`, a sixth gate
value that certifies no reason (`Reason` stays empty — `trailClassifyRun`'s C2 is green unamended) but
is no longer `trailGateOutOfContract`. The owes-one and path-unnamed absence sub-cases and
present-and-empty are unchanged. `trailClassifyRun` gains a matching step-1 arm,
`trailOutcomeVoidPathOwesNoReason` — a twelfth run outcome and a void, deliberately not
`trailOutcomeVoidNoTrailer` (a trailer *was* written on this path) and not `trailOutcomeOutOfContract`
(this is a reading, not a defect). Both closed sets — the union map, every membership predicate, every
consumer switch over the gate's values — grow in the same commit: a gate value with no arm in
`trailClassifyRun`'s default-less step-1 switch would fall through to steps 3–8 and award a scan-side
answer about pyry from a record the gate says certifies nothing, the same hazard class one step past the
shipped "falls through to step 2" shorthand (C4 forces `Admit` empty for a non-certifying value, so step
2's `trailAdmitProof` test cannot fire either).

PR [#1423](https://github.com/pyrycode/pyrycode/pull/1423). Split from #1368 ← #1351 ← #1237, blocked
by #1419 and #1420 (both merged at `93b2018`). Security-sensitive (architect self-review PASS).

## Implementation

- **`trailGateAbsentOwesNone = "gate-absent-reason-owes-none"`** — new gate const, checked distinct
  against all 35 existing union-map constants (now 37) and against the three `reason-*` case markers in
  particular. Its doc records what the reading supports and no more: absence is that path's documented
  healthy shape (cited to the passthrough and watchdog-only synthesis above), it certifies nothing, it
  says nothing about whether a process was alive, nothing about the sibling defect in #1369 (a trailer
  that *carries* a `terminal_reason` on a path that owes none — still `trailGateUsable` today), and
  nothing about the path a *live* run took.
- **One return site changes its value, not its shape.** In `trailGate`'s absence branch's
  `case trailReasonAbsentOwesNone:` (the `trailReasonAgainstPath`-driven switch #1420 built), the return
  now carries `Value: trailGateAbsentOwesNone` with rewritten prose. Presence is still the gate's own
  key-name membership read (never `decodedReason != ""` — the collapse #1357's reading prevents); which
  absence still comes from `trailReasonAgainstPath` **called**, never re-switched; `Reason` stays empty;
  `RunnerPath` is still echoed. The owes-one and path-unnamed sites, and the present-and-empty arm, are
  untouched.
- **Byte budget measured, not guessed** (`go test -overlay`, no worktree writes): composed Details land
  at **461 / 464 / 468 B** against the 512 B `reachMaxCommandBytes` cap, with the embedded
  `trailReasonAgainstPath` Detail contributing 264 / 269 / 286 B. The owes-none arm carries the tightest
  ceiling of the three — 470 B (512 − the 42 B `trailNeedle`) — because AC5's leak row asserts the needle
  would still have fitted; each case's own prose is under 200 B and is **rewritten to fit, never
  appended to** (appending truncates past the embedded value marker and publishes a severed sentence
  that still satisfies a marker assertion — the same trap #1420 recorded).
- **`trailIsGateValue`** gains the value — the only gate-side membership change.
- **`trailClassifyRun` step 1** gains `case trailGateAbsentOwesNone:` returning
  `trailOutcomeVoidPathOwesNoReason`, with a Detail naming what decided and explicitly *not* claiming the
  observed path is the path a live run took. C1's published Detail (which both counts and enumerates all
  gate values) grows a sixth `%s`; the step-1 hazard note is re-derived against what is *reachable*
  rather than the shipped "falls through to step 2" shorthand — C4 forces `Admit` empty for a
  non-certifying value, so the unhandled-arm hazard is steps 3–8, not step 2.
- **`trailRunAbsentOwesNoneReadings()`** — a new fixture function (not a var, for the same
  `go test -race` reason `trailRunWellFormed()` is a function) building the composed input through the
  **real producers**: `trailGate(trailGateInput{Scan: trailGateAbsentReasonScan(), RunnerPath:
  tdnRunnerFromArgv(tdnFixtureStreamArgv)})`, `Admit` left zero — exactly what a correct consumer leaves
  behind when the gate certified nothing (C4). `MatchCount` set to 1, undocumented at the assignment site
  itself (a code-review NIT, left open — see below) but load-bearing: it is what makes the `-overlay`
  arm-deletion demonstration read `run-matched-not-attributed` rather than `run-no-row-matched`.
- **`trailRunCases()` gains a row** using that fixture, `want: trailOutcomeVoidPathOwesNoReason` — not
  named by the ticket and mandatory anyway, since `TestTrailClassifyRun`'s coverage loop errors on any
  `trailRunOutcomeValues()` member no row reaches.
- **`TestTrailRunComposesUnderAnAbsentReasonOnAPathThatOwesNone`** — new end-to-end composition test.
  Asserts the gate reaches `trailGateAbsentOwesNone` from a real scan under a real reading, and the
  composition reaches the new outcome; the vacuity guard is a **controlled experiment inside the test**
  rather than a doc claim — a control pair of readings (`MatchCount` 1 vs 0 under a usable gate) first
  proven to reach two *different* outcomes (`trailOutcomeMatchedUnattributed` /
  `trailOutcomeNoRowMatched`), then the same two readings with only the gate answer swapped to the new
  value, both required to converge on the new outcome. Invariance across tails proven to disagree is what
  shows step 1 decided. Does **not** hand the classifier `trailAdmitProof` alongside the new value — C4/C5
  reject that pair upstream of step 1, so such a test would re-prove the contract block and say nothing
  about the arm.
- **`TestTrailGateNamesWhichAbsenceCaseFired`** amended, not replaced. New per-row `wantValue` field: R1/
  R3/R4 keep `trailGateOutOfContract` as a non-vacuity precondition (five arms answer it now, not six);
  R2 becomes the discriminator, asserting `trailGateAbsentOwesNone` directly. All four rows keep their
  marker assertions. Mutant matrix extended with M5–M9 (gate's own `against.Value` switch, distinct from
  M1–M4's `trailReasonAgainstPath` label-switch mutants): M5 awards the new value on the path-unnamed
  answer (sole red R3), M6 on the owes-one answer (sole red R1), M7 on every absence answer at once (red
  R1 **and** R3 — recorded as sole-red-for-neither, not mistaken for one), M8 keys the new arm on the
  decoded reason rather than key names (sole red R4 — inside `reason == ""` the decoded test is
  constantly true, so present-and-empty routes into the absence switch), M9 lets the new arm certify a
  reason (sole red R2, plus C2 as an independent second red outside this file). Each demonstrated under
  `go test -overlay`.
- **`TestTrailGateIgnoresTheRunnerPathExceptAtTheAbsenceArm`** — the exempted row's **value** comparison
  is now exempt alongside the byte comparison on `pathVaries` rows (value varies by reading after this
  ticket: `trailGateAbsentOwesNone` at reading 1, `trailGateOutOfContract` at the other four). The
  certified-reason comparison stays unconditional on every row — still invariant (`""` on all five
  absence readings), and what keeps a path-varying arm from starting to certify. The companion sub-test's
  per-reading expectation becomes a pair (value + unconditional empty reason); `len(details) != 3` stays
  pinned at 3 — three distinct Details, one of them now belonging to a different gate value.
- **`TestTrailGateThenAdmit`'s non-certifying switch** gains a fourth value
  (`trailGateAbsentOwesNone`, alongside `trailGateNoTrailer`/`trailGateScanAborted`/
  `trailGateOutOfContract`), fatal message updated. No shipped row reaches it — defensive, per AC4.
- **`TestTrailAdmissibilityRecordsCarryNoCapturedBytes`'** leak sweep gains a third row: `keyNames`
  without `trailReasonKeyName` but with `trailNeedle` planted as a key name, `reading:
  tdnRunnerFromArgv(tdnFixtureStreamArgv)`, `want: trailGateAbsentOwesNone`. The two shipped rows both
  drove `trailRunnerUnread()` and so reached only the path-unnamed fall-through — this row is what
  actually exercises the new arm. Because `reachCapCommand` truncates rather than fails, the row also
  asserts on the output that the Detail is not truncated and that the 42 B needle would still have
  fitted (`len(Detail) + len(trailNeedle) <= reachMaxCommandBytes` — 464 + 42 = 506 ≤ 512, 6 B to spare).
- **Every count re-derived from its set, not adjusted by one:** gate space five → six; out-of-contract
  arms six → five; non-certifying values three → four (`TestTrailGateThenAdmit`'s switch and its
  `Fatalf`, plus `trailAdmitAttribution`'s doc); outcome space eleven → twelve (three answers, nine named
  voids); the union map's own size, corrected from a stale "twenty-nine" (already thirty-five at HEAD,
  stale since #1366) to thirty-seven, read off the map rather than printed by hand. A residual numeral
  and count-word sweep confirmed no others survive.
- **The one stale scope paragraph named out of the ticket's own site list, corrected deliberately**:
  `trailer_terminal_reason_test.go:48-56`'s claim "nothing here touches `trailGate` or
  `trailClassifyRun`, and nothing consumes this predicate yet" was already false at HEAD (#1420 wired the
  predicate in) — rewritten to what is true, discharging both the #1368/#1367 hazard attributions it
  carried.

## Patterns established

- **A closed set's own printed size drifts from the set silently — read it off the map instead of
  adjusting it by one.** The union map's doc comment said "twenty-nine" while the map held thirty-five,
  stale since #1366 added six reason values two tickets ago and never caught. Confirmed by counting the
  map's actual keys rather than trusting the prior comment plus the ticket's own delta.
- **A vacuity guard for "the arm decided" is a controlled experiment, not a doc claim.** Proving the two
  tails genuinely disagree under a usable gate *before* swapping in the new value is what makes the
  subsequent invariance meaningful — without the control, convergence on one outcome is equally
  consistent with the tails never having mattered.
- **Mutants of two different switches need separate matrix sections even when they share rows.** M1–M4
  (which absence case a reading reduces to) and M5–M9 (which gate value a case is awarded) can produce
  the same sole-red row (M1/M2 and M5 all land sole-red-or-shared on R3) — the discriminator has to be
  the *wrong value* reported in the failure message, not the row alone.
- **A row that shares a red with another mutant is worth recording precisely because it isn't sole-red.**
  M7 (awarding the new value on every absence answer) fails both R1 and R3 and is sole red for neither —
  recorded in the matrix explicitly so a reader doesn't mistake shared-red for a matrix gap.

## Lessons learned

From code review (three rounds — FAIL, FAIL, PASS — both FAILs on an abandoned/incomplete cross-file
cite-renumbering sweep, never on the ticket's substance):

- **A large insertion into a heavily cross-cited file needs a mechanical cite sweep, not a spot-check.**
  Inserting ~290 lines into `trailer_admissibility_test.go` and ~250 into `trail_run_outcome_test.go`
  shifted every downstream cite by +19 to +193 lines across 10 files. First round: 79 of ~99 shifted
  cites were left stale (some renumbered, most not) — round 1 code review's own sharpest evidence was
  five cite-bearing lines this PR *itself edited* (changing `eleven` → `twelve` in the same breath) that
  left the adjacent line number stale. **A cite sweep is mechanical, not read-by-eye**: resolve each
  cited line against the base file, locate that exact content uniquely at HEAD, map forward — never trust
  a partial pass that "looks done."
- **A bare `(:NNN)` cite's inherited file is a hypothesis, not a fact — and the carry pass cannot certify
  itself.** Round 2 found two cites the round-1 fix missed, both bare refs that inherited the wrong file
  from the last-named `.go` file to their left while the symbol they described lived elsewhere. The fix
  that survives future insertions is naming the file outright rather than nudging the number — a renumber
  edits exactly the line source-alignment needs to match, so pairing must run on **normalised prose**
  (strip `:\d+`) as well as positional diff alignment; the two have different blind spots and neither
  alone is sufficient. See [[code-review-pair-cites-by-normalised-prose]] and
  [[code-review-detect-bare-chained-cites-with-a-last-named-file-scan]] (prior-session memory entries this
  ticket's review reconfirmed).
- **The substance itself was sound from round 1** — every load-bearing numeric claim (byte budget, mutant
  matrix, closed-set sizes, offline green counts) was independently re-derived by reviewer across all
  three rounds and never found wrong. The only defect across three review passes was attribution
  bookkeeping in comments, not the gate/classifier logic.

Two NITs left open at PASS, neither blocking:

- **`trailRunAbsentOwesNoneReadings()`'s `in.MatchCount = 1` is unexplained at its own assignment site**,
  in a file where every other field assignment in that fixture carries its reasoning inline. It is not
  incidental — it is what makes the `-overlay` arm-deletion demonstration surface as a *matched*
  scan-side answer (`run-matched-not-attributed`) rather than a no-match one, confirmed by reviewer
  deleting the arm and reading the failure message. Left open rather than fixed since it doesn't affect
  correctness, only a future reader's ability to see why the value was chosen.
- **`finding_staging_gate_test.go:148`'s `trailGateResult:238-253` cite names no file**, correct only
  under `trailer_admissibility_test.go` while its own carry names `trail_run_outcome_test.go`. Not a
  regression — it was wrong at base too and `1ab6fbe` correctly re-resolved the *number* without applying
  the file-naming remedy applied at nine sibling sites in the same commit.
