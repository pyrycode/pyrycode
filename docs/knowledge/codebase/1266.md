# Ticket #1266 — Result-trailer observation with an honest lateness bound

Adds `internal/e2e/realclaude/result_trailer_observation_test.go` (617 lines, purely
additive — nothing else in the repo edited). A pure scan over pyry's stdout that keeps
three states apart where `parseResultTrailer` keeps two (trailer seen / absent), plus a
poll over `probeSyncBuffer` that stamps the observation instant together with an honest
bound on how late that stamp may be. Ships the observation only; classifying a run's
observations into a finding is [#1267](https://github.com/pyrycode/pyrycode/issues/1267)'s
job. Split from #1254; offline, `e2e_realclaude` build tag, no live claude or credentials.

## Implementation

- **Two closed value spaces, both non-collapsible.** `trailSeen` / `trailAbsent` /
  `trailAborted` for what the scan found; `trailBoundFromMiss` / `trailBoundFromStart` /
  `trailBoundNone` for what the staleness bound was measured from. Every constant is a
  non-empty, pairwise-distinct string specifically so a zero-valued struct field can never
  misread as one of them — `TestTrailConstantsAreClosed` asserts this against both the
  constants and the zero `trailObservation`.
- **The bound's honesty problem: a bare duration is sometimes a bound and sometimes not.**
  If the first poll already matches, no non-matching poll was ever observed, and the only
  available duration (measured from the loop's start) bounds nothing — the trailer may have
  become visible before the loop began. `trailBoundFromStart` names that case explicitly so
  a consumer discriminates it by field value, never by reading prose. This is the same shape
  of defect the ticket exists to close, recurring one level up.
- **`parseResultTrailer`'s uncaught `scanner.Err()`.** It discards the scanner error, so a
  stdout line past `bufio.Scanner`'s 64 KiB default (the trailer's `result` field carries
  the last assistant message verbatim — not hypothetical) returns the same
  `"no type:result line in stdout"` as a genuine absence. `trailScan` is a new function that
  reads `scanner.Err()` after the loop and reports `trailAborted` — distinct from
  `trailAbsent` — so an instrument failure can never be filed under a real "trailer never
  appeared" outcome. `parseResultTrailer` and its nine call sites (`budget_test.go` ×3,
  `resilience_test.go` ×2, `long_session_test.go`, `mcp_smoke_test.go`, `per_agent_test.go`,
  `tool_loop_test.go`) are untouched — all nine want today's two-valued behaviour.
- **The cap and the consumer's field must not compete.** The trailer's wire order
  (`internal/agentrun/streamjson/emitter.go:456-468`) is pinned: `result` sits sixth,
  `terminal_reason` last. A 512-byte cap (`reachCapCommand`/`reachMaxCommandBytes`) applied
  to the raw line truncates inside `result` on any ordinary run and destroys everything
  after it — `terminal_reason`, exactly the field #1267 branches on. Resolution: decode the
  **full** line into `resultTrailer` first, then cap only the retained `Line` copy.
  `resultTrailer` has no `result` member (verified — zero hits), so the decoded value
  structurally cannot carry the assistant payload; truncation degrades only the
  human-readable evidence.
- **Stamp-before-read is the correctness argument for the miss-derived bound.**
  `trailWaitForTrailer` stamps `now := time.Now()` *before* reading `stdout.Bytes()` on
  every iteration. A miss stamped after its read could postdate the append that made the
  trailer visible, making `now - lastMiss` an *under*-estimate of the true lateness — a
  non-bound wearing a bound's label. Stamped before the read,
  `lastMiss ≤ readInstant ≤ visibilityInstant` holds unconditionally, so
  `Staleness ≥ ObservedAt - visibilityInstant` holds unconditionally. `TestTrailWaitForTrailer`'s
  first subtest is the regression guard for this inequality (asserted against a real
  goroutine race under `-race`, not simulated).
- **What the bound bounds, named explicitly in the file header.** Two unmeasured gaps sit
  between pyry writing the trailer and the record's `ObservedAt`: gap A (pyry's write → the
  `os/exec` copier making it visible in the buffer, unmeasured) and gap B (the 200 ms poll
  tick, bounded). `Staleness` bounds gap B only — the doc comment says this in those terms so
  a reader cannot mistake it for a bound on when pyry actually wrote the trailer.
- **`Trailer *resultTrailer` is a pointer on purpose.** nil on `trailAbsent`/`trailAborted`;
  a consumer dereferencing without checking `State` panics loudly rather than silently
  reading `TerminalReason == ""` as a real empty terminal reason — the same silent-zero
  collapse the state constants forbid, one level down in the struct.
- **Reused, not rebuilt:** `resultTrailer` (decode shape), `reachCapCommand` /
  `reachTruncationMarker` (the cap), `probeSyncBuffer` / `probePollInterval` (buffer and
  200 ms tick) — all called, none duplicated. Identifier prefix `trail*`, re-verified free
  with `git grep -nP '\btrail[A-Z]'` (0 hits) against a `tdn*` control (489 hits), confirming
  the `-P` flag (not `-E`, which lacks `\b` support in this repo's grep) actually finds
  things.
- **Test coverage:** `TestTrailConstantsAreClosed`, `TestTrailScan` (table-driven: ordinary
  trailer, trailer preceded by ordinary lines, absent with no trailer, empty stdout, >64 KiB
  line → aborted never absent, over-long line *after* the trailer → still seen, and the
  cap-vs-consumer-field case with a leak assertion over `json.Marshal` of the whole record),
  `TestTrailWaitForTrailer` (miss-derived bound under `-race`, start-derived bound, deadline
  expiry with no bound). 11 subtests, 0 SKIP: `go test -race -tags e2e_realclaude -run '^TestTrail' -v ./internal/e2e/realclaude/`.

## Patterns established

- **A discriminator's closed value space needs the zero value tested, not just the named
  constants.** `TestTrailConstantsAreClosed` checks the zero `trailObservation`'s `State`
  and `BoundFrom` don't coincidentally equal any real constant — the failure mode isn't two
  constants colliding, it's an unfilled struct field silently reading as a filled one.
- **A pure scan and a stateful poll are different types, composed by embedding.** A function
  with no clock cannot honestly report an observation instant; `trailScanResult` (pure) and
  `trailObservation` (`trailScanResult` + `ObservedAt` + `Staleness` + `BoundFrom`) are kept
  separate so the type system — not convention — prevents a zero `time.Time` from posing as
  a real timestamp.
- **When a cap and a downstream consumer's field compete, decode first, cap the copy.** The
  general shape (also load-bearing in #1260's fixture-frame propagation lesson): if a
  wire-format field the consumer needs sits *after* the field the cap must degrade, capping
  the raw bytes is wrong regardless of cap size — decode into a struct with no member for the
  capped field, then cap only the retained human-readable copy.

## Lessons learned

- **A mutation that doesn't apply passes, and reads exactly like a mutation that was
  survived.** Mutation-testing `trailBoundNone = trailBoundFromMiss` came back green on the
  first attempt — not because the check was vacuous but because the `perl` substitution
  assumed gofmt-aligned `=` spacing that a `const` block with a doc comment per constant
  never has (gofmt restarts alignment groups at every comment, so spacing varies line to
  line). A mutation test needs its edit confirmed applied (`grep` the mutated line) before
  its result is evidence — "green" is the same output for *the check is weak* and *nothing
  was changed*. See also
  [[developer-1266-unapplied-mutation-reads-as-survived]] for the general form of this trap.
- **The stamp-before-read ordering is doc-comment-load-bearing, not test-load-bearing.**
  Stamping the miss poll after its read instead of before is the defect the design exists to
  prevent, but at a 500 ms append against a 200 ms tick, reversing the order only moves
  `lastMiss` by microseconds — `Staleness >= true lateness` still holds and the suite stays
  green. The inequality test is a regression guard for the *magnitude*; the ordering
  *argument* is carried entirely by the doc comment (`trailWaitForTrailer`'s "whole
  correctness argument" section), and no test in this file would catch that comment's claim
  being silently reversed. Worth naming rather than letting "tested" imply the design's real
  argument is exercised.
