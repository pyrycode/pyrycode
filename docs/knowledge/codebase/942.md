# Ticket #942 — Migrate the phone-dependent v1 e2e tests to the v2 Noise handshake

Test-only, no security surface ([[security-sensitive-label-tracks-design-not-lineage]]: transport
swap, no new design surface). Child B of the #939 split, unblocked once sibling #941 relocated the
shared harness helpers. Migrates the three e2e tests that still dial a phone and complete a
handshake before exercising daemon behaviour — `respawn_after_eviction_test.go`,
`per_conversation_eviction_test.go` (two sub-tests), `register_push_token_test.go` — from the v1
plaintext `hello`/`hello_ack` route to the v2 Noise_IK sealed path, so their coverage survives
#913 removing the v1 relay dispatch leg (a v1-handshaking phone can never open once that branch is
gone). This was the last prerequisite before #913.

## Implementation

- **Phone stays; only the transport flips.** The architecture spec evaluated dropping the phone
  entirely for the two session-lifecycle tests (eviction/respawn), since the eviction trigger
  itself is already phone-free. Rejected: each test's load-bearing assertion is the *inbound wire
  verb → dispatcher reply* round-trip (`send_message`→ack, `create_conversation`→
  `conversation_created`, `register_push_token`→ack), and a phone-free driver would exercise a
  different reactivation entrypoint, forfeiting exactly that coverage.
- **Non-interactive `driveHandshakeToOpenDaemon` for all three**, not the interactive variant. The
  interactive capability gates only the *outbound* structured turn stream — `cmd/pyry/relay.go`'s
  v2 `Handlers` map registers `send_message`/`create_conversation`/`register_push_token`
  unconditionally, so inbound verb dispatch needs no capability. This also matches the original
  tests' semantics (no capabilities advertised).
- **Single-frame reads replace the v1 drain loops.** A non-interactive conn receives no unsolicited
  outbound (pinned by `relay_two_phone_structured_test.go`'s phone-B negative), so each reply is
  the first and only sealed frame. The v1-era `recvEnvelope` spinner-drain (which skipped
  interleaved `message` envelopes racing the ack) is no longer needed — deleted from `harness.go`
  along with its now-unused `fakephone`/`protocol` imports. Its two callers were these tests.
  `mustJSON`, `shortHome`, `readPersistedServerID`, `relayTestLogger` (relocated by #941) keep their
  many v2 callers, untouched.
- **Per-file transport swap** (uniform shape): env `PYRY_MOBILE_V2=0`→`1`, route `/v1/server`→
  `/v2/server`, decode `pairPayload.ServerStaticPubkey` alongside the existing token, replace the
  plaintext hello send/receive with `driveHandshakeToOpenDaemon(t, phone, pubKey, token)`, and
  replace verb send/receive with seal→`sendNoiseMsg`→`decryptInnerEnvelope(readInnerFrame(...))`.
  All non-wire assertions (registry state, PID checks, eviction fields, on-disk persistence, LRU
  victim selection) are unchanged — they never depended on transport.
- **`per_conversation_eviction_test.go`'s helpers rewritten to thread cipher state.**
  `dialHelloPhone` now takes `pubKey []byte` and returns `(*fakephone.Client, *noise.CipherState,
  *noise.CipherState)` (send/recv) instead of just the client; `createConversationViaPhone` takes
  the cipher states and decrypts via `decryptInnerEnvelope` instead of the deleted `recvEnvelope`.
  Kept the `dialHelloPhone` name despite the v1-flavored vocabulary — 2 call sites, minimal churn
  (an open question the spec left to developer judgment).
- **Noise receive-nonce invariant**: every daemon→phone `noise_msg` frame must be decrypted in
  capture order or the next decrypt desyncs. The non-interactive path's one-frame-per-request
  property is what makes a single `decryptInnerEnvelope` per reply safe — no read-and-discard.

## Deviation from spec

`register_push_token`'s original v1 assertion was `ack.ID >= 2` (a `hello_ack` consumed outbound id
1 first). In v2 the hello is embedded in the Noise handshake — no separate envelope consumes an id
— so the register ack is the daemon's **first** stamped reply (id 1). Caught by the test failing on
the first run; fixed to `ack.ID >= 1` (just "is stamped"), matching how the v2 daemon round-trip
tests assert `InReplyTo` rather than the reply-id magnitude. This is a case where a v1-specific wire
detail (an id offset caused by a handshake envelope that no longer exists in v2) doesn't carry over
mechanically — the underlying protocol invariant ("is this a real stamped reply") does.

## Lessons learned

- **A migrated numeric assertion tied to a retired envelope's side effect (like an id offset) needs
  re-deriving from the new protocol's invariant, not copying forward.** The v1 hello/hello_ack
  consumed a wire id before the verb reply; the v2 handshake doesn't touch the application id
  space at all. Spec-writing time can flag "this assertion may need adjustment" but can't always
  predict the exact new value without running the test — worth a fast first-run check on any
  ported magic-number assertion when a protocol layer is swapped out from under it.
- Confirms [[architect-939-splits-relocate-set-vs-noise-migrate-set]]'s split shape: relocate-only
  work (#941) cleanly unblocked the Noise-migrate set (#942) with zero rework needed on the
  relocated helpers.
