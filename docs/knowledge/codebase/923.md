# Ticket #923 — Lift claude descendant-group reaper into `internal/agentrun`

Pure relocation, no behaviour change for the PTY runner. #565 built the claude-descendant-process-group
reaper (`reapDescendantGroups` + `descendantPGIDs`) package-local inside `internal/agentrun/ptyrunner`.
#915 found the stream-json runner has the same parity gap, but `streamrunner`'s package doc forbids
importing a sibling `agentrun` subpackage — so the reaper had to move up to the shared `internal/agentrun`
parent before it could be reused. This ticket is the lift only; wiring `streamrunner` to consume it is
the sibling ticket #924 (blocked-by this one).

## Implementation

- **New `internal/agentrun/reap.go`** — `ReapDescendantGroups(rootPid int, logger *slog.Logger)`,
  exported, colocated beside `ExitErrIsBenign` ([`exitclass.go`](../../../internal/agentrun/exitclass.go)).
  Body is byte-identical to the old `reapDescendantGroups` except the log-prefix neutralisation
  (`ptyrunner:` → `agentrun:`); the three load-bearing guards (`pgid<=1`, `pgid==self`,
  `pgid==rootPid`) and the ESRCH-benign skip are preserved exactly. `descendantPGIDs` (the `ps
  -axo pid=,ppid=,pgid=` enumeration walk) and `reapPSTimeout` (2s) relocate alongside it, staying
  **unexported** — no consumer outside the reaper, so the shared package's API surface isn't widened
  beyond the one entry point.
- **`internal/agentrun/ptyrunner/reap.go` shrinks to two lines of substance**: `killGrace` (a
  distinct SIGTERM-grace const consumed by `runner.go`'s `cmd.WaitDelay` — stays, does not collide
  with `agentrun`) and the `reapDescendantGroupsFn` seam, re-pointed at `agentrun.ReapDescendantGroups`.
  `runner.go` itself is untouched — the seam re-point is entirely inside `reap.go`, so the three
  teardown call sites (operator-cancel `cmd.Cancel`, post-spawn defer, budget-terminate hook) and their
  seam-swap tests (`reapRecorder.record`, `swapReapSeam`) keep working unchanged.
- **Test relocation**: `TestReapDescendantGroups` (4 subtests) and its process-tree fixtures
  (`startReapHelper`, `waitReport`, `processAlive`, `waitGroupGone`, `runReapHelper`,
  `blockUntilKilled`, `spawnGrandchildAndBlock`) move to `internal/agentrun/reap_test.go`, folding into
  the package's existing `exitclass_test.go` `TestMain` dispatch (env keys renamed
  `GO_PTYRUNNER_REAP_*` → `GO_AGENTRUN_REAP_*`; the `GO_PTYRUNNER_HELPER=1` gate dropped since
  `agentrun`'s dispatch keys purely on the mode var being non-empty, matching the `GO_EXITCLASS_HELPER`
  pattern). `ptyrunner/helper_test.go` loses the reap-mode dispatch branch and the three fixture
  functions; the fake-claude modes it still serves (runner tests) are untouched.

## Patterns established

- **Lift-then-wire as two tickets, not one.** When a shared helper needs to move to unblock a second
  consumer, the lift (pure relocation, behaviour-preserving) and the wire (the consumer's actual new
  behaviour) are separate tickets. The lift stands alone as a harmless relocation even if the wire's
  premise (#924: does headless `claude -p` leak groups on SIGTERM?) turns out not to hold.
- **Seam stays at the call site, only its target moves.** `reapDescendantGroupsFn` didn't need to move
  with the function it wraps — re-pointing a package-var seam at a newly-exported symbol from a
  different package is a one-line change that leaves every call site and every seam-swap test
  untouched. Reuse this shape whenever a helper being shared upward already has a local test seam.

## Lessons learned

- go1.26's `gofmt` realigns doc-comment list-item continuations, but this repo (`go.mod` pins
  `go 1.26.2`) ships 26 pre-existing files formatted in the pre-1.26 aligned style, and CI does not gate
  on `gofmt` (only `vet` + `test` + `staticcheck`). Relocated doc comments were preserved verbatim
  rather than reformatted, to match the repo-wide idiom instead of becoming the lone reformatted
  outlier in the diff.
