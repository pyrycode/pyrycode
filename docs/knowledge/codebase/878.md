# Ticket #878 — reconcile queue truth on connect (re-send outstanding `queue_state`)

The **queue half of #829**'s reconcile-on-connect direction (ADR 025), and the twin of
[#877](877.md) (the modal half): when a v2 session reaches `V2StateOpen` with the
`interactive` capability, unicast the current per-conversation `queue_state` for every
non-empty backlog to that connection, so a phone that connects or reconnects **between**
backlog changes sees current queue truth instead of the stale or empty view `queue_state`'s
push-only-on-change design (#722) leaves. `queue_state` is already snapshot-shaped full
state (`queued: []` clears), so the re-send is idempotent by construction — no
stale-replay risk, no "how long was the client away" bookkeeping.

## Implementation

Reuses the #877 connect-time reconcile hook near-mechanically. Three additive changes
across three packages, plus one wiring line — no existing signature changes:

- **`internal/msgqueue.Queue.SnapshotAll() map[string][]QueuedMessage`** — the one
  genuinely new piece (`Snapshot(convID)` reads one named conversation; `convs` is
  private, so enumerating the conversations holding a backlog needed a new read).
  Takes `q.mu` for the whole read (one consistent instant, no TOCTOU between
  enumerate and per-conversation read); for each `convs` entry projects items exactly
  as `Snapshot` does (value-copy, in-flight head included); **skips `len(c.items) ==
  0`** — `shrinkLocked` leaves a drained-but-retained `convQueue` with `items ==
  nil`, so this filter is what makes an empty conversation contribute no map entry
  (AC3). A pure read: mints no id, dequeues nothing.
- **`V2SessionConfig.OutstandingQueues func() []protocol.QueueStatePayload`** — new
  optional seam (nil ⇒ no reconcile, byte-identical to pre-#878), sibling of
  `OutstandingModals`. A closure, not a `*msgqueue.Queue` import: `internal/relay`
  doesn't import `internal/msgqueue`, and `protocol.QueueStatePayload` is already
  imported, so the boundary crosses with no new import and no cycle.
- **`reconcileQueues(ctx, s)`** — structural twin of `reconcileModals`, substituting
  `protocol.TypeQueueState`/`QueueStatePayload` for the modal type: guards on
  `!s.interactive || m.cfg.OutstandingQueues == nil`, snapshots once (empty ⇒
  nothing sent), and per payload marshals + `m.Push`es a
  `protocol.Envelope{ID: 1, Type: TypeQueueState, TS: ts, Payload: payload}` to
  `s.connID` only. `ID: 1` is non-load-bearing (the phone correlates on
  `conversation_id` + `queued_msg_id`, not envelope order); `EventID` stays nil
  (control event, never in the turn-event replay ring). A marshal or `Push` failure
  logs only content-free discriminants (`event`, `conn_id`, `conversation_id` —
  **never** `text`) and continues; `ctx.Err() != nil` returns early.
- **Call site:** one line in `handleNoiseInit`'s success tail, immediately after
  `m.reconcileModals(ctx, s)` and still before the #647 replay hook. Ordering
  relative to `reconcileModals`/`replayMissed` is immaterial to correctness
  (distinct payload types); modal-then-queue documents intent (surface the
  time-sensitive permission prompt ahead of the backlog).
- **`cmd/pyry`** adds an `outstandingQueues(queue *msgqueue.Queue) func() []protocol.QueueStatePayload`
  adapter beside the existing `toQueueStatePayload` mapping in `queue_state_v2.go` —
  composes `SnapshotAll()` with `toQueueStatePayload` per entry, reusing the #722
  wire vocabulary (**no new payload type**). Wires
  `OutstandingQueues: outstandingQueues(queue)` into the `V2SessionConfig` literal in
  `relay.go`, beside `OutstandingModals: modalReg.Snapshot`. `queue` is the same live
  daemon queue the #722 producer snapshots on change and the #723 `QueueRemover`
  mutates — no new threading through `startRelay`/`startRelayV2`.

## Patterns established

- **The #877 reconcile hook is a reusable shape, not a one-off.** The second
  consumer (#878) required zero changes to the hook itself — only a sibling config
  seam, a sibling helper, and a second call-site line. When a new "bring a
  reconnecting phone to current truth for domain Y" need appears, the shape to
  reach for is: (1) a pure-read enumeration/snapshot seam on the domain's own
  package if one doesn't already exist, (2) an optional closure field on
  `V2SessionConfig` typed in terms `internal/relay` already imports, (3) a
  `reconcileY` helper cloned from `reconcileModals`'s control flow (guard →
  snapshot-once → per-payload marshal-and-unicast → content-free error logging),
  (4) one more line in `handleNoiseInit`'s success tail.
- **A `map[string][]T]` enumeration return, not a `[]struct{Key; Items}` slice.**
  `SnapshotAll` returns `map[string][]QueuedMessage]` rather than inventing an
  intermediate struct — consistent with #722's "no intermediate internal
  QueueState model" precedent, and each `queue_state` is self-identifying by
  `conversation_id` on the wire regardless of map iteration order.
- **The drained-but-retained-entry filter is the AC enforcement point, not the call
  site.** `SnapshotAll`'s `len(c.items) == 0` skip is where AC3 ("empty backlog
  produces no `queue_state`") is actually enforced — the reconcile helper and the
  `cmd/pyry` adapter both just pass through whatever `SnapshotAll` returns. Putting
  the filter at the read seam (not the consumer) means every future consumer of
  `SnapshotAll` inherits the same guarantee for free.

## Security review

`security-sensitive` (per the ticket label — dispatches confidential,
phone-originated queued `text` over the internet-exposed v2 relay to a
possibly-untrusted peer, the same audit surface #722's producer and #877's modal
reconcile twin carried the label for). Architect self-review: **PASS**. The two
existing gates carry the load, identical in shape to #877's: Noise_IK
authentication (an unauthenticated/token-rejected peer never reaches
`handleNoiseInit`'s success tail; `forwardEnvelope` re-checks `V2StateOpen` at seal
time) and the `interactive` capability guard (identical to the #722 producer's own
gate). Unicast-to-`s.connID` is strictly narrower than the #722 producer's
broadcast fan-out. Each payload's `conversation_id` and its items come from a
single `SnapshotAll` map entry threaded through `toQueueStatePayload`, so a payload
can never carry conversation A's id with conversation B's text — and `SnapshotAll`
enumerates the daemon's own map keys, never a caller-supplied id. `SnapshotAll`
mints no id and dequeues nothing, so the `queued_msg_id` space, the FIFO, and the
per-conversation `MaxQueuedPerConversation` cap (#869) are all untouched by a
reconcile; re-sending the same snapshot grants no new capability (idempotent
full-state). Logging is content-free (`event`/`conn_id`/`conversation_id` only —
**never** `text`, the payload bytes, or a raw `err`, since `encoding/json` could
quote the untrusted `text` into its error). Snapshot→deliver is a benign,
self-healing race: a conversation may change in the window between `SnapshotAll()`
and delivery, but the next #722 on-change re-send corrects it, and the
reset-on-reconnect client contract makes a later absent snapshot mean empty.

## Testing

`internal/msgqueue/queue_test.go` (new table): two conversations each with a
backlog → both keys present, each FIFO-correct; a conversation drained to empty →
omitted (AC3), paired with a non-empty conversation so the map isn't trivially
empty; fresh queue → empty non-nil map; in-flight head included; returned slices
are value copies (mutating one doesn't affect a later `Snapshot`/`SnapshotAll`);
`-race` against concurrent `Enqueue`/drain on other conversations.

`internal/relay/v2session_queuereconcile_test.go` (new, clones
`v2session_modalreconcile_test.go`): one non-empty conversation → one unicast
`queue_state` (AC1); two non-empty conversations → two `queue_state`, keyed by
`conversation_id`, order-independent (AC1); unicast-only — opening a second
interactive conn (B) delivers only to B, not to an already-open conn A (AC2);
non-interactive open → zero (AC4); empty backlog → nothing for that conversation
(AC3); nil seam → inert, session stays `V2StateOpen` (foreground/unwired
byte-stability); content-free logging on the marshal-error/push-drop branches — no
`text` substring in any emitted log record (AC5).

`cmd/pyry/queue_state_v2_test.go` (extended): the `outstandingQueues` adapter over
a real `msgqueue.New` plus a couple of `Enqueue`s across two conversations (one
drained empty) returns one `QueueStatePayload` per non-empty conversation with the
mapped items, and none for the empty one.

`go test -race ./internal/msgqueue/... ./internal/relay/... ./cmd/pyry/...` and
`go vet ./...` pass.

## Out of scope (named)

- **Delivery ordering vs. #777 replay for a reconnecting client advertising
  `last_event_id`:** the reconcile `queue_state` is held in `m.queues` behind the
  replay tail and drains after it, same as #877's modal reconcile. Acceptable
  (replayed history first, then current backlog); jumping the tail is a future
  follow-up.
- **#829's own disposition** (rescope as the end-to-end acceptance slice on the
  #877 umbrella, or supersede) is an operator decision, not resolved by this
  ticket — both halves (#877 modal, #878 queue) have now landed.
- **Mobile-client match-and-replace behaviour** on receiving a re-sent
  `conversation_id`/`queued_msg_id` set is a separate client-side contract ticket
  (filed alongside #878); no daemon change needed beyond the existing `queue_state`
  vocabulary.
