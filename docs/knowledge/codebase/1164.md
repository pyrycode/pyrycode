# Ticket #1164 — Bootstrap resumes its pinned `--session-id` when the transcript already exists

Split from #1163. Root fix for the bootstrap crash-loop: #839 made the PTY
supervisor spawn `--session-id <pinned-id>` on **every** spawn, but claude
2.1.199 refuses `--session-id` when `<id>.jsonl` already exists ("Session ID
… is already in use", ~220ms exit). On a hard daemon restart the transcript
survives, so every backoff respawn collided identically — the daemon stayed
up but never brought up a working bootstrap session. `internal/streamsup`
doesn't have this bug (it already had a `firstRun`-gated `--resume` branch);
the PTY supervisor's `buildClaudeArgs` had no `--resume` branch at all, so it
could never escape. Not `security-sensitive` (narrows the trust surface —
adds a by-id stat, no dir scan). See
[docs/specs/architecture/1164-bootstrap-resume-existing-transcript.md](../../specs/architecture/1164-bootstrap-resume-existing-transcript.md)
and [ADR 032](../decisions/032-bootstrap-resume-per-spawn-existence-probe.md)
for the resume-vs-rotate decision this ticket made.

## Implementation

- **`internal/supervisor/supervisor.go`** — `Config.ResolveSessionID` widened
  from `func() string` to `func() (id string, resume bool)`. `buildClaudeArgs`
  gained a fifth parameter `resume bool`: when `sessionID != ""`, `resume=true`
  emits `--resume <id>`, `resume=false` emits `--session-id <id>` (both still
  suppress `--continue`); the `sessionID == ""` branch (`--continue` iff
  `!firstRun && continueLast`) is untouched and `resume` is inert there. The
  `Run` call site reads both return values in one call and threads them
  through — same-call atomicity means the `StatByID` probe (below) always
  targets the id that's about to be spawned, so a `/clear` rotation racing a
  spawn can't skew id and resume-decision apart.
- **`internal/sessions/pool.go`** — the bootstrap `supCfg.ResolveSessionID`
  closure now probes `transcript.StatByID(cfg.ClaudeSessionsDir, id)` each
  call: transcript exists → `(id, true)` → `--resume`; absent, empty id, or
  `ClaudeSessionsDir == ""` → `(id, false)` → `--session-id` (byte-identical
  to #839's create path). The id-resolving closure was factored out as a
  named `resolveID func() string` so both `ResolveSessionID` and the
  growth-confirm resolver (`newProbePreferredTranscriptResolver`'s 4th arg,
  previously fed `supCfg.ResolveSessionID` directly) share one id source
  under the new two-return signature.
- **The rule is per-spawn, not a one-shot decision in `New()`.** A decision
  fixed at construction is insufficient: cold start has no transcript yet
  (`--session-id`), but the moment the first child creates `<id>.jsonl`, an
  in-process respawn with a fixed decision would still collide. Because
  `ResolveSessionID` already runs fresh every spawn (#839's cadence), the
  probe rides that existing loop with no new seam.
- **Resume, not rotate.** The architect's explicit decision — see ADR 032.
  Resume preserves the pinned bootstrap's idle conversation (the entire
  point of #839's pinning); rotate would drop it every restart and defeat
  pinning's purpose. `#1165` (independent, not blocked-by/blocking) is the
  generic N-fast-crash-self-heal safety net for the residual case where
  `--resume` itself fails (corrupt/unresumable transcript) — different
  fabric (rotate on persistent failure vs. resume on transcript-exists), so
  the two compose without overlap.

## Tests

- `internal/supervisor/args_test.go` — extended `buildClaudeArgs` table:
  `resume=true` → `--resume <id>`, never `--session-id`/`--continue`, even
  with `firstRun=false, continueLast=true`; `resume=false` → `--session-id
  <id>`, never `--resume`/`--continue`; `sessionID==""` rows unchanged for
  both `resume` values; no-mutation-of-input-slice assertion extended.
- `internal/supervisor/restart_test.go` — `TestSupervisor_Run_IgnoresSessionIDField`'s
  closure updated to the two-return signature (`return resolvedID, false`);
  new `ResumeBitEmitsResumeFlag`-style test proves a `(id, true)` provider
  emits `--resume <id>` end-to-end and never `--session-id`.
- `internal/sessions/pool_bootstrap_resume_test.go` (new) — drives
  `Pool.New` directly via the real-`/bin/sh` `helperPoolArgvRecorder` seam
  (no live claude), `ClaudeSessionsDir` pointed at a temp dir:
  - **AC-1** pre-create `<bootstrapID>.jsonl` → argv carries `--resume
    <bootstrapID>`, never `--session-id`.
  - **AC-2** no transcript → argv carries `--session-id <bootstrapID>`,
    never `--resume` (byte-identical to #839).
  - **AC-3 isolation** `<bootstrapID>.jsonl` absent but a **foreign**
    `<other-uuid>.jsonl` present (even newer) → argv still carries
    `--session-id <bootstrapID>` — the by-id probe ignores foreign files, no
    dir scan, no adoption (the #839 isolation guarantee holds).
- `go test -race ./internal/supervisor/ ./internal/sessions/`, `go vet
  ./...`, real-claude e2e all green (see code-review PR comment on #1166).

## Patterns established

- **Per-spawn existence probe, not a construction-time or `firstRun`-gated
  decision, when a spawn flag depends on mutable on-disk state.** The
  `streamsup` sibling's `firstRun` heuristic wastes exactly one crash on
  daemon restart before self-healing; the per-spawn `StatByID` rule handles
  cold-start, in-process-respawn, and daemon-restart uniformly with no
  bookkeeping and no wasted crash. Reusable whenever a provider closure
  already runs every spawn (#839's cadence) and the flag-shape decision
  needs the current on-disk truth.
- **Widen a provider's return tuple instead of adding a second call**, when
  two derived facts (id, resume-or-not) must never skew relative to each
  other under concurrent mutation (here: a `/clear` rotating `p.bootstrap`
  mid-loop). One call, one snapshot, no TOCTOU between two separate reads.
