# Ticket #1331 — Attribute the stream stdin tee per child so M4 can name the receiving child

`TestRelayV2_StreamNewSessionRotatesAndRestartsFresh`'s M4 asserted "the fresh
post-rotation child received turn #2" by polling one shared stdin log
(`PYRY_FAKE_CLAUDE_STDIN_LOG`) for a needle. Both the bootstrap child and the fresh
post-rotation child inherit the same env var from the daemon's process env and both
tee into it with `O_APPEND`, so a needle there proved only that *some* child received
the turn, never which one. When the outgoing child got it instead, M4 went green on
the wrong evidence and the run then surfaced as an AC-1 "broken instrument" failure
whose two named readings were both wrong. This is the e2e-evidence half of a flake
whose production half was #1330 (closed `dac5779`, prior to this ticket); this ticket
does not fix a race, it makes the test able to see one.

## Implementation

- **`internal/e2e/internal/fakeclaude/main.go`** — `PYRY_FAKE_CLAUDE_STDIN_LOG` is
  re-interpreted in stream mode only: its value is now a path *stem*, and each child
  appends to `<stem>.<the session id its own argv was pinned to>` instead of the bare
  stem. New pure helper `streamStdinLogPath(stem, args []string) string` derives the
  suffix from `argvSessionID(args)` (the existing helper that reads the value after
  the last `--session-id`/`--resume`), falling back to the sentinel stem
  `unattributed` when argv carries none — unreachable via `streamsup.buildArgs`
  today (every spawn ends in a session-id flag), so it's a rendering choice, not a
  defense. `argvSessionID`'s stem guard (rejects `/`, `\`, `.`) is reused, not
  re-implemented, which is what makes splicing the raw argv value into a path safe.
  Same shape #1195 already used for the per-child JSONL trigger path — key on the
  spawn's own session id, not pid or spawn ordinal, so a same-session crash-respawn
  (`--resume <sameID>`) still appends to one file. The PTY tee (`startStdinReader`)
  and its 7+ consumers are untouched — the two modes are mutually exclusive at
  `main()`'s first branch.
- **`internal/e2e/relay_v2_stream_new_session_test.go`** — three new fatal-free
  helpers (no `*testing.T`, no `t.Fatal*`, since M4's failure record calls them while
  building its message): `childStdinLog(stem, sessionID)` duplicates the writer-side
  derivation (fakeclaude is `package main`, unimportable); `childReceivedTurn(stem,
  sessionID, needle)` reads only one child's log; `childStdinLogs(stem)` enumerates
  every per-child log via `os.ReadDir` + a prefix filter (not `filepath.Glob` — a
  stem containing a glob metacharacter would make `ErrBadPattern` read as "no
  children"). M4 now calls `childReceivedTurn(stem, post.ID, needle)`, reading only
  the post-rotation child's file — a turn delivered solely to the outgoing child now
  fails M4. M4's failure record renders a per-child byte-count inventory
  (`childrenWith`) instead of one number, naming the wrong-child reading explicitly.
  AC-1's message gains a third reading — "the fresh child received turn #2 but never
  echoed it" — worded to exclude "never received the turn", which M4's new assertion
  now forecloses before AC-1 can even fire (the guard only runs on a green M4). M5's
  `/clear` check and its non-vacuity guard now span every per-child log via
  `childStdinLogs`, so an empty inventory fails non-vacuity and a `/clear` typed at
  the *outgoing* child still fails M5.
- **`internal/e2e/internal/fakeclaude/stdin_log_path_test.go`** (new) —
  `TestStreamStdinLogPath`, untagged table test mirroring `argv_session_id_test.go`'s
  idiom: `--session-id`, `--resume`, both-present (last wins), no flag
  (`.unattributed`), a guard-rejected value (`.unattributed`, with the directory
  invariant checked separately), and a stem that itself contains a `.` (harmless —
  only the final component is the id).
- **`TestChildStdinLogAttribution`** (in `relay_v2_stream_new_session_test.go`,
  beside `TestDaemonLogWindow`) — AC-3's proof. Fixture files are built with a
  hand-written literal path shape (`filepath.Join(dir, "fakeclaude-stdin."+id)`),
  never through `childStdinLog`, so the fixture can't pass under any derivation by
  construction. Rows cover: only-outgoing-has-the-needle (the row that's red under
  the old shared-file instrument, green under the new one), a reachability control
  (both children have it), post-rotation file present-but-empty vs. absent (distinct
  readings), and the M5 rows (`/clear` in outgoing only, in post-rotation only,
  neither, non-vacuity with only outgoing's bytes, empty map, unrelated file in the
  same directory not collected).
- Trivial line-number comment updates that shifted because the test file grew ~593
  lines: `internal/streamsup/runner.go` (two `relay_v2_stream_new_session_test.go:NNN`
  cites) and `internal/e2e/relay_v2_perconv_interrupt_test.go` (one
  `fakeclaude/main.go:NNN` cite). No behavioral change in either file.

## Patterns established

- **Key a per-child artifact on the session id, not pid or spawn ordinal**, when the
  claim being tested is about a session ("the child spawned with `--session-id
  post.ID`"). Same move as #1195's per-child JSONL trigger; now applied to a second
  artifact (the stdin tee).
- **Per-child files over interleaved markers in one shared file**, when the
  instrument's checks are contiguous-substring checks. `io.TeeReader` writes exactly
  the bytes each `Read` returns, so one turn's envelope can span a read boundary — an
  inline marker could split a needle across it. Per-file writers (one writer per
  file, by construction) make every needle contiguous without adding synchronization.
- **A duplicated derivation across an import boundary is sound if drift is loud, not
  silent.** `childStdinLog` can't import `streamStdinLogPath` (fakeclaude is
  `package main`), so it re-implements the same three-line derivation. This is safe
  specifically because any writer/reader disagreement — including both sides
  silently falling back to `.unattributed` — leaves the post-rotation id's file
  absent, which fails M4, and leaves `childStdinLogs` empty, which fails M5's
  non-vacuity. There is no path where the derivations drift and the suite stays
  green.
- **A sentinel fallback for an unreachable-today branch should be legible, not
  merely present.** `unattributed` was chosen partly because it contains no hex-only
  characters valid across the full UUID alphabet by accident — it's spelled to be
  impossible to collide with a minted session id, not just unlikely to.
- **Narrowing one assertion can silently narrow a sibling's guard too — check what
  discharges the sibling before narrowing.** M5's non-vacuity guard is discharged by
  turn #1's needle, which lands in the *outgoing* child's log. Narrowing M5 the same
  way M4 was narrowed (post-rotation child only) would have made non-vacuity depend
  on turn #2 — the very thing a red M4 might mean is missing. `childrenWith` serves
  both M5 checks so both span every child by construction, keeping non-vacuity
  independent of what M4 finds.

## Lessons learned

From [PR #1360](https://github.com/pyrycode/pyrycode/pull/1360)'s own "Lessons
learned" section:

> A per-child fixture proves attribution but cannot prove writer/reader agreement.
> Agreement is proven only by a live green M4 plus M5's non-vacuity — a drift is
> loud (M4 red), never silently green. Stated in the fixture test's doc comment so a
> reader cannot over-read it.
>
> Narrowing one assertion can vacate a sibling's guard. M5's non-vacuity is
> discharged by turn #1's needle, which lands in the outgoing child's log — so
> narrowing M5 alongside M4 would have made the guard depend on turn #2, the very
> thing M4 may have just found missing.
>
> Enumerating evidence needs the same sentinel doctrine as rendering it.
> `childStdinLogs` uses `os.ReadDir` + a prefix filter rather than `filepath.Glob`
> (a metacharacter in the stem would make `ErrBadPattern` read as "no children"),
> and the inventory renders "failed to enumerate" and "enumerated, found none" as
> distinct sentinels — the same rule `daemonLogWindow` already follows.

**Code review ([PR #1360 review](https://github.com/pyrycode/pyrycode/pull/1360),
decision PASS, 3 NIT, no blockers)** verified AC-3's two claimed mutations
independently via `go test -overlay` (reverting the reader to the retired
"did-some-child-receive-it" semantics, and splicing a raw argv value past the stem
guard — both reproduced RED), confirmed live writer/reader agreement on a targeted
run (M4 green and attributed, M5 reporting 2 per-child logs), and hand-verified the
cite sweep (3 inbound Go cites, 3 bare self-cites in the e2e file). None of the NITs
required a follow-up ticket:

1. **[NIT, addressed here]** The PR's own "Lessons learned" mis-attributed two stale
   `fakeclaude-binary.md` cites (`main.go:149` and `main.go:129`) as "+8/+55 this PR
   shifts". Both actually name the same `logPath != "" || tui` gate, now at
   `main.go:692` — ~563 lines of *pre-existing* staleness (gap magnitude vastly
   exceeds this PR's largest shift), unrelated to this change. Both re-derived and
   fixed in this documentation pass (see `features/fakeclaude-binary.md`).
2. **[NIT, not fixed]** `TestChildStdinLogAttribution` omits `t.Parallel()`, unlike
   its sibling `TestStreamStdinLogPath`. Each subtest uses its own `t.TempDir()`, so
   it would be safe to add; left as a follow-up-if-touched, not worth a ticket on
   its own.
3. **[NIT, scope calibration only]** ~721 code insertions vs. the spec's ~400
   projection / ~600 soft limit. Code review judged the overage fully accounted for
   by the mandated rationale-comment density on three fatal-free helpers plus AC-3's
   fixture — not scope creep.

**`make e2e-realclaude` SKIPPED in both the PR's and the review's environment** — no
Claude login available. No `needs-real-claude` label warranted: every AC here
concerns fakeclaude's stdin tee and the fake-daemon e2e; nothing in the ticket's
acceptance depends on a live claude.
