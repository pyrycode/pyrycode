# Ticket #747 — ACP `initialize` + `authenticate` handshake declaring minimal client capabilities

ACP opens every connection with an `initialize` request that negotiates the
protocol version and exchanges capabilities, optionally followed by
`authenticate`. [#755/#756](756.md) landed the JSON-RPC transport + the `pyry acp`
subcommand that serves it, registering **no** handlers; [#761](761.md)/[#762](762.md)
added the `session/*` verbs. This ticket registers the first two **handshake**
methods so a host can complete the opening exchange before opening a session.

**Divergence 5 is the point.** pyry runs claude on the daemon's own machine, with
its own disk and terminal, so it never asks the host to read/write files (`fs/*`)
or create/run terminals (`terminal/*`). The handshake declares pyry needs no such
client capabilities and advertises only the agent capabilities the epic has
actually delivered.

Epic [#600](https://github.com/pyrycode/pyrycode/issues/600) — `pyry acp` as a
thin adapter over the shared remote-head core. Sub-issue of #600, blocked-by
(now-closed) #756. Spec:
[`specs/architecture/747-acp-initialize-handshake.md`](../../specs/architecture/747-acp-initialize-handshake.md).
**Not security-sensitive** — local trusted-host stdio surface (the peer is a
co-located, user-launched host like Zed/Claudian, LSP-style); the `authenticate`
handler is a credential-free no-op (no token/secret to audit) and the capability
declaration only *minimizes* (adds no gate, expands no control). The epic's
security boundary lives on the mobile wire and in the permission proxy (#752).

## Implementation

**1 new production file (`cmd/pyry/acp_handshake.go`, package `main`, +110
lines), 1 one-line edit (`cmd/pyry/acp.go`), 0 changes to `internal/acp`.** Both
handlers are pure functions of their `params` — no goroutines, no shared state,
no pool. The transport dispatches them inline on its single read-loop goroutine;
neither blocks (no I/O, no claude, no outbound `Call`).

### Handlers + wire types live in `package main`, not `internal/acp`

`internal/acp` is **deliberately method-agnostic** — it "owns framing, ids, and
error codes; it knows nothing about any concrete ACP method." Putting the
`initialize`/`authenticate` wire types or bodies inside it would violate that
boundary, and two tiny handlers do not justify a new package (simplicity-first; a
future ticket can extract one when the handler count warrants it). So the
constant, the (all-unexported) wire structs, the two handler funcs, and the
`registerHandshake` helper live in a new `cmd/pyry/acp_handshake.go`.

### `SupportedProtocolVersion = 1`, returned unconditionally

ACP `protocolVersion` is an integer (u16 on the wire); v1 is current. The
`initialize` handler returns the constant **unconditionally** — with exactly one
supported version there is nothing to negotiate, and every real client advertises
`>= 1`, so returning `1` is always a valid (`<=` client) response. A
`min(client, agent)` clamp lands only when pyry speaks a second version
(evidence-based: no second version exists to clamp against). Reconcile the literal
with the ACP-mapping ADR (#745, still OPEN) when it merges.

### Divergence 5 is structural, not a field

ACP's `InitializeResponse` has **no** "agent requires client capability X" field —
the agent never declares required client capabilities; it simply uses whatever the
client offered, or doesn't. So "pyry requires no `fs/*`/`terminal/*`" is expressed
two ways, both structural:

1. `initializeResult` carries **only** `protocolVersion` + `agentCapabilities` +
   `authMethods` — there is nowhere in it to request a client capability.
2. pyry issues no `fs/*` or `terminal/*` outbound `Call`s (nothing in this ticket,
   nothing in the epic's plan for the local-disk runtime).

The host's `clientCapabilities` (fs/terminal) are **intentionally not modelled** in
`initializeParams` — an unmodelled field is silently dropped on `json.Unmarshal`,
which is exactly divergence 5's "tolerate a host that offers them and never use
them." `initializeParams` decodes only `protocolVersion`, and even that serves
purely as a **shape gate**: a params value that is not a JSON object (e.g. an
array) fails to unmarshal and is rejected with `CodeInvalidParams`; empty/absent
params is tolerated (zero-value defaults).

### Minimal-safe agent capabilities (all false today)

`agentCapabilities` advertises only the **optional** capabilities whose backing
methods this epic has delivered. Core methods (`session/new`, `session/prompt`) are
baseline-mandatory and are **not** capability-gated. Everything is false:

- `loadSession: false` — see the coordination point below.
- `promptCapabilities.{image, audio, embeddedContext}: false` — pyry drives a
  text-only interactive claude turn today; rich prompt content is #748.
- `mcpCapabilities` / `set_mode` / `set_config_option` are **omitted** entirely —
  their backing methods (#748/#753) have not landed. The delivering ticket amends
  `agentCapabilities` when it does.

`authMethods` is a non-nil `[]authMethod{}` so it marshals to `[]`, not `null`
(pinned by a test). The `authMethod` struct is kept — none advertised today — so a
future real auth method has a shape to populate.

### `authenticate` — deliberate no-op stub

Local `pyry acp` speaks to a co-located, user-launched host over stdio; there is no
token, secret, or credential in play, so `authenticateHandler` ignores params and
returns `authenticateResult{}` → `{}` on the wire (the spec-compliant
all-optional-fields `AuthenticateResponse`, chosen over `null` for
forward-compatibility). A code comment documents the deliberate stub (AC-3).

### Registration

`registerHandshake(t)` calls `t.Register("initialize", …)` +
`t.Register("authenticate", …)`. It is invoked once at the top of
`serveACPWithPool`'s `register` closure, alongside the `session/*` handlers, so the
composition root reads as a list of capability registrations. Both handlers are
stateless, so `registerHandshake` takes no pool.

## Patterns established

- **Handshake handlers belong in `package main`, keeping `internal/acp`
  method-agnostic.** The transport package knows framing/ids/error-codes only;
  concrete ACP methods and their wire types register against it from `cmd/pyry`.
  Two tiny handlers don't justify a package — extract one only when the count
  warrants it.
- **Divergence 5 is a structural property, not a wire field.** There is no ACP
  field for "agent requires client capability X"; the guarantee holds because the
  result has nowhere to request one *and* pyry issues no `fs/*`/`terminal/*`
  `Call`s. Tested by asserting the marshalled result contains none of `"fs"`,
  `"terminal"`, `"readTextFile"`, `"writeTextFile"` — true by construction.
- **ACP capabilities are feature flags, not a method list — advertise only what's
  delivered.** Baseline-mandatory methods (`session/new`, `session/prompt`) are
  never capability-gated; an *optional* flag is turned on only when its backing
  ticket has landed the full contract. If it hasn't, advertise the minimal safe
  set and let the delivering ticket amend the handshake.
- **`loadSession` stays `false` even though a `session/load` handler is already
  registered (from #762) — deliberate under-advertisement.** ACP's `loadSession`
  capability promises the agent **replays conversation history via `session/update`
  on load**. That replay is not wired (Phase 2 structured-event bridge / #596), so
  #762's `session/load` is a deliberately partial, within-process `Lookup`+`Activate`
  — not the full ACP `loadSession` contract. Advertising `true` here would
  over-promise a replay pyry doesn't perform. **Coordination point: #748 must flip
  `loadSession` to `true` when it lands the replay semantics.**
- **Stateless handlers register without a pool — the structural proof of AC-1.**
  Registering `initialize`/`authenticate` with no pool (the test harness does
  exactly this) *is* the demonstration that they succeed before any session exists
  and hold no session state.
- **No version negotiation until a second version exists.** Returning the single
  supported version unconditionally is always valid; the `min(client, agent)` clamp
  is deferred as an open question, not a code TODO (evidence-based — nothing to
  clamp against yet).

## Code review

**PASS** — merged in [PR #766](https://github.com/pyrycode/pyrycode/pull/766). No
MUST/SHOULD-FIX findings. `make check` green (`go vet`, `go test -race`,
staticcheck, substrate-guard); real-claude e2e green
(`internal/e2e/realclaude` 154s). Blast radius clean (codegraph): `initialize`/
`authenticate` register exactly once, no duplicate-`Register` panic; `serveACP`'s
signature is unchanged (every other caller passes `nil` register, so the
`TestServeACP_*` EOF/blank-line tests stay green).

The reviewer verified the **`loadSession: false` under-advertisement is correct and
intentional** (not a defect): #762's `session/load` is a partial within-process
resume, not the full ACP replay contract, so advertising `false` is honest — and
flagged it as the coordination point above for #748.

## Lessons learned

- **Reconcile the registration seam against live code, not the spec's line
  numbers.** The architect spec was written pre-#761/#762 and put the seam in
  `serveACP` with a `// registers NO handlers` comment to reword. By the time this
  landed, the composition root had moved into `serveACPWithPool`'s `register`
  closure and `serveACP` had gained a `register func(*acp.Transport)` param. The
  developer wired `registerHandshake` into the closure instead; the spec's "reword
  the stale comment / EOF-test messages" step no longer applied (the
  `TestServeACP_*` tests pass a `nil` register, so "no handlers registered" stayed
  accurate). A stale spec seam is expected on a fast-moving epic branch — trust the
  live seam.

## Testing

All new, appended to `cmd/pyry/acp_test.go` — transport-driven (frames fed
*through* `serveACP`, never calling handler funcs directly), table-driven,
`t.Parallel()`, stdlib-only.

- **`driveHandshake` harness** — feeds one JSON-RPC request through `serveACP` with
  **only** `registerHandshake` (no pool) and runs to EOF, returning the parsed reply
  + the raw response line. Registering no pool is the structural proof of AC-1's
  "holds no session state, succeeds before any session exists."
- **`TestACP_Initialize_Result`** (AC-1, AC-2a, AC-2b) — the host *offers*
  `fs`+`terminal`; the reply echoes id `1`, `protocolVersion == 1`,
  `loadSession == false`, all `promptCapabilities` false, `authMethods` is `[]`
  (not `null`), and the raw result contains none of `"fs"`/`"terminal"`/
  `"readTextFile"`/`"writeTextFile"` (divergence 5).
- **`TestACP_Initialize_ParamsTolerance`** — table: absent params / empty object /
  only-client-capabilities all succeed with the same capability set; array params →
  `CodeInvalidParams`.
- **`TestACP_Authenticate_Success`** (AC-3) — success frame, id `2` echoed, result
  is exactly `{}` (empty object, no `error` member).

## Out of scope (deferred)

- **No claude, no session** — stateless handshake only; session lifecycle is
  [#748](https://github.com/pyrycode/pyrycode/issues/748).
- **`loadSession` flag flip → #748** — when it lands the `session/update` replay
  semantics, it flips `loadSession` to `true` (see the coordination point above).
- **`mcpCapabilities` / `set_mode` / `set_config_option` advertisement** — backing
  methods (#748 / [#753](https://github.com/pyrycode/pyrycode/issues/753)) haven't
  landed; the delivering ticket amends `agentCapabilities`.
- **Version-negotiation clamp** — deferred until pyry speaks a second protocol
  version; then the handler returns `min(requested, SupportedProtocolVersion)` and
  gains a downgrade test.
- **Real authentication** — the epic's security boundary is the mobile wire and the
  permission proxy ([#752](https://github.com/pyrycode/pyrycode/issues/752)), not
  this handshake. `authMethods` populates (and `authenticate` stops being a no-op)
  only if a later ticket adds a real method.
- **Protocol-version literal reconciliation** — pinned to `1` from the vault interim
  reference; reconcile with ADR [#745](https://github.com/pyrycode/pyrycode/issues/745)
  (still OPEN) when it merges. Low risk — v1 is the current ACP wire version.
