# Ticket #1506 — Correct `emitRekeyRequest`'s documented recovery contract on seal/marshal failure

Comment-only correction, no production behaviour change. `emitRekeyRequest`'s doc comment promised "the next 1-hour cadence will attempt another emit" after a seal or marshal failure; none of the four failure branches arms anything, so that clause was false — filed from the 2026-08-16 full-repo code review as claim/code drift, not a live bug.

## Implementation

- **What was actually wrong.** All four failure `return`s in `internal/relay/v2session_rekey.go` happen before `s.awaitingRekeyReply = true`, so no reply window ticks and nothing re-arms `s.rekeyTimer`. On the scheduled path the timer is left pointing at the **spent one-shot that delivered the wake** — non-nil, fired, inert, not nil. On the manual path it's worse: `handleManualRekey` stops and **nils** `s.rekeyTimer` before calling in, so a failed manual emit leaves the pointer actually nil. The filed ticket body scoped the finding to the scheduled path only; the corrected comment covers both, and is explicit that the scheduled case is non-nil-but-inert (not "nil-equivalent" — a future re-arm guarded on `s.rekeyTimer == nil` would fire on the manual path and never on the scheduled one).
- **Why the code stays as-is.** The trigger is unreachable: `s.send.Encrypt` forwards flynn/noise's `Encrypt`, whose only two error returns are `ErrMaxNonce` (send-nonce exhaustion) and `ErrCipherSuiteCopied` (set only by `(*CipherState).Cipher()`, which nothing in this repo calls). `docs/protocol-mobile.md`'s "Out of scope (v2)" section already rules the 2⁶⁴ nonce counter out as a practical limit, and the three marshal branches encode closed structs that cannot fail. A re-arm would need a signature change on `emitRekeyRequest` (it returns nothing today) across both call sites, or branching the primitive on which caller it serves — and there is no way to test it: `internal/noise.CipherState` wraps its flynn state with no nonce setter, and adding one to test dead code is a footgun (a backwards set is nonce reuse under a live key). Evidence-Based Fix Selection: the failure mode has not been observed and the spec declares the state cannot arise, so the fix documents the residual instead of defending against it.
- **What the new comment asserts.** Seal failure named as `ErrMaxNonce`-only and still "realistically unreachable"; on failure the frame drops, a WARN fires, the conn stays open in `V2StateOpen` (unchanged); scheduled path — no further scheduled emit is armed, `s.rekeyTimer` non-nil/fired/inert; manual path — `handleManualRekey` already nil'd `s.rekeyTimer`, so the operator's `pyry rekey` re-run is a recovery step, not a cadence fallback; recovery either way is a phone-initiated re-key (`handleRekeyInit` → `rekeyComplete`), plus the idle sweep, which reaps a session that goes quiet but does **not** bound the key lifetime of one that stays busy; the paragraph is scoped to the four failure branches — the `awaitingRekeyReply` early-skip return is explicitly *not* a cadence-death path, since it's bounded by the in-flight `rekeyReplyTimer`.
- **`Rekey`'s doc comment** picked up one added clause (permitted, not required, by the spec) noting that its "documented posture" forward-reference now also means "and a session with no scheduled cadence until a phone-initiated re-key."
- **Verification.** Diff-hygiene gate: every added/removed line in `git diff origin/main -- '*.go'`, leading whitespace trimmed, starts with `//` — 0 non-comment lines. `go test -race ./internal/relay/`, `go vet ./...`, `make cite-guard`, `go build ./cmd/pyry` all pass. No new tests — nothing to assert; the branches are unreachable by construction, per § Design decision above.

Files touched: `internal/relay/v2session_rekey.go` (comment only), `docs/specs/architecture/1506-rekey-emit-failure-cadence-comment.md` (spec).

## Patterns established

- **A `cite-guard`-governed doc comment names symbols, not line numbers, and cites external docs by `§` section.** The architecture doc for this ticket flagged that the ticket body's own `internal/relay/v2session.go:553`/`:564` citations had already rotted in the ~3 days between filing and refinement — substance correct, coordinates stale. The corrected comment cites `docs/protocol-mobile.md` by section (matching the file's existing two references), never by line, and names `ErrMaxNonce` rather than restating flynn's `MaxNonce = math.MaxUint64 - 1` arithmetic, so nothing in the comment can rot the way the ticket's own cross-file line numbers did.
- **A rejected testing seam is itself the security-positive outcome.** The security review's one finding (spec-relevant residual: unbounded key lifetime *if* the unreachable trigger became reachable) resolves as "accepted and now documented," not "fixed" — and the review calls out that *not* adding a nonce setter to `internal/noise.CipherState` (considered and rejected as a test seam) is the correct call, since a backwards nonce set is nonce reuse under a live key. Documenting a residual precisely, without building an untestable defense or a footgun seam to test it, is the accepted posture here — same shape as #912's precondition-on-primitive-not-enforced-in-it pattern (see [`codebase/912.md`](912.md) § Patterns established).

## Lessons learned

(From the PR body's own lessons section.)

- The idle sweep is easy to overclaim in a comment about key lifetime: `idleTimer` re-arms on every inbound frame, so it bounds a session that goes *quiet*, not the key lifetime of one that stays busy. A comment saying "the idle sweep bounds it anyway" would hide exactly the residual this ticket documents.
- A fired `*time.Timer` is a non-nil, inert pointer. Documenting the failure path as "no timer" would invite a future re-arm behind `if s.rekeyTimer == nil`, which fires on the manual path and never on the scheduled one — the comment has to name the distinction, not just the outcome.

## Security review

Architect self-review, verdict **PASS**. One finding, classified SHOULD FIX / addressed-in-spec (no MUST FIX): the four failure branches silently end the 1-hour rotation mandated by `docs/protocol-mobile.md` § Re-key for the life of an actively-used session, a real forward-secrecy weakening *if* reachable — it isn't, since the sole trigger (`ErrMaxNonce`) is nonce exhaustion, which the same spec rules out as impractical. Rejecting a nonce-setter test seam on `internal/noise.CipherState` is called out as the security-positive choice, not a gap. Full text in the architecture doc's § Security review.
