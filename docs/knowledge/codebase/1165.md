# Ticket #1165 — Supervisor self-heals on a deterministic fast-crashing bootstrap child

Split from #1163. The bootstrap supervisor's backoff loop retries forever on
a crashing child — the right default for a *service* supervisor recovering
from a transient outage, but a *deterministic* fast-crash (e.g. #1163's "id
already in use" collision) never recovers on its own and silently wedges the
daemon with no working bootstrap session. The sibling ticket #1164 (merged,
PR #1166) root-fixes that *specific trigger* with a deterministic *startup*
resolution (resume when the pinned id's transcript already exists). #1165 is
the generic *runtime* backstop: any future deterministic fast-crash cause,
whatever it is, self-heals by rotating off the wedged id instead of looping
forever. Realizes the long-tracked "Backoff cooldown/bail-out" open
follow-up. Not `security-sensitive` (local daemon lifecycle; the rotated id
is a UUIDv4, not key material). See
[docs/specs/architecture/1165-supervisor-fast-crash-self-heal.md](../../specs/architecture/1165-supervisor-fast-crash-self-heal.md)
and [ADR 033](../decisions/033-supervisor-self-heal-dedicated-rotation-no-skip-set.md)
for the "dedicated primitive, no skip-set" decision.

## Implementation

- **`internal/supervisor/supervisor.go`** — three additive `Config` fields:
  `FastCrashWindow time.Duration` (0 → `defaultFastCrashWindow` = 2s),
  `FastCrashThreshold int` (0 → `defaultFastCrashThreshold` = 4), and
  `SelfHeal func() error` (nil → self-heal disabled entirely — every existing
  `Config{...}` literal is byte-identical in behaviour). The `Run` loop
  tracks a goroutine-local `fastCrashes int` counter, incremented after the
  parent-ctx and `drainRestart` (deliberate-restart) guards, so a
  `Supervisor.Restart` is never miscounted as a crash: `err != nil && uptime
  < FastCrashWindow` → `fastCrashes++`; any healthy run (`uptime >= window`)
  or clean exit (`err == nil`) → reset to 0. At the threshold, `SelfHeal()`
  fires once and the counter resets either way (success: give the fresh id a
  full window; failure: avoid re-firing every iteration and fall back to
  retry-forever on the same id — `slog.Warn`, no regression vs. today).
  `backoff.go` is untouched — self-heal is orthogonal to the backoff timer,
  the fresh id just spawns after the current backoff delay.
- **The fresh id needs no new plumbing to reach the spawn path.**
  `SelfHeal()` only mutates the pool's `p.bootstrap`; the very next
  iteration's pre-existing `ResolveSessionID` pull
  (`func() string { return string(p.BootstrapID()) }`, #839) resolves the
  rotated id automatically — the rotation and the respawn were already
  wired.
- **`internal/sessions/pool.go`** — new `Pool.RotateBootstrapForSelfHeal()
  (SessionID, error)`: mints via `NewID()`, then under a single `p.mu`
  (write) hold reads `p.bootstrap`, guards it's still present
  (`ErrSessionNotFound` on TOCTOU), re-keys via the shared `rekeyLocked`
  helper (same seam `RotateID`/`RotateForNewSession` use), and
  `saveLocked()`s (failure → `slog.Warn` + swallowed, matching
  `RotateForNewSession`'s best-effort-durability posture — in-memory
  rotation is authoritative for the running daemon). Wired as a thin
  `SelfHeal` closure adapter in the bootstrap `supCfg` block (pool.go, next
  to `ResolveSessionID`): `func() error { _, err :=
  p.RotateBootstrapForSelfHeal(); return err }`.
- **Deliberately does NOT reuse `RotateForNewSession`.** No skip-set
  registration and no `ReasonClear` client transition — see
  [ADR 033](../decisions/033-supervisor-self-heal-dedicated-rotation-no-skip-set.md)
  for the full "why not" and the load-bearing correctness argument (the
  rekey commits before the next spawn's `<newID>.jsonl` CREATE, so the
  rotation watcher's `ref.ID == stem` guard already covers it — structurally
  identical to cold start).

## Tests

- `internal/supervisor/selfheal_test.go` (new) — reuses the existing
  `TestHelperProcess`/`helperConfig` harness, plus one new helper-child mode
  (`fast_crash_until_healed`: marker file absent → `os.Exit(1)` immediately,
  present → block until killed).
  - `TestSupervisor_SelfHeal_FastCrashesTriggerOneRotation` (AC1/AC5): small
    threshold (3), generous window (5s, so instant exits — dominated by
    ~200ms re-exec overhead — always count as fast); injected `SelfHeal`
    writes the marker, standing in for a fresh-id mint. Asserts `SelfHeal`
    called **exactly once** and the child then reaches a *stable* healthy
    state — same non-zero pid observed twice ~500ms apart. The double-read
    is deliberate: sampling `State()` at the instant `SelfHeal` fires still
    reads the stale just-crashed `PhaseRunning` (the `PhaseBackoff` update
    lands later), so a single `waitForPhase`-style check would be flaky.
  - `TestSupervisor_SelfHeal_HealthyExitDoesNotTrigger` (AC2/AC3): child
    sleeps 800ms (clearly above a 200ms window) before crashing; asserts
    `SelfHeal` never called — the streak resets every cycle.
  - `TestSupervisor_SelfHeal_NilKeepsRetrying` (AC3, disabled path):
    `SelfHeal == nil`, fast-crash loop well past threshold; asserts nothing
    is called and the supervisor keeps retrying (spawn count ≥ 3), proving
    the nil-disabled path doesn't panic or change behaviour.
- `internal/sessions/selfheal_test.go` (new) — unit-tests
  `RotateBootstrapForSelfHeal` directly: mints a fresh `ValidID` distinct
  from the old bootstrap id, `BootstrapID()` resolves the new id, the old id
  404s (`ErrSessionNotFound`), the *same* `*Session` pointer survives the
  rekey, `IsAllocated(newID) == false` (the no-skip-set assertion — this is
  the test that pins the ADR 033 correctness argument), and the on-disk
  registry round-trips with exactly one `Bootstrap: true` entry at the new
  id. A second subtest asserts `SetTransitionObserver` fires **zero** times
  (no `ReasonClear`).
- `go test -race ./internal/supervisor/ ./internal/sessions/`, `go vet
  ./...`, real-claude e2e (0.868s) all green (code-review PASS, see PR #1167
  comment).

## Patterns established

- **Crash-loop detection lives on the `Run`-goroutine as unlocked local
  state (`fastCrashes int`), not on `*Supervisor`.** No new lock, no new
  ordering — matches `firstRun`/`bo`'s existing shape. Reusable whenever a
  loop needs a streak counter that only that loop's goroutine ever touches.
- **A dedicated rotation primitive per caller-intent, sharing only the
  re-key/persist core (`rekeyLocked`/`saveLocked`), rather than parameterizing
  one primitive with behavior flags.** Three pool rotation entry points now
  exist (`RotateID`, `RotateForNewSession`, `RotateBootstrapForSelfHeal|`)
  each with a distinct doc comment stating what it does and doesn't do,
  instead of one method with boolean toggles whose combination matrix has to
  be re-derived from call sites. See [ADR 033](../decisions/033-supervisor-self-heal-dedicated-rotation-no-skip-set.md).
  Same shape #1164 used for `RotateForNewSession` (per-spawn probe) vs.
  cold-start (no-transcript) — different callers, shared seam, distinct
  contracts.

## Lessons learned

- **A crash-loop test can't `waitForPhase` a single sample.** The obvious
  assertion — read `State()` once right when the injected `SelfHeal`
  callback fires, expect `PhaseRunning` — is flaky: the just-crashed
  iteration's `State` hasn't advanced to `PhaseBackoff` yet at that instant,
  so a single sample can catch a stale `PhaseRunning` from *before* the
  crash. Fix is two samples of the same non-zero pid ~500ms apart, proving
  the child is not just running but *staying* running. Worth remembering for
  any future supervisor test that asserts "and then it recovers" right after
  a callback-triggered state transition.
