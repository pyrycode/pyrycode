# #1125 — Route `new_session` to the active conversation's bound runner (rotate + fresh-restart, no `/clear`)

**Size:** S. Security-sensitive (cross-conversation isolation, same class as #1121). 5 files touched
(`cmd/pyry/main.go`, `cmd/pyry/relay.go`, `cmd/pyry/streamsup_runner.go`, `internal/sessions/pool.go`,
`internal/sessions/transition.go`) + 2 new test files (`cmd/pyry/new_session_routing_test.go`,
`internal/sessions/transition_test.go` additions) + `internal/e2e/relay_v2_new_session_test.go` reworked
in a follow-up rework commit. `internal/relay` itself is untouched. Blocked-by #1124 (merged — the
runner-level `RestartFresh(newID)` mechanism this ticket consumes), split from #1100 (itself split from
#1078). The routing twin of interrupt sibling #1121.

## What shipped

Fixes the same bootstrap-mis-route bug #1121 fixed for `interrupt`, plus removes an indirection: the
inbound `new_session` control frame (`internal/relay`'s `SessionStarter.StartNewSession()`) was wired to
the **bootstrap** supervisor (`SessionStarter: w.sup`) regardless of which conversation the client was
actually in, and typed a fixed `/clear` into that child — the pool-side id flip then happened only
**indirectly**, when the fsnotify rotation watcher later observed claude's self-rotated `<uuid>.jsonl`.

`new_session` is now routed to the **active conversation's bound runner**, and on the stream-json path
it is a **direct** operation: mint a fresh id, rotate the pool-side id to it, and fresh-restart the bound
runner — no typed `/clear`, no waiting on the watcher.

Three new/changed pieces:

- **`Pool.RotateForNewSession(oldID) (SessionID, error)`** (`internal/sessions/transition.go`) — the
  daemon-driven analog of the watcher's `onRotate`. Mints via `NewID()`, then under `Pool.mu` (write):
  `ErrSessionNotFound` if `oldID` is absent (TOCTOU guard), re-keys via the newly-extracted `rekeyLocked`
  helper (byte-identical to `RotateID`'s prior inline body — `RotateID`'s exported signature and its
  `onRotate` caller are untouched), then `registerAllocatedUUIDLocked(newID)` — **the one asymmetry vs.
  `onRotate`**: the watcher detects a self-rotation because the id is *not* allocated; here the daemon is
  about to spawn `--session-id <newID>` itself, so the id must already be registered or the watcher
  double-rotates it on the CREATE it causes. `saveLocked()` failures are Warn-logged and swallowed
  (in-memory state authoritative). Off-lock, fires `notifyTransition(ReasonClear)` — reuses the existing
  reason, no new wire value, no #657 emitter change.
- **`activeSessionStarter` + `startFreshRunner` + `resolveBoundSession`** (`cmd/pyry/main.go`) — mirror
  `activeInterrupter` / `interruptRunner` / `resolveBoundRunner` one-for-one (#1121). `resolveBoundSession`
  is a **sibling** to `resolveBoundRunner`, not a refactor of it (same `Get → CurrentSessionID == ""` guard
  → `Pool.Lookup` body, returns `(*Session, boundID, ok)` instead of `(sessions.Runner, ok)` since the
  rotate call needs the id too) — the spec explicitly traded a small duplication for keeping interrupt's
  path byte-stable, same tolerance #1121 was granted. `startFreshRunner` type-switches, `RestartFresh`
  matched first: a `streamRunner` rotates (`Pool.RotateForNewSession`) **then** calls `RestartFresh(newID)`
  — order load-bearing, rotate must complete (skip-set published under `Pool.mu`) before the fresh spawn's
  `<newID>.jsonl` CREATE can fire, or the watcher double-rotates; a `*supervisor.Supervisor` falls to the
  `/clear` arm (`StartNewSession()`, unchanged PTY behavior); unknown runner → inert.
- **`streamRunner.RestartFresh(newID string)`** (`cmd/pyry/streamsup_runner.go`) — the forwarder to
  `(*streamsup.Runner).RestartFresh` (#1124). **Load-bearing and easy to miss**: the per-conversation
  stream runner is stored in a `Session` as the `streamRunner` *adapter*, not `*streamsup.Runner` directly,
  so `startFreshRunner`'s type-switch only matches once this forwarder exists — without it the routing
  compiles clean and silently falls through to inert. Same shape as the `Interrupt` forwarder #1121 added.

`cmd/pyry/relay.go`: one field added to `relayWiring` (`activeSessionStarter relay.SessionStarter`), one
wiring line flipped (`SessionStarter: w.sup` → `SessionStarter: w.activeSessionStarter`).
`internal/relay` — the `SessionStarter` seam, `handleNewSession`'s `s.interactive` gate and nil-seam
guard, and its unit tests — is completely untouched; only the adapter behind the seam changed.

## QA rework — e2e test needed an active-conversation binding, not a production fix

QA's first pass on PR#1130 flagged `TestRelayV2_NewSessionRotatesOnDisk` as a **regression**: post-#1125
`activeSessionStarter` is inert (AC4, by design) until a turn stamps the active-conversation cursor, and
the pre-#1125 e2e paired an interactive phone and sent `new_session` with **no conversation established**
— exactly the old bootstrap-mis-route behavior the ticket set out to remove. The rework verdict: **no
production gap**, the test needed updating to match the new architecture, mirroring `TestRelayV2_InterruptStopsRunningTurn`'s existing `seedBoundConversation` + `send_message`-before-control-verb pattern from #1121. Also strengthened `TestRelayV2_NewSessionNonInteractiveInert`, which would otherwise pass
vacuously post-reroute (an unstamped cursor is inert regardless of the capability gate) — it now stamps
the cursor via a `send_message` (not interactive-gated) so `s.interactive == false` is the *sole* reason
for inertness. Scope: test-only, `internal/e2e/relay_v2_new_session_test.go`, no production code changed.
See `po-qa-deterministic-red-may-be-loadsensitive-timeout-flake`-style precedent — a "regression" signal
that resolves to a test/architecture mismatch, not a code fix, is a distinct call from a flake.

## Patterns established

- **Rotate before restart, always.** Any future "actuate a fresh-restart under a new id" caller must
  complete the pool-side rotation (specifically, the allocated-skip-set registration) before triggering
  the spawn — reversing the order reopens the watcher double-rotation race. This is now the second
  confirmed instance of the "register-allocated-before-spawn" invariant (`Pool.Create` was the first).
- **The routing/mechanism split (#1120/#1121, #1124/#1125) is repeatable for a third control verb** if one
  needs a runner-type-specific direct actuation: ship the runner-internal primitive as a concrete,
  un-widened method in its own (`not-sec`) ticket, then a `cmd/pyry` adapter + type-switch dispatch ticket
  (`security-sensitive`, carries the isolation guard) that wires it behind the existing `internal/relay`
  seam. `internal/relay` never needs to know the runner concretes exist.
- **A stream-runner adapter method addition is a silent-inert failure mode, not a compile failure**, if the
  dispatch type-switch is written before the forwarder. Grep for existing forwarders (`Interrupt`,
  `Restart`) on the adapter type when wiring a new concrete-method dispatch, and add the test that would
  catch a missing forwarder (an injected fake with the method present, asserting it's actually called) —
  `TestActiveSessionStarter`'s bound-fake-records-one / bootstrap-fake-records-zero pair is that test.

## Lessons learned

- (From the PR body.) The per-conversation stream runner is stored in a `Session` as the `streamRunner`
  **adapter** (`cmd/pyry`), not `*streamsup.Runner` directly — so the concrete-method type-switch dispatch
  (`startFreshRunner`) only matches once the adapter grows a `RestartFresh` forwarder, exactly as it grew
  an `Interrupt` forwarder for #1120/#1121. Adding the routing without the adapter method compiles but
  silently falls through to inert — see *Patterns established* above.
- QA "regression" on an e2e test can be a stale-test-vs-new-architecture mismatch rather than a production
  gap — verify by checking whether the sibling ticket (#1121) already solved the identical shape and
  whether its e2e already carries the fix pattern (`seedBoundConversation` + pre-verb `send_message`)
  before assuming the routing itself is wrong.
