# Ticket #1056 — banner the Phase-0 entry docs (architecture/protocol/plan/multi-session) as historical

The 2026-07-15 docs review flagged four top-level Phase-0 entry docs (`docs/architecture.md`,
`docs/protocol.md`, `docs/plan.md`, `docs/multi-session.md`) as unmarked historical layers sitting
beside maintained `docs/knowledge/` docs with equal apparent authority — a reader landing on one
could mistake an early design snapshot for the current-state reference.

## Implementation

- Each of the four files got a bold blockquote banner prepended as line-1 content, one blank line,
  then the original `# Title` H1 and body untouched. `git diff --numstat` against `main`: 4/9/6/6
  insertions, 0 deletions across the four files — strictly additive.
- All four banners redirect to `docs/knowledge/architecture/system-overview.md` as primary
  current-authority successor.
- `docs/protocol.md`'s banner carries two extra required clauses (AC2): it scopes itself to only
  the original `status`/`stop`/`logs`/`attach` control-socket verbs, and states it is **not**
  superseded by the mobile protocol — a separate wire surface — cross-referencing
  `docs/protocol-mobile.md` as a "see also," not a successor. The control socket is still live and
  has since grown session/rekey/relay verbs; wording says "grown," not "superseded," since an
  over-strong claim would mislead in the opposite direction (this distinction is the reason the
  ticket exists).
- Verified: quoted section headings in `system-overview.md` resolve (`### Session Registry
  (Phase 1.2a)` L190, `## Beyond Phase 0 — landed work and roadmap` L317); `docs/protocol-mobile.md`
  exists and its own intro reciprocally frames the control socket as "a separate concern."
- Docs-only; no code, no new `docs/knowledge/` feature/architecture/decision doc created — no
  `INDEX.md` entry applies.
- Same shape and same reviewer as [#1055](1055.md) (`docs/specs` tree historical banner), merged
  immediately prior. Code review: PASS, no findings.

## Patterns established

- **"Grown, not superseded" is a distinct banner register from #1055's "Superseded by X."** Use it
  when the subsystem a doc describes is still live and has merely accreted surface beyond what the
  doc captures (control socket: 4 original verbs → verbs plus session/rekey/relay). "Superseded"
  implies a replacement subsystem exists; "historical, doc has not kept pace" is the correct framing
  when the subsystem itself didn't change identity. Picking the wrong register misleads readers in
  the opposite direction from the one the banner is meant to fix.
- **A same-target redirect can still need a second, non-primary cross-reference.** `protocol.md`
  points at `system-overview.md` as primary authority *and* at `protocol-mobile.md` as a sibling
  surface — verify the two targets aren't accidentally conflated (mobile wire protocol vs. local
  control socket are genuinely different protocols, not two views of one).
