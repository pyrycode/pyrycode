# Ticket #1342 — Probe rig: declare the run's FIFO name, hold prompt, staged command literal and env delta, with their offline traps

A later live `pyry agent-run` probe stages one turn in which claude is asked
to `cat` a FIFO that never closes; the auto-background trigger fires, and
`finOutcomeStagingGate`'s identity arm (`finding_staging_gate_test.go:299`) is
byte equality between claude's verbatim `input.command` and whatever the rig
says it staged. Get either operand wrong and every *correctly*-staged run
reports `stage-command-not-staged`, with the rig looking correct and one live
claude turn burned per attempt. This ticket ships the four declarations that
equality turns on — the run's FIFO name, the hold prompt, the staged command
literal and the env delta — plus one offline trap per declaration, so that
defect is caught for free instead of live.

New file only: `internal/e2e/realclaude/finding_live_staging_test.go`
(`//go:build e2e_realclaude`, 489 lines). No existing file edited, no
production code, no live run, no `pyry` spawn, no real claude, no `ps` exec,
no FIFO, no record assembly. Imports `fmt`, `strings`, `testing` and nothing
else.

## Implementation

- **`finLiveStageFIFOName = "fin-live-stage-hold"`** — re-derived at `26d83b7`
  via `rg -n 'FIFOName *=|FIFOPath *=' internal/e2e/realclaude/` (the
  two-alternative recipe; a `FIFOName`-only search misses `finLivePinFIFOPath`,
  #1338's `FIFOPath` const). Substring-disjoint, both directions, from all
  eight shipped names/paths.
- **`finLiveStageSystemPrompt = probeSystemPrompt`** — an identifier alias,
  not a re-typed copy, so the driver (#1340) can hand `spawnProbePyry` both
  halves it needs without this file inventing a second prompt. Carries no
  trap: asserting it equals its own definition would prove nothing.
- **`finLiveStageCommand(fifoPath string) string`** — `probeHeldCommandName +
  " " + fifoPath`. Splices the shipped verb constant rather than re-typing
  `"cat"`, because #1340's liveness read calls `probeHasCommand(…,
  probeHeldCommandName)`; the splice makes a verb rename a build break
  instead of a silent drift between what's staged and what's checked. Bare
  command — not `finOutcomeHoldCommand`'s `sh -c … ; exit 0` stand-in shape,
  which is a gate fixture, deliberately the wrong shape, and is never reused
  here.
- **`finLiveStagePrompt(fifoPath string) string`** — follows `probePrompt`'s
  delimited form (verb inside backticks, sentence period outside), with the
  *whole* command interpolated rather than just the path, so the prompt and
  the staged literal derive from one `fmt.Sprintf` call instead of being
  written twice. Deliberately not `bgIdlePrompt`'s form, where the period
  abuts the path and there is no delimiter to extract on. No cache-buster —
  `probePrompt` carries none and fired 7/7 live in #1223.
- **`finLiveStageEnvDelta() []string`** — a func, not a var (mirrors
  `finRecordEnvDelta`, since a package-level slice is mutable by every test
  in the package and two downstream tickets read this one). Two literals of
  its own, not a concatenation of `reachEnvDelta` + `finRecordEnvDelta`:
  `BASH_DEFAULT_TIMEOUT_MS=5000` (the settled #1223 trigger) and
  `PYRY_USE_STREAMJSON=0`, named explicitly because
  `reachRunnerPathFromEnv` reads the ambient `os.Getenv` first and only then
  lets the delta override — an empty delta would make the downstream runner
  reading a reading of the operator's shell, not this rig.
- **`finLiveStageFixtureFIFOPath`** — `"/tmp/pyry-fin-live-stage/" +
  finLiveStageFIFOName`, a compile-time const splice. Never `t.TempDir()`,
  never `os.Getenv`; passed only to the two formatters and never opened,
  stat'd, joined or executed, so path traversal/TOCTOU/symlink-following are
  structurally inapplicable rather than merely unaddressed.
- **`finLiveStageCommandFromPrompt(prompt string) (string, bool)`** — the
  test-side second reading. Returns the text between the prompt's only two
  backticks; `ok` is false unless exactly two are present. Producing side is
  a `fmt.Sprintf`, recovering side is a delimiter scan — no shared
  implementation, so a hand-copied second literal couldn't have stood in for
  it.
- **`finLiveStageDeltaHas(delta []string, entry string) bool`** — exact
  `KEY=VALUE` match, not a prefix match (`PYRY_USE_STREAMJSON=0` and `=1` are
  opposite instructions). Code review flagged this as a SHOULD FIX — it
  duplicates `slices.Contains`, already used at seven call sites elsewhere in
  the package — left un-actioned at merge since SHOULD FIX doesn't block; see
  Lessons learned.

No type is declared anywhere in the file, so the no-JSON-tags rule
(`finTranscriptReading`'s) is satisfied structurally rather than by
inspection.

## Tests

`TestFinLiveStagePromptStagesTheDeclaredCommand` (AC1) — extraction
round-trip (`finLiveStageCommandFromPrompt(finLiveStagePrompt(p)) ==
finLiveStageCommand(p)`, failure message reports lengths only, never the
strings); the extractor is not a pass-through; exactly one backticked span,
and `ok` is false for zero/one/three-backtick mutants; the staged command
itself carries no backtick, doesn't end in `.`, contains the FIFO path it was
formatted from, and contains none of `;`, `&&`, `|`, `sh -c`.

`TestFinLiveStageFIFONameIsDisjointFromEveryShippedName` (AC2) — an 8-row
table referencing the shipped FIFO name/path constants **by identifier**
(`probeFIFOName`, `reachFIFOName`, `tdnFIFOName`, `fifoLiveFIFOName`,
`trailRigFIFOName`, `finStageFIFOName`, `bgIdleFIFOName`,
`finLivePinFIFOPath`), asserting `strings.Contains` false in both directions
per row, `len(taken) != 8` as a deletion guard, and deliberately no
empty-name guard (`strings.Contains(s, "")` is `true`, so an accidentally
empty `finLiveStageFIFOName` fails loudly on the second direction — the safe
failure).

`TestFinLiveStageEnvDeltaNamesTheRunner` (AC3) — `t.Setenv("PYRY_USE_STREAMJSON",
"1")` as the hostile ambient (the file's only environment write); a control
assertion first proves a `nil` delta takes the ambient branch
(`"streamrunner"`), which is what makes the claim below non-vacuous by
construction; then the declared delta yields `"ptyrunner"` through
`finRecordRunnerLabel` (compared through the truncator, never the raw
`"ptyrunner (interactive TUI, the agent-run default)"` string against a bare
literal); composition checked against `reachEnvDelta` and
`finRecordEnvDelta()` by identifier; exactly 2 entries, since a third
(`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`) would suppress the very trigger
the rig depends on.

## Patterns established

- **Both sides of a byte-equality gate derive from one `fmt.Sprintf` call,
  never two.** The prompt interpolates the *whole* staged command, not just
  the FIFO path, so `finLiveStagePrompt` and `finLiveStageCommand` cannot
  drift apart independently — and the test's extraction reading is
  independent (delimiter scan vs. producing `Sprintf`), so it isn't a
  hand-copied literal standing in for a real second witness.
- **A splice into a shipped constant, not a re-typed literal, when two
  tickets must agree on a bare word.** `finLiveStageCommand`'s verb comes
  from `probeHeldCommandName` because #1340's liveness check reads the same
  constant; a rename becomes a build break instead of a silent staging/check
  mismatch.
- **An env delta consumed by multiple downstream tickets is a func returning
  a fresh slice, never a package-level `var`** — following
  `finRecordEnvDelta`. Its own two literals, never a concatenation of two
  shipped deltas, so this rig's environment doesn't silently follow edits to
  either sibling; the test instead asserts containment against both shipped
  identifiers.
- **A collision-avoidance sweep over shipped constants references them by
  identifier, in the same package under the same build tag, never by
  re-typed string** — a rename breaks the build rather than rotting the
  list silently, and the sweep states its own limit (traps the *n* named
  today, not an *n+1*th added later) instead of overclaiming coverage.
- **A declaration that composes without adding logic (`finLiveStageSystemPrompt
  = probeSystemPrompt`) carries no trap, and the file says why**: an
  assertion that a thing equals its own definition proves nothing, and
  stating that plainly is more honest than shipping a vacuous test to pad
  coverage.

## Lessons learned

(From the PR body; see PR #1344.)

- **This machine's ambient really is `PYRY_USE_STREAMJSON=1`.** The hazard
  `background_reach_probe_test.go:1092-1094` records as an operator's shell
  observed once on 2026-07-25 is live in the dispatcher environment today,
  not historical. Any test in this package that reads the runner from the
  environment without setting the ambient is reading *that*, not its own
  delta — which is exactly why AC3's hostile-ambient requirement isn't
  academic.
- **The hostile-ambient requirement is demonstrable, not just arguable.**
  Mutating the delta to stop naming `PYRY_USE_STREAMJSON` (keeping two
  entries) and running with the variable unset in the shell: with the test's
  `t.Setenv` removed, the runner claim goes green against the *broken*
  delta; with it present, the same broken delta goes red. That gap is what
  separates this trap from the nearest precedent
  (`finding_run_record_test.go:819-827`), which argues the independence in
  its failure message but never sets the ambient — and was therefore
  deliberately not copied as-is.
- **A `t.Fatalf` round-trip check can hide the guard that follows it.**
  Code review found `TestFinLiveStagePromptStagesTheDeclaredCommand`'s
  pass-through guard (`:267-271`, `len(got) >= len(prompt) || got ==
  prompt`) unreachable-red under the obvious pass-through mutant
  (`return prompt, true`): that mutant dies at the equality `Fatalf` two
  lines above and never reaches the guard, so the guard looked untested by a
  single-line mutation. It's only reachable-red when the round-trip
  *agrees* — a two-part mutant where the prompt's whole content is itself
  the bare command. Filed as a NIT, not a blocker, since the sibling checks
  below it (exact-backtick-count) are independently reachable. General
  lesson: before concluding a guard-below-an-equality-check is decorative,
  build the mutant that makes the equality pass *and* the guard fire —
  a single mutant that only shrinks the round-trip proves the earlier
  `Fatalf` catches it, not that the guard does.
- **A SHOULD FIX can ship unaddressed and the ticket still completes.**
  Code review flagged `finLiveStageDeltaHas` as duplicate machinery
  (`slices.Contains` already used at seven call sites in this package) but
  rated the finding non-blocking; it merged as filed. Recorded here rather
  than silently treated as resolved, since a future edit to this file that
  "cleans up" the helper should know it was a known, deliberately-deferred
  SHOULD FIX rather than an oversight nobody flagged.
