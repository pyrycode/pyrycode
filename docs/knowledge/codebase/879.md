# Ticket #879 — reconcile-on-connect contract (docs)

Writes the single written rule that [#877](877.md) (modal) and [#878](878.md) (queue) already
implement, so every client author (desktop today, mobile later) builds against one contract
instead of inferring control-state reconciliation from daemon behaviour. Docs only — no code,
no tests. Frames the correctness contract behind #829/#903/#904.

## Implementation

Four edit sites in `docs/protocol-mobile.md` plus one in ADR 025, per the spec at
[`specs/architecture/879-reconcile-on-connect-contract-docs.md`](../../specs/architecture/879-reconcile-on-connect-contract-docs.md):

- **Canonical rule.** `## Backfill semantics` retitled to `## Reconnect / Backfill semantics`
  and expanded into two data-type-keyed modes: **Mode A** (bulk transcript content → cursor
  backfill — `last_seen_ts` v1 backfill plus the #647 `last_event_id` ring replay with
  `resync` fallback; *replay of past events*) and **Mode B** (control state → current-state
  snapshot; the reconcile-on-connect rule — *replays no past control events*). The axis of
  difference is stated explicitly as **data type, not outage length**.
- **Match-and-replace by stable id.** Mode B spells out three sub-rules keyed on stable
  identity (`modal_id`; `conversation_id` + `queued_msg_id`): a re-delivered `modal_shown` for
  a known id updates in place and never double-shows; an already-resolved id is a no-op;
  control state not re-asserted after a fresh handshake is gone (reset-on-reconnect, since
  every reconnect is a fresh Noise_IK handshake with no session resumption).
  - **`### Modal (v2)`** gained a "Reconcile on (re)connect" note pointing to the rule and
    stating answer semantics are unchanged under re-delivery — the `modal_id` nonce plus
    `answer_token` keep a prompt answerable exactly once, and deny-on-timeout is armed once at
    raise time and never re-armed by a re-send — by **reference** to the existing Security &
    validation contract note and ADR 025 § Security model, not restated.
  - **`### Queue (v2)`** — the stale L692 clause ("a phone that reconnects after missing a
    `queue_state` sees the current backlog only on the next change") directly contradicted
    #878's shipped connect-time reconcile. Rewritten: the daemon unicasts a `queue_state`
    snapshot for every non-empty backlog on (re)connect, idempotent by construction because
    `queue_state` is already snapshot-shaped full state; the existing "pushes on change" (#722)
    note stays as the complementary change-driven trigger.
  - **`### Reconnect`** (backoff/jitter timing) gained a one-line cross-reference so the
    timing subsection stays uncluttered while the reconnect entry point still surfaces the
    application-layer rule.
- **ADR 025 supersession note.** A dated blockquote (`> **Superseded for control events —
  2026-07-10 (ADR 025 amendment).**`) added directly under § Backpressure / replay's L130
  paragraph, in the house style of the existing 2026-06-22 amendment note. Explicitly
  supersedes, **for control events only**, the "the binary replays from a bounded
  per-conversation event ring" wording — the cursor/ring path stays as-is for bulk transcript
  content (`assistant_delta`, the turn-event stream). The original L130 paragraph is preserved
  unmodified as the superseded prior wording (append/amend, never rewrite).

## Patterns established

- **Docs-only tickets still follow the edit-site → AC map discipline.** The spec listed five
  edit sites against five ACs before any prose was written; every AC lands as a traceable
  sentence in a specific section rather than diffuse restatement. Worth reusing whenever a
  ticket's job is to write a contract for an already-shipped mechanism.
- **A supersession note amends, it never rewrites.** The ADR 025 blockquote sits *under* the
  original paragraph rather than replacing it, so the historical wording stays legible as
  "what we used to say" — the same house style as the pre-existing 2026-06-22 amendment.
- **Reference the security invariants, don't restate them.** The nonce / `answer_token` /
  deny-on-timeout / first-answer-wins contract already has one home (protocol § Security &
  validation contract, ADR 025 § Security model). #879 only ties them to reconcile-on-connect
  ("unchanged under re-delivery," "never re-armed by a re-send") rather than duplicating the
  invariants — duplication is exactly what lets two homes drift.

## Security review

**Not** `security-sensitive` (per the ticket label). Docs-only, zero production/test source
files: writing a security contract into prose carries no new design surface. The primitives
being documented (nonce, `answer_token`, deny-on-timeout) already earned `security-sensitive`
in their owning tickets (#701/#703/#706/#717/#725); this ticket adds no wire behaviour and no
new field.

## Testing

Docs-only — no Go build/test surface. Verification per the PR: no `#backfill-semantics` anchor
was referenced anywhere in `docs/` (safe retitle to `#reconnect--backfill-semantics`); the
stale "sees the current backlog only on the next change" clause is gone; new cross-links
(`#reconnect--backfill-semantics`, `#modal-v2`, `#reconnect-replay--resync-consumer-647`)
resolve to existing anchors. Code review: **PASS**, one non-blocking NIT (a dated breadcrumb in
a sibling ticket's file, `codebase/723.md`, deliberately left untouched — out of scope, per the
per-ticket-file convention).

## Lessons learned

- The `Security & validation contract` lead-in in `protocol-mobile.md` is bolded inline text,
  not a `####` heading — it has **no GitHub anchor**. Reference it by name in prose; don't mint
  a `#security--validation-contract` link, which would 404.

## Out of scope (named)

- **`docs/knowledge/codebase/723.md:239`** carries a now-superseded historical note ("a phone
  reconnecting after a missed dequeue sees the backlog only on the next change") that reads as
  a breadcrumb to #722's own out-of-scope decision, not a live protocol claim. Code review
  flagged it as a non-blocking NIT for a future evergreen sweep; left untouched here per the
  per-ticket-file convention (never edit a sibling ticket's file). `docs/protocol-mobile.md`,
  the live wire contract, is already clean.
- **Mobile-client implementation of match-and-replace** is a separate client-side ticket; this
  spec writes the contract the client builds against, not the client code itself.
