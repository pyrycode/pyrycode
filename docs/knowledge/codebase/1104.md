# Ticket #1104 — Control-socket `mcp.approve` verb: forward → permbridge, block, default-deny

Daemon side of the Streamrunner Interactive permission bridge's forwarding hop. Adds `VerbMCPApprove` ("mcp.approve") to `internal/control`: it receives a forwarded claude tool-approval request (`tool_name`, `input`, `tool_use_id`) over the control unix socket, registers it with `internal/permbridge` (#1103), blocks until a verdict is available, and returns it in the wire shape the sibling `pyry mcp-approve` subcommand marshals straight to claude as the MCP tool result. Split from #1079; blocked by #1103 (merged).

Full design writeup: [`features/control-plane.md` § Approve](../features/control-plane.md#approve-mcpapprove-verb--forward-to-permbridge-block-default-deny-1104). Spec: [`specs/architecture/1104-control-socket-approve-verb.md`](../../specs/architecture/1104-control-socket-approve-verb.md). Registry primitive: [`features/permbridge-package.md`](../features/permbridge-package.md).

## Implementation

- `internal/control/protocol.go`: `VerbMCPApprove Verb = "mcp.approve"` (dotted like `sessions.*`); `ApprovePayload` (snake_case tags matching the T1 spike's `fixture-p4-approval-contract.json`, so the sibling subcommand marshals straight from claude's tool call); `ApproveResult`, deliberately byte-identical in field/tag layout to `permbridge.Verdict`'s wire shape (same mirror-and-document rule as `SessionInfo` vs `sessions.SessionInfo`) so the subcommand round-trips it to claude without a second translation.
- `internal/control/server.go`: `Server.approvals *permbridge.Registry` + `approvalTimeout time.Duration`, installed via `SetApprovalRegistry(reg, timeout)` — the `SetRekeyer` post-construction-setter shape, keeping `NewServer`'s signature frozen. `handleApprove` follows `handleRekey`'s guard order (nil-dependency check, then payload validation) but — unlike every other one-shot verb — **blocks** between decode and response: clears the handshake deadline (`handleAttach`'s pattern), starts a per-conn watcher goroutine, then calls `pending.Await()`.
- The watcher (`watchApproveConn`) maps the two cancellation sources `permbridge.Pending.Await` cannot see on its own (it's ctx-free by #1103's design) into a fail-closed `reg.Resolve(id, Deny(...))`: caller disconnect (an inner `conn.Read` goroutine hits EOF) and daemon shutdown (`s.closedCh`, already used by the `handleAttach` shutdown-abort machinery, #863). The handler closes a `stop` channel after `Await` returns so the watcher doesn't double-resolve on the normal path.
- `cmd/pyry/main.go` `runSupervisor`: `approvals := permbridge.New()` created before `startRelay`/`relayWiring`, then `ctrl.SetApprovalRegistry(approvals, mcpApprovalTimeout)` between `control.NewServer(...)` and `ctrl.Listen()`. `mcpApprovalTimeout = 2 * time.Minute`, a `cmd/pyry` const documented as a tuning knob (inert until the sibling wires `--permission-prompt-tool`, and until #1080 lands there's no resolver so every requested approval times out to deny).
- New file `internal/control/approve_test.go` (363 lines): allow, resolver-deny, timeout-deny, disconnect-before-resolution (poll `reg.Lookup` present → close conn → poll absent), unavailable (nil registry), missing-`tool_use_id`, shutdown-unblocks.

## Patterns established

- **Blocking verb over the setter-installed-optional-dependency shape.** Every prior nil-dependency verb (`handleRekey`, the relay-plane phone frames) is fire-and-ack; this is the first control-socket verb that blocks for an externally-resolved outcome while still following the `SetRekeyer` degrade-cleanly template. The combination — optional dependency + blocking wait + per-conn cancellation watcher — is now the reference shape for any future long-lived-decision verb.
- **Two-cancellation-source watcher pattern for a ctx-free blocking primitive.** `permbridge.Pending.Await` deliberately takes no `context.Context` (#1103's design — the registry doesn't know about sockets or daemon lifecycle). The consumer maps its own cancellation sources into `Resolve` calls instead of threading ctx into the primitive. Reusable whenever a leaf primitive's blocking wait needs to be cancelled by a consumer-side event it can't itself observe.
- **`s.closedCh` as the in-handler shutdown signal.** Reused from the existing `handleAttach`/`Server.Close` shutdown-abort machinery (#863) rather than inventing a second shutdown channel — `Serve`'s `handleWG.Wait()` doesn't stall for `approvalTimeout` because the watcher unblocks the handler promptly on `Close()`.

## Lessons learned

- `ApproveResult` deliberately duplicates `permbridge.Verdict`'s field/tag layout (kept in `protocol.go`, which stays internal-import-free apart from `encoding/json`) so the sibling `pyry mcp-approve` subcommand consumes the wire types without transitively importing `internal/permbridge` — same mirror rule as `SessionInfo` vs `sessions.SessionInfo`. A future drift between the two shapes must be caught by hand (documented in both doc-comments); no compile-time check ties them together.
- AC-4 ("permbridge wired into daemon composition so the verb reaches a shared registry instance") is satisfied by creating the shared `*permbridge.Registry` in `runSupervisor` scope and installing it via the setter — **not** by adding a `relayWiring.approvals` field. A set-but-unread unexported field would trip `staticcheck` U1000 (CI-gated) since nothing reads it until #1080 lands; the architect spec flagged this explicitly rather than adding dead wiring to satisfy a literal reading of the AC.
- Code review (PR #1112, PASS) flagged the watcher goroutines as a NIT, not a MUST FIX: they're spawned with a bare `go` rather than tracked on `Server.streamingWG`, which superficially looks like the untracked-goroutine leak class other verbs avoid. Judged not a leak because `handle`'s deferred `conn.Close()` bounds the parked inner reader goroutine deterministically — the same reasoning that already applies to `handleAttach`'s detach watcher. Recorded as a reusable review heuristic: an untracked watcher goroutine is fine if a conn-close in the same function's defer chain is guaranteed to reap it; only flag as MUST FIX if no such bound exists.
