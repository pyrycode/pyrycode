# Ticket #965 — Offload app-handler execution off the V2SessionManager Run goroutine

`V2SessionManager.Run` is a single-goroutine actor: every Noise cipher operation (`s.send.Encrypt`, `s.recv.Decrypt`) and every session-state mutation must happen there, because flynn/noise `CipherState`s are single-owner. [#909](909.md) moved `dispatch.Route` (→ handler → `c.Send`, no AEAD) onto a short-lived per-frame goroutine, but `dispatchAppFrame` still **blocked** `Run` until `Route` returned — a private two-arm drain select with nothing else to do while the handler ran. The concrete case: `create_conversation` → `pool.CreateIn` → `Activate` waits up to 30s for PTY readiness, parking `Run` for that whole window. While parked, every other connection's frames piled up and every per-session timer (`m.wake`, `m.modalTimeout`, `m.manualRekey`) stalled — the head-of-line-blocking shape the retired v1 Dispatcher's doc comment warned about, and #909 explicitly deferred ("#909 fixed the reply-*count* deadlock, not this reply-*latency* stall").

This ticket removes the blocking. Handler execution now runs on a per-connection worker goroutine; replies fold back into `Run`'s main `select` via a new arm, so `Run` keeps servicing every other arm while a handler runs.

## Implementation

- **One production package, `internal/relay`**, across `v2session.go` (+257/-52 net), `v2session_handshake.go` (+12), `v2session_seams.go` (doc rewrite), plus the required stale-comment fix in `handlers/create_conversation.go` and a doc-only touch-up in `v2bundlestream.go`. New test file additions in `v2session_appframe_test.go` (+409 LOC, 7 new tests).
- **`dispatchAppFrame`'s tail is now a non-blocking enqueue.** The control-envelope discriminator (rekey/modal/interrupt/new_session/dequeue/snapshot/debug_bundle/settings) is unchanged and stays on `Run`. An application frame's plaintext goes onto a new per-conn `V2Session.appFrames chan []byte` (buffered `appFrameQueueDepth = 16`, a package `var` not a `const` so the overflow test can shrink it) via `select { case s.appFrames <- pt: default: <overflow> }`, and `dispatchAppFrame` returns immediately — `Run` never blocks on a handler again.
- **`appFrameWorker(ctx, s)`** is the new per-conn sub-actor, exactly one per open session, spawned in `handleNoiseInit`'s open tail (`ctx` = `runCtx`) *after* `s.device` is set and `s.state = V2StateOpen` — establishing the happens-before edge the worker relies on to read those fields. It drains `s.appFrames` in strict FIFO order, fully routing frame N (Route returned, all replies forwarded) before dequeuing N+1 — the per-conn serialization guarantee (AC-2). Terminates on `ctx.Done()` (Run exit) or `s.done` closing (`closeWith`, per-session teardown, no wait for Run exit).
- **`routeAppFrame`** is `dispatchAppFrame`'s old spawn-Route-then-drain body, lifted onto the worker verbatim (preserving #909's concurrent-drain shape unchanged — `TestV2Session_OpenState_ProlificHandler_NoDeadlock`/`…_EmissionOrder` pass unmodified), except each reply now goes to a new `forwardToRun` helper instead of calling `forwardAppReply` directly.
- **`forwardToRun`** blocks sending `appReplyMsg{s, reply}` onto the new `V2SessionManager.appReply` channel (unbuffered — deliberate backpressure onto the worker, not a manager-global accumulation buffer) with `ctx.Done()`/`s.done` escapes, so a worker parked on a reply send unblocks on teardown rather than leaking.
- **`Run`'s new `case rep := <-m.appReply:` arm** calls `forwardAppReply(rep.s, rep.reply)` — the only call site now; the seal (`s.send.Encrypt`) stays on `Run`. `forwardAppReply` gained a leading `if s.state != V2StateOpen { <debug log>; return }` gate (mirrors `forwardEnvelope`), dropping replies from a worker whose session `closeWith` already tore down — no nonce burned on a dead session.
- **`closeWith`** gained `if s.done != nil { close(s.done) }`, symmetric with the existing `m.queues` delete; the function's top-of-body `V2StateClosed` guard makes this close-once.
- **Overflow policy:** `appFrameQueueDepth` app frames already in flight for one conn (far beyond the realistic 1–2 pipelining depth) closes that conn at 4421 (`StatusProtocolMismatch`, reused rather than minting a new wire code) with a WARN (`v2.app_frame.queue_overflow`, `conn_id` + static count only — no plaintext). Self-inflicted only: frames are AEAD-decrypted under `s.recv` before reaching the queue, so only the authenticated phone can fill its own queue.
- **`V2SessionConfig.Handlers`'s doc comment rewritten** — it previously said handlers run on the manager's single dispatch goroutine and must be synchronous; now describes the worker model (handlers must still return in bounded time or stall that conn's *own* subsequent frames — bound long waits with a ctx timeout, as `create_conversation` already does).
- **Stale-comment fix (ticket-required):** `handlers/create_conversation.go`'s two "per-conn goroutine" comments (describing the retired v1 Dispatcher) now describe the v2 app-frame worker instead.

## Test coverage (`v2session_appframe_test.go`, +7 tests)

- `TestV2Session_SlowHandler_DoesNotStallOtherConn` (AC-1a) — two conns via the existing `openModalConn` (#727) conn-aware helper (no new harness variant needed; the spec's speculative `driveToOpenConn` wasn't required). Conn A's handler blocks; conn B's `list_conversations` reply seals and emits before A is released.
- `TestV2Session_SlowHandler_ModalTimeoutStillFires` (AC-1b) — blocked app handler on conn A; modal deny-on-timeout still fires on schedule.
- `TestV2Session_SlowHandler_RekeyStillEmits` (AC-1, rekey) — blocked app handler; scheduled/manual rekey still emits.
- `TestV2Session_AppFrame_PerConnSerialization` (AC-2) — a handler that signals entry then blocks on a per-token `release` channel proves frame 101 never enters while frame 100 is still inside its handler; both replies decrypt (via `initRecv`, which fails loudly on any reorder) with `in_reply_to` in arrival order.
- `TestV2Session_AppFrame_QueueOverflow_ClosesConn` — shrinks `appFrameQueueDepth` to 4 (package var, not `t.Parallel()` for that reason), floods conn A behind a permanently-blocked handler, asserts conn A closes at 4421 while conn B stays healthy.
- `TestV2Session_OpenState_ProlificHandler_NoDeadlock` / `…_EmissionOrder` — pre-existing #909 tests, unchanged, regression-pin that `routeAppFrame` preserves the concurrent-Route-drain shape.
- AC-3 (every seal stays on `Run`) has no separate fixture — `-race` across all of the above is the proof; an off-`Run` seal or concurrent CipherState touch fires the detector and breaks the ordered-decrypt assertions.

## Patterns established

- **Per-conn worker + manager-funnel-back is the extension of #909's "Run owns cipher, off-Run does non-AEAD work" split** — from one offloaded frame to a per-conn FIFO stream. The shape generalizes: a single-owner goroutine can absorb an arbitrary number of slow off-owner workers as long as (a) the owner-sensitive operation (the seal) has exactly one call site reachable only from the owner loop, and (b) the workers' only channel back to the owner is unbuffered or small, so backpressure lands on the worker rather than accumulating owner-side state.
- **Non-blocking enqueue + explicit overflow-close beats blocking-enqueue or silent-drop for synthetic per-conn backpressure on a multiplexed transport with no native flow control.** Blocking reintroduces the exact cross-conn stall being removed; dropping silently strands a request/response the caller is still awaiting. A bounded queue + deterministic teardown is the responsible floor, not a speculative feature — since the relay↔binary leg is one shared WebSocket, this pattern is the general answer to "what path controls X" for the multiplexed-leg-inbound-per-entity family.

## Lessons learned

- **The "second conn" harness the spec flagged as a likely-needed extension already existed.** The spec's Testing strategy section speculated a new `driveToOpenConn(connID)` variant would be needed to drive two conns open for AC-1(a). It didn't — `openModalConn` + `sealAppFrameConn` (built for #727's modal fan-out tests) already covered a conn-aware handshake + seal. Worth checking existing multi-conn test helpers before adding a new one; the modal/interrupt/new_session/dequeue test files established a conn-parametrized pattern that outlived its original ticket.
- **`noise.CipherState.Decrypt` returns a freshly-allocated slice** (flynn/noise's `Open` with `dst=nil` allocates), so a decrypted inbound plaintext can be enqueued onto `s.appFrames` for later off-Run processing with no defensive copy — no buffer-aliasing hazard between `handleNoiseMsg`'s decrypt and the worker's later read.
- **#909's interleave-drain `routeAppFrame` body lifted onto the worker verbatim** — the "single-owner sink (the seal) stays on the owner goroutine, non-AEAD work moves off" split generalizes cleanly from one offloaded frame (#909) to a per-conn FIFO stream (#965) with no change to the drain shape itself, only to where its output is forwarded (`forwardAppReply` directly → `forwardToRun`/`m.appReply`).
