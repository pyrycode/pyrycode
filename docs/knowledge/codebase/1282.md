# Ticket #1282 — Probe instrument: fill the gather's parameters from a real held command in its own process group (offline)

Adds `internal/e2e/realclaude/finding_stage_held_group_test.go` (one new file,
617 lines, purely additive, zero production change, zero consumer call
sites). `finGatherReadings` (#1281) proved its own composition — that
`finGatherReadings`' two parameters (`stderr []byte`, `pinned []int`) can
reach both the finding and a genuine negative — but every row that proved it
was driven from synthetic stdout, synthetic stderr and **hand-passed pgid
integers**. Hand-passed integers prove the composition; they do not prove
the parameters can be *filled*. This ticket closes that gap: a real command,
held un-finishable on a real FIFO, in a process group of its own, whose
group comes off a real `pinScanArgv` (#1280) scan and is handed to the
gather as `pinned`. Still entirely offline — real FIFO, real `sh`, real
`cat`, synthetic stdout buffer, synthetic reap line; no live claude, no
credentials, no turn, no `t.Skip`. Split from #1277; the next and last
ticket in the chain that promotes `PyryExited`/`ClaudeState` off the staged
values is #1279 (a live pyry).

## Implementation

- **`finStageHeldGroup(t, body func(finStageSubject))`** is the staging.
  Copies the *wrapper* subject shape from `trail_run_rig_test.go:506-556`
  (`sh -c '"$1" "$2"; exit 0'`, both operands resolved via `exec.LookPath`
  in the parent and passed positionally — a compile-time constant with no
  interpolation site), not the flip test's bare `exec.Command` shape
  (`:277`), which inherits the test process's own group and would collapse
  AC3's own-group trap arm into the finding arm. `cmd.Env = []string{}`
  scrubs `CLAUDE_CODE_OAUTH_TOKEN`/`ANTHROPIC_API_KEY`; `SysProcAttr{Setpgid:
  true}` is the load-bearing line. A callback rather than a return value, so
  the `SIGKILL(-pgid)` `defer` sits in one place ahead of every arm — a
  helper that *returned* would fire its own teardown before any arm ran.

- **The teardown is three statements, not two, and the ordering is
  measured, not assumed.** `syscall.Kill(-pgid, SIGKILL)` reaches the
  grandchild `cat` (a direct `cmd.Process.Kill()` on the shell would not);
  but `t.Fatalf` runs deferred functions via `runtime.Goexit()`, so on the
  guard's own red path (`Setpgid` dropped) the group kill hits `ESRCH` and
  `cmd.Wait()` would otherwise block forever on a live `sh` awaiting an EOF
  only `holdProbeFIFO`'s `t.Cleanup` can deliver — which cannot run until
  the test goroutine finishes its `Goexit`. A direct `cmd.Process.Kill()`
  between the group kill and `Wait()` is what turns that deadlock into a
  0.06s fail. Verified independently in code review, not just claimed in
  the spec.

- **AC1's guard asserts the pgid as `pinScanArgv` reports it
  (`distinct[0] != syscall.Getpgrp()`), never `cmd.Process.Pid`.** A freshly
  forked child's pid is never the test process's group id, so
  `cmd.Process.Pid != syscall.Getpgrp()` holds whether or not `Setpgid` took
  effect — the vacuous form, confirmed green under the dropped-`Setpgid`
  mutation in code review. The scanned-`.PGID` form reddens on that same
  mutation because without `Setpgid` the scanned group *is*
  `syscall.Getpgrp()`, the same value every arm hands the gather.

- **The `len(distinct) == 1` check is a fail-closed gate against a
  third-party row, not only a staging sanity check.** `pinScanArgv` reads
  an ambient, untrusted process table — any local process can put arbitrary
  bytes in its own argv — so an unrelated row happening to carry the needle
  would land in a different group and this check fails the staging rather
  than silently pinning a group the test never staged.

- **`finStageSubject{Needles, Pinned, Group, Rows}`** carries only integers
  and needle paths — never `pinScan.Matches` or a `reachProc` — in
  `finAttributeFanOut`'s own `[]int` shape (#1280), so "no captured bytes
  leave the staging" is structural rather than a per-call-site discipline.
  `Pinned` keeps its duplicates (one entry per matched row) so the fan-out's
  step-1 dedupe is the thing under test rather than a reduction the staging
  performed first.

- **Liveness is filled for the first time in the `fin*` family**, and Step
  6 (`trailOutcomeVoidLivenessInstrument`) sits above Step 7
  (`trailOutcomeMatchedUnattributed`) in `trailClassifyRun`. Every prior
  `fin*` file ran at `MatchCount == 0`, so `readings.Liveness` was always
  empty and Step 6 was unreachable. Here it's non-empty, so a single
  `pinStateInstrumentFailed` would divert every non-finding arm to a
  `run-void-*` — exactly what AC2 forbids. `finStageAssertLiveness` runs on
  every arm to close that; the finding arm is immune only because Step 2
  returns first.

- **Two top-level tests, five arms, 0 SKIP**
  (`go test -race -tags e2e_realclaude -run '^TestFinStage' -v`).
  `TestFinStageRealHeldGroupFillsTheGather` — one staging, two arms
  differing in exactly the group the synthetic reap line names: naming the
  real staged group reaches `trailAdmitProof` →
  `trailOutcomeRunningAtTrailer`; naming `subject.Group + 1` (never a typed
  constant — collision-proof by construction, and unreportable-safe since
  `Group + 1 >= 3`) reaches `trailAdmitVoidGroupUnnamed` →
  `trailOutcomeMatchedUnattributed`, an *answer*, never a `run-void-*`. Also
  asserts AC4: `len(subject.Pinned) > 1` and `len(record.Entries) == 1` with
  `record.Entries[0].PGID == subject.Group` — the count of groups is not the
  count of rows, proven against a real process table.
  `TestFinStageRigHardcodingsCannotReachTheFinding` — its own staging,
  three arms: a **control** (the finding arm re-run, asserted first — a
  broken staging would otherwise let both traps pass while proving
  nothing), then `nil` stderr (varies stderr only) and the own-group key
  `[]int{syscall.Getpgrp()}` (varies pinned only, keeping the control's
  `namesTheGroup` stderr expression byte for byte). Both trap arms assert
  at the **`Admit`** layer (`trailAdmitVoidNoLine` /
  `trailAdmitVoidGroupUnnamed`) — never the outcome layer, since both
  hardcodings produce an `Admit` void but neither produces a void
  *outcome* — and additionally assert `outcome == trailOutcomeMatchedUnattributed`
  as a second, deterministic fabric alongside `outcome != trailOutcomeRunningAtTrailer`.

- **Prefix census clean at spec time**: `finStage[A-Z]` = 0 outside the new
  file; controls `fin[A-Z]` = 641, `trail[A-Z]` = 1297 (code review's
  re-run), both non-zero.

## Patterns established

- **An assertion pair can be jointly satisfiable by the failure it is
  supposed to exclude — run every mandated mutation a second time with the
  positive-path guard removed.** The trap arms' two assertions
  (`Admit == void`, `outcome != trailOutcomeRunningAtTrailer`) are both
  still true when `finStageAssertLiveness` is removed and a
  `pinStateInstrumentFailed` is forced into `Liveness`: Step 6 diverts the
  arm to a `run-void-*`, which satisfies both checks while publishing a
  void the trap never intended. The fix was a second, deterministic
  assertion (`outcome == trailOutcomeMatchedUnattributed`) rather than
  relying on one stochastic-ordering helper as the only fabric. See
  [`developer-1282-grade-mutations-per-line-not-per-exit-code`] in project
  memory.
- **A guard designed to go red under a mutation must survive its own red
  path.** `t.Fatalf` runs deferred functions (`runtime.Goexit()`), so a
  teardown built only for the happy path can deadlock exactly on the
  regression it exists to catch. The general shape — trace what every
  `defer` does when the assertion immediately above it fails, not just
  when the test passes — generalizes past this file. See
  [`architect-1282-red-path-must-be-fast-and-licences-expire`] in project
  memory.
- **A neighbouring file's "printing the whole struct is safe" licence is
  scoped to the fields the cited proof actually walked, not to the type.**
  `finding_run_gather_test.go`'s `TestFinGatherReturnsNoCapturedBytes`
  licenses whole-struct `%+v` on `readings`/`record`, but every row there
  runs at `MatchCount == 0`, so `Liveness` — and `pinStateOutcome`'s three
  string fields (`Detail`, `StateColumn`, `ToolStderr`) — was never
  examined by that proof. This file is the first to fill `Liveness`, so it
  forbids whole-struct printing and names scalars instead, even though the
  fields are independently safe (`pinStateArgs` never carries a command or
  environment column). Code review flagged the header's own may-name list
  extension as making the same argument shape it criticises in its
  neighbour (an allow-list argument from the shipped column list, not from
  a test) — non-blocking, but the next `fin*` file should inherit the
  *argument*, not the list.

## Lessons learned

- **Grade a mutation by which line reddens, not by the test's exit code.**
  Changing AC1's guard subject to `cmd.Process.Pid` (with `Setpgid` still
  dropped) left `TestFinStageRealHeldGroupFillsTheGather` entirely green —
  the guard is genuinely vacuous with that operand — while
  `TestFinStageRigHardcodingsCannotReachTheFinding` reddened, because the
  own-group arm collapsed into the finding arm and returned
  `trailAdmitProof` where it wants `trailAdmitVoidGroupUnnamed`. A run
  graded on the binary pass/fail of one test would have missed that the
  *other* test's red is the tell.
- **A test-file teardown copied from a neighbour can be strictly worse
  under a mutation the neighbour never has to survive.**
  `trail_run_rig_test.go`'s two-statement teardown (group kill + `Wait()`)
  is correct there because that file has no guard that reddens on a
  dropped `Setpgid`. This file's AC1 guard does, so the same two-statement
  shape would deadlock on its own red path; the third statement
  (`cmd.Process.Kill()`) is what this ticket adds and the reason it can't
  be copied wholesale.
- **Redaction licences do not transfer across a field's fill state.** See
  "Patterns established" above — restated because it's the concrete
  instance of a more general rule: before reusing "test X proves value Y is
  safe to print," check that X's own fixtures actually populated Y.
