# Ticket #1434 — A `terminal_reason` on a runner path that owes none reaches a gate value and a run outcome of its own (offline)

`trailGate`'s presence arm — `terminal_reason` on the line, observed runner path owes none — was
shipped by #1433 answering `trailGateOutOfContract`, whose documented meaning is *"the input is not
a reading."* That was wrong about what happened: `streamrunner.Run` tee-parses claude's stdout for
the watchdog and passes the bytes through unchanged
(`internal/agentrun/streamrunner/runner.go:177-179`), so the line **is** genuinely what the run
produced. Nothing is malformed and no caller erred — the record was a measurement filed as a defect.
#1433 shipped that residual stated rather than hidden, and named this ticket as its resolution in
both the arm's doc and its published `Detail` ("a value of its own is #1434").

This ticket is the #1417 step for the **presence** side (#1417 did the same promotion for the
absence side's owes-none case). The arm now answers a gate value of its own,
`trailGatePresentOwesNone`, and `trailClassifyRun` publishes a matching run outcome,
`trailOutcomeVoidReasonNotOwedByPath`, for it. Both closed sets grow in one commit — `trailGate`'s
value space and `trailClassifyRun`'s outcome space — because `trailClassifyRun`'s step-1 switch has
no default arm by design: an unhandled gate value doesn't fall through to step 2 (C4 forces `Admit`
empty for anything non-certifying), it falls through to steps 3-8 and awards a scan-side answer
about pyry from a record the gate itself says certifies nothing.

PR [#1438](https://github.com/pyrycode/pyrycode/pull/1438). Split from #1427 (itself re-filed from
the closed-NOT_PLANNED #1369). Blocked by #1433 (merged `a4506b2`). Blocks #1428 (the reason ×
reading matrix ticket). Security-sensitive (architect self-review PASS).

## Implementation

- **Two new unexported test constants, one per file.** `trailGatePresentOwesNone =
  "gate-present-reason-owes-none"` in `trailer_admissibility_test.go`'s gate const block, after
  `trailGateAbsentOwesNone`; `trailOutcomeVoidReasonNotOwedByPath =
  "run-void-reason-not-owed-by-path"` in `trail_run_outcome_test.go`'s outcome const block, after
  `trailOutcomeVoidPathOwesNoReason`. Both names were chosen and verified to pass a two-way
  `strings.Contains` containment check against every marker they could shadow (the drivers assert
  with `Contains`, not equality) — the union map's collision check alone would not have caught a
  substring relationship.
- **The arm's `Value` changes; nothing about its placement or trigger does.** `trailGate`'s
  presence-side `if against.Value == trailReasonPresentOwesNone` guard, its position after the
  budget arm and before the present-and-blank fall-through, and the fact that it consults exactly
  one of the reduction's answers are all unchanged from #1433. `Reason` stays empty, which keeps
  `trailClassifyRun`'s C2 green unamended and lets C4 force `Admit` empty.
- **The Detail rewrite lost the stale forward pointer and stayed under budget.** The shipped Detail
  dropped the ~69 B closing clause ("a value of its own is #1434") and measures **427 B** against
  the arm's 470 B ceiling (512 − the 42 B leak-sweep needle) — down from #1433's 445 B, with 43 B of
  spare. It still keeps the three phrases the presence driver's P1 row asserts (`"NEVER that pyry
  wrote it"`, the `streamrunner/runner.go:177-179` cite, `"never whether a process was alive"`) and
  still names the case constant `trailReasonPresentOwesNone` rather than embedding the reduction's
  395 B Detail, which is what buys the headroom.
- **The new gate value's doc carries the claim limit #1433 had already written for the arm** —
  moved onto the constant rather than restated: the line is not that path's documented healthy
  shape; it certifies nothing (`Reason` stays empty); **never** that pyry wrote it (cited to the
  passthrough as the *reason* — claude's own output can produce the same reading, and a value
  claiming more would let claude's output name pyry as its author); and it is a statement about what
  the trailer carried, never about whether a process was alive.
- **`trailGateOutOfContract`'s enumeration lost the sub-case this arm took**, six → five, with the
  landing-order history extended: #1419 split empty vs. absent, #1420 split absent three ways,
  #1417 took owes-none out of absence, #1433 added present-and-named as *out-of-contract*'s first
  presence case, #1434 takes it back out again. `trailGate`'s return-site total does not move —
  still eleven — because this ticket changes what a shipped site answers and adds none; the split
  moves from six `OutOfContract` / zero `PresentOwesNone` to five / one.
- **The step-1 arm and outcome doc mirror `trailOutcomeVoidPathOwesNoReason`'s shape**, re-argued
  for the opposite reading: not `trailOutcomeVoidNoTrailer` (a trailer *was* written — it's claude's
  own result line); not `trailOutcomeOutOfContract` (that's precisely the wrong sentence this ticket
  stops publishing); not its sibling `trailOutcomeVoidPathOwesNoReason` (same void-ness, opposite
  reading — absent-on-owes-none is that path's healthy shape, present-on-owes-none is not); still a
  void, because nothing was certified and there's no certified instant for an aliveness claim to be
  about.
- **New fixture helper `trailRunPresentOwesNoneReadings()`, a function and not a package-level
  `var`** — mirrors `trailRunAbsentOwesNoneReadings()`, driven by the real `trailGate` over
  `trailGateUsableScan()` at a streamrunner reading, `Admit` left zero (the shape a correct consumer
  produces and the only one C4 accepts). Must be a function because `trailRunReadings.Liveness` is a
  slice and `go test -race` runs this package's tests in parallel — a shared backing array would let
  one caller's mutation reach another's.
- **New composition test `TestTrailRunComposesUnderANamedReasonOnAPathThatOwesNone`**, mirroring
  `TestTrailRunComposesUnderAnAbsentReasonOnAPathThatOwesNone`: premise from the real gate producer
  (fatal if not `trailGatePresentOwesNone`), certifies-nothing check (`gate.Reason == ""`), the
  composition itself, and a controlled-experiment vacuity guard — the same two tails reach two
  *different* outcomes under a usable gate (control), then both collapse to the new outcome once
  only the gate answer is swapped (experiment). Neither shape the spec explicitly refused was built:
  no test hands the classifier `trailAdmitProof` beside the new value (C4/C5 reject that pair
  upstream of step 1), and no test asserts "cannot reach step 2" (unreachable for every
  non-certifying value, would pass against a build with no arm at all).
- **Mandatory new row in `trailRunCases()`** reaching the new outcome — `TestTrailClassifyRun`'s
  coverage loop errors on any `trailRunOutcomeValues()` member no row reaches, so this was not
  optional and not covered by the composition test alone (the same trap #1417 hit, per its own row
  comment).
- **Both closed sets' every count re-derived from the set, both directions**: gate space six → seven,
  non-certifying four → five, outcome space twelve → thirteen (nine → ten voids), union map
  thirty-seven → thirty-nine, and downward `trailGateOutOfContract`'s sub-cases six → five with every
  consumer of that count (the absence driver, the presence driver, the runner-path companion, the
  leak sweep's non-vacuity precondition) re-derived rather than adjusted by one.
- **The presence driver's argument inverts, not just its numbers.** Before this ticket, the value
  was "a precondition on two rows and never the discriminator" (P1 and the present-and-empty arm
  both answered the same `trailGateOutOfContract`, so only the Detail could tell them apart). After
  this ticket exactly one arm answers the new value, so on P1 the value **is** the discriminator —
  rewritten in `TestTrailGateNamesWhichAbsenceCaseFired`'s shape (precondition on one row,
  discriminator on the other) rather than renumbered. Same inversion applied to the runner-path
  companion's want map (row 1 now wants `trailGatePresentOwesNone`) and its message.
- **Residual sweep run in three forms** (number-words, numerals, ordinals) over the whole
  `internal/e2e/realclaude/` package, since `make check` cannot compile any file here
  (`//go:build e2e_realclaude`, no such tag on the standard gate) — an ordinal like "the third of
  them" or "that fourth value" is a live positional claim a number-word sweep alone would miss. Three
  consumers outside the pair were affected: `finding_trailer_evidence_test.go`'s
  `len(distinct) != 19 → 20` (a hard red, not just prose — `finTrailerOutcomeValues()` appends the
  run-outcome and staging spaces), several files' prose "twelve" → "thirteen", and
  `trail_ptyrunner_composition_test.go`'s claim about which value the presence arm reaches under a
  streamrunner reading.
- **Both mandated mutants demonstrated red under `go test -overlay`, not asserted**: deleting the
  step-1 arm makes the composition test read `run-matched-not-attributed` — the scan-side answer the
  arm exists to suppress, one step past the retired "falls through to step 2" shorthand; making the
  arm certify a reason reddens the presence driver's P1 `wantReason` assertion (and, as code review's
  NIT found, three further tests beyond the "sole red" the pre-#1434 doc claimed — `trailRunCases()`'
  new row quotes C2's own Detail verbatim in the red).

## Patterns established

- **A stale byte figure beside a `<=` assertion passes silently.** The headroom tests assert
  `len(Detail)+needle <= cap`, never equality, so three sites carrying the old 445 B figure stayed
  green while the shipped Detail measured 427 B. Re-measured via an overlay-injected probe file (no
  worktree writes) and corrected all three call sites.
- **Cite re-derivation needs prose-normalised pairing, not "line unchanged from `main`."** Keying
  re-derivation on an unchanged cite line only survives one pass — the pass itself edits those lines,
  so a second run classifies them all as new and does nothing. Pairing on prose with `:\d+` stripped
  is re-runnable from any state, which matters because a later rewrap shifts targets again and the
  sweep has to run last.
- **Content-equality re-derivation (`main@old == branch@new`) preserves pre-existing cite drift on
  purpose.** Deriving each cite from its `main` number through a `main`→worktree map keeps cites
  that were already wrong exactly as wrong, rather than moving them somewhere new — that's what
  separates PR-created staleness from inherited debt and keeps the inherited kind out of a given
  ticket's scope.
- **Bare `(:NNN)` cites resolve by named symbol first, last-named-file only as fallback.** Two
  MUST FIXes in the first code-review round were bare cites that inherited the *wrong* file because
  a filename happened to sit to their left; both were correct on `main` and got moved anyway. A
  second sweep pass using the corrected method found two more of the same class the first pass
  missed. Auto-derivation cannot reach a cite inside newly written prose at all (no `main` counterpart
  to pair against) — those need a separate fuzzy pass plus a hand check.

## Lessons learned

From the PR body's own "Lessons learned" section (developer):

- **A stale byte figure beside a live assertion passes silently** — see Patterns above; this is the
  concrete instance (445 B carried forward, shipped Detail measured 427 B).
- **The cite sweep needs prose-normalised pairing, not "line unchanged from main"** — see Patterns
  above.
- **Content-equality re-derivation preserves pre-existing cite drift, and that is correct** — see
  Patterns above.
- **Auto-derivation cannot reach a cite inside newly written prose.** Numbers copied from the ticket
  body into new paragraphs (C2, C4) were correct at spec time and stale on landing, invisible to any
  content-pairing pass since the surrounding prose has no `main` counterpart.

From code review (one FAIL → rework → PASS):

- **Bare-cite resolution by last-named-file, not named symbol, is this family's most persistent
  failure mode.** Two MUST FIXes (`finding_trailer_evidence_test.go:272`, `finding_run_record_test.go:889`)
  were bare `(:NNN)` cites whose subjects lived in files this PR did not touch, moved anyway because
  a different file's name sat to their left. Re-running the sweep with the corrected method (resolve
  by named symbol first) found two more of the same class in `finding_run_gather_test.go` that the
  original pass missed.
- **A "sole red" claim in a mutant matrix needs re-measurement when a row's precondition changes.**
  The doc claimed C2 was "still a contract here rather than an observed red" because the one fixture
  driving the arm pre-asserted `Reason == ""` — but `trailRunCases()`'s new row drives the same
  helper without that pre-assertion, so the certify-a-reason mutant reddens four tests, not two (C2's
  own Detail appears verbatim in one of the new reds). Fixed by rewriting the paragraph to match the
  measurement rather than adjusting only the count.
