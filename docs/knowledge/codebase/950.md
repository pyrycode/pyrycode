# Ticket #950 — guard test: every inbound v2 wire type must have a registered handler

Structural regression guard for the #949 failure class: a wire type can be
fully defined (constant, payload, registry op) yet dispatch nowhere, falling
through to `protocol.unsupported` with no test catching it. This ticket adds
one test that makes that permanently impossible to ship silently — zero
production code changes.

## Implementation

- `cmd/pyry/relay_guard_test.go` (new, 374 LOC, package `main`, plain `go
  test` — no build tag). `cmd/pyry` is the only package that can see all
  three inputs (imports `internal/protocol` + `internal/relay`, constructs
  the `Handlers` map), so the guard cannot live lower.
- **Mechanism: AST-read the real wiring, not a re-declared shadow of it** — a
  shadow list could drift exactly the way the dispatch map did in #949.
  `go/parser` + `go/ast` extract three sets straight from source, keyed by
  **constant name** (e.g. `"TypePromoteConversation"`, the AST identifier)
  so no name↔value bridge is needed anywhere:
  - `allAppTypes` — every `Type*` const in `internal/protocol/codes.go`.
  - `mapHandlerTypes` — keys of the `Handlers:` map literal in
    `cmd/pyry/relay.go` (surface #1, consulted by `dispatch.Route`).
  - `switchTypes` — `case protocol.Type*:` labels in
    `V2SessionManager.dispatchAppFrame`'s switch
    (`internal/relay/v2session.go`, surface #2, runs *before*
    `dispatch.Route`).
- Two hand-classified lists (`inboundTypes`, `excludedTypes` tagged
  `reply`/`push`/`handshake`/`v1-legacy`) plus four set assertions:
  1. **Coverage** — `inboundTypes ⊆ mapHandlerTypes ∪ switchTypes`; the
     actual point of the ticket, names the offending type on failure.
  2. **Reverse tie** — `mapHandlerTypes ∪ switchTypes ⊆ inboundTypes`; a
     type wired into either surface but missing from the hand-list fails,
     forcing the classification to track new wiring.
  3. **Totality tie** — every `allAppTypes` name is in exactly one of
     `inboundTypes` / `excludedTypes`; an unclassified constant fails
     "classify it inbound or excluded", closing the AC #2/#3 silent-new-type
     hole.
  4. **Surface-located, or loud** — asserts exactly one `Handlers` literal
     and one `dispatchAppFrame` switch were found; a moved/renamed surface
     fails loudly rather than silently extracting zero types.
- All four failure modes report a **sorted, deduped** list of offenders per
  run, not one-per-run.

## Audit deliverable (AC #4)

Ran against `main`: 50 app constants → 21 inbound (12 map-dispatched + 9
switch-intercepted), 29 excluded. **Every inbound type already covered — no
gaps beyond `promote_conversation`, already fixed by #949.** No follow-up
tickets filed. Two borderline calls made explicit in the classification
comments:
- `TypeHello` — phone→binary, but consumed by the auth first-frame gate
  (`AuthenticateFirstFrame`), never reaches `dispatchAppFrame` — classified
  `handshake`, not inbound.
- `TypeBackfillSince` — a v1 inbound verb with no v2 handler — classified
  `v1-legacy` (retiring under #913), not flagged as a v2 gap.

## Patterns established

- **AST-read-the-real-thing over shadow re-declaration** for any future
  drift-prone coverage guard: extracting map keys / switch case labels
  directly from source is what makes the guard immune to the same class of
  drift it's guarding against. See [`compat_test.go`](../../internal/protocol/compat_test.go)
  for the sibling v1/v2 partition guard this one modeled its
  totality-tie idiom on.
- Keying every extracted set by **AST identifier name** rather than wire
  string value eliminates a name↔value bridge between extractors and
  hand-lists — reusable whenever a guard compares Go source structure
  against a hand-classified list.

## Lessons learned

- AST-reading the real wiring (map keys + switch case labels) instead of
  re-declaring a shadow list is what makes a guard drift-proof — a
  re-declared list drifts exactly the way the dispatch map did in #949.
  Keying every set by the constant *name* rather than the wire value lets
  all three extractors and both hand-lists compare directly with no
  name↔value bridge.

## Security review

**Not security-sensitive.** Read-only enumeration/coverage assertion over
existing type tables and dispatch surfaces — no untrusted content handled,
no policy set, no crypto touched, and (per design) the live
`dispatchAppFrame` interception switch is never refactored, only parsed.

## Out of scope

- A third inbound dispatch surface would need its own AST extractor unioned
  into `registeredTypes` — the guard doesn't auto-discover new surfaces, but
  a verb dispatched only through one fails the coverage assertion (#1),
  forcing a maintainer here.
- Refactoring `dispatchAppFrame`'s switch into an enumerable table (rather
  than parsing it as a switch) was explicitly left out — doing so would be
  a live-dispatch refactor on an internet-exposed surface and
  security-sensitive in its own right, per the ticket's sizing note.
