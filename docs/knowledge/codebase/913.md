# Ticket #913 — remove the v1 relay dispatch branch + `PYRY_MOBILE_V2` from `startRelay`

Deletion ticket, `security-sensitive`. Collapses `startRelay`'s
`if w.v2Enabled { …v2… } else { …v1… }` into an unconditional v2 (Noise_IK) leg —
the daemon now speaks only Mobile Protocol v2. `PYRY_MOBILE_V2=0` previously flipped
the daemon onto a wire no shipping client speaks (ADR 024's hard v2 cutover, ADR
025's 2026-06-22 amendment removed capability negotiation); the "escape hatch"
restored nothing, so removing it drops dead code rather than a live fallback. This
is the **startRelay-level** production slice of the v1 retirement; later slices
retire `internal/dispatch`'s v1 `Dispatcher`/`FirstFrameGate` and
`relay.AuthenticateFirstFrame`/`Token` (both exported, no `staticcheck` forcing
function, deferred out of this ticket).

Written against post-#917 (`relayWiring` params struct). Prerequisites #941/#942
(v1 e2e retirement) and #917 both closed before this landed.

## Implementation

- `cmd/pyry/main.go` — removed the `PYRY_MOBILE_V2` env read + its comment block,
  and the `v2Enabled: v2Enabled,` field assignment in the `relayWiring{…}` literal.
- `cmd/pyry/relay.go` — dropped the `v2Enabled` field off `relayWiring` (and its
  struct-doc mention); collapsed `startRelay`'s branch to the unconditional v2 leg
  (log the v2 selection, call `startRelayV2`, `conn.Close()`+return on error, else
  set `legCleanup` to the close+drain closure). The v1 `else` — `dispatch.New`, the
  11 `d.Register` calls, the assistant-turn bridge wiring, the dispatcher/forwarder
  goroutines — is gone. The shared `conn.Wait()` classifier (4409-conflict →
  `shutdown()`, ctx-cancel → debug, other terminal error → warn) and the final
  `cleanup` are **preserved verbatim** — the v2 leg inherits that contract
  unchanged. Deleted `authGate` (`relay.go:26-49`), the cmd-local closure bridging
  `dispatch.FirstFrameGate` → `relay.AuthenticateFirstFrame`; its sole caller was
  the deleted v1 branch.
- Deleted `cmd/pyry/assistant_turn.go` (the coarse v1 assistant-turn bridge:
  `assistantTurnQueueSize`, `connBroadcaster`, `assistantTurnEmitter`,
  `newAssistantTurnEmitter`, `startAssistantTurnBridge`) and
  `cmd/pyry/assistant_turn_test.go` — but only **after** relocating what they still
  fed:
  - `cursorReader` (the interface, still satisfied by `newInteractiveTurnEmitterV2`
    and `activeConversation.CurrentConversation()`) moved to
    `interactive_turn_v2.go`, its surviving consumer's file.
  - Three test helpers moved to `interactive_turn_v2_test.go`: `discardLogger()`
    (used by 8 other `cmd/pyry` test files), `stubCursor`/`.set()`, and
    `testConvID` — a **third** shared helper the ticket body's AC-4 didn't name
    (it said "the two shared test helpers"; there were three). `testChunk`, the
    const-block sibling of `testConvID`, was not shared and was deleted with the
    file rather than relocated into disuse.
- Net: 6 files touched, 525 lines deleted / 59 added. No call-site edits anywhere
  else — every relocated symbol is referenced by name within `package main`.
- No import churn in `relay.go`: `dispatch`/`protocol`/`handlers` are still used by
  `startRelayV2`, so the compiler needed no pruning.

## Patterns established

- **Fused-slice removal when a dead branch's sole caller relationship forces
  co-deletion.** The v1 `else` branch was the only production caller of both
  `authGate` and `startAssistantTurnBridge`; leaving either behind after deleting
  the branch trips `staticcheck` U1000 on an unexported symbol. When a ticket's
  ratified scope proposes splitting such a removal, `staticcheck`'s U1000 on
  cmd-local (unexported) symbols is itself the argument for fusing the slices —
  see [[po-913-v1-retire-tests-first-then-fused-removal]].
- **Relocate-before-delete for symbols a doomed file still shares with survivors.**
  Two distinct hazards on the same file: (1) a production interface
  (`cursorReader`) another live package-`main` file still implements/consumes, and
  (2) test helpers a `git rm` would silently take down with it, breaking the whole
  `cmd/pyry` test package compile rather than failing a single test. Both require
  grepping every symbol the doomed file defines for surviving referents *before*
  deletion, not just the ones the ticket body names — the spec caught a third
  shared test const (`testConvID`) the issue text omitted.
- **Deleting a first-frame auth gate is safe when it only gated a now-dead
  consumer.** `authGate` fed the v1 dispatcher; the surviving `startRelayV2`
  authenticates the Noise_IK handshake before any verb dispatch independently, so
  no unauthenticated path opens. Security-sensitivity here tracked the *deletion
  surface* (an auth gate on the internet-exposed relay), not a design change — the
  same "sec tracks design, not lineage" reasoning as
  [[security-sensitive-label-tracks-design-not-lineage]].

## Lessons learned

- The architecture spec flagged that the ticket body's AC-4 said "the two shared
  test helpers" when the file actually defined three surviving-consumer symbols
  (`discardLogger`, `stubCursor`+`.set`, and `testConvID`). Relocate-before-delete
  tickets should grep the doomed file's full symbol list against the rest of the
  test package rather than trusting the issue body's named count.
