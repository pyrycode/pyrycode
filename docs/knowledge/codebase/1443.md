# Ticket #1443 — Name the instant in the run classifier's certifies-nothing statements

`trail_run_outcome_test.go` predates #1440's `trailEstablishSighting`. Six of its
statements foreclose a claim on the grounds that nothing was certified, written
when only the **declared-finished** instant existed in this family — since #1440,
a second instant exists (**trailer-sighting**, whenever the trailer was sighted on
pyry's stdout), and the blanket/ambiguous phrasings would foreclose a
sighting-based finding from a file that cannot see it. This ticket makes each
statement name the instant it is about and the claim it forecloses. No verdict
moves: no value joins any space, no arm moves, no input is read that was not read
before — this is a prose-precision and test-hardening ticket, not a behavior
change.

PR [#1445](https://github.com/pyrycode/pyrycode/pull/1445). Split from #1437.
Consumer of #1440's vocabulary (`trailSightingInstantClause`,
`trailEstablishSighting`). Security-sensitive (architect self-review PASS; code
review PASS, two NITs, no rework).

## Implementation

- **Two defect shapes, six sites, two amendment strategies.** Shape A (`:361`,
  `:531-532`) is a blanket — "no certified instant for **any** claim" — and gains
  only the instant name ("no certified **declared-finished** instant"), which
  scopes the foreclosed claim to declared-finish-shaped claims without touching the
  claim clause itself. Shape B (`:167-169`, `:188-190`, `:568`, `:582`) already
  names the declared-finished instant but forecloses a claim that reads as
  unqualified or two-way ambiguous once a second instant exists — these gain the
  qualifier `aliveness-at-declared-finish` on the claim instead. All six are
  **comments**, never runtime-observable, so none is pinned by a test; they are the
  reviewed-by-reading half of AC3.
- **`trailDeclaredFinishInstantClause`** — a new unexported `const string`,
  appended after the file's prior last line (old `:1678`) rather than declared
  beside the arms that use it. Fixed prose, zero interpolation: *"Nothing is
  certified, so there is no declared-finished instant for an
  aliveness-at-declared-finish claim to be about."* Landed at **117 bytes**, not
  the spec's recommended 122 — the developer used the ticket's own open-question
  latitude to shorten it, re-running the arithmetic against the tightest arm
  (`trailGatePresentOwesNone`: 472 − 89 + 118 = 501 B, 11 B free) rather than
  treating the spec's number as fixed. Mirrors `trailSightingInstantClause`'s shape
  (`trail_sighting_liveness_test.go:216`) but names the *other* instant and is
  likewise not a member of any value space — it does not join
  `TestTrailAdmissibilityConstantsAreClosed`'s union map, since a clause is prose,
  not a value a consumer can hold.
- **Three step-1 Details exchange, never append.** `trailGateNoTrailer`,
  `trailGateAbsentOwesNone` and `trailGatePresentOwesNone` each replace a
  hand-written sentence saying the same thing with the shared clause, spliced in
  place. Rendered against `trailDetail`'s silent 512-byte cap: 290 / 490 / 501
  bytes. Appending instead of exchanging was arithmetically impossible on the two
  `OwesNone` arms (461 B and 472 B pre-change, both with under 89 B of headroom) —
  the cap forces the exchange, and this was proved as a mutation rather than argued
  as prose (see below).
- **The budget-fired carve-out is deliberately untouched**, and its reason is now
  recorded rather than left silent. `trailOutcomeVoidBudgetFired`'s doc (`:132`)
  and its Detail (`:552`) keep the bare phrase `aliveness-at-trailer` because that
  arm certifies a terminal reason and the reap provably preceded the trailer write
  — both instants are foreclosed there, not neither, so qualifying the phrase would
  be wrong. Both sites gained `, at either instant` in place, and the new sweep
  test (below) carries the carve-out in full in its own doc.
- **New file `trail_run_instant_clause_test.go`** (`//go:build e2e_realclaude`),
  keeping both new tests off the zero-displacement file's line count:
  - `TestTrailRunCertifiesNothingArmsNameTheInstant` (AC2) — drives
    `trailRunCases()` and asserts the clause is present on exactly the three
    certifies-nothing arms' Details and absent from every other row — conditional
    on the arm, unlike #1440's unconditional per-row check, because here three of
    thirteen outcomes carry it rather than every arm of one predicate.
  - `TestTrailRunBareAlivenessAtTrailerIsBudgetFiredOnly` (AC3) — reads
    `trail_run_outcome_test.go`'s own source from the package directory and
    requires the retired bare phrase to appear **exactly twice**, both on a line
    that also carries the budget-fired argument's shared prefix (pins identity,
    not just count). The needle is assembled from parts rather than written as one
    literal, so the sweep's own source can't accidentally match itself.
- **Zero displacement, verified not assumed.** Every hunk at or before the file's
  old last line adds exactly as many lines as it removes; the only unbalanced hunk
  is the trailing const append. None of the ~100 inbound line-number cites from 16
  sibling files moved, and `docs/knowledge/features/e2e-realclaude.md` — which
  carries no cite into this file — needed no edit.
- **No verdict moves.** Thirteen outcomes, unchanged membership and size;
  `trail_ptyrunner_composition_test.go` passes unamended; the shipped truncation-
  marker per-row check (`:1098`, and the two composition tests at `:1367`/`:1510`)
  stays unweakened rather than duplicated.

## Patterns established

- **An additive-clause AC can be arithmetically impossible — render the strings and
  subtract before choosing append vs. exchange.** Two arms had 51 B / 40 B of
  headroom under a silent 512-byte cap; appending an 80+ B clause would overflow
  both. When the site already spends a hand-written sentence saying the same thing
  the clause will say, the work is an **exchange**, not an addition — this was
  identified at the PO stage ([[po-1443-an-additive-clause-ac-can-be-arithmetically-impossible]])
  and carried through spec and implementation unchanged.
- **The spec's own arithmetic is a floor to re-run, not a number to inherit
  verbatim.** The developer shipped a 117 B clause against the spec's recommended
  122 B, because the ticket's *Open questions* section explicitly permitted
  different wording provided the arithmetic against the tightest arm was re-run —
  and it was, landing 11 B free rather than the spec's stated 6.
- **Converting a spec's arithmetic table into a mutation is worth doing when the
  underlying failure mode is silent.** The developer ran the spec's append-vs-
  exchange table as a `go test -overlay` mutation (`trailGatePresentOwesNone`
  appending instead of exchanging → 590 B → silently truncated → caught by the
  shipped per-row marker check) rather than leaving it as a comment. Code review
  endorsed this explicitly: "arithmetic in a comment goes stale and a red test does
  not."

## Lessons learned

From the PR body's own "Lessons learned" section (developer):

- **A source-reading sweep is invisible to `go test -overlay`.** The overlay
  substitutes what the compiler sees, not what `os.ReadFile` opens at runtime, so
  `TestTrailRunBareAlivenessAtTrailerIsBudgetFiredOnly` (which reads its own
  package's `.go` source) cannot be mutation-tested via overlay at all — it needs a
  real on-disk edit and restore. Every other mutation in this ticket ran
  overlay-only with zero worktree writes; this is the one shape that can't. Worth
  adding to [[code-review-mutation-test-via-go-overlay]] as a named exception, not
  just a one-off note.
- **Greedy re-wrapping is optimal for line count, which makes "does this reflow fit
  in the same number of lines?" decidable rather than a matter of trying.** Two of
  the seven amended paragraphs provably could not absorb their qualifier at the
  same line count at any width ≤ 84 columns — one was fixed by the spec's shorter
  qualifier text, the other by an `and not` → `,` punctuation swap. Measuring first
  turned what looked like a zero-displacement constraint depending on luck into
  arithmetic.
- **An unbreakable identifier can eat a paragraph's whole reflow budget.**
  `TestTrailAdmissibilityConstantsAreClosed's` (42 characters, can't wrap mid-word)
  forced a short line that wasted ~31 columns in the step-1 comment, which is why
  that comment needed 84 columns of width rather than the file's usual 82.

From code review (PASS, two NITs, no rework round):

- A bare `runner.go:492-503` cite in the *new* file resolves correctly
  (`internal/agentrun/ptyrunner/runner.go:492`) but relies on anchoring context
  (`:23`, `:187`) that only exists in `trail_run_outcome_test.go`, not in the file
  that now also carries the cite. Left as a NIT: one word
  (`ptyrunner/runner.go:492-503`) would close it, not worth a rework cycle on its
  own.
- The AC3 sweep's same-line coupling (needle and argument-prefix must share a
  source line) is the spec's deliberate design and does pin identity rather than
  just count — but both exempt sites sit one paragraph-wrap away from tripping it
  on an unrelated future reflow. Recorded as a known fragility, not fixed now.
- One verification the PR flagged as **not run**: on-disk mutation of the AC3
  sweep itself (the dispatcher denied the restore step, `git checkout --`, mid-PR).
  Code review did not require a retry — the sweep's non-vacuity is structural
  (exactly two sites required, so an empty or failed read reddens at zero; a read
  error is `t.Fatalf`), independently re-verified by the reviewer reading the same
  file and getting the same two line numbers.
