# Ticket #880 — Durable archived state on conversations, surfaced in the list read

Split from #821. Adds a durable manual-archive flag to `Conversation` (distinct from the
existing auto-archive `Sweep`, which permanently `Delete`s idle discussions) plus its read
surface in `list_conversations`. The verbs that flip the flag (`archive_conversation` /
`unarchive_conversation`) are #881, which depends on and consumes this slice's
`Registry.SetArchived` primitive.

## Implementation

Four additive touch points, no renames, no signature changes, no consumer cascade:

- **`internal/conversations/conversation.go`** — new `Conversation.IsArchived bool`
  `json:"is_archived,omitempty"`, placed after `IsPromoted`. `omitempty` is deliberately the
  opposite of `IsPromoted`'s tag: the AC1 contract is "absent key decodes as active, with no
  migration step," which `omitempty` satisfies in both directions — a pre-#880 row with no
  `is_archived` key decodes to `false` (active), and an all-active registry re-serializes
  byte-identical to its pre-#880 form. Only genuinely-archived rows gain the key.
- **`internal/conversations/registry.go`**:
  - `ListFilter` gains `IsArchived *bool`, mirroring `IsPromoted`; `List` adds the matching
    nil-check. When both fields are set on one `ListFilter`, they AND (orthogonal to the
    pre-existing "only `filter[0]` of multiple `ListFilter` args is consulted" variadic rule —
    code review flagged the two doc comments as easy to misread as contradictory; they aren't,
    left as a NIT).
  - New `Registry.SetArchived(id ConversationID, archived bool) bool` — modeled on
    `Delete`/`RebindSession`: lock, scan by `ID`, flip exactly `IsArchived`, return hit/miss; no
    `Save` (caller's concern, same convention as `Create`/`Update`/`Promote`/`Delete`/
    `RebindSession`). One `bool` arg both archives and restores — no separate `Archive`/
    `Unarchive` pair. The single-field flip is enforced structurally (the method has no way to
    touch another field), so #881's verb handler can't violate "must not change id, cwd, name, or
    session binding" even by accident.
- **`internal/protocol/conversations_read.go`** — `ConversationSummary.IsArchived bool`
  `json:"is_archived"`, **no** `omitempty` (opposite of the on-disk tag) — a client must read the
  flag on active rows too, to partition and count both sides.
- **`internal/relay/handlers/list_conversations.go`** — one line, `IsArchived: conv.IsArchived`,
  in the existing projection loop. The handler still calls `reg.List()` unfiltered — both active
  and archived rows surface, each tagged. No new read verb.

`Registry.SetArchived` has no production callers yet; #881 is the consumer.

## Patterns established

- **`omitempty` asymmetry between the on-disk and wire representations of the same boolean is a
  legitimate, deliberate choice** when the two surfaces have opposite defaulting contracts (disk:
  "absent = default, no migration"; wire: "client always needs both states"). Don't "fix" one to
  match the other for consistency — check the field's contract first. `IsPromoted` (no
  `omitempty` on disk) and `IsArchived` (`omitempty` on disk) coexist on the same struct for this
  reason; see the field comment in `conversation.go`.
- **A single-field mutator method is deterministic enforcement of a "don't touch other fields"
  constraint** — stronger than documenting the constraint on the caller. `SetArchived` is the
  third instance of this shape in the package (`Delete`, `RebindSession`, now `SetArchived`),
  reinforcing dedicated-method-over-`Update`-closure as this package's idiom for named-semantic
  mutations (`Update` stays the escape hatch).

## Lessons learned

- **A non-`omitempty` wire-key addition to `ConversationSummary` requires updating
  `internal/protocol/testdata/conversations.json`.** `TestConversationsPayload_RoundTrip`
  byte-compares against that fixture via whitespace-compaction only — no key re-sort — so a new
  field must be inserted into the fixture at the same position as the struct-field order. The
  spec's "no golden byte assertion on `ConversationSummary`" note (from `compat_test.go`) is
  about type-string freezing, not this round-trip fixture; the two are easy to conflate. Confirmed
  safe here because the fixture was updated in the same diff (`is_archived` inserted right after
  `is_promoted` on both rows).
