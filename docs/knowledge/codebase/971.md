# Ticket #971 — post-review comment hygiene sweep

Pure comment/doc-string sweep correcting three misleading comments flagged in
the 2026-07-15 review, so a reader (human or pipeline agent) reasons about the
*current* mechanism rather than a deleted or never-existing one. No behavior
change — 12 files touched, all edits are `//` comments or a package
doc-string. Spec: [`specs/architecture/971-comment-hygiene-sweep.md`](../../specs/architecture/971-comment-hygiene-sweep.md).

  `seedBootstrapRegistry` doc-comments) dropped an anticipatory, pre-#839

## Patterns established

- **Tree-wide grep as the AC, not a fixed file list.** The review's file
  enumeration for the `reconcileBootstrapOnNew` sweep was stale/incomplete
  (missed 2 of 10 files, one stale line number) — the ticket's AC was written
  as a tree-wide grep (`grep -rn reconcileBootstrapOnNew --include='*.go' .`)
  rather than trusting the enumerated list, which is what surfaced the full
  10-file set. Comment-hygiene sweeps sourced from a review's file list should
  re-derive the surface via grep rather than trusting the list verbatim.
- Confirms [[code-review-docs-completeness-grep-fragile-gofmt-align]]-adjacent
  practice: verification greps for this ticket were run architect-side and
  re-run post-edit, catching drift between review-time and edit-time state.
