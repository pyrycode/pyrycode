# Ticket #941 — Retire the no-handshake v1-transport e2e tests

Child A of the #939 split. The legacy v1 relay dispatch leg (`PYRY_MOBILE_V2=0`,
`/v1/server`) is being retired ahead of #913 (production v1-branch removal): no shipping client
speaks v1, and ADR 025's 2026-06-22 amendment removed the old-app support it existed for. This
ticket retires the subset of v1-transport e2e tests that need **no phone-handshake authoring** —
straight deletes where a v2 twin already covers the behavior, route-swaps for transport-agnostic
binary-leg tests, and relocation of the shared harness helpers those files happen to host. Sibling
#942 (blocked by this ticket) migrates the three phone-dependent files
(`per_conversation_eviction_test.go`, `respawn_after_eviction_test.go`, `register_push_token_test.go`)
that still consume the helpers relocated here.

Test-only — no production change, no security surface. 1 production-source file touched
(`internal/e2e/harness.go`, the relocation target); everything else is `_test.go`.

## Implementation

- **Deleted whole** (no coverage loss — each verb already asserted by a named v2 e2e test):
  `relay_roundtrip_test.go`, `relay_send_message_test.go` (envelope roundtrip / `send_message` →
  covered by `relay_two_phone_structured_test.go` + `relay_v2_*`); `relay_assistant_turn_test.go`
  (asserted the v1 coarse `message` fan-out, removed from the v2 path in #699 and replaced by the
  capability-gated structured stream); `relay_auth_test.go` (`TestRelay_AuthReject_4401`, 4401 close
  over v1 — the v2 twin `testV2BadToken`/`bad_token_4401` in `relay_v2_handshake_test.go` asserts the
  same 4401 close over Noise). `relay_base_url_test.go` also dropped: production `resolveDialURL`
  (`internal/relay/connection.go:162`) appends `/v1/server` for a bare base URL and this ticket may
  not touch production, so the e2e couldn't be re-targeted to `/v2/server` without leaving it
  selecting the v1 leg; `TestResolveDialURL` (`connection_test.go:585–629`) already covers the
  append/passthrough logic at the unit level, including the explicit-v2 passthrough case.
- **Relocated, not removed** — five helpers moved verbatim from their doomed hosts into
  `harness.go` (which carries the wider `//go:build e2e || e2e_install` tag, so it can host helpers
  used by both e2e and e2e_install test files): `shortHome`, `readPersistedServerID`,
  `relayTestLogger`, `recvEnvelope` (all from `relay_test.go`) and `mustJSON` (from
  `relay_auth_test.go`). Same-package move → zero call-site edits. `recvEnvelope`'s sole surviving
  caller post-delete is `per_conversation_eviction_test.go` (a #942 carve-out), and `mustJSON` has
  ~13 surviving callers — that's why staticcheck never flags either as unused (U1000) despite their
  original hosts being gone.
- **Route-swapped to `/v2/server`**: `TestRelay_4409` and `TestRelay_1011` in `relay_test.go` (which
  survives, reduced). Both dropped `PYRY_MOBILE_V2=0` from `extraEnv` and changed the relay flag from
  `.../v1/server` to `.../v2/server`. These assert the binary WebSocket close-code path (4409 → clean
  daemon exit + "server-id conflict" log; 1011 → transport reconnect-absorb, daemon stays alive), not
  the phone handshake — `fakerelay` routes `/v2/server` through the same `handleBinary`, and its
  `RejectNextBinaryWith4409`/`ForceCloseBinary`/`WaitBinary` hooks key on `serverID`, not path, so the
  behavior is identical over v2.
- **Reduced**: `relay_v2_daemon_test.go`'s `testV2DaemonDisabledDoesNotEngageV2` sub-test (asserted
  `PYRY_MOBILE_V2=0` selects the v1 path, replying a v1 `hello_ack`) is now
  `testV2DaemonDefaultEngagesV2` — the switch is left **unset**, the relay flag is `/v2/server`, and
  the assertion flips to: the daemon's Noise manager answers a `noise_init` with `noise_resp` (v2 is
  the default without opting in). Reused the file's existing `readInnerFrame` helper — no new
  handshake code. The doc comment cross-referencing the now-deleted `TestRelay_AuthReject_4401` was
  dropped with it; `TestRelayV2_Daemon`'s top comment now describes "unset → v2 by default" instead
  of the retired v1-first-frame-gate behavior. The two `PYRY_MOBILE_V2=1` round-trip sub-tests are
  untouched — they still pin the explicit-on behavior.
- **Negative guardrail (AC6)**: swept every `PYRY_MOBILE_V2=0` / `/v1/server` / `"v1"` hit across
  `internal/e2e/` and classified each. Two carve-outs are *expected* to still show v1 markers after
  this ticket, and are not regressions: (a) the three #942 phone-dependent files, and (b)
  `harness.go`'s `StartRotationWithRelay` — its `relayURL` param is caller-supplied and its
  `/v1/server` example doc-comment describes the route #942's phone tests still pass, so a literal
  `grep '/v1/server' internal/e2e/harness.go` still hits post-ticket by design. The fakerelay/fakephone
  harness plumbing (which still defines `/v1/server`/`/v1/client` routes for #942's use) is likewise
  untouched.

## Patterns established

- **Relocate-not-delete for shared test helpers with surviving-but-orphaned callers.** When a
  file hosting a shared helper is deleted for coverage reasons, check whether *other* surviving
  files still call the helper before deleting it too — moving it into the package's helper file
  (`harness.go` here) keeps every survivor compiling with zero call-site edits, since Go resolves
  same-package symbols regardless of which file defines them.
- **A negative "no v1 selection remains" AC scopes to *operative* selection, not incidental text.**
  Distinguishing "this file dials `/v1/server`" from "this file's doc-comment mentions `/v1/server`
  as an example for a caller that still needs it" is what let AC6 pass without breaking #942's
  still-in-flight phone-dependent tests — a relocation target that's touched but keeps
  sibling-owned references isn't a leftover v1 selection.
- **A bare-URL e2e test can be un-migratable to a route-swap when production itself hardcodes the
  old route for that code path.** `relay_base_url_test.go` couldn't move to `/v2/server` because
  `resolveDialURL`'s bare-URL branch structurally appends `/v1/server` until #913 changes production;
  the resolution was to drop the e2e test in favor of existing unit coverage, not to force a
  route-swap that doesn't reflect what the code actually does.
