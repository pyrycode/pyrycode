# Ticket #1025 — move debug-bundle streaming out of `v2session.go`

Fifth and final slice of the [#964](https://github.com/pyrycode/pyrycode/issues/964)
split of `internal/relay/v2session.go`, chained after
[#1021](1021.md) (handshake), [#1022](1022.md) (rekey), [#1023](1023.md)
(modal+queue), and [#1024](1024.md) (settings). Carves the
`request_debug_bundle` handling — the request handler, its deterministic
error-reply helper, its per-conn in-flight gate (#911), and the shared
error-message constant — into a new file in the same `package relay`. Pure
mechanical move: no exported-API change, no behaviour change, zero
call-site changes.

## Implementation

New file `internal/relay/v2session_debugbundle.go` (179 lines) now owns
four declarations, moved verbatim with their doc comments byte-for-byte:
`msgDebugBundleUnavailable` (const), `handleDebugBundleRequest`,
`debugBundleReplyError`, and `bundleInFlight`. `v2session.go` drops by 161
lines, from 2086 to 1925.

The cut was the single clean span `v2session.go:1273-1432` the architect
identified, bounded above by `snapshotReplyError` and below by
`SetReplaySource`, with nothing debug-bundle-unrelated interleaved —
confirmed by the diff, which touches only that one contiguous block plus
one collapsed blank line.

The `case protocol.TypeRequestDebugBundle:` dispatch arm in
`dispatchAppFrame` (`v2session.go:1041`, the caller) and the
`V2SessionConfig.DebugBundler` seam field (`v2session.go:593-607`) **stay
in core**, per the ticket's Technical Notes — same-package references, so
the move is transparent to both. `StreamBundle` was already split out into
`v2bundlestream.go` by an earlier slice and is untouched here.

Imports were compiler-forced to **zero net change** in the donor file,
exactly as the spec predicted: `context`, `encoding/json`, `time`, and
`internal/protocol` are all still used by the ~1900 lines remaining in
`v2session.go`, so its import block is unchanged. The new file imports the
same four packages for its own use — this is the inverse of #1022, where
`bytes` was used only by the moved code and the compiler forced its
removal from the donor.

## Patterns established

None new — the fifth and final confirmation of the #964 pure-move
discipline, closing out the parent split. Same variant as #1024: the
donor file's import set needed no edit at all, because every import the
moved block used was also used elsewhere in `v2session.go`.

## Lessons learned

None — the move went exactly as scoped in the architecture spec. Worth
reconfirming the theme across all five #964 slices, here at its strongest:
the moved code handles the plaintext debug bundle (recording + logs) — the
highest-value secret surface in the system, streamed only over the
AEAD-sealed push path (#911, #812) — and it *still* correctly stayed **not
security-sensitive**. Lineage (what the code touches) is not the same
thing as design surface (what changed): a pure same-package move audits to
zero new design, no matter how sensitive the moved code's original design
was. See [[security-sensitive-label-tracks-design-not-lineage]].

## Verification

`go build ./internal/relay/...` clean; `make check` green (vet, `-race`
test incl. `internal/relay`, staticcheck, substrate-guard, hermetic e2e —
live-claude e2e legs SKIP on missing credentials, unaffected by this
diff). The diff touches exactly the two intended files (`v2session.go`,
`v2session_debugbundle.go`) plus the architect's spec doc — no other file
in the tree changed, and `v2session_debugbundle_test.go` (pre-existing)
was left byte-for-byte untouched, confirming the move is transparent to it
(AC #3).
