# Ticket #1081 — Config toggle `interactive_runner` + stream-json turn drain wiring

Adds the operator-facing `interactive_runner` config switch (`~/.pyry/config.json`) and turns the
stream-json interactive path (`internal/streamsup`) on end-to-end. Every seam it wires was already
merged — `sessions.Config.RunnerFactory` (#1077), `newStreamRunnerFactory` (#1109), and
`startStreamTurnDrainV2` (#1098) — so this ticket is pure assembly: one config field, one startup
selector, and one parallel relay-leg branch. No new logic, zero new exported types. Blocked-by #1131
(the last typed-nil `w.sup` guard), which merged first.

## Implementation

- **`internal/config/config.go`** — additive `InteractiveRunner string \`json:"interactive_runner"\`` field,
  no `DefaultConfig` entry (absent → `""` → PTY). `Load` stays parse-only, matching the `DebugCapture`
  precedent — enum validation happens at the composition root, not here (the accepted set maps to
  factories the leaf `config` package can't import).
- **`cmd/pyry/main.go`** — `selectInteractiveRunner(cfg, logger) (sessions.RunnerFactory, *streamTurnSink, error)`:
  `""`/`"pty"` → `(nil, nil, nil)` (rollback path); `"stream-json"` → builds exactly **one**
  `newStreamTurnSink`, returns it alongside `newStreamRunnerFactory(sink)` so the caller threads the same
  instance two ways; anything else → an error naming the offending value and both accepted tokens (AC4).
  Called in `runSupervisor` right after `config.Load`, **before** `sessions.New` — an invalid value
  aborts startup before the pool is built, no silent PTY fallback. The factory feeds `sessions.Config.RunnerFactory`;
  the sink feeds the new `relayWiring.streamSink` field.
- **`cmd/pyry/relay.go`** — `streamSink *streamTurnSink` on `relayWiring`; `w.streamSink != nil` is the
  stream-mode discriminant for three raw `w.sup.State()` readers that would nil-deref on the typed-nil
  bootstrap supervisor in stream mode:
  - `snapshotUsage` build — gated `w.streamSink == nil && w.claudeSessionsDir != ""`; stream mode leaves
    it `nil` (the `screen_snapshot` handler reports zero usage, coherent with `screenSnapshotterOrNil`
    already returning nil in stream mode).
  - The shared PTY-interactive-streams `if w.bridge != nil && w.claudeSessionsDir != ""` gate became a
    three-way branch: `w.streamSink != nil` (stream mode — see below) / `else if` the unchanged PTY arm
    (`startInteractiveTurnStreamV2` + `startInteractiveModalStreamV2`) / `else if w.bridge != nil` (unchanged
    no-sessions-dir log).
  - **Stream-mode branch**: builds `newInteractiveTurnEmitterV2(w.active, mgr, logger)` +
    `mgr.SetReplaySource(emitter.ring, w.active.CurrentConversation)` — byte-identical construction to the
    PTY path, only the feeder differs — then `startStreamTurnDrainV2(ctx, w.streamSink, emitter,
    activeSession, logger)`. Does **not** gate on `w.bridge`/`w.claudeSessionsDir`: the drain consumes
    parsed `turnevent.Event`s from the sink, not a PTY bridge or on-disk transcript. Only the turn stream
    needed a stream-mode replacement — the PTY modal stream's analogue (the #1080 approval bridge) was
    already wired unconditionally.
  - New `boundSessionIDForActive(active *activeConversation, convReg *conversations.Registry) (sessionID
    string, ok bool)` — the drain's AC2 follow-active scoping gate. Resolves `active.CurrentConversation()`
    → `convReg.Get(...)` → `conv.CurrentSessionID`; returns `("", false)` on no active conversation,
    unknown conversation, or an unbound (`CurrentSessionID == ""`) conversation — mirroring the #678
    isolation guard `resolveBoundRunner`/`resolveBoundSession` enforce. Deliberately skips `pool.Lookup`
    (unlike `boundHost`): a stale tag matches no live producer, so forwarding nothing is already the
    fail-closed outcome, with no `*sessions.Pool` dependency dragged into `relay.go`.
  - `streamDrainCleanup` joins the returned `cleanup` closure alongside `streamCleanup`/`modalStreamCleanup`,
    guarded non-nil, before `<-mgrDone`.

## Patterns established

- **Key the mode discriminant off the object the branch actually needs, not off the typed-nil check
  it's logically equivalent to.** `w.streamSink != nil` and `w.sup == nil` are equivalent here (a stream
  runner's `Session.Supervisor()` genuinely returns nil), but branching on the sink is self-documenting
  and the sink is what the branch consumes anyway.
- **A resolver that "deliberately skips a lookup" is a legitimate fail-closed design**, not a missing
  guard — `boundSessionIDForActive` skips `pool.Lookup` because the fail-closed behavior (drop on
  mismatch) is identical whether the stale id is looked up or not, and skipping avoids an unnecessary
  `*sessions.Pool` import in `relay.go`. Code review confirmed this rather than flagging it as an
  oversight.
- **Three-way mode branch over refactoring the shared PTY gate.** The spec's guidance to "prefer a clean
  parallel branch over refactoring the PTY path" held: the PTY arm is untouched line-for-line inside its
  `else if`.

## Lessons learned

From the PR body (#1134):

- The stream-mode discriminant is best keyed off `w.streamSink != nil` rather than `w.sup == nil`:
  `bootstrap.Supervisor()` returns a genuine nil `*supervisor.Supervisor` for a stream runner, so the two
  are equivalent, but the sink is the object the branch needs anyway and reads self-documenting. A
  three-way `if streamSink != nil / else if bridge && dir / else if bridge` branch keeps the PTY path
  untouched (no refactor).

## Known gap filed as a follow-up (not fixed here)

The spec's Open Question 1 (also flagged in its Security review as a SHOULD-FIX, security-benign
finding): the stream-json turn-event sink tags each event with the runner's **construction-time**
`SessionID`; a stream-mode `new_session` (`RestartFresh`, #1124/#1125) rebinds `conv.CurrentSessionID` to
a fresh id but never retags the Parser. After that rotation, `boundSessionIDForActive` returns the new id
while events stay tagged with the old one, so the drain's scoping gate drops everything for that
conversation until the daemon restarts. **Fail-closed** — an unmatched tag forwards nothing, so this is
an availability/functional gap, not a confidentiality one. Filed as **#1133** (rotate the Parser's tag on
`RestartFresh` — a `internal/streamsup`/`stream_turn_drain.go`-side fix, out of this ticket's pure-wiring
scope). Noted for #1082's e2e coverage.

## Security review

Reviewed as `security-sensitive` (first live wiring of the stream-json outbound turn-event path to
authenticated remote clients). Architect + code-review both passed: `boundSessionIDForActive` reads the
live follow-active cursor and is fail-closed on every ambiguous state; the factory and drain share
exactly one sink instance, correctly keyed per session; `SetReplaySource` is byte-identical to the PTY
path's session-scoped construction; all three typed-nil `w.sup` readers are structurally gated off in
stream mode (a mis-wire there would be an availability defect, not a disclosure); AC4's error path has no
silent PTY fallback and names only the operator's own non-secret config value. Full text:
`docs/specs/architecture/1081-interactive-runner-toggle.md` § Security review.
