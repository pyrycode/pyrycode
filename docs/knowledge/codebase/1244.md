# Ticket #1244 — Assert `turn_end{cancelled}` in the minted per-conversation PTY interrupt oracle

`TestRelayV2_PerConversationInterruptStopsRunningTurn`
(`internal/e2e/relay_v2_perconv_interrupt_test.go`) used to prove only that an
interrupt stopped the minted conversation's turn, never that it was *reported* as
an interrupt — `EventKindJsonlEndOfTurn` was the mapper's only `turn_end` source,
so tui-driver could not distinguish an interrupt-stop from a clean end.
[#1243](https://github.com/pyrycode/pyrycode/issues/1243) (merged 2026-07-30, PR
#1246) added a second source: claude's own interruption marker maps to
`turnevent.TurnEnd{Cancelled}` (`internal/turnbridge/mapper.go:95`). This ticket
makes the oracle assert it. Split from
[#1229](https://github.com/pyrycode/pyrycode/issues/1229), blocked on #1243
landing. Spec: `docs/specs/architecture/1244-minted-interrupt-turn-end-cancelled.md`.
PR: [#1258](https://github.com/pyrycode/pyrycode/pull/1258). Size S — one
production-adjacent file (`internal/e2e/internal/fakeclaude/main.go`, test-only
`package main`), three test files, zero files under `internal/turnbridge` or
`cmd/pyry`.

See [features/fakeclaude-binary.md § Interrupt mode](../features/fakeclaude-binary.md)
(updated by this ticket) and [codebase/1243.md](1243.md) for the mapper change this
asserts.

## Implementation

- **The fake couldn't just add the assertion — it staged the wrong shape.**
  fakeclaude's bare-ESC handler wrote a canned assistant `stop_reason:"end_turn"`
  line (`interruptEndTurnLine`), which *looks like a clean completion on disk* and
  drives `mapper.go:30`, not `:95`. Asserting `cancelled` against it would be red
  for the wrong reason. Fixed by replacing the const with `interruptMarkerLine`,
  claude's actual interruption entry, and renaming `appendTurnEnd`'s payload
  accordingly (the function's name, signature, call site, and one-shot `escEnded`
  gate are unchanged — only the bytes written).
- **The staged line is DERIVED, not captured, and says so.** Byte-shaped after
  `internal/agentrun/jsonl/testdata/no_end_turn.jsonl:53` (claude 2.1.128) — the
  repo's one recorded interruption entry — preserving the full **13**-key
  top-level set and its order verbatim (the architect spec said 12; the count
  matters because it's the whole argument for using the full set — an absence
  among a different number of keys than production sees would understate the
  span this ticket covers). Only the session-identity fields (`parentUuid`,
  `promptId`, `uuid`, `timestamp`, `cwd`, `sessionId`, `gitBranch`) are
  substituted, with shape-preserving canned values (`cwd` deliberately
  `/tmp/fake-claude` so nobody mistakes the line for a capture) — nothing on this
  path reads any of them, and the base line's real values name a developer
  worktree and a real session. Same provenance discipline #1243 established for
  `mapper_test.go` fixtures (verbatim vs. derived, no third arm), now applied to a
  fake's canned line for the first time.
- **Two absences are load-bearing and silent if broken.** No top-level
  `permissionMode` key (`userAuthored`'s presence check, `mapper.go:163-166` —
  one extra key reads the line as user-authored and produces no `turn_end` at
  all) and no `tool_result` block (`ParseToolResult` precedes the marker check
  and returns first, `mapper.go:80-86` — a "more realistic" line with a rejection
  `tool_result` bolted on would silently stop producing a `turn_end`). Both
  failures present identically: a 15 s timeout at the pre-existing "never
  received a turn_end" fatal, with nothing pointing at the cause.
- **The causality invariant is re-derived in the file, not inherited.** The
  oracle's whole design rests on "the bare ESC is the only thing that can produce
  an end-of-turn line in the minted transcript." That held for a reason that no
  longer exists after #1243 (a second `turn_end` source now exists in the repo).
  The test's doc comment now enumerates all three `turnevent.TurnEnd{`
  construction sites, shows only `mapper.go:95` is reachable from the ESC
  handler's line (of the four line kinds the minted transcript can contain, only
  the marker is even a `type:"user"` entry), and shows `mapper.go:30` is now
  *unreachable* in this test (none of the four line kinds satisfy `IsEndTurn`).
  This discharges S-2 of
  `docs/specs/architecture/1191-minted-perconv-interrupt-oracle.md:590-609`, the
  finding that flagged this exact hazard for whoever next extended this file.
- **A new live coupling to the mid-turn kicker, found and documented.** The old
  canned line produced *two* events (`TextChunk` + `TurnEnd`) and opened its own
  turn. The marker produces *one* — `interactive_turn_v2.go:208-213` silently
  drops a `TurnEnd` when no turn is open (debug log
  `interactive_turn.turn_end_no_turn`, nothing on the wire). So Phase 3's
  mid-turn kicker, previously only a vacuous-pass guard, became a **precondition**
  for the new assertion to be reachable at all. Recorded at the Phase 3 comment
  site with its basis: `endTurn()` has exactly two call sites, and nothing closes
  a turn on inactivity.
- **The AC1 timeout stopped having one reading, so its fatal was widened.** With
  the marker as the sole `turn_end` source, "ESC never arrived," "marker held out
  by the authorship gate," and "`TurnEnd` dropped outside a turn" all present as
  the identical 15 s timeout. The fatal now names the discriminator: does the
  minted transcript contain the interruption needle?
- **`endTurnNeedle` → `interruptMarkerNeedle`, and the new needle is strictly
  stronger.** It's the exact string `isInterruptMarker` keys on
  (`interruptMarkerSentinel`, `mapper.go:108`), inside a JSON *string value*
  rather than in key position — so needle-drift and mapper-drift cannot diverge:
  if the fake's line ever stops carrying it, the mapper stops matching, no
  `turn_end` arrives, and the run dies loudly in the same run. That keeps the
  Phase 5 bootstrap-transcript absence check (the #678/#1121 mis-route detector)
  from ever going silently vacuous.
- **The shared knob's other consumer (`PYRY_FAKE_CLAUDE_ESC_ENDS_TURN`, set by
  exactly two tests) got a rewrite, not a second knob.** The architect's call:
  correcting the fake improves fidelity for every consumer, and the #794
  bootstrap capstone (`relay_v2_interrupt_test.go`) never asserted `StopReason`,
  so it stays green under the marker. Its `:55-61` paragraph, which stated as
  fact that the reason was `end_turn` "because tui-driver cannot distinguish,"
  was rewritten: the reason is now `cancelled`, and the test still deliberately
  doesn't assert it — that's this ticket's job, one tier up, on the minted path.
- **AC5 mutation proof, pasted in the PR.** Flipping `mapper.go:95`'s reason to
  `TurnEndReasonEndTurn` (one token) still delivers a `turn_end` — the run
  reaches the new assertion, which then fails on the reason. That's the
  discriminating mutation. The weaker adjacent one (deleting the
  `isInterruptMarker` arm outright) dies 15 s earlier at the pre-existing fatal
  instead, proving the staging is load-bearing but not that the reason assertion
  discriminates.

## Patterns established

- **A test's own "this is deliberately not asserted, here's why" comment is a
  liability the moment its cited reason can change underneath it.** This ticket
  existed because #1243 silently falsified `:91-97`'s premise and nothing
  flagged it. The fix isn't just deleting the stale paragraph — it's replacing it
  with a re-derivation over a *closed, countable set* (every `TurnEnd{`
  construction site in the repo, enumerated) so a future change to that set is
  checkable against the same paragraph rather than requiring another silent
  staleness.
- **A staged fixture that "looks more realistic" can silently defeat the thing
  it's staged to prove.** Bolting a rejection `tool_result` onto the interruption
  marker, or adding `permissionMode` for verisimilitude, both look like hardening
  and both produce a *worse* test — one that times out instead of asserting.
  Struck explicitly in the spec (Technical Notes) rather than left for a reviewer
  to catch after the fact.
- **Extending a fake's canned bytes can introduce a dependency the fake's own
  diff never shows.** The `TextChunk`+`TurnEnd` → `TurnEnd`-alone shrink is
  invisible from `fakeclaude/main.go`'s side; it only shows up as a live
  precondition in the *consuming* test (`inTurn` must already be true). Same
  shape as #1191's original S-2 finding — this is the second time this specific
  file has needed a coupling re-derived after a mapper change, worth watching for
  a third.

## Lessons learned

(From the PR's own **Lessons learned** section, pasted at hand-off.)

- **The spec's base-line key count was off by one.** `no_end_turn.jsonl:53`
  carries 13 top-level keys, not 12. Flagged rather than silently corrected in
  the spec, since the count is the load-bearing argument for the full-key-set
  design (`docs/specs/architecture/1244-minted-interrupt-turn-end-cancelled.md`
  states 12 in two places — left as-is per this repo's convention that specs are
  point-in-time build artifacts, not evergreen).
- **`gofmt` re-reads a wrapped `+` as a list bullet.** A doc-comment continuation
  line starting `//     + non-empty text, …` inside an indented `//   - …` bullet
  was silently rewritten by `gofmt` into a second `//   - …` bullet, changing
  what the sentence claimed. Worth knowing for any file enumerating a
  conjunction inside a bullet list — avoid a line-leading `+` in wrapped
  Go-doc-comment prose.
- **Code review found a stale-comment gap the rename sweep missed**: two
  present-tense comments inside `fakeclaude/main.go` itself (`:756-757`, the ESC
  arm's own inline comment at the injection path AC1 names, and `:1233`) still
  described the pre-#1244 "append a canned assistant `end_turn` line" behavior
  after the merge — the doc comment on the const and on `appendTurnEnd` were
  updated, but the call-site comments naming the same effect in prose weren't.
  Also two NITs: `relay_v2_perconv_interrupt_test.go:214` still says "ESC→`end_turn`
  handler" where `:88`'s identical claim was updated to "ESC→marker handler",
  and `:108`'s "constructed at three sites" undercounts a fourth
  (`internal/turnevent/event.go:169`, the compile-time `_ Event = TurnEnd{}`
  assertion — inert but present under a plain `grep 'TurnEnd{'`). Review verdict
  was PASS with these left non-blocking (comment-text only); **they were not
  fixed as of the merged commit** — a maintainer who next opens
  `fakeclaude/main.go:756-757` to ask "what does the ESC arm write?" gets the
  pre-#1244 answer, which is exactly the failure mode this ticket exists to
  eliminate from the *test file's* prose. Worth a follow-up sweep if anyone
  touches this handler again before then.
- **`docs/knowledge/features/fakeclaude-binary.md`** (lines 344, 356, 379-393,
  584 pre-this-update) still documented the old canned line and the
  `end_turn`-not-`cancelled` claim — left for this documentation pass per the
  spec, now updated.

## Security note

Carries `security-sensitive` (crosses the same trust boundary attacker-controlled
transcript content does — fake writes → `TailJSONL` → `parseEntry` → `Raw` →
`mapEntry`, the same route production data takes). Architect self-review verdict
**PASS**; the one SHOULD FIX (guard against a `tool_result` block or a
`permissionMode` key ever being added to the staged line) was already satisfied
by the spec's design, not a code change. Code review independently re-verified
both absences empirically (unmarshalled the const, diffed key sets and order
against the base capture) and confirmed zero production-file changes survive to
the merged commit (the AC5 mutation is reverted). No production trust boundary
touched — `internal/turnbridge` and `cmd/pyry` are read-only in this ticket.
