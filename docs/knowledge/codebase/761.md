# Ticket #761 — `session/new` over an embedded tui-driver-hosted pool

The **first ACP method that does real work** plus the **composition root** it
needs. `pyry acp` (a bare JSON-RPC stdio transport since [#756](https://github.com/pyrycode/pyrycode/issues/756))
now stands up an embedded `internal/sessions` pool — trimmed to the ACP subset
(no relay, control socket, conversations registry, or message queue) — and
serves `session/new`. Each call allocates one pool session via `Pool.Create`,
which spawns exactly one supervised **interactive** `claude` through the
tui-driver, and returns its fresh id for the host to address in later calls.

Epic [#600](https://github.com/pyrycode/pyrycode/issues/600) — `pyry acp` as a
thin adapter over the shared remote-head core. Split from #748, sub-issue of #600.
Spec: [`specs/architecture/761-acp-session-new-embedded-pool.md`](../../specs/architecture/761-acp-session-new-embedded-pool.md).
Design decision: [ADR 026](../decisions/026-embedded-acp-pool-exact-one-claude.md).
Not security-sensitive — the spawn reuses the daemon's own workdir and the
shared cmd-layer `trustMark`; no caller-supplied path reaches it (the handler
ignores ACP's `cwd`/`mcpServers` params). The flip condition — honouring a
caller-supplied `cwd` that bypasses the trust seam — is deferred to #762+.

## Implementation

**2 production files modified, 0 new production files, 0 new exported types.**

### `internal/sessions/pool.go` — two purely-additive primitives

Both preserve today's behaviour at their zero value and have a **single new
consumer** (the ACP root) — no call-site fan-out.

- **`Config.BootstrapEvicted bool`** — when true, `New` forces the bootstrap
  session to `stateEvicted` (overriding the warm/cold-start branch that
  otherwise forces `stateActive`), so `Pool.Run → supervise(bootstrap) →
  runEvicted` **parks it and spawns no claude**. The eager claude is now solely
  `Pool.Create`'s job, so `session/new` produces exactly one. `false` (zero
  value) is byte-identical to today's eager-bootstrap behaviour. The override
  lives at `New` right after the warm/cold-start `lcState` choice
  (pool.go:376-381) and flows into the existing evicted channel-init branch
  (`activeCh = make(chan struct{})`, `evictedCh = closedChan()`).
- **`Pool.Ready() <-chan struct{}`** — a channel (internal `readyCh`, created in
  `New`) closed **once** by `Run` under `sync.Once` (`readyOnce`), right after
  `runGroup`/`runCtx` are wired and `supervise(bootstrap)` returns nil — i.e.
  once `Pool.Create`'s `supervise` can no longer return `ErrPoolNotRunning`.
  Before `Run` is ever called the channel is open (never ready). Read lock-free
  (set once in `New`, never reassigned).

Why `Ready()` is a **correctness gate, not a nicety**: `Create` calls
`supervise`, which returns `ErrPoolNotRunning` when `runGroup` is nil. On that
path `Create` returns a **non-empty id** for a session that is minted (and
would-be persisted) but **never supervised** — there is no public re-supervise,
and `Activate` on it blocks forever. The session is permanently stuck and the
failure is unrecoverable. A microsecond window between backgrounding `pool.Run`
and the first `session/new` is enough to strand the first call, so the standup
**must** gate on `Ready()` before serving.

### `cmd/pyry/acp.go` — composition root + handler

- **`runACP`** now stands up a trimmed `runSupervisor` spine before serving:
  `confineWorkdirToHome("")` (process cwd, confined to `$HOME`) → shared
  `trustMark` (mark the workdir trusted in `~/.claude.json` so claude never
  wedges on the workspace-trust modal) → `sessions.New` with
  `BootstrapEvicted: true` and a service-mode `Bootstrap.Bridge`
  (`supervisor.NewBridge`). `RegistryPath`/`ClaudeSessionsDir`/
  `ConversationsRegistry`/`SweepInterval`/`ActiveCap` are all left zero → no
  persistence, reconcile, rotation watcher, sweep, relay, control socket, or
  message queue (AC-1).
- **`serveACPWithPool(ctx, pool, stdin, stdout, logger)`** — backgrounds
  `pool.Run(runCtx)` on a buffered(1) `poolErr` channel, then `select`s:
  `<-pool.Ready()` → proceed to serve; `<-poolErr` → Run failed before
  readiness (map non-`Canceled` error, else clean) → return; `<-ctx.Done()` →
  signal during startup → cancel, drain `poolErr`, return nil. After serving it
  `cancel()`s (the EOF path needs this to stop `pool.Run`; the signal path
  already cancelled the parent) and joins `<-poolErr` so no supervisor goroutine
  outlives the call. stdin/stdout are parameters (not `os.Stdin/os.Stdout`) so
  the test drives it with in-memory pipes against a fake-claude pool.
- **`newSessionHandler(pool) acp.Handler`** — `func(ctx, json.RawMessage) (any,
  error)`. Calls `pool.Create(ctx, "")`, returns `newSessionResult{SessionID:
  string(id)}` marshalling to `{"sessionId": "<uuid>"}`. On error wraps and
  returns it (`fmt.Errorf("session/new: %w", err)`) → `CodeInternalError` on the
  wire, detail logged by the transport, never leaked. **Params
  (`cwd`/`mcpServers`) are deliberately ignored** — the spawn uses the daemon
  workdir, so no caller path reaches it. `newSessionResult` is an unexported
  type with one exported json-tagged field → **zero new exported types.**
- **`serveACP`** gained a final `register func(*acp.Transport)` parameter,
  invoked after `acp.New` and before `Serve` (the acp "register before Serve"
  invariant). `register == nil` ⇒ register nothing, preserving the #756
  behaviour every existing caller/test relies on. The ACP root passes a closure
  that does `t.Register("session/new", newSessionHandler(pool))`.

### Data flow

```
ACP host ──stdin──▶ serveACP io.Pipe ──▶ acp.Transport.Serve
                                              │ session/new
                                              ▼
                                    newSessionHandler(pool)
                                              │ pool.Create(ctx,"")
                                              ▼
   pool.Run errgroup ◀── supervise(sess) ── mint fresh UUID → buildSession
     (bootstrap parked                        (service-mode Bridge; args
      in runEvicted, PID 0)                     = [--session-id <uuid>])
                                                     │ runOnce → tui-driver.Spawn
                                                     ▼
                                          ONE interactive claude (PID>0)
                                                     │ MirrorOutput → per-session
                                                     ▼ Bridge (no attach → discarded)
   handler returns {"sessionId":"<uuid>"} ──▶ writeSuccess ──stdout──▶ host
   (os.Stdout stays clean for JSON-RPC frames)
```

## Patterns established

- **A purely-additive Config bool with a single consumer suppresses a
  load-bearing default without touching any existing call site.**
  `BootstrapEvicted` overrides the eager-bootstrap default that pyry's
  daemon-mode startup contract ("claude is available") bakes in, so an embedded
  host with an inverted contract (ACP: zero claudes until `session/new`) reuses
  the whole pool wholesale. Zero-value = byte-identical; the override is a
  three-line branch. See [ADR 026](../decisions/026-embedded-acp-pool-exact-one-claude.md)
  for why this beat adopting `Pool.Default()`.
- **Gate the first mint on a readiness channel when the "not-yet-running" error
  is unrecoverable rather than merely racy.** `Pool.Ready()` is a `sync.Once`-
  closed channel, not a retry/poll — the deterministic safety net the pipeline
  principle calls for (belt-and-suspenders in *different fabric*: a channel, not
  another stochastic wait). Same shape as [ADR 023](../decisions/023-activate-waits-pty-readiness.md)'s
  `WaitForPTY` gate.
- **Service mode is mandatory when the composition root owns stdout.**
  `supervisor.runOnce` in foreground mode (`Bridge == nil`) copies claude's PTY
  output to `os.Stdout` (supervisor.go:771-775). ACP owns stdout for the
  JSON-RPC frame stream, so setting `Bootstrap.Bridge` (service mode) routes
  claude's `MirrorOutput` to a per-session Bridge — discarded when nothing
  attaches — keeping the frame stream clean. The Bridge is the supervisor's I/O
  mediator, **not** one of the prohibited subsystems (relay/control/
  conversations/queue).
- **An `io.Reader`/`io.Writer` + injected pool seam makes the whole standup
  testable without a TTY or real claude.** `serveACPWithPool` takes the pool and
  the streams as parameters, so the test wires a fake-claude pool over in-memory
  pipes and drives `session/new` end-to-end. Extends #756's `serveACP(io.Reader,
  io.Writer)` split.
- **Add the handler-registration seam as a nil-defaulted parameter, not a new
  method.** `serveACP`'s new `register func(*acp.Transport)` param (nil ⇒
  register nothing) threads handler wiring through the existing composition root
  with zero blast radius on #756's callers.

## Code review

**PASS** — the reviewer found the diff clean, idiomatic, and spec-compliant;
real-claude e2e suite green. Verified in depth: `serveACP`'s new `register`
param updated at all 5 call sites (4 tests + `serveACPWithPool`), no missed
callers; `Pool.Ready`/`Config.BootstrapEvicted` purely additive, single-consumer,
no duplication; the background `pool.Run` + `Ready()`-gate select sound
(buffered(1) `poolErr` → no goroutine leak on any of the three exit paths,
`readyCh` closed once under `sync.Once` and read lock-free, `-race` green);
`BootstrapEvicted` override flows correctly into the evicted channel-init branch;
handler error-wrapping maps to `CodeInternalError` with detail logged not leaked.

One NIT-level observation (not actioned, matches the spec design): the
`<-poolErr` join after serving discards a potential non-`Canceled` `pool.Run`
error mid-serve — but that path realistically only ever carries
`context.Canceled`, and surfacing a mid-serve pool error would race the
already-returning `serveErr` anyway.

## Lessons learned

- **The Go-test-binary-as-fake-claude flag-parse trap applies to any
  `Pool.Create`-driven `cmd` test, not just e2e.** `Pool.Create` appends
  `--session-id <uuid>` to the spawn argv; a `TestHelperProcess` re-exec (the Go
  test binary) rejects that unknown flag *before* the helper body runs, so it
  can never record its argv. The fix used here is a tiny `#!/bin/sh` wrapper that
  appends `"$*"` (one line per spawn) to a file whose path is **baked into the
  script** (no env plumbing), prints a screen-output marker to its PTY, then
  `exec sleep`s. That single fake proves all four behavioural ACs at once:
  exactly-one line → AC-3 (one claude); the line is exactly `--session-id
  <uuid>` with no `-p`/`--print` → AC-4 (interactive path); the marker never
  reaching the frame-stream reader → AC-1 (stdout hygiene); the returned id
  round-tripping to the spawn argv and validating via `sessions.ValidID` → AC-2.
- **The eager-bootstrap claude is invisible at the LOC/reuse level.** The ticket
  body framed the work as "reuse `Pool.Create`", but `sessions.New` + `pool.Run`
  *always* eager-spawns a bootstrap interactive claude (the bootstrap cold-starts
  `stateActive`; `runActive` spawns immediately). A naive standup that then
  `Pool.Create`s per `session/new` yields **two** interactive claudes for one
  ACP session — a divergence-6 and hard-cost-invariant violation. Trace
  `pool.Run → supervise(bootstrap)` before trusting a "reuse the pool" framing;
  count **total** supervised claudes in the "exactly one" assertion (a per-id
  check passes vacuously).

## Out of scope (deferred)

- **`session/load`, `session/cancel`, and the no-double-spawn-for-same-id
  guard** → #762. `session/new` mints a fresh id each call, so a same-id respawn
  cannot arise here.
- **Honouring a caller-supplied `cwd`** (ACP request field) — deferred with its
  `security-sensitive` flip condition to a later ticket.
- **Turn delivery, transcript reconciliation, `/clear` rotation watcher, idle
  eviction** — none wired (`ClaudeSessionsDir`/`RegistryPath` empty).
- **`initialize` handshake** — an unregistered `initialize` returns
  `CodeMethodNotFound`, which conformant hosts tolerate for this floor ticket. A
  separate handler if integration shows a host hard-requires it.
- **Connecting to a running daemon** instead of embedding a pool — scope
  satisfies either; the embedded model is what shipped (per #756's `runACP`
  framing).
