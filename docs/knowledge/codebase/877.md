# Ticket #877 — reconcile modal truth on connect (re-send outstanding `modal_shown`)

The **modal half of #829**'s reconcile-on-connect direction (ADR 025): when a v2 session
reaches `V2StateOpen` with the `interactive` capability, unicast the still-outstanding
`modal_shown` set (original `modal_id` + payload) to that connection, so a phone that
connects or reconnects while a permission prompt is pending is brought to current modal
truth instead of letting the prompt silently ride the daemon's 2-minute deny-on-timeout
window unseen. `modal_shown` is broadcast only once at raise time (`EventID` nil, so it
never enters the turn-event replay ring) — this is the first mechanism that reaches a
**brand-new** WS connection, distinct from #874's within-grace hold and #875's eager
flush (both of which only cover a *surviving* conn).

## Implementation

Two additive changes in `internal/relay/v2session.go`, plus a one-line `cmd/pyry` wire:

- **`V2SessionConfig.OutstandingModals func() []protocol.ModalShownPayload`** — new
  optional seam (nil ⇒ no reconcile, byte-identical to pre-#877). A closure, not a
  `*modalbridge.Registry` import: `internal/relay` doesn't import `internal/modalbridge`,
  and `protocol.ModalShownPayload` is already imported, so the boundary crosses with no
  new import and no cycle — matches the `SnapshotSettings`/`SnapshotUsage` idiom of
  defining the dependency where it's consumed.
- **`reconcileModals(ctx, s)`** — structural sibling of `broadcastModalDismissed`, minus
  the fan-out: guards on `!s.interactive || m.cfg.OutstandingModals == nil`, snapshots
  once, and per payload marshals + `m.Push`es a `protocol.Envelope{ID: 1, Type:
  TypeModalShown, TS: ts, Payload: payload}` to `s.connID` only (unicast). `ID: 1` is
  non-load-bearing (correlate on `modal_id`); `EventID` stays nil (control event, never
  in the replay ring). A marshal or `Push` failure logs only `event`/`conn_id`/`modal_id`
  and continues; `ctx.Err() != nil` returns early.
- **Call site:** one line in `handleNoiseInit`'s success tail, immediately before the
  #647 replay hook — after `s.interactive`/`s.state = V2StateOpen` are set and after the
  conn's push queue exists. Ordering relative to `replayMissed` is immaterial: the
  reconcile lands in `m.queues` (held behind any #777 replay tail, then drains), while
  `replayMissed` enqueues into the separate `replayQueue`.
- **`cmd/pyry/relay.go`** wires `OutstandingModals: modalReg.Snapshot` into the
  `V2SessionConfig` literal — the same daemon-singleton registry the raise-time producer
  `Record`s into and the `ModalResolver` consumes.

Consumes the already-merged `internal/modalbridge.Registry.Snapshot()` (#876) and the
existing `modal_shown` wire vocabulary — no new payload type, no new wire shape.

## Patterns established

- **A connect-time reconcile is a unicast structural sibling of an existing broadcast
  helper, not a new fan-out shape.** `reconcileModals` mirrors `broadcastModalDismissed`
  line-for-line except for the addressee (one `connID` vs. every open interactive conn)
  and the payload source (a snapshot vs. a dismissal). When a new delivery path needs
  "the same envelope shape, a different audience," clone the existing helper's structure
  rather than parameterizing broadcast-vs-unicast into one function — the two audiences
  have different security postures (unicast is strictly narrower) and are easier to
  reason about as separate call sites.
- **Enumerate-current-truth avoids stale-replay risk entirely.** Because `Snapshot()` is
  read fresh at reconcile time, a resolved-before-open modal is simply absent — no
  timestamp bookkeeping, no "how long was the client away" special case, unlike an
  event-ring-replay design would need.
- **A closure crossing a one-way import boundary, not a concrete-type field.** Same
  pattern as `SnapshotSettings`/`SnapshotUsage`: when the consuming package (`relay`)
  must not import the producing package (`modalbridge`), the config seam is typed in
  terms the consumer already imports (`protocol.ModalShownPayload`), and the production
  wiring binds the concrete method (`modalReg.Snapshot`) at the composition root
  (`cmd/pyry`) instead.

## Security review

`security-sensitive` (per the ticket label — dispatches nonce-adjacent, permission-body
payloads over the internet-exposed v2 relay). Architect self-review: **PASS**. The two
existing gates carry the load — Noise_IK authentication (unauthenticated/token-rejected
peers never reach `handleNoiseInit`'s success tail) and the `interactive` capability
guard (identical to `broadcastModalDismissed`'s). Unicast-to-`s.connID` is strictly
narrower than the existing broadcast's fan-out. `Snapshot()` mints no nonce and the
reconcile calls no arm/resolve path, so the deny-on-timeout timer and one-shot `Resolve`
answerability are both unchanged. No `answer_token` rides the outbound payload (that
field exists only inbound). Logging is content-free (`event`/`conn_id`/`modal_id` only —
never `Title`/`Prompt`/options).

## Testing

`internal/relay/v2session_modalreconcile_test.go` (new): one and two outstanding modals
re-sent keyed by `modal_id`; unicast-only proof (opening a second interactive conn
delivers to it, not to an already-open first conn); non-interactive open gets zero;
nothing-outstanding sends zero; nil seam is inert (session stays `V2StateOpen`); a modal
resolved before open (via a real `modalbridge.Registry`) never resurfaces; a pure-read
proof that the registry snapshot is unchanged across the re-send and a second `Resolve`
of the same id is inert. `go test -race ./internal/relay/... ./cmd/pyry/...` and `go vet
./...` pass.
