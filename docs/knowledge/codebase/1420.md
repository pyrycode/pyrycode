# Ticket #1420 — The trailer gate names which absence case fired (offline)

`trailGate`'s absence arm (`trailer_admissibility_test.go`, the `!slices.Contains(in.Scan.KeyNames,
trailReasonKeyName)` branch #1419 shipped) answered one `Detail` for three situations that mean
different things: `terminal_reason` absent from a path that owes one (ptyrunner), absent from a path
that owes none (a healthy `PYRY_USE_STREAMJSON=1` run), and absent from a path naming no runner. The
arm now calls the shipped `trailReasonAgainstPath` (`trailer_terminal_reason_test.go:215`) — its
first decision-path caller — and splits into three return sites, one per case. No answer changes: all
three still return `trailGateOutOfContract` with `Reason` empty, so the five-value gate allowlist and
`trailClassifyRun`'s C1/C2 are untouched. `trailGate` now has ten return sites, six of them
`trailGateOutOfContract` (was eight / four). PR [#1422](https://github.com/pyrycode/pyrycode/pull/1422).
Split from #1416, blocked by #1419 (merged `ee6fe0f`).

## Implementation

- **The switch lives on the absence branch only.** Presence itself still comes from the gate's own
  `!slices.Contains(in.Scan.KeyNames, trailReasonKeyName)` read, exactly as #1419 landed it — never
  from `against.Value` and never from `decodedReason != ""`. Inside that branch,
  `against := trailReasonAgainstPath(in.RunnerPath, in.Scan.KeyNames, reason)` is switched on
  `against.Value`, with `trailReasonAbsentOwesOne` and `trailReasonAbsentOwesNone` as explicit cases
  and `trailReasonPathUnnamed` as the **fall-through**, not a `default` guard — the reachable answer
  set here is exactly the three absence values because `present` is false by the enclosing branch, and
  an unreachable fourth `default` site would break `TestTrailGateIgnoresTheRunnerPathExceptAtTheAbsenceArm`'s
  clause-B totality claim (a site no fixture row can reach).
- **Three return sites, not one interpolating `against.Detail`.** Rejected as too simple: a single site
  would compile and pass every AC but forfeits the per-case byte budget (below) and the "each of the
  three sites echoes `RunnerPath: in.RunnerPath`" totality argument `TestTrailGateIgnoresTheRunnerPathExceptAtTheAbsenceArm`'s
  re-scoped clause B depends on.
- **The gate's own prose is rewritten, not appended to.** The shipped absence Detail was 480 B of a
  512 B `reachMaxCommandBytes` cap (32 B headroom); appending a 264–286 B embedded `trailReasonAgainstPath`
  Detail would truncate 1–5 bytes past each case's own value marker, false-greening a naive
  `strings.Contains` assertion (`reachCapCommand` cuts at 512 and appends `reachTruncationMarker`, so
  the marker survives while the explaining clause after it does not). The three rewritten Details
  measure **461 / 460 / 468 B**, each checked on the *output* via `len(Detail) <= reachMaxCommandBytes`
  **and** `!strings.Contains(Detail, reachTruncationMarker)` — the second is the direct tripwire; a
  length check alone would not catch a truncation that still fits under the cap in some future reword.
  The `NOT DECIDED AT THIS ARM` tail marker is retired — the arm now decides.
- **`TestTrailGateNamesWhichAbsenceCaseFired`** — four rows (R1 ptyrunner reading → owes-one, R2
  streamrunner reading → owes-none, R3 indeterminate reading → path-unnamed, R4 present-and-empty scan
  → path-invariant), each driven off #1419's shipped `trailGateAbsentReasonScan()` /
  `trailGateEmptyReasonScan()` fixture helpers rather than hand-built scans. Every row asserts its own
  case marker present **and** the other two markers absent (`trailGateAbsenceCaseMarkers()`), on the
  **full constant**, never a substring fragment — `"reason-absent-on-owes-one-path"` (30 B) is not a
  substring of `"reason-absent-on-owes-none-path"` (31 B) in either direction, verified before the
  markers are used for anything else, because a fragment check would silently pass across an
  owes-one/owes-none swap. Four mutants of `trailReasonAgainstPath`'s label switch are each the sole
  red row: M1 (indeterminate→streamrunner) and M2 (indeterminate→ptyrunner) both fail only R3 and are
  told apart by the *wrong value* the failure message reports (got-vs-want), not by a distinguishing
  row; M3 (ptyrunner→streamrunner) fails only R1; M4 (streamrunner→ptyrunner) fails only R2. All four
  demonstrated under `go test -overlay`, no worktree writes.
- **`TestTrailGateIgnoresTheRunnerPathExceptAtTheAbsenceArm`** (renamed from
  `TestTrailGateIgnoresTheRunnerPath`) — narrowed claim: every arm except the absence one ignores the
  path. A new `pathVaries bool` field on `trailGateCase`, set only on row nine (the absence-shaped row
  #1419 added), is a **declared** exemption rather than one detected from the Details differing —
  detecting it from the diff would exempt precisely the rows that fail, and re-deriving the gate's
  branch condition inside the sweep would restate the thing under test. Clause A (pairwise-distinct
  readings) and the four-field pin are unchanged. Clause B (the arriving reading read back from
  outside the gate) runs **unconditionally on every row under every reading** — this is what keeps the
  three new return sites' `RunnerPath: in.RunnerPath` echo checked; skipping the row wholesale would
  have silently withdrawn clause B from exactly the sites this ticket adds. The value/`Reason`
  comparison also keeps running on the exempted row — strictly stronger than exempting it, since all
  three absence cases answer the same `Value`/`Reason` pair — and only the `Detail` byte comparison is
  skipped, only under `tc.pathVaries`. A companion sub-test drives `trailGateAbsentReasonScan()` (row
  nine's own fixture helper, not a slice index) across all five `trailGateRunnerReadings()` and asserts
  the Detail lands on the expected case per reading, with the set of distinct Details across the five
  pinned at cardinality exactly 3 — the positive proof that the exempted arm *does* vary, not merely an
  assertion that it may.
- **Totality re-derived:** ten return sites; the nine `trailGateCases()` rows reach all ten only when
  driven across the five readings (row nine alone contributes three of them); at any single reading the
  nine rows reach eight.
- **Two assertions keyed on the retired `NOT DECIDED AT THIS ARM` phrase, both re-pointed rather than
  deleted.** The absent-arm assertion (was `:1004`) now asserts the Detail names `trailReasonPathUnnamed`
  (its input, `trailRunnerUnread()`, reduces to `indeterminate`). The present-and-empty-arm assertion
  (was `:991`) — which would have gone green-and-vacuous the moment the phrase left the file — now
  asserts the present-and-empty Detail carries **none** of the three new case markers, preserving the
  mutual-exclusion check it exists to make.
- **Nine doc blocks correcting "no arm reads the path"** (all inside `trailer_admissibility_test.go`),
  plus a tenth outside AC3's file scope in `trail_ptyrunner_composition_test.go:28-34`, narrowed to the
  claim that's still true there (that test drives `trailFixtureTrailer`, which reaches
  `trailGateUsable`, an arm that still ignores the path). The `:242-248` block is the load-bearing one:
  its old safety argument ("no arm reads the field, so an unfilled one cannot misroute a decision") is
  replaced with the answer it used to defer to the now-NOT_PLANNED #1374 — `finRecordRunnerLabel("")`
  returns `""`, which matches neither runner, so an unfilled reading routes to `trailReasonPathUnnamed`
  by construction. Six `#1374` attribution references corrected to say supply stays **unowned** (no new
  ownership, no behaviour change) rather than pointing at a cancelled ticket.
- **Count literals re-derived against the shipped function, not adjusted by one:** arm-count comments
  move 4→6 sub-cases (`:125`), 8→10 return sites (`:307`, and the stale companion at
  `trailer_admissibility_test.go:1894` code review caught — "four arms answer trailGateOutOfContract"
  → "six of trailGate's ten return sites"), and "the seven that carried it" (`:786`) stays the numeral
  seven (10 − 3, same as 8 − 1 before) with only the surrounding prose changing. `nine rows × five
  readings = forty-five` (`:667`, `:723`, `:1074`, `:1077`) confirmed unchanged, not assumed.
- **`finding_run_gather_test.go` / `trail_run_rig_test.go`** — attribution-only edits to the two gather
  supply comments, same "#1374 → unowned" correction, no behaviour change. Both gathers still fill
  `RunnerPath` with `trailRunnerUnread()`; live runs therefore still reach only the path-unnamed case.

## Patterns established

- **Call the shipped reduction on the branch already established, don't re-source presence from it.**
  `trailReasonAgainstPath` computes `present` internally and its default arm is reached *before*
  consulting it, so absent and present-and-empty both answer `trailReasonPathUnnamed` on an
  indeterminate reading — a caller that took presence from the callee's answer could not tell those two
  apart on exactly the reading both shipped gathers supply. The gate keeps its own presence read and
  calls the function only on the branch that read has already decided is absent.
- **A composed Detail gets measured on the output, per case, not trusted from source-level appending.**
  480 B (shipped) + 264–286 B (embedded) = 744–766 B against a 512 B cap is an obvious overflow on
  paper; what isn't obvious is that the 27–31 B value marker survives the cut at offset 480 while its
  explaining clause doesn't, so a `strings.Contains(detail, marker)` assertion alone passes against a
  severed sentence. `len <= cap` **and** `!strings.Contains(detail, reachTruncationMarker)`, together,
  on the rendered string, is the pattern — see [[po-1420-composed-detail-truncates-past-the-marker]].
- **An exemption on a sweep is a declared field, never a detected condition.** `pathVaries` on
  `trailGateCase` names which row's Detail is allowed to vary; detecting the exemption from the Details
  differing would exempt exactly the rows that are broken, and inlining the gate's branch condition
  into the test would restate the thing under test rather than checking it independently.
- **A forced exemption still needs positive proof of variance, not just permission to differ.** Skipping
  the byte comparison on `pathVaries` rows only proves the sweep no longer complains; the companion
  sub-test driving all five readings against row nine's own fixture is what proves the arm actually
  moves — without it the sweep is silently blind about the one return-site family it stopped covering.
- **Two same-value mutants sharing one red row are separated by the wrong value, not by a second row.**
  M1 and M2 both corrupt the indeterminate reading and both fail only R3; there is no fixture that tells
  them apart structurally. The discriminator has to live in the failure message (got vs. want), which
  is why the AC required asserting the value reached rather than "is/is not the path-unnamed case."

## Lessons learned

From the PR body's own "Lessons learned" section (developer, condensed):

- **A re-pointed marker assertion can silently lose the role it used to play.** `NOT DECIDED AT THIS
  ARM` was a *tail* phrase, so asserting on it doubled as an implicit cap tripwire (a truncation would
  have cut it off). Its replacement, the case constant, sits where the embedded Detail *begins* — so a
  truncated record keeps the marker and loses every clause explaining it. Re-pointing an assertion
  means re-deriving what it used to discriminate, not just finding a new string that currently matches;
  the tripwire had to be rebuilt explicitly as a headroom check on the output (see [[po-1420-composed-detail-truncates-past-the-marker]]).
- **The mutant worth keeping in the matrix isn't always one the spec mandates.** The four AC1 mutants
  all live inside `trailReasonAgainstPath`. A fifth, unmandated mutant — re-collapsing the gate's three
  return sites back to one — leaves the sweep's own byte comparison **green**, because that row is
  exempted; only the companion assertion catches it. Demonstrating that blind spot is what proves the
  companion sub-test is load-bearing rather than decorative.
- **Large insertions into a heavily cross-cited file stale line cites in sibling files.** This ticket
  adds ~350 lines to `trailer_admissibility_test.go`; every inbound cite below the insertion point in
  other files is now off by that much. The cites the spec named, and the one this change itself staled
  in `trail_ptyrunner_composition_test.go` (a +1 shift from editing the two gathers), were re-taken.
  Others are pre-existing staleness and were left alone per the spec's explicit scope note — a
  dedicated cite-sweep ticket is the right owner, not ad-hoc repair riding on an unrelated change.

From code review (PASS, two SHOULD FIX + one NIT, all comment-only, absorbed by this documentation
pass rather than reworked on the branch):

- **SHOULD FIX (fixed here):** `trailer_admissibility_test.go:1894`'s non-vacuity-precondition comment
  still read "four arms answer `trailGateOutOfContract`" after the split to six — the exact stale-count
  class AC3 exists to remove, missed by the PR's own numeral sweep because the comment sits inside the
  file's carry-forward sweep rather than in one of the nine blocks the ticket enumerated by cite.
- **SHOULD FIX (fixed here):** `docs/knowledge/features/e2e-realclaude.md`'s #1415 and #1419 ticket-list
  rows still named `TestTrailGateIgnoresTheRunnerPath` after this PR renamed it — the rows' *claims*
  stayed true (the test still drives all five readings over `trailGate` alone), only the symbol
  dangled. Confirmed no other Go-source references to the old name remain.
- **NIT (left open, no code change):** the `pathVaries` exemption is guarded in one direction only — a
  row that forgets to declare `pathVaries: true` on a genuinely path-varying arm goes red (the intended
  direction), but a row that declares it *without* its arm actually varying would silently withdraw the
  byte comparison with nothing red to catch it. No such row exists today and the failure has never been
  observed, so a guard would defend against a hypothetical — left as a note rather than a fix, per this
  repo's evidence-based fix-selection rule.
