# Ticket #1373 — The trailer gate's input carries a runner-path reading no arm reads

`trailGate` (`internal/e2e/realclaude/trailer_admissibility_test.go`) decided
admissibility from `trailScanResult` alone, and that type says nothing about
which runner produced the trailer line. It needs to: `terminal_reason` is
pyry's invention, and ptyrunner's trailer owes a non-empty reason by
construction while streamrunner's healthy trailer is claude's own `result`
line and owes none at all — the same shape is a healthy run on one path and a
broken record on the other. #1366 shipped `trailReasonAgainstPath`, the pure
predicate over exactly that pair, but it had no decision-path caller because
the gate couldn't see a path. **This slice carries the path to the gate's
input and changes no arm** — the decision lands in #1374. Splitting the shape
change from the decision is what makes #1374's red a statement about the
gate's arms rather than about a signature. Test-only, offline, `e2e_realclaude`
build tag; zero production source files touched.

## Implementation

- **`trailGateInput{Scan trailScanResult, RunnerPath string}`** — new wrapper
  type; `trailGate` now takes this instead of a bare `trailScanResult`.
  `RunnerPath` holds `tdnRunnerFromArgv`'s **output** (one of its five
  constant answers) and never its argv input — the same rule
  `finRecordInputs.ClaudeCommand` states at its own tier ("READ, reduced …
  and NEVER RETAINED", `finding_run_record_test.go:235-238`). Kept off
  `trailScanResult` deliberately: that type is `trailScan`'s output over
  bytes alone and is pinned unreachable from the published record
  (`finding_run_record_test.go:780-812`); widening it would put that pin up
  for renegotiation for no gain here.
- **`trailGateResult.RunnerPath string`** (4th field, `json:"runner_path,omitempty"`)
  — the reading the gate was handed, echoed out unread. No arm consults it;
  it exists so the value that reached a pure function is observable from
  outside it, which is the only channel #1374's composition test can assert
  against. Its doc states the field is not a copy of captured bytes (one of
  five source-authored constants, not argv) and that an unfilled `""` — a
  value no shipped producer emits — is #1374's question to answer, not this
  ticket's.
- **`trailRunnerUnread() string`** — `return tdnRunnerFromArgv("")`, the
  honest "runner not read from the process table" reading, obtained by
  calling the shipped reader rather than re-typing its prose. Both gathers
  and all eight fixture rows go through this one function so the two sides
  of `finGatherAssertContract`'s C2 equality can't drift apart. A function,
  matching `trailRigHeldPGID()`'s shape in this family, not a package var.
- **`trailGateCase.in`** retyped from `trailScanResult` to `trailGateInput`;
  all eight `trailGateCases()` rows wrapped with `RunnerPath: trailRunnerUnread()`.
  This is the shape choice that leaves `trailGate(tc.in)` call sites
  textually untouched — retyping the row's field instead of rewriting the
  call.
- **Every one of `trailGate`'s seven return sites** gained
  `RunnerPath: in.RunnerPath`; body otherwise just `res.` → `in.Scan.`.
- **Two gathers updated**, `finGatherReadings` (`finding_run_gather_test.go:546`)
  and `trailRigGather` (`trail_run_rig_test.go:157`), both now pass
  `trailGateInput{Scan: ..., RunnerPath: trailRunnerUnread()}`. Neither
  gains a parameter — #1374 replaces `trailRunnerUnread()` with the reading
  derived from each gather's own argv scan.
- **`finGatherAssertContract`'s C2`** (`finding_run_gather_test.go:787`)
  updated to build its `want` through the same `trailGateInput{...,
  RunnerPath: trailRunnerUnread()}` shape, which makes the whole-struct `==`
  slightly stronger for free: it now also asserts the gather handed the gate
  the expected reading, not just the expected scan.
- **`trail_run_outcome_test.go:641`** (`trailRunCases`' `realGate`) is the
  file's only hunk — `trailClassifyRun`'s step-1 switch
  (`:476-484`, the landmine a new *gate value* would arm) is untouched, as
  is `TestTrailRunComposesWithGateCases` (`:1092`, `:1118` — zero diff).

### Call-site accounting

`trailGate(` has 12 call sites. 4 have zero textual diff because the widening
rides on `trailGateCase.in`'s retyping rather than a call rewrite
(`trailer_admissibility_test.go:847`, `:1195`, `trail_run_outcome_test.go:1092`,
`:1118`); the other 8 are one-expression wraps.

### New test — `TestTrailGateIgnoresTheRunnerPath` (AC2)

Drives all 8 `trailGateCases()` rows under each of `tdnRunnerFromArgv`'s
5 distinct answers (obtained by calling the shipped reader over 5 real
argvs, never re-typed as literals) and asserts, per row:

- the 5 readings are pairwise distinct (clause A);
- `got.RunnerPath == reading` after the call — the read-back, total over
  all 7 of the gate's return sites, so a single arm that forgot to carry
  the field can't hide behind one that did (clause B, the vacuity guard
  AC2 names);
- `Value`, `Reason` and a **byte-identical** `Detail`
  (`bytes.Equal([]byte(got.Detail), []byte(base.Detail))`) are identical
  across all 5 readings — `RunnerPath` is the sole exemption;
- `reflect.TypeOf(trailGateResult{}).NumField() == 4`, so a future 5th
  field must join the comparison or state its own exemption;
- the premise (`base.Value == tc.want`, `base.Reason == tc.reason`) is
  checked before the invariance sweep, so a gate collapsed to one constant
  answer can't pass vacuously.

## Mutation coverage

`TestTrailGateIgnoresTheRunnerPath` was run against a 12-mutant matrix via
`go test -overlay` (scratchpad copies, no worktree writes). Every mutant
went red, and in every case this sweep was the **sole** test that caught it:

| Mutant | Clause it lands on |
|---|---|
| Carriage dropped from each of the 7 return sites (7 runs) | read-back, proving the assertion is total over the arms |
| An arm's `Detail` interpolates the reading | byte-identical `Detail` |
| The sweep builds its input without filling the path | read-back (the vacuity clause) |
| A 5th field added to `trailGateResult` | `NumField` pin |
| An arm branches on the runner path | value/reason invariance |

## Patterns established

- **A wrapper-input type is how a pure decision function gains a
  contextual reading without widening the value it decides over.**
  `trailGateInput{Scan, RunnerPath}` keeps `trailScanResult` — the scan's
  own output, pinned unreachable from the published record — untouched,
  and lets the gate's contract stay exactly as strict as before.
- **Retyping a shared test-fixture field, rather than rewriting call
  sites, is a lever for keeping a signature-widening ticket's diff to a
  small multiple of its call-site count.** `trailGateCase.in`'s retyping
  left 4 of 12 `trailGate(` call sites with zero textual diff.
- **Echoing an input field back onto a pure function's result, unread, is
  the shape for making "the value X reached Y" observable from outside Y**
  when Y is otherwise a black box to its caller. This is what lets #1374's
  composition test assert what arrived at the gate without adding a
  contract check to the gate itself.

## Lessons learned

(From PR #1375's body.)

- **A whole-struct equality does not catch a dropped field carriage.**
  `finGatherAssertContract`'s C2 (`readings.Gate != want`) is the
  strongest-*looking* assertion on the gate's output, yet it stayed green
  under all 7 dropped-carriage mutants — both sides run through the same
  mutated gate, so the equality proves nothing about carriage. Only the
  per-arm read-back in `TestTrailGateIgnoresTheRunnerPath` caught them. When
  a field is *carried* rather than *computed*, an equality against a
  recomputation of the same function is structurally blind to it.
- **A mutant that appends to a capped `Detail` can read green.**
  `trailDetail` caps at 512 bytes via `reachCapCommand`; a leak injected at
  the *end* of a format string can be silently truncated away. Injecting at
  the *start* is what makes the mutant bite — a plant-placement detail worth
  remembering for any future needle/leak sweep against a capped field.
- The zero-diff call-site count is a property of *where* the widening
  lands: retyping the fixture row's field left 4 of 12 sites textually
  untouched, exactly as the architecture doc's size-check table predicted
  and `git diff` confirmed.
