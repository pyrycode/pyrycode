# Ticket #857 — Carry context-window usage on `screen_snapshot`

Wire child of #855 (usage-on-snapshot), consuming the leaf reader #856
(`internal/contextwindow.Read`, merged). Follows the #847→#848
settings-on-snapshot split exactly: adds `UsedTokens`/`WindowTokens` to
`ScreenSnapshotPayload` (no `omitempty`), an optional primitive-typed
`SnapshotUsage` seam on `V2SessionConfig`, and the `cmd/pyry` closure that
resolves the bootstrap transcript and calls `Read`. Not `security-sensitive`
— outbound-only reflection of two non-secret aggregate integers to an
already-paired, AEAD-authenticated client that already receives the full
rendered screen text under the same seal.

## Implementation

Three production files, ~65 production LOC + ~152 test LOC, no edit fan-out:

- **`internal/protocol/snapshot.go`** — `UsedTokens int` / `WindowTokens int`
  added to `ScreenSnapshotPayload` after `YOLO`, no `omitempty`. `UsedTokens`
  is the current context size on the latest usage-bearing transcript entry
  (not a running total); `WindowTokens` is the context-window size (200000
  today). `window_tokens == 0` means the usage seam was not wired — the
  doc comment states this explicitly since it's the client's signal to treat
  "X of Y" as unavailable rather than divide by zero.
- **`internal/relay/v2session.go`** — new optional field on `V2SessionConfig`:
  `SnapshotUsage func() (usedTokens, windowTokens int)`, alongside
  `SnapshotSettings`. `handleRequestSnapshot` reads it on the success path
  only, immediately before the `SnapshotSettings` read and the
  `json.Marshal` — nil-guarded, leaves both at `0` when unset. No reject
  branch, offline branch, or error path touched.
- **`cmd/pyry/relay.go`** — the `snapshotUsage` closure, built in
  `startRelayV2` directly above the `V2SessionConfig{…}` literal (**not**
  threaded from `main.go` the way #848's `snapshotSettings` was — see
  "Predicted-vs-actual seam" below), gated on `claudeSessionsDir != ""`:
  1. builds a **dedicated** `resolveOwnBootstrapJSONL` instance over
     `newBootstrapProbe(logger)` and `func() int { return sup.State().ChildPID }`
     — the exact construction the turn-stream gate uses 100 lines below, kept
     as a separate instance since the resolver is stateful and documented
     "not safe for concurrent use";
  2. on each call, resolves the path (collapsing a resolver error to `""`);
  3. calls `contextwindow.Read(path)`, and on a `Read` error (a genuine open
     failure on a resolved path — the case #856 left to this ticket) falls
     back to `contextwindow.Read("")`, which never errors and returns the
     deterministic fresh-session report `Usage{0, 200_000}`;
  4. returns `u.UsedTokens, u.WindowTokens`.
- **`internal/protocol/snapshot_test.go`** + `testdata/screen_snapshot.json` —
  extended `TestScreenSnapshotPayload_ZeroSettingsFieldsPresent` with
  `used_tokens:0`/`window_tokens:0`; fixture gained representative non-zero
  values (`45000`/`200000`) asserted in `TestScreenSnapshotPayload_RoundTrip`.
- **`internal/relay/v2session_test.go`** — extended
  `TestV2Session_OpenState_RequestSnapshot` with a `usage` column and three
  new rows (injected non-zero usage; nil seam → `(0,0)`; wired-but-fresh
  seam → `(0,200000)`, distinguishing the nil case from a fresh session on
  the wire). Added `TestV2Session_OpenState_RequestSnapshot_UsageShrinks`, a
  dedicated two-request test proving a shrinking `SnapshotUsage` stub (the
  wire form of a post-compaction reset) surfaces a smaller `used_tokens` on
  the second reply — AC-4, without re-testing #856's own compaction-reset
  unit test.

`go test -race ./internal/protocol/... ./internal/relay/... ./internal/contextwindow/...`

## Predicted-vs-actual seam: not `ResolveTranscript`, but `resolveOwnBootstrapJSONL`

The ticket's Technical Notes and #856's own doc
([contextwindow-package.md](../features/contextwindow-package.md), pre-#857
revision) both anticipated this ticket would obtain the transcript path via
`internal/sessions`' existing `ResolveTranscript` seam
(`supervisor.Config.ResolveTranscript`, populated by
`newProbePreferredTranscriptResolver` — see
[sessions-package.md](../features/sessions-package.md)). The architect spec
deliberately overrode that: `ResolveTranscript` is a `*sessions.Pool`-owned
seam, and threading it into `relay.go` would have re-imported the
`internal/sessions` dependency `relay.go` stays free of (the discipline
`SnapshotSettings`/#848 established via a `main.go`-side closure). Instead
the closure reuses `resolveOwnBootstrapJSONL`
(`cmd/pyry/interactive_turn_stream_v2.go`) — the same probe-preferred,
cmd/pyry-local resolver the turn-stream gate already uses — via a **second,
dedicated instance** so its per-instance `resolvedOnce`/`sawEmpty` state is
never shared across the two consumers. Net effect: `relay.go` owns this
closure entirely, no `main.go` edit, three files instead of four. See the
spec's Design §4 for the full rationale. **Both docs corrected to reflect
this** — see [contextwindow-package.md](../features/contextwindow-package.md)
and [v2-session-manager.md](../features/v2-session-manager.md).

## Design invariant (AC-2/AC-4)

Usage-source == snapshot-source == the bootstrap session, by construction:
`Snapshotter` renders the bootstrap child's screen, and the dedicated
`resolveOwnBootstrapJSONL` instance resolves that same child's transcript via
`sup.State().ChildPID`. No runtime cross-check needed. AC-4 (post-compaction
shrink) holds because `contextwindow.Read` is last-usage-wins with no
running total (#856) — a smaller `input_tokens` on the next usage-bearing
transcript entry surfaces as a smaller `used_tokens` on the very next
`request_snapshot`, with no dedicated compaction marker on the wire.

## Out of scope

- A conversation-keyed usage accessor — deliberately not added, per the
  invariant above (mirrors #848's settings scope decision).
- Caching the transcript scan across snapshot requests — deferred,
  evidence-based (`request_snapshot` is user-initiated and infrequent); see
  Open Questions in the spec for the escalation trigger.
- Any change to `internal/contextwindow` itself (#856, unchanged here) or to
  the client-side gauge rendering (pyrycode-desktop#182).
