# Ticket #1446 — The `gate-absent-reason-owes-none` arm consults the pinned-pid sighting route and publishes under a route of its own (offline)

`trailClassifyRun`'s step-1 switch answered `trailGateAbsentOwesNone` with an
unconditional `return` of `trailOutcomeVoidPathOwesNoReason`, before any evidence
was examined. #1440 had already shipped a complete evidence route for exactly this
case — `trailEstablishSighting`, which fills the gap left by the headless stream
path writing no reap log at all on a clean exit — but wired it to nothing: a route
added at steps 2-8 never fires on the one gate value it exists to serve, since step
1 answers and returns first. This ticket reaches it, from inside the arm, and
publishes a finding under a value and an evidence-route field of its own.

PR [#1449](https://github.com/pyrycode/pyrycode/pull/1449). Split from #1444
(itself split into #1446 → #1447 → #1448, wired natively so neither later ticket
reaches an architect until this one closes). Security-sensitive (architect
self-review PASS). Two code-review rework rounds, both fixed without touching the
classifier's decision logic.

## Implementation

- **The arm consults the route, never falls through.** `case
  trailGateAbsentOwesNone` now calls `sighting :=
  trailEstablishSighting(readings.Ordering, readings.PinnedPid)` and branches on
  `sighting.Value == trailSightingEstablished`. Consulting *inside* the arm rather
  than adding a step 2-8 route was the whole point: step 1's own comment states
  that a record the gate says certifies nothing must not be awarded a scan-side
  answer about pyry — "the same hazard class, one step further down." The switch
  stays total over the gate's seven values, no default arm.
- **The new value: `trailOutcomeAliveAtSightingByOrdering =
  "run-alive-at-sighting-by-ordering"`.** Deliberately *not*
  `run-sighting-alive-by-ordering` (the obvious `run-`-prefixed transform of
  #1440's `sighting-alive-by-ordering`) — that string would *contain* #1440's
  value, and the union map's equality-only comparison is blind to containment,
  which this family has already been bitten by once
  (`TestTrailRunComposesUnderANamedReasonOnAPathThatOwesNone`'s hand-written
  both-ways guard). Also deliberately not `trailOutcomeRunningAtTrailer` — AC1
  forbids it, since the reap-log route and this one state the *same English
  sentence* ("alive at declared finish") from different evidence classes, which
  #1440's header calls its own central risk. `trail_ptyrunner_composition_test.go`
  passes **unamended** (verified: zero non-comment changes in that file).
- **The evidence-route field: `trailRunOutcome.Route string
  \`json:"evidence_route,omitempty"\`.** A closed two-value space of its own
  (`trailRouteReapLog` / `trailRouteSighting`), **derived** rather than
  switch-duplicated: `trailIsRunRoute` iterates `trailRunRouteValues()` instead of
  re-listing the constants in a second switch, which is a deliberate departure
  from this family's other four membership predicates (each needs an agreement
  test to keep list and predicate from drifting; a two-value space built in one
  commit has no such history to preserve, so deriving removes the drift class
  outright). Set to `trailRouteSighting` on the new finding, `trailRouteReapLog` on
  step 2's `trailOutcomeRunningAtTrailer` (one added line, its Detail format string
  untouched — naming the route in prose there would have spent the 68 B
  `trail_ptyrunner_composition_test.go` requires that arm to keep free). `""`
  everywhere else, exactly as `Admit` is `""` where the predicate was owed no call.
  AC3's reason: the two finding values state nearly the same sentence, and a field
  is what keeps them distinct to a *consumer*; a naming convention only keeps them
  distinct to a map.
- **Two new whole-record fields on `trailRunReadings`: `Ordering trailOrderResult`,
  `PinnedPid pinStateOutcome`.** Narrowing either was foreclosed by
  `trailEstablishSighting`'s own doc: `Ordering` is trap-free by construction
  (three bools in) so taking it whole costs nothing; `PinnedPid` is
  string-bearing (`Detail`, `StateColumn`, `ToolStderr` — the last a live raw-`ps`-
  stderr capture route) and narrowing it to a bare verdict string would leave no
  route for the no-captured-bytes needle to travel, making the sweep unbuildable.
  `PinnedPid` is deliberately **not** folded into `Liveness` (the argv scan's
  per-pid set, blind once the group re-parents to init, and feeds two other
  consumers that have nothing to do with this route).
- **No C10 contract check over either new field — a comment instead, and the
  omission is load-bearing, not an oversight.** The instinct to validate
  `PinnedPid` the way C7 validates every `Liveness` verdict against `pinIsVerdict`
  is exactly wrong: no shipped gather stages either input (both fill the gate's
  runner-path field with `trailRunnerUnread()`), so a zero `pinStateOutcome`
  (`Verdict: ""`) and a zero `trailOrderResult` (`Value: ""`) are what every run in
  existence produces today. A tenth check would answer `trailOutcomeOutOfContract`
  on all of them — filing a routine reading as an instrument defect, the collapse
  #1417 exists to prevent, one value along. The unstaged pair needs no such check
  anyway: `trailEstablishSighting`'s own first guard (uncertified ordering
  outranks the pid verdict) already routes it to `sighting-reason-ordering-
  uncertified`, which this arm's `else` branch turns straight back into today's
  `trailOutcomeVoidPathOwesNoReason` — the shipped predicate does the safety work,
  not a new check.
- **The void arm's Detail exchanges its closing clause rather than growing.**
  Measured headroom before this ticket: 22 B on this arm (490/512), 11 B on its
  mirror `trailOutcomeVoidReasonNotOwedByPath` (must stay untouched), 68 B on
  `trailOutcomeRunningAtTrailer`. 22 B does not hold a route clause naming
  `sighting.Value` (longest member 24 B), so the arm's prior "kept apart from
  `trailOutcomeOutOfContract`" tail was traded for "the pinned-pid sighting route
  was consulted and answered %s" — same argument's other half is preserved in the
  value's own doc comment instead of the rendered Detail. Measured after: 461 B
  unstaged / 472 B refuted, both under cap, no truncation marker.
- **`trailDeclaredFinishInstantClause` joins the new value's Detail, making it the
  fourth carrier in `trailRunCertifiesNothingArms()`.** #1443's two-sided check
  (merged after this ticket's parent spec was written) forces the decision either
  way — an unlisted arm whose Detail carries the clause is red, same as a listed
  arm whose Detail omits it. This is the one arm in the run space publishing a
  *positive finding* from a gate that certified nothing, which is exactly the
  misreading the clause exists to prevent, so it joins rather than staying off the
  list. The one tension — the clause opens "Nothing is certified" while the
  *ordering* is in fact certified — is resolved by never naming the ordering's
  certification in this arm's Detail; it names `sighting.Value` /
  `sighting.Reason` instead, neither of which contains "certified."
- **Two new fixture rows in `trailRunCases()`.** `trailRunSightingEstablishedReadings()`
  (built on `trailRunAbsentOwesNoneReadings()`, with `Ordering =
  trailCertifyOrdering(true, true, true)` — the real producer, not a hand-built
  literal — and `PinnedPid = trailSightingPin(pinStateRunning)`, #1440's own pin
  fixture, not a second one) reaches the finding and is **mandatory**: the
  coverage loop reddens on any outcome value no row reaches. A second row with
  `PinnedPid = trailSightingPin(pinStateNoSuchProcess)` reaches the void and
  proves the arm consulted the route rather than becoming a blanket answer once
  both inputs are staged — without it, a build that ignored `sighting.Value` and
  reported the finding whenever the ordering certified would pass every other row.
  The existing both-zero row is unchanged and stays the regression guard for the
  no-C10 argument.
- **`TestTrailClassifyRun`'s per-row loop gains the `Route` invariant** alongside
  the existing `Gate`/`Admit` provenance assertions: non-empty exactly on the two
  finding values, a member of `trailIsRunRoute` when non-empty, and the correct
  constant per value — in the loop rather than a new table, since the const
  insertion displaces cites regardless of where the assertion lives.
- **Registration, both hard and prose.** `len(trailRunOutcomeValues()) != 13` → 14,
  `len(distinct) != 20` → 21 (`finding_trailer_evidence_test.go`), the union
  closure map (+3: the outcome plus both route constants, narrative 51 → 54), all
  eighteen "thirteen"/"Thirteen" prose sites, plus four sites no word-sweep for
  "thirteen" finds because this value is an *answer* (the "three answers" /
  "the three answers" comment / "three answers and ten named voids" phrasings →
  four).

## Patterns established

- **A derived membership predicate is the right call for a space with no drift
  history to guard.** `trailIsRunRoute` iterates `trailRunRouteValues()` instead
  of switching over the constants a second time — the family's other four
  predicates were written before their lists and need an agreement test to keep
  the two from diverging; a two-value space introduced in one commit has nothing
  to diverge from yet, so deriving removes the class of bug outright rather than
  shipping a test to guard against a duplication nothing forced.
- **A leak sweep's unit is the reachable *outcome*, not the arm.** One arm that
  consults a route can have more than one reachable verdict, each rendering a
  different Detail from the same inputs. A needle planted on only one of an arm's
  outcomes says nothing about the others — see Lessons below for how this bit the
  first draft here. [[code-review-a-leak-sweep-is-per-arm-not-per-record]]
  generalizes the finding from this ticket.

## Lessons learned

From the PR body's own "Lessons learned" section (developer):

- **A `size:s` ticket can carry a doc-comment claim in a *sibling* file that only
  the change itself falsifies.** #1440's own scope note read "that switch answers
  `trailGateAbsentOwesNone` with an unconditional return, so a route wired below
  it would not fire" — true when written, false the moment this ticket landed, and
  invisible to every count sweep and cite sweep in the manifest. The signal was a
  cite the line-map couldn't resolve: a cite pointing *into* the region being
  rewritten is worth reading as prose before repointing it, since the surrounding
  sentence may describe the very code being changed.
- **Repoint cites by mapping source lines, then verify the mapping against the
  baseline's own bytes.** A `difflib` old→new line map built from the pre-edit
  file re-pointed 128 of 136 cites; the 8 it couldn't map were exactly the
  rewritten regions, the correct set to review by hand. The check that made this
  trustworthy: for every renumbered endpoint, assert the baseline's text at the
  old number is byte-identical to the new file's text at the new one — 282
  endpoints verified, 0 wrong.
- **The bare-cite trap bites the file that documents it.** `trail_run_outcome_test.go`'s
  own closing doc carried a bare `:1655` two paragraphs below a mention of
  `trail_sighting_liveness_test.go`, inheriting the wrong file and reading clean
  under a filename-anchored sweep. Fixed by spelling the filename, with the reason
  recorded in place.
- **A new two-value closed space does not need the family's list-plus-predicate-
  plus-agreement-test trio** — see Patterns above.

From code review (two FAIL rounds, then PASS):

- **Round 1 — three stale line cites**, all bare `(:NNN)` or symbol-anchored,
  invisible to a filename-anchored `grep`. Two were plain number swaps; the third
  (`finding_trailer_evidence_test.go:272`) needed the *symbol-anchored* form
  rather than a bare renumber, because the bare form at that point in the file
  inherits the wrong last-named file — spelling the filename instead would have
  fixed that cite and broken its same-line neighbour, which correctly inherits a
  different file. #1434's remedy (`8bf84b0`) applied again.
- **Round 2 — the leak sweep covered one of the arm's two reachable outcomes.**
  `TestTrailRunOutcomeCarriesNoCapturedBytes`' first draft planted its needle only
  on the finding side (`trailGateAbsentOwesNone` → `run-alive-at-sighting-by-
  ordering`); the void side (`run-void-path-owes-no-reason`, reached when the
  route is consulted and refuted) had no needle-bearing fixture. Demonstrated with
  matched mutants: `PinnedPid.ToolStderr` — the field the architect's own security
  review names as the trust boundary — **survived every test** on the void side.
  Fixed with a third `t.Run` block over the refuted fixture, needle in
  `Ordering.Detail`, `PinnedPid.Detail`, and `PinnedPid.ToolStderr`. Re-measured
  with a *substitution*-form mutant (replacing an existing operand rather than
  appending) specifically so a truncation-marker kill couldn't be mistaken for a
  leak kill — an appended leak that overruns the 512 B cap trips the marker
  regardless of whether the sweep's own assertion ever runs, so a marker-only kill
  proves nothing about the sweep. Under substitution, `PinnedPid.Detail` also had
  no killer pre-fix — one field wider a gap than the review's own measurement,
  found by re-measuring rather than trusting the finding at face value. Both
  Detail fields died only on the marker pre-fix; only `ToolStderr` survived
  outright. Generalized as [[code-review-a-leak-sweep-is-per-arm-not-per-record]].
- Three stale answer-count phrasings (`finding_staging_gate_test.go:28`,
  `finding_exit_path_probe_test.go:146`, `finding_stage_held_group_test.go:74`) —
  all "three answers"/"three-answer" in a form the manifest's prescribed
  `grep -rn "hree answers\|hree outcomes"` cannot see (case-sensitive, space-only,
  misses `three ANSWERS` and `three-answer`). `grep -rniE "\b(three|thirteen)[
  -]?(answer|outcome)"` catches the class; five other same-shaped phrasings
  elsewhere in the package were confirmed to still correctly say "three."
- Verification, final round: `go test -race -tags e2e_realclaude
  ./internal/e2e/realclaude/` — 159 top-level PASS, 668 with subtests, 0 FAIL, 0
  races, all 48 skips env-gated live-claude tests (no `TestTrail*`/`TestFin*`
  skipped). Containment checked both ways across all 54 union-map values: zero
  collisions. Cite pass: 1037 pre/post pairs machine-checked via a git-diff line
  map; the residual after both rework rounds was 0.
