# Ticket #1013 — hold the queued turn while claude's startup trust modal is pending

Split from [#992](992.md); blocks #1014. Closes the one gap left in an otherwise pre-built pipeline: when the interactive session pool spawns claude in a cwd the daemon host hasn't trusted, claude's startup trust-folder modal was already surfaced to remote clients and already resolvable (`AcceptTrust`, #708/#717), but `Supervisor.deliverViaSession` discarded `Readiness.TrustModal` and typed the queued turn straight into the modal — clobbering the last consent gate a `--dangerously-skip-permissions` interactive session has, per #988's agreed no-auto-trust design.

## Implementation

Two-file change, entirely inside `internal/supervisor`, no new surfacing or resolution code:

- `internal/supervisor/supervisor.go`:
  - New sentinel `ErrTrustModalPending = errors.New("supervisor: trust modal pending")`, alongside `ErrNoLiveSession`/`ErrTurnNotCommitted`.
  - New free function `readyForDelivery(ctx, waitReady func(context.Context) (tuidriver.Readiness, error)) error` — a pure classifier, unit-testable independent of a live `Session`. Calls `waitReady`; a non-nil error passes through unwrapped (the caller applies the `"wait ready: %w"` wrap); `Readiness.TrustModal == true` yields `ErrTrustModalPending` **before any delivery**; otherwise nil. It marks nothing trusted and sends no keystroke — read-only classification.
  - Both `deliverViaSession` modes now route through it: the nil-`ResolveTranscript` (foreground) mode inline, and the growth-confirm mode via the `deliverGrowthDeps.waitReady` closure — `confirmViaTranscriptGrowth` already returned before `deliver` on a `waitReady` error, so the growth mode gets its hold for free with no other change.
- `internal/supervisor/supervisor_test.go`: `TestReadyForDelivery` (table: trust-modal-pending → sentinel + no-deliver; idle → nil + deliver; ctx error and `*tuidriver.ProcessExitedError` pass through unwrapped, never misclassified as the trust sentinel), `TestSupervisor_ConfirmViaTranscriptGrowth_TrustModalHolds` (growth-mode hold, asserts the `deliver` fake is called 0 times), `TestSupervisor_WriteUserTurn_TrustModalPendingHolds` (boundary contract: `errors.Is(err, ErrTrustModalPending)` survives the wrap chain out of `WriteUserTurn`, and the conversation cursor is still stamped per the pre-existing #312 contract even though delivery was held).

## Patterns established

- **Retryable sentinel, not a blocking park.** The alternative shape — block inside `deliverViaSession` polling `WaitReady` until the modal clears — would never *return* while pending, so the msgqueue give-up streak (`drain`'s `firstFailedAt`) would never start. That would silently implement #1014's give-up-bound exemption inside this ticket, coupling two tickets that were deliberately split. Returning `ErrTrustModalPending` and letting the existing `msgqueue` retry-on-error loop (`internal/msgqueue/queue.go`, 1s retry / 2min give-up, unchanged) hold the head keeps #1013 to exactly one behavior (don't clobber) and leaves #1014 a clean seam (`errors.Is`) to add the typed session error and the give-up exemption on top.
- **Single-wrap contract at the call site, not inside the classifier.** `readyForDelivery` returns bare errors; each of the two `deliverViaSession` call sites applies its own `"wait ready: %w"` wrap, so the sentinel survives to `WriteUserTurn`'s outer `"supervisor: write user turn: %w"` wrap as one clean chain (`errors.Is` still resolves it). Keeping the wrap at the call site rather than in the shared classifier avoids double-wrapping across the two delivery modes.
- **A closing-a-gap ticket can be a pure net security tightening with zero new surface.** No new goroutine, lock, surfacing code, or resolution code — the fix is a read-only classifier gating an existing call site. The security review treats this as the load-bearing property: before the fix, untrusted phone-originated queued text could reach a consent gate via `DeliverPrompt`; after, that path is structurally unreachable while the modal is pending (the sentinel returns before `DeliverPrompt` is ever called).
