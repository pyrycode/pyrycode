# Ticket #749 — `session/prompt`: content blocks → `DeliverPrompt`, call held open

The main ACP call. A `session/prompt` request carries a user turn as an ordered
list of content blocks; this handler resolves the target session from the
[#761](761.md) embedded pool, maps those blocks to a user-turn payload, delivers
it into the supervised **interactive** claude via `Session.WriteUserTurn` (the
tui-driver `DeliverPrompt` path), and **holds its own JSON-RPC call open** for the
duration of the turn using [#765](765.md)'s deferral primitive. An ACP turn is one
`session/prompt` request that streams `session/update` notifications and then
returns a `stopReason`, so deliver-in and hold-open are one handler — a
`session/prompt` that returned synchronously would violate the turn model.

**security-sensitive.** Host-sourced prompt text reaches claude here; the ACP host
may be remote/untrusted. The design guarantees host content is delivered **strictly
as a user turn** — never interpreted as pyry control input, shell input, a path, or
a terminal control sequence. Architect security pass: **PASS** (after one MUST FIX,
folded in — the control-byte guard below).

Sub-issue of epic [#600](https://github.com/pyrycode/pyrycode/issues/600). Spec:
[`specs/architecture/749-acp-session-prompt.md`](../../specs/architecture/749-acp-session-prompt.md).
Feature doc: [`features/acp-package.md` § `session/prompt`](../features/acp-package.md#sessionprompt--the-held-turn-call-749).

## Implementation

**1 new production file (`cmd/pyry/acp_prompt.go`, 267 lines), 1 edit to
`cmd/pyry/acp.go` (`serveACPWithPool`, ~15 lines), 0 new exported types.** Package
`main` only — consumes existing `internal/acp` (#765 deferral), `internal/sessions`
(#761 pool), `internal/supervisor` seams. No cross-package coordination.

### Data flow

```
host: {"id":N,"method":"session/prompt","params":{"sessionId":S,"prompt":[blocks]}}
  read loop (single-threaded, race-free):
    1. decodeSessionID(params)   empty/missing → CodeInvalidParams (pre-Lookup, bootstrap-trap guard)
    2. mapPromptContent(params)  non-text / control-byte / empty / malformed → CodeInvalidParams
    3. resolve(id)=pool.Lookup   ErrSessionNotFound → CodeInvalidParams "unknown session"
    4. ResponderFrom(ctx)         nil (notification misuse) → plain error, no hold
    5. holds.begin(S, resp)       already in flight → CodeInvalidRequest, no hold, no spawn
    6. go deliverPrompt(...)      WriteUserTurn off the read loop (~10s WaitReady+commit)
    7. return acp.ErrDeferred     transport writes NOTHING; loop scans next frame
  delivery goroutine: WriteUserTurn ok → LEAVE held; err → holds.fail (resolve + free slot)
  resolver goroutine (T7 / test placeholder): holds.end(S, stopReason) → resp.Reply
```

### `promptHolds` — the per-session in-flight registry

A `sync.Mutex`-guarded `map[string]*acp.Responder`, at most one held call per
session id. Sole owner of held-call resolution:
- `begin(id, resp) bool` — atomic check-and-insert; `false` if one is already in
  flight (caller then rejects the second prompt, registers nothing, spawns nothing).
  Called **inline on the read loop** so the guard is race-free against itself.
- `end(id, stopReason)` — the **T7 [#751](https://github.com/pyrycode/pyrycode/issues/751) seam**: resolve with `{"stopReason":…}` and free the slot.
- `fail(id, *acp.Error)` — delivery failed: resolve with an error frame and free the
  slot, so the next `session/prompt` for that session is accepted.

`end`/`fail` **capture the `*Responder` under `mu`, delete, then release `mu`
before** calling `Reply`/`ReplyError` (those take the transport's `writeMu`) — so
`mu` stays a pure leaf and no `mu → writeMu` nesting exists. A missing entry is a
**no-op** (idempotent), so `end` is safe even if `fail` already fired and vice-versa.
Exactly-one-frame across every race (double-`end`, `end`-vs-`fail`,
resolve-after-teardown) rides #765's `Responder.done` CAS; `promptHolds` adds the
slot bookkeeping, not a second frame guard.

### `mapPromptContent` — content blocks → payload bytes (fail-closed)

Decodes `{prompt:[{type,text}]}`; iterates blocks in order, joining `text` with
`"\n"` **between** blocks (bracketed-paste-safe per tui-driver v1.3.0 — an embedded
newline does not submit the turn early). Rejects, with `CodeInvalidParams`:
- **first non-text block** (`image`/`audio`/`resource`/…) — pyry advertises
  `promptCapabilities` all-false, so any non-text block is a host protocol
  violation; rejecting (vs silently dropping) never loses host content and never
  reinterprets it (AC-3, documented behaviour).
- **any disallowed control byte** (`hasDisallowedControl`) — see Security boundary.
- **empty assembled payload** / absent `prompt` → `"empty prompt"`.
- **malformed params JSON** → `"invalid params"`.

Otherwise text passes through **verbatim** — no escaping, no transformation. No
length cap: the transport's 16 MiB per-line frame bound already caps it.

### `serveACPWithPool` edit

Constructs one `holds := newPromptHolds(logger)` per `pyry acp` process and
registers `session/prompt` alongside the other four verbs. The `resolve` closure
wraps `pool.Lookup(id)` and **returns a true nil interface on error** — a typed nil
`*sessions.Session` would wrap a non-nil interface and defeat the handler's err
short-circuit (the same nil-interface trap the cancel handler documents). The
handler maps `errors.Is(err, ErrSessionNotFound)` → `CodeInvalidParams "unknown
session"` (mirrors `loadSessionHandler`); any other resolve error →
`CodeInternalError`, detail logged, never leaked.

## Concurrency model

- **One short-lived delivery goroutine per accepted prompt**, lifetime bounded by
  `promptDeliverTimeout = 15s` (> the supervisor's ~10s budget, so a genuine
  supervisor failure surfaces first; the timeout is only the outer backstop). It
  derives from the handler ctx (the Serve loop ctx), so Serve shutdown cancels
  in-flight deliveries. No goroutine outlives its bound; no new long-lived
  goroutine, clock, or ticker.
- **Read-loop liveness is the point** — `begin` + spawn + `return ErrDeferred` are
  all non-blocking, so the loop keeps classifying while a call is held. This is the
  #765 property the concurrent-second-prompt reject and `session/cancel` rely on;
  it is why `WriteUserTurn` (seconds-long) **must not** run inline.
- **Shutdown:** Serve ctx cancels → `WriteUserTurn` returns `ctx.Err()` →
  `holds.fail` (its write no-ops on the torn-down writer, logged-and-dropped per
  #765). A delivered-successfully call still "running" (never `end`ed, since T7
  isn't wired) is abandoned: its `Responder` is GC'd with the store, no frame owed.
  No leak.

## Security boundary

`prompt[].text` is the sensitive datum. The security property: host content is
delivered **strictly as a user turn** into claude and is never interpreted as pyry
control input, shell input, a path, or a terminal control sequence.

- **Single narrow sink.** `mapPromptContent`'s `[]byte` output has exactly one
  sink: `promptDeliverer.WriteUserTurn` → `Supervisor.WriteUserTurn` → tui-driver
  `DeliverPrompt` (bracketed paste into claude's PTY). The bytes never reach
  `os/exec`, the control-socket verb dispatch, or a filesystem path.
- **Content-as-shell-command is structurally absent.** No shell is in the path; the
  claude argv is fixed at spawn (`--session-id <uuid>`, #761), long before any
  prompt arrives. `$(…)`, backticks, `;`, `../` are inert here.
- **Content-as-terminal-control is closed by the control-byte guard (the MUST FIX).**
  Because delivery frames the payload as a **bracketed paste**, a raw `ESC` — e.g.
  an embedded paste terminator `ESC[201~` — could break out of paste framing and
  reach claude's TUI as keystrokes / control sequences. `hasDisallowedControl`
  rejects any C0 (`0x00–0x1f`) or DEL (`0x7f`) byte **except** `\t \n \r`. It scans
  **bytes, not runes**, which is correct: valid multi-byte UTF-8 uses only bytes
  ≥ 0x80, so a byte < 0x20 or == 0x7f is never a UTF-8 continuation byte → no false
  positive on legitimate international text. A text-only host never legitimately
  sends a raw control byte, so fail-closed rejection loses no valid content.
- **No host content is logged** — handler / `promptHolds` / `deliverPrompt` log only
  method, session id, and error sentinels. `conversationID` passed to
  `WriteUserTurn` is the **resolved pool id**, not a host string (and isn't consulted
  anyway — the ACP pool sets `ValidateConversation == nil`).

## Patterns established

- **A deterministic control-byte guard is the belt for a paste sink.** When
  untrusted text is delivered as a bracketed paste, shell-injection reasoning
  (fixed argv, no `sh -c`) misses the real vector — terminal-escape injection via a
  raw `ESC`/paste-terminator. The fix is a deterministic code guard at the trust
  boundary (belt of different fabric — not a second stochastic layer). Scan bytes,
  not runes: every disallowed control byte is single-byte ASCII, so a byte scan is
  both correct and UTF-8-safe.
- **Deliver-in and hold-open are one handler when the protocol makes a turn one
  call.** The handler returns `acp.ErrDeferred` to suppress the synchronous frame
  and moves the seconds-long `WriteUserTurn` to a goroutine, keeping the guard
  check + spawn non-blocking on the read loop. Consuming #765 this way is what makes
  the concurrent-second reject and `session/cancel` stay live during a held turn.
- **A per-session hold registry with capture-then-resolve keeps `mu` a leaf.**
  `begin` inline on the read loop is race-free; `end`/`fail` capture the responder
  under `mu` and resolve **after** releasing it, so `writeMu` is never nested under
  `mu`. Idempotent delete-on-first-resolve means at most one of `end`/`fail` finds
  the entry; #765's `Responder.done` CAS is the single frame-authority.

## Lessons learned

*(lifted from PR [#795](https://github.com/pyrycode/pyrycode/pull/795)'s "Lessons
learned" — both are test-harness gotchas, not product defects.)*

- **Testing a held/deferred ACP call over the `io.Pipe` harness: resolve off the
  reader goroutine.** `holds.end` → `Responder.Reply` writes the response frame
  synchronously, and an `io.Pipe` write blocks until a reader consumes it. A test
  goroutine that both resolves *and* reads deadlocks. Wrap the resolve in
  `go holds.end(...)` — which also mirrors production, where T7's turnbridge
  resolves from its own Run goroutine, never the read loop.
- **`substrate-guard` bans `\x1b[` in source in every form** (escaped text *and*
  raw ESC+`[` bytes). A control-byte-guard test that needs the paste terminator
  `ESC[201~` must build it at runtime (`string([]byte{0x1b}) + "[201~"`) rather than
  as a string literal. Prose mentions of `ESC[201~` in doc comments are fine.

## Testing

New `cmd/pyry/acp_prompt_test.go` (467 lines). Table-driven, `t.Parallel()`,
`-race` via `make check`. A `recordingDeliverer` fake (records payloads, optional
injected error / commit gate, mirroring `gatingWriter`) plus a pool-free
live-transport driver reusing `serveACP(ctx,r,w,logger,register)` over `io.Pipe`s
with a custom register wiring `session/prompt` over a test-owned `promptHolds` +
fake deliverer (no fake-claude pool needed — the delivery seam is the interface).
Scenarios: `mapPromptContent` (single/joined text, `\t\n\r` **preserved** inside a
block, non-text kind rejected, `ESC[201~` and bare `\x00` rejected, empty/malformed);
delivery + hold (payload recorded, no frame on the wire until `holds.end` →
`{"stopReason":"placeholder_end"}` echoing the id); concurrent-second reject
(`CodeInvalidRequest` *before* #1 resolves, proving read-loop liveness); unknown /
empty session; security boundary (shell-dangerous text recorded byte-identical, no
side effect); delivery failure frees the slot (subsequent prompt accepted).

## Out of scope (deferred)

- **Resolving the held call on real `TurnEnd`** with the mapped `stopReason` — T7
  [#751](https://github.com/pyrycode/pyrycode/issues/751), via `holds.end`. Until T7
  lands, a delivered prompt holds until host disconnect; tests exercise `end`
  through the placeholder-end path. In a live `pyry acp` with only #749 wired this
  is a safe, incomplete interim, consistent with the epic building up unwired.
- **Producer wiring** (standing up the `turnbridge` producer + `acpTurnStream` sink
  for ACP sessions) — also #751's; #750's sink and #761's pool ship the building
