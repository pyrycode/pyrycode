# Ticket #912 — Gate scheduled + manual rekey emit behind `transportDown()`

`security-sensitive` · extends the #874 push-drain hold to `emitRekeyRequest`'s two callers (umbrella #829 reconnect-reliability design).

Before this ticket, a rekey `rekey_request` sealed while the relay transport was down burned a Noise send-nonce on a frame `m.send` silently dropped. The phone never saw the request; 30s later `handleWake`'s `wakeRekeyReplyTimeout` arm tore the session down at `StatusHandshakeFailure` (4426) and logged `noise.rekey_failed` — a transport outage mislabelled as a rekey failure. Even inside the 30s window, the burned nonce gapped the phone's recv nonce, MAC-failing its next decrypt and killing the conn at 4421 regardless.

## Implementation

- **Gate at the call sites, not inside `emitRekeyRequest`.** Both callers already diverge after the check (scheduled re-arms a timer, manual returns an error), and `handleManualRekey` stops the scheduled 1-hour `rekeyTimer` *before* calling `emitRekeyRequest` — if the check lived inside and returned "deferred," that stop-and-nil would have already run with nothing to re-arm it. `emitRekeyRequest` stays an unchanged pure emit primitive, gaining only a doc-comment precondition (callers MUST check `transportDown()` first) — a documented contract, not enforced code, since the seal site has exactly two callers, both edited here.
- **Scheduled path (`handleWake`'s `wakeRekeyEmit` arm, `internal/relay/v2session.go`).** `transportDown()` true → seal nothing, arm no reply window, re-arm `w.s.rekeyTimer = m.armRekeyRetryTimer(ctx, w.s)` (new helper, copies `armRekeyTimer`'s `time.AfterFunc` + `select{m.wake<-…; <-ctx.Done()}` shape but at `rekeyRetryInterval` instead of `rekeyInterval`), log one content-free Info line (`v2.rekey.emit.deferred_transport_down`), return. The fired 1-hour timer that delivered this wake is one-shot and inert, so overwriting `rekeyTimer` needs no `Stop()`. Re-entering the same `wakeRekeyEmit` kind makes deferral a self-healing bounded-retry loop: each retry fire re-checks `transportDown()` and either emits (recovered) or re-arms (still down).
- **`rekeyRetryInterval = 1 * time.Minute`** — new lowercase package var, test-overridable like `rekeyInterval`/`rekeyReplyTimeout`. Chosen to sit above the relay reconnect backoff ceiling (~30s, so one retry usually lands recovered) and well under the 15-minute `idleTimeout` (so a permanently-dead phone is reaped by the idle sweep, not spun on forever by the retry loop).
- **Manual path (`handleManualRekey`).** New check inserted after the existing `ErrConnNotFound`/`ErrSessionNotOpen` eligibility guards but *before* the scheduled-timer `Stop()`: `if m.transportDown() { return ErrTransportDown }`. Ordering matters both ways — a missing/ineligible conn still gets its precise error regardless of transport state, and on transport-down the scheduled 1-hour timer is left untouched (the session keeps its cadence; the operator just gets "retry later").
- **`ErrTransportDown`** — new package-level sentinel (`errors.New`, mirrors `ErrSessionNotOpen`'s pattern), distinct so the operator sees "transport down, retry" instead of "not open." Needs zero `internal/control` changes: `handleRekey` already puts any non-nil `Rekey` error into `Response.Error` verbatim and only maps `ErrConnNotFound` to a wire `ErrorCode`.
- **TOCTOU-free by the same single-owner-goroutine argument as #874.** Both gate sites and the seal run on the Run goroutine; `s.send` has one owner; `transportDown()` reads an immutable construction-time `func() bool`. No lock, no atomic. The accepted residual is the same one-frame up→down transition race #874 accepted.
- **Inert when unwired.** `transportDown()` is false whenever `Connected` is up or nil, so every existing rekey test (constructed without `Connected`) is byte-identical to pre-#912 behavior — no existing test changed.

Files touched: `internal/relay/v2session.go` (+85/-3), `internal/relay/v2session_test.go` (+279, four new tests). Single production file, as sized.

## Patterns established

- **Extends, doesn't repeat, the #874 precondition-gate shape** — see [`codebase/874.md`](874.md) § Patterns established ("pre-seal probe gates the pop, not the seal"). Here the "pop" analog is the call into the emit primitive: gate at the call site, keep the primitive pure, diverge the recovery action per caller.
- **A precondition documented on the primitive, not enforced inside it, is an acceptable contract when the call-site count is small and fixed.** `emitRekeyRequest` has exactly two callers today, both edited by this ticket; the reserved future `"compromise"` caller inherits the same doc-comment obligation. This is a narrower, more permissive case than #874's `drainOnce` (which *does* enforce the guard inline) — the difference is that `emitRekeyRequest`'s two callers structurally diverge after the check (timer re-arm vs. named error), so a guard *inside* the primitive would need a way to signal the caller which branch fired, which the primitive doesn't have reason to know.
- **A deferred timer retry re-enters the same wake arm rather than introducing a new one** — `armRekeyRetryTimer` pushes the same `wakeRekeyEmit` kind, so `handleWake` doesn't need a new case; the retry is just another fire of the existing arm, self-healing by re-checking the gate each time.

## Security review

Architect self-review (full text in `docs/specs/architecture/912-rekey-emit-transport-down-gate.md` § Security review) verdict: **PASS**. Net-positive, same class as #874: the fix strictly reduces what crosses the internet-exposed Noise send-nonce sequence (no blind seal while down), introduces no new attacker-influenceable input, and preserves the ADR 024 1-hour rekey cadence (a blip defers rekey, never skips it — a genuinely-gone phone is still reaped by the independent 15-minute idle sweep). The one open TOCTOU is the same accepted single-frame transition race #874 carries. `ErrTransportDown`'s text and the new deferred-log line are both content-free (no conn payload, no key material).
