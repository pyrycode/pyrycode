# Ticket #1600 — Map claude's `system/init` model announcement to a bounded daemon event

`init` leaves `ignoredLineTypes`'s implicit drop and gains the sixth `emitSystemSubtype`
arm (fourth `system` subtype), mapping claude's per-turn model announcement to a new
`turnevent.ModelAnnounced{Model, Truncated}`. Sixth member of the family #1380 opened:
#1380 (`task_started`), #1381 (`background_tasks_changed`), #1382 (`task_updated`), #1385
(`thinking_tokens`), #1404 (`rate_limit_event`). PR
[#1614](https://github.com/pyrycode/pyrycode/pull/1614). No wire frame appears —
`turnbridge.MapEvent`'s `default` still drops the variant, exactly as it does for the five
siblings — so this is the producer half only.

## Implementation

- **Why the value is worth having.** The daemon's two existing `model` payloads
  (`protocol.ScreenSnapshotPayload`, `protocol.SessionSettingsPayload`) both mean the
  *per-session override* — `""` means "inherited default, no override" — so in the
  ordinary case the daemon publishes an empty string while claude has named a concrete
  model on every turn. The daemon knows what it asked for; only claude knows what it got.
- **What claude actually announces, measured across two claude versions and three spawn
  shapes:** a bare family alias gets dated (`haiku` → `claude-haiku-4-5-20251001`, the
  committed capture), anything already fully formed passes through unchanged
  (`claude-haiku-4-5`, `claude-sonnet-5`). The rule is "at least as specific as what it
  was given" — not reliably dated, and not guaranteed to appear in any published model
  list. `Model` carries the value byte-for-byte: no lowercasing, alias expansion,
  date-stamping, family mapping, or list lookup.
- `systemInitLine{ Model string }` — one field. The captured init line carries 22 keys;
  21 are deliberately absent from the decode target. `cwd` (operator's filesystem path)
  and `session_id` (claude's session identity, not the daemon's conversation identity)
  are named specifically: absent from the *decode target* is a stronger guarantee than a
  reflection sweep, because a field never declared cannot leak. A non-string `model`
  fails the whole decode — the only reachable undecodable case, since `consumeLine` has
  already decoded the line into `streamLine` before this second decode runs.
- New cap `maxModelField = 256` — ~10x the observed maximum (25/16/15 bytes across the
  three spawn shapes), the same ratio `maxTaskFieldID` has to its observation. A separate
  constant from `maxTaskFieldID`/`maxRateLimitField` even though all three currently equal
  256 (folding them would let a future task-id budget change silently move this one), and
  deliberately *not* `validModel`'s 64 (`internal/relay/v2session_settings.go`) — that
  validator bounds a phone-supplied override the daemon accepts and enforces a charset;
  this cap bounds what claude announces, which the daemon neither controls nor may reject.
- **Empty suppresses, absent suppresses, undecodable logs — three drop paths, only one
  logs.** `il.Model == ""` (absent and present-but-empty land here identically) returns
  `true` with no event and no log at all — diverging from the task handlers, which emit
  with the field empty on an absent value. Here the model *is* the whole payload: an
  event naming no model would assert a claim the line didn't make. `emitRateLimit`'s
  `case ""` rung is the precedent, not `emitBackgroundTaskStarted`'s emit-with-empty rule.
  The undecodable arm logs `Debug("streamsup: dropping undecodable system line",
  "subtype", "init")` — the subtype keyword only, **never `err`**: `encoding/json` quotes
  the offending input bytes into its error text, so `"err", err` would leak the model
  value through a channel no per-path attribute check can see, defeating the whole
  no-log guarantee via the exact idiom CLAUDE.md otherwise asks for (wrap errors with
  context). Message is byte-identical to the task siblings' undecodable arms.
- **Observable consequence of going silent instead of logging on the empty-model path:**
  before this arm, every `init` produced one `"streamsup: dropping stdout line"` Debug
  per turn (the generic `system` drop). After it, a model-carrying `init` produces no log
  record at all, and a model-less one produces none either — one *fewer* Debug per turn,
  and no test pins the record that disappeared.
- No `Unrecognized` on any path: keeping `system` whole on `ignoredLineTypes` is what
  makes "no system line reaches the unrecognized lane" structural, worth more than
  surfacing a malformed line of a subtype the parser already knows.
- `cmd/pyry/interactive_turn_v2.go`'s `eventKind` gained a sixth mapped arm,
  `ModelAnnounced → "model_announced"` — name only, never `Model`, for the #833 posture
  restated in `internal/relay/v2session_settings.go` and `internal/sessions/pool.go`
  ("model / effort / YOLO values are NEVER logged at any level"). No `Handle` arm: the
  variant has no wire mapping yet, so it lands in `Handle`'s `default`
  (`interactive_turn.unknown`, content-free) — deliberately deferred to whichever ticket
  adds the protocol type and the `turnbridge.MapEvent` case together.
- **The one place the spec's "0 consumer call sites" read turned out incomplete:**
  `cmd/pyry/stream_turn_busy_test.go`'s `TestTurnMarkFor_TotalOverEveryVariant` derives
  its expected set from `turnevent`'s `isTurnEvent` markers, not from any `default` arm,
  so it needed a new table row (`ModelAnnounced{...} → turnMarkNone`) the moment the
  variant existed — the production `turnMarkFor` switch itself needed no change, exactly
  as the spec said.
- **Corrections landing in this PR (AC 5):** `consumeLine`'s drop-branch comment (`init`
  no longer named as a dropped example; `status` is the one measured-and-dropped subtype
  left); `TestParser_IgnoredLineTypesStaySilent`'s doc (its opener used to argue the
  table's purpose *from* `system/init`; rewritten around `system/status` and the
  never-seen-subtype row, `init`'s row re-homed verbatim into the new mapping tests);
  `internal/e2e/realclaude/dropped_line_capture_test.go`'s `system/init` `why:` string
  (subtype is mapped now; verdict unchanged because *this* fixture carries no `model`);
  `interactive_stream_inband_model_test.go`'s header (the "no daemon event" half is now
  false — the log half survives: the value reaches an event, still reaches no log);
  `interactive_stream_unrecognized_test.go`'s header (dropped the now-doubly-stale
  "into background-task events" characterisation).

## Patterns established

- **A variant's totality test can derive from the type package's markers rather than any
  switch's `default` arm — check both before counting consumer sites as zero.** A sizing
  pass that enumerates dropping `default`s misses a marker-derived enumeration test like
  `TestTurnMarkFor_TotalOverEveryVariant`; it still needed a new table row even though the
  production switch needed none.
- **A capture whose value is already in the mapping's canonical form cannot prove the
  mapping doesn't normalize.** The captured model (`claude-haiku-4-5-20251001`) is already
  lowercase and already dated, so a mapping that lowercased or date-stamped values would
  map it to itself and the from-capture test would stay green regardless. The verbatim
  proof needs synthesized mixed-case and bare-alias rows, not just the capture.
- **`encoding/json`'s error text quotes rather than reproduces input, so a
  `strings.Contains` sweep on it is not a reliable no-leak proof.** The drop-path no-log
  test asserts the record's attributes with an exact-match comparison against the
  expected map, not "does it contain the sentinel value."

## Lessons learned

From the PR body's own "Lessons learned" section (developer, verbatim):

> **A new `turnevent` variant is not consumer-free: `cmd/pyry`'s
> `TestTurnMarkFor_TotalOverEveryVariant` (#1496) derives its expected set from the
> package's `isTurnEvent` markers, so it fails the moment a variant lands.** The spec's
> red-line count read "consumer call sites needing simultaneous update: 0" on the
> strength of `turnMarkFor` having a dropping `default` — true of the production switch,
> and the production switch did need no change. What the marker-derived totality test
> requires is one TEST row declaring the new variant's classification (`turnMarkNone`
> here). That is the test doing its job, not a defect, but a sizing pass that enumerates
> dropping `default`s will miss it: the guard is derived from the marker set, not from
> any switch. Worth checking for marker-derived enumerations, not just for `default`
> arms, when adding a variant.
>
> **`encoding/json` quotes the offending input into its error text, so `"err", err` on a
> decode-failure path is a content leak a `strings.Contains` sweep cannot reliably
> catch** — the error text quotes rather than reproduces. The drop-path test therefore
> asserts the record's attrs with `reflect.DeepEqual` against the exact expected map, not
> "does it contain the value".
>
> **A capture whose value is already in the mapping's canonical form cannot prove the
> mapping does not normalize.** The captured model reads `claude-haiku-4-5-20251001` —
> already lowercase, already dated, already fully formed — so a mapping that lowercased
> or date-stamped would map it to itself and the from-capture test would stay green. The
> verbatim proof needs synthesized mixed-case and bare-alias rows.
>
> Flagged for the documentation phase (spec § "Not a developer AC"):
> `docs/knowledge/features/e2e-realclaude.md` still says `emitSystemSubtype` has no
> `init` arm "by the #833 posture" — now false, and its reasoning was already wrong,
> since an event is not a log.

Code review's own verification, worth keeping alongside the above:

- AC 3's pin proven by mutant: removing `emitModelAnnounced`'s empty-model gate (via
  `go test -overlay`, no worktree write) reddens exactly `TestDropcapClassification/system/init`
  and nothing else in that test, plus the two counterpart stays-green-unmodified pins the
  spec named — `TestParser_LineMapping`'s "system init is a no-op" row and
  `roundtrip_test.go`'s two-events-per-turn assertion.
- `go vet -tags e2e_realclaude ./internal/e2e/realclaude/...` type-checks the tag-gated

  (10 `=== RUN`).
