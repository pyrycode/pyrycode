# Ticket #1362 — Probe instrument: prove end to end that no value from the trailer line reaches the artifact through the published key names (offline)

#1363 published the trailer's top-level key names on `finSighting` and
`finTrailerRecord`, bounded by `finBoundKeyNames`; #1364 proved the bounds
bite. Neither checked what happens **after** the reader returns — that the
two builders between the reader and the artifact, and the writer after them,
keep the field value-free in the files an operator actually pastes. This
ticket closes that gap with four checks over the assembled pipeline, no one
of which subsumes another, plus a line-count-neutral repair of a comment
#1364 left false.

## Implementation

- **One new file**, `internal/e2e/realclaude/finding_key_name_containment_test.go`
  (650 lines, `//go:build e2e_realclaude`), plus a 5-line repair of
  `finding_trailer_evidence_test.go:200-204`. Zero production source touched.
- **Shared drive helper**, `finContainRender(t, line) (map[string][]byte, []string)`
  — scans a fixture line, substitutes it as `finWriteInputs().Trailer`, writes
  the artifact under a per-test `t.TempDir()`, and returns the rendered files
  plus the reader's own `KeyNames` alone. The narrow `[]string` return is a
  security-review MUST FIX fix: the first draft returned the whole
  `trailScanResult`, which would have promoted `scan.Line` (up to 512 bytes of
  model-chosen text, OPERATOR-REVIEW-BEFORE-PASTE) and `*resultTrailer` into
  the reach of every failure message in the file. After the fix no test here
  holds a `trailScanResult`, a `*resultTrailer`, or a `trailObservation` —
  containment by shape, not by a printing discipline that must not be broken.
- **AC1 — `TestFinContainArtifactCarriesNoTrailerValue`.** Sweeps every file
  `finWriteRender` wrote for `trailNeedle`, planted two ways in a dedicated
  fixture (`finContainValuePlantedTrailer`, not a repad of the shipped
  `finWriteTrailerPad` fixture): past the 512-byte line cap inside `result`,
  and as `session_id`'s whole value (`trailPaddedTrailer` hard-codes
  `session_id` to a UUID, so this needed its own renderer). The plant list
  excludes the four positions the record publishes verbatim by design
  (`subtype`, `is_error`, `terminal_reason`, `stop_reason`) — planting there
  would fail a *correct* build. Covers `run.md`, not `run.json` alone; the
  shipped in-cap row at `finding_artifact_write_test.go:1084-1087` is left
  untouched as a sibling, since it and this check need opposite pad positions
  and each is blind to the other's mutant (M3 vs M4).
- **AC2 — `TestFinContainPublishedNamesCarryNoValue`.** Reuses the shipped
  `trailKeyNamesNeedledTrailer` / `trailKeyNamesNeedles()` fixture at **pad
  0** — the deliberate inversion of the reader-tier
  `TestTrailKeyNamesCarryNoValues`'s pad 600 — and sweeps the **published
  names field alone**, after both builders, via the shipped
  `finPublishedKeyNames`. This is the only check that can see a builder
  copying one of the four by-design-verbatim positions into the names field
  (M5); AC1 is green there by design.
- **AC3 — `TestFinContainCarriersReachNoRawMessageMap`.** A `reflect` walk,
  per carrier (`finSighting{}`, `finTrailerRecord{}`), banning
  `map[string]json.RawMessage` reachability via the shipped
  `finRecordInputReaches`, paired with a control asserting the same walk
  *does* reach `[]string` (`KeyNames`'s own type) — without the control the
  ban would be green against a walk finding nothing at all.
- **AC4 — `TestFinContainNoDetailNamesAKeyName`.** Splices a needle onto
  `trailFixtureTrailer` as one extra top-level key name (sorts first —
  uppercase precedes `_`), asserts it reaches the artifact's `trailer_keys`
  field as element 0, then walks every Detail in the rendered `run.json` with
  the shipped `finWriteObservedDetails` and asserts none contains it. This
  discharges the *names* half of the Detail prohibition #1364 left open; the
  *count* half (M7) has no instrument and is stated as unproven at the row,
  not implied discharged.
- **The comment repair.** `finding_trailer_evidence_test.go:200-204` claimed
  the Detail prohibition was "made red by a hostile-name fixture in #1364" —
  false since #1364 measured that fixture 27 bytes short of red and cut it
  (see `codebase/1364.md`). Replaced five comment lines with five, naming
  this ticket's needle sweep as what makes it red and stating the count half
  stays unproven. Strictly line-count-neutral, so the nine inbound cites
  below the repair site hold unmoved.

## Review cycle

One pass, **PASS**, no MUST FIX. Two SHOULD FIX, both left unfixed as
non-blocking (threshold is three):

1. AC1's non-vacuity precondition (`reflect.DeepEqual(read, trailExpectedKeyNames())`)
   is scoped to everything that would make the *check* fail, not to what
   would make it *vacuous* — under mutation M1 it fires before the sweep
   does, so the sweep itself is never observed red on the headline mutant
   the ticket's own matrix predicted it would catch. Not a correctness gap
   (M1 is still caught, and M4 was run as an overlay specifically to exercise
   the sweep directly), but a diagnosis cost: the fix the reviewer describes
   is the same shape AC2 already uses (bounds-inertness plus a count check
   rather than full equality).
2. The header's mutant-matrix table quoted a projected Detail-size figure
   (424 bytes / 88 of room) that AC4's own measurement over the actual
   fixture superseded (426 / 86); a third independent measurement in review
   found a third figure (419 / 93) — evidence the number is a property of
   the mutant's exact wording, not of the tree, and shouldn't be pinned in
   two places.
3. **[NIT]** the plant-list comment says "every string-valued position the
   line carries, the four the record publishes included" — only three of
   the four are string-valued (`is_error` is a bool). Inherited from the
   AC's own phrasing.

Security review (spec self-review, second pass): **PASS**. The one MUST FIX
from the first pass (the `trailScanResult` return) is described above under
"Shared drive helper" and landed as specified — verified in code review by
grepping the file for `trailScanResult`, `*resultTrailer` and `scan.Line`.

## Lessons learned

(From PR #1372's body and its code-review comments.)

- **A non-vacuity precondition can preempt the sweep it guards, and that
  costs diagnosis, not correctness.** AC2's spec'd precondition was
  `published == read`; a builder that *adds* an entry (M5, the exact mutant
  AC2 is the sole red for) is a slice diff, so equality would have fatal'd on
  it before the sweep could name which position leaked. Shipped instead with
  the two bounds' own inertness checks plus a dropped-name count, which lets
  an added entry reach the sweep. AC1 kept the tighter `DeepEqual` form and
  paid the same cost on M1 (SHOULD FIX 1 above) — when a precondition and the
  check below it can both fire on the same mutant, scope the precondition to
  what would make the check *vacuous*, not to everything that would make it
  *fail*.
- **"Not mutation-demonstrable" is worth one overlay before it's accepted.**
  The spec wrote off M4 as a schema edit rather than a one-liner. Under
  `-overlay` that cost about one turn, and it was the only thing that ever
  exercised AC1's headline sweep and proved the directory walk reaches
  `run.md` and not just `run.json`.
- **Prose that pins a projected measurement drifts on contact.** The spec
  projected a 424-byte names-interpolating Detail over its own hypothetical
  fixture; the shipped fixture measures 426. Code review found a third figure
  (419) under a differently-worded mutant. A failure message that computes
  its headroom from the observed Detail can't go stale; a comment that
  quotes a literal will.
