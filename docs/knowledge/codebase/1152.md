# Ticket #1152 — Outbound-stream tailers adopt owned-fd `TailFromEnd`

Split from #973. The offset-adoption clause sequenced behind the resolver consolidation (#1150): the three outbound-stream resolvers' warm-resume offset switches from a caller-`os.Stat`ted byte size to `tuidriver.TailFromEnd` (`-1`), so `TailJSONL` (tui-driver v1.12.0) seeks against its own fd instead of a size the caller measured on a possibly-different fd. This closes the #929/#930 cross-fd TOCTOU class on the phone-facing tail path: caller stats file A, the tail later opens a rotated file B, and the stat-time offset lands wrong. The cold-start `offset = 0` rule (a brand-new file whose whole content is the in-flight reply) is unchanged.

## Implementation

PR #1161, one production file (`cmd/pyry/interactive_turn_stream_v2.go`, +42/-33 lines net across mechanical + doc-comment edits) plus its test file.

- `resolveLatestSessionJSONL`, `resolveOwnBootstrapJSONL`, `resolveBoundSessionJSONL` — each warm-branch offset assignment (`off := res.Size` / `off := info.Size()`) became `off := int64(tuidriver.TailFromEnd)`. The cold-start override (`if !resolvedOnce && sawEmpty { off = 0 }`) is untouched in all three.
- `resolveOwnBootstrapJSONL`'s `os.Stat(candidate)` stays — it's the vanish-race existence gate that latches `sawEmpty` — but its result is no longer read for size: `info, err := os.Stat(candidate)` became `if _, err := os.Stat(candidate); err != nil { … }`.
- Doc comments on all three resolvers reworded from "offset = size (tail from EOF)" to "`TailFromEnd` — own-fd EOF, tail owns its fd" so the prose matches the mechanism; same confidentiality property (never replay a transcript's history to the phone), stronger guarantee (content written in the resolve→open window is also skipped, since `TailJSONL`'s own-fd stat happens at open time, not resolve time).
- No signature change on any resolver (`func(ctx) (path string, startOffset int64, err error)`), so the three tailers (turn stream, ACP turn stream, ACP permission stream — the latter two reuse `resolveBoundSessionJSONL` verbatim) inherit the sentinel for free. `producer.go:327`'s `sess.Events(subCtx, path, off, tr)` and its `cold_start` diagnostic (`off == 0`) are unchanged — warm is now `-1` instead of a size, cold is still `0`.
- `internal/transcript` is untouched: `Result.Size` is still produced by `Newest`/`StatByID` and still consumed by Family A (`internal/sessions` growth-confirm); Family B just stopped reading it for the offset.

## Patterns established

- **A caller-stat offset handed across an fd boundary is a TOCTOU by construction**, independent of how carefully the file is guarded beforehand. `GuardProbedPath`/`CanonicalDir`/`ValidStem` (from #1148, wired in #1150) validate *which file* is safe to tail; they say nothing about *what offset* is safe once the tail opens its own fd later. The fix here isn't a guard — it's not computing the offset from a separate stat at all. `TailFromEnd` (or any own-fd-relative sentinel) structurally removes the cross-fd swap window rather than narrowing it.
- **A stat call can be kept as a pure existence/vanish-race gate after its size-read is deleted.** `resolveOwnBootstrapJSONL`'s `os.Stat` still runs, still detects the file vanishing between probe and stat, still feeds `sawEmpty` — only the `.Size()` accessor on its result was dropped. Don't over-collapse a "delete the size read" change into "delete the stat call."

## Lessons learned

(From the PR #1161 body and code-review pass — see `code-review-tailfromend-outbound-tailers-pass-recipe` for the full recipe.)

- When a value-only change flows through a forwarding seam (`producer.go:327` → `Session.Events` → `TailJSONL`), grep every *consumer* of that value, not just the call sites that changed. `relay.go:520` has a second `resolveOwnBootstrapJSONL` call (`usageResolve`) that discards the offset (`path, _, err := …`) — inert to this change, but worth confirming explicitly rather than assuming from the three named tailers alone.
- Verify the sentinel-forwarding claim (AC2 — "no tui-driver bump needed") against the actual pinned dependency source, not the ticket body's guess at a version. The ticket originally cited tui-driver v1.11.2 as stale; refinement confirmed `go.mod` already pinned v1.12.0 and `Session.Events` (`pkg/tuidriver/events.go:259`) forwards `startOffset` unchanged, and `TailJSONL` only rejects `< -1` — so `-1` is legal with zero library change.

## Out of scope (named in the ticket, unchanged)

- `internal/turnbridge/producer_test.go`'s `newBoundResolve` — a local test double that still returns `info.Size()` for its warm case, but the test it backs (`TestNewTargetSubscriber_SwitchDuringBackoffColdStartsBoundTail`) asserts only the cold-start offset (`0`), which this change doesn't touch.
- The interactive **modal** stream (`interactive_modal_stream_v2.go`, `NewScreenTargetSubscriber` → `ScreenEvents`) — not a tailer, opens no JSONL, has no offset.
- The **contextwindow** reader (full-scan from 0) and **growth-confirm** (size baseline, no tail) — neither consumes a tail offset.
- The **agent-run** PTY path (`internal/agentrun/ptyrunner/runner.go`, hardcoded offset 0, its own `tuidriver.SessionJSONLPath`) — a separate single-session reader, not part of this consolidation.

## Testing

`cmd/pyry/interactive_turn_stream_v2_test.go` — every warm-offset assertion flipped from `want <size>` to `want tuidriver.TailFromEnd`, and the three `_WarmStartTailsFromSize` tests renamed to `_WarmStartTailsFromEnd`; the `_ColdStartTailsFromZero` tests and every not-found `("", 0)` assertion stayed at `0` unedited. New behavioral test drives a real `tuidriver.TailJSONL` end-to-end: write `[a, b]`, resolve → assert `TailFromEnd`, append `c` **before** opening the tail, open the tail, append `d`, drain → assert only `d` streams (neither the pre-existing history `[a, b]` nor the mid-resolve-window growth `c` replays). A cold-start counterpart pins the file-appears-after-not-found path streaming `[a, b, …]` from the top. `make check` (go vet, staticcheck, `go test -race ./...`) green; `make e2e-realclaude` ok (0.901s, creds present).
