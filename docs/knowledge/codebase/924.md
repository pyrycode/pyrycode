# Ticket #924 — streamrunner reaps claude's detached Bash process groups on teardown

Wire-consumer child of the #923 reaper lift (split from #915). The stream-json runner
(`PYRY_USE_STREAMJSON=1`, the operator rollback path kept per the #914/2026-05-19 decision) had no
equivalent of ptyrunner's #565 descendant-Bash-group reap: its `cmd.Cancel` only SIGTERMed claude
itself. A dispatcher wall-clock SIGTERM landing mid-tool therefore left claude's detached Bash group
(`go test -race`, a Gradle daemon, an `npm` build) orphaned, reparented to init, unbounded.

## Implementation

- **New `internal/agentrun/streamrunner/reap.go`** — one seam var,
  `reapDescendantGroupsFn = agentrun.ReapDescendantGroups`. Byte-for-byte mirror of
  `ptyrunner/reap.go`'s seam, minus `killGrace` (streamrunner already defines its own SIGTERM→SIGKILL
  grace const at `runner.go:44`, untouched by this ticket).
- **`runner.go`'s `cmd.Cancel`** (the sole edit site) now reaps before signalling:
  ```go
  cmd.Cancel = func() error {
      reapDescendantGroupsFn(cmd.Process.Pid, logger)
      return cmd.Process.Signal(syscall.SIGTERM)
  }
  ```
  `cmd.Cancel` fires when `childCtx` is done — via the operator ctx (SIGTERM/SIGINT) **and** the
  idle-stall watchdog's `cancelChild` — so this single hook covers both teardowns. No `ctx.Err()`
  discriminator: the watchdog-path reap is a harmless no-op (the watchdog only fires while claude
  owes an assistant turn, i.e. no tool in flight, so the descendant walk finds nothing). Never fires
  on a clean exit — `cancelChild` there runs only after `cmd.Wait()` returns, by which point os/exec
  has already stopped its ctx watcher.
- **Test**: `TestRun_CtxCancel_ReapsDescendantGroups` in `runner_test.go`, cloning the existing
  `TestRun_CtxCancelMidRun` harness (`sleep` fake-claude mode, cancel the parent ctx ~100ms in) and
  adding `reapRecorder` / `swapReapSeam` / `assertReapedLivePid` (ported from
  `ptyrunner/runner_test.go`) on top. Non-parallel — it mutates the package-var seam. One test
  suffices for both teardown paths: both route through the identical `cmd.Cancel` closure, and the
  watchdog path is independently proven to cancel `childCtx` by the existing watchdog tests.
- **Premise gate (AC#1):** per the architect spec, the structural-fallback branch applied — #565
  already measured (interactive claude, 3/3) that a graceful SIGTERM does not make claude reap its
  own detached Bash group, and the detachment is claude's own `setpgid` isolation of each tool
  command, independent of which runner signals it. The wire is harmless even under a wrong premise
  (an empty/already-reaped tree → `ESRCH` skipped, no-op), which bounds the downside.

## Patterns established

- Confirms the [[architect-923-helper-lift-seam-and-testmain-fold|923 lift]] pattern: re-pointing a
  package-var seam at a newly-shared symbol is a one-line change per consumer, with the call site,
  the comment rationale, and the test doubles all portable verbatim from ptyrunner to streamrunner.
- One `cmd.Cancel` hook covering two independently-triggered teardowns (operator ctx + watchdog) is
  provably safe without a discriminator when the "wrong" path's reap is structurally a no-op (no live
  descendant tree at fire time) — don't add branching to distinguish teardown causes when both are
  safe to treat identically.
