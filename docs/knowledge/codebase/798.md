# Ticket #798 — live-wire the interactive modal surfacer into the relay

The **composition-root wiring** that gives the frozen, unit-proven
`interactiveModalEmitterV2` (`cmd/pyry/interactive_modal_v2.go`) its **first
non-test caller**. Before this ticket `newInteractiveModalEmitterV2` had **zero
non-test callers**, so a running daemon could never emit `modal_shown`, the
fail-closed deny-on-timeout ([#725](725.md)) never armed in production (nothing
`Record`ed a modal), and the local-attach dismissal arm ([#706](706.md)) was
dormant. Three in-code comments deferred the live `Session.Events()` wiring to
"#708", but #708 closed and split into four **test-only** e2e tickets
(#791–#794) without ever carving out the production wiring it was meant to
carry. This ticket delivers that missing wiring, so the Phase 3 live capstones
[#791](https://github.com/pyrycode/pyrycode/issues/791) (remote permission
answered) and [#793](https://github.com/pyrycode/pyrycode/issues/793) (two-head
first-answer-wins) become genuinely harness-only. EPIC #597 Phase 3.

**Wiring only** — every leg's correctness is proven upstream (surface
[#716](716.md), gated resolution + nonce anti-replay [#717](717.md),
deny-on-timeout [#725](725.md), cross-head local dismissal [#706](706.md)) and is
**not touched or re-proven** here. The template is the shipped
`startInteractiveTurnStreamV2` ([#633](../features/turnbridge-package.md), the
mobile turn stream).

Full package documentation:
[features/modalbridge-package.md § Live daemon wiring](../features/modalbridge-package.md#live-daemon-wiring-798)
and [features/v2-session-manager.md § Deny-on-timeout](../features/v2-session-manager.md).

## Implementation

**2 production files** (one new, one edited), plus one new test file. **No new
package, no new exported type, no reject branch** — pure additive within-`cmd/pyry`
wiring of pre-built primitives; `modalReg`, `sup`, `active`, `boundHost`, `mgr`,
`claudeSessionsDir`, `logger` are all already locals at the `relay.go:306` call
site, so no signature fan-out into `startRelayV2`.

- **`cmd/pyry/interactive_modal_stream_v2.go` (new, ~153 LOC)** — three free
  functions + one consumer-side interface:
  - `startInteractiveModalStreamV2(ctx, sup, active, boundHost, mgr, modalReg, claudeSessionsDir, logger) func()`
    — constructs `newInteractiveModalEmitterV2(modalReg, mgr, mgr, logger)` (`mgr`
    is **both** the capability-gated broadcaster — `ActiveConns`/`Push`, already
    the turn emitter's broadcaster — **and** the deny-on-timeout armer —
    `ArmModalTimeout`, [#725](725.md)), reuses `resolveTarget` +
    `turnbridge.NewTargetSubscriber` **verbatim** from the turn stream, spawns one
    goroutine over `runModalStream`, and returns a `func(){ <-done }` cleanup.
  - `boundScreenText(active, boundHost, bootstrap screenSnapshotter) func() string`
    — the paired-screen resolver (below).
  - `runModalStream(ctx, sub, screenText, emitter)` — the bespoke mapper-free drain
    (below); the **sole caller** of `emitter.Handle`.
  - `screenSnapshotter interface{ ScreenSnapshot() (text string, live bool) }` —
    the bound host's rendered-screen seam.

- **`cmd/pyry/relay.go` (edit)** — one gated call + one cleanup join, co-located
  with the turn stream inside the existing shared gate. Also refreshed the now-stale
  `#708` registry comment at `relay.go:302`.

### The reuse decision — a second, independent follow-active subscription

The turn stream and the modal stream need the *same* thing: the active
conversation's live tui-driver event stream, following conversation switches with
cross-conversation confidentiality ([#679](679.md)/[#686](686.md)). The key
insight (PO-confirmed, architect-adopted): `NewTargetSubscriber` yields **raw**
`tuidriver.Event`s — the turnbridge mapper that *discards* modal events
(`EventKindPtyModalShown`/`Hidden`) runs **downstream** in `Producer.drain`, which
this stream does **not** use. So the modal stream **reuses `resolveTarget` +
`NewTargetSubscriber` wholesale** and adds only a bespoke, mapper-free drain loop.
This is why the ticket is *thinner* than the turn stream despite consuming raw
events — and why it is **not** a second `turnbridge.Producer`.

This opens a **second** `Session.Events()` subscription on the same bound
`*tuidriver.Session`. tui-driver blesses that explicitly (`events.go:159` — two
`Events()` calls spawn two independent merge loops, each over its own JSONL tail +
50 ms poll loop, sharing no mutable state), so the modal stream cannot perturb the
turn stream. The modal drain ignores every non-modal event, so the extra JSONL
tail bytes are never inspected — the by-id resolver still selects the correct
per-conversation file, so no foreign transcript is opened.

### The `ScreenSnapshot` seam — type-assert, do NOT widen `turnbridge.SessionHost`

`boundHost` returns a `turnbridge.SessionHost` (`Session()`/`WaitForPTY()` only),
but the paired screen text (AC3) must come from the same bound supervisor, whose
concrete type `*supervisor.Supervisor` **also** carries `ScreenSnapshot`
(`supervisor.go:446`). Rather than widen the shared `turnbridge.SessionHost`
interface (which would force a rendered-screen method onto a package that has no
business with screens, and touch a cross-package contract for a `cmd/pyry`-local
need), the wiring defines a **consumer-side** `screenSnapshotter` interface in
`package main` and **type-asserts** the returned host to it. The host `boundHost`
returns is concretely `*supervisor.Supervisor` (`main.go:774,778`), so the
assertion succeeds in production and stays testable with a fake. This mirrors the
existing `relay.ScreenSnapshotter` (`v2session.go:433`, consumed for
`request_snapshot`). Blast radius stays inside `cmd/pyry`: no turnbridge edit, no
turn-stream disturbance.

### `boundScreenText` — the paired-screen resolver (AC3)

A closure that mirrors `resolveTarget`'s host-selection branch so the paired screen
comes from the **same** supervisor as the modal event:

- `convID == ""` (no route yet) → `bootstrap.ScreenSnapshot()` — the pre-route
  path, matching `resolveTarget`'s bootstrap branch (AC4 consistency). `bootstrap`
  is the same `sup` (`*supervisor.Supervisor`) the turn stream takes.
- `convID != ""` and `boundHost(convID)` ok → type-assert the returned
  `SessionHost` to `screenSnapshotter`, return its `ScreenSnapshot()` text.
- `boundHost` miss, or host not a `screenSnapshotter` (defensive) → `""`. An empty
  screen is safe: the emitter surfaces a modal with an empty body; the
  security-critical fields (`modal_id`, `class`, `options`) are screen-independent.

Only `text` is used (the `live` bool is ignored — an empty text is the natural
degrade). **Never logs the returned text.** `active` never resets to `""` once a
route lands (`activeConversation.set` only advances to non-empty ids,
`main.go:1073`), so a modal on a bound session always resolves that bound host's
screen — **never a stale bootstrap host** (AC3).

### `runModalStream` — the single-goroutine drain

The bespoke outer-resubscribe + inner-drain loop, mirroring `Producer.Run`/`drain`
but over raw `tuidriver.Event`s (no `turnbridge.Producer`, no mapper):

- **Outer:** `sub(ctx)` errors only on ctx cancel (the `Subscriber` contract) →
  return. A closed channel (session restart) breaks back to re-subscribe onto the
  now-active target — **follow-active**.
- **Inner:** `select` on `<-ctx.Done()` (return) and `ev, ok := <-ch` (`!ok` ⇒
  break to re-subscribe). Per event:
  - `EventKindPtyModalShown` → `emitter.Handle(ctx, ev, screenText())` — evaluate
    the screen **only here**, so no `ScreenSnapshot` render happens on the 50 ms
    idle/thinking/JSONL ticks (AC2 efficiency).
  - `EventKindPtyModalHidden` → `emitter.Handle(ctx, ev, "")` — screen unused on the
    hidden path (the body is already gone; `interactive_modal_v2.go:85`).
  - every other kind → ignored.

**Single-Run-goroutine invariant (AC2):** `Handle` is invoked only from this one
goroutine, so the emitter's unguarded counters (`nextID`, `outstandingID`,
`outstandingClass`) never race — the exact invariant the emitter documents
(`interactive_modal_v2.go:22`). The one field a second goroutine touches is the
modal registry (`modalReg`, shared with the inbound resolver at `relay.go:337`),
which carries its own mutex ([#717](717.md)/[#706](706.md), unchanged).

### Data flow

```
claude permission/trust prompt appears on bound host A
  → tuidriver merge loop (SECOND, modal subscription) emits EventKindPtyModalShown{class}
  → runModalStream drain (single goroutine) receives it
  → screenText() = A.ScreenSnapshot()   (rendered, ANSI/OSC-free, inside the ADR-025 seal)
  → emitter.Handle(ctx, ev, screenText)
      → PermissionRequestForClass(class, screenText)  (body = trimmed screen)
      → modalReg.Record → mints modal_id nonce
      → mgr.ArmModalTimeout(ctx, modalID)             (fail-closed deny window, #725)
      → broadcast modal_shown to every interactive conn (#607 gate)

operator answers at the local attach TTY → claude modal vanishes
  → EventKindPtyModalHidden{class}
  → emitter.Handle → modalReg.Resolve(id) → if this head wins: audit + broadcast modal_dismissed{local} (#706)
```

### Relay wiring & lifecycle

Co-located inside the existing shared gate `bridge != nil && claudeSessionsDir != ""`
(foreground has no phone-mirroring surface; an empty sessions dir would make the
resolver perpetually error and Warn-spam every retry). The gate now installs
**both** streams; the disabled-info log covers both. The new `modalStreamCleanup`
is joined in the cleanup closure **before `<-mgrDone`**, alongside `streamCleanup`,
so no fan-out races a winding-down manager (mirrors the turn stream at
`relay.go:401-412`). Shutdown: ctx cancel → `sub(ctx)` returns `ctx.Err()` (or the
drain's `<-ctx.Done()` fires) → `runModalStream` returns → `done` closes →
`<-done` unblocks.

## Patterns established

- **"Ship the primitive unit-tested, wire it in a lifecycle ticket" — closed for
  the mobile modal leg.** #716/#717/#725/#706 shipped the surfacer + all four
  resolution arms with a scripted-fake harness and **zero non-test callers**; #798
  is the lifecycle ticket that stands up the live event feed and gives the emitter
  its first production caller. Same split as [#632](632.md)/#633 (turn stream) and
  #750/[#796](796.md) (ACP outbound) — and the exact mirror of the mobile turn
  stream.
- **Raw-event consumers reuse the whole follow-active subscriber; only the drain is
  net-new.** Because `NewTargetSubscriber` yields raw `tuidriver.Event`s and the
  modal-dropping mapper lives downstream in `Producer.drain`, a *second* consumer
  over the *same* follow-active machinery costs only a mapper-free drain loop — not
  a bespoke subscriber and not a second `turnbridge.Producer`. This is the sizing
  key that kept the ticket at S; grep the subscriber's return type before assuming
  "consumes raw events ⇒ build a new subscriber".
- **Type-assert a `cmd/pyry`-local interface rather than widen a shared contract.**
  When a follow-active consumer needs a method (`ScreenSnapshot`) the shared
  `turnbridge.SessionHost` doesn't expose but the concrete host
  (`*supervisor.Supervisor`) carries, define the narrow interface consumer-side and
  type-assert — keeping the shared turnbridge contract screen-free and the blast
  radius inside `cmd/pyry`. Mirrors `relay.ScreenSnapshotter`.
- **Two independent `Events()` subscriptions per session are legitimate.**
  tui-driver's `events.go:159` docstring explicitly blesses concurrent merge loops;
  the modal stream opens its own alongside the turn stream's without sharing mutable
  state, at the cost of one extra poll loop + JSONL tail per session (negligible,
  symmetric with the already-shipped turn stream).

## Code review

**PASS** — no findings ([PR #800](https://github.com/pyrycode/pyrycode/pull/800)).
The reviewer confirmed the wiring is a clean, faithful mirror of the shipped
`startInteractiveTurnStreamV2` with no correctness, concurrency, or idiom concerns:
construction (`mgr` as both broadcaster and armer), the single-Run-goroutine
invariant (AC2 — `runModalStream` sole `Handle` caller), follow-active host + screen
pairing (AC3), gate + cleanup-before-`<-mgrDone` (AC4), the drain's faithful
`Run`/`drain` mirror, and content-free logging (AC5). Codegraph confirmed the
"zero non-test callers" premise held pre-PR. `make check` (vet + `go test -race` +
staticcheck + substrate-guard) and `make build` both green. The only auto-committed
churn was the recurring `testdata/permission_protocol_v2.*.json` golden file — a
known per-PR artefact, not a defect (see [745.md](745.md)/[750.md](750.md)).

## Lessons learned

- **Factor the drain and host-selection as free functions for a live-wiring-free
  test seam.** `runModalStream` and `boundScreenText` are top-level functions
  (not methods on a struct that owns a live subscription) precisely so the drain
  can be driven by a `scriptedSubscriber` and the host-selection by a fake screen
  func, with **no live supervisor/JSONL/PTY**. This is the same test seam the turn
  stream established — the reason a "wiring-only" ticket can still carry six
  meaningful unit tests. (Lifted from the PR body.)
- **The screen is re-resolved at handle time, not captured atomically with the
  event.** Reusing `NewTargetSubscriber` (the S-sized path) hides the
  per-subscription host, so `boundScreenText` re-resolves the *current* active bound
  host's screen when a `Shown` arrives. A narrow switch-race window exists where an
  in-flight `Shown` is paired with a just-switched host's screen — but the mobile
  modal surface is **operator-global, not conversation-scoped** (`ModalShownPayload`
  carries no `conversation_id`; the broadcast fans to every interactive conn, all
  authenticated to the same operator via Noise_IK). The worst case is one operator
  momentarily seeing their own *other* conversation's screen in a modal body —
  within a single trust domain, touching **no** security-critical field. Accepted &
  documented, not silently swallowed (see Security below).

## Security

`security-sensitive`. Architect's inline security review (the `security-review.md`
file is absent from the worktree — same fallback as specs #487/#670) is **PASS**,
**net-positive**:

- **Activates a dormant fail-closed control.** Without this wiring `ArmModalTimeout`
  never armed in production, so a surfaced-but-unanswered permission modal would
  block claude indefinitely. After wiring, every surfaced modal is safe-denied on the
  [#725](725.md) window even if it reaches zero phones.
- **Forwards only sealed, redaction-proven screen text.** `ScreenSnapshot` renders
  inside the ADR-025 seal and returns opaque plain text; the wiring forwards it
  without inspecting, storing, or logging it. It is the **first production code to
  handle rendered `ScreenSnapshot` bytes**; the mandated `NoScreenTextLogLeak` test
  guards against a new content-echoing log. Content-free discriminants only.
- **No new inbound surface, secret, or escalation path.** The goroutine runs as the
  daemon, calls only already-authorized `mgr` methods, routes no keystroke itself,
  and cannot grant a permission (`modal_shown` is a notification; the only allow
  keystroke is minted by the gated inbound `modal_answer` resolver [#717](717.md),
  untouched here). Deny-on-timeout remains the default.
- **Residual switch-race** (see Lessons learned): within-operator, screen-only,
  cosmetic body mismatch during a conversation switch — bounded to one trust domain,
  no security-critical field. Documented, accepted; the deterministic alternative (a
  bespoke `(host, ch)`-pairing subscriber) would re-implement the ~120-line
  follow-active loop and blow the S ceiling. Deferred until evidence demands it.

## Testing

`cmd/pyry/interactive_modal_stream_v2_test.go` (package `main`), `-race`-clean,
reusing `scriptedSubscriber`, `fakeInteractiveBcast`, `fakeArmer`, `waitClosed`,
`lockedWriter` from the turn-stream and emitter test files, plus a new
`fakeScreenHost` (a `turnbridge.SessionHost` that **also** satisfies
`screenSnapshotter`) and `fakeSessionHost` (a `SessionHost` that does **not**).
Six scenarios mirroring the turn-stream wiring tests:

- **`TestInteractiveModalStream_ShownReachesEmitterWithBoundScreen` (AC5 surface)** —
  one scripted `Shown{Permission}` reaches `Handle` paired with the screen text;
  asserts one `modal_shown` push whose `Prompt` is the **trimmed** screen body and
  exactly one `ArmModalTimeout` for the surfaced `modal_id`.
- **`TestInteractiveModalStream_LocalDismissal` (AC5)** — `Shown` then `Hidden{same
  class}` yields exactly one `modal_dismissed{source: local, outcome: dismissed_local}`.
- **`TestInteractiveModalStream_NonModalEventsNoRenderNoPush` (AC2 efficiency +
  no-op)** — idle/thinking/JSONL/stall/MCP-failure events: a spying `screenText`
  asserts it is **never called**, and zero pushes / zero arms result.
- **`TestBoundScreenText_HostSelection` (AC3)** — table: routed conv + screen-carrying
  host → that host's text; no route → bootstrap text; `boundHost` miss → `""`; host
  not a `screenSnapshotter` → `""`.
- **`TestInteractiveModalStream_TeardownUnblocks` (AC4)** — a never-yielding
  subscriber; on ctx cancel the goroutine exits and `<-done` returns within a
  deadline.
- **`TestInteractiveModalStream_NoScreenTextLogLeak` (AC5 content-free)** — a `Shown`
  carrying a secret screen body with `pushErr` set so the emit push-drop DEBUG branch
  fires for every conn (the most log-heavy path); asserts the secret substring never
  appears in captured logs. Mirrors `TestInteractiveTurnStream_NoAppOutputLogLeak`.

The loop's correctness (nonce anti-replay, deny-on-timeout, first-answer-wins) stays
proven by #716/#717/#725/#706 and is **not** re-proven here.

## Out of scope (deferred)

- **ACP permission proxy wiring** — `acpPermissionProxy` (`acp_permission.go`) is a
  *separate* unwired consumer of the same raw modal-event stream; its live wiring is
  the ACP follow-up ([#751](https://github.com/pyrycode/pyrycode/issues/751)
  territory), explicitly out of scope. `acp_permission.go` left untouched.
- **Byte-exact screen/event pairing** — the accepted switch-race (above). A future
  ticket that needs atomic pairing would widen the subscriber to surface the captured
  per-subscription host; deferred until evidence demands it.
- **The frozen emitter** — `interactive_modal_v2.go` was left untouched; a real gap
  in the emitter routes back rather than being patched here (per the ticket).
