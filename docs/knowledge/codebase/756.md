# Ticket #756 — `pyry acp`: serve the `internal/acp` transport over stdio

The **composition root** for epic
[#600](https://github.com/pyrycode/pyrycode/issues/600)'s ACP agent surface.
Registers the `pyry acp` verb, constructs the `internal/acp` JSON-RPC transport
(#755) over the process's real stdio driven by a stderr-only logger, and serves
until the host closes stdin (EOF → exit 0) or a signal cancels the context
(SIGINT/SIGTERM → exit 0). It registers **no** method handlers and drives **no**
claude — later epic-#600 tickets register the `session/*` handlers against the
transport this verb wires up.

Split from #746, sub-issue of #600, blocked by #755 (merged).
Spec: [`docs/specs/architecture/756-acp-subcommand.md`](../../specs/architecture/756-acp-subcommand.md).
Feature doc: [`features/acp-package.md`](../features/acp-package.md#subcommand-pyry-acp-756).
Not security-sensitive — composition-root plumbing at a **local parent→child
stdio** boundary: it registers no handlers, validates no frames (the transport
owns framing/dispatch), and drives no claude. Re-evaluate the label on the later
tickets that register real `session/*` handlers.

## Implementation

Purely additive: one new production file (`cmd/pyry/acp.go`, ~60 LOC), one test
file (`cmd/pyry/acp_test.go`), and a 7-line edit to `cmd/pyry/main.go` (dispatch
`case "acp"` + package-doc verb line + `printHelp` entry). No signatures changed
or removed — **blast radius nil**.

- **`runACP(args []string) error`** — the thin, non-testable shell (touches real
  process globals). Rejects any argument (`len(args) != 0` → error, *before* any
  side effect — mirrors `runStatus`'s guard), builds the signal context
  (`signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)` +
  `defer cancel()`, identical to `runSupervisor`), builds a **plain stderr
  logger**, then delegates to `serveACP(ctx, os.Stdin, os.Stdout, logger)`.
- **`serveACP(ctx, stdin io.Reader, stdout io.Writer, logger)`** — the testable
  core. Takes `io.Reader`/`io.Writer` (not `*os.File`) so tests inject in-memory
  readers with no TTY or real fds. Wires `acp.New(pr, stdout, logger)` (registers
  **no** handlers, AC#2) and blocks on `t.Serve(ctx)`.
- **Plain stderr logger, no ring buffer.** `slog.New(slog.NewTextHandler(os.Stderr, …))`
  — deliberately **not** `runSupervisor`'s `control.SlogTee` + `NewRingBuffer`.
  The ACP host captures this subprocess's stderr and keeps its own diagnostics
  ring; there is no `pyry logs` consumer for `pyry acp`, so the tee/ring would be
  dead weight. AC#5 requires only diagnostics-off-stdout, which the frame stream
  owns by construction (`os.Stdout` is the transport's writer; the logger writes
  stderr).

### The blocked-read closer (AC#4 — the load-bearing decision)

The ticket suggested "close `os.Stdin` on shutdown" to unblock a `Read` parked on
a quiet host. **That is a trap and was rejected.** A `Read` parked in the kernel
on the non-pollable `os.Stdin` fd cannot be interrupted by `Close` — `Close`
itself then blocks on the fd's `fdMutex` until the read returns, which on a quiet
host never happens (the exact `#78` failure — `docs/lessons.md:92`, `:243`).

Instead `serveACP` **bridges real stdin through an in-memory `io.Pipe`**:

- a **closer** goroutine (`<-ctx.Done()` → `pr.CloseWithError(ctx.Err())`)
  synchronously unblocks any blocked `PipeReader.Read` — `io.Pipe` is a channel
  internally, so a blocked reader observes the close immediately. AC#4 is
  satisfied with **zero** syscall/nonblock/poller machinery.
- a **bridge** goroutine (`io.Copy(pw, stdin)` then `pw.Close()`) feeds the pipe
  from real stdin; the host closing stdin surfaces as EOF, closing the pipe and
  letting `Serve` return (AC#3).

`Serve` reads the in-memory `PipeReader`, never `os.Stdin` directly.

### Clean-exit mapping — `ctx.Err() != nil`, not `errors.Is(context.Canceled)`

The clean-exit guard is `ctx.Err() != nil`, **not** the `runSupervisor`
`errors.Is(err, context.Canceled)` precedent. The forced-pipe-close path surfaces
a wrapped `io.ErrClosedPipe`/`os.ErrClosed`, not `context.Canceled`; guarding on
"did *we* deliberately cancel?" absorbs both the cancelled-between-frames case and
the forced-close case as a clean exit-0, while still declining to swallow a
genuine stream break (only reachable with `ctx.Err() == nil`).

| Exit condition | `Serve` returns | `ctx.Err()` | `serveACP` returns | Exit |
|---|---|---|---|---|
| Host closes stdin (EOF) | `nil` | `nil` | `nil` | 0 |
| Signal, cancelled **between** frames | `context.Canceled` | non-nil | `nil` | 0 |
| Signal, cancelled **during** a blocked read | wrapped `os.ErrClosed` | non-nil | `nil` | 0 |
| Over-long line / read error, **not** shutting down | wrapped error | `nil` | `fmt.Errorf("acp: %w", err)` | 1 |

## Concurrency model

Three goroutines during serve: (1) the caller blocked in `acp.Serve` (the
transport's single read/dispatch loop, #755, unchanged); (2) the **bridge**
(`io.Copy(pw, os.Stdin)`); (3) the **closer** (`<-ctx.Done()` →
`pr.CloseWithError`). No shared mutable state beyond the internally-synchronised
`io.Pipe`.

- **Signal path:** signal → ctx cancel → closer fires `pr.CloseWithError` →
  `Serve`'s scan returns the pipe-close error → `serveACP` sees `ctx.Err() != nil`
  → returns nil → exit 0.
- **EOF path:** host closes pipe → `io.Copy` returns → `pw.Close` → `Serve` reads
  EOF → returns nil → exit 0. The closer stays parked on `<-ctx.Done()` until
  `runACP`'s `defer cancel()` fires, then no-ops on the already-closed pipe — so
  it never outlives the call.
- **No join.** `serveACP` must **not** wait for the bridge goroutine: joining
  would force the EOF path to block until a signal, and the bridge is unjoinable
  on the signal path (blocked on `os.Stdin.Read`). The goroutines are
  fire-and-forget, reaped by process exit. This asymmetry is deliberate and
  documented inline.

### The one-shot bridge-goroutine leak (accepted, documented)

On the signal path the `io.Copy(pw, stdin)` goroutine stays blocked on
`os.Stdin.Read` and leaks. This is acceptable **only here**: `pyry acp` is a
one-shot subprocess that exits immediately after `serveACP` returns, so exactly
one goroutine dies with the process. Contrast #78, where the identical leak was
fatal because it recurred *per restart iteration* inside a long-lived supervisor,
piling readers onto the shared `os.Stdin` `fdMutex`. `supervisor.openTTYInput`'s
dup/reopen + O_NONBLOCK + poller-mediated-close machinery exists to defeat that
*accumulation*; it buys nothing for a single terminal shutdown and would add
fd-lifecycle fragility to a composition-root verb. Simplicity-first: accept the
one-shot leak, document why.

## Patterns established

- **Sibling-file verb pattern.** `runACP` follows `runStatus`/`runAgentRun` —
  `run()`'s `switch os.Args[1]` dispatches each verb to a `runX(args []string) error`
  in its own file. The arg-rejection guard fires before any side effect.
- **Bridge an unpollable fd through an in-memory `io.Pipe` to make it
  cancellable.** When a blocking read on a non-pollable fd (`os.Stdin`) must be
  interrupted on shutdown, feeding it through an `io.Pipe` and closing the pipe
  reader is a deterministic, fd-machinery-free alternative to the
  dup/O_NONBLOCK/poller reopen dance — valid *precisely because* the leaked bridge
  goroutine dies with a one-shot process. The seam to swap in if `pyry acp` ever
  becomes long-lived: a pollable reopened stdin behind the same `io.Reader`
  boundary `serveACP` already takes.
- **Guard clean-exit on `ctx.Err()`, not the returned error's identity, when the
  shutdown path can surface more than one error type.** `errors.Is(err, context.Canceled)`
  is insufficient once a forced-close introduces a second shutdown error
  (`os.ErrClosed`); "did we cancel?" absorbs every deliberate-shutdown error shape
  without swallowing genuine failures.
- **Inject `io.Reader`/`io.Writer` into the testable core so shutdown semantics
  are testable without a TTY.** CI runners have no terminal; the
  `serveACP(ctx, io.Reader, io.Writer, *slog.Logger)` signature is what makes
  AC#3/AC#4 deterministically testable — the split between the process-globals
  shell (`runACP`) and the injectable core (`serveACP`) is the reusable shape.

## Testing

`cmd/pyry/acp_test.go`, same-package, stdlib `testing` only, `t.Parallel()`,
`-race`-clean, no TTY:

- `TestServeACP_EOFReturnsNil` / `_BlankLinesThenEOF` — AC#3 (EOF → nil,
  whitespace-only lines skipped, nothing on the frame stream).
- `TestServeACP_BlockedReadUnblocksOnCancel` — **the load-bearing test (AC#4)**:
  an `io.Pipe` reader with nothing written blocks forever; assert `serveACP` has
  not returned; `cancel()`; assert it returns nil within 2s (the #78 regression
  guard). Cleanup closes the write end so the bridge drains and the test leaks
  nothing.
- `TestServeACP_StreamBreakReturnsError` — AC#5: a single over-long line
  (> 16 MiB `maxLineBytes`) with a non-cancelled ctx → wrapped `acp:` error,
  detail on the diagnostics stream, nothing on the frame stream.
- `TestRunACP_RejectsArgs` — AC#1: an argument → error naming it, without blocking
  on stdin (guard fires first). `runACP(nil)` is not unit-tested directly (it
  blocks on real `os.Stdin`; covered transitively by the `serveACP` tests).

## Lessons learned

- **"Close `os.Stdin` on shutdown" is a trap for unblocking a blocked read.** A
  `Read` parked in the kernel on the non-pollable `os.Stdin` fd cannot be
  interrupted by `Close` (the #78 / `lessons.md:243` failure). Bridging real stdin
  through an in-memory `io.Pipe` and calling `pr.CloseWithError` on cancel
  sidesteps the whole fd/poller machinery — the closer is trivially,
  deterministically correct and testable with an injected reader (no TTY).
- **The clean-exit guard must be `ctx.Err() != nil`, not
  `errors.Is(err, context.Canceled)`** (the `runSupervisor` precedent): the
  forced-pipe-close path surfaces a wrapped `os.ErrClosed`, so a
  `context.Canceled` check would misclassify a signal-driven shutdown as an error
  exit.

## Out of scope (deferred)

- **Real `session/*` handlers** — every ACP method is a later epic-#600 ticket's
  registration against the transport this verb wires; this ticket registers none.
- **Outbound-request primitive** (#757) — makes the transport bidirectional;
  independent of this verb.
- **e2e coverage** — a spawn-real-`pyry acp` / close-stdin / SIGINT-a-quiet-one
  exit-code e2e is deferred: it needs a new `acp` invocation mode in
  `internal/e2e/harness.go` (extra surface for an S ticket), and the unit tests
  already pin the load-bearing mechanism deterministically. Fold a
  shutdown-exit-code assertion in when epic #600's later handler tickets add an
  e2e harness for `pyry acp`.
- **Pollable-stdin upgrade** — if `pyry acp` ever becomes long-lived or
  re-entrant, the one-shot bridge-goroutine leak stops being free; swap the
  `io.Pipe` bridge for a pollable reopened stdin (dup + O_NONBLOCK +
  poller-mediated `Close`, per `supervisor.openTTYInput`) behind the same
  `io.Reader` boundary. No wire-contract change. Deferred until observed need.
