# Ticket #1193 — Record the interrupt route's dispatch arm and its neither-method inert case

Split child B of #1190 (child A was #1192). #1192 instrumented the three
interrupt-route arms reachable without changing any function signature; this
ticket closes the remaining two, both of which live behind `interruptRunner`
(`cmd/pyry/main.go`) — the type switch that dispatches to
`streamRunner.Interrupt()` vs `*supervisor.Supervisor.SendEsc()`. Before this
ticket a successful actuation was exactly as silent as a runner exposing
neither method, and nothing else on the route was.

## Implementation

- `interruptRunner` gains a second return value naming the arm it dispatched
  to, and is otherwise byte-identical:
  ```go
  type interruptArm string
  const (
      armInterrupt interruptArm = "interrupt" // streamRunner.Interrupt()
      armSendEsc   interruptArm = "send_esc"  // *supervisor.Supervisor.SendEsc()
      armNone      interruptArm = "none"      // neither method — inert
  )
  func interruptRunner(r sessions.Runner) (interruptArm, error)
  ```
  The constant *values* are operator-facing (logged verbatim as the `arm`
  field) and are part of the record contract, not an internal detail.
- **Direction: return the arm upward, emit in `activeInterrupter.SendEsc`** —
  the only scope holding the conversation id. `interruptRunner` stays pure (no
  logger, no ambient state), so `TestInterruptRunner_Dispatch`'s five
  call-site table gains an arm assertion instead of gaining a logger and a
  conversation id it has no business owning.
- Two new `Info`-level records, continuing #1192's arm numbering (4, 5) and
  `v2.interrupt.*` event family:
  - `v2.interrupt.dispatched` — `conversation_id`, `arm` (logged as
    `string(arm)`, never the named type: `slog` renders a named string type
    through the `Any` path, and relay's `TextHandler` vs `cmd/pyry`'s
    `JSONHandler` don't agree on how that renders). Emitted **unconditionally
    once an arm actuated, including when that arm's call returned an error** —
    it records *which arm was dispatched to*, not that the child quiesced
    (hence `dispatched`, not `actuated`). The failure itself is already
    reported by `v2.interrupt.keystroke_err` (`Warn`, carries the error but not
    the arm), so the pair together names *which* actuation failed. No `err`
    field on `dispatched` — duplicating the error under a second correlation
    key was rejected as widening the log surface for no diagnostic gain.
  - `v2.interrupt.no_actuator` — `conversation_id` only. Completes the
    family's `no_<thing>` progression: no active conv → no bound runner →
    no actuator.
  - Both at `Info` (not `Debug`): the daemon defaults to `slog.LevelInfo`,
    same load-bearing reasoning as #1192 — an intermittent live failure may
    not survive to a `-pyry-verbose` re-run.
- **Closes the coverage invariant.** Every path *through* the route now
  emits, so on a wired daemon an empty `v2.interrupt.*` log means the frame
  never reached the handler — no separate "frame arrived" record needed. Two
  doc comments carrying an explicit interim caveat saying the invariant did
  **not** yet hold (`activeInterrupter.SendEsc`, `cmd/pyry/main.go:1330-1334`;
  `handleInterrupt`, `internal/relay/v2session_modal.go:466-468`) were flipped
  to state the invariant instead. The `handleInterrupt` flip adds the level
  caveat: the nil-`Interrupter` arm still records at `Debug`, invisible at the
  daemon's default `LevelInfo` (raised only by `-pyry-verbose`) — hence
  "wired daemon," not just "daemon." Production always wires the interrupter,
  so the qualifier is precise rather than weaselly.
- No control-flow change: every arm actuates exactly what it actuated before
  and returns exactly what it returned before. `armNone` still pairs with a
  nil error; the `Interrupt()`-before-`SendEsc()` match order and the inert
  default ("no actuation beats wrong actuation") are untouched and still
  pinned by `TestInterruptRunner_Dispatch`. `resolveBoundRunner` and its
  `conv.CurrentSessionID == ""` guard (#678 cross-conversation isolation) are
  untouched.
- Test changes are confined to `cmd/pyry/interrupt_routing_test.go` — no
  relay-side test changes, since both new records are emitted in `cmd/pyry`
  and `internal/relay`'s fake `Interrupter` never reaches `interruptRunner`.
  `TestActiveInterrupter`'s literal at (then-)`:251` — "a live runner's
  interrupt error propagates," the one literal of four that omitted `log` —
  gained `log: auditLogger()`'s logger, because it now resolves successfully
  and emits; left unwired, the record would have escaped to `slog.Default()`
  unasserted.

## Patterns established

- **A pure dispatcher should return an enumerated outcome rather than take a
  logger, when only the caller has the context (here, conversation id) to
  make the record meaningful.** Widening `interruptRunner`'s five call sites
  with a logger + conv id it doesn't use would have made an observability
  concern leak into a function whose only job is picking a method.
- **An observability-only return value needs an explicit "nothing branches on
  this" constraint stated next to its type**, when the value's only other
  plausible use is a fallback that would reintroduce a fixed isolation bug.
  Here: `armNone` must never trigger a fallback to the bootstrap supervisor —
  that's the exact #678 cross-conversation break `resolveBoundRunner`'s guard
  exists to prevent. Stated as a MUST NOT in the `interruptRunner` doc
  comment, not just in the architecture spec, so it survives independent of
  this ticket's closure.
- **A record documenting "which arm dispatched" should fire on the arm's
  error path too, not just its success path**, when a sibling record already
  owns the error and needs the arm identity to be useful. Suppressing the
  record on error would have deleted the one place an operator can tell which
  actuation failed after `keystroke_err` reports that something did.
- **Log a converted plain value, never a named string type, across a `slog`
  call that can reach more than one handler.** `slog` routes named string
  types through the `Any` path, and `TextHandler` vs `JSONHandler` render
  that path differently — `string(arm)` guarantees `KindString` in both.

## Lessons learned

(from the PR body)

- Same shape as #1192's per-line hygiene lesson, reapplied: a closed
  key-set assertion (`{time, level, msg, event, arm, conversation_id}` for
  `dispatched`) catches a future field addition that a forbidden-substring
  list would silently miss.
- The direction choice (return arm upward vs push logger down) determines
  which test file changes: returning the arm upward kept all logger/conv-id
  plumbing out of `TestInterruptRunner_Dispatch` and put every record
  assertion in `TestActiveInterrupter`, where the conversation id already
  lives.
