# Ticket #1097 — `internal/streamsup`: `*streamsup.Runner` satisfies `sessions.Runner`

Makes a streamsup-backed runner drivable through the existing [`sessions.Runner`](../features/sessions-package.md)
seam (`internal/sessions/runner.go`, introduced by [#1077](1077.md)) so the session pool can run a
stream-json conversation through the same lifecycle it uses for the PTY supervisor, and so #1081
can compile a `stream-json` `RunnerFactory` arm at all. Purely additive: nothing on the `sessions` side
changes, and `send_message`/`set_session_settings` work unchanged once a `streamRunner` exists, because
both already dispatch through the interface rather than the concrete type.

## Implementation

- **New `internal/streamsup/state.go`.** `Phase` (`starting`/`running`/`backoff`/`stopped`) and `State{Phase,
  ChildPID, StartedAt, RestartCount, LastUptime, NextBackoff}` mirror `supervisor.Phase`/`supervisor.State`
  field-for-field and string-for-string. `Runner.State()` / `Runner.updateState(fn)` are lock-guarded via a
  new leaf `stateMu` (kept separate from the existing `mu` guarding `stdin` — different concern, different
  access pattern: control-plane reader vs. `Run`-goroutine writer). The `Run` loop and `spawnAndWait` are
  instrumented to keep all six fields faithful (not just `Phase`), because `cmd/pyry`'s `buildStatus`
  reads all six.
- **Live-restart seam ported into `internal/streamsup/runner.go`.** The package doc previously stated
  streamsup's `Run` loop has "no live-restart seam like `supervisor.Restart`" — this ticket adds one,
  wholesale-ported from `internal/supervisor/supervisor.go`: a third leaf mutex `restartMu` guards `args`
  (live spawn base argv) and `iterCancel` (current iteration's `context.CancelFunc`); a buffered(1)
  `restartCh` carries a non-blocking deliberate-restart hint. `Restart(args []string)` swaps `args`,
  sends the hint, and cancels `iterCancel` if a child is live. The `Run` loop now derives `iterCtx :=
  context.WithCancel(ctx)` per iteration and passes **`iterCtx`** (not the parent `ctx`) to `spawnAndWait`
  — so `cmd.Cancel`'s reap+SIGTERM fires on either a parent-ctx cancel (shutdown) or an `iterCtx`-only
  cancel (restart). The existing `if ctx.Err() != nil` check after `spawnAndWait` uses the **parent** ctx,
  so it stays the shutdown-vs-restart discriminator unchanged: an `iterCtx`-only cancel leaves it nil and
  falls through to relaunch. `drainRestart()` after the `started`/`firstRun` update skips backoff on a
  deliberate restart (not a crash); a `case <-r.restartCh:` in the backoff `select` relaunches immediately
  if a restart arrives mid-backoff. Because `firstRun` is already `false` after the first spawn, every
  restart resumes via `--resume <sessionID>` rather than forking.
- **`WriteUserTurn(ctx, conversationID, payload) error`** — a one-line wrap of the already-reviewed
  `WriteTurn` free function (#1088/#1093): no new envelope construction, inherits `WriteTurn`'s exact
  contract (`ErrNoLiveChild` with no live child before the gate claim, `turncommit.ErrDropped` with zero
  bytes on a gate deny). `conversationID` is unused this slice — accepted only for interface conformance
  and the future outbound-cursor wiring (T4/T7).
- **`WaitForPTY(ctx) error`** — bare `return nil`. The stream path has no PTY to await; the no-live-child
  window is already handled per-turn by `WriteTurn`'s retryable `ErrNoLiveChild`.
- **New `cmd/pyry/streamsup_runner.go`.** `sessions.Runner.State()` returns `supervisor.State`, but
  `internal/streamsup`'s package doc forbids importing `internal/supervisor` — Go has no covariant return
  on interface satisfaction, so `*streamsup.Runner` cannot declare that signature directly. `streamRunner{
  r *streamsup.Runner }` is a thin wrap-and-forward adapter (same shape as `poolResolver` in
  `cmd/pyry/main.go`): `State()` calls `mapStreamState(a.r.State())` (a plain field-by-field copy, `Phase`
  via a string cast since the values are identical across packages); `WriteUserTurn`/`WaitForPTY`/`Run`/
  `Restart` forward unchanged. `var _ sessions.Runner = streamRunner{}` is the AC1 compile-time proof — the
  build fails if a method is missing or mis-typed. The factory arm that *constructs* a `streamRunner` from
  a `supervisor.Config` is #1081's scope; this ticket delivers only the adapter and the assertion.
- Test files: `internal/streamsup/interface_test.go` (new, 346 lines — AC2–AC5 scenarios per the spec's
  Testing section) and `cmd/pyry/streamsup_runner_test.go` (new — `TestMapStreamState` field/`Phase`
  round-trip); `internal/streamsup/helper_test.go` grew a `record_block` fake-child mode (records argv to
  `GO_STREAMSUP_HELPER_ARGV_FILE` like `crash`, but blocks until SIGTERM instead of self-exiting) so the
  live-restart test can prove the first child was killed by `Restart`, not a self-exit.

## Patterns established

- **Covariant-return interface snag → composition-root adapter, not a relaxed interface or a relaxed
  import boundary.** When a package's dependency-direction rule forbids importing the type an interface
  method needs to return, give the concrete type a same-shape *native* method instead, and let a thin
  adapter in the composition root (which already imports both sides) map the covariant return and forward
  everything else. Same shape as `poolResolver`; see `docs/lessons.md` § "Interface adapters for covariant
  returns".
- **Porting a lifecycle seam wholesale, not reinventing it.** The live-restart seam
  (`args`/`iterCancel`/`restartCh`/`liveArgs`/`setIterCancel`/`drainRestart`) is a direct structural port
  of `supervisor.Restart`'s shape — three-leaf-mutex discipline (never nested), buffered(1) channel
  coalescing, and the parent-ctx-vs-iterCtx shutdown/restart discriminator all carry over unchanged. When
  a sibling package already solved the exact concurrency problem, port the shape rather than design a new
  one.

## Lessons learned

- The covariant adapter's methods and `mapStreamState` stay staticcheck-clean (no U1000) despite having no
  factory caller yet: the `var _ sessions.Runner = streamRunner{}` interface conversion marks every
  interface-satisfying method as used. Confirmed with `staticcheck`; if U1000 ever fires here, the fix is
  #1081's factory wiring, not a suppression.
- Passing `iterCtx` (not the parent ctx) to `spawnAndWait` means `cmd.Cancel`'s reap+SIGTERM fires on a
  deliberate `Restart` as well as on shutdown — so a live-restart test needs the real reaper (kept
  parallel) and runs measurably slower (~2s) than a crash-path test, where the child self-exits and
  `cmd.Cancel` never fires. Don't be surprised by that asymmetry when tuning test timeouts in this package.

## Code review

PASS (PR #1102), no blocking findings. Two NITs, no action taken:
- `WriteUserTurn`'s `conversationID` and `WaitForPTY`'s `ctx` are unused — correct and intentional
  (interface-conformance signatures, documented in both the doc comments and the spec's Open Questions).
- On the deliberate-restart `continue` path, `State()` briefly reports `Phase=Running` with the
  just-killed child's PID until the next spawn's `updateState(Running)` fires — a faithful copy of
  `supervisor.Run`'s own behavior (it also skips a state reset on its `drainRestart` continue); the window
  is microseconds and no consumer polls that tightly.

Verified: faithful line-for-line port of the supervisor pattern (mutex discipline, restart coalescing,
shutdown/restart discriminator); correct divergence (`if started { firstRun = false }` vs. supervisor's
unconditional flip — the previously-reviewed #1087 fix for streamsup's `--session-id`/`--resume` branch);
fully additive blast radius (`streamRunner` reached only via the compile assertion until #1081); full AC
coverage; real-claude e2e ran (not skipped).
