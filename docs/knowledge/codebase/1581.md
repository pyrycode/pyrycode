# Ticket #1581 — sessions: deliver a model/effort-only settings change in-band instead of restarting the child

`Pool.UpdateSettings` live-applied every settings change the same way: recompose argv, kill the child, let the
supervisor relaunch it (`sup.Restart(newArgs)`, #842). On a session that has never run a turn, that respawn
re-execs with `--resume`, claude answers `No conversation found with session ID` and exits 1, and the daemon
crash-loops on a widening backoff — observed 2026-08-18. Measured 2026-08-19 against claude 2.1.220: claude
accepts `/model <name>` and `/effort <level>` as ordinary user turns on the stream the daemon already holds
open, and applies them to the running session with no respawn. This ticket partitions the live-apply on that
fact — a model/effort-only change goes in-band; everything else keeps the restart — which avoids the crash-loop
rather than fixing it.

## Implementation

- **`internal/sessions/pool.go`** — two new unexported symbols plus a branch at the tail of `UpdateSettings`
  (after `p.mu.Unlock()`, same position `sup.Restart` used to occupy alone):
  - `inBandDeliverable(update SettingsUpdate) bool` — total predicate. True iff `update.YOLO == nil` **and**
    at least one of `Model`/`Effort` is present **and** neither present field is the empty string. A present
    YOLO — including one equal to the stored value — always takes the restart; a clear-to-`""` (model or
    effort) always takes the restart, since claude has no in-band form for "revert to default."
  - `(*Pool).deliverSettingsInBand(id SessionID, sup Runner, update SettingsUpdate)` — writes `/model <v>` then
    `/effort <v>` (model first, fixed order) as two **separate** `sup.WriteUserTurn(context.Background(), "",
    []byte(cmd))` calls, one per *present* field (not per *changed* field — a redundant `/model` on an
    unchanged-but-present value is accepted cost, not a bug). Every write error is logged at `Info`
    (`"sessions: in-band settings command not delivered"`, fields `session`/a fixed `"model"`or`"effort"`
    literal/`err` — never the value, the payload, or the conversation id) and swallowed; `UpdateSettings`
    still returns `nil`. `context.Background()` is correct, not a shortcut: `WriteTurn` only consults ctx for
    the turncommit gate, and its own doc names this exact call shape as the nil-gate case.
  - The tail: `if inBandDeliverable(update) { sup.SetSpawnArgs(newArgs); p.deliverSettingsInBand(id, sup,
    update); return nil }` then the unchanged `sup.Restart(newArgs); return nil`. **Both branches install
    `newArgs`; only one kills.** The in-band branch uses #1580's `SetSpawnArgs` (the swap-only half of
    `Restart`) rather than skipping the install — skipping it would let the operator's change silently revert
    on the next crash-respawn or evict→`Activate`.
- **`internal/sessions/session.go`, `runner.go`** — doc-only; no signature or behaviour change. `Runner`
  already carried `SetSpawnArgs` from #1580; this ticket is its first caller.
- **`internal/relay/v2session_settings.go`, `cmd/pyry/relay.go`** — comment corrections only (see Documentation
  below); no production logic changed in `internal/relay`.
- **Test harness (`internal/sessions/runner_test.go`)** — `lifecycleRunner` gained a `writes [][]byte` field
  (guarded by the existing `r.mu`) and three deep-copying accessors (`restartArgs()`, `spawnArgSets()`,
  `userTurns()`); `WriteUserTurn` now appends a clone of the payload instead of discarding it. This closes the
  gap the architecture doc calls "trap 2" — before this ticket an in-band delivery was invisible to any test.
- **`internal/sessions/pool_update_settings_inband_test.go`** (new) — `TestInBandDeliverable` (table test over
  the partition), `TestPool_UpdateSettings_InBand_ModelAndEffort` (live child, AC #1 + #4's live-child half),
  `TestPool_UpdateSettings_InBand_EvictedNoLiveChild` (AC #4's evicted half — `_Evicted_SwapOnly` in the
  sibling file carries YOLO and proves nothing about this path), `TestPool_UpdateSettings_ClearModel_KeepsRestart`
  (AC #2's uncovered corner: none of the six untouched tests exercises clear-to-`""`).
- **`internal/sessions/pool_update_settings_restart_test.go`** — six of seven tests untouched (AC #2). The
  seventh, `TestPool_UpdateSettings_YOLOAbsent_NoBypassOnRestart`, was a model-only update asserting a
  respawn — the new rule necessarily changes it. Renamed to `..._YOLOAbsent_NoBypassInBand` (keeping
  `OnRestart` in a test that now asserts *no* restart would be a comment that lies) and rewritten to assert no
  respawn, exactly one `/model opus` turn, and a bypass-free installed argv — the fail-safe assertion is
  preserved, checked against the argv the next spawn will use rather than the argv a respawn did use.

All new "no respawn" and "delivery happened" assertions read the double's `Restart`/`WriteUserTurn` records
directly — never `doneAppears`, which the spec measured as vacuous under this harness (`recordingRunnerFactory`
ignores `cfg.ClaudeBin` and always returns a `lifecycleRunner`, whose `Run` execs `/bin/sleep`, so the sentinel
`doneAppears` polls for is never written).

## Patterns established

- **A restart-replacing branch must still perform the restart's non-kill half, or the change silently reverts
  on the next crash.** `Restart(args)` was doing double duty (install + kill); the fix is not "stop calling
  `Restart`" but "call the half you still need." #1580 shipped `SetSpawnArgs` for exactly this shape — the
  general lesson for any future partition of a fused install-and-restart method is: swap first, always, then
  decide whether to kill.
- **Key a delivery-mechanism partition on wire *presence*, not on merged-vs-previous diffing.** The partition
  reads `update.Model != nil` / `update.YOLO != nil`, never "did the value change" — because the wire's own
  `omitempty` pointer contract already guarantees a client changing one field sends only that field. This
  keeps the predicate a pure, total, table-testable function of the update struct, with no dependency on prior
  state.
- **Swap-before-write, so a failed delivery loses nothing.** The argv install happens before the fire-and-forget
  `WriteUserTurn` calls. If the write fails, the settings are already persisted and the next spawn already
  carries them — the same "install is the durable half" pattern #1580 established for `Restart` itself.

## Lessons learned

From the PR body:

- `doneAppears` in `pool_update_settings_restart_test.go` cannot observe a respawn under this harness — see
  Implementation above. New tests read the double's `Restart` record instead; this is now documented on the
  helper itself, not just in this file, so it doesn't have to be rediscovered.
- A test double's records need read accessors under the double's own mutex, not exported fields directly —
  the lifecycle goroutine writes while the test goroutine reads, and deep-copying accessors are what keep the
  new assertions `-race`-clean.
- `SetSpawnArgs` on the double deliberately does not route through `recordArgv` (the channel `waitArgv`
  reads) — #1580 left that as a signpost for its first caller. An assertion written against `waitArgv` would
  not see the swap on the in-band path, and worse would return the *stale construction* argv immediately
  rather than timing out, since `clearRecording` removes only files. The install has to be asserted off the
  double's own `setArgs`/`spawnArgSets()` record, normalised through `stripMCPSettings`.
- A mechanism change invalidates "nothing calls X yet" doc comments as surely as it invalidates behavioural
  ones. Sweeping the ticket's specified "next spawn" claim caught the six named sites; the sweep also
  surfaced two more comments (`sessions.Runner`'s `SetSpawnArgs` doc, `streamsup-package.md`) claiming the
  installer had no caller — this ticket is that caller, so both were corrected alongside the six.

From code review (one round, PASS with two SHOULD FIX, both comment-accuracy, neither behavioural):

- A "this is already covered by test X and Y" credit in a comment needs to be checked, not assumed, especially
  when it justifies deleting an assertion. The rewritten test's comment claimed two sibling tests asserted a
  pinned session id across a restart; neither actually does — one checks the id only *before* the restart, the
  other reads a double field that is fed solely at construction and can't observe a post-restart id at all
  (the same blindness class as `doneAppears`). The deletion itself was fine; the stated reason for it wasn't.
- A measurement cited to justify a structural claim needs re-verifying against the tree it's cited in, not
  just the tree it was taken from. A `doneAppears`-blindness demonstration ("delete the no-op early return, X
  stays green") was measured pre-#1581 and silently stopped isolating what it was cited for once the tree
  gained a second reason (`inBandDeliverable` routing) for the same test to stay green under that mutant. The
  structural argument beside it (the harness ignores `cfg.ClaudeBin`) remained airtight on its own.

## Testing

`go test -race ./internal/sessions/... ./internal/relay/... ./cmd/pyry/...`, `go vet ./...`, `make staticcheck`,
`make cite-guard` all pass. Five `-overlay` mutants (always-restart, install-dropped, YOLO-in-band,
empty-model-in-band, effort-before-model) each go red on a distinct test, no worktree writes. No e2e — this
ticket is proven hermetically by design; the live-claude proof that the running child actually changed is
**#1582**, blocked by this one.

Code review: one round, PASS. Two SHOULD FIX (both addressed above under Lessons learned, neither reaching the
three-finding threshold), one NIT on a triplicated `argvRecorderTemplate` prefix-strip (left as a follow-up,
not gating), one NIT on orphaned comment-wrap lines from mid-paragraph doc edits (cosmetic, `gofmt`-clean).
Security review: PASS, embedded in the architecture spec — the shape-checked `validModel`/`validEffort` values
now reach a command interpreter on claude's stdin instead of only an `exec` argv; the charset `validModel`
already enforces (`[A-Za-z0-9._-]`, no space/newline/control-byte/`/`/leading `-`) rules out a second argument,
a nested slash-command, or a forged stream-json line, and `marshalTurnEnvelope` JSON-escapes besides. The
bypass fail-safe is structurally preserved: `inBandDeliverable` requires `YOLO == nil`, so no update carrying a
present YOLO can reach the non-restarting branch.
