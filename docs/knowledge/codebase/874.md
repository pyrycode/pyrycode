# Ticket #874 — v2 push drain: hold control envelopes unsealed while the relay transport is down

`security-sensitive` · layer 1 of the reconnect-reliability design (umbrella #829; immediate flush-on-reconnect is the follow-up #875; new-connection catch-up is the separate reconcile-on-connect mechanism, also under #829).

ADR 025 § Backpressure promises control messages (`modal_shown`, `queue_state`, …) are never dropped. That promise held on the *enqueue* side of the v2 push queue (`queuedEnv` holds every envelope unsealed, since the Noise send nonce is strictly sequential) but broke on the *drain* side: during a daemon↔relay reconnect blip, `drainOnce` popped the queue head and `forwardEnvelope` sealed it (`s.send.Encrypt`, nonce++) *before* `send` learned the transport was down — the transport error surfaces only after the seal, swallowed at debug as `v2 outbound drop`. The popped envelope was lost, **and** the seal had already burned a nonce the surviving phone never consumed; its next delivered frame MAC-failed and the session died at WS 4421 — poisoning a still-authenticated connection over a mere network blip.

## Implementation

- **`V2SessionConfig.Connected func() bool`** (`internal/relay/v2session.go`) — additive, nil-optional seam, same idiom as `Interrupter`/`QueueRemover`/etc. A level poll of the relay transport leg's live-conn state.
- **`transportDown()`** — private helper: `m.cfg.Connected != nil && !m.cfg.Connected()`. nil `Connected` ⇒ always false ⇒ byte-identical to pre-#874 behaviour (every existing test, foreground/unwired path).
- **`drainOnce`** — `transportDown()` is checked first, off-lock, before `pushMu` and before the replay-gate snapshot. A `true` result returns immediately: nothing popped, nothing sealed, nothing re-signalled. The head stays exactly where `enqueue` left it. Everything downstream of the guard (replay snapshot, `pushMu`-guarded pop, `forwardEnvelope`, the `more` re-signal) is unchanged.
- **Hold is structural, not a runtime error tag.** The probe gates the *pop*, upstream of `forwardEnvelope`'s session-level failure returns (`ErrConnNotFound`, `ErrSessionNotOpen`, marshal/seal failure), which still drop — reached only once the probe has passed. Transport-down and session-level-failure can't conflate by construction.
- **Lazy re-flush.** A held head does not re-signal `drainCh` itself; the next `Push` on any conn (existing behaviour) re-enters `drainOnce`, and if the transport has recovered the held head drains in FIFO order. Immediate flush-on-reconnect (not waiting for a `Push`) is out of scope — #875.
- **`transport.Client.IsConnected() bool`** (`internal/transport/wssclient.go`) — new synchronous level poll, distinct from the existing edge-triggered `Connected() <-chan struct{}`. `false` iff `closeCh` is closed or `c.conn == nil`; agrees with `Send`'s own live-conn predicate. `Close` doesn't nil `c.conn`, so gating on `closeCh` too is what makes a closed client read down.
- **`relay.Connection.Connected() bool`** (`internal/relay/connection.go`) — one-line passthrough to `c.client.IsConnected()`.
- **`cmd/pyry/relay.go`** — `startRelayV2` wires `Connected: conn.Connected` beside the existing `Outbound: conn.Send` in the `V2SessionConfig` literal.

Files touched: `cmd/pyry/relay.go` (+1), `internal/relay/connection.go` (+9), `internal/relay/v2session.go` (+42), `internal/relay/v2session_test.go` (+200), `internal/transport/wssclient.go` (+23), `internal/transport/wssclient_test.go` (+62). No wire change, no new close code, no new lock, no new goroutine.

## Patterns established

- **Pre-seal probe gates the pop, not the seal.** When a seal burns a scarce, strictly-sequential resource (a Noise nonce), the guard against "seal a frame that can't be delivered" has to sit upstream of the pop that commits to sealing — reacting to the transport error *after* the send is structurally too late, the resource is already spent. This is the general shape for any future seal-while-down fix (see the deferred `drainReplayOnce`/`emitRekeyRequest`/dispatch-reply extension, noted in the spec's Open Questions and the feature doc's Out-of-scope list).
- **Level poll vs. edge-triggered signal, same underlying state.** `transport.Client` already had `Connected() <-chan struct{}` (edge-triggered, single-observer, for "wake up and re-run the handshake"). The drain needed "is it up *right now*" at an arbitrary call site — a different shape over the same `c.conn`/`closeCh` state, not a reuse of the channel. Added as a sibling method (`IsConnected`) rather than repurposing the channel API.
- **nil-optional seam as the byte-identical-by-default contract.** Consistent with every other optional `V2SessionConfig` field (`Interrupter`, `QueueRemover`, `SnapshotSettings`, …): the new capability is additive, and every existing construction site (including every existing test) keeps its prior behaviour with zero changes.

## Security review

Spec carried `security-sensitive` (nonce/AEAD sequencing integrity is the surface) and passed a full adversarial review before implementation — see `docs/specs/architecture/874-push-drain-hold-unsealed-while-transport-down.md` § Security review. Verdict: **PASS, net-positive** — the change *removes* a network-blip-triggered session-poisoning nonce burn, introduces no new attacker-influenceable input (the `Connected` bool originates from the daemon's own transport client, never phone-controlled), gates timing only (never authorization — `V2StateOpen` and per-conn addressing stay in `forwardEnvelope`, downstream of the probe), and fails safe in every degenerate case (nil `Connected` ⇒ never holds; a closed client's `IsConnected` reads false ⇒ holds, harmless during teardown).

**Residual, documented, not defended further:** a single-frame TOCTOU at the up→down transition instant (probe reads up, conn drops before the seal/send) still burns one nonce — exposure shrunk from *every frame across the whole down window* (pre-#874) to *at most one frame at the transition* (post-#874). Closing this fully needs a rekey/resync backstop; deferred absent an observed transition-instant burn in practice.
