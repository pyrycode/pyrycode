# Ticket #1430 — Name the runner-path sweep after the per-row declaration it keys on

The trailer probe family described `trailGate`'s runner-path reading **by arm** in four places, but
the tree stopped keying on the arm at #1420 — it keys on a per-row `pathVaries` declaration on
`trailGateCase`. A reader trusting the old name,
`TestTrailGateIgnoresTheRunnerPathExceptAtTheAbsenceArm`, built the model that an absence-shaped row
is exempt automatically; the shipped contract is that such a row goes **red** until it declares. This
ticket renames the sweep to `TestTrailGateReadsTheRunnerPathOnlyWhereARowDeclaresIt` — 54 characters,
byte-for-byte the same length as the name it replaces, so all 12 Go occurrences are in-place
substitutions — and repairs the prose that rendered the same wrong model four (really seven) ways.
Comment-only, one `t.Errorf` message string, one evergreen-doc block. Zero production code (all three
touched Go files are `_test.go`), no assertion, no conditional, no comparison changed. PR
[#1431](https://github.com/pyrycode/pyrycode/pull/1431). Split from #1426 ← #1369.

## Implementation

- **The rename is length-neutral by construction, not by luck.** The replacement name was chosen and
  verified collision-free *because* it is exactly 54 characters — the architect's spec treats "≤ 54
  chars" as the hard constraint on any alternative, since the 12 sites sit on lines already 69–83
  characters in files that wrap around 80: a longer name invites a re-wrap, and a re-wrap is the one
  edit that silently breaks line-count neutrality. `gofmt` does not rewrap comments, so nothing would
  have caught it.
- **Seven prose sites, not four.** The ticket named four defect renderings (the sweep's own doc, the
  `pathVaries` field doc, a stale `trail_ptyrunner_composition_test.go` failure message, and the
  evergreen doc). The architecture spec found three more Go comments that "re-point the identifier"
  alone would have left self-contradicting under the new name: `trailer_admissibility_test.go:229`
  ("Every other arm ignores the field, and `<N>` is what makes that narrower claim a proof"), `:359`
  ("requires a BYTE-IDENTICAL Detail … on every row but the absence one"), and the renamed test's own
  opening doc at `:1483` ("EVERY ARM EXCEPT THE ABSENCE ONE ignores it"). All three are now
  declaration-keyed: an undeclared row's decision (value, certified reason, Detail) is invariant across
  the five `tdnRunnerFromArgv` readings; the declaring row's variance is proved positively by the
  companion sub-test rather than left uncovered.
- **`docs/knowledge/features/e2e-realclaude.md:796-801`** kept the true, arm-level fact ("since #1420
  exactly one [arm] does [read it] — the absence arm") and the verbatim `9 rows × 5 readings` counts,
  but dropped "the narrower claim is **proved, not stated**, by `<old name>`" — that sentence attributed
  an arm-level proof to a sweep that never inspects an arm. What the sweep proves is stated as the
  row-scoped, declaration-keyed property instead.
- **The retracted failure message.** `trail_ptyrunner_composition_test.go:198-202`'s `t.Errorf` argued
  "no arm reads the path today" — stale since #1420's absence arm started reading it, and contradicted
  by the same file's own header 165 lines above. Replaced with the reason that still holds
  (`:53-60`): the sweep is over the Detail *string*, never the marshalled record, because
  `trailGateResult` carries the reading in its own `RunnerPath` field by design and clause B requires it
  to arrive intact. The `if strings.Contains(gate.Detail, reading)` condition and the sibling message at
  `:205-208` are untouched.
- **Per-hunk neutrality, not per-file.** The spec's stated risk — "+2 lines at the top and −2 at the
  bottom nets to zero while displacing every line between them" — is why the gate is a `git diff -U0`
  awk script asserting every individual hunk adds exactly as many lines as it removes, not a `wc -l`
  diff. Validated in both directions before use (green against #1414's known-neutral diff, red against a
  known non-neutral one) before being trusted on this diff. Result: 15 hunks, 0 breaches. This protects
  109 line-anchored cites into the three files plus 9 invisible bare `(:NNN)` back-references that
  inherit their filename from the line above — a plain filename grep cannot find those, only neutrality
  does. One of the nine, `trail_ptyrunner_composition_test.go:56`'s bare `(:1585-1590)`, was confirmed
  to still resolve to clause B (`got.RunnerPath != reading` + its `t.Fatalf`) after the edit.
- Test evidence: `go test -count=1 -v -tags e2e_realclaude -run '^TestTrail' ./internal/e2e/realclaude/`
  → 149 passed / 0 failed / 0 skipped, matching the pre-change baseline exactly, offline, no
  credentials. `make check` does not compile these `//go:build e2e_realclaude` files and was not cited
  as evidence.

## Lessons learned

From the PR body's own "Lessons learned" section:

- **A per-hunk neutrality gate catches what a per-file count cannot, and a count-word audit needs a
  third column.** Alongside the `git diff -U0` per-hunk gate, diffing the *multiset* of numerals and
  count words between removed and added lines caught a silent regression a line-count check would have
  missed: an early pass at the sweep's opening doc dropped its `#1420` attribution while staying
  perfectly line-neutral. Three anaphoric "one"s (`the absence one`, `that one`, `THE ABSENCE ONE`)
  legitimately disappear as the arm-keyed phrasing being removed — the audit is what turns that from an
  assumption into a checked decision, by forcing every numeral/count-word delta to be explained.

From code review (PASS, three NITs, all left open — no code change on this branch):

- `trailer_admissibility_test.go:1486`'s rewritten opening lists "certified reason" among the fields
  that "may move with the reading only where that row declares `pathVaries`". True as an upper bound,
  but the certified-reason comparison actually runs unconditionally, including on the declaring row —
  only the `Detail` byte comparison is what `pathVaries` skips. Site D (`:772-773`) states this
  correctly with the narrower two-field list ("its VALUE and its DETAIL"); the reviewer noted the same
  list would make the opening congruent with it, at no length cost.
- `:228`'s "which is an inference from today's row set" reads as if the arm-level fact itself (not just
  the sweep's *support* for it) were an inference — it isn't; `trailGate`'s source states it directly at
  `:344-356`. The colon-clause that follows supplies the correct intent, so no reader is actually
  misled; the "which" just points one clause further left than it means to.
- `trail_ptyrunner_composition_test.go:200`'s new failure text argues from "clause B" without naming the
  test that owns it. Recoverable — the file header names it fully 165 lines above at `:53-60` — but a
  failure message is read at the exact moment its header is *not* being read, unlike the outgoing
  self-contained message.

Neither the developer's design nor the reviewer treated these as blocking: all three are prose-register
issues inside an XS, comment-only diff, and none changes what the sweep enforces. See
[[po-1430-a-repoint-ac-cannot-fix-an-asserting-cite]] (why "re-point the identifier" alone was
insufficient for the three asserting cites) and
[[po-1430-per-file-line-parity-permits-displacement]] (why the neutrality gate had to be per-hunk).
