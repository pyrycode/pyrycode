# Ticket #1004 — e2e: `new_session` over the v2 wire (rotation observable on disk)

Fake-daemon e2e for the `new_session` v2 control verb (#831), split from the
oversized four-verb #962 batch (the 2026-07-15 review gap; siblings `interrupt`
(#794), `modal_cancel` (#1003), `dequeue_message` already had e2e). Test-only —
no production change — new file `internal/e2e/relay_v2_new_session_test.go`
(`//go:build e2e`), plus a new fakeclaude mode it depends on.

## Implementation

Confirms live, over one spawned daemon, the path the unit tier already proves
deterministically: phone `new_session` (no payload) → Noise decrypt →
`dispatchAppFrame` intercept → `handleNewSession` (`internal/relay/v2session.go:2621`,
interactive-gated, fire-and-forget, no reply/no broadcast) →
`SessionStarter.StartNewSession()` (already wired in production —
`cmd/pyry/relay.go:488` sets `SessionStarter: w.sup`) → `ClearInputLine` (Ctrl-U) +
`TypePrompt("/clear")` + `\r` into the supervised child → `/clear` rotates claude's
session UUID → pyry's rotation watcher follows the most-recently-modified JSONL →
registry bootstrap id updates on disk. The only observable is that on-disk id
change — there is no reply and no broadcast for this verb.

**`TestRelayV2_NewSessionRotatesOnDisk`** (AC-1 + AC-2): bring-up mirrors the
`interrupt` e2e template (pair → pre-create `<initialUUID>.jsonl` → `StartRotationWithRelay`
→ `driveHandshakeToOpenDaemonInteractive`), minus the turn machinery. Ordered
assertions: baseline id == `initialUUID` (non-vacuity precondition) → bounded
**re-send loop** (send `new_session`, poll registry, repeat every ~250ms up to
~10s) until the id rotates away from `initialUUID` → assert the new id matches
`uuidStemPattern` and `LastActiveAt` advanced → direct stdin-log oracle
(belt-and-suspenders, different fabric: fakeclaude's own byte record that
`/clear` was routed, independent of the daemon's registry write).

**`TestRelayV2_NewSessionNonInteractiveInert`** (AC-3): same bring-up but via
`driveHandshakeToOpenDaemon` (non-interactive). Asserts the registry id stays at
`initialUUID` and the stdin log never gains `/clear` bytes over a bounded ~1.5–2s
window. Non-vacuity comes from the sibling test proving the *same* harness+mode
*does* rotate for an interactive conn — a broken interactive gate would surface
within the window via either oracle.

### The bounded re-send loop (not a single blind send)

`new_session` is fire-and-forget and drops silently (`ErrNoLiveSession`,
Warn-logged) if the tui-driver session isn't yet attached to the supervisor when
the frame is processed. The `interrupt` e2e sidesteps this with a confirmed
round-trip (send_message + ack) before its keystroke; `new_session` has no reply
to round-trip on, so the cheaper equivalent is re-sending every ~250ms until the
registry observably rotates. fakeclaude's clear-rotate is one-shot, so once the
session is live the first `/clear` rotates and every later re-send is inert —
the loop cannot double-rotate or corrupt the assertion.

### Structural-causality guard

The file trigger (`StartRotationWithRelay`'s trigger arg) points at a path that
is never created. So in this test the **only** thing that can rotate the JSONL
is the `/clear` keystroke — an observed registry id change is only possible
because the `new_session` frame drove `/clear` to the child. Same discipline as
the `interrupt` e2e's "fakeclaude's ESC handler is the only source of a
turn_end" guard.

## fakeclaude: clear-rotate mode

`internal/e2e/internal/fakeclaude/main.go` gains `PYRY_FAKE_CLAUDE_CLEAR_ROTATES`
— an env-gated mode that rotates the live session JSONL once when the `/clear`
slash-command bytes are observed on stdin. Purely additive, byte-identical when
unset, mirrors `PYRY_FAKE_CLAUDE_ESC_ENDS_TURN`'s shape exactly (signal-only
reader → `atomic.Bool` → main-goroutine-performs-the-mutation, reusing the
shared `rotated` one-shot gate so the file-trigger and clear-rotate paths can
never both fire). Detection (`containsClearCommand`) is a plain
`bytes.Contains(buf, []byte("/clear"))` over the reader's accumulated buffer —
safe because in this mode the only stdin fakeclaude ever receives is that
keystroke sequence. No raw-mode entry needed: the trailing `\r` from
`ClearInputLine`+`TypePrompt` commits the canonical line, so a single read
already carries `/clear\n` (the leading Ctrl-U is consumed by the line
discipline as VKILL on an empty line — a no-op). Full mode writeup, config
table entry, and layout notes: [features/fakeclaude-binary.md § Clear-rotate
mode](../features/fakeclaude-binary.md#clear-rotate-mode-1004).

A small untagged table test, `containsClearCommand` in
`clear_detect_test.go`, pins the detector the same way `esc_detect_test.go`
pins `containsBareESC`.

## Patterns established

None new — this ticket is the same "clone the interrupt bring-up, mirror an
existing fakeclaude signal-then-mutate mode" shape as #1003 (`modal_cancel`) and
#794 (`interrupt` itself). Reconfirms: reuse in-package e2e helpers and rotation
assertions (`rotation_test.go`'s `waitForBootstrapID`/`waitForBootstrapIDChange`)
verbatim, never redefine (duplicate-symbol compile error); a fire-and-forget verb
with no reply needs a bounded re-send loop, not a single blind send, to be
deterministic against session-attach timing.
