# Ticket #1415 — Pin the ptyrunner trailer → attribution → run composition over fixtures

The live exit-path probe reached `run-running-at-trailer` on `admit-proof` on a real run (2026-08-06), under
`PYRY_USE_STREAMJSON=0` (ptyrunner). The three pure functions that produced that reading —
`trailGate` → `trailAdmitAttribution` → `trailClassifyRun` — were each driveable offline, but nothing pinned
the *composition* under a ptyrunner reading specifically: `TestTrailRunComposesWithGateCases` drives the
whole chain but every row carries the indeterminate reading, and `TestTrailGateIgnoresTheRunnerPath` drives
all five readings but only over `trailGate`, comparing each row against itself (invariance, not a baseline).
Two queued tickets edit the gate's arms; this closes the gap before they land. Purely additive — one new
test file, zero production files. PR [#1418](https://github.com/pyrycode/pyrycode/pull/1418).

## Implementation

- **`internal/e2e/realclaude/trail_ptyrunner_composition_test.go`** (new, `//go:build e2e_realclaude`) —
  `TestTrailComposesUnderAPtyrunnerReading`. Drives the reading through the shipped reader
  (`tdnRunnerFromArgv(tdnFixturePtyArgv)`), never by re-typing its prose; classifies a real reap record via
  `tdnClassifyReapLog` rather than typing one; builds the gate from `trailFixtureTrailer` (**not**
  `trailPaddedTrailer`, which renders `max_turns` and composes to a different outcome entirely); takes a
  copy of `trailRunProofReadings()` and overwrites only its `Gate`/`Admit` fields with the real results,
  since that fixture's other fields (counts, `Liveness`, `PyryExited`, `BoundFrom`, `ClaudeState`) already
  satisfy contract checks C6–C9.
- **Four premises (`t.Fatalf`), three of them new to this ticket**: the reading reduces to `"ptyrunner"`
  via `finRecordRunnerLabel`; the reading carries neither of the two *values* in the fixture argv
  (`/tmp/s.json`, `11111111-`) that sit after a flag — this is the first test to drive a real runner argv
  into `trailGateInput.RunnerPath`, a field that **is** marshalled into the published gate record, so this
  premise is the boundary that keeps a command-string echo out of it (flagged SHOULD FIX by the architect's
  self-review, addressed in the spec); the classified reap record matches the real producer's shape; the
  gate certified a non-empty reason before the attribution predicate is called.
- **Nine assertions pinning the published bytes, not the enum**: run-level outcome, both provenance fields
  (`out.Gate`, `out.Admit`), a no-echo pair on `gate.Detail` and `out.Detail` (the pair that matters — the
  third possible rung, on `trailAdmitAttribution`'s Detail, is dropped because that function's signature
  `(reap tdnReapOutcome, certified string)` is handed no runner path at all, so a byte assertion on it would
  be green by construction), and three ordering-sentence assertions, one per `Detail`, each keyed on a
  phrase unique to that arm (the admit and run arms both close "alive strictly AFTER the trailer was
  written" — separated by the em dash vs. the comma that follows).
- **`docs/specs/architecture/1415-ptyrunner-trailer-composition-pin.md`** — architect spec, including a
  self-review security pass (PASS) and the measured-fact table (byte sizes, cap headroom) the design rests
  on.

## Patterns established

- **A no-echo rung is scoped by walking the producing function's parameter list, not by "every Detail in
  the chain".** `trailAdmitAttribution` never receives a runner path, so a byte assertion on its Detail
  could never be reddened by any mutation to that arm — the chain has two no-echo rungs, not three, and the
  reason is stated in the test's own doc comment at the point a reader would look for the missing third.
- **Cap-headroom gets a dedicated `else if` branch only where the measured margin makes truncation a live
  risk, never as a blanket defence.** `out.Detail`'s no-echo assertion is paired with a headroom check
  (44-byte needle against 68 bytes of slack) because a modest prose addition could push the cap into hiding
  a real echo (#1284's cap-vacuity failure); `gate.Detail`'s 283 bytes of slack gets no such clause — an
  unobserved failure mode earns no defence. The pairing is `if / else if`, not two independent `if`s: any
  mutation that echoes the reading also eats the headroom, so two independent checks would double-fire on
  the same mutation and neither would be a sole red.
- **Discrimination-by-construction: enumerate the mutations before writing the assertions, and require a
  1:1 map.** Nine assertions, nine mutations, each verified independently under `go test -overlay` (no
  worktree writes) by both the developer and, on review, the code reviewer re-running the whole matrix
  rather than trusting the PR's table. A green pin that has never been shown to discriminate anything is
  worth exactly nothing, which is the ticket's own framing.

## Lessons learned

From the PR body's own "Lessons learned" section (developer, verbatim):

- A 40-byte literal pad is the value that separates a cap-headroom claim from the shipped truncation guard.
  `TestTrailClassifyRun:938` already reddens on `reachTruncationMarker`, so any pad pushing the Detail past
  512 bytes reddens *that* rather than the headroom clause. 484 bytes sits in the one gap where nothing is
  truncated yet the headroom (28) is below the needle (44) — the value that makes the mutation a sole red
  rather than collateral.
- The `if` / `else if` on the run-side no-echo pair is load-bearing for sole-red, not style. Any mutation
  that echoes the 44-byte reading also consumes the headroom, so two independent `if`s would have made the
  interpolation mutation redden both assertions at once.
- A byte assertion on `trailAdmitAttribution`'s Detail is vacuous by signature, not by accident. Walking the
  parameter list — not the Detail's prose — is what decides how many no-echo rungs a composition chain
  actually supports.

From code review (PASS, two NITs, neither required a change):

- A bare line-number cite (`(:963)`) two lines after a different named file resolves, under this package's
  own convention, to the *wrong* file — the last file named, not the symbol's actual location. Harmless here
  because the symbol name sits right beside the cite, but the convention this package uses for citing prior
  work needs the filename repeated on every bare cite, not just the first one in a paragraph.
- A spec's "Collateral (shipped)" column can under-report without weakening the ticket's own claim: sole-red
  is scoped to the new test's own assertion set, so a mutation reddening several shipped tests besides is
  expected and not a defect — but it is worth listing exhaustively for anyone re-running the matrix later.
