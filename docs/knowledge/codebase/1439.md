# Ticket #1439 — Certify the pinned-pid ordering argument on its three premises, naming the void per failed premise (offline)

A staged probe run holds its command un-finishable on a FIFO nobody writes to for the whole of the
wait on pyry's exit, which orders three instants by construction: the trailer is sighted, pyry
exits, then a pinned pid is re-read. That ordering only holds *by construction* if three premises
actually held — the trailer was sighted, pyry exited within its deadline, and the hold was held for
the whole of the wait — and each can fail independently, as the rig's own failure rather than
pyry's. This ticket ships `trailCertifyOrdering`, the pure offline predicate that certifies the
ordering or refuses with the name of the missing premise, so a later liveness claim rests on a
checked premise instead of an assumption.

The predicate makes no claim about any command's liveness — it says only that the three instants
were ordered, or which premise is missing. It is the smaller half of #1436's split; #1440 is the
consumer that composes an aliveness claim on top of the certified ordering, and #1437 separately
owns adding a hold field to `trailRunReadings` (untouched here).

PR [#1441](https://github.com/pyrycode/pyrycode/pull/1441). Split from #1436 (closed). Sibling:
#1440 (consumer, not yet built). Adjacent: #1437 (owns `trailRunReadings`'s shape). Security-sensitive
(architect self-review PASS; code review FAIL → rework → PASS).

## Implementation

- **One new file, one edited file, zero production Go touched.** `internal/e2e/realclaude/trail_ordering_premises_test.go`
  (new, `//go:build e2e_realclaude`) carries the value space, the record, the predicate, two
  membership helpers, a fixture type and four tests. `trailer_admissibility_test.go` gains the four
  values in its union closure map plus two corrected prose sentences (§ below).
- **`trailCertifyOrdering(trailerSighted, pyryExited, holdHeld bool) trailOrderResult`** — three plain
  booleans, not a `finSighting` or any record that could carry a trailer value. The parameter type is
  the enforcement: `finSighting` marshals `TerminalReason`/`StopReason`/`Subtype`/`KeyNames` under
  keys (`terminal_reason`, `stop_reason`, `subtype`, `trailer_keys`) that a `command`/`args`/`comm`/`argv`
  denylist would not catch, so narrowing the input type is what forecloses the leak that widening a
  denylist could not. Pure: no exec, no clock, no filesystem, no `*testing.T`, never fails a test —
  `trailGate`'s contract copied verbatim.
- **`trailOrderResult{Value, Detail string}`** — exactly `trailAdmitResult`'s shape, no third field.
  The three input booleans reach a reader through the Detail's fixed tail
  (`trailOrderPremiseClause = "premises: trailer-sighted=%t pyry-exited=%t hold-held=%t"`, ~65 B)
  rather than as struct fields.
- **Four values, `order-` prefixed**: `trailOrderCertified` (`order-certified`), `trailOrderVoidUnsighted`
  (`order-void-trailer-unsighted`), `trailOrderVoidNoExit` (`order-void-pyry-did-not-exit`),
  `trailOrderVoidUnheld` (`order-void-hold-released`). The prefix is load-bearing, not cosmetic:
  `order-void-pyry-did-not-exit` sits one word from the shipped `run-void-pyry-did-not-exit`
  (`trail_run_outcome_test.go:147`), and the Go identifiers deliberately avoid the `trailOutcomeVoid…`
  shape so autocomplete from `trailO` can't collide two untyped strings the compiler wouldn't catch.
  **Deliberately no `order-out-of-contract` value** — three bools admit eight readings by
  construction, so there is nothing an out-of-contract value could be about; the const block's doc
  states this as a decision, not an omission.
- **Precedence `hold → sighting → exit`, chosen on a structural-outranks-situational rule and checked
  by all eight rows.** The hold outranks both other premises because its failure removes the
  *subject* (the pid may have been retired and reissued), not merely one endpoint of the ordering —
  same rule `trailAdmitAttribution` uses for `trailAdmitVoidBudgetFired`. Sighting outranks exit
  because it's the earlier instant. Body shape is three guards (`holdHeld` → `trailerSighted` →
  `pyryExited`) then a fall-through certified arm, so no arm is a defensive default no fixture
  reaches.
- **`trailOrderValues() []string` / `trailIsOrderValue(v string) bool`** — `trailIsGateValue`/`trailIsRunOutcome`'s
  shape, the closed set as data plus a switch over the same four.
- **Union map join, not a fifth self-contained closure test.** The four values join
  `TestTrailAdmissibilityConstantsAreClosed`'s map (following #1271's precedent) because the
  realistic mistake is *cross-space* — the `run-`/`order-` near-collision above — and a per-space
  closure test (the `fin*` family's shape) is scoped to one space per call and can't see it. Two
  stale prose sentences in that test's doc were corrected in the same commit: the space count
  (three → four) and parenthetical, and the per-space consumer list (`trailClassifyRun`,
  `trailReasonAgainstPath`, now `trailCertifyOrdering` for the fifth space). Union map: 39 → 43
  entries, size still read off the map rather than printed as a literal.
- **Four tests, all offline, fixture-driven, no live claude:** `TestTrailOrderAllEightPremiseCombinations`
  (AC2 — all eight input combinations as distinct fixtures in a `map[trailOrderPremises]bool`, not a
  bare `len(cases)` cardinality check, plus per-row non-empty/no-truncation-marker/clause-content
  assertions), `TestTrailOrderEachPremiseHasItsOwnVoid` (AC3 — three subtests, each flips exactly one
  premise off the all-true fixture), `TestTrailOrderValuesAgreeWithThePredicate` (AC4 — both
  directions, count asserted against the ticket's own enumeration, and the reverse direction spells
  out all 7 gate + 7 admit + 4 liveness values plus the 3 scan states plus 3 `run-` near-collision
  values, rather than sampling), `TestTrailOrderResultCarriesNoCapturedBytes` (AC5 — structural
  marshal-and-walk only; the `trailNeedle` byte sweep is deliberately absent since the 3-bool input
  gives a planted needle no route in — #1440's record is the first that can carry one).
- **Precedence sanity check run as verification, not shipped as a test:** reordering the three guards
  to exit → sighting → hold under `go test -overlay` reddens exactly rows 5–8, proving the eight-row
  table pins the precedence rather than merely covering it.

## Patterns established

- **A shared Detail-format constant stops four arms drifting from each other; it does not make "every
  Detail carries X" structural on its own.** Code review round 1 killed this exact claim with a
  mutant: deleting the shared `trailOrderPremiseClause` tail from the certified arm left the whole
  suite green, because nothing asserted the clause's *presence*, only that the four arms would agree
  *if* present. The fix — render the clause from each row's own booleans and require the Detail to
  contain it — also pins the argument *order*, which a `strings.Contains(Detail, "premises: ")`
  prefix check would not have.
- **A cardinality guard (`len(cases) != N`) is not a coverage guard.** Duplicating one fixture row and
  dropping another keeps the count right while silently unpinning whichever rule the dropped row
  carried. Collecting the fixture inputs into a set and asserting the set's size is the same three
  lines and makes the failure message's promise exact.
- **A union-map insertion breaks cites the diff never shows.** Joining four values at
  `trailer_admissibility_test.go:1197-1246` shifted the file by +18 lines and broke four cites in
  files this PR never opened (`trail_ptyrunner_composition_test.go` ×2, `trail_run_outcome_test.go`
  ×1) plus one self-inflicted cite inside the new file — none caught by a plain grep because a
  filename-anchored sweep can't see a *bare chained* reference (`(:2056-2061)`) that inherits its
  filename from a citation two lines above it. See [[cite-sweeps-have-a-third-symbol-anchored-form]]
  and the code-review memory on detecting bare chained cites statefully.
- **Gap-size vs shift-magnitude is how you tell PR-created cite damage from pre-existing debt.** The
  rework round's own hand-off note (below) mis-attributed several `docs/knowledge/codebase/` cites as
  broken by this PR's +18 shift; the round-2 reviewer caught it by checking each cite's *pre-PR* gap
  against the *actual* +18 the PR made — the pre-existing ones had gaps of ~53, ~20 and ~27, none
  matching 18, so blindly re-pointing them by +18 would have moved already-wrong cites to a
  *different* wrong line.

## Lessons learned

From the PR body's own "Lessons learned" section (developer):

- **A guard-reorder overlay is what separates "the table covers the rule" from "the table pins the
  rule."** Eight rows over three booleans look exhaustive, but only the four multi-failure rows
  (5–8) carry precedence information — the four single-fact rows stay green under any guard order.
  Running the reorder is what proves which rows are load-bearing.
- **Sharing a format-string constant stops drift; it does not make a "must always be present" rule
  structural** — see Patterns above; this is the concrete instance code review caught with a mutant.
- **An insertion into a heavily-cited file breaks cites no diff shows and no grep finds** — see
  Patterns above. The bare chained ref needed a stateful scan tracking the last-named file per line,
  not a `grep '<file>\.go:[0-9]'` sweep.
- **A cardinality guard is not a coverage guard** — see Patterns above.
- **A stale count can hide in a comment that argues counts go stale.** `TestTrailAdmissibilityConstantsAreClosed`'s
  doc narrates its own past drift ("#1434's two make thirty-nine") to justify reading the size off the
  map; read plainly it still asserts a *current* size, so adding a fifth space made it false — a
  third stale sentence beyond the two the spec had already named.

From code review (two rounds, FAIL → rework → PASS):

- **Round 1 SHOULD FIX × 2, both fixed in rework:** the four collateral cite breaks above (a fifth
  found during rework via the stateful bare-ref scan), and the false "structural" claim (fixed by
  adding the clause-content assertion rather than softening the comment, since the clause is the
  design's stated substitute for a second field on the four multi-failure rows).
- **Round 2 caught the rework's own hand-off note as wrong, and this note is directly relevant to
  future documentation passes: do not apply it.** The rework comment asked the documentation phase to
  re-point `docs/knowledge/codebase/1420.md:88`/`:148` and `1430.md:73` by +18 (following this PR's
  shift). The round-2 reviewer verified those cites against `origin/main` and found none was broken
  by this PR — all were already stale before the branch opened (a 1429.md cite not even in the
  original hand-off list was found the same way), so re-pointing them by +18 would have made them
  *more* wrong, not less. **This documentation pass leaves `codebase/1420.md`, `codebase/1430.md` and
  `codebase/1429.md` untouched accordingly** — their `trailer_admissibility_test.go` cites are
  pre-existing debt for a future sweep, not this ticket's to fix.
