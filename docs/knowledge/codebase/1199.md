# Ticket #1199 — hold a mid-turn stream-json send in the queue until the turn ends

Split from #1189. Natively blocked by #1210 (the last child of the #1198 turn-busy tracker lineage),
which landed first. On `interactive_runner: stream-json` — live on the Mac daemon since 2026-07-24 — a
message sent while claude is mid-turn was enqueued correctly but the queued-backlog UI never appeared
and the drop-before-drain control never worked: the message was never lost, but the two mobile-facing
controls that make it visible and cancellable were regressed relative to `pty`. `pyrycode-desktop`#483's
8/8 real-claude gate was blocked on this cross-repo.

## Implementation

- **The gap, precisely.** `internal/msgqueue`'s `DeliverFunc` contract requires the delivery seam to
  block while claude is busy — that block *is* the drain's turn-end pacing. The PTY seam honours it
  (`supervisor.WriteUserTurn` gates on `waitReadyAutoContinue`). The stream seam did not:
  `streamsup.Runner.WriteUserTurn` is a one-line `WriteTurn(ctx, r.Stdin(), payload)` that returns as
  soon as the envelope is in the child's stdin pipe, so the drain emptied at write speed and the
  `queue_state` snapshot typically found nothing left — a race, not a deterministic hold.
- **`cmd/pyry/stream_turn_busy.go`**: two new methods on the existing `turnBusyTracker` (#1201),
  nil-receiver-safe and empty-key-safe like every other method on the type — no new fields, no new
  synchronisation. `waitIdleForDelivery(ctx, conversationID, timeout) error` wraps `WaitIdle` in a
  `context.WithTimeout`. `openForDelivery(conversationID) (undo func())` marks the conversation busy and
  returns the closing closure. `setBusy` gained a `changed bool` return, reported out of the single lock
  acquisition it already takes; `openForDelivery`'s `undo` is a no-op unless its own call actually moved
  membership, which is what stops a failed write's undo from clearing a turn opened by a different feed
  (a `--resume` respawn replaying events landing in the wait→mark gap is the plausible route) — deriving
  that answer from a separate `Busy` read would have reintroduced the TOCTOU this closes.
- **`cmd/pyry/main.go`**: `newInboundDeliver` gained two parameters (`busy *turnBusyTracker`,
  `hold time.Duration`) and now performs `waitIdleForDelivery` then `openForDelivery`, both between
  `Activate` and `WriteUserTurn`; a write error runs `undo()` and returns the error verbatim (unwrapped,
  so msgqueue's `errors.Is` classification of `ErrNoLiveSession`/`ErrTrustModalPending`/
  `turncommit.ErrDropped` is untouched). The wait failure is wrapped (`"stream turn hold: %w"`) so
  `errors.Is(_, context.DeadlineExceeded)`/`context.Canceled` still holds for the drain's own
  classification. New const `streamTurnHoldTimeout = 15 * time.Minute` sits beside
  `inboundActivateTimeout`, whose stale closing clause ("does NOT bound the `WriteUserTurn` that
  follows") is amended to note that on stream the pacing block now sits in front of the write and is
  bounded. The tracker is constructed at the composition root (`streamSink != nil` gate, not
  `cfg.InteractiveRunner == "stream-json"` — the former is `selectInteractiveRunner`'s own
  post-validation answer) between the runner-factory call and `msgqueue.New`, dissolving the
  construction-order fork the ticket flagged: `convReg` (its only input) is already loaded, and no
  factory signature changes.
- **`cmd/pyry/relay.go`**: `relayWiring` gained a `busy *turnBusyTracker` field (non-nil exactly when
  `streamSink` is), replacing the local the relay leg used to construct. The `:731-746` comment that
  named this ticket's consumer by role ("the consumer slice that consults it for delivery promotes it to
  a field") is rewritten to the field's provenance — leaving it would have inverted exactly as #1207 and
  #1210 both found elsewhere.
- **Seam choice: `newInboundDeliver`, not `streamRunner.WriteUserTurn`.** The runner seam was the other
  candidate (spec's "Technical Notes"); `newInboundDeliver` won because it dissolves the construction
  fork for free, its blast radius equals the AC scope exactly (the runner seam is also the ACP prompt
  path's target, which carries no `turncommit` gate and no AC coverage here), and AC4 (PTY unchanged) is
  structurally free either way once both tracker methods are nil-receiver no-ops.
- **Tests**: `cmd/pyry/stream_turn_busy_test.go` extended for the two new methods, including an
  undo-scoped-to-its-own-open case and a mark-before-write ordering assertion made from inside the
  writer stub. `cmd/pyry/inbound_deliver_test.go` extended for AC1 (deterministic hold, ordered
  delivery), AC2 (`Remove` returns `true` on the parked head — the non-vacuous assertion, false before
  this ticket because the head claims `committing` almost immediately), AC3 (bounded failure, writer
  never called), and the undo-on-write-failure case. `internal/e2e/relay_v2_stream_queue_drain_test.go`
  renamed to `TestRelayV2_StreamMidTurnHoldDropAndDrainInOrder`, extended to four sends so msg4 is
  dropped mid-hold and the terminal assertion proves it never reaches claude — its own stale doc block
  ("a `queue_state` depth of N is NOT reliably observable here") is rewritten, since this ticket is what
  makes that observable.
- **`TestTurnBusyTracker_ImportsStayMinimal` widened, not weakened.** `waitIdleForDelivery`'s
  `time.Duration` parameter forced a `"time"` import the guard previously used as its proxy for "no
  clock read." Rather than retire the guard, it now walks the AST and requires every `time.X` selector
  in the file to be `time.Duration` — naming the actual property (no `time.Now`/`After`/`Tick`/
  `NewTimer`/`Sleep`) instead of proxying it through the import list. A caller-supplied bound that
  becomes a ctx deadline reports that the *waiter* gave up, never that the conversation went idle, so it
  doesn't weaken the #1201 no-timestamp contract.

## Patterns established

- **Placement delivers an AC by itself when it's chosen against the callee's documented contract.**
  AC2 (drop-before-drain) needed no new removal logic: `msgqueue.commitGate`'s own doc says the seam
  calls it "after the idle-gate wait and before the write," so putting the hold in front of
  `WriteUserTurn` (and therefore in front of `WriteTurn`'s internal `turncommit` claim) is what keeps the
  queued head `draining && !committing` — the only state `Remove` will drop — for the wait's entire
  duration. The spec derived this from reading the callee, not from designing a removal mechanism.
- **A mark must precede the action whose completion would race it.** The tracker's ordinary opener feed
  is asynchronous (child → parser → sink → drain → `observe`); marking *after* a successful write lets a
  fast child's own `TurnEnd` clear the mark before the marking statement runs, leaving a stale mark
  nothing will ever clear again. Marking first makes the ordering unconditional regardless of child
  speed — the cost is one `undo()` on the write-error path, cheaper than the alternative failure mode.
- **A `changed` return out of the one lock acquisition a mutation already takes closes a TOCTOU that a
  second read cannot.** `openForDelivery`'s undo needing to know "did *I* open this" could have been
  answered by a `Busy` read either before or after `setBusy`, but either ordering leaves a window for a
  competing opener to land in between — reporting the answer from inside the mutation itself removes the
  window entirely rather than narrowing it.

## Lessons learned (from PR#1213 — code review PASS, 0 MUST/0 SHOULD + 3 NITs; and the developer's own PR body)

- **A unit-tier fake can make a "still droppable" assertion vacuous without looking wrong.**
  `msgqueue.Remove` no-ops on a `committing` head, and `committing` is set only when the delivery seam
  claims the `turncommit` gate — which `streamsup.WriteTurn` does but a naive test double does not.
  Asserting `Remove == true` against a writer that never claims the gate proves nothing about the hold;
  the drop test needed a writer that claims it exactly as production does.
- **`git checkout <file>` to undo an experimental RED-check patch discards the real, uncommitted work in
  that file too**, not just the patch. Reverting a temporary mutation that way wiped every edit in
  `stream_turn_busy.go`, including the deliverable. Inverse-replace the patch, or restore from a copy
  taken before the experiment.
- **Code review's citation-shift sweep (the #1210 class) found zero regressions this time** — the four
  in-tree Go citations the developer updated all verified by content, and the diff's own insertions
  shifted six tree-wide citations with zero previously-correct ones broken. Recorded because the same
  sweep, run against this documentation pass, *did* find three stale knowledge-doc citations this diff's
  insertions broke (`streamsup-package.md`'s references to `relay.go:395-410`, `relay.go:756`, and
  `stream_turn_busy.go:187`, now `relay.go:406-421`, `relay.go:784`, and `stream_turn_busy.go:240`) — the
  in-tree sweep and the docs sweep are separate checks, and only the code-review one runs by default.
- **The undo's scoping doc closes one race and is silent on its lower-probability twin, by design.**
  Code review's one substantive NIT: `setBusy`'s `changed` return closes the wait→mark gap. The mark→write
  gap has the same shape at much lower probability (mark → a teardown clear → a foreign re-open → our
  write fails → `undo()` clears a turn we no longer own) — needs a teardown *and* a respawn-replayed
  opener *and* a failed write in a microsecond window, self-corrects on the next opener event, and a real
  fix wants a generation token the #1201 membership-only contract forbids. Correct call not to build a
  defense for an unobserved failure mode; the spec should have spent one sentence saying so explicitly
  rather than leaving the next reader to re-derive it (the spec has since been read that way — this file
  is that sentence).
