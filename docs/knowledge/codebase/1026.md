# Ticket #1026 — move snapshot/replay/resync out of `v2session.go`

Sixth and final-planned slice of the [#964](https://github.com/pyrycode/pyrycode/issues/964)
split of `internal/relay/v2session.go`, chained after
[#1021](1021.md) (handshake), [#1022](1022.md) (rekey), [#1023](1023.md)
(modal+queue), [#1024](1024.md) (settings), and [#1025](1025.md)
(debugbundle). Carves two reconnect-recovery concerns — the screen-snapshot
request path and the missed-event replay/resync path — into a new file in
the same `package relay`. Pure mechanical move: no exported-API change, no
behaviour change, zero call-site changes.

## Implementation

New file `internal/relay/v2session_replay.go` (389 lines) now owns seven
declarations, moved verbatim with their doc comments byte-for-byte: the
`msgSnapshotConvNotFound`/`msgSnapshotOffline` const block,
`handleRequestSnapshot`, `snapshotReplyError`, `SetReplaySource`,
`replayMissed`, `emitResync`, and `drainReplayOnce`. `v2session.go` drops by
367 lines, from 1925 to 1558.

The move was two cuts, not one contiguous span: Block A
(`v2session.go:1121-1409`, the const pair through `emitResync`) and Block B
(`v2session.go:1695-1770`, `drainReplayOnce`), separated by seven functions
that stayed (`sealError`, `marshalInnerFrameV2`, `closeWith`, `send`,
`Push`, `transportDown`, `drainOnce`).

`snapshotReq` (`v2session.go:113-122`) was **deliberately excluded** from
the move despite being named in the ticket's Technical Notes — a
name-collision, not an oversight. It is the ActiveConns-enumeration request
type (`chan []ActiveConn` reply envelope), unrelated to the screen-snapshot
path; neither `handleRequestSnapshot` nor `snapshotReplyError` references
it. All four of its consumers (the `snapshot chan snapshotReq` struct
field, `NewV2SessionManager`, `ActiveConns`, and `Run`'s select arm) stayed
in `v2session.go`, so moving the type away from every one of its users
would have reduced cohesion — the opposite of the ticket's goal. Same
"interleaved neighbour stays" shape as [#1022](1022.md)'s
`armIdleTimer`/`wakeKind`.

Imports were compiler-forced to **zero net change** in the donor file:
`context`, `encoding/json`, `time`, and `internal/protocol` are all still
used by the ~1550 lines remaining in `v2session.go`. `eventring` in
particular stays live via the `replayQueue []eventring.Event` (`:278`) and
`replayRing *eventring.Ring` (`:754`) struct fields — the moved code was
not its only user. The new file imports the same five packages
(`context`, `encoding/json`, `time`, `eventring`, `protocol`) for its own
use. Inverse of [#1022](1022.md), where `bytes` was used only by the moved
code and the compiler forced its removal from the donor.

The `TypeRequestSnapshot` dispatch case in `dispatchAppFrame`, the
`V2Session`/`V2SessionManager` structs, the `Run` loop, and the shared
`forwardEnvelope`/`sealError` seal path all stay in `v2session.go`,
same-package references untouched by the move.

## Patterns established

None new — the sixth and final confirmation of the #964 pure-move
discipline, closing out the parent split (`internal/relay/v2session.go`
now 1558 lines, down from 3744 when first flagged).

## Lessons learned

None — the move went exactly as scoped in the architecture spec, including
the `snapshotReq` name-collision the spec's CRUX flagged in advance. Worth
noting as a category: a same-package pure move can be told to leave a
similarly-named-but-unrelated type in place purely on cohesion grounds
(every consumer stays), even when a ticket's own Technical Notes list names
it for the move — the architect's "finalizes exact placement" grant is
what makes that override legitimate, not just useful.

## Verification

`go build ./internal/relay/` clean at each cut; `make check` green (vet,
`-race` test incl. `internal/relay`, staticcheck, substrate-guard,
hermetic e2e — live-claude e2e legs SKIP on missing credentials,
unaffected by this diff; the manual real-claude e2e re-run during code
review also passed clean). Code review: PASS, no findings. The diff
touches exactly the two intended files (`v2session.go`,
`v2session_replay.go`) plus the architect's spec doc — no other file in
the tree changed; `cmd/pyry/interactive_turn_stream_v2.go`'s
`SetReplaySource` call site and the pre-existing
`v2session_replay_test.go` were both left byte-for-byte untouched (method
resolves per-type, tests reference package-internal names), confirming the
move is transparent to both (AC #4).
