# Ticket #1108 — construction-safe session-id seam for a stream-json runner factory

Split from #1107 (the sibling `RunnerFactory` ticket is #1109, blocked on this one). Adds an eager `SessionID string` field to `supervisor.Config`, set unconditionally at both pool construction sites, so a future stream-json `RunnerFactory` can read a non-empty session id at construction — `streamsup.New` requires its id eagerly and has no lazy-resolve path.

## Implementation

- `internal/supervisor/supervisor.go` — new `Config.SessionID string` field, placed next to `ResolveSessionID`. Doc comment states the PTY supervisor deliberately ignores it (keeps rotating via `ResolveSessionID`) and that it is construction-fixed — does not mirror a `/clear` rotation. `buildClaudeArgs` keeps its 4-param signature; the field structurally cannot reach argv.
- `internal/sessions/pool.go` — two assignment sites:
  - `Pool.New` bootstrap `supCfg`: `SessionID: string(bootstrapID)` (the already-resolved local, not the late-bound `p.BootstrapID()` closure `ResolveSessionID` uses).
  - `Pool.buildSession`: `SessionID: string(id)` (the funnel shared by `CreateIn`/`GetOrCreateIn`), alongside the pre-existing `--session-id <id>` baked into `ClaudeArgs`.
- Seam chosen: (i) additive eager field, not (ii) a lazy resolver on `streamsup.New` — seam (ii) would change a shipped package's public signature for no benefit, since `streamsup` is structurally fixed-at-construction anyway (`buildArgs` `--resume`s the same id forever, no rotation mechanism).
- `/clear` rotation decision: **accepted-and-documented as fixed-at-construction for the stream-json path.** PTY path keeps full rotation via `ResolveSessionID` untouched. Stream-json has no production consumer yet (#1109 not landed); mirroring rotation there is deferred until something actually drives that path.

## Tests

- `internal/sessions/runner_test.go` — extended `TestRunnerFactory_InvokedAtEveryConstructionSite` to capture `cfg.SessionID` at each factory call and assert it's non-empty and equals the site's minted id (`BootstrapID()` at bootstrap, the `id` param at `buildSession`).
- `internal/supervisor/restart_test.go` — new `TestSupervisor_Run_IgnoresSessionIDField`: sets `SessionID` and `ResolveSessionID` to *different* ids, spawns, asserts the child argv carries only the `ResolveSessionID`-resolved id and never leaks the ignored `SessionID` value. This is the deterministic code guard (not a stochastic rule) against a future edit accidentally wiring `SessionID` into the arg path.

## Patterns established

- Confirms the existing pattern (see [[architect-streamsup-construction-safe-id-seam-i-additive-config-field]]): when a downstream consumer needs a construction-time value that today only exists as a spawn-time closure, add an inert, additive field to the shared `Config` struct rather than changing the existing lazy mechanism's shape. The "ignored by the thing that doesn't need it" property is itself the rollback guarantee — no gating on whether a factory is present.

## Lessons learned

None — code review passed clean with no findings (PR #1110). Spec, implementation, and review were an exact match; nothing surprising surfaced.
