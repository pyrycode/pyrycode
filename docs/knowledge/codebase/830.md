# Ticket #830 — start-new-session (`/clear`) keystroke seam

A fourth keystroke actuator on the #726 safe-answer seam: `Supervisor.StartNewSession()`
drives claude's `/clear` (start-a-new-session) slash command through the live PTY.
Split from #824. Ships **unwired** — the remote `new_session` wire verb that
consumes it (with its authorization) is a sibling ticket, mirroring the
codebase's own #726 → #707 factoring (actuator ticket, then the relay verb that
consumes it). Architect downgraded S → XS: the compose collapsed to two existing
tui-driver calls inside one existing `switch`, no new file, no `supervisor.go` edit.

## Implementation

One file, purely additive: `internal/supervisor/modal.go` (+ its test file).
~15 prod LOC.

- **`modalKey` enum widened.** Added `keyStartNewSession` as a fourth constant
  and `String()` case (`"start new session"`, feeds the error-wrap prefix). The
  type doc comment now describes the enum as "an abstract keystroke intent, one
  level up from tui-driver's concrete key methods" rather than strictly
  modal-resolution, since this member drives a slash command, not a modal answer.
- **`StartNewSession() error`** — a one-liner sibling of `AcceptTrust`/`Answer`/
  `SendEsc`: `return s.sendModalKey(keyStartNewSession, "")`. Reuses
  `sendModalKey` verbatim (capture `s.sess` under `sessMu`, release, actuate on
  the captured pointer; nil session → wrapped `ErrNoLiveSession`, writes
  nothing; keystroke error → wrapped with the stable
  `"supervisor: start new session:"` prefix, `errors.Is`-preserved).
- **`sendModalKeystroke`'s new `case keyStartNewSession`** composes two
  tui-driver calls, failing loud on the first error:
  1. `sess.ClearInputLine()` — Ctrl-U line-kill. **Load-bearing, not
     defensive:** claude's slash-picker only opens when `/` is the first
     character of the input line; drafted text left in the box would make
     `/clear` render as literal text (`hello/clear`) and open no picker.
  2. `sess.TypePrompt("/clear")` — types `/clear` byte-by-byte (each byte
     opens then filters the slash-picker), settles, then writes an isolated
     `\r` that runs the highlighted entry. This single call *is* the
     "open-picker → filter → commit" sequence.
- **No `supervisor.go` edit.** The `keystrokeFn` field
  (`func(sess *tuidriver.Session, k modalKey, choice string) error`) and its
  `New` wiring (`s.keystrokeFn = sendModalKeystroke`) already existed and route
  a new enum value automatically — the signature doesn't name the enum's
  members.
- **No new sentinel, no new exported type, no `context.Context`, no new
  goroutine/mutex.** `choice` is ignored; `/clear` is a fixed code literal
  (AC-5: no caller-supplied free text, no trust decision).

### Why `TypePrompt`, not `SendKeys`/paste (recorded so it isn't "simplified" later)

- **Not a bracketed paste.** claude's paste path treats `/clear` as literal
  prompt text and does not open the slash-picker — only genuine byte-spaced
  typing (`TypePrompt`) makes claude register it as typed input.
- **Not `SendKeys("/clear\r")`.** `SendKeys` is tui-driver's documented
  spike-only hatch, "not intended for production drivers"; a bulk write can
  trip claude's paste-detection heuristic, the exact failure `TypePrompt`
  exists to avoid.
- **No explicit extra Enter step.** `TypePrompt`'s trailing `\r` (written as a
  separate byte after settle) is the picker commit; typing the full word
  `clear` filters the picker to the exact `/clear` entry as the highlight, so
  no `Navigate`/arrow step is needed.

### Tests (`internal/supervisor/modal_test.go`, extended)

Added one table row each to the three existing #726 tests, following the same
`keystrokeFn` injection seam (a real tui-driver call nil-derefs a zero-value
`&tuidriver.Session{}`, so this boundary — like the three sibling verbs — is
tested via injection, not a real spawn):

- **Dispatch (AC-4):** `StartNewSession()` → seam records `keyStartNewSession`/`""`, returns nil.
- **No live session (AC-2):** no `setSession` → `errors.Is(err, ErrNoLiveSession)`, `"supervisor: start new session:"` prefix, seam never called.
- **Keystroke error wrap (AC-3):** seam returns sentinel `boom` → `errors.Is(err, boom)` holds, prefix present.

The real `ClearInputLine`+`TypePrompt("/clear")` compose, and the live
assertion that claude actually renders `ModalClassSlashPicker` and rotates its
session UUID, are **not** unit-tested here — same documented boundary as
`AcceptTrust`/`Answer`/`SendEsc`. Confirmed live only by the sibling
`new_session` verb's e2e/manual path.

## Patterns established

- **A sealed keystroke seam can grow a new intent without touching its
  injection point.** `keystrokeFn`'s signature is generic over the enum
  (`modalKey`, not named constants), so a fourth actuator slotted in with one
  `switch` case and zero edits to `supervisor.go` or its `New` wiring. Any
  future keystroke-shaped primitive on this seam gets the same free ride.
- **The enum's doc-scope widens honestly when a member stops fitting the old
  name.** Rather than force `/clear` to pretend it's "modal resolution",
  `modalKey`'s doc comment was updated to "abstract keystroke intent" — the
  accurate umbrella both the three modal verbs and the new slash-command
  actuator fall under.
- **Actuator/consumer split repeats the #726→#707 shape.** The mechanical
  keystroke primitive ships first, unwired, carrying no trust decision; the
  wire verb that authorizes and invokes it is a separate, later ticket. Same
  factoring both times this shape has come up.

## Lessons learned

- **`TypePrompt` vs `SendKeys`/paste is the load-bearing design decision, not
  an implementation detail — document it in-code.** `/clear` only opens
  claude's slash-picker in response to genuine byte-spaced typing;
  paste-shaped delivery (bracketed paste or a bulk `SendKeys` write) is either
  read as literal prompt text or risks tripping claude's paste-detection
  heuristic. Both the architect spec and the shipped code carry this rationale
  inline so a future pass doesn't "simplify" the two-call compose into a
  single paste write and silently break `/clear`. (Lifted from the PR's
  *Lessons learned*.)
- **`ClearInputLine` first is a correctness requirement, not a defensive
  nicety.** claude's slash-picker only opens when `/` is the first character
  of the input line; without clearing, any drafted text in the box makes
  `/clear` render as trailing literal text and no picker opens at all.

## Out of scope / incidental

- **No rotation observation.** Does not touch `Pool.RotateID`, `onRotate`, the
  rotation watcher, or the `session_transition` emitter (all pre-existing,
  separate machinery in `internal/sessions/` — see
  [features/rotation-watcher.md](../features/rotation-watcher.md)). Driving
  the keystroke is the entire scope; observing its effect is out of scope.
- **No wiring.** No relay handler, no `cmd/pyry` flag, no wire message. The
  sibling `new_session` verb (split from #824) consumes this primitive with
  its own authorization.
- **Not security-sensitive.** A fixed-`/clear` mechanical actuator: no trust
  decision, no caller-supplied free text, loosens no control. Same
  classification as #726.
