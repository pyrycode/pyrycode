# Ticket #974 — e2e: `rename_conversation` over the v2 wire

A 2026-07-15 full-repo review found eleven client-sendable v2 wire verbs whose
only coverage was package-level unit tests — the exact gap shape that let #949
ship a `promote_conversation` handler nothing exercised end-to-end. This
ticket closes that gap for `rename_conversation`, one of four
conversation-lifecycle verbs split off the review epic (#960); siblings cover
`delete_conversation` and the `archive`/`unarchive` round-trip, and #963 is
the realclaude capstone blocked by all of them.

## Implementation

Test-only, one new file, no production code:

- `internal/e2e/relay_v2_rename_test.go` (new, ~308 LOC, build tag `e2e`) —
  `TestRelayV2_Rename` with two independent subtests, each owning its own
  pair → spawn → Noise_IK handshake (copied call-for-call from
  `relay_v2_promote_test.go`, per the spec's explicit no-shared-helper
  instruction):
  - `testV2DaemonRenameRoundTrip` — seeds a conversation row that is already
    `is_promoted: true` and named, seals a `rename_conversation` frame over
    the encrypted channel, and asserts the decrypted `conversation_updated`
    reply: `in_reply_to` correlates to the request id, `Name` echoes the new
    title, `IsPromoted`/`IsArchived`/`Cwd` are preserved, and `LastUsedAt` is
    compared with `.Equal` (never `==`) to prove a rename does not bump
    last-used. Reads `conversations.json` back off disk to confirm the rename
    persisted with `is_promoted`/`cwd` unchanged.
  - `testV2DaemonRenameNotFound` — targets a conversation id absent from the
    registry, asserts the decrypted reply is an `error` envelope carrying
    `conversation.not_found`, and reads the registry back to prove the
    seeded row was never mutated (the handler replies before any `Save` on a
    miss).
  - Two spawns rather than one shared daemon is deliberate: it keeps the
    not-found subtest's seeded row pristine, so "unchanged" asserts the
    exact seeded name rather than a value a prior rename could have touched.
  - Seeding `is_promoted: true` (rather than `false`) for the happy path
    makes "unchanged" a real check — a handler that hard-coded `false` or
    dropped the flag would be caught.

## RED-on-regression

If the handler's `TypeRenameConversation` registration at
`cmd/pyry/relay.go:407` were removed, the verb would fall through to the
no-handler `protocol.unsupported` arm and the happy-path
`want conversation_updated` assertion (a `t.Fatalf`) would fail. The test is
a live guard on that registration, not just the handler body — closing the
same #949 gap shape end-to-end.

## Security review

Not security-sensitive: test-only, asserts observable behaviour (decrypted
wire frames, on-disk file state), no new production code or attack surface.
