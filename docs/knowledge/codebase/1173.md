# Ticket #1173 — realclaude/stream: multi-turn continuity against live claude

Adds the first real-claude e2e that drives **>=3 sequential turns on one held-open
stream-json interactive session**, proving the interactive stream runner's core
purpose — keeping a single live `claude` child's stdin open across turns with
context intact — against real claude, not just a scripted fake. Every prior
stream real-claude spec (#1153, #1154, #1172) is single-turn; every multi-turn
stream behaviour was covered only against fakeclaude, which can't catch the
fake-green/real-red class (#949). Split from #1083 (T9); sibling leaves are
#1174 (new-session rotation) and #1175 (permission DENY).

## Implementation

- `internal/e2e/realclaude/interactive_stream_multiturn_continuity_test.go`
  (new file, `//go:build e2e_realclaude`, PR #1179). Test-only, zero production
  files, no edits to any existing file.
- `TestInteractiveStreamMultiTurnContinuity` transcribes #1153's
  `TestInteractiveStreamLiveness` setup verbatim (pair → seed bootstrap registry
  + bound conversation → `spawnBootstrapDaemon` → handshake), then replaces the
  single send with a **3-entry turn plan** driven strictly sequentially over one
  held-open session, each turn fully drained to `turn_state{idle}` before the
  next send:
  1. **plant** — instructs claude to remember a per-run-unique token
     (`PYRY<hex nonce>`, from `time.Now().UnixNano()`).
  2. **filler** — an intervening turn with no bearing on the token. Load-bearing
     for AC #1: it proves the child served a turn *between* plant and recall
     without respawn — a 2-turn plant→recall wouldn't establish "≥3 turns on one
     held-open child".
  3. **recall** — asks for the token back; its `assistant_delta` text is
     captured and must contain it.
- Continuity is asserted by content, not process inspection: after the recall
  turn, `strings.Contains(strings.ToUpper(recallText), token)` must hold. A
  freshly respawned, memory-less child cannot produce the token, so this is the
  observable that distinguishes "same child served all turns" from "unexpected
  respawn" — deliberately no pid probe (the harness doesn't expose the child pid,
  and content memory is a strictly stronger observable anyway).
- New helper `drainForCompletedTurnText(t, phone, cs, convID, timeout) string` —
  a text-capturing superset of #1153's `drainForCompletedTurn`. Byte-identical
  milestone semantics (M1: non-empty `assistant_delta` for `convID`; M2: terminal
  `turn_state{idle}` for `convID`) with one addition: it accumulates *every*
  matching delta's text into a `strings.Builder` and returns the concatenation at
  M2, instead of stopping at the first delta. Mirrors the sibling's frame loop
  exactly (decrypt every `noise_msg` in receive-nonce order; skip non-`noise_msg`
  control frames without decrypting, to avoid a CipherState desync).
- Fresh package-private seed constants `streamMultiTurnBootstrapUUID`
  (`cccccccc-…`) / `streamMultiTurnConvID` (`dddddddd-…`) — distinct in both name
  and literal from every same-package const and from `feature/1172`'s in-flight
  `33333333`/`44444444`.

## Patterns established

- **A capturing drain is a separate helper, not a parameterized shared one.**
  `drainForCompletedTurnText` duplicates the sibling `drainForCompletedTurn`'s
  ~50-line frame loop rather than adding a "capture text" flag to it — editing
  the shared drain would touch two already-merged sibling call sites (#1153
  liveness, #1154 modal) and change their asserted behaviour, exceeding "one new
  file, no production change". The append gate is kept identical to the M1 gate
  (`ConversationID == convID && TrimSpace(Text) != ""`) so accumulation and
  liveness never drift out of lockstep. Applies to any future stream spec that
  needs the full reply text rather than just liveness.
- **Content continuity, not pid inspection, proves "no respawn".** When a test
  needs to prove a resource (here: a live child process) persisted across
  operations without exposing a handle to that resource, a content-memory
  observable planted before and checked after is a strictly stronger and simpler
  proof than trying to inspect the resource's identity directly.

## Lessons learned

- (from the PR body) A text-capturing drain and a milestone-only drain want to
  be **separate helpers**, not one parameterized helper — see "Patterns
  established" above for the full reasoning.
