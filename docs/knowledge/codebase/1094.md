# Ticket #1094 — `internal/streamsup`: type-aware idle watchdog with emit-not-kill stall hook

Lifts the type-aware idle watchdog from the one-shot runner
(`internal/agentrun/streamrunner/watchdog.go`) into `internal/streamsup`, the receive-side counterpart to
[#1093's send-side turncommit gate](1093.md). One crucial divergence: the one-shot runner **kills** on
idle stall; this slice **emits and never kills**, because the T1 spike (#1075, claude 2.1.199) measured a
pending permission approval blocking claude synchronously until the approval tool answers — unbounded
*owed* silence that a kill-on-stall watchdog would mistake for a wedge.

## Implementation

- New additive file `internal/streamsup/watchdog.go` (+ `watchdog_test.go`). Zero diff to `runner.go`,
  `parser.go`, `envelope.go`, or `internal/supervisor` (AC4).
- `stallTracker` (unexported `io.Writer`) — lifted `feed`/`consumeLine` mechanics from `streamrunner`'s
  `streamParser`, minus the passthrough `dst` (it's a terminal sink, not a tee — `Write` always reports
  `(len(b), nil)` so `io.MultiWriter` sees a full consume) and minus `sawResult`. Tracks `awaiting`
  (claude owes an assistant turn) purely from each line's top-level `type`: `assistant`→false,
  `user`/`tool_result`→true, `result`→false; everything else is activity-only. Starts `awaiting: true`
  (claude owes the first turn once the opening envelope is sent). Locks (`sync.Mutex`) because, unlike
  the #1088 `Parser`, a second goroutine (the poller) reads its state via `snapshot()` concurrently with
  the `os/exec` forwarder goroutine's `Write`.
- `shouldFire(awaiting, last, now, idle) bool` — pure predicate, `awaiting && now.Sub(last) > idle`. The
  type-aware core: an in-flight tool run (`awaiting=false`) never fires, however long the silence.
- `Watchdog` (exported) — owns the tracker, a `WatchdogConfig{Idle, PendingPermission, OnStall, Logger}`,
  and a single poll goroutine (`Start(ctx)`/`Wait()`) ticking at `watchdogTickFor(Idle)` (lifted
  verbatim: `idle/8` clamped to `[5ms, 5s]`).
- **Emit-not-kill enforced structurally, not just by convention:** `Watchdog` holds no
  `context.CancelFunc` and no process handle — `WatchdogConfig` has no field to wire one in. The KILL
  machinery (`idleStallResult`, `idleStallUsage`, `writeIdleStallResult`, the synthetic `result` trailer,
  `sawResult`) was deliberately **not** lifted.
- **Pending-permission hook annotates, does not gate.** `OnStall func(pendingPermission bool)` fires on
  *both* a genuine wedge (`pending=false`) and an approval-wait (`pending=true`) — the distinction lives
  in the argument the consumer receives, not in whether the callback runs. Rejected alternative: gating
  the emit off while pending (contradicts the ticket's "emits ... while a permission approval is
  pending").
- **Edge-triggered latch, one emit per stall episode.** A goroutine-local `fired bool` (not tracker
  state) fires once when `shouldFire` flips true, re-arms when a tick observes `!shouldFire` (activity or
  an `awaiting` flip cleared it). The poller never returns after firing — it keeps polling until
  `ctx.Done()`, which is what lets it tolerate an unbounded pending-permission window (AC2 "however long
  the approval stays outstanding").
- One shared clock seam (`WatchdogConfig.now`, unexported test hook) threaded into both the tracker's
  `lastEvent` and the poll's elapsed check — a deliberate tightening over `streamrunner`, which mixes
  `p.now()` in the parser with `time.Since` in the poll.
- Reuses `defaultMaxParseBuf` from `parser.go` (not redefined) and `discardLogger` from
  `parser_test.go`.

## Patterns established

- **Structural enforcement of a behavioral divergence.** When a lifted component must diverge from its
  source in a safety-critical way (kill → emit), remove the capability from the type rather than relying
  on a call-site rule: `Watchdog` has no cancel/process field, so a future edit literally cannot wire a
  kill back in without changing the struct shape. Same belt-and-suspenders instinct as
  [#1089's gate/watchdog child split](../PROJECT-MEMORY.md), applied one level deeper (inside a single
  type's field list, not just ticket scope).
- **Hook annotates the signal, doesn't gate it.** When a "don't treat this as owed" signal and an "emit a
  stall" signal both need to reach the consumer, thread the hook's value through as the emitted event's
  payload rather than branching emission on it — preserves "always observe genuine idle, let the consumer
  decide what to do" as a single code path instead of two.
- **Per-tracker logger for drop-diagnostics parity.** The spec's `stallTracker` struct sketch omitted a
  logger field; the tracker's error-handling table (oversized-partial drop) and the sibling #1088
  `Parser`'s existing byte-count Debug log on the same condition both call for one. Added `log
  *slog.Logger` to keep the two same-package line-splitting `io.Writer`s consistent — a deliberate, small
  deviation from the literal spec sketch, not a scope change.

## Lessons learned

- Spec struct sketches for a lifted/mirrored type are a starting point, not a contract — cross-check
  against the sibling type in the same package (here, #1088's `Parser`) for fields the sketch dropped
  (here, the logger) before treating the sketch as final.

## Code review

PASS. One NIT, no action taken: `Start` has no guard against being called twice (would spawn two poll
goroutines that both `close(w.done)` → panic on the second close). Matches the `streamrunner`
`startWatchdog` precedent (same single-call contract, no guard) and the component is internal + unwired
with a single documented caller shape — flagged only so the eventual wiring slice preserves the one-call
contract, not for immediate action.
