# Ticket #867 — rotation: bound the darwin lsof probe with a timeout

`darwinProbe.OpenJSONL` shelled out to `lsof` with `exec.Command(...).Output()` — no context, no timeout. A hung `lsof` (dead network mounts, uninterruptible-sleep targets, loaded hosts) could freeze any of its three synchronous callers indefinitely: the v2 manager's single `Run` dispatch goroutine (`snapshotUsage`, once per `screen_snapshot` — a hang here freezes the entire phone surface), the turn-stream/modal-stream bootstrap resolvers, and the rotation watcher's `probeWithRetry` goroutine. Mirrors the same discipline `ptyrunner.reap.go` already applies to its `ps` snapshot (`reapPSTimeout`, [`codebase/864.md`](864.md)).

## Implementation

Confined to `internal/sessions/rotation/probe_darwin.go` (darwin-only build tag; the linux probe reads `/proc` directly and is unaffected).

- **`lsofProbeTimeout = 2 * time.Second`** — a package `var`, not a `const`, unlike `reapPSTimeout`. The reap precedent could stay a const because its tests swap the whole reap function and never exercise the timeout firing. This ticket's AC 1 *requires* exercising the fire, so the bound must be test-shrinkable (~100ms) to keep the test fast and non-flaky.
- **`newLsofCmd` package-var seam** — `func(ctx context.Context, pid int) *exec.Cmd`, mirrors `reapDescendantGroupsFn`. Injects the **command factory**, not a whole run-and-return-output runner: the seam replaces only which binary is exec'd, leaving the `context.WithTimeout` construction, both error classifications, and the parse loop as production code exercised by a real subprocess that the real ctx kills.
- **`OpenJSONL` body**: builds `ctx, cancel := context.WithTimeout(context.Background(), lsofProbeTimeout)`, calls `newLsofCmd(ctx, pid).Output()`, then classifies the error in this order:
  1. `ctx.Err() != nil` → wrapped timeout error (`fmt.Errorf("lsof probe timed out after %s: %w", lsofProbeTimeout, ctx.Err())`).
  2. `*exec.ExitError` with `ExitCode() == 1` → `("", nil)` (unchanged benign "no matching files"/"process gone" path).
  3. anything else → `fmt.Errorf("lsof: %w", err)` (unchanged).
- The `ctx.Err()` check is checked first even though a SIGKILL'd process can't produce exit code 1 (`ExitCode()` returns `-1` on signal kill, so it would never collide with the exit-1 branch regardless). It's kept as an explicit, deterministic guard — a clear greppable timeout error instead of a bare signal-kill wrap, and immune to any future platform quirk in the killed-process exit code. No `WaitDelay` is set — same reasoning as `descendantPGIDs`: lsof has no inheritable pipe grandchildren, so `Output()` returns promptly on kill.
- No caller change required (AC 3): the timeout error joins the existing `error` return channel that `probeWithRetry` and both resolvers already treat as transient/skip.

## Testing

`probe_darwin_test.go` gained the package's first `TestHelperProcess` re-exec fake (CODING-STYLE.md pattern) — a fake `lsof` with three modes (`sleep` 10s, `exit1`, `success` via `testdata/lsof_basic.txt`), selected by env var, `newLsofCmd` swapped to re-exec the test binary through it.

- `TestOpenJSONL_TimeoutFiresWithinBound` (AC 1) — shrinks `lsofProbeTimeout` to 100ms, points at the `sleep` fake; asserts a non-nil error wrapping `context.DeadlineExceeded` returns in well under 2s (not the fake's 10s).
- `TestOpenJSONL_Exit1IsBenign` (AC 2) — points at the `exit1` fake; asserts exactly `("", nil)`. First unit coverage of this branch (previously reachable only via a real `lsof`).
- `TestOpenJSONL_SuccessPassthrough` — points at the `success` fake; confirms the seam didn't disturb the happy path.

All three swap package-var seams non-parallel, restored via `t.Cleanup`. `go test -race ./internal/sessions/rotation/` is the gate; existing `parseLsofOutput`/`parseProcFD`/`noopProbe.Available` tests untouched.

## Lessons learned

None beyond what the spec already anticipated — implementation matched the spec's design 1:1 (seam choice, var-vs-const rationale, ctx.Err()-first ordering) with no deviations surfaced during review.
