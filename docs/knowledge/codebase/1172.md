# Ticket #1172 — realclaude stream running-turn trigger helper

Adds reusable trigger infra, plus the smoke that proves it, for holding a live
`claude` turn in `turn_state{responding}` for a bounded window under the
stream-json interactive runner. Split from the T9 (#1083) stream real-claude
coverage batch; consumed by [#1176](https://github.com/pyrycode/pyrycode/issues/1176)
(interrupt), already natively `blocked-by` this ticket. Ports the desktop
`e1fe219` (2026-07-17) fix: a silent `sleep` gets backgrounded by claude (turn
ends early) and a chatty per-iteration loop floods the frame stream (delays
`turn_state` delivery) — the working approach drives the turn with a bounded,
silent, foreground shell loop inside one Bash-tool call.

## Implementation

- `internal/e2e/realclaude/interactive_stream_running_turn_test.go` (new file,
  `//go:build e2e_realclaude`, PR [#1178](https://github.com/pyrycode/pyrycode/pull/1178)).
  Test-only, zero production files, no edits to any existing file.
- The load-bearing mechanism: the interactive turn emitter
  (`cmd/pyry/interactive_turn_v2.go`) fires `ToolStart` → `responding` the
  instant claude issues the Bash tool call (before the command runs), emits
  nothing new while the command executes (de-duped at `transitionTo`), and
  fires `TurnEnd` → `idle` exactly once at the very end of the whole turn. So
  a turn running one Bash loop of `L` seconds holds `responding` for the
  entire `L` — observing `responding` then verifying no `idle` for a window
  `hold < L` is the running-turn proof, and it fails loud (never a silent
  pass) if claude backgrounds or refuses the loop.
- `startStreamRunningTurnHarness(t) (*perConvHarness, string)` — transcribes
  `TestInteractiveStreamLiveness`'s (#1153) setup body verbatim: pair
  **without** `--allow-remote-permissions` (no answer path needed) → seed
  bootstrap registry + bound conversation → spawn via `spawnBootstrapDaemon`
  (`--dangerously-skip-permissions`, so the Bash loop runs with no permission
  modal in the way — opposite posture from the modal specs #1030/#1154) →
  handshake. Reusable seam #1176 composes, same as #1153 flagged
  `writeStreamInteractiveConfig` for #1154.
- `driveRunningTurn(t, h, reqID, convID, hold)` — computes
  `loopSeconds = (hold + runningTurnLoopSlack).Seconds()`, mints a per-run
  nonce, seals `runningTurnPrompt(loopSeconds, nonce)` via `sealSendMessage`.
- `runningTurnPrompt(loopSeconds, nonce) string` — forces one Bash call
  running `for i in $(seq 1 <loopSeconds>); do sleep 1; done` in the
  foreground ("do NOT run it in the background"), ends with "reply with a
  single short word" (guarantees a terminal turn; word never asserted),
  embeds `run=<nonce>` to defeat caching. No content/echo assertion anywhere.
- `drainForResponding(t, phone, cs, convID, timeout) time.Time` — mirrors
  `drainForTurnState` (#1153's family): decrypts every `noise_msg` in receive
  order (skips non-`noise_msg` control frames without decrypting, to keep the
  nonce in sync), returns `time.Now()` the instant `responding` for `convID`
  is observed; `t.Fatalf`s on timeout naming the likely cause (UUID mismatch
  between the two seeds hangs the drain).
- `assertNoIdleWithin(t, phone, cs, convID, since, hold)` — the smoke-only
  verifier, `drainForCompletedTurn`'s structure inverted: here `idle` before
  `since+hold` is failure, and the window elapsing with no `idle` (including
  via repeated `ErrReceiveTimeout`, since a silent loop produces no frames)
  is success.
- `TestInteractiveStreamRunningTurn` — drive turn → `drainForResponding`
  (AC1/AC3) → `assertNoIdleWithin` (AC2/AC3). `h.initRecv` threads through
  both drains sequentially so the receive nonce stays continuous.
- Constants: `runningTurnBootstrapUUID = "33333333-…"`,
  `runningTurnConvID = "44444444-…"`, `runningTurnHold = 20s`,
  `runningTurnLoopSlack = 20s`. Coupling constraint documented in-code:
  `hold + slack` must be `> hold` (no early idle) and `< 120s` (the claude
  Bash-tool default timeout) — `40s` satisfies both.

## Patterns established

- **Spec-suggested UUID literals are a starting point, not a source of
  truth — grep the package before trusting them.** The architecture spec
  suggested `runningTurnBootstrapUUID = "99999999-…"`, which already collides
  with `liveModalBootstrapUUID` in the same package/build-tag namespace. The
  developer greped every existing UUID-v4 literal in
  `internal/e2e/realclaude` and picked genuinely-unused values
  (`33333333-…`/`44444444-…`) instead. Not a compile-time hazard (each test
  owns its own tempdir `HOME`), but honoring "distinct from every existing
  literal" required enumeration, not trust. Code review confirmed this
  deviation was the correct call. Applies to any future file in this package
  that seeds its own bootstrap/conversation pair — cross-check the spec's
  suggested literal against the package before using it verbatim.
