# Ticket #1280 — Fan the reap-log attribution across every pinned process group

Adds `internal/e2e/realclaude/finding_attribution_fanout_test.go` (767 lines,
purely additive). `trailAdmitAttribution` (#1270) takes **one** held process
group; the probe's argv scan (#1230/#1235) returns a **set**, because
`pinScanArgv` deliberately refuses to resolve "the" pid. `finAttributeFanOut`
reduces that set to the single `trailAdmitResult` that `trailRunReadings.Admit`
(#1271) accepts, under a stated total order that ranks strongest evidence
first — so no group's void suppresses another group's proof, and no
composition of voids manufactures one. Offline, `e2e_realclaude` build tag, no
live claude or credentials. Split from #1277; natively blocks #1281 (the live
gather that will call this fan-out with real `pinScan.Matches`).

## Implementation

- **Two named record-level conditions, never selectable values.**
  `finAttributeGroupUnreportable` — a pinned group with `pgid <= 1`, which
  `reap.go:52` skips before it ever kills anything, so no reap line can carry
  it; handing it to `tdnClassifyReapLog` would trip that function's own guard
  and blame the instrument for a staging fault. `finAttributeNoGroups` — no
  reportable distinct group remained (nil input, or every group hit the
  condition above). Both are surfaced in `Conditions`, never written into
  `Selected` — `trailRunReadings.Admit` only accepts what `trailIsAdmitValue`
  accepts (called, not re-switched on).

- **`finAttributeFanOut(stderr []byte, pgids []int, certified string) finAttributeRecord`
  is pure**, same contract as `trailGate`/`trailAdmitAttribution`/
  `tdnClassifyReapLog`: dedupe pgids through a map then `sort.Ints` (never
  publish map range order — flaky, not deterministically red), partition
  `pgid <= 1` into `Unreportable`, classify each remaining pgid via
  `tdnClassifyReapLog` + `trailAdmitAttribution` into one `finAttributeEntry`,
  select the entry ranked highest by `finAttributeOrder`. Nothing reaching
  `Entries` is built by struct literal — the signature itself is the
  enforcement (AC1).

- **`finAttributeOrder()` is a total order over the seven admissibility
  values, proof first**, argued in the code rather than left to slice
  position: only ranks 1–3 can ever co-occur in one fan-out (budget-fired and
  out-of-contract are decided by `certified` alone and are uniform; no-line
  and instrument-failed are decided by the stderr alone; the `pgid <= 1`
  route is filtered out before classification). Below proof, `VoidNotOneReapLine`
  outranks `VoidGroupUnnamed` — reporting "unnamed" for a stderr that *did*
  name the group discards the strongest thing observed. Ranks 4–7 exist for
  totality, not a contested case (architect's open question #3 in the spec).
  A **function**, not a package-level var — matches `trailRunOutcomeValues()`
  and `trailRunWellFormed()`'s stated reason: a shared backing array is
  reachable from every test in the package.

- **The credential channel is closed by the signature, not a check.** Takes
  `pgids []int`, never `[]reachProc` — `reachProc.Command` is verbatim argv
  off the ambient process table, the channel a `ps` column would use to leak
  `CLAUDE_CODE_OAUTH_TOKEN`/`ANTHROPIC_API_KEY`. `certified string` **crosses
  verbatim** by design — it's spliced `%q` into `trailAdmitResult.Detail` on
  two arms (already-shipped, publishable behaviour) — and the fan-out
  multiplies that pre-existing exposure by the distinct-group count, each
  copy capped at 512 bytes by `reachCapCommand`. Documented rather than
  "fixed" — AC1/AC5 both mandate carrying the result whole.

- **`finAttributeEntry` carries only `PGID int` and `Admit trailAdmitResult`**
  — no `tdnReapOutcome` (its `Line` is pyry's own stderr) and no `reachProc`
  (verbatim argv). `trailAdmitResult` is documented trap-free by construction
  (#1270), which is what makes carrying it whole safe.

- **Test coverage — four top-level functions, 0 SKIP** (`go test -race -tags
  e2e_realclaude -run '^TestFinAttribute' -v`, re-verified at documentation
  time). `TestFinAttributeFanOut` is table-driven, every row run twice
  (`pgids` as given and reversed) asserting identical records — discharges
  AC2's "either input order" for all rows at once. `TestFinAttributeOrderCoversTheAdmitSpace`
  guards against an eighth admissibility value ranking silently last.
  `TestFinAttributeEmptySetAlternativesArePublishedFalsehoods` prices both
  wrong answers to the empty set (unset `Admit` → `trailOutcomeOutOfContract`
  via C3; `trailAdmitOutOfContract` → `trailOutcomeNoRowMatched` via Step 8)
  by staging `Admit` on a `trailRunReadings` directly — the *other* layer,
  not a manufactured classification, matching `trailRunProofReadings`'s
  precedent. `TestFinAttributeRecordCarriesNoCapturedBytes` plants `trailNeedle`
  on an *anchored* reap line (a non-anchored plant is vacuous — the line is
  skipped before any field fills) and asserts the marshalled record's premise
  (`Entries[0].Admit.Value == trailAdmitProof`) before checking containment,
  so a plant that stops being anchored fails loudly instead of passing
  silently. Prefix census clean: `\bfin[A-Z]` = 0 outside the new file at
  spec time, 52 (all in-file) at review time; control `\btrail[A-Z]` = 880.

## Patterns established

- **A credential/verbatim-payload channel is closed by the parameter's
  *type*, not by a runtime check.** `[]int` instead of `[]reachProc` is the
  enforcement; a `[]reachProc` signature that only read `.PGID` would pass
  every test in this file while reopening the channel. Code review should
  check the signature on any fan-out/gather that touches `pinScan.Matches`,
  not just the record it produces.
- **When a verbatim-crossing input is a documented, pre-existing, shipped
  behaviour (here, `certified` splicing `%q` into `trailAdmitResult.Detail`),
  a fan-out that multiplies its copy count is a scale change, not a new
  defect** — name it in the record's doc comment and in the no-captured-bytes
  test's doc comment (why this one input is excluded from the needle) rather
  than trying to "fix" it by breaking the whole-value-carried contract AC1/AC5
  both require.
- **`finAttributeOrder`/`finAttributeCases` as functions, not package-level
  vars**, continues #1271's precedent (`trailRunOutcomeValues`,
  `trailRunWellFormed`) for any slice a large shared-package test file reads
  every call.

## Lessons learned

From the PR body (#1283):

- **A containment needle's plant position is the whole test, and it's
  checkable rather than arguable.** Verified by mutation: planting `trailNeedle`
  on a non-anchored line *and* recording the whole `tdnReapOutcome` on an
  entry leaves `TestFinAttributeRecordCarriesNoCapturedBytes` green, because
  `tdnClassifyReapLog` skips every line not carrying `tdnReapMessage` before
  filling any field. The anchored plant plus the premise assertion
  (`Entries[0].Admit.Value == trailAdmitProof`) is what makes a de-anchored
  plant fail loudly instead of passing silently.
- **For a table row whose expected values are uniform across all groups, a
  per-group pin is redundant with the selection assertion** — a group reading
  anything stronger would outrank it and change the selection. Confirmed by
  running seven independent mutations (rank swap, comparison inversion,
  dropped sort, dropped dedupe, widened filter, filled-on-empty, whole-outcome
  recorded) against the trimmed table; all seven went red.
- **LOC came in at 767 against the spec's ~515 target (49% over)**, following
  the same package-wide inflation pattern #1270 (1028) and #1271 (1233) hit.
  The spec's cut order was followed to its floor — header at the 45-line cap,
  redundant per-row pins removed — and the remainder is content the spec
  explicitly protects (the ordering argument, the AC5 vacuity paragraph, the
  reversed-order runner half) plus the security review's mandated MAY/MAY-NEVER
  Detail prose. A rule-ticket concern for the package's `size:s` calibration,
  not a per-ticket one — same conclusion the PO already recorded for this
  chain ([[po-1254-split-point-dependent-at-the-proof]]).

## Code review

**PASS**, one SHOULD FIX deferred to #1281 (not fixed in this PR):

- **The no-captured-bytes structural check is top-level-only over a now-nested
  record.** `TestFinAttributeRecordCarriesNoCapturedBytes` decodes to
  `map[string]json.RawMessage` and scans top-level keys, following
  `trail_run_outcome_test.go`'s precedent — but that precedent's guarded type
  (`trailRunOutcome`) is flat, while `finAttributeRecord` nests `Entries
  []finAttributeEntry`. The scan sees `{entries, selected, detail}` and never
  descends into an entry's own keys, so a future `Command string` field added
  to `finAttributeEntry` (the exact "for provenance" edit AC5 names as the
  temptation) would pass this loop unnoticed. The needle-based half stays
  genuinely non-vacuous (verified: `trailAdmitProof` is reachable only if the
  needle-bearing line was read as anchored and parsed); only the structural
  half has the gap. Fix is cheap — decode `entries` into
  `[]map[string]json.RawMessage` and run the same forbidden-substring loop
  per entry. **Relevant to #1281**: that ticket is the first consumer holding
  `pinScan.Matches` and will feel the same "add Command for provenance" pull.
- Two NITs, both non-blocking: `finAttributeHasCondition` hand-rolls
  `slices.Contains` instead of calling it (the package's idiom elsewhere);
  `finAttributeOrder` ranks `VoidBudgetFired` below the reap-side voids,
  inverting that constant's own documented precedence in `trailer_admissibility_test.go` —
  safe only because the two can never co-occur in one fan-out, but the
  comment doesn't name the inversion explicitly.
