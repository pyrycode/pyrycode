# Ticket #918 — e2e default stand-in tolerates daemon-appended argv

Found 2026-07-10 by the first timed run of the fake-daemon e2e suite (the suite is in no standing
CI gate, so this had sat red since #839/PR #882 merged). #839 wired `Config.ResolveSessionID` on
every bootstrap spawn (`internal/supervisor/supervisor.go`'s `buildClaudeArgs` appends
`--session-id <uuid>`, driven from `internal/sessions/pool.go`). The e2e harness's *default*
supervised stand-in (`Start` / `StartIn` / `StartInWithEnv`'s zero-value `spawnWith` `spawnOpts`
path) invoked `/bin/sleep` directly, and both BSD and GNU `sleep(1)` reject the unknown
`--session-id` flag with a usage banner and exit — crash-looping the bootstrap child under
backoff. Three default-path tests needing the child to reach and hold `running` went red:
`TestE2E_BootstrapWarmStart_IgnoresEvictedOnDisk`, `TestE2E_IdleEviction_LazyRespawn`,
`TestRelayV2_Daemon/v2_enabled_request_snapshot_round_trip`.

## Scope note — one ticket, three mechanisms, three fixes

The original ticket claimed all 8 red e2e tests shared one root cause. Reproduction on `main`
showed they fail via **three distinct supervised stand-ins**; this ticket (#918) fixes only the
default `/bin/sleep` path (3 tests). The other two land in parallel with no file overlap:

- **#257** — `spawnAttachableDaemon` (`internal/e2e/attach_pty.go`) passes `-pyry-claude=os.Args[0]`
  (the Go test binary), which rejects `--session-id` via `flag.Parse()` before `TestHelperProcess`
  runs. 4 `TestE2E_Attach_*` tests. Different stand-in, different fix (migrate to the
  `echoClaudeScript` wrapper) — untouched by this ticket.
- **#929** — `TestRelayV2_InterruptStopsRunningTurn` uses argv-immune fakeclaude and fails
  deterministically at "turn never started" — a daemon-side #839 regression, not a stand-in issue.

## Implementation

- **Relocated `sleepClaudeScript` / `writeSleepClaude` verbatim** from `internal/e2e/cap_test.go`
  (`//go:build e2e`, introduced by #116 for `Pool.Create`-driven tests) into `internal/e2e/harness.go`
  (`//go:build e2e || e2e_install`), adjacent to `spawnOpts`/`spawnWith` which now consume them.
  Pure move — no signature change, no rename. All ~20 existing call sites (`sessions_*_test.go`,
  `auto_attach.go`, `cap_test.go` itself) resolve to the same package symbol, zero edits needed.
  `cap_test.go` drops its now-unused `path/filepath` import.
- **One default-value swap** in `spawnWith`: `o.claudeBin = writeSleepClaude(t, home)` replaces the
  literal `"/bin/sleep"`. `claudeArgs`'s `{"99999"}` default is unchanged — the wrapper
  (`#!/bin/sh` + `exec sleep 99999`) ignores all positional args identically, whether that's the
  bootstrap invocation's trailing `99999` or a daemon-appended `--session-id <uuid>`.
- Updated doc comments on `Start`, `spawnOpts`, and `spawnWith` in `harness.go` to describe the
  wrapper instead of a bare `/bin/sleep`.
- Full design/no-regression rationale (idempotent double-write for extraFlag-based
  `-pyry-claude=` overrides, `StartExpectingFailureIn`'s wrapper-written-but-never-run path) is
  written up in [`features/e2e-harness.md` § Default Stand-In Argv Tolerance](../features/e2e-harness-default-stand-in-argv-tolerance.md#default-stand-in-argv-tolerance-918),
  which is the evergreen home for this pattern going forward.

## Lessons learned

- **The spec's suggested build-tag verification was itself unachievable, and pre-dates this
  ticket.** `go build -tags e2e_install ./internal/e2e/...` (pure `e2e_install`, no `e2e`) still
  fails with `undefined: safeBuffer` — `harness.go` (`e2e || e2e_install`) already referenced
  `safeBuffer`, defined only in `auto_attach.go` (`//go:build e2e`), before this ticket touched
  anything. The install tests are opt-in (no CI/Makefile target) and are always built with **both**
  tags together; the meaningful compile check is `go build -tags "e2e e2e_install"
  ./internal/e2e/...`, not pure `e2e_install`. The fixture relocation is still the right call: it
  avoids introducing a *second* cross-tag undefined symbol, and co-locates the fixture with its
  new consumer (`spawnWith`).
- **The e2e suite's lack of a standing CI gate let four independent #839-era regressions
  accumulate silently**: this ticket's 3, #257's 4, #929's 1, and a **9th red test found during this
  ticket's verification pass** — `TestTwoPhoneStructured_InteractiveReceivesStream`
  (`StartRotationWithRelay` sets `claudeBin` directly, bypassing the default-stand-in path
  entirely; fails identically on `main`, so not a regression from this PR). Filed as **#930**,
  left red, not fixed here — same daemon-side #839 producer-regression shape as #929, likely a
  sibling. A standing `-tags e2e` CI job would have caught all of these at merge time instead of
  a manual sweep discovering them nine tickets later.
- This invalidates the pre-#839 note at `docs/lessons.md` #116 ("Bootstrap-only e2e tests don't
  hit this appended-flag problem") — #839 made the bootstrap path append `--session-id` too, not
  just `Pool.Create`'s new-session path. `lessons.md` is frozen (2026-05-11); the correction lives
  here and in `features/e2e-harness.md` instead of being appended there.
