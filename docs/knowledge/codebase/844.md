# Ticket #844 — v2 wire vocabulary for the set-session-settings verb + reply

Split from #841 (itself split from #834/#826). Adds the v2-only
`TypeSetSessionSettings` (phone → binary control) and
`TypeSessionSettingsUpdated` (binary → phone reply) envelope types, their
payload structs, and a `session.not_found` error code — wire vocabulary only.
No handler, `dispatchAppFrame` case, or persistence call: those land in sibling
#845, which decodes into `sessions.Pool.UpdateSettings` (#840).

## Implementation

## The presence contract (the reason this earned its own ticket)

The request's three settings fields (`model`, `effort`, `yolo`) are pointers
with `omitempty` — the opposite of the sibling `*string`-without-`omitempty`
payloads (`BackfillSincePayload`, `SessionTransitionPayload`), which encode a
literal `null` sentinel on the wire. Here an **absent** key means "leave
unchanged" and a **present** key — including at its zero value (`""`,
`false`) — means "set to this value":

| Field state | Wire | Decodes to |
|---|---|---|
| `nil` | key absent | `nil` — leave unchanged |
| non-nil `*""` / `*false` | key present, zero value | non-nil pointer to zero — explicitly set |

An absent `yolo` can therefore never be read as a sent `false`, and an absent
`model` can never be read as an instruction to clear a stored value. This
mirrors `sessions.SettingsUpdate{Model, Effort *string; YOLO *bool}` (#840)
field-for-field so the #845 handler decodes 1:1. The struct doc comment in
`settings.go` calls out the divergence from the sibling payloads explicitly,
so a future contributor doesn't "fix" it by copying their no-`omitempty`
style.

## Not security-sensitive (by design)

Per the wire-vocab → handler split precedent (#701→#703, #720→#723,
#812→#813, #656→#657), this leaf earns `security-sensitive` only if it
defines a security primitive (a nonce, token, or capability gate). It defines
none — `yolo` is a shape, not a gate. The YOLO fail-safe (nil = never enables
bypass) lives in `sessions.SettingsUpdate` (#840, already shipped); the
capability gate, validation, and persistence are handler sibling #845, which
carries the label.

## Lessons learned

- The `omitempty`-over-pointer shape is a deliberate *inversion* of the
  existing `*string`-without-`omitempty` precedent in the same package
  (`BackfillSincePayload`, `SessionTransitionPayload`). Both are valid wire
  shapes for different intents (absent-vs-set vs absent-vs-null-sentinel);
  the byte-equal round-trip on the fully-omitted fixture is what actually
  catches a regression if someone "harmonizes" the two styles later.
