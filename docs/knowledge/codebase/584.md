# Ticket #584 — Fix flaky `TestFakeClaude_OpensInitialAndRotatesOnTrigger` (trigger-removal races rotated-JSONL creation)

`TestFakeClaude_OpensInitialAndRotatesOnTrigger`
(`internal/e2e/internal/fakeclaude/main_test.go`) passed in isolation but flaked
under the full parallel `-tags e2e` load with `trigger file still present after
rotation: err=<nil>`. The test broke its poll loop the instant the rotated
`<uuid>.jsonl` appeared, then single-shot asserted the trigger was gone — but
fakeclaude **opens the rotated file before removing the trigger** (the `main.go`
rotation block), so between `openSession` and `os.Remove(trig)` there is a window
where the rotated JSONL exists and the trigger does not yet. The test's implicit
*"rotated JSONL observed ⇒ trigger already consumed"* was a false happens-before
assumption, and the assertion raced. **Test-only fix (Option 2)**: fold the
trigger-gone check into the poll loop's break condition. Zero production change,
so the close-OLD-before-open-NEW invariant (AC-3) is untouched.

Spec: [`docs/specs/architecture/584-fakeclaude-rotation-trigger-flake.md`](../../specs/architecture/584-fakeclaude-rotation-trigger-flake.md).
Feature doc updated: [`features/fakeclaude-binary.md`](../features/fakeclaude-binary.md) (§ *Verification* — the poll now waits for both post-conditions).

## Implementation

One file, `main_test.go`, a ~20-line restructure of the existing poll loop (no
new helper, no new timeout constant, no production `main.go` change):

- **Guard the directory scan with `if rotatedUUID == ""`** so it runs only until
  the rotated stem is found — the file persists, no need to re-scan it every
  cycle. The scan body itself is unchanged (skip non-`.jsonl`, skip `initialUUID`,
  require the `uuidStem` regexp match).
- **Break only when both post-conditions hold:**

  ```go
  if _, err := os.Stat(triggerPath); rotatedUUID != "" && os.IsNotExist(err) {
      break
  }
  ```

  i.e. the rotated JSONL is observable **and** the trigger has been removed. The
  50 ms cadence and the shared 3-second `deadline` (which already bounds both the
  "rotation happened" and "trigger removed" waits) are unchanged.
- **The two post-loop fatals stay verbatim** as timeout diagnostics:
  - `if rotatedUUID == "" { … "no rotated JSONL appeared …" }` — still fires when
    rotation never happens.
  - `if _, err := os.Stat(triggerPath); !os.IsNotExist(err) { … "trigger file
    still present after rotation" … }` — now fires only on **timeout** with the
    rotated JSONL present but the trigger never removed, which is a genuine
    fakeclaude regression, not the pre-existing race. AC-1's real-regression
    signal is preserved.

Chosen over Option 1 (reorder fakeclaude's rotation to remove-before-open) on the
architect's call: Option 1 would impose a *new* incidental "remove-before-open"
contract on the production double that a future `main.go` poll-loop refactor could
silently re-break, re-introducing this exact flake. Option 2 has zero production
surface and is robust to *any* ordering.

Verified green: `go test -tags e2e -count=10 -run
TestFakeClaude_OpensInitialAndRotatesOnTrigger ./internal/e2e/internal/fakeclaude/`
(and the developer's `-race -count=20` per the spec). No code-review rework — the
change landed clean.

## Patterns established

- **Observe a cross-process test double by its post-conditions, not by the
  internal ordering of its steps.** A black-box double like fakeclaude only
  contracts its *end state* (rotated JSONL present, trigger consumed) and the one
  documented internal invariant (close-OLD-before-open-NEW). A test that breaks
  its wait on a *partial* observable and then asserts the rest is single-shot
  races whatever side effect the double does last. Fold the full post-condition
  into the break gate; let the post-loop assertion degrade to a pure timeout
  diagnostic.
- **Prefer the test-only fix when the bug is a false assumption in the test.**
  The root cause was the test's ordering assumption, not a defect in the double.
  Fixing the double (reorder) would trade a test-local change for a new
  cross-process contract — larger surface, and a fresh way to reintroduce the
  same flake later. Smaller, ordering-agnostic surface wins (Simplicity First).

## Lessons learned

- **"Downstream observable appeared ⇒ upstream side effect already happened" is a
  happens-before assumption you must verify against the producer's actual
  ordering.** fakeclaude opens the rotated JSONL *before* removing the trigger, so
  observing the JSONL guarantees nothing about the trigger. The double never
  promised that ordering — only close-OLD-before-open-NEW.
- **A single-shot assertion immediately after a poll-loop `break` races any
  side effect the producer performs after the observable the loop broke on.** If
  the assertion is really a post-condition, put it *in* the break gate and keep
  the standalone check only as the timeout diagnostic.
- This flake was surfaced during #581's `WaitBinary` readiness-migration
  validation (filed separately per scope discipline) and independently observed
  out-of-scope on [#593](593.md); it is `e2e`-tagged (not in the `make check`
  gate), which is why it survived until now. Both prior notes flagged it for a
  future reader — now closed.
