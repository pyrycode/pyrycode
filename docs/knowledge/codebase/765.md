# Ticket #765 — held/deferred inbound-response primitive in the ACP transport

The transport as built ([#755](755.md)) dispatches every inbound request **inline
on the single read-loop goroutine** and writes the response the instant the
handler returns — `Handler` is `func(ctx, params) (any, error)`, with no way to
say "not yet." Epic [#600](https://github.com/pyrycode/pyrycode/issues/600)'s
`session/prompt` needs exactly that: an ACP turn is one `session/prompt` request
that streams notifications and then returns a `stopReason`, so the adapter must
**hold the in-flight call open for the whole turn and resolve it later — from the
outbound event goroutine, not the read loop.** Blocking the handler stalls the
read loop for the entire turn (no second prompt or `session/cancel` can be read);
returning resolves immediately. Neither holds.

This ticket adds the missing capability: an inbound handler can **defer** its
response, and any goroutine can **resolve** it later through the transport's
existing serialized write path. Pure transport plumbing — **no session
semantics, no host content interpreted.** Consumed by #749 (the `session/prompt`
handler, which defers and stashes the responder) and T7 [#751](https://github.com/pyrycode/pyrycode/issues/751)
(which resolves it with the `stopReason` on `TurnEnd`); neither can be built
without it.

Split from #749, sub-issue of #600. **Not security-sensitive** — it changes
*when* a response is written, not *what* method is dispatched or *how* untrusted
content is handled; no host content is parsed and no routing/gate decision is made
on untrusted input. The host-content delivery boundary lives entirely in the
consumer (#749, which carries `security-sensitive`). Spec:
[`specs/architecture/765-acp-held-inbound-response.md`](../../specs/architecture/765-acp-held-inbound-response.md).

## Implementation

**1 new production file (`internal/acp/responder.go`, 89 lines), 1 edit to
`internal/acp/acp.go` (`dispatchRequest`, ~10 lines), 1 new exported type
(`Responder`).** One package, no cross-package coordination — `Handler`,
`Register`, and every existing handler/test stay byte-identical.

### Decision: context-injected responder + `ErrDeferred` sentinel — `Handler` unchanged

The handler needs a handle (the request id + a way to write through `writeMu`) to
resolve later, and only the transport can mint it. Two ways to hand it over:

1. **Change the `Handler` signature** to `func(ctx, params, *Responder) (any, error)`.
   **Rejected** — fans out to the 3 merged handlers in `cmd/pyry/acp.go`
   (`session/new`, `session/load`, `session/cancel`) plus ~15 inline test handlers
   (~18 sites, all forced to accept a param they ignore), and makes a one-concept
   change touch two packages.
2. **Inject the responder via `context.Context`** (request-scoped values are the
   idiomatic use of `context`, per `net/http`) and signal defer with a sentinel
   error. **Chosen** — fully additive; only the one method that needs deferral
   opts in.

### New surface (`responder.go`)

```go
var ErrDeferred = errors.New("acp: response deferred")          // handler → dispatchRequest: don't write now
var ErrAlreadyResolved = errors.New("acp: response already resolved") // 2nd resolve → returned, never a 2nd frame

type Responder struct { /* t *Transport; id json.RawMessage (owned copy); done atomic.Bool */ }
func (r *Responder) Reply(result any) error    // success frame; guarded → ErrAlreadyResolved on 2nd call
func (r *Responder) ReplyError(e *Error) error // error frame; guarded; nil e → generic internal error

func ResponderFrom(ctx context.Context) *Responder // the injected responder, or nil (notification / non-dispatch ctx)
```

- **`Reply`** — `done.CompareAndSwap(false, true)` gate; on win, `t.writeSuccess(r.id, result)`
  (which already falls back to an internal-error frame on a marshal bug — still one
  frame); on loss, return `ErrAlreadyResolved` and write nothing.
- **`ReplyError`** — same gate; on win, `t.writeErrorWithData(r.id, e.Code, e.Message, e.Data)`.
  `e == nil` is a consumer bug: resolves as `CodeInternalError`/"internal error"
  rather than deref-panicking (preserves never-panic + exactly-one-frame).
- **`ResponderFrom`** — unexported zero-size context key (`type responderKey struct{}`),
  type-asserted to `*Responder`, nil on miss. Consumers nil-check before stashing.

### `dispatchRequest` change — single answer-authority per id

`dispatchRequest` now builds **one `*Responder` per request** and routes **its own
synchronous success/error path through that responder too** — not through
`writeSuccess`/`writeError` directly. The responder's once-guard therefore becomes
the **single authority** that answers a given id: the sync path, the deferred
path, and any accidental mix all funnel through one guarded resolve, so **"exactly
one frame per id" is a structural invariant, not a matter of handler discipline.**
Existing wire output is unchanged — the responder's methods call the same
`writeSuccess`/`writeErrorWithData`.

The classifier and signature are untouched. After looking up the handler, it
builds `resp`, injects it into ctx, dispatches, then branches on the sentinel:

```
resp := &Responder{t: t, id: append(json.RawMessage(nil), msg.ID...)}
ctx = context.WithValue(ctx, responderKey{}, resp)
result, err := h(ctx, msg.Params)
switch {
case errors.Is(err, ErrDeferred): return          // handler owns resp; write nothing, scan next frame
case err != nil:                                    // *Error → resp.ReplyError(rpcErr); else log + resp.ReplyError(internal)
default:            resp.Reply(result)
}
```

The method-not-found early return (`writeError` before a handler exists) stays
as-is — no responder is built when there is no handler.

### id-copy rule (correctness pin)

The responder holds the id until a resolve that may happen **many `Scan`s later**,
long after `dispatchRequest` returns. `scanner.Bytes()` is valid only until the
next `Scan`, so the responder captures an **owned copy** of the id bytes —
`append(json.RawMessage(nil), msg.ID...)` — never aliasing `msg.ID`. The copy is
unconditional (both paths share one construction); the sync path is unaffected
because it resolves before the next `Scan`. `msg.ID` is guaranteed non-nil here
(the request-vs-notification classifier gate), so the copied id is always real and
`idOrNull` echoes it verbatim.

## Concurrency model

- **No new goroutines.** The primitive adds cross-goroutine *state* (a responder
  resolved off the read loop), not new goroutines.
- **Resolve-once** via `Responder.done atomic.Bool` `CompareAndSwap(false, true)`.
  Two goroutines racing to resolve the same id: exactly one wins and writes; the
  loser gets `ErrAlreadyResolved`. No mutex.
- **Write serialization** rides the existing `writeMu`: every resolve goes through
  `writeSuccess`/`writeErrorWithData` → `reply` → `writeMessage`. A resolve racing
  the read loop's own dispatch write is serialized there — the invariant `writeMu`
  already guarantees (load-bearing since [#757](757.md)). **No new lock, no second
  write path.**
- **Leaf-lock discipline preserved.** The `done` CAS is not held across the write;
  `writeMu` is taken *inside* `writeMessage` after the CAS returns. No lock
  ordering introduced.
- **Read-loop liveness — the core behavioral fix.** A deferring handler returns
  promptly (after stashing `resp`), so `dispatchRequest` returns and `Serve`
  proceeds to the next `Scan`. Holding a request open no longer blocks
  classification/dispatch of later frames.

## Edge cases

- **Double-resolve** → the second `Reply`/`ReplyError` loses the CAS → returns
  `ErrAlreadyResolved`, writes no frame.
- **Resolve-after-teardown** (resolve after `Serve` returned / reader EOF'd) →
  **no dedicated teardown state.** The `Transport` and `writeMu` outlive `Serve`;
  `writeMessage` → `enc.Encode` on a dead writer returns an error that `reply`
  logs at Warn ("write frame failed") and drops. With the once-guard, a
  post-teardown resolve is at most one *attempted* frame that fails silently —
  never a panic, never a second frame. Per **Evidence-Based Fix Selection**, no
  speculative `closed` flag was added for this unobserved failure; the existing
  write path already tolerates a dead writer.
- **`ReplyError(nil)`** → generic internal error (consumer bug; never deref-panic).
- **`ErrDeferred` returned but `resp` never stashed** → the request hangs (no
  frame ever). This is a **consumer contract** (#749's concern), not the
  primitive's to police — the sentinel means "I have taken ownership and will
  resolve."

## Patterns established

- **A per-id single answer-authority makes "exactly one frame" structural.** By
  routing even the synchronous success/error path through the same `*Responder`
  that a deferred resolve uses, the once-guard — not handler discipline — enforces
  one-frame-per-id across the sync path, the deferred path, and any accidental
  mix. The sync wire output is byte-identical because the responder calls the same
  `writeSuccess`/`writeErrorWithData`.
- **Hand a request-scoped handle to a handler via `context`, not the signature.**
  A sentinel-error opt-in (`ErrDeferred`) + a `ctx`-injected `*Responder` keeps
  `Handler` byte-identical, so a new capability costs zero fan-out to the 3 merged
  handlers + ~15 test handlers. Only the method that needs it opts in. Mirrors
  `net/http`'s request-scoped-value idiom.
- **Copy the id when a resolve may outlive the scanner buffer.** A held handle
  that resolves many `Scan`s later must own its id bytes (`append(json.RawMessage(nil), msg.ID...)`);
  aliasing `scanner.Bytes()` would echo a corrupted/next-frame id. Reuses the same
  scanner-buffer-lifetime reasoning [#757](757.md) applied to routed responses,
  now for the outbound-held direction.
- **Don't add a teardown flag for a write path that already tolerates a dead
  writer.** The once-guard + `writeMessage`'s log-and-drop on `enc.Encode` failure
  already give "no panic, no second frame" after `Serve` exits; a speculative
  `closed` state would be belt with no observed failure to defend.

primitive.)

## Testing

New `internal/acp/responder_test.go` (5 scenarios) + two harness additions to
`internal/acp/acp_test.go`. Same-package, stdlib `testing` only, `t.Parallel()`,
`-race`-clean.

- **Harness:** `newLiveTransportReg(t, reg)` — `newLiveTransport` with a
  registration hook run before `Serve` starts (inbound-handler tests need handlers
  registered on the live transport; `Register` panics after `Serve`). `nextResponse()`
  reads one frame off the writer and decodes it as a generic map, asserting the
  `jsonrpc:"2.0"` envelope — the deferred tests read a resolve written *off* the
  read loop.
- `TestResponder_DeferSuppressesSyncFrame` — single-shot `run`; a handler that
  stashes `ResponderFrom(ctx)` and returns `ErrDeferred` emits **no** synchronous
  frame (Serve runs to EOF, never resolved), and `ResponderFrom` returned non-nil.
- `TestResponder_ResolveLaterWritesOneFrame` — `liveTransport`; resolve from the
  **test goroutine** (≠ read loop). `Reply` echoes the id + result; `ReplyError`
  echoes the id + code. Exactly one correct frame each.
- `TestResponder_ReadLoopAliveWhileHeld` — request #1 (`hold`, deferred) then #2
  (`quick`, sync): **#2's response is written before #1 is resolved**, proving the
  read loop kept classifying/dispatching while a request was held. Then #1
  resolves and its frame reads back.
- `TestResponder_DoubleResolveWritesOneFrame` — after one resolve, a second
  `Reply` **and** a `ReplyError` both return `ErrAlreadyResolved`; a sentinel
  request (`id:99`) is fed and its response is the very next frame — proving the
  double-resolves wrote nothing.
- `TestResponder_ResolveAfterTeardownSafe` — a `deadWriter` (fails once `dead` is
  set) driven synchronously via `run`; after `Serve` returns to EOF, flip the
  writer dead and resolve. No panic; the write failure is logged ("write frame
  failed") and dropped; no second-frame path exists.
- **`-race` coverage** comes from the `liveTransport` scenarios (concurrent
  resolve vs. read-loop dispatch/writes) under the package's existing `-race`
  gate; the read-loop-alive test is the explicit concurrent-write case.

## Out of scope (deferred)

- **The `session/prompt` handler** that defers and stashes the responder,
  per-session in-flight guard, content mapping, delivery/security boundary — #749
  (`security-sensitive`).
- **Resolving the held call with the turn's `stopReason`** on `TurnEnd` from the
  outbound event goroutine — T7 [#751](https://github.com/pyrycode/pyrycode/issues/751).
- **Serve-exit teardown signalling** — no `closed` flag; a post-teardown resolve
  is a silently-dropped best-effort write. Additive if an observed failure ever
  demands it.
