# Ticket #904 — e2e: a non-empty backlog missed while disconnected is reconciled as `queue_state` exactly once on reconnect

The **queue half of #829**'s end-to-end acceptance slice (ADR 025 → "Backpressure /
replay"), the twin of the modal half ([#903](903.md)). #829 itself is closed,
superseded by this split. Test-only — no production change — one new file,
`internal/e2e/relay_v2_queue_reconnect_test.go` (`//go:build e2e`), proving the
cross-layer contract #878's unit tests couldn't: a real fake client, disconnected
then reconnected over a fresh Noise handshake, sees a non-empty message backlog
reconciled as a `queue_state` snapshot exactly once, reflecting current backlog
truth, with a genuinely driven second reconnect observed re-sending the identical
snapshot idempotently.

## Implementation

One test file, structurally mirroring #903's shape but namespaced queue-specific
throughout (`reconnectQueueHarness`, `queuePhoneSession`,
`openInteractiveQueuePhone`, `assertQueueStateFor`, `knownQueueConvID`,
`queueMsg{1,2}Marker`) — the deliberate-duplication house pattern, applied this
time to avoid a **real** symbol collision: #903 was unmerged when #904's spec was
written but landed first in practice (PR #906, merged before #904's PR #907 opened),
so this file compiles standalone against #903's generic `phoneSession` /
`openInteractivePhone` with zero renaming needed after the fact.

- **`bringUpReconnectQueueHarness`** — mirrors `relay_v2_queue_drain_test.go`'s
  bootstrap (pair **without** `--allow-remote-permissions` — no answer path here,
  only `send_message` enqueue + `queue_state` observation — `seedBoundConversation`,
  sessions-dir alignment, pre-created `<initialUUID>.jsonl`), but starts a fakeclaude
  **busy** via `PYRY_FAKE_CLAUDE_IDLE_TRIGGER` pointing at a trigger file the test
  never creates. Claude comes up busy (`WaitReady` blocks) and stays busy for the
  whole run, freezing the backlog across every disconnect/reconnect — no drain, no
  drain-order oracle needed. Deliberately stops short of dialing a phone.
- **`openInteractiveQueuePhone`** — dial + `driveHandshakeToOpenDaemonInteractive` +
  the frozen `sealSend`/`nextEnv` closures, copied verbatim from
  `relay_v2_queue_drain_test.go`. A reconnect is
  `old.phone.Close(); ps := openInteractiveQueuePhone(t, h, "phone-a")` with the
  **same** token — same device identity, brand-new `conn_id` + fresh Noise
  `CipherState`s, exactly the fresh-attach path `reconcileQueues` (#878) fires on.
- **`assertQueueStateFor(t, ps, wantTexts)`** — drains under a 20s deadline until a
  `queue_state` for `knownQueueConvID` with the expected FIFO backlog arrives,
  skipping the #722 on-change producer's intermediate partial (single/double)
  snapshots; `t.Fatal`s on deadline or an intervening `TypeError`. Returns the
  decoded payload so the caller can capture the daemon-minted `queued_msg_id`s
  rather than guess them.
- **`assertNoSecondQueueState(t, ps, within)`** — bounded drain that `t.Fatal`s on a
  second `queue_state` or any `TypeError`; a clean timeout is the pass.
- **`TestRelayV2_QueueReconcileOnReconnect`** — seven-step flow, each step a hard
  precondition of the next (assertion order load-bearing): (1) phone #1 connects,
  sends two `send_message` envelopes while claude is busy — both enqueue and stay
  queued; (2) `original := assertQueueStateFor(ps1, want)` — the populate fence and
  the source of the true `queued_msg_id`s; (3) `ps1.phone.Close()` — disconnect,
  backlog unchanged (claude still busy); (4) `ps2 := openInteractiveQueuePhone(...)`
  — fresh attach, same token; (5) `assertQueueStateFor(ps2, want)` asserts the
  reconciled snapshot carries the *same* `queued_msg_id`s as `original` (not a
  re-mint), then `assertNoSecondQueueState(ps2, 3s)` proves exactly-once (AC1); (6)
  `ps2.phone.Close()`, reconnect again as `ps3`, assert `again.Queued` equals
  `original.Queued` element-for-element by id + text + order (AC2 idempotency), same
  bounded no-second drain; (7) optional never-drained fence — `stdinLog` stays
  empty/absent for the whole run, confirming the backlog was genuinely held, not
  partially drained.

## Patterns established

- **AC1's "both reconnect modes" collapses to one daemon-observable path — a design
  fact, not a coverage gap.** Identical reasoning to #903: `reconcileQueues` is
  grace-agnostic (fires on every fresh interactive handshake), and `fakerelay` has no
  30s grace and mints a fresh `conn_id` per upgrade, so `Close` + fresh `Dial` is
  inherently the single fresh-attach path. The literal "within grace / same session"
  mode is #874/#875's *surviving*-conn hold/flush, unreachable by this harness and
  owned by those tickets. Documented in the file's header comment rather than faked
  as a cosmetic subtest.
- **Isolation via strict happens-after, not a mechanism stub** (same doctrine as
  #903). Phone #2/#3 dial strictly *after* the last backlog change (the enqueues on
  phone #1's watch), so the #722 on-change producer — which broadcasts only to conns
  open at change time — structurally cannot have reached them. `reconcileQueues` is
  provably the *sole* delivery path; a green assertion proves reconcile, not an
  accidental re-broadcast. Code review's non-vacuity check (stubbing
  `reconcileQueues`'s call site) confirmed this split exactly: phone #1's fence still
  passed (on-change broadcast), phone #2 failed at the deadline (no reconcile).
- **A busy-hold, not a drain-and-refill, freezes the backlog.** Where #903's modal
  twin has no drain concept at all, #904's queue domain does (#722 pops on
  `WaitReady`), so the harness needed an explicit freeze: point
  `PYRY_FAKE_CLAUDE_IDLE_TRIGGER` at a file and never create it. This is the one
  structural harness difference from the modal twin, driven by the domain (a queue
  can drain; a modal cannot partially resolve itself).
- **Symbol-collision avoidance paid off exactly as anticipated.** #903 named this as
  an anticipated reuse ("#904 can lift `openInteractivePhone` verbatim") but this
  ticket's spec (written before #903 merged) chose full namespacing instead
  (`queuePhoneSession` etc.) to guarantee standalone compilation regardless of merge
  order. Code review confirmed zero collision against the now-merged #903 file. Filed
  in the PR's own lessons-learned; worth keeping as the going-forward rule for any
  third reconcile-domain e2e twin: namespace file-locally, don't assume a shared
  helper will land first.

## Security review

Not `security-sensitive` — correctness / no-data-loss proof, not a security-property
test. The queued `text` is untrusted content but is never logged by the test or the
production path it exercises (#878 already carries that posture); the
security-*property* half of the #829 split is the modal twin, #903. Architect
self-review: no nonce/auth/untrusted-input invariant is being certified here that
`security-sensitive` labeling would protect — reconcile idempotency and no-data-loss
are correctness properties, confirmed independently by code review's non-vacuity
stub-and-observe check rather than by an adversarial security pass.

## Testing

`go test -tags e2e -race -run TestRelayV2_QueueReconcileOnReconnect ./internal/e2e/`
— PASS, ~9s. Non-vacuity verified by code review: temporarily commenting out the
`reconcileQueues(ctx, s)` call site (`internal/relay/v2session.go:1461`) made phone
#1's populate fence still pass (via the #722 on-change broadcast) while phone #2's
reconcile assertion failed at the 20s deadline — proving the test's green result
depends on the actual reconcile producer, not an accidental broadcast, and confirming
the documented isolation-fence reasoning. `go vet -tags e2e ./internal/e2e/...`
clean; `go build ./cmd/pyry` OK. Full `go test -race ./...` green except the
pre-existing `#905` `internal/msgqueue` deadlock
(`TestQueue_SnapshotAll_RaceWithEnqueueAndDrain`), confirmed environmental (no
import, untouched path, passes isolated) — not routed to rework. Real-claude e2e
(`make e2e-realclaude`) green.

## Lessons learned

- **A spec written against an unmerged sibling should still hedge on naming, not just
  document the collision risk.** The #904 spec (written while #903 was still on a
  feature branch) instructed copying #903's generic `phoneSession` /
  `openInteractivePhone` "verbatim." The developer instead fully namespaced every
  symbol (`queuePhoneSession`, `openInteractiveQueuePhone`, `reconnectQueueHarness`)
  precisely because merge order between two siblings targeting the same package
  isn't guaranteed at spec-writing time. This turned out correct: #903 merged first
  (PR #906 before #907), and the namespacing meant zero post-merge fixup was needed.
  Generalizes: when two same-package e2e siblings are speced concurrently, prefer
  file-local namespacing over "copy verbatim" even if the spec says otherwise.
