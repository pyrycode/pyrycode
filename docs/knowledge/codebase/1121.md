# #1121 — Route interrupt to the active conversation's bound runner

**Size:** S. Security-sensitive (cross-conversation isolation). 5 files touched (`cmd/pyry/main.go`,
`cmd/pyry/relay.go`, `cmd/pyry/streamsup_runner.go`, `internal/sessions/session.go`, + a new
`cmd/pyry/interrupt_routing_test.go`), 0 new files besides the test. `internal/relay` itself is
untouched. Blocked-by #1120 (merged), split from #1099 (itself split from #1078).

## What shipped

Fixes a latent mis-routing bug: the inbound `interrupt` control frame (`internal/relay`'s
`Interrupter.SendEsc()`, `handleInterrupt`) was wired to the **bootstrap** supervisor
(`Interrupter: w.sup`), while turns route to per-conversation bound runners since #678. An
interrupt therefore actuated the idle bootstrap child, not the runner running the active
conversation's turn — both a functional bug and a cross-conversation isolation gap.

Four new/changed pieces, all in `cmd/pyry` (+ one accessor in `internal/sessions`):

- **`Session.Runner() sessions.Runner`** (`internal/sessions/session.go`) — returns `s.sup`
  unchanged, but as the `Runner` interface rather than the concrete `*supervisor.Supervisor`
  `Supervisor()` returns (which is `nil` for a stream-json runner). Total for both runner types.
- **`streamRunner.Interrupt() error`** (`cmd/pyry/streamsup_runner.go`) — forwards to
  `(*streamsup.Runner).Interrupt()` (#1120). A concrete method off the `sessions.Runner` interface
  (which stays un-widened, #1077) — reached by type assertion, exactly as `SendEsc` is reached for
  the PTY runner.
- **`interruptRunner(r sessions.Runner) error`** (`cmd/pyry/main.go`) — the SendEsc-vs-Interrupt
  type dispatch. Type-switches on `interface{ Interrupt() error }` (stream-json, matched first)
  then `interface{ SendEsc() error }` (PTY); an unknown runner is inert (`nil`, no actuation). Lives
  in `cmd/pyry` specifically because `streamRunner` — the streamsup→`sessions.Runner` adapter — lives
  there; `internal/sessions` cannot see it, so this dispatch structurally cannot live lower.
- **`resolveBoundRunner(convReg, pool, convID) (sessions.Runner, bool)`** (`cmd/pyry/main.go`) — the
  security-critical resolution: `convReg.Get(convID)` → `conv.CurrentSessionID == "" → (nil, false)`
  (the **load-bearing guard**, copied in intent from `sessionRouter.resolve`: `Pool.Lookup("")`
  returns the *bootstrap* session, so without this guard an unbound conversation's interrupt would
  fall through to shared bootstrap claude) → `pool.Lookup` → `sess.Runner()`.
- **`activeInterrupter`** (`cmd/pyry/main.go`) — the `relay.Interrupter` adapter. Two injected seams
  (`currentConv func() string`, `resolveRunner func(string) (sessions.Runner, bool)`) rather than raw
  `*Pool`/`*Registry`, so the composition test can drive it with fakes. `SendEsc()` — the seam keeps
  this name; see below — reads `currentConv()`, resolves via `resolveRunner`, and calls
  `interruptRunner`; every ambiguous state (`""` active conv, unresolvable binding) is inert.

`cmd/pyry/relay.go`: one field added to `relayWiring` (`activeInterrupter relay.Interrupter`), one
wiring line flipped (`Interrupter: w.sup` → `Interrupter: w.activeInterrupter`). Nothing in
`internal/relay` changed.

## The seam decision

The two runner types interrupt through differently-named methods (`SendEsc` on
`*supervisor.Supervisor`, `Interrupt` on `streamRunner`), and only `cmd/pyry` sees both concretes.
Widening `sessions.Runner` was rejected (forbidden by #1077's "speculative surface" doc comment, and
impossible anyway — the two concretes don't share a method name). Renaming the relay seam
`Interrupter.SendEsc()` → `.Interrupt()` for honesty was also rejected: it would touch
`internal/relay/v2session_seams.go` + `v2session_modal.go` + the `fakeInterrupter` fixture (crossing
the ≥5-file scope gate) and rewrite the existing interrupt regression tests. Deferred — the relay
`Interrupter` doc already abstracts `SendEsc` as "claude's own interrupt," so keeping the name held
the change to 4 production files and left all of `internal/relay`, including its interrupt tests, as
an untouched regression guard.

## Patterns established

- **Reach a runner-type-specific method by type assertion from the one package that can see both
  concretes, rather than widening a narrow shared interface.** Mirrors the #1077 `Session()` /
  `Supervisor()` split: keep the interface minimal, add a same-shaped accessor (`Runner()`) that
  returns the interface (not the concrete), and let the consumer that already imports both concrete
  adapter types do the type-switch. Reach for this again for any future runner-type-specific
  capability that can't be uniformly named across PTY and stream-json runners.
- **Copy a load-bearing empty-id guard verbatim in intent, not by refactoring the original into a
  shared helper.** `resolveBoundRunner`'s `CurrentSessionID == ""` check duplicates
  `sessionRouter.resolve`'s guard rather than extracting it — deterministic, independently testable,
  no cross-package coupling for a 2-line check. Belt-and-suspenders is different fabric: the guard is
  code, not a stochastic rule, and this is the second independent guard against the same
  `Pool.Lookup("")`-returns-bootstrap trap (`errNoBoundSession` being the first).
- **Inject the two seams a routing adapter needs (`currentConv`, `resolveRunner`) instead of the raw
  registries**, so the composition (adapter wiring + fail-safe branches) is unit-testable with fakes
  independent of a real `*conversations.Registry` / `*sessions.Pool`. The resolution *guard* itself
  still gets its own test against the real types (`TestResolveBoundRunner`), since that's the layer
  fakes can't validate.

## Lessons learned

- No lessons flagged in the PR body beyond what the spec already anticipated — the isolation guard,
  the seam-naming tradeoff, and the type-dispatch shape all landed as designed.
