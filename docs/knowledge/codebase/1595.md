# Ticket #1595 — realclaude: does a `set_permission_mode` control request land in-band?

Measurement-only ticket, split from #1573. `inBandDeliverable` (`internal/sessions/pool.go`)
requires `YOLO == nil`, so any settings update carrying a bypass-posture change still falls
through to the kill-and-respawn path (`sup.Restart(newArgs)`) — the same path #1581/#1582 proved
could be bypassed for model/effort. No in-band form of the YOLO change had been measured, because
the candidate isn't a slash command (`/permissions` is an interactive picker); it's a
control-channel `set_permission_mode` request on the same held-open stdin the daemon already
writes interrupts to. Whether claude's handler for that subtype is wired under pyry's actual
stream-json-in/stream-json-out invocation — as opposed to merely present in the binary — could
only be settled by a live run. This ticket adds that run and changes no production code.

## Implementation

- **`internal/e2e/realclaude/set_permission_mode_probe_test.go`** (new, 1036 lines,
  `//go:build e2e_realclaude`) — the only test file this ticket touches. Two tests:
  `TestRealClaude_SetPermissionMode_InBandProbe` (live) and
  `TestRealClaude_SetPermissionMode_FixtureNamesAvoidRegressionGlobs` (live-free).
- **Shape mirrors `permission_protocol_spike_test.go`, not #1582's `interactive_stream_inband_model_test.go`.**
  Four direct `exec.CommandContext("claude", …)` children, not an in-process `sessions.Pool` — a
  deliberate divergence from #1582's approach, because this ticket needs to read a
  `control_response` off stdout via a plain `bufio.Scanner` over `cmd.StdoutPipe()`, not tap
  `streamsup.Config.Stdout`. Four helpers are reused verbatim from the spike file (same package,
  no copy): `captureClaudeVersion`, `versionSlug`, `packageDir`, `truncateString`.
- **Four arms, one drive sequence** — `revoke` (launched WITH `--dangerously-skip-permissions`,
  sends `mode: "default"`), `enable` (launched WITHOUT it, sends `mode: "bypassPermissions"`), and
  two controls (`control_default`, `control_bypass`) that run the identical two-turn sequence with
  no control request, as the behavioural baseline each measurement arm's turn 2 is judged against.
  The controls still drive both turns — a measurement arm's post-change read is its *turn 2*, so
  comparing it against a control's turn 1 would fold a turn-index confound into the verdict.
- **Argv diverges from the #383 spike in three ways, each load-bearing for the ticket's premise**:
  no `--permission-prompt-tool stdio` (the spike found that flag short-circuits enforcement; pyry's
  invocation doesn't carry it), no `--allowed-tools` (same reason), and
  `--dangerously-skip-permissions` rather than `--permission-mode bypassPermissions` for the
  bypass posture (the flag `claudeSettingsArgs` actually emits).
- **`setModeControlLine`** marshals the control-channel request structured, never by string
  concatenation — the same discipline `marshalInterruptEnvelope`
  (`internal/streamsup/envelope.go`) holds for the production interrupt line this one is modeled
  on. `(*Runner).Interrupt` mints a request id and deliberately never reads the reply; this test
  is the first thing in the repo that does.
- **Verdict computed from turn-2 behaviour, never the echoed `control_response` alone** — per the
  ticket's AC, an echoed `success` that still behaves like the bypass control would be recorded as
  a FAILED revocation, and an escalation whose behaviour matches the bypass control would count as
  succeeded even on an error response. A discrimination gate runs first: if the two controls'
  turn-2 outcomes are equal, the probe can't tell the postures apart on this argv and both
  directions record "does not discriminate" rather than a verdict.
- **Fixture naming closes a glob trap named in the architecture spec.**
  `fixtureGlob`/`fixtureNameRE` (`permission_protocol_regression_test.go`) sweeps
  `testdata/permission_protocol_v*_*.json` and parses the trailing token as an *expected*
  `init.permissionMode`; `dropcapFixtureGlob` (`dropped_line_capture_test.go`) is the other
  testdata glob in the package. `set_permission_mode_v<version>_<arm>.json` falls outside both.
  `TestRealClaude_SetPermissionMode_FixtureNamesAvoidRegressionGlobs` pins that deterministically
  — no subprocess, no credentials, passes on a machine with no `claude` at all — by driving the
  same filename-minting function the live writer uses, over a table of adversarial version tokens
  including one containing an underscore.
- **The dividing line for `t.Fatalf` vs. a recorded field**: is this outcome information, or a
  broken instrument? No `result` line, no `control_response`, a mismatched `request_id`, an
  `error` response, no `init` line after the control request — all recorded fields, not failures.
  `t.Fatalf` is reserved for claude absent, no credentials, spawn failure, or an arm that captured
  zero stdout lines. The test passes on every recorded outcome, per the
  `TestRealClaude_PermissionProtocol_Spike` precedent.

## Patterns established

- **A control-channel round-trip the daemon only ever writes one-way (`Interrupt` mints an id and
  never reads the reply) can still be measured by a test that owns the child directly** — read the
  `control_response` off the same `bufio.Scanner` used for every other stdout line, correlate by
  `request_id`, and record it verbatim. No production reader needed to answer "is this wired."
- **A behavioural verdict against a live LLM needs a same-turn-index control, not just a control.**
  Both control arms drive the identical two probe turns as their measurement counterpart and are
  compared only at turn 2 — the same position in the session, same accumulated context. This is
  the general shape for any future "did an in-band change actually take effect" measurement in
  this package: pair the change with a from-birth control at the same turn index, don't compare
  across turn 1 and turn 2.
- **A discrimination gate is a first-class verdict**, not a defensive fallback. Given #383's own
  recorded finding that a `default`-launched child can auto-approve anyway under a different argv,
  "the probe can't tell the postures apart on this argv" was a live possible outcome that needed
  its own reportable state, not an assumption the behavioural read would always work.

## Lessons learned

From the PR body:

- **The behavioural probe's discrimination is argv-dependent, and #383's finding #2 does not carry
  over.** That spike recorded a `default`-launched child auto-approving Bash anyway — but it ran
  with `--permission-prompt-tool stdio`, which it itself concluded short-circuits enforcement. On
  pyry's actual argv (no prompt-tool, no `--allowed-tools`) a `default` child *is* gated:
  `permission_denials: 1`. Re-deriving that on the target argv, rather than inheriting the #383
  finding, is what made the behavioural verdict non-vacuous.
- **A strict whole-value outcome comparison is not run-to-run stable, and the instability is
  informative rather than noise.** One run classified `enable` INCONCLUSIVE purely because claude
  retried the denied tool (`tool_use_names` `[Bash Bash]` vs. the controls' `[Bash]`); a rerun of
  identical code the same day classified it ESCALATION FAILED. The fix was not to loosen the
  comparison — dropping a field for looking redundant is how a probe stops discriminating — but to
  log a per-field breakdown alongside it, so an INCONCLUSIVE can be read rather than merely
  reported.
- **`bufio.Scanner` output cannot be appended to a `[]json.RawMessage` destined for a fixture
  without a validity guard.** An empty or non-JSON line makes `json.MarshalIndent` of the whole
  record fail, so a single odd stdout line would destroy the entire capture. Retaining invalid
  lines as JSON *strings* with a counter keeps the fixture parseable and the evidence verbatim.

## The finding

Measured against claude 2.1.220, 2026-08-19: **the mechanism is wired, and it is one-way.**
`revoke` (`bypassPermissions → default`) succeeded on all three independent reads —
`control_response` `success`, the next `init.permissionMode` echo, and turn-2 behaviour matching
the `control_default` arm exactly. `enable` (`default → bypassPermissions`) was refused, with a
third error string not previously read out of the binary: `Cannot set permission mode to
bypassPermissions because the session was not launched with --dangerously-skip-permissions`.
`inBandDeliverable` can split on the *direction* of a YOLO change — drop in-band, add via
restart — but routing both directions in-band is not supported by this measurement. No production
writer exists yet; #1596 decides whether to add one. The `enable` direction failing is itself a
security-relevant negative result: had it succeeded, a bypass-posture escalation would have been
reachable over the daemon's stdin channel with no writer needed to prove it.
