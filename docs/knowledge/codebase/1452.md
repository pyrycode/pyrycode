# Ticket #1452 — Probe instrument: the live gather's trailer gate reads the runner path the run actually took (offline)

`finGatherReadings` typed `trailRunnerUnread()` into the trailer gate's
`RunnerPath` at its own call site, so `trailReasonAgainstPath` always fell
through to its path-unnamed case and the gate's absence branch could only ever
answer `trailGateOutOfContract` — never `trailGateAbsentOwesNone`, the value
#1417 built for a healthy headless `PYRY_USE_STREAMJSON=1` run whose trailer is
claude's own `result` line and carries no `terminal_reason` key by
construction. That made the whole #1439 → #1440 → #1446 → #1447 → #1448
evidence route unreachable from anything but a fixture. This ticket routes the
runner-path reading the live caller (`finExitRunProbe`) already derives from
its own driver-side pin scan into the gather, so a stream-path run reaches the
gate value its trailer shape earns. Offline throughout — no live claude, no
credentials.

PR [#1454](https://github.com/pyrycode/pyrycode/pull/1454). Spec:
[`docs/specs/architecture/1452-gather-gate-reads-the-runner-path.md`](../../specs/architecture/1452-gather-gate-reads-the-runner-path.md)
(architect self-review PASS). Two code-review rounds — FAIL then PASS — both
entirely on the cite-renumbering pass, never on substance (see below).

## Implementation

- **`finGatherInputs` gains a seventh field, `RunnerPath string`** — the
  runner-path reading, **already reduced by the caller**. Its doc names the
  channel it keeps shut in the same shape `Pinned []int`'s doc already does:
  the one admissible producer is `tdnRunnerFromArgv`, never
  `Pin.ClaudeCommand` itself (verbatim argv, marked INPUT ONLY — NEVER
  PUBLISHED at `finLivePinReading`). `""` is admissible and means "the caller
  staged no reading."
- **The reduction happens at the call site, never inside the gather.**
  `finExitRunProbe` (`finding_exit_path_probe_test.go`) now passes
  `RunnerPath: tdnRunnerFromArgv(h.Pin.ClaudeCommand)` into
  `finGatherInputs` — the same conversion-site doctrine `Pinned []int`
  already applies to `pinScan.Matches`. A design that took `ClaudeCommand
  string` and reduced inside the gather was rejected: it would put verbatim
  argv, and with it an operator's `CLAUDE_CODE_OAUTH_TOKEN` or
  `ANTHROPIC_API_KEY`, one struct field from an artifact destined for a
  public issue.
- **`finGatherRunnerPath(reading string) string`** — new pure helper, total
  and information-preserving: `"" → trailRunnerUnread()`, else passthrough.
  `trailRunnerUnread()` **is** `tdnRunnerFromArgv("")`, so the two spellings
  of "nothing was read" collapse onto the one the record can publish.
  Deliberately **not** the `ClaudeState` no-fill-in-if-unset doctrine
  (`finGatherReadings`' own comment) — that rule exists because C7 is a
  shipped classifier check over the claude verdict, and there is no
  analogous checker over `RunnerPath`: `finRecordRunnerLabel("")` already
  returns `""`, matching neither runner label, so `""` and
  `trailRunnerUnread()` reach the *same* `trailReasonPathUnnamed` gate
  decision. The fix is a **publication** fix — `trailGateResult.RunnerPath`
  is `json:"runner_path,omitempty"`, so an unfilled reading would silently
  drop the field rather than publish today's non-empty indeterminate answer.
  One symbol, two callers: `finGatherReadings` and C2's whole-struct
  recomputation both route through it.
- **The gate call site** (`finGatherReadings`) now reads `RunnerPath:
  finGatherRunnerPath(in.RunnerPath)` instead of `trailRunnerUnread()`.
- **The gather's needle set is untouched.** `pinScanArgv(in.Needles, nil)`
  still runs over `in.Needles` verbatim; `RunnerPath` is a reduced string,
  never a needle. `finExitRunProbe`'s needle prohibition
  (`finding_exit_path_probe_test.go:264-272` — no `tdnClaudeNeedle`) stands
  untouched, because the reading now comes from the caller's own
  `finLivePinReduce` scan rather than from the gather's.
- **`finStageRun` and `trailRigGather` are both unchanged by design.**
  `finStageRun` supplies nothing (`RunnerPath` zero-value `""`) and still
  reaches `trailGateUsable` under `trailFixtureTrailer`'s named reason.
  `trailRigGather` runs no claude process at all, so it has no producer for
  any reading; its stale comment (previously delegating its whole reason to
  `trail_ptyrunner_composition_test.go:19-26`, which this ticket falsifies)
  was rewritten to its own structural reason instead.
- **Neither `trailGateCases()` (9 rows) nor `finGatherCases()` (3 rows)
  grew.** The new coverage lives in a fresh table,
  `finGatherRunnerPathCases()` / `TestFinGatherGateReadsTheRunnerPathTheRunTook`
  (4 rows), each asserting the **shipped gate's own output over the row's own
  reading** — never a typed-in `trailGateResult`:
  - **R1** — reading reduces to `streamrunner`, trailer absent
    `terminal_reason` → `trailGateAbsentOwesNone`. The value this ticket
    exists to make reachable.
  - **R2** — reading reduces to `ptyrunner`, same absent trailer →
    `trailGateOutOfContract` at the **owes-one** site, discriminated from R3
    by Detail marker since both share the same value.
  - **R3** — `""` (caller supplies nothing) → `trailGateOutOfContract` at
    the **path-unnamed** site — today's behaviour for every live run, and
    the sole red for a missing normalisation.
  - **R4** — reading reduces to `ptyrunner`, trailer carries a named
    `terminal_reason` → `trailGateUsable` certifying `"completed"` — the row
    that keeps #1337's recorded ptyrunner finding classified the same way.
- **`TestFinGatherRunnerPathDoesNotReachTheScan`** proves AC2 (the scan is
  unchanged) **without** the obvious-but-flaky design. It does not compare
  `MatchCount` across rows using `os.Args[0]` as the gather's own needle —
  this package makes 29 `t.Parallel()` calls and re-execs itself at five
  sites, so a sibling's transient child process would move that count between
  rows. Instead: a `t.TempDir()` needle gives a deterministic `MatchCount ==
  0` baseline on three ordinary rows, and a fourth **abusive** row passes
  `RunnerPath: os.Args[0]` (a needle that *would* match) to prove the reading
  never reaches `in.Needles`. A **control** — the test's own
  `pinScanArgv([]string{os.Args[0]}, nil)` finding its own pid — is what
  stops the abusive row's zero from being vacuous. This design (`t.TempDir`
  needle + abusive reading + self-scan control) replaced a flakier draft
  during the architect's own security self-review (see below).
- **`TestFinGatherRunnerPathCarriesNoCapturedBytes`** (AC4) — the first sweep
  to run `runner_path` under a reading derived from a real argv rather than
  under `trailRunnerUnread()`'s empty-argv answer. Five rungs: plant a needle
  in an argv, reduce it, hand it to the gather; assert the route is real
  (`runner_path` is marshalled and equals the reading); assert the needle
  *would* have travelled had the reduction echoed its input; assert the
  needle's actual absence from the marshalled record, `readings`, `sighting`
  and both Details; and a second fabric asserting `/opt/node/bin/node` (the
  shared head of both argv fixtures, present in none of `tdnRunnerFromArgv`'s
  five constant answers) is also absent — catching a reduction that echoes
  its input's head rather than its tail.
- **Detail-budget invariance rows** — since no Detail interpolates the
  reading (`trailer_admissibility_test.go:307-311`,
  `trailer_terminal_reason_test.go:208-221`), R1–R3's three absence Details
  under three *different* readings each assert `< reachMaxCommandBytes`
  (512 B) with no truncation marker, turning that invariant into a per-row
  check rather than a comment.

## Patterns established

- **A reduced-string field crossing a credential boundary needs its
  admissible producer named in the field's own doc, not just at the call
  site.** `RunnerPath string` cannot, by type, distinguish a label from raw
  argv — the mitigation is three layered, different-fabric checks (the doc,
  the tail-echo sweep rung, the head-echo sweep rung) rather than one, since
  no single one of them is sufficient on its own. Flagged as a SHOULD FIX in
  the architect's own security review and accepted rather than gated on,
  since the unsafe caller shape (`ClaudeCommand string` reduced inside the
  gather) doesn't exist and was rejected at design time.
- **A normalisation helper that changes no decision still needs its own
  doc distinguishing it from a sibling doctrine that looks identical.**
  `finGatherRunnerPath`'s `"" → trailRunnerUnread()` fill looks like the
  `ClaudeState` "no fill-in-if-unset" rule it sits three lines from in the
  same function, and is not: one guards a shipped classifier check (C7),
  the other exists purely so `omitempty` can't silently drop a field. Naming
  the distinction in the helper's own doc is what stops a future reader
  from "fixing" it into the other shape.
- **When a package re-execs itself and runs its tests in parallel, "vary one
  field, hold the rest of the environment fixed" needs a needle no sibling
  test can also produce.** `t.TempDir()` gives a deterministic zero-match
  baseline; `os.Args[0]` does not, in a package with 29 `t.Parallel()` calls
  and five re-exec sites — the flaky cross-row-`os.Args[0]`-comparison
  design was caught and replaced during the architect's own security
  self-review, before code review ever saw it.

## Lessons learned

From the PR body's own "Lessons learned" section (developer), all about the
cite-renumbering tail rather than the substance:

- **A displaced citation is not the same finding as a wrongly-written one.**
  `cmd/cite-guard`'s own `changedLines` doc settles the scope question — the
  gate stops the *inflow* of new citations and deliberately does not
  revalidate the existing stock, because chasing displacement is the tax
  that killed two runs on this ticket.
- **Resolve a bare `(:NNN)` before believing it is stale.** A line-map scan
  over the branch flagged 17 candidates; all but one resolved into files the
  branch never touched. Attributing a bare ref to the self-file, or to the
  last-named file without resetting per comment block, manufactures
  findings.
- **Two cites on one comment line defeat naive pairing.** Pairing normalised
  prose against `main` must be positional per cite, or the second cite on a
  line is checked against the first one's target and reports a confident
  wrong delta.
- **A line map tells you where a line went, not whether a cite already
  followed it.** Fixing the review's six findings, the developer twice
  applied the `main`→branch map to a cite that had *already* been correctly
  bumped, turning a right answer into a wrong one. The map's input must be
  the number as it stood on `main`; the reliable method is resolving the
  cite against the **post-edit tree** and checking the target says what the
  prose claims. Deltas find suspects; prose resolution convicts them.
- **Attribute a bare `(:NNN)` by subject, not by the last filename in the
  block.** A positional sweep raised four bare refs whose enclosing comment
  block last named a file the branch *had* touched — all four were about a
  different symbol entirely and resolved into untouched files. A heading or
  subject change mid-block breaks the last-named-file inheritance heuristic.

From code review (FAIL → rework → PASS): the design, the tests and the prose
sweep were right from round one — every finding was a cite pointed the wrong
way (2 MUST FIX, re-points onto the opposite-polarity function or into a file
the branch never touched) or a cite list bumped on one cite but not its
neighbour on the same line (4 SHOULD FIX). All six sat on lines the commit
itself edited — not the displacement-chasing the PR argued was out of scope.
Fixed in a comment-only, 6-file, 6-line follow-up commit
(`496cda2`), independently re-verified by the developer's own positional
sweep before re-requesting review, then confirmed by a **bidirectional**
cite check (forward positional + reverse left-behind-class) on re-review. Two
residual mis-attributions were found and correctly left untouched — both
pre-existing on `main`, both filed as follow-up #1455 rather than fixed here.
