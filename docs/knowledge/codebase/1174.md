# Ticket #1174 — realclaude stream `new_session` rotates + spawns fresh

Real-claude e2e proving that, on the production stream-json interactive
runner, `new_session` rotates the bootstrap session id AND restarts the
bound runner with a genuinely fresh live `claude` child under the rotated
id — not a `--resume` of turn one's session. The real-claude cross of the
fakeclaude stream sibling (`TestRelayV2_StreamNewSessionRotatesAndRestartsFresh`,
`internal/e2e/relay_v2_stream_new_session_test.go`, #1137) and the
real-claude session-control sibling (#1031, PTY-runner `/clear` rotation).
One of three independent T9 (#1083) stream real-claude
leaves alongside #1173 (multi-turn continuity) and #1175 (permission DENY).

## Implementation

- `internal/e2e/realclaude/interactive_stream_new_session_test.go` (new
  file, `//go:build e2e_realclaude`, PR
  [#1180](https://github.com/pyrycode/pyrycode/pull/1180)). Test-only,
  **zero production files** — the stream `new_session` path already ships
  (#1124/#1125/#1137).
- Five milestones on one daemon / one bound conversation / one encrypted
  channel (sequential spine, single `initRecv` so the Noise receive nonce
  stays in lockstep across every drain):
  - **M1** — turn 1 drains end-to-end via `drainForCompletedTurn` (#1153),
    proving the pre-rotation session is alive.
  - **M2** — a `new_session` re-send loop (transcribed from #1031's
    actuation loop, lines 188–206, byte-for-byte) polls
    `readBootstrapRowIfPresent` until the on-disk registry id leaves
    `idBefore`; `waitBootstrapIDSettled` confirms the rotated id is a valid
    UUIDv4 stem.
  - **M3** — `drainForControlEvent(TypeSessionTransition)` (#1154) asserts
    the client-observed `session_transition{reason:"clear", previous:
    idBefore, new: <valid stem>, conversation: convID}`.
  - **M4** — turn 2 asserts **only its `ack`**
    (`drainForReply(TypeAck, reqID)`), never a phone-side delta.
  - **M5** — the AC3 fresh-spawn proof: a fresh `<idAfter>.jsonl` transcript
    appears under the authenticated claude sessions dir, alongside the
    untouched turn-1 `<idBefore>.jsonl`.
- **The load-bearing tension (why M4 is ack-only).** On the opt-in stream
  path the turn-drain gate forwards an event only when the producing
  runner's sink tag equals the bound conversation's session id. The sink
  tag is fixed at runner **construction** (`idBefore`), and
  `streamsup.Runner.RestartFresh` re-spawns the child **in place** — it
  never rebuilds the runner/parser/sink. So a turn issued *after* rotation
  has its `assistant_delta` dropped at the gate; draining a phone-side
  delta for turn 2 would **hang**. The fakeclaude sibling (#1137) worked
  around this with a stdin-log tee, a hook real claude has no equivalent
  of — hence M4 asserts the `ack` only (produced by the `send_message`
  handler on delivery, not gated by the sink tag), proving `Route` resolved
  `convID → idAfter → Pool.Lookup` HIT on the re-keyed pool. Documented as
  a known #1081 production follow-up, out of scope here.
- **M5 observable — located empirically, not recomputed.**
  `streamNewSessionTranscriptDir(t, home, idBefore, timeout)` polls
  `<home>/.claude/projects/*/` for the subdir containing `idBefore.jsonl`
  and returns it (Fatal lists the tree on timeout — self-diagnosing).
  `requireTranscriptAppears(t, dir, idAfter, timeout)` then polls that dir
  for `idAfter.jsonl`. Locating empirically (rather than recomputing
  `DefaultClaudeSessionsDir`'s `encodeWorkdir`) sidesteps the #989 hazard:
  the daemon's stream runner sets the child cwd via `ResolveWorkdir`, which
  additionally applies `canonicalCase` and could diverge from a
  test-side recomputation. `RestartFresh(idAfter)` re-arms first-run form
  (`--session-id idAfter`, proven by `runner_test.go:662`), so a fresh
  `<idAfter>.jsonl` — coexisting with the untouched `<idBefore>.jsonl` — is
  the discriminator a `--resume` (which only appends to `idBefore.jsonl`)
  cannot produce, and a scripted fakeclaude (stdin-tee based) cannot
  regress.
- **Double-rotation tolerance.** The re-send loop may deliver a second
  `new_session` before the first rotation is observed; if two rotations
  stack, `waitBootstrapIDSettled` returns the final id and M5 uses that.
  M3 asserts `prev == idBefore` (always true for the *first*
  `session_transition`, robust to the stacked case) and asserts `new` is a
  valid stem `!= idBefore` rather than pinning it to `idAfter`.
- Constants (free `e`/`f` UUID block — main package uses
  `1,5,6,7,8,9,a,b`; in-flight siblings reserved `3,4` (#1172) and `c,d`
  (#1173)): `streamNewSessionBootstrapUUID = "eeeeeeee-…"`,
  `streamNewSessionConvID = "ffffffff-…"`.
- Budgets reused verbatim from #1031 (tuned for real-claude stream
  rotation): `newSessionResend=1s`, `rotateBudget=45s`,
  `idSettleQuiesce=2s`, `idSettleTimeout=45s`, `perTurnReplyBudget=120s`
  (both turn-1 drain and the turn-2 ack — generous because the fresh child
  cold-spawns).

## Patterns established

- **A production `--session-id` vs `--resume` argv distinction (fixed
  first-run form on rotation) can be turned into a word-independent,
  fake-unregressable real-claude observable by comparing on-disk transcript
  *filenames*, not content.** `RestartFresh` re-arming first-run form
  means the fresh child mints a brand-new `<newID>.jsonl` instead of
  appending to the old one; asserting *that file's existence* sidesteps
  both claude's non-deterministic wording and the drain-gate's
  post-rotation delta-drop. Applicable to any future real-claude spec
  needing a "fresh spawn, not resume" proof where content inspection is
  gated off.
- **Locate claude's on-disk artifacts empirically rather than recomputing
  the path formula, whenever the test-side cwd resolution and the
  production cwd resolution could diverge** (here: `ResolveWorkdir`'s
  extra `canonicalCase` step vs. a naive `DefaultClaudeSessionsDir` call).
  Same shape as the #989 tmpdir hazard on other siblings — the guard
  doubles as a non-vacuity check (finding turn-1's transcript first proves
  the empirical approach itself works) and fails loud with a tree dump
  rather than passing vacuously on a wrong-but-close path.

## Lessons learned

- The stream runner's `buildArgs` first-run form (`--session-id <id>`,
  `internal/streamsup/runner.go:583-604`) is what makes the on-disk
  transcript a sound "fresh vs resume" oracle: `RestartFresh` re-arms
  first-run so the rotated id mints `<idAfter>.jsonl`, while a `--resume`
  would only append to `<idBefore>.jsonl`. Two coexisting files ⟹ fresh
  spawn — this is the reusable insight for any future "prove a fresh
  child spawned" real-claude assertion.
- The fresh no-memory / content-continuity angle is **not observable** on
  the stream path today: proving it would need the turn-2 reply, which is
  the very delta the drain gate drops (#1081). The on-disk transcript
  appearance is the achievable deterministic proof; a future fix to the
  drain-gate's construction-fixed sink tag (#1081) would unblock the
  stronger claim.
