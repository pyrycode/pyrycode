# Ticket #1003 — e2e: `modal_cancel` over the v2 wire (dismiss + bare ESC)

Fake-daemon e2e for the `modal_cancel` v2 control verb, split from the oversized
four-verb #962 batch (the 2026-07-15 review gap; siblings `modal_answer` (#791),
`interrupt` (#794), `dequeue_message`, `rekey_request`, `request_snapshot` already had
e2e). Test-only — no production change — one new file,
`internal/e2e/relay_v2_modal_cancel_test.go` (`//go:build e2e`), `TestRelayV2_ModalCancelDismisses`.

## Implementation

Confirms live, over one spawned daemon + fakeclaude raising a real permission modal,
the path the unit tier already proves deterministically: phone `modal_cancel{modal_id}`
→ Noise decrypt → `dispatchAppFrame` → `handleModalCancel` (`internal/relay/v2session.go:2283`,
fire-and-broadcast, no reply) → `ModalResolver.ResolveCancel` (`cmd/pyry/modal_resolve_v2.go:63`)
→ `reg.Resolve(modal_id)` (one-shot gate) → `SendEsc()` (lone `0x1b` to the child) →
`broadcastModalDismissed` → `modal_dismissed{modal_id, "cancelled", "remote"}` back to the phone.

Five-step body, assertion order load-bearing (each precondition has its own `t.Fatal`
naming its failure mode, so later assertions can't pass vacuously):
1. Raise a modal, assert `Class == "permission"` before sending the cancel.
2. Send `modal_cancel` naming the raised modal (fire-and-broadcast — no correlated ack,
   so the envelope ID is cosmetic).
3. Drain to `modal_dismissed` under a ~20s deadline; assert `ModalID` matches
   (`t.Fatalf`, since a wrong/absent modal invalidates the ESC oracle below), and
   `Outcome == "cancelled"` / `Source == "remote"` (`t.Errorf`, value fidelity).
4. Bounded ~2s poll of the fakeclaude stdin log for a **bare** ESC (`hasBareESC` —
   `0x1b` not immediately followed by `0x5b`), since the keystroke crosses a process
   boundary and `modal_dismissed` only fences the wire side, not the PTY write. Then
   `assertNoAnswerDigit` (cancel routes only the ESC, never an answer digit).
5. Replay the identical `modal_cancel` and assert it's inert (~3s short deadline, no
   second `modal_dismissed`, stdin log byte-for-byte unchanged) — the cheap substitute
   for AC-4's timeout-vs-cancel one-shot check.

No new helpers: reuses `bringUpModalHarness`, `awaitModalShown`, `hasBareESC`,
`assertNoAnswerDigit`, `mustJSON` verbatim from the `modal_answer` (#791) and
`interrupt` (#794) templates — none redefined (would be a duplicate-symbol compile
error).

### AC-4 disposition (timeout-vs-cancel one-shot)

The AC asked, *if cheap*, to also prove a cancel-resolved modal isn't double-resolved
by a subsequent timeout. The literal variant isn't cheap — the deny-on-timeout window
is the real `modalDenyTimeout` (~2 min) inside the pyry subprocess and can't be
shrunk from the e2e (`TestRelayV2_RemotePermissionDeniedOnTimeout` pays the full
`2m+20s` for the same reason). The one-shot property is enforced at a single point
for *both* paths — `modalbridge.Registry.Resolve`, which `ResolveCancel` and
`ResolveTimeout` both call and both bail on `ok=false` — so step 5's replayed-cancel
negative exercises that exact gate cheaply (~3s) and the literal 2-minute variant is
deferred per the AC's "if not cheap, deferred and noted" clause.

## Patterns established

None new — this ticket is a straight clone of the frozen `modalHarness` template
applied to a fifth verb. It reconfirms the discipline from #791/#793/#794: reuse
in-package e2e helpers verbatim rather than extracting or mutating shared infra, and
keep the vacuous-pass guard (modal actually raised → dismissal observed → keystroke
on disk) as dedicated ordered `t.Fatal`s.
