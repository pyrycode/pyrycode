# Ticket #1363 — Probe instrument: carry the trailer's key names onto both record tiers, bounded, with the artifact's standing safety claim made true (offline)

`trailScan` already read the result trailer's top-level key **names** (#1357) but
carried them no further than `trailScanResult`, an unpublished intermediate.
`terminal_reason` is a pyry invention — claude's own `result` line on the healthy
headless path carries no such key at all, and after `resultTrailer`'s fixed decode
an *absent* `terminal_reason` and one emitted as `""` collapse to the same value —
so the presence of the **key**, not any value, is the only thing that lets a
reader of a filed probe record tell "pyry wrote this trailer, the watchdog fired"
from "claude wrote it, the run was healthy". This ticket carries the names the
rest of the way onto the two record tiers that reach the artifact, bounds them
(count and per-name length, independently), and repairs the artifact's own
standing safety sentence, which goes false the instant a field of
claude-authored strings lands in a record that claims every field is "a string
this rig authored". Offline throughout — no live claude, no production code
touched.

## Implementation

- **The field**, added identically to both tiers: `KeyNames []string
  \`json:"trailer_keys"\`` on `finSighting` (`finding_run_gather_test.go`) and on
  `finTrailerRecord` (`finding_trailer_evidence_test.go`), no `omitempty` on
  either — matching the family's blanket rule, and stated at the field as to why
  the collapse that rule defends against is structurally unreachable here: a
  *seen* trailer's match return is past `tr.Type == "result"`, so the map decode
  always succeeds and always carries at least `type`; "no names" is reachable
  only from the not-seen arm. `finRecordRun` gains no field of its own — it
  embeds `finTrailerRecord` whole, pinned by
  `TestFinRecordEmbedsTrailerRecordWhole`.
- **Two named bounds, one enforcement point.**
  `finTrailerMaxKeyNames = 32` and `finTrailerMaxKeyNameBytes = 64`
  (`finding_run_gather_test.go`), deliberately unequal so a fill or proof
  reaching for the wrong constant is detectable. The count bound is chosen
  against the scanner's own ceiling, not a name count: `trailScan`'s
  `bufio.Scanner` buffer is deliberately not raised past the 64 KiB default, a
  line at or past 65536 bytes **aborts the scan** (nil `KeyNames`, not a
  truncated read), and at ordinary `"k000000":"v"` key shapes that puts the
  unprovable floor near 4680 names — so 32 sits two orders of magnitude below it
  and a `bound+1`-name fixture (#1364's) stays a readable ~400 bytes rather than
  golfed against the scanner. `finBoundKeyNames(names []string) []string` is the
  single shared enforcement point — no `error` return, matching the family's
  pure-builder contract. Five load-bearing clauses: nil in → nil out, never
  `[]string{}` (a not-seen record must render `null`); keeps at most
  `finTrailerMaxKeyNames`, in order (already sorted, so an alphabetic prefix);
  bounds each name **individually, never as a joined string** — a joined cap
  would let a leak in a late name be truncated away and turn a containment sweep
  green over a record that leaked, the defect #1284 shipped and had to fix; an
  over-long name is truncated and marked with `reachTruncationMarker`, never
  silently dropped; and it allocates its own backing array on **every** path,
  explicitly forbidding the "input already under both bounds, return it as-is"
  fast path — `finTrailerBuild` copies the field by plain slice assignment, so a
  pass-through would alias `trailScanResult.KeyNames` itself, and the shipped
  `dropped := seen` struct copy in
  `TestFinTrailerRecordFillsTheFourScalarsOnlyBehindCarriesTrailer` would then
  put two carriers on one backing array under `go test -race`'s parallel run.
- **Three fill sites, one obligation stated at each.** `finTrailerSighting`
  (fixture side) and `finGatherReadings`' inline carrier fill (live side) both
  call `finBoundKeyNames` behind the existing `CarriesTrailer` guard, beside the
  four scalars — `trailObservation` embeds `trailScanResult`, so the live side
  needed no new plumbing to reach `obs.KeyNames`. `finTrailerBuild` copies the
  already-bounded field through by plain assignment and computes nothing. The
  agreement obligation ("these two fills must produce the same answer") already
  lived in comment at both sites for the four scalars; this ticket extends both
  comments to cover the key-name call, because nothing structural enforces it —
  every offline test drives the fixture side, so bounding it and forgetting the
  live fill would ship an unbounded field on every live probe run with nothing
  red. Held by comment and by code review, in the same register as the
  pre-existing `CarriesTrailer` pair obligation.
- **The false arm's Detail names the drop.** Behind `CarriesTrailer == false`
  the key names are zeroed exactly like the four scalars — under the carrier
  that's a decision, not a consequence, since the field is separately settable —
  and the arm's Detail format changed from *"the four trailer fields hold their
  zero values"* to *"the four trailer fields and the key names hold their zero
  values"*. No renumbering to "five": that phrase is about the four **decoded**
  scalars specifically and stays true; `KeyNames` is a different reader's
  output, not a fifth member of that set.
- **AC3 — Detail interpolates nothing derived from the line.** Stated as its own
  rule rather than inferred from the existing Line prohibition: the Detail may
  name no key and interpolate no count of them. The 512-byte cap /
  470-byte-headroom rule (`reachMaxCommandBytes` minus `len(trailNeedle)`) holds
  unchanged on the existing row, which the shipped fixture (eleven short names)
  cannot make red on its own — the hostile fixture that proves the prohibition
  bites is #1364's.
- **The safety claim (AC4).** `finWriteSafetyClaim`
  (`finding_artifact_write_test.go`) is rewritten to name the field explicitly:
  the trailer's key names "cross verbatim from claude's own output line...key
  names and never values, bounded in count and in length." Three properties any
  reword had to keep: contains neither `operator-review-before-paste` nor
  `OPERATOR-REVIEW` (the record still has no field that obligation attaches to —
  if the honest wording needed "review this", the right call would have been not
  to carry the names at all); says *claude*-authored, not *rig*-authored, which
  is what makes the sentence true rather than merely unfalsified; and states
  both halves of why the field is safe — bounded (this ticket's constants) and
  value-free (proved at the reader tier by the already-shipped
  `TestTrailKeyNamesCarryNoValues`).
- **`TestFinRecordPublishesTheTrailerKeyNamesTheReaderRead`** (AC1, new, appended
  at EOF of `finding_run_record_test.go` — that file's highest inbound cite was
  `:1036` against a 1057-line file, so appending shifted zero cites). Drives the
  shipped builders end to end from a fixture line (`trailPaddedTrailer(0)`),
  asserts three preconditions before comparing anything (scan actually carries a
  trailer and names; the fixture's name set sits under both bounds, so "the
  reader's names" and "the published names" are provably the same list rather
  than a prefix; the expected set contains `terminal_reason`, the discriminator
  the field exists for), then asserts `finRecordBuild(...).Trailer.KeyNames`
  equals `trailKeyNames`'s own output for that line — never a hand-written list,
  which would pin the fixture rather than the carriage. A second record built
  from `finTrailerAbsentScan()` is marshalled and compared on raw JSON bytes:
  `trailer_keys` is present on **both** records (catches an `omitempty`
  regression), renders exactly `null` on the not-seen one, and a non-empty array
  on the seen one — the distinction this whole family exists to keep.

## Patterns established

- **A cap that must be applied at two independent fill sites needs its
  arithmetic in exactly one shared function, not two hand-written copies.**
  `finBoundKeyNames` is called identically from the fixture and live sides;
  the alternative (each site clamping inline) is how two fills that the code
  already states "must agree" stop agreeing.
- **A "no-op fast path" in a bounding function is a correctness hazard, not a
  free optimization, when its output is later copied by plain assignment.**
  `finBoundKeyNames` must allocate a fresh backing array even when the input is
  already under both bounds, because the consumer (`finTrailerBuild`) does a
  bare `rec.KeyNames = sighting.KeyNames` with no defensive copy of its own —
  a pass-through here would make two carriers alias one backing array under
  `-race`'s parallel test execution.
- **An obligation with no available in-code pin is stated at both call sites in
  comment, and code review discharges it explicitly** (verifies both routes and
  reports the check as done) rather than treating "no pin exists" as itself a
  finding. Continues the register already established for the `CarriesTrailer`
  pair fill (see [`codebase/1320.md`](1320.md)).
- **A record's own standing safety/trust sentence is a claim that goes stale the
  moment a new field lands, and nothing catches that automatically** — the
  shipped test asserted only that `run.md` *contains* the constant, never that
  it's *true*. When a ticket adds a field the sentence's categories don't cover,
  repairing the sentence belongs in the same commit as the field, not a
  follow-up.

## Lessons learned

(From PR #1365's body and its code-review comments.)

- **A line map is not a sufficient check for a cite sweep — verify the outcome
  by target *text*, not just by offset.** `difflib.SequenceMatcher`'s
  proportional mapping inside an *expanded* replace block can return
  `map(x) == x`, silently hiding a cite whose target actually moved. Comparing
  `main[old_target]` against `new[new_target]` for every cite caught one bad
  pointer the map itself had passed.
- **Re-running a sweep script over an already-swept tree double-shifts and
  reports a full set of false positives.** The census must be anchored on
  `origin/main`, never re-derived from the working copy mid-sweep.
- **The bare-cite "last-named-file" carry heuristic is wrong roughly half the
  time** — consistent with #1357's own finding. Several bare refs here inherited
  a file with no `.go` filename anywhere in their own comment block (pointing
  into `trail_run_outcome_test.go`'s C2–C9 contract checks), while at least one
  cross-file bare cite went unmarked by the informal "cross-file cites say
  *there*" convention the spec cited as reliable — it isn't. Only the target's
  own text settles a bare cite; the heuristic is a starting guess, never a
  verifier.
- **Appending a new test strictly at EOF holds a heavily-cited file's line map
  to identity**, avoiding a sweep entirely for that file's ~25 inbound cites —
  confirmed load-bearing here, since a sibling file's own cite pointed at one of
  the lines that would otherwise have shifted.
- **A spec can self-contradict on which existing test is "untouched"** when two
  of its own sections independently derive an edit to the same test from
  different acceptance criteria. Resolving in favor of the edit that a security
  property actually depends on (here: pinning the key-name drop on the false
  arm, since nothing else in the diff proves it) is the correct tiebreak.
