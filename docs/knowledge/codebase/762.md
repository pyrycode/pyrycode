# Ticket #762 — `session/load` + `session/cancel` lifecycle over the embedded pool

After [#761](761.md) stood up the embedded ACP pool and served `session/new`, the
host needs to **address sessions it already opened**. `session/load` resumes an
existing session by id and returns a success result; `session/cancel` is an ACP
**notification** (no response) that resolves onto the target session's supervisor
— the seam T9 ([#753](https://github.com/pyrycode/pyrycode/issues/753)) drops the
abort keystroke onto. Both verbs reduce to one primitive — resolve an ACP
`sessionId` onto its pool session via `Pool.Lookup` — plus one shared param
decode, and both register in #761's existing `register` closure. **No new
transport wiring.**

Epic [#600](https://github.com/pyrycode/pyrycode/issues/600) — `pyry acp` as a
thin adapter over the shared remote-head core. Split from #748, blocked by #761,
sub-issue of #600. Spec:
[`specs/architecture/762-acp-session-load-cancel.md`](../../specs/architecture/762-acp-session-load-cancel.md).
Not security-sensitive — it resolves *existing* ids only and accepts no
caller-supplied path, so #761's `cwd` flip condition does not fire.

**Divergence 6 holds:** `session/load` resumes the existing supervised `claude`
for an id; it never starts a second. Exactly one live interactive `claude` per
ACP session throughout.

## Implementation

**1 production file modified (`cmd/pyry/acp.go`, +86 lines), 0 new production
files, 0 new exported types.** Every new symbol is an unexported function that
reuses existing `internal/sessions` / `internal/acp` primitives verbatim — no
changes to those packages.

### `decodeSessionID(params) (sessions.SessionID, *acp.Error)` — the shared decode

The single seam both verbs share (the ticket's "one shared decode covers both
verbs"). Unmarshals `{"sessionId": string}`; a JSON error, a missing key, or an
**empty** `sessionId` returns `acp.NewError(acp.CodeInvalidParams, …)`. It
returns `*acp.Error` (not a plain `error`) so `session/load` gets the exact
`CodeInvalidParams` wire code — and because `*acp.Error` also satisfies `error`,
`session/cancel` passes it straight into its logged-and-discarded return with no
conversion.

**The empty-string rejection is load-bearing.** `Pool.Lookup("")` resolves to the
parked **bootstrap** session, *not* an error (the empty-id → default-session seam
is deliberate for the control plane, `pool.go:721`). An empty/missing `sessionId`
must be refused *before* it reaches `Lookup`, or `session/load` would activate the
bootstrap.

### `loadSessionHandler(pool) acp.Handler` — `session/load`

`decodeSessionID` → `pool.Lookup(id)` → `pool.Activate(ctx, id)` →
`newSessionResult{SessionID: string(id)}` (reuses #761's result struct →
`{"sessionId":"<id>"}`, zero new types).

- **`Lookup` gives miss-is-an-error with no side effect.**
  `errors.Is(err, sessions.ErrSessionNotFound)` → `CodeInvalidParams` ("unknown
  session"), **no `Activate`, no spawn** (AC-2).
- **`Activate` is idempotent on the already-active session.** The pool is uncapped
  (`ActiveCap == 0`), so `Pool.Activate` delegates to `Session.Activate`
  (`pool.go:1221-1223`), whose already-`stateActive` fast path
  (`session.go:209-229`) returns immediately off the closed `activeCh` and signals
  no lifecycle goroutine. A session Created by `session/new` is already active, so
  loading it (once or twice) spawns **no second claude** (AC-1, AC-3, divergence
  6). It re-activates an evicted session in place, same id.
- **`GetOrCreate` is deliberately NOT used.** It *creates on miss*, which would
  spawn a fresh claude for an unknown id and break both AC-2 and divergence 6.

### `resolveCancelTarget` + `cancelSessionHandler` — `session/cancel`

Cancel routing is factored into a small, directly unit-testable resolver:

```
resolveCancelTarget(pool, params) (*supervisor.Supervisor, error)
  = decodeSessionID → pool.Lookup(id) → sess.Supervisor()
```

`cancelSessionHandler` calls it and returns `(nil, nil)` on success. **Delivering
the abort keystroke is T9's (#753) job** — this ticket lands only the resolution
seam that reaches the per-session `*supervisor.Supervisor`. A one-line comment
marks `sup` as the T9 extension point.

**The no-response guarantee (AC-4) is structural, not code.** `session/cancel` is
an ACP notification (a frame with `method` but no `id`); the transport's
`dispatchNotification` (`internal/acp/acp.go:246-258`) routes it to the same
handler map but **discards every notification handler's return** — success or
error. So registering the handler is the whole mechanism; a resolution error is
returned only so the notification path logs it, and it too emits no response
frame.

### Registration

Two additive `t.Register` lines in #761's existing `register` closure in
`serveACPWithPool` — alongside `session/new`. No new imports (`errors` and
`internal/supervisor` were already imported by `acp.go`).

### Scope: within-process boundary (architect call)

The ticket delegated the within-vs-across-process "existing session" boundary to
the architect. **Decision: within-process only.** `pyry acp` stands up a fresh
**in-memory** pool per invocation (#761 leaves
`RegistryPath`/`ClaudeSessionsDir` zero → no persistence, no reconcile) and is a
one-shot stdio subprocess bound to one host connection. The sessions a host can
address are exactly the ones it opened via `session/new` in this process — all in
memory. Cross-process reload (an id a prior process created) would need
`RegistryPath` + reconcile wired into the ACP standup — **new persistence work,
out of scope, deferred.** The within-process boundary satisfies the behavioural AC
("resume an existing session by id") for every id this process can produce with
**zero** persistence work; the reload path is additive when a future ticket needs
it.

## Patterns established

- **Two verbs, one resolution seam → one S.** `session/load` and `session/cancel`
  are independent (no ordering dependency) but share exactly the id-resolution
  (`Pool.Lookup`), the `sessionId` decode, and the registration closure, so they
  land together. The shared decode returning `*acp.Error` — satisfying both the
  request path's typed-wire-code need *and* the notification path's
  plain-error-logged need — is what lets one function serve both with no
  conversion.
- **Resume = `Lookup` + `Activate`, never `GetOrCreate`.** The miss semantics are
  the whole point: an unknown id must error with no side effect (no spawn), which
  `Lookup` + `ErrSessionNotFound` gives and `GetOrCreate` (creates-on-miss)
  breaks. `Activate`'s already-active idempotency is what makes divergence-6's "no
  second claude" hold — reuse of an existing invariant ([ADR 026](../decisions/026-embedded-acp-pool-exact-one-claude.md)),
  not new code.
- **A notification verb needs no response-suppression code.** The transport's
  `dispatchNotification` guarantees no-response structurally; a new notification
  method is just a `Register` call. (Contrast the request path, where the handler's
  return shapes the wire frame.)
- **Factor the routing resolver out of the notification handler.** Extracting
  `resolveCancelTarget` makes AC-4's "resolves onto the correct session's
  supervisor" provable by pointer-equality in a unit test *today* — with no T9
  abort logic — and gives T9 a named extension point *tomorrow*. `sup` is consumed
  by the resolver's test now and by T9's handler later; it is not dead.

## Code review

**PASS** — merged in [PR #764](https://github.com/pyrycode/pyrycode/pull/764).
`make check` green (`go test -race`, `go vet`, staticcheck, substrate-guard);
real-claude e2e green (`internal/e2e/realclaude` 152s). The reviewer verified the
empty-id bootstrap trap is closed, divergence 6 holds via the argv-line-count
proof, AC-2 spawns nothing, and AC-4's no-response is structural. One **NIT**
(non-blocking, not actioned): `decodeSessionID` returns the message
`"missing sessionId"` for the empty-string case as well as the genuinely-absent
case — both correctly map to `CodeInvalidParams`, so behaviour is right; the doc
comment already explains the empty-string rejection is the bootstrap-trap guard.

## Lessons learned

- **The shared `sessionId` decode must reject an empty string *before*
  `Pool.Lookup`.** `Lookup("")` resolves to the parked bootstrap session (not an
  error), so an empty id would otherwise let a host resolve — and `session/load`
  activate — the bootstrap. The empty-string guard in `decodeSessionID` is the
  fix; it is not cosmetic input-validation but a correctness gate on a deliberate
  control-plane seam repurposed here.
- **`session/cancel`'s no-response guarantee is structural, not code.**
  `dispatchNotification` discards every notification handler's return, so
  registering the handler is the entire mechanism — no response-suppression logic
  needed. This is why cancel needed only lifecycle routing and no transport
  plumbing.

## Testing

All new, in `cmd/pyry/acp_test.go` — extending #761's transport-driven,
fake-claude harness (paired `io.Pipe`s + argv-line counting; no real claude, no
TTY). A reusable `acpHarness` (`send`/`read`/`shutdown` over a `newFakeClaudePool`
standup) was factored out of #761's single test.

- `TestDecodeSessionID` — table: valid round-trips; missing / empty / non-string /
  null / garbage / absent → `CodeInvalidParams` (the empty-string case is the
  `Lookup("")` bootstrap-trap guard).
- `TestResolveCancelTarget` — the strongest AC-4 proof: a known-id cancel resolves
  onto that session's own supervisor by **pointer equality** to
  `pool.Lookup(id).Supervisor()`; unknown / malformed id → error (an `*acp.Error`
  with `CodeInvalidParams`).
- `TestACP_SessionLoad_ResumesExistingClaude` — AC-1 + AC-3/divergence-6:
  `session/new` → id, then two `session/load`s of that id both succeed and echo
  the id; the argv file stays **exactly one** line (no second claude), argv
  exactly `--session-id <id>`.
- `TestACP_SessionLoad_UnknownID_NoSpawn` — AC-2: unknown id → `CodeInvalidParams`,
  **zero** argv lines (bootstrap evicted, nothing spawned).
- `TestACP_SessionLoad_MalformedParams` — missing / empty / absent `sessionId` on
  the wire → `CodeInvalidParams`, no spawn.
- `TestACP_SessionCancel_NotificationEmitsNoResponse` — AC-4: two cancels (known +
  unknown id) followed by a `session/load` with `id:2`; the **next frame read
  carries `id:2`**, proving neither cancel emitted a response (deterministic, vs a
  racy read-with-timeout). After shutdown the stderr buffer shows **exactly one**
  `notification handler error` (the unknown-id cancel; the known-id cancel logged
  none) and neither wrote a frame.

  ([#753](https://github.com/pyrycode/pyrycode/issues/753))**. This ticket lands
  only the resolution seam (`resolveCancelTarget` → `*supervisor.Supervisor`).

  created; needs `RegistryPath` + reconcile wired into the ACP standup. Additive,
  deferred.
- **Honouring a caller-supplied `cwd`** — deferred with its `security-sensitive`
  flip (#761's note). This ticket accepts no caller path.
