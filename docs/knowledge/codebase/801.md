# Ticket #801 — live-wire the permission proxy into the ACP session

The **composition-root wiring** that gives [#752](752.md)'s `acpPermissionProxy`
its **first non-test caller**. When the supervised claude raises an on-screen
permission modal, pyry now issues an outbound `session/request_permission` `Call`
to the ACP host and routes the host's choice back into claude's live prompt as the
resolving keystroke ([ADR 027](../decisions/027-acp-mapping.md) divergence 2).
Before this ticket `newACPPermissionProxy` had **zero non-test callers** and its own
doc said so — the adapter was built and unit-tested (#752) but nothing in the
`pyry acp` composition root constructed it or fed it a modal-event source. Epic
[#600](https://github.com/pyrycode/pyrycode/issues/600) T8-wiring, and the **exact
twin of [#796](796.md)** (which live-wired the outbound turn stream): this is the
last unwired ACP outbound adapter before the [#754] conformance capstone can observe
divergence 2 in a full run.

**Pure wiring.** The round-trip / `route` / deny / one-shot logic already lives in
the frozen proxy; this ticket supplies its **three collaborators** and the
**per-session lifecycle** — no round-trip logic is (re)designed. **security-sensitive**
(inherited from #752): it wires an outbound tool-permission **policy** surface with
default-safe-deny; the label tracks the permission-decision design, not the
local-trusted ACP stdio transport.

Full package documentation:
[features/acp-package.md § Permission-proxy wiring (#801)](../features/acp-package-acp-permission-proxy-session-request-permission.md#permission-proxy-wiring-801).

## Implementation

**1 production file (new) + 1 edited**, plus one new test file. **No new package,
no new exported type, no constructor-signature change** — additive within-`cmd/pyry`
wiring of a pre-built primitive, and `acp.go` is **untouched**.

### Placement: fold into the existing per-session manager

`acpTurnStreams` (`cmd/pyry/acp_turn_streams.go`, the #796 turn-stream manager)
already owns **exactly** the collaborators and lifecycle the permission proxy needs
— `ctx` (runCtx), `dir`, `transport` (via `attach`), `logger`, the `started`
idempotency map, and the `wg` that `wait()` joins. Rather than stand up a parallel
manager (and thread a second `start`/`wait`/`attach` through `acp.go` and both
session handlers), the permission drain is **folded into the same `start(id)`**: one
manager, one `started` mark per session guarding both goroutines, one `wait()`
joining both. The manager now owns **two** outbound adapters per session (turn
producer + permission drain); its type doc is broadened to say so. A rename to
`acpSessionStreams` was **rejected** — it fans out across `acp.go` + both session
handlers + two test files for zero behavioural gain. Keep the name; broaden the doc.

### `cmd/pyry/acp_permission_streams.go` (new, ~94 LOC)

Three things:

- **`const acpPermissionTimeout = 2 * time.Minute`** — bounds each outbound
  `session/request_permission` `Call`; a host that never answers denies-and-unblocks
  after this window rather than wedging claude. Mirrors the daemon's
  `modalDenyTimeout` (`internal/relay/v2session.go:81`) for policy consistency across
  the mobile and ACP permission legs. A **package const, not a constructor param** —
  the value is fixed policy, so plumbing it through `newACPTurnStreams` would be churn
  for no configurability.
- **`startPermissionProxy(host *supervisor.Supervisor, sessionID string)`** (method
  on `*acpTurnStreams`) — the manager glue. Constructs
  `newACPPermissionProxy(m.transport, host, sessionID, acpPermissionTimeout, m.logger)`,
  where `m.transport` is the `permissionCaller` (`*acp.Transport`, set by
  `attach`), and `host` is **both** the `modalKeystroker` (`Answer`/`SendEsc` via
  `sess.Supervisor()`) **and** the `turnbridge.SessionHost`. Builds a fixed-target
  subscriber **identical in shape to the turn stream's**: a `resolve` closure
  returning `turnbridge.Target{Host: host, Resolve: resolveBoundSessionJSONL(m.dir, sessionID), Switch: nil}`,
  wrapped by `turnbridge.NewTargetSubscriber(resolve, tuidriver.NewTracker(...), m.logger)`
  with a **fresh** `Tracker` per session. Then `m.wg.Add(1)` and
  `go runPermissionModalStream(m.ctx, sub, proxy)`.
- **`runPermissionModalStream(ctx, sub, proxy)`** — the modal drain **and the AC3
  test seam**. The ACP sibling of `runModalStream` (the mobile modal-surfacer leg,
  [#798](798.md)) but **simpler**: no `screenText`, **no per-kind pre-filter** — it
  hands *every* raw `tuidriver.Event` straight to `proxy.Handle`, which owns the
  filter (no-ops every non-permission event). Outer/inner loop verbatim in shape from
  `runModalStream`/`Producer.Run`: `sub(ctx)` errors only on ctx-cancel → return; a
  received event → `proxy.Handle(ctx, ev)`; a closed channel (session restart) →
  break to re-subscribe onto the now-live session (follow-restart). Logs **nothing
  itself** (mirrors `runModalStream`) — the proxy owns all logging, all content-free.

### `cmd/pyry/acp_turn_streams.go` (edit, one call + doc)

Inside `start(id)`, immediately after the turn-producer goroutine is spawned:

```go
m.startPermissionProxy(host, sessionID)
```

`host` (`*supervisor.Supervisor`) and `sessionID` (`string(id)`) are both already in
scope. The type-doc comment is broadened to note the manager now owns the per-session
**permission-proxy drain** alongside the turn producer — both spawned by `start(id)`,
both disabled when `dir == ""`, both under the same `started` mark, both joined by
`wait()`.

### Why the modal drain still needs the JSONL resolver

`NewTargetSubscriber` opens the unified event stream via `sess.Events(ctx, path, off, tr)`,
which is **JSONL-gated** (`WaitForSessionJSONL` before open). Modal events are
PTY-sourced, but the subscriber surfaces them *through* the JSONL-tailing stream, so a
valid JSONL `path` is required to open it at all. Hence `resolveBoundSessionJSONL` is
reused verbatim, and hence `dir == ""` (no `$HOME` / unresolvable sessions dir)
disables the permission drain by the **same `start()` guard** that disables the turn
stream — correct, because the drain cannot function without the JSONL path, and in
production `runACP` always supplies a non-empty `claudeSessionsDir`.

### Data flow

```
claude PTY modal (EventKindPtyModalShown, ModalClassPermission)
  → NewTargetSubscriber(fixed Target: host=supervisor, resolveBoundSessionJSONL(dir,id), Switch=nil)
  → runPermissionModalStream ──every raw event──▶ proxy.Handle(ctx, ev)
       └─ handleShown → go runRoundTrip(cctx=WithTimeout(m.ctx, 2m), …)
            → transport.Call("session/request_permission", {sessionId, options[4]})
            → route(host reply):
                 selected + optionId ∈ set → Answer(idx+1)      (allow)
                 anything else / timeout / teardown → SendEsc   (deny)
```

## Concurrency & lifecycle

- **Two goroutines per session, one join.** `start(id)` now spawns the turn producer
  (`prod.Run`) **and** the permission drain (`runPermissionModalStream`), both under
  `m.wg`, both parented on `m.ctx` (runCtx). `wait()` (called after `cancel()` in
  `serveACPWithPool`) joins both. The `started` map marks the id once, so a duplicate
  `start(id)` (a `session/load` after `session/new`) re-spawns **neither** — exactly
  one of each per session.
- **Second `Session.Events()` subscription is blessed.** The permission drain opens a
  second `Session.Events()` on the same bound `*tuidriver.Session` alongside the turn
  stream's. tui-driver explicitly supports this — two `Events()` calls = two
  independent merge loops over their own JSONL tail + poll, sharing no mutable state.
  A **fresh `Tracker` per subscription** keeps that invariant (never shared with the
  turn stream's Tracker).
- **The proxy's single-goroutine invariant holds.** `runPermissionModalStream` is the
  **sole** caller of `proxy.Handle`, so `p.inflight` (touched only by the drain
  goroutine) never races. The only cross-goroutine handoff — to the detached
  round-trip goroutine — is the proxy's own `atomic.Bool` one-shot.
- **Round-trip goroutine lifecycle (no leak).** `handleShown` spawns a detached
  `runRoundTrip` with `cctx = context.WithTimeout(m.ctx, acpPermissionTimeout)`.
  Because `cctx` **descends from `m.ctx`**, teardown-cancel unblocks any in-flight
  `Call` immediately: it returns `ctx.Err()`, `route` denies (ESC), the goroutine
  exits in microseconds. It is **not** `wg`-joined (the frozen proxy owns its spawn;
  the wiring cannot join it) but it is ctx-bounded and cannot outlive teardown — the
  **drain** is the joined unit, matching the turn stream's discipline.

## Patterns established

- **Wire the frozen adapter by folding into the existing per-session manager, not a
  parallel one.** When a second outbound adapter needs the *same* per-session
  lifecycle a manager already owns (ctx, transport, dir, `started`, `wg`), add one
  `m.wg`-tracked goroutine inside the existing `start(id)` rather than duplicating the
  whole `start`/`wait`/`attach` scaffold. Cost: the manager's name now under-describes
  it — broaden the doc, don't rename (a rename fans out across the composition root and
  both session handlers for zero behavioural gain). This is the ACP twin of the #796
  turn-stream wiring, using the manager #796 built.
- **The drain hands every event through; the proxy owns the filter.** Unlike the
  mobile modal leg (`runModalStream`, which pre-filters kind and sources a screen
  render), the ACP drain is a mapper-free, filter-free loop — `proxy.Handle` no-ops
  every non-`ModalClassPermission` event internally, so the wiring needs no
  (expensive) screen snapshot to guard. Simpler *because* the frozen adapter already
  does the discriminating.
- **A fixed-policy timeout is a package const, not a constructor param.** Plumbing a
  value that is never configured through `newACPTurnStreams` is churn for no
  configurability. `acpPermissionTimeout` mirrors the daemon's `modalDenyTimeout` at
  the package level; a future ACP-specific answer window is a one-line const change.
- **ctx-descent is the no-leak contract for a goroutine you cannot join.** The frozen
  proxy spawns its own detached `runRoundTrip`; the wiring can't `wg`-join it. Deriving
  its `cctx` from the manager's `m.ctx` makes teardown-cancel unblock its in-flight
  `Call` and force a microsecond exit — the **drain** is the joined unit, and the
  round-trip is provably ctx-bounded (demonstrated by the in-flight-teardown test).

## Lessons learned

- **Fold, don't fork, when a manager already holds the lifecycle.** The obvious shape —
  a parallel `acpPermissionStreams` manager mirroring `acpTurnStreams` — would have
  duplicated `attach`/`start`/`wait`/the `started` map/the `wg` and threaded a second
  set through `acp.go` and both session handlers. Folding the permission drain into the
  existing `start(id)` touched `acp.go` **not at all** and changed no constructor
  signature; the price is a one-word-stale manager name, paid down by broadening the
  type-doc instead of renaming.
- **A "wire the frozen adapter" ticket really is pure wiring — resist re-deriving.** The
  option mapping (`toACPOptions` / `modalbridge.PermissionRequestForClass`), the four
  ACP kinds and their order, the default-safe `route`, and the one-shot all live in the
  frozen proxy. The wiring's whole job is the three collaborators + the drain loop;
  re-deriving any of the round-trip logic would have been both out of scope and a
  divergence risk against #752's security-reviewed adapter.
- **Reuse the sibling adapter's exact subscriber shape.** The turn stream's fixed-target
  `resolve` closure + `resolveBoundSessionJSONL` + fresh-`Tracker` pattern transplants
  verbatim (it's target-agnostic — the modal drain and the turn producer differ only in
  their sink, `proxy.Handle` vs `OnEvent`). Building a fresh resolver + Tracker **per
  session** (not shared) preserves the #671 cold/warm offset reset and the
  one-Tracker-per-subscription no-race invariant, same as #796.

## Testing

New test file `cmd/pyry/acp_permission_streams_test.go` (package `main`), table-free
scenario tests, `-race`-clean, **reusing** existing doubles with zero duplication:
`scriptedSubscriber` / `waitClosed` (from `interactive_turn_stream_v2_test.go`), and
`fakePermissionCaller` / `newSyncKeystroker` / `selectedResp` / `generousTimeout` /
`discardLogger` / `auditLogger` (from `acp_permission_test.go`). Every test drives the
**production** `runPermissionModalStream` through a `scriptedSubscriber` with **no live
claude modal** — the deterministic seam #754 consumes to observe divergence 2.

- **`TestACPPermissionStreams_ScriptedModalRoutesSelection` (AC1/AC3)** — one
  `permissionShown()` event through the wired drain issues exactly **one** `Call` to
  `session/request_permission` carrying the session id and the four options in fixed
  order with kinds `allow_once`/`allow_always`/`reject_once`/`reject_always`; the host
  selects **`reject_once`** (the 3rd option) and the drain routes `Answer("3")` (digit
  = index+1 — a passing assertion proves the index→digit map is real, not "always 1"),
  no `SendEsc`. Proves the wiring, not just the proxy — the analog of
  `TestACPTurnStreams_ScriptedTurnEmitsOrderedFrames`.
- **`TestACPPermissionStreams_NeverAnsweringHostDenies` (AC2)** — a `Call` that blocks
  until its ctx fires + a short (20 ms) per-Call timeout → after the window the drain
  routed exactly `SendEsc`, never `Answer`. Default-safe-deny survives **in the wired
  path**, not only in the isolated adapter.
- **`TestACPPermissionStreams_TeardownDeniesInflightAndJoins` (AC4)** — a round-trip
  blocked inside the `Call`; `cancel()` the drain ctx → the Call's `cctx` (descended
  from the drain ctx) fires, the round-trip routes the safe deny (ESC), and the drain
  goroutine returns. **No in-flight goroutine outlives teardown.**
- **`TestACPPermissionStreams_NoOptionIDLogLeak`** — a forged canary `optionId` denies
  and the canary appears in **no** debug-level log field, driven through the wired
  chain (content-free preservation; mirrors the proxy's `_NoOptionIDLeak`).

**Free regression coverage:** `TestACPTurnStreams_LifecycleTeardownJoinsProducer` and
`TestACPTurnStreams_EmptyDirDisablesStreaming` now *also* exercise the permission drain
(via the shared `start()`) — the lifecycle `wait()` joins both goroutines, the empty-dir
guard disables both. Both pass unchanged.

## Out of scope (deferred)

- **Hard `wg`-join of the detached round-trip goroutine.** `runRoundTrip` is ctx-bounded
  (via `cctx` descending from `m.ctx`) but not `wg`-joined — the frozen proxy owns its
  spawn, so a `goleak`-style hard-join assertion would require a proxy change. The
  design's position: ctx-bounded exit satisfies AC4's "no leaked goroutine," demonstrated
  by the in-flight-teardown test. Additive follow-up if ever needed.
- **ACP-specific permission-answer window.** `acpPermissionTimeout` reuses the daemon's
  2-minute `modalDenyTimeout`. If the ACP host UX wants a different window, that's a
  one-line const change; not designed as configurable now (evidence-based — no observed
  need).
- **`toolCall` correlation.** The gating tool-call id (from the turn stream's
  `ToolStart`) is still `omitempty`-reserved in `requestPermissionParams`; correlating it
  across the two subscriptions is a separate ticket, inherited from #752's scope note.
