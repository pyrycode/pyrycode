# Ticket #1291 — The publishable run record: process evidence and the runner path recorded as observed

Adds `internal/e2e/realclaude/finding_run_record_test.go` (1061 lines,
purely additive, offline, `e2e_realclaude` build tag). Builds `finRecordRun`,
the record one probe run publishes — pyry's exit code, every matched row's
identity, the per-pid liveness verdicts, the reap-log attribution, the
embedded trailer sub-record, and the runner path — plus `finRecordBuild`, the
pure projection that produces it from synthetic readings. Split from #1285;
blocked by #1290 (merged), whose `finTrailerRecord` this record embeds whole.
The artifact writer and its full multi-input no-captured-bytes sweep are
#1286's, out of scope here.

## Implementation

- **`finRecordProc` — three `int` fields and nothing else** (`PID`, `PPID`,
  `PGID`). A field typed `[]reachProc` would pass every test in the file
  while keeping `Command`/`Needles` one edit away; the row type makes the
  argv prohibition true by construction, asserted by a reflection walk over
  the type's fields (all three must be `reflect.Int`) rather than argued in
  a comment. The three integers are not a reduced fallback — a live run of
  this shape matches two rows sharing a pgid, one the other's parent, and
  that relationship is exactly what the integers let a reader of the issue
  check that a bare count could not.

- **`finRecordRun`** embeds `Attribution finAttributeRecord` (#1280) and
  `Trailer finTrailerRecord` (#1290) whole, carries `Liveness
  []pinStateOutcome` whole (ties verdicts to rows via the outcome's own
  `PID`/`PPID` — no row-index field added), and publishes both runner
  readings plus a three-valued `RunnerAgreement`. No scalar field carries
  `omitempty`: `ExitCode == 0` is a real successful exit, and a caller with
  no observed exit must hand `pinExitStatusUnknown` instead of leaving the
  field unset — a documented caller obligation, not a validated one (no
  builder in this family validates its inputs, and no such miswrite has
  been observed).

- **`finRecordInputs` uses named fields, not positional parameters** —
  departing from `finAttributeFanOut`/`finTrailerBuild` for one reason: of
  the eight inputs, `RunnerFromEnv` and `ClaudeCommand` are adjacent,
  same-typed strings on opposite sides of the argv prohibition. Positional
  transposition would write verbatim claude argv into `runner_from_env`
  with nothing going red; named fields make that transposition a compile
  error. The struct has no `trailObservation` field and no `trailScanResult`
  field — that absence is the whole of AC2's structural half, keeping
  `trailScanResult.Trailer` (nil unless `State == trailSeen`, panics loudly
  on a bare deref) out of reach.

- **Two properties, stated separately.** The record is trap-free by
  construction (no field can hold argv, the observation is unreachable by
  the input struct's shape). The builder is not — `in.Rows[i].Command` and
  `in.ClaudeCommand` are verbatim argv in reach inside `finRecordBuild`, and
  that no-captured-bytes property is held by the Detail content rule plus
  the AC4 test, the same posture `finTrailerBuild` occupies for `Line`.

- **`finRecordRunnerAgreement(fromEnv, fromArgv string) string`** — the one
  new reduction. Compares **labels**, not whole readings: the env and argv
  producers each append their own parenthesised reason, so the full strings
  are never equal even when both name the same runner (a whole-string
  compare would report `disagree` on every run). `indeterminate` is checked
  **first** and is a third answer, not folded into `disagree` — it says the
  argv was not read, not that the run took the other path. Only the argv
  side can produce it; there is deliberately no dead arm for an
  indeterminate env reading. `finRecordRunnerLabel` extracts the token
  before `" ("`; its degenerate no-`" ("` path returns the whole string,
  failing toward `disagree` rather than a false `agree` — defensive only,
  since both shipped producers always emit a parenthesised reason.

- **`finRecordBuild(in finRecordInputs) finRecordRun`** is pure — no exec,
  no clock, no filesystem, no `*testing.T`, never fails a test. Converts
  `[]reachProc` → `[]finRecordProc` at the single conversion point
  (dropping `Command`/`Needles`), reduces `ClaudeCommand` via
  `tdnRunnerFromArgv` to one of three constant strings, caps
  `ClaudeVersion` through `reachCapCommand` (the live caller's error path
  interpolates the resolved binary path — an operator's home directory —
  into a record destined for a public issue), and builds `Detail` from
  derived scalars only (counts, labels, the agreement verdict, the
  attribution's selected value, the trailer outcome) — never a `%v` on an
  input struct or slice, which is the concrete mechanism the argv
  prohibition guards against.

- **Five tests, one per AC, all offline:**
  - `TestFinRecordCarriesEveryMatchedRow` (AC1) — two rows (wrapper +
    command, shared pgid, one the other's parent); asserts the
    relationship survives, not just the values, and asserts the
    **cross-reference** (every `Liveness[i].PID` lands inside the
    published row set) rather than the echo (the handed-in outcomes come
    back unchanged) — the latter is a tautology over a pass-through field.
  - `TestFinRecordLivenessIsConsumedAsHanded` (AC1, second half) — drives
    all four `pinState*` values through one call and pins all four carried
    out **distinct**, so a record that collapsed liveness to a boolean
    fails to even express the claim, not merely to satisfy it.
  - `TestFinRecordEmbedsTrailerRecordWhole` (AC2) — `reflect.DeepEqual`
    against a `finTrailerBuild`-produced record, plus a reflection walk
    over `finRecordInputs`' fields asserting none is typed
    `trailObservation` or `trailScanResult`.
  - `TestFinRecordRunnerAgreement` (AC3) — three rows: streamrunner argv
    vs. ptyrunner env → `disagree`; ptyrunner argv vs. ptyrunner env →
    `agree` (the row that fails against a whole-string comparison,
    asserted in the same subtest); neither-marker argv →
    `indeterminate`, not `disagree`. `PYRY_USE_STREAMJSON` is pinned in
    the env delta rather than left unset.
  - `TestFinRecordCarriesNoCapturedBytes` (AC4) — plants `trailNeedle` in
    every input row's `Command` and in `ClaudeCommand`, asserts a
    non-vacuity precondition first, sweeps the marshalled record and
    `Detail` separately, and asserts per-row headroom
    (`reachMaxCommandBytes - len(Detail) >= len(trailNeedle)`) on the
    **built** record — the channel #1284 shipped leaking through a
    cap-exhausting Detail.

- **Reuse, not rebuild.** `finAttributeFanOut`, `finTrailerBuild`,
  `trailReapLine`, `trailDetail` (no `finDetail` twin — settled twice
  already, #1280/#1284), `tdnFixturePtyArgv`/`tdnFixtureStreamArgv`,
  `reachCapCommand`/`reachMaxCommandBytes`. `finRecordLivenessValues` /
  `finRecordMatchedRows` / `finRecordEnvDelta` are functions, not
  package-level `var`s, for `trailRunWellFormed`'s stated reason: a shared
  backing array is reachable from every test in the package under
  `go test -race`.

- **AC5 (offline-only)** discharged the same way #1290 fixed it after
  being burned once: every forbidden helper (`probeClaudeVersion`,
  `resolveClaudeBin`, `WithWorktreeAuthenticated`, `pinReadState`,
  `pinExit1`, `pinScanArgv`, `probeProcessSnapshot`, `tdnScan`,
  `holdProbeFIFO`) is named in the header **by file and line rather than
  by name**, so the mandated grep for those symbols reports on this
  file's code and can't be defeated by its own prose. See Lessons learned
  below for the one place this still slipped on first pass.

## Patterns established

- **A row type of pure scalars, reflection-asserted, is how "never its
  argv" becomes structural rather than disciplinary.** `finRecordProc`'s
  three-`int` shape is checked by walking `reflect.TypeOf(finRecordProc{})`
  and asserting every field is `reflect.Int` — the same move
  `finAttributeEntry` made for #1280, now the second instance in the
  family. A future field addition of the wrong kind fails a test, not a
  code review.
- **Comparing two producer-generated strings for "same underlying value"
  requires comparing an extracted label, never the whole string, when each
  producer appends its own free-text reason.** `finRecordRunnerAgreement`
  is the first place in this family that reduces two humanish strings to a
  verdict; `finRecordRunnerLabel`'s prefix-extraction is the general shape
  for any future comparison of two independently-worded readings of the
  same closed value space.
- **`indeterminate`-before-`disagree` ordering is what makes a third
  answer structural.** Checking the argv-side indeterminate arm first,
  before any label comparison runs, is what keeps "no reading" from ever
  being mistaken for "reading disagrees" — an ordering choice worth
  re-checking whenever a new three-valued (or wider) verdict is added
  elsewhere in this family.

## Lessons learned

From the PR body (#1293) and code review:

- **A mandated `exec.` grep is defeated by the file's own prose, the same
  way #1290's `t.Skip` grep was — twice now in this family.** The
  forbidden helpers were referenced by file:line specifically so the
  symbol grep wouldn't false-positive on this file's own prose, but the
  plain `exec.` grep still matched two comment lines (`` `exec.` `` in
  prose, `*exec.ExitError` in a note) before being reworded. **General
  rule for this family: any file whose AC is "this grep returns nothing"
  must keep the pattern itself out of its own comments**, not just out of
  its forbidden-symbol references.
- **Green-on-first-write proved nothing here either; mutation testing
  found the one real gap.** Nine of ten spec-mandated mutations reddened
  immediately, but `ClaudeVersion`'s inbound `reachCapCommand` had no
  assertion at all — the AC driving `ClaudeVersion` used a short string
  that a dropped cap wouldn't touch. Added a capped-version assertion
  using an intentionally overlong fixture. An unasserted cap is a claim
  living only in a comment.
- **Code review's one SHOULD FIX was not landed before merge, and is worth
  a future editor's attention.** The attribution sub-record's "carried
  whole, never rebuilt" claim is asserted via a single nested scalar
  (`rec.Attribution.Selected.Value != in.Attribution.Selected.Value`) while
  its failure message claims the whole-carriage property; the trailer half
  twenty lines below does this correctly with
  `reflect.DeepEqual(rec.Trailer, sub)`, which reddens under the equivalent
  mutation while the attribution check does not (code review verified this
  by mutating the builder to drop `Attribution.Entries` and observed the
  suite stay green). Decision was PASS with this left as a non-blocking
  SHOULD FIX rather than fixed inline — mirrors the same asymmetric-pinning
  shape #1280 shipped with (deferred there to #1281). If #1286 or a later
  ticket touches this file, tightening that one assertion to
  `reflect.DeepEqual` is a one-line fix with a known-good template beside
  it.
- **Headroom was measured, not assumed, and the counts-not-pids rule is
  what keeps it independent of input size.** Built Details land at
  195–217 bytes across the three AC4 rows, 295–317 bytes of headroom
  against the 42-byte needle — roughly 7× the requirement — because the
  Detail names counts and labels rather than every row.
- **523 code lines against a ~400 projection, 30% over the family's prior
  siblings (354–411).** Explicable rather than gold-plating: this record
  composes three sub-records (two embedded whole) and adds a recursive
  `reflect`-based reachability walk the siblings didn't need. Worth
  folding into the next architect's size calibration for any ticket in
  this family that composes multiple existing sub-records rather than
  building one net-new shape.

## Code review

**PASS**, one SHOULD FIX (attribution whole-carriage assertion — see
Lessons learned) plus three NITs, none blocking:

- `finRecordRunnerLabel`'s degenerate path has no test row; the safe
  direction is stated in a comment and is genuinely unreachable from both
  shipped producers today.
- `RunnerFromEnv` is retained uncapped while `ClaudeVersion` is capped, an
  asymmetry with no live channel behind it (the shipped producer returns
  one of two constants) — noted, not requested as a change.
- The Detail's third AC3 row reads "...which indeterminate" rather than
  "...which is indeterminate" — a dropped word, three bytes against
  ~300 bytes of headroom.

Independently verified in review: `make e2e-realclaude` reported 88 PASS /
46 SKIP under `-v` (skips are the pre-existing live-credential baseline);
all five new `TestFinRecord*` tests passed. Eight mutations run via
`go test -overlay` against the builder, each asserted to be a real edit,
all eight reddened against the right channel — including the
`trailObservation`-added-back-to-inputs mutation (caught by the recursive
reachability walk, not a shallow scan) and the truncation-hiding Detail
mutation (caught by the headroom assertion firing before the containment
check, the exact #1284 defect now structurally impossible here). AC5's
three greps (`t.Skipf?\(`, `exec\.`, the nine-symbol forbidden-name
alternation) all reported clean. `finRecord` census: 124 hits confined to
the new file; control `trail[A-Z]` = 1098 (non-zero).
