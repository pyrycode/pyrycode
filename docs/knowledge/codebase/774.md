# Ticket #774 — tear down an idle encrypted v2 session (in-repo idle sweep)

A phone's encrypted v2 session (`V2Session`) holds two Noise `CipherState`s and an
armed 1-hour `rekeyTimer`. The relay↔binary leg is a **single multiplexed WebSocket**
with **no per-connection disconnect frame**, so when a phone drops or backgrounds
(the protocol says phones close-on-background, then push-to-wake) the binary receives
*nothing* for that `conn_id`. Before this slice the stale session lingered until its
scheduled rekey fired (up to an hour later), went unanswered, and only then timed out
at WS 4426. Under normal connect/disconnect churn these idle encrypted sessions
accumulated. This slice adds an **in-repo idle sweep**: an open session that receives
no inbound frame within a bounded window is torn down through the existing `closeWith`
path, bounding the lifetime of the cipher states and the armed rekey timer.

Filed from the 2026-07-03 Cross-Repo Code Review (the daemon side of "the relay never
implements the disconnect half of the routing contract"). This is the ticket body's
**option b** — the self-contained in-repo sweep. Option (a), a relay-emitted
per-connection disconnect signal, is cross-repo relay work that does not exist in this
repo and is out of scope (a future exact-teardown-on-disconnect ticket can supersede or
complement the sweep). `security-sensitive`; spec-stage security review verdict **PASS**.

## Implementation

One production file changes (~103 LOC), additive — no new files, no new package, no new
exported type beyond the close code, no signature changes, no new goroutine topology.
The whole mechanism reuses the **existing** `time.AfterFunc → wakeSignal → handleWake`
machinery (#450) and the **existing** `closeWith` teardown (#446).

| File | Change |
|---|---|
| `internal/relay/v2session.go` | **The idle timer lifecycle + fire.** New exported close code `StatusIdleTimeout websocket.StatusCode = 4408` (in the existing const block, beside `StatusProtocolMismatch`/`StatusHandshakeFailure`). New package var `idleTimeout = 15 * time.Minute` (lowercase, test-overridable, mirrors `rekeyInterval`). New `wakeIdleTimeout` `wakeKind` const. Two new Run-owned `V2Session` fields: `idleTimer *time.Timer` and `lastActivityAt time.Time`. New helper `armIdleTimer(ctx, s, d) *time.Timer` (copies `armRekeyTimer`'s callback shape; callback touches only `m.wake`). New `wakeIdleTimeout` arm in `handleWake` (reschedule vs teardown). One-line `s.lastActivityAt = time.Now()` stamp in `handleFrame` after the `V2StateClosed` early-return. `s.idleTimer = m.armIdleTimer(ctx, s, idleTimeout)` armed in `handleNoiseInit`'s success tail beside the rekey timer. `if s.idleTimer != nil { s.idleTimer.Stop(); s.idleTimer = nil }` added to `closeWith`'s existing timer-stop region. |
| `docs/protocol-mobile.md` | **The wire spec.** New `4408` row in § Error codes (direction: binary, forwarded by relay; `v2-new`) + a paragraph explaining the idle-sweep origin, the HTTP-408 echo, and the swept-then-reconnect / dead-conn-no-op semantics. |

### Data flow

```
inbound frame on conn_id X ─► handleFrame ─► s.lastActivityAt = now        (Run goroutine)
                                             (armed idleTimer keeps chasing)

idleTimer fires (fresh AfterFunc goroutine) ─► select{ m.wake<-{s,wakeIdleTimeout} | ctx.Done }
                                             │
Run select ◄─────────────────────────────────┘
   handleWake, wakeIdleTimeout arm:
     state != Open?            → drop (already closed by another path)
     idle < idleTimeout?       → s.idleTimer = armIdleTimer(ctx, s, idleTimeout-idle); return
     else                      → log v2.idle.teardown; closeWith(ctx, s, 4408, nil)
                                   ├─ state = Closed
                                   ├─ stop+nil idleTimer, rekeyTimer, rekeyReplyTimer
                                   ├─ delete m.sessions[X], m.queues[X]
                                   └─ Outbound{ConnID:X, CloseCode:4408, Frame:nil}
```

A later frame on `conn_id X` after teardown lazy-creates a fresh `V2StateAwaitingInit`
session (existing `handleFrame` behaviour) → the returning phone re-handshakes cleanly.

## Patterns established

- **A third mechanism on the wake-channel precedent: single-arm timer that *chases a
  deadline*.** #450 established `time.AfterFunc → wakeSignal → handleWake` for a
  fixed-cadence rekey timer; #725 generalised it to a daemon-global modal timeout. #774
  adds the *deadline-chasing* variant: instead of re-arming on every inbound frame (which
  would churn `Stop`+re-alloc on the hot path), `handleFrame` writes a single
  `lastActivityAt` field and the timer, on fire, either reschedules for the remaining
  window (`idleTimeout - time.Since(lastActivityAt)`) or tears down. `handleFrame`'s hot
  path stays a **single field write**; the timer converges to fire at exactly
  `lastActivityAt + idleTimeout`. This was preferred over a periodic sweep over
  `m.sessions` because that needs a second duration (sweep interval) + a separate channel,
  whereas the AC asked for **one** test-overridable window in the `rekeyInterval` idiom —
  which a per-session timer keyed on `*V2Session` (reusing `m.wake`/`wakeSignal` unchanged)
  delivers with the smallest diff.
- **Stale-wake safety is two *deterministic* guards composed — belt-and-suspenders where
  both fabrics are code.** The `handleWake` arm reads only Run-owned state and composes
  (a) `w.s.state != V2StateOpen` (existing #450 guard — catches "`closeWith` already ran")
  and (b) `idle < idleTimeout` (new — catches "a frame arrived after this timer was armed
  but before the wake was serviced"; `handleFrame` already re-stamped `lastActivityAt`, so
  the reschedule re-points the timer at the fresh deadline). No active session is ever torn
  down by a stale wake, and there is **no second stochastic timer** guarding the first — the
  correct fabric for a safety net (see [PROJECT-MEMORY][pm] "belt-and-suspenders means
  different fabric"). No TOCTOU: read-and-act happen in one synchronous `handleWake` call on
  the owner goroutine.
- **The teardown reuses `closeWith` verbatim; the sweep adds exactly one stop+nil.**
  `closeWith` already sets `V2StateClosed`, stops+nils `rekeyTimer`/`rekeyReplyTimer`,
  deletes the session + push queue, and sends the close-only `CloseCode` envelope. The only
  addition is the `idleTimer` stop+nil in its existing timer-stop region, mirroring the two
  sibling blocks — so the sweep inherits full, tested teardown (both `CipherState`s dropped
  to GC, all per-session timers stopped, maps cleaned) with no new teardown code path.
- **4408 echoes HTTP 408, extending the 44xx←HTTP close-code convention.** The idle-teardown
  code slots into the same convention as 4401←401, 4404←404, 4409←409, 4429←429 (Request
  Timeout → idle-session timeout). No new close-code *family*, just one more row.
- **`idleTimeout` is a lowercase test-overridable package var, not config-driven.** Same
  posture as `rekeyInterval` / `rekeyReplyTimeout` / `modalDenyTimeout`: production cannot
  override the 15-min default (a static program literal — the natural rate-limit against a
  hostile config bump), and tests substitute a sub-second value via save/restore + `t.Cleanup`.
  Wiring it to `internal/config` is deferred, tracked alongside `modalDenyTimeout`'s #708 note.

## Lessons learned

- **`qmd`'s `pyrycode-docs` collection indexes the *canonical* repo checkout
  (`.../Projects/pyrycode/docs`), not the per-ticket worktree.** A `docs/*.md` edit made in a
  dispatch worktree shows as "unchanged" to `qmd update`, and `qmd embed` is a no-op until
  the change merges — so the CLAUDE.md "always `qmd update && qmd embed` after touching docs"
  step is naturally a **post-merge** operation, not something the doc phase can (or should)
  run from inside the worktree. (Lifted from the PR's Lessons-learned section.)

## Out of scope (deferred)

- **Event-driven exact teardown on phone-initiated WS close** — the cross-repo relay work
  (option a). If the relay later emits a per-connection disconnect signal, a follow-up can
  tear down on the exact event and treat this sweep as the coarse backstop.
- **Config-drivability of `idleTimeout`** — deferred, same posture as `modalDenyTimeout`/#708.
- **#647 reconnect-replay reconciliation is not a concern** — a swept session is fully deleted
  (session + queue), so a returning phone re-handshakes from scratch with no `last_event_id`
  continuity to preserve across the sweep.

## Testing

Four new same-package tests in `internal/relay/v2session_test.go`, all deterministic and
`-race`-clean. They override `idleTimeout` to a sub-second value via a `setIdleTimeout(t, d)`
save/restore helper and are **not `t.Parallel`** (they mutate a package var), matching the
`TestV2Session_RekeyInitiator_*` idiom. Two new local helpers support them: `waitForConnClose`
(polls the recorder keyed on `(conn_id, close_code)` so churn tests can wait for one conn's
teardown amid interleaving) and `handshakeConnToOpen` (drives a Noise_IK handshake to open on
an already-running manager, so churn tests can open many conns on one `Run`).

- `TestV2Session_IdleTeardown_FullTeardown` (**AC-1**) — one open conn, no further frames;
  asserts a `RoutingEnvelope` with `CloseCode == 4408` and `Frame == nil`, exactly two total
  envelopes (`noise_resp` + the 4408 close — **no `rekey_request` slips in**, proving the sweep
  pre-empts the unchanged 1-hour rekey since `idleTimeout` ≪ `rekeyInterval`), and both
  `m.sessions[connID]` and `m.queues[connID]` deleted after `Run` stops.
- `TestV2Session_IdleActivity_ReArmsNoPrematureTeardown` (**reschedule arm**) — 8 inert
  `interrupt` app frames at 40 ms intervals span 320 ms > the 200 ms window; asserts **no** 4408
  during the active span (only `noise_resp` recorded), then the 4408 close appears after
  `idleTimeout` past the last frame. Exercises the `idle < idleTimeout` reschedule branch.
- `TestV2Session_IdleChurn_ReturnsToBaseline` (**AC-3**) — connect → handshake → go-idle → sweep
  on 5 distinct `conn_id`s; asserts `ActiveConnIDs` peaks at exactly one and returns to `[]`
  after each idle window — stale sessions do not accumulate.
- `TestV2Session_SweptThenReconnect_ReHandshakes` (**AC-3 reconnect clause**) — after the 4408
  sweep, a fresh `noise_init` on the **same** `conn_id` completes a clean IK handshake yielding a
  valid `hello_ack` (`ProtocolVersion == "v2"`, matching `ConnID`) — no stuck/half-torn-down state.

`go test -race ./internal/relay/...`, `go test -race ./...`, and `go vet ./...` pass.
