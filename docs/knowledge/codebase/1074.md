# Ticket #1074 — surface claude api-retry + compaction status over the v2 relay stream

Threads two new PTY-derived status peers of the existing `stall` event through
the same five-layer interactive-turn pipeline, so a remote head shows "retrying
(attempt N/M)" or "compacting…" instead of a frozen screen or a generic
thinking state. tui-driver **v1.12.0** (already pinned in `go.mod`) delivers both
detectors (`EventKindPtyApiRetry{Shown,Hidden}` / `EventKindPtyCompacting{Shown,Hidden}`)
on the unified `Session.Events` stream the producer already drains — the mapper's
`default` arm previously dropped them. `security-sensitive` (frames forward a
screen-derived attempt counter across the tui-driver substrate seal). PR #1160,
merged as `a5f7bdb`.

## Implementation

**Wire shape decision (architect):** one frame type per state, carrying an
`active` bool, not four paired shown/hidden frame types. The `Shown` edge is
`active:true`; the `Hidden` edge is `active:false` (the AC #3 clear signal). This
keeps the new-exported-type count at 4 and lets tui-driver's api-retry counter
re-fire (3/10 → 4/10) ride through as just another `active:true` frame — no
dedup, no per-tick flood.

The five layers, each an additive echo of the `Stall` exemplar (see
[codebase/639.md](639.md) for the template this ticket repeats one tier up):

1. **`internal/turnevent/event.go`** — two new sealed `Event` variants:
   `ApiRetry{Active bool; Current, Total int}` and `Compacting{Active bool}`.
   Compaction is banner-only (tui-driver streams no progress payload), so it
   carries nothing beyond the edge bool.
2. **`internal/turnbridge/mapper.go`** — four new `mapEvent` arms (Shown/Hidden ×
   ApiRetry/Compacting). The counter is copied on both edges (tui-driver carries
   last-known on `Hidden` "so the final render stays coherent"); the phone
   ignores it when `active:false`. `{0,0}` (unparsed counter) passes through as a
   legitimate "retrying, count unknown" state — no error branch.
3. **`internal/turnbridge/outbound.go`** — two new `MapEvent` arms mirroring the
   `Stall` arm: conversation-id only, `tc.TurnID`/`tc.Seq` ignored (not
   turn-scoped, not a delta).
4. **`internal/protocol/codes.go`** + **`interactive.go`** — `TypeApiRetry`
   (`"api_retry"`) / `TypeCompacting` (`"compacting"`) consts, and
   `ApiRetryPayload{ConversationID, Active, Current, Total}` /
   `CompactingPayload{ConversationID, Active}`, both following the package's
   no-`omitempty` rule (boundary values like `active:false`/`current:0` always
   serialize).
5. **`cmd/pyry/interactive_turn_v2.go`** — one merged `Handle` arm,
   `case turnevent.ApiRetry, turnevent.Compacting:` (the developer simplified the
   spec's two separate arms into one, since both bodies are byte-identical —
   flagged as a fine simplification in code review), flushing any pending delta
   then emitting with **no lifecycle mutation** (`startTurnIfNeeded` /
   `transitionTo` / `endTurn` untouched). Two new `eventKind` arms
   (`"api_retry"` / `"compacting"`) for content-free log discriminants.

`producer.go` needed no change — its `drain` loop maps every event via
`mapEvent`, so the new arms are picked up for free.

## Patterns established

- **A second event kind threaded through the same five-layer pipeline in one
  ticket, at the wire-shape level, not the layer level.** Confirms the #639
  precedent generalizes: a new PTY-derived status peer of `stall` is always
  three-to-five additive `case` arms across the same file set, never a new
  interface, package, constructor, or goroutine — regardless of how many event
  *kinds* it introduces, as long as they share one wire-shape decision (here:
  one frame type with an `active` bool, covering two tui-driver kinds each).
- **Two drift-detectors gate a new `protocol.Type*` constant in `cmd/pyry`, not
  one.** Beyond `internal/protocol/compat_test.go`'s `v2OnlyTypes` /
  `TestTypeConstants_V1V2Partition` / `TestIsKnownAppType` trio, `cmd/pyry`'s
  `relay_guard_test.go` (`TestEveryInboundV2TypeHasHandler`) independently
  classifies every `Type*` constant — a new outbound-only type must be added to
  its `excludedTypes` map as `"push"`. The architecture spec's § Testing named
  only the `compat_test.go` trio; the second detector was missed by the spec and
  caught by the developer at build time (`go test ./cmd/pyry` fails
  "unclassified" until it's added). **Both detectors are load-bearing for any
  future v2-only `Type*` addition — check `cmd/pyry/relay_guard_test.go` as well
  as `internal/protocol/compat_test.go`.**
- **Merging identical-body type-switch arms is a legitimate simplification over
  a spec that sketched them separately**, as long as the merge doesn't touch an
  already-tested sibling arm (here, `Stall`'s case stayed untouched) — pinned as
  a non-blocking code-review note, not a deviation requiring rework.

## Lessons learned

- `cmd/pyry` has a second type-classification drift-detector,
  `relay_guard_test.go`'s `TestEveryInboundV2TypeHasHandler`, beyond
  `internal/protocol/compat_test.go`'s trio — the architecture spec's § Testing
  named only the `compat_test.go` detectors. Any new `protocol.Type*` constant
  must also be classified there (outbound-only frames go in `excludedTypes` as
  `"push"`, peers of `TypeStall`), or `go test ./cmd/pyry` fails "unclassified".
  (From the PR body's Lessons-learned section.)

## Scope (S, six production files, zero new)

Six production `.go` files modified (`cmd/pyry/interactive_turn_v2.go`,
`cmd/pyry/relay_guard_test.go` counts as test, so five prod + this test file;
see file list below), zero new production files, four new exported types
(`ApiRetry`, `Compacting`, `ApiRetryPayload`, `CompactingPayload`), zero new
consumer call sites, zero new goroutines/locks/channels. The PO had already
adjudicated the file-count-vs-split question during #1074's own rework (invalid
`size:m` → `size:s`): the count is intrinsic to threading a new event kind
through an already-built five-layer pipeline, not a proxy for real coordination.
Code review: **PASS**, zero findings; real-claude e2e `ok 0.861s` (creds
present).
