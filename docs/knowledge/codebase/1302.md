# Ticket #1302 — Probe instrument: fill the run-outcome gather's pyry-exit and claude-liveness readings from the caller (offline)

Changes two existing files in `internal/e2e/realclaude` (no new file, zero
production `.go` change): `finding_run_gather_test.go` and
`finding_stage_held_group_test.go`. `finGatherReadings` (#1281) staged
`PyryExited = true` and `ClaudeState = ""` in its own body, so neither value
was reachable through the gather — a hardcoding its own doc comment filed as
an obligation to promote *"BEFORE it feeds this gather a live pyry"*. #1282
fed it no pyry at all, so nothing there could distinguish either setting, and
the obligation routed to the first live consumer. This ticket discharges it
offline, ahead of that consumer: both values become fields of a
`finGatherInputs` struct and are copied whole into the readings, no default,
no zero-value rewrite, no `pinIsVerdict` repair. The classifier
(`trailClassifyRun`) is untouched — both arms it needs (Step 3's
`trailOutcomeVoidPyryDidNotExit`, C7's `ClaudeState` out-of-contract check)
already existed and were already tested. Split from #1279.

## Implementation

- **`finGatherInputs` struct, not two extra positional parameters.**
  (`finding_run_gather_test.go:220`.) The four existing parameters
  (`Stdout`, `Needles`, `Stderr`, `Pinned`) move in unchanged; `PyryExited
  bool` and `ClaudeState string` join them. `finGatherReadings` now takes one
  argument: `func finGatherReadings(in finGatherInputs) (trailRunReadings,
  finAttributeRecord)`. `finRecordInputs` (#1281's sibling precedent) argues
  for named fields from a transposition risk that only weakly applies here
  (a `bool` and a `string` can't transpose without a compile error); the
  reason that does apply is `TestFinGatherPyryExitIsObservableAtTheOutcome`'s
  own requirement that its two arms be identical in every field but one —
  over a struct that's `copy the value, change one field`, holding by
  construction instead of by discipline maintained across six positional
  arguments at two call sites.

- **Both new fields keep the readings' own names, types and zero-polarity,
  documented at the field.** `PyryExited`'s zero is `false` → Step 3's void
  (the safe direction, same argument `trailRunReadings.PyryExited` makes for
  itself); `ClaudeState`'s zero is `""`, C7's shipped "not read" — an honest
  report, not an unfilled field. A caller who fills nothing degrades to a
  named nothing-was-measured, never a claim.

- **The body copies both fields verbatim** (`readings.PyryExited =
  in.PyryExited`, `readings.ClaudeState = in.ClaudeState`) — no `if`, no
  `!= ""` guard, no `pinIsVerdict` call. A second opinion in the gather would
  repair exactly the record C7 exists to reject and make
  `run-out-of-contract` unreachable through this composition.

- **`finGatherCase` gains no new field.** All three existing rows in
  `finGatherCases()` want the value the constant held (`PyryExited: true`,
  set once per row on the inputs the row builds), so there is no case-struct
  zero to point anywhere and AC4 (every existing row keeps its outcome) is
  discharged by construction. AC2 and AC3's rows are deliberately **not** in
  that table — `finGatherAssertContract` runs on every row there and fails
  any row that classifies `run-out-of-contract`, so both got their own
  standalone tests.

- **`TestFinGatherPyryExitIsObservableAtTheOutcome`**
  (`finding_run_gather_test.go:764`) is the AC2 test: one `finGatherInputs`
  built on the negative composition (usable gate, `MatchCount == 0`,
  `trailAdmitVoidGroupUnnamed`), gathered once at `PyryExited: true`
  (`trailOutcomeNoRowMatched`) and once — same struct, one field flipped —
  at `PyryExited: false` (`trailOutcomeVoidPyryDidNotExit`). Built on the
  negative arm deliberately: `proofPyryLive` pins the proof arm to
  `trailOutcomeRunningAtTrailer` regardless of `PyryExited`
  (`trail_run_outcome_test.go:695-696, 820-821`), because Step 2 returns
  before Step 3 is ever consulted, so the proof arm cannot produce this pair
  and reordering the classifier to make it would be a defect. The two arms
  share one `Stdout` buffer (`Bytes()` returns a copy of an append-only
  buffer, so reading it twice is genuinely byte-for-byte, not
  "two buffers seeded the same way") and one `Needles` slice (`t.TempDir()`
  mints a new directory per call, so calling the needle helper twice would
  vary a second dimension).

- **`TestFinGatherCarriesTheClaudeVerdictAsHandedIn`**
  (`finding_run_gather_test.go:852`) is the AC3 test, three scenarios: a
  documented verdict (`pinStateRunning`) crosses unchanged and is republished
  verbatim as `claude_state`; an undocumented verdict
  (`finGatherUndocumentedState`, a fixture string distinct from both
  `pinReadState`'s four values and the classifier layer's own
  `"some-verdict-nobody-defined"` fixture) is carried whole and reaches
  `trailOutcomeOutOfContract` — asserted by checking which arm fired via a
  fragment of C7's own sentence, not the value alone, since eight other
  contract checks answer with the same outcome value; and `""`, handed in
  explicitly, reaches a real answer rather than the out-of-contract arm,
  proving the empty value survives as a deliberate caller statement and not
  just an omitted field.

- **The needle exclusion gains a third crossing.** `ClaudeState` is now a
  caller-supplied string that crosses the gather, the classifier and a
  published `Detail` (C7) verbatim, so the obvious reading of #1271's
  "plant the needle in every string-bearing input" is red against correct
  code here — same shape as the existing `terminal_reason` exclusion.
  `TestFinGatherReturnsNoCapturedBytes` (`:959`) now hands the gather
  `pinStateRunning`, a closed-set constant that structurally cannot carry a
  needle, making the exclusion structural in the fixture rather than a
  discipline at the plant site. The file header's verbatim-crossing section
  (`:68-83`) documents `ClaudeState` as the third named crossing.

- **Five call sites updated, all mechanical.** Four rows in
  `finding_run_gather_test.go` (`TestFinGatherComposesTheFindingAndTheNegative`,
  `TestFinGatherEmptyPinnedSetIsNotAReading`,
  `TestFinGatherReturnsNoCapturedBytes`, and the forbidden-key walk) plus
  `finStageRun` (`finding_stage_held_group_test.go:409-435`), which does
  **not** gain a parameter: its five callers all want `PyryExited: true`,
  so the value is set once at the call site with the original justifying
  comment ("no pyry runs in this file, so there is none to fail to exit")
  moved from the gather's body to here. Threading a parameter through five
  callers that all pass the same value would be noise — this ticket makes
  the value passable, not read, everywhere it could be.

## Prose removed (AC1)

Six sites, not just the two staged assignments:

- The file header's *"The two staged values that are still staged, and who
  owns them"* section — deleted; nothing is staged any more.
- The gather's doc comment's "four inputs" count — now names the struct.
- The caller-obligations section's bullet 2 (the promotion obligation) —
  deleted; bullet 1 (`pinned` is `[]int`, never `[]reachProc`) stands.
- The body comment above the two staged assignments — deleted with the
  assignments.
- `finStageRun`'s doc claim *"finGatherReadings stages PyryExited true,
  which closes Step 3"* — rewritten as *"this function PASSES PyryExited
  true"*, since the gather no longer stages anything.
- `finding_stage_held_group_test.go:26`'s line-number cross-reference into
  the deleted bullet — repointed, along with two more stale references a
  package-wide grep for `<file>.go:[0-9]` found beyond the one the spec
  named (`:230` → `:298`, `:100-108` → `:105-113`).

**No replacement sentence claims the staging void displaces the finding.**
The issue's own comment said a hardcoded gather would make a hung-pyry run
"report a scan-side answer — or the finding — instead of the staging void,"
and the "or the finding" half is backwards: Step 2 is consulted before Step
3 by design, and `proofPyryLive` pins a proof-carrying row with
`PyryExited: false` to `trailOutcomeRunningAtTrailer`, not the void. The
promotion moves the outcome of exactly one class of run — usable gate,
attribution not proof — and leaves the proof arm and the non-usable-gate
arms exactly where they were.

## Lessons learned

- The mutation worth running on a promotion ticket is the one that restores
  the *pre-change* body: it reproduces the exact state the ACs describe, and
  by leaving every pre-existing row green in the same run, it demonstrates
  "a caller passing the values the constants held reaches the same outcome"
  more convincingly than re-deriving expectations by hand would.
- Deleting a doc-comment bullet shifts every line-numbered cross-reference
  into that file, including ones the spec didn't name. `grep -rn
  '<file>\.go:[0-9]'` over the package found two stale references beyond the
  one the spec flagged — worth running whenever an edit renumbers a file
  other files cite by line.
