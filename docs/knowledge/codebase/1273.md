# Ticket #1273 — Make M4's failure self-diagnosing in the stream `new_session` e2e

`TestRelayV2_StreamNewSessionRotatesAndRestartsFresh` (#1137) failed once during QA's
`make check` on PR #1272, burning M4's full 20 s `turnTwoDeadline`. The filed report read
the 20.21 s runtime as "near a timeout under load"; it is actually a flat 20.00 s deadline
burn, so everything through ack #2 took 0.21 s — at the *fast* end of the passing range.
The machine was not slow. M4's old message named two readings ("delivery never reached it,
or the rotated session did not re-spawn") and discriminated neither, while a third reading
(a second rotation racing turn #2's delivery) was invisible in the record and is exactly
what the file's own M2 comments already anticipate ("the rare double-actuation case"). This
ticket is diagnostic-only: no fix, no repro, no deadline or retry change. Raising the
deadline was rejected in the ticket's own framing — the msgqueue drain M4 waits on
(`internal/msgqueue/queue.go`, #704) blocks on an idle wake-up with no periodic retry, so a
missed wake-up is an unbounded stall and any deadline value reads the same red.

## Implementation

All changes are inside `TestRelayV2_StreamNewSessionRotatesAndRestartsFresh`
(`internal/e2e/relay_v2_stream_new_session_test.go`), no production code touched:

- **Elapsed stamps on every milestone line.** `testStart := time.Now()` as the first
  statement of the test body (before `shortHome`, so the stamp covers pairing + daemon
  startup — the exact prefix the 20.21 − 20.00 arithmetic turns on) and an `elapsed()`
  closure prefix `[t=%s]` onto all five `M1`–`M5` `t.Logf` lines, message bodies otherwise
  byte-identical. `go test` prints buffered `t.Logf` output when a test *fails*, not only
  under `-v`, so a future M4 failure carries M1–M3's stamps for free — no re-run needed to
  see where the time went.
- **Stdin-log size at ack #2 vs. at poll expiry**, same instrument (`os.ReadFile` + `len`)
  at both ends — matches what the poll loop already does and what the existing `log=%q`
  already prints. Mixing an `os.Stat` size into one end would make the delta unattributable
  since the log is appended to concurrently. The poll loop's read error is now kept (was
  discarded) so an unreadable file renders as "read err: …", not a `len(nil) == 0` that
  reads as "the file was empty." Growth between the two probes separates "no bytes arrived
  at all" from "bytes arrived, but not turn #2's."
- **One-shot registry re-read at failure time.** `readBootstrapIfPresent(regPath)` (the
  same non-fataling, non-polling helper and field M2 already reads) re-read in the M4
  failure branch and reported beside `post.ID` captured at M2. A mismatch is the second-
  rotation reading, previously indistinguishable from a stall. `ok == false` renders as a
  sentinel string (`"<no bootstrap entry: …>"`), never `""` — an empty string would read as
  "the rotation lost the id," a fabricated finding from a broken instrument.
- **No `t.Fatal*`-ing helper on the failure path.** `boundSessionID`, `readBootstrap`,
  `waitForBootstrapID`/`waitForBootstrapIDChange`, `mustReadFile` are all deliberately
  avoided — any of them firing its own fatal while building the M4 message's `t.Fatalf`
  args would mean the diagnostic itself never prints.

## Patterns established

- **A diagnostic's own failure to measure must not render as a measurement.** Every new
  probe on a failure path carries its own error (or a sentinel distinct from every real
  value) so a broken instrument can't silently masquerade as a finding. Applies to both new
  probes here (`os.ReadFile` read errors, the registry sentinel) and generalizes to any
  future diagnostic-on-a-failure-path work in this package.
- **Pair a before/after measurement with one instrument.** When two probes are compared as
  a delta against a concurrently-mutated target (here, an `O_APPEND` log two children write
  into), both ends must use the identical read mechanism — a mixed instrument makes the
  delta unattributable to either bytes-arrived or which-child-wrote-them.
- **Nothing on a test's failure-reporting path may call a `t.Fatal*`-ing helper.** The
  helper that looked most on-point for AC-3 (`boundSessionID`) was wrong for exactly this
  reason; the rule generalizes to any future M4-style "assemble a rich failure message"
  work — check every candidate helper for whether it can itself terminate the test before
  the message is built.

## Lessons learned

From the PR body (developer-flagged) — see [PR #1274](https://github.com/pyrycode/pyrycode/pull/1274):

> A stamp is worth most where no milestone line exists. Nothing logs between M3 and an M4
> failure, so the up-to-15s ack #2 wait sat invisible inside the gap — and whether ack #2
> landed at t=0.2s or t=14s is the slowness-vs-stall discriminator.

Verified by firing the failure path twice under temporary local perturbation (reverted
before commit — the post-revert run was a `go test` cache hit, itself proof the file
returned byte-identical) rather than by inspection alone: both failure arms (needle never
arrives; registry unreadable) rendered real, non-fabricated values.

**A code-review SHOULD FIX survived to merge as a named, accepted gap.** Review
([PR #1274 comment](https://github.com/pyrycode/pyrycode/pull/1274#issuecomment-5172040994),
decision PASS) found that the AC-3 sentinel guards `ok == false` but not
`ok == true && e.ID == ""` — `readBootstrapIfPresent` doesn't require a non-empty `id`, so a
corrupt registry with an empty-string bootstrap id renders as `regNowID = ""`, printing a
**manufactured proof** of the second-rotation reading (strictly worse than the manufactured
void the spec explicitly forbade, since production never persists an empty id — this needs
an already-corrupt registry to reach). The file already guards this exact case 160 lines up
at its own M2 check (`:267`, `ok && e.ID != "" && e.ID != initialUUID`), making this call
site the one of four in the package that omits the emptiness guard. Fix is one clause
(`ok && e.ID != ""`); not taken before merge (below the 3-finding FAIL threshold, one token
cost, requires corrupt state to trigger). As of this writing the code at
`relay_v2_stream_new_session_test.go:429` still reads `if e, ok := readBootstrapIfPresent(regPath); ok {`
— unguarded. **A future ticket touching this file should fold in `&& e.ID != ""` rather than
let this re-surface as a fresh finding.**

Two NIT findings were also left unaddressed (cosmetic, reviewer-acknowledged): the
no-growth/growth interpretive clause in the failure message doesn't gate on both reads
succeeding, and "no growth ⟹ no bytes arrived at all" is imprecise (turn #1's bytes are
already in the log at ack #2) — both are readable in practice from the adjacent printed
error values and raw counts.

## What this record does and does not decide

Per the architecture spec: the elapsed stamps bound reading 1 (genuine slowness), the size
pair separates "no bytes at all" from "bytes, but not turn #2's" (weakening, not
eliminating, reading 4's env-not-set arm), and the registry re-read decides reading 3 (a
second rotation) outright via a mismatch. It does **not** separate reading 2 (delivery
stalled — the msgqueue drain's idle wake-up missed, #704, no periodic retry) from reading 4
(fresh child never spawned) on its own — that needs a daemon-log or process-liveness
observable, deferred as a follow-up only if the flake recurs. No repro was attempted; this
ticket's output is that follow-up's precondition, not a substitute for it.
