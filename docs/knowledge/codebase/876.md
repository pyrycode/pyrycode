# Ticket #876 — enumerate outstanding modals as re-emittable `modal_shown` payloads

The **current-truth read seam** the reconnect-reliability direction ([#829], ADR 025)
needs: `internal/modalbridge.Registry` retained every outstanding modal (`Record` writes,
`Resolve` retires) but exposed only **id-keyed** reads (`Lookup`, `Resolve`) — nothing
could ask *"what is outstanding right now?"*. This ticket adds that one read seam,
`Registry.Snapshot()`, and nothing else: no producer, no wire traffic, no
session-manager change. The connect-time producer that consumes it and re-sends the
payloads over the relay is the follow-up, **#877**.

## Implementation

**One production method added, in `internal/modalbridge/modal.go`:**

```go
func (r *Registry) Snapshot() []protocol.ModalShownPayload
```

- **Direct field copy, not a re-derivation.** `Outstanding` already holds exactly the
  six `ModalShownPayload` fields — `Record` stores it from the *already-built* payload.
  So `Snapshot` copies straight from each stored `Outstanding`, restamping its
  `o.ModalID`. It does **not** call `buildPayload`: that assembles a payload from a
  `PermissionRequest` + wire class, so reversing it would mean un-mapping `Outstanding`
  back into a `PermissionRequest` — lossy, and re-derives data the registry already
  stores verbatim. (The ticket's technical note — "reverses `buildPayload`" — describes
  the net effect, not the mechanism; the architecture spec flagged this explicitly so
  the developer wouldn't take the note literally.)
- **Leaf-lock read**, mirroring `Lookup`/`Resolve`: the whole O(n) map walk runs inside
  one `r.mu.Lock()`/`Unlock()`, no nested locks.
- **`Options` cloned per payload** (`slices.Clone`, already imported for `Record`) so a
  mutating consumer can't corrupt the stored `Outstanding` through an aliased slice —
  this is what keeps "leaves registry state unchanged" true even under a careless
  caller, not just under a well-behaved one.
- **Mints no id.** `newModalID` is never touched; the one-time-nonce and #717's
  deny-on-timeout semantics are unaffected.
- **Return shape:** `make([]protocol.ModalShownPayload, 0, len(r.outstanding))` — an
  empty registry yields a non-nil, zero-length slice, not `nil`.
- **Map-walk order is unspecified.** #877 reconciles by `modal_id`, never by position.

## Patterns established

- **A registry that stores a payload's flattened fields can enumerate them as a direct
  copy — no inverse-of-build-function needed.** When the stored type *is* the payload's
  fields (as `Outstanding` is), a "give me everything" read is a field copy per entry,
  not a call through the original builder in reverse. Reaching for `buildPayload` here
  would have re-introduced the class→title/options mapping this method has no reason to
  repeat.
- **Enumerating stored state is NOT security-sensitive, even for a nonce-bearing type.**
  `Snapshot` restamps the original `modal_id` on every payload, but the seam takes no
  input, produces no wire traffic, and mints nothing — it is a registry-internal
  read of state the package already owns. Distinguish this from a *wire-producing*
  sibling (#877, which sends these payloads to a possibly-untrusted relay peer) —
  that sibling is the one that would earn a security-sensitive label, not this one.
- **Clone-on-read mirrors clone-on-write.** `Record` already clones `Options` when
  storing; `Snapshot` clones it again when reading back out, so neither direction lets
  a caller alias into registry-internal memory.

## Testing

`go test -race ./internal/modalbridge/` and `go vet ./...` pass. Added to
`internal/modalbridge/modal_test.go`, reusing the file's `optionIDs`/`slicesEqual`
helpers and `PermissionRequestForClass` + `Record` setup:

- `TestSnapshot_Empty` — `New().Snapshot()` is zero-length (AC2).
- `TestSnapshot_ResolvedModalDoesNotResurface` — record, resolve, then snapshot is
  zero-length: retired modals never re-surface (AC3).
- `TestSnapshot_SingleOutstandingRoundTrips` — one recorded modal's snapshot entry is
  field-equivalent to the payload `Record` returned (AC4).
- `TestSnapshot_MultipleOutstandingKeyedByID` — two recorded modals (permission +
  trust) both appear; asserted via a `map[modalID]payload` built from the result,
  deliberately not asserting slice order (map-walk order is unspecified).
- `TestSnapshot_PureReadLeavesStateUndisturbed` — after `Snapshot()`, a subsequent
  `Lookup`/`Resolve` of the same modal still succeeds, and mutating a returned
  payload's `Options` does not affect a later `Lookup` (proves the clone) (AC5).

## Out of scope (named)

- **The connect-time reconnect producer that calls `Snapshot()` and re-sends the
  payloads over the relay — #877.** No producer, wire, or session-manager change ships
  in this ticket.
