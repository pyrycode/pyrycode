# Ticket #1098 — Drain streamsup turnevents into `interactiveTurnEmitterV2`

Gives the stream-json path (`internal/streamsup`) a way to fan its parsed turnevents through the **unchanged** `interactiveTurnEmitterV2` — the same `turn_state`/`assistant_delta`/tool-event surface the PTY path's `turnbridge` producer feeds, but without a transcript to tail. #1109 built the pool-supervised runner and deliberately left `Config.Stdout` nil for this ticket to fill; production *selection* of the stream factory (#1081) is still out of scope.

## Implementation

- **`cmd/pyry/stream_turn_drain.go`** (new): a late-bound, daemon-singleton fan-in that lines up two disjoint lifetimes — N per-session `streamsup.Parser`s (sink fixed at runner *construction*, no emitter handle available there) and the one `interactiveTurnEmitterV2` built later on the relay leg.
  - `streamTurnSink` — one buffered `chan streamTurnEnvelope{sessionID, ev}` (256 slots, the `pushQueueCap` precedent). `sinkFor(sessionID)` returns the per-Parser closure; it is a **non-blocking** send (drop-newest + content-free Debug log on a full channel) because it runs on claude's stdout forwarder goroutine and must never wedge the child. The channel is never closed (a Parser may outlive the drain during shutdown).
  - `startStreamTurnDrainV2(ctx, sink, emitter, activeSession, logger) (cleanup func())` — the single drain goroutine, the stream analogue of the PTY path's `OnEvent`/`FlushSignal`/`OnFlush` triple (`startInteractiveTurnStreamV2`), reproduced without `turnbridge` (the Parser already emits `turnevent.Event`; there's nothing to un-map back to a `tuidriver.Event`). Selects over `sink.ch` (gate: forward to `emitter.Handle` only when `sessionID == active session`, else drop **before** `Handle` — the AC2 scoping property), `emitter.flushC()` (drives `flushDelta`), and `ctx.Done()`. Only this goroutine ever calls `Handle`/`flushDelta` — single-writer invariant, `-race`-tested with two parsers feeding concurrently.
- **`cmd/pyry/streamsup_runner.go`**: `streamRunnerFactory` (#1109) became `newStreamRunnerFactory(sink *streamTurnSink) sessions.RunnerFactory` — the returned closure installs `streamsup.NewParser(sink.sinkFor(cfg.SessionID), cfg.Logger)` as `scfg.Stdout` after calling `mapStreamsupConfig(cfg)`, so the mapper itself stays pure (its `Stdout == nil` assertion is untouched — the Parser is a runtime object installed one layer up, not a mapper concern).
- **`cmd/pyry/stream_turn_drain_test.go`** (new): table/scenario tests driving raw stream-json bytes through `Parser` → sink → drain → a fake broadcaster, covering full single-turn flow, AC2 cross-session scoping (including a concurrent `-race` feed of two sessions), empty-cursor drop, the flush-timer path, tool events, and a structural AC3 assertion (no filesystem setup, no fsnotify/jsonl import).
- **`cmd/pyry/streamsup_runner_test.go`**: `TestStreamRunnerFactory_*` re-targeted to `newStreamRunnerFactory(newStreamTurnSink(...))(cfg)`; `TestMapStreamsupConfig_*` unchanged (still pins `Stdout == nil`).

## Patterns established

- **Late-bound daemon-singleton fan-in** as the seam shape when a per-session producer (fixed at construction) needs to reach a single consumer built later on a different lifecycle leg, and no shared registry/fan-out is otherwise needed — one buffered channel in, one goroutine out. Not a general fan-out mechanism; deliberately scoped to avoid becoming one (see the architecture spec's "why this isn't shared fan-out infrastructure" reasoning).
- **Gate at `Handle` time, not at the sink.** The per-event session check happens in the drain goroutine immediately before calling `emitter.Handle`, not inside the sink closure — keeps the forwarded event's gate decision consistent with the cursor `Handle` itself reads via `CurrentConversation()`.
- **Non-blocking producer-side send, drop-newest on full.** Mirrors the emitter's own "owns no queue" principle: a channel fed from a child-process forwarder goroutine must never block, so backpressure is resolved by dropping the newest event rather than blocking the child.

## Lessons learned

- The drain's `cleanup()` blocks on the goroutine's `ctx`-driven exit (same contract as `startInteractiveTurnStreamV2`), so a test must **cancel before joining**. `defer cancel(); defer cleanup()` deadlocks — LIFO runs `cleanup()` first while `cancel()` is still pending. Use `defer func(){ cancel(); cleanup() }()`. A `-timeout` bound turns the deadlock into a fast failure instead of a 600s hang.
- Piping `go test` into `tail` masks the test's real exit code with `tail`'s — a green "exit 0" that actually hid a timeout. Capture to a file and read the real exit code.
