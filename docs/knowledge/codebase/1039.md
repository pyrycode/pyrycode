# Ticket #1039 — remove the dead v1 `Dispatcher` / `FirstFrameGate` machinery

Split from #966. #913 slice 1 removed the production v1 relay branch and its
`PYRY_MOBILE_V2` escape hatch, orphaning the v1 gate-and-demux state machine
in `internal/dispatch` with zero production callers. This ticket physically
deletes that machinery, leaving only the v2 routing surface the live relay
path (`internal/relay/v2session.go`) actually uses: `Route`, `Conn`,
`NewConn`/`NewTestConn`, `NextID`, `Send`, `Reply`, `sendError`.

Not security-sensitive: the removed code included a first-frame auth gate,
but it had 0 live callers (verified) so it gated nothing on the live surface,
and `Route` (the kept inbound router) is unchanged — no design change to
audit.

## Implementation

`c28545e` (spec) + `3a606aa` (dev), confined to `internal/dispatch/`: 522
lines removed from `dispatch.go`, 538 from `dispatch_test.go`, `gate_test.go`
(451 lines) deleted whole. Net −1259 LOC, one production file.

- **Deleted wholesale**: `Config`, `FirstFrameGate`, `FirstFrameOutcome`,
  `Dispatcher`, `connState`, `New`, `Register`, `Outbound`, `ActiveConns`,
  `Run`, `routeConn`, `runConn`, `runGate`, `handleOne` — the contiguous
  gate+demux span.
- **`setAuth` also deleted, despite AC2's literal keep-list naming it.**
  Its sole caller was `runGate` (deleted in the same span), so keeping it
  trips staticcheck U1000, which AC6/AC7 (`make check`) forbid. This was a
  spec-flagged, architect-anticipated deviation, not scope creep — an
  unwired gate with 0 verified callers is not security-sensitive despite
  touching an auth-adjacent symbol, because there's no live design left to
  audit. `Conn.auth` is unaffected — it's
  populated once at construction by `NewConn`/`NewTestConn` (the v2 session
  manager passes its handshake-matched device at `v2session.go:1051`) and
  read via `Auth()` (live reader: `internal/relay/handlers/register_push_token.go`).
- **`dispatch_test.go` re-homed, not bulk-deleted**, per AC4: tests driving
  a *kept* `Route` branch through the deleted `Dispatcher.Run` harness were
  re-expressed as direct `Route`/`Conn` calls mirroring the pre-existing
  `TestRoute_StandaloneInvocation` / `TestRoute_NoHandler_UnsupportedReply`
  pattern — `TestMalformedInnerFrame`, `TestUnknownType`,
  `TestEncryptedRefusal`, `TestIDCounter_MonotonicPerConn`. Tests covering
  only removed machinery (`Dispatcher.Run` teardown, per-conn arrival
  ordering, `ActiveConns` snapshots, `Register`/`New` guards) were deleted,
  along with the `runDispatcher` harness helper.
- Doc comments citing removed identifiers were reworded (package doc,
  `Handler`, `Conn.auth` field, `Auth()`, `NewTestConn`, `NewConn`) — no
  linter catches stale prose naming a deleted symbol. `Route`'s own doc
  comment cited `Dispatcher` twice despite not being in the spec's
  enumerated rewrite list; tidied during dev alongside the spec-listed set.
- `sync` import dropped (compiler-forced — only the deleted `Dispatcher`
  used `sync.Mutex`/`sync.WaitGroup`).

Code review: PASS (see PR #1045). `make check` green including hermetic e2e.

## Patterns established

- **Dead-code removal that spans an AC-literal keep-list can still force an
  extra deletion.** When the ticket's keep-list is written against the
  *pre-removal* call graph, a symbol on that list can still go U1000 once
  its only caller is deleted in the same change — the staticcheck gate
  (AC6/AC7 here), not the keep-list, is the actual authority. Flag the
  deviation explicitly in the spec/PR rather than working around it with a
  `//lint:ignore`.
- Confinement verification (`codegraph_impact` returning only in-file hits,
  tree-wide grep of removed names finding only comments elsewhere) is worth
  doing *before* estimating a removal ticket's size — it's what let this
  stay S despite `internal/dispatch` having historical-analogy comments in
  `v2session.go`, `eventring/ring.go`, and `acp/acp.go` that were correctly
  left untouched (comments, zero build/lint impact, out of scope).

## Lessons learned

- (from PR body) `setAuth`'s removal is the clean instance of the "U1000
  forces a keep-list deviation" pattern above — worth citing if a future
  ticket's spec debates whether to preserve a technically-still-named
  symbol that has lost its only caller in the same diff.
- (from PR body) When a ticket's AC says "tidy comments citing removed
  identifiers" and enumerates specific doc comments, still grep the kept
  surface's *own* doc comments for the removed type name — `Route`'s
  comment referenced `Dispatcher` twice and wasn't on the spec's list.
