# Ticket #1029 — `change_workspace` real-claude round-trip + live-session liveness gate

Adds `TestInteractiveChangeWorkspace` to `internal/e2e/realclaude/`
(new file `interactive_change_workspace_test.go`, `//go:build e2e_realclaude`) —
the first real-`claude` coverage of `change_workspace`. Split from #963;
`change_workspace` previously had fake-tier coverage only (#980).

**Rescoped during refinement.** The original ask was to prove "real claude
picks up the changed cwd." That behaviour does not exist in production — no
production path reads a stored `conv.Cwd` and spawns with it (a session's
spawn workdir is fixed at runner construction, and `RestartFresh` on respawn
never re-reads it) — so no test can assert it. What shipped instead is the
narrower, genuinely real-tier-only claim: the verb round-trips correctly
against a **real** daemon with a **live supervised claude child**, and does
not wedge or kill that child. A scripted fake cannot regress a real child
dying.

## Implementation

Sequential spine, one daemon, one seeded bound conversation, over one Noise
v2 encrypted channel, against real `claude --model haiku` — the #1028/#1031
shape:

turn 1 (liveness, drained to `turn_state{idle}`) → `change_workspace` (target
minted directly via `os.MkdirAll`, sent in **tilde form** `~/ws-<nonce>`) →
assert the `conversation_updated` reply's `Cwd` is the `$HOME`-confined
**realpath**, not the raw request → assert the same realpath is persisted
on disk → turn 2 (liveness, proves the verb didn't disturb the live child).

Reuses the restored harness (`harness_daemon_test.go`, #1473 — the file
#1348 deleted along with its tests) and the #997/#1028 generalised
control-frame helpers (`sealEnvelope`, `drainForReply`,
`assertConversationUpdated`) verbatim. The only new code is
`readConversationCwdOnDisk` (~25 lines), mirroring #1028's
`readConversationIDsOnDisk` with `Cwd` added to the row struct. Zero
production files touched.

**Request sent in tilde form, not absolute.** AC2 requires the reply to
carry the resolved realpath, "not the raw requested path." Sent as an
absolute path, that clause only bites where `$HOME` sits under a symlink —
true for a macOS `t.TempDir()` under `/var`, generally false on Linux, so
the assertion would silently stop discriminating on half the supported
platforms. The tilde form (what `expandTilde`'s own doc says a real phone
must send, since it can't know the daemon's absolute home) makes the
requested string differ from the resolved one on every platform, by
construction.

**No config file written.** Unlike `TestInteractiveStreamLiveness`, this
test does not call `writeStreamInteractiveConfig`. Since #1348 the
empty/default `interactive_runner` already selects the stream-json runner,
so writing the config would add a moving part that changes nothing —
flagged explicitly in the test's header comment since copying the
stream-liveness spine makes copying that call the natural mistake.

## ANTI-GOAL — do not "fix" this into a hang

The test does **not** assert that any spawned claude runs in the *new*
folder, and never should. Production has no such path — this is
structural, not a gap this ticket left open. The turn-2 liveness delta is
produced by the child still running at the conversation's **original**
cwd. It proves the daemon survived the verb, not cwd adoption. The doc
claims on `Conversation.Cwd` and `ChangeWorkspace` ("the new folder takes
effect on the conversation's next fresh session spawn") are unbacked by
code — a separate production/doc defect, filed separately, and this test
deliberately does not compensate for it. This is stated at length in the
test file's header comment specifically so a later reader doesn't
misread AC4 as a cwd proof and turn it into a hang.

## Patterns established

None new — reconfirms #1028/#1031's "reuse the frozen harness verbatim,
add one small on-disk reader" discipline for another verb family, and
reconfirms the tilde-vs-absolute non-vacuity trick is worth reaching for
any time a "resolved, not raw" assertion could accidentally depend on the
test host's directory layout.

## Lessons learned

(From the PR body's Lessons learned section — see PR #1476.)

- `internal/e2e/realclaude` is build-tagged in its entirety, including
  `fixtures.go`, so an **untagged** `go test ./internal/e2e/realclaude/`
  fails with "build constraints exclude all Go files" rather than running
  zero tests. A touched-package race check for this package must run
  **with** `-tags e2e_realclaude`; the untagged form isn't a weaker check,
  it's not a check at all. Same blind spot as #1348's, one level down.
- A "reply carries the resolved realpath, not the raw request" assertion
  is platform-dependent when the request is sent as an absolute path — see
  § Implementation above for the tilde-form fix.

## Verification

Code review PASS on PR #1476 (one NIT, not requested as a change: `readConversationCwdOnDisk`
and `readConversationIDsOnDisk` are near-identical decoders over the same
file — defensible per the spec's explicit sanction to mirror rather than
refactor the existing helper; noted only so a third copy triggers the
merge). Reviewer independently re-derived every load-bearing claim in the
test's header (the `RestartFresh` no-rebind fact, the `""` runner-selector
arm, the single production `CreateIn` call site) rather than inheriting
the spec's attribution, and confirmed neither AC2 nor AC3 can pass
vacuously against un-mutated seed state. `go vet -tags e2e_realclaude`,
`gofmt`, and tagged `staticcheck` all clean (11 pre-existing baseline
findings in files this PR doesn't touch; zero new). The live rotate path
itself — `make e2e-realclaude` against real credentials — was **not** run
in the review environment (no creds available); the ticket carries
`needs-real-claude` for the dispatcher to close post-merge.
