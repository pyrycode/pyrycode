# Ticket #793 — Live e2e capstone: two-head first-answer-wins (phone + `pyry attach`)

The **[EPIC #597] Phase 3 live exit gate** for two-head modal ownership (split from
[#708], mirrors the Phase 2 capstone [#642] and the sibling [#791] answered-permission /
[#792] queue-drain / [#794] interrupt live capstones). Over **one daemon + a real (fake)
claude that raises a permission prompt, observed by BOTH a paired phone AND a local
`pyry attach` head**, it confirms **live** what [#706] (first-answer-wins across the two
heads + the local `handleModalHidden` arm) proved **deterministically** upstream and
[#798] live-wired into the daemon: the local TTY answers first, claude's modal vanishes,
tui-driver fires `EventKindPtyModalHidden`, the #706 local arm `Resolve`s the shared
registry and broadcasts `modal_dismissed{source: local}`, the phone's `modal_shown`
clears, and the phone's subsequent (late) `modal_answer` misses the consumed nonce and is
a rejected no-op. It **confirms; it does not re-prove** — the correctness oracle stays
upstream ([#706]). **Test/harness only** — the two-heads production code shipped in
[#706] and was live-wired by [#798].

**`security-sensitive`** — the adversarial question is not "does this introduce a vuln"
but **"could this test PASS while the guarantee is broken?"** (a permission observed by
two heads must resolve **exactly once**, the loser dismissed, the loser's late answer
routing no keystroke). Architect spec-stage self-review verdict **PASS, no MUST FIX**;
code-review **PASS** (two NITs — a deliberate `Fatalf`/`Errorf` mix and the intentional
#791 bring-up duplication; plus the recurring realclaude `thinking_tokens` known-red flag,
not attributable).

## Single flow — no split

The four ACs (both heads observe → local answers → phone dismissed → phone late answer is
a no-op) decompose into **one** single-modal scenario, not four tickets. The loser-no-op
(AC3) negative is **meaningless unless both heads provably observed the same prompt and
the modal was provably resolved locally in the same run** (the vacuous-pass guard), so
there is no clean seam to split along. This is the [[po-plus-title-capstone-is-one-flow]]
shape. One test, one ticket, held at **S**.

## What was missing over #706 / #716 / #798 — and the one design decision

[#706] proved first-answer-wins + the local arm with **unit tests**; [#716]/[#717]/[#725]
shipped the modal surface / gated answer / deny-on-timeout; [#798] live-wired the producer
(`startInteractiveModalStreamV2` → `runModalStream`, which drives **both**
`EventKindPtyModalShown` **and** `EventKindPtyModalHidden` through the #706 emitter over
**the same `modalReg` the inbound resolver consumes**). What none proved is the **live**
end-to-end behaviour over one running daemon hosting a real supervised child, a connected
phone, **and** a connected local attach.

The one real design decision this ticket lands: **the local first-answer-wins arm is
`EventKindPtyModalHidden`-driven**, and that event fires only on a genuine
`Permission→Unknown` screen transition. [#791]'s `MODAL_TRIGGER` fake raises the modal
and **never clears it** — sufficient for #791 (the phone answers and the daemon's
**remote** arm broadcasts the dismissal regardless of claude's screen), but the local arm
would never fire. So the fake must **clear its modal in response to the local answer
keystroke**, making that keystroke the *cause* of the Hidden event — the same
structural-causality shape [#794] used for Esc→`turn_end`
([[architect-modal-live-capstone-fixed-options-and-subprocess-timer]]'s LOCAL-arm-must-clear
note; [[architect-interrupt-live-capstone-esc-drives-turnend]]). Reusing #791's fake
unchanged would leave the local arm dead and the capstone unbuildable.

## Implementation

The entire delta is **one production-source file** (fakeclaude, ~30 LOC) + **one extended
untagged detection assertion** + **one new `//go:build e2e` test**. No `pyry` runtime
change, no new exported types, **no `harness.go` change** (the `extraEnv` seam already
existed — the [#642] precedent), **no `cmd/substrate-guard` allowlist change** (the clear
screen reuses the already-allowlisted idle glyph).

### fakeclaude: `PYRY_FAKE_CLAUDE_MODAL_CLEAR_ON_ANSWER` — the keystroke *is* the cause

The mechanism that makes the local answer the **cause** of the modal vanishing (not a
scripted dismissal). Gated behind a **new** env — not a change to `MODAL_TRIGGER` — so it
is byte-identical to today when unset (the [[architect-additive-entry-point-when-golden-tests-back-back-compat-ac]]
discipline). When both `MODAL_TRIGGER` and the new env are set:

- **Signal, don't write.** The stdin reader `Store`s a `clearPending atomic.Bool` on
  every read (the local head's answer keystroke) — signal only, exactly like the shipped
  `turnPending`/`escPending`; the reader **never** writes stdout or `f`, preserving the
  single-writer discipline.
- **One-shot main-loop drain.** The `main` poll loop, gated on `modalShown && !modalCleared
  && clearPending.Swap(false)`, calls `clearModalScreen()` once and sets `modalCleared`.
  The `modalShown` gate ensures a pre-modal keystroke cannot clear early — `clearPending`
  stays set until the modal is up, then fires on the first post-modal keystroke. Only the
  main goroutine writes stdout (modal mode emits no spinner), so the single-writer
  discipline holds.
- **`clearModalScreen` → `modalClearScreen`.** Writes `modalClearScreen = strings.Repeat(
  "\r\n", 16) + string(idleGlyph)` once, fsync'd. The 16 blank lines scroll the
  `"Do you want to proceed?"` anchor above the bottom `permissionRegionRows` (12) window
  `DetectModalClass` scans (the screen is a 40-row `DefaultPtyRows` grid), so the detected
  class transitions `Permission→Unknown` and the merge loop fires `EventKindPtyModalHidden`.
- **The trailing idle glyph is load-bearing, not decoration.** `trimGridText` drops
  trailing empty rows, so a clear screen made **only** of newlines collapses back and the
  anchor re-enters the bottom-12 window — the screen would still classify as Permission. A
  non-empty final row (the `❯` glyph) pins the grid height. Reusing the already-declared
  `idleGlyph` means **no new substrate glyph and no allowlist change**.

**De-risk the fixture before the e2e.** `TestFakeClaude_ModalClearScreenReturnsToNonPermission`
(untagged, harness-free) feeds the concatenated `modalScreen+modalClearScreen` bytes to a
fresh `DetectModalClass`, reproducing the daemon's sequential-write vt10x state
deterministically — so it predicts the live `Permission→Unknown` transition in
milliseconds. A non-clearing fixture (too few newlines, or a newline-only screen that
`trimGridText` collapses) is caught here, never inside a slow live-daemon run. The
original `modalScreen == Permission` assertion (#791) is unchanged.

### The local `pyry attach` head (`spawnLocalAttachHead`)

The relay daemon `StartRotationWithRelay` spawns is in **bridge mode** (its stdin is
`/dev/null` → `IsTerminal` false) and exposes `h.SocketPath`, so a local
`pyry attach -pyry-socket=<h.SocketPath>` with an **empty session id** binds the **same**
daemon's bootstrap session — the ADR-025 two-heads model (local `output` head + phone
observer coexist). The helper lifts `StartAttach`'s attach-spawn block: `pty.Open()`
(`t.Skipf` if unavailable — sandboxed CI), `exec.Command(bin, "attach", ...)` with the
slave on stdio and `SysProcAttr{Setsid:true, Setctty:true}` and `childEnv(h.HomeDir)`, the
early-death `select`, and a `t.Cleanup` that closes Master/slave and kills the process. It
returns the pty **Master**; the test writes the answer keystroke to Master and reads Master
to observe the modal on the local head's screen. Two facts make it faithful:

- **Input is raw passthrough.** Attach bridges keystrokes straight to claude's PTY via
  `Session.AttachInput` (**not** `DeliverPrompt`, which bracketed-pastes phone turns) — so
  a byte written to Master reaches the fake's stdin **verbatim** and is logged to
  `PYRY_FAKE_CLAUDE_STDIN_LOG` (the "winning keystroke delivered exactly once" oracle).
- **Output includes the modal.** The Bridge fans claude's PTY output to the local `output`
  head, so the attach's screen carries `modalScreen` once it is raised — **provided the
  attach is bound before the modal is raised.** The Bridge does **not** replay scrollback
  to a newly-attached head, so `bringUpTwoHeadModalHarness` spawns the attach and fences on
  the daemon's `"control: client attached"` log (emitted strictly **after** `Bridge.Attach`
  sets the output writer) **before** the test raises the modal.

### The test choreography (`TestRelayV2_TwoHeadFirstAnswerWins`)

Reuses the frozen freestanding #791 helpers verbatim (`decodePairPayload`,
`readPersistedServerID`, `waitBinaryHello`, `driveHandshakeToOpenDaemonInteractive`,
`encodeWorkdir`, `awaitModalShown`) and does **not** mutate `bringUpModalHarness`/
`modalHarness`; the daemon+phone bring-up is **duplicated deliberately** in
`bringUpTwoHeadModalHarness` (not refactored into a shared helper) to keep #791
byte-frozen (code-review NIT, accepted). The answering phone is paired **with
`--allow-remote-permissions`** (the #702 device gate) so its late answer reaches
`ResolveAnswer`'s `Lookup` (and misses on the consumed nonce) rather than denying at the
gate — else the loser-no-op would be vacuous for the wrong reason.

1. **[Vacuous-pass positive #1 — phone observes]** (AC1 phone side). Raise the modal; drain
   the phone until `modal_shown` (`awaitModalShown`, ~20 s `t.Fatal`). Assert
   `Class == "permission"` and the four fixed option IDs (`allow_once`..`reject_always`);
   capture `modalID`.
2. **[Vacuous-pass positive #2 — local attach observes]** (AC1 attach side). Read the
   attach Master until the output contains the `"Do you want to proceed?"` anchor
   (`t.Fatal` at 20 s — the "local head never saw the prompt" mode). **Both surfaces have
   now provably observed the same prompt.** A background goroutine then keeps Master
   drained so claude's later PTY output never backs up against an unread master and stalls
   the supervisor's PTY drain.
3. **[Winner — local answers first]** (AC2). Write `"1"` (allow_once) to Master. The fake
   clears on the first post-modal byte → `EventKindPtyModalHidden` → the local arm
   `Resolve`s and broadcasts. Await `modal_dismissed` on the phone; assert
   `ModalID == modalID`, `Source == "local"`, `Outcome == "dismissed_local"` (this is the
   phone learning its `modal_shown` is gone — AC3 "the phone modal clears").
4. **[Winning keystroke delivered exactly once]** (AC2). `modal_dismissed` is a
   happens-after fence (the fake fsyncs the stdin write before the clear that triggers the
   broadcast). Read `stdinLog`; assert the local keystroke appears **exactly once**.
   Snapshot the log length for step 6.
5. **[Live audit-trail evidence]** (AC4, in lieu of the deferred flight recorder). Assert
   `h.Stderr` contains `dismissed_local` — the local arm's `audit: remote permission
   decision` line (`source=local`), proving the resolution is recorded to the audit trail
   live.
6. **[Loser — phone's late answer is a no-op]** (AC3). Send `modal_answer{modalID,
   allow_once, token}` from the phone **after** the local dismissal. It misses at `Lookup`
   (already consumed by the local `Resolve`) → no keystroke, no dismissal. Assert **no**
   further `modal_dismissed` within a short deadline **and** `stdinLog` is byte-for-byte
   unchanged (the loser routed nothing).

**Assertion order is load-bearing:** the two observe-positives (both surfaces saw the
prompt) and the winner dismissal are hard preconditions of the loser-no-op negative, each
with a dedicated `t.Fatal` naming its failure mode — a "late answer ignored" over a prompt
a surface never saw, or over a modal never resolved locally, cannot pass vacuously.

### Data flow

```
[bring-up] phone connected (interactive) + local pyry attach bound to bootstrap session
           (attach fenced on "control: client attached" BEFORE the modal is raised)

os.WriteFile(modalTrig)
  → fakeclaude emitModalIfTriggered → modalScreen ("Do you want to proceed?")
  → supervisor tui-driver: DetectModalClass Unknown->Permission → EventKindPtyModalShown
  → runModalStream (#798) → handleModalShown → mint modal_id → broadcast modal_shown → phone [AC1 phone]
  → Bridge output head → attach Master shows "Do you want to proceed?"                       [AC1 attach]

local attach types "1" → Master → Bridge.Read → Session.AttachInput → fake stdin (logged)   [AC2 exactly once]
  → clearPending → clearModalScreen → modalClearScreen (16×\r\n + ❯)
  → DetectModalClass Permission->Unknown → EventKindPtyModalHidden
  → runModalStream → handleModalHidden
      → reg.Resolve(modal_id) WINS → audit{outcome:dismissed_local, source:local}           [AC4 audit → h.Stderr]
      → broadcast modal_dismissed{Outcome:"dismissed_local", Source:"local"} → phone         [AC2/AC3 phone clears]

phone → modal_answer{modal_id, allow_once, token}   (LATE)
  → handleModalAnswer → ResolveAnswer → Lookup MISS (consumed) → no keystroke, no dismissal  [AC3 no-op]
```

## Patterns established

- **The local first-answer-wins arm is `EventKindPtyModalHidden`-driven, so the live proof
  needs a real screen transition caused by the keystroke — not a scripted dismissal.** This
  is the counterpoint to #791's **remote** arm, which broadcasts the dismissal regardless of
  claude's screen (so #791's fake never clears). The fake genuinely clearing its modal in
  response to the local keystroke is what makes `modal_dismissed{local}` provably *caused*
  by the local answer — the same structural-causality discipline #794 used for Esc→`turn_end`.
  A capstone that scripted the dismissal would confirm nothing about the live Hidden→local-arm
  path. Recorded at intake as the LOCAL-arm-must-clear branch of
  [[architect-modal-live-capstone-fixed-options-and-subprocess-timer]].
- **A new env, not a change to `MODAL_TRIGGER` — additive-entry-point discipline protects
  the sibling.** If `MODAL_TRIGGER` cleared on *any* answer keystroke, #791 Test A would
  break: there the phone's answer routes bytes to the fake's stdin, and clearing on it would
  fire the local `Resolve` **racing** the remote `ResolveAnswer` for the same `modal_id` — a
  coin-flip between `{source: remote}` (what #791 asserts) and `{source: local}`. Gating the
  clear behind a **new** env that is byte-identical when unset keeps #791 frozen. The general
  rule when two capstones share a fake: extend via a new default-off env, never mutate an
  existing mode's behaviour. [[architect-additive-entry-point-when-golden-tests-back-back-compat-ac]].
- **Two heads ⇒ two *ordered* observe-positives gate the loser-no-op** — the
  `security-sensitive` headline. The phone's `modal_shown{permission, 4 fixed IDs}` **and**
  the local attach rendering the anchor **on its own screen** are both hard preconditions of
  the AC3 negative, each with its own `t.Fatal`. Same vacuous-pass shape #642/#791/#792/#794
  established, extended to a two-surface observation.
- **The Bridge does not replay scrollback to a newly-attached output head.** Only PTY output
  written *after* the attach binds reaches it, so a two-head e2e **must bind the local attach
  before raising the modal**, and can fence deterministically on the daemon's
  `"control: client attached"` log (emitted strictly after `Bridge.Attach` sets the output
  writer) rather than a fixed sleep. (PR Lessons-learned #1.)
- **Attach input is raw passthrough (`Session.AttachInput`), so a byte written to Master is
  the direct exactly-once oracle.** Unlike a phone turn (bracketed-pasted via
  `DeliverPrompt`), the local keystroke reaches the fake's stdin verbatim and is fsynced to
  the stdin log — so `bytes.Count(log, key) == 1` after the dismissal is a sound "winner
  routed exactly once" check, and an unchanged log after the late phone answer is a sound
  "loser routed nothing" check.
- **`modal_dismissed{local}` and the `dismissed_local` audit line are happens-after fences.**
  The fake fsyncs the stdin write *before* the clear that triggers the broadcast, and the
  #706 local arm audits *before* it broadcasts — so reading `stdinLog` (step 4) and
  `h.Stderr` (step 5) only **after** observing the dismissal needs no polling for those
  values; the fence is structural. `dismissed_local` is a unique, format-agnostic marker
  greppable in `h.Stderr` (the live AC4 audit oracle).
- **Harness reuse over harness build — the [#642] `extraEnv` seam pays off again.** The whole
  proof rides the *shipped* production stack (supervisor + relay + Bridge + `modalReg`
  arbiter + #798 producer); the only new harness surface is the ~30-LOC fakeclaude mode + the
  attach-head helper. `StartRotationWithRelay` appends `extraEnv` verbatim, so **no
  `harness.go` change**. The build-vs-reuse call was the architect's (the #642 reuse note +
  a local attach head); reuse held. The #791 bring-up was duplicated rather than extracted to
  keep #791 byte-frozen — an accepted trade-off (code-review NIT).

## Lessons learned

*(Lifted from the PR #809 **Lessons learned** — three non-obvious surprises this ticket
surfaced; the first is captured as a Pattern above and restated here as the transferable
lesson.)*

- **The supervisor `Bridge` does not replay scrollback to a newly-attached output head** —
  only PTY output written *after* the attach binds reaches it. A two-head e2e must bind the
  local attach *before* raising the modal, and can fence on the daemon's
  `"control: client attached"` log (emitted strictly after `Bridge.Attach` sets the output
  writer) rather than a fixed sleep.
- **`DetectModalClass` always renders the snapshot at the default 40×120 grid** regardless of
  the PTY's actual (possibly attach-resized) dimensions, so an attach head's resize cannot
  perturb modal-detection geometry — the `modalClearScrollRows = 16` margin is computed
  against the fixed grid, not the live PTY size.
- **`trimGridText` drops trailing empty rows**, so a clear screen made only of newlines
  collapses back and the permission anchor re-enters the bottom-12 detection window — a
  non-empty final row (the idle glyph) is **load-bearing, not decoration**. The
  `modal_detect_test.go` assertion pins this: a newline-only clear screen would fail it in
  milliseconds rather than time out inside a live run.

## AC4 (flight recorder) — scoped out of CI, mirrors #791 AC5 / #792 AC4 / #794 AC4

AC4 ("The run is recorded by the flight recorder for the audit trail") is the **same wording
and disposition as the siblings**. The flight recorder (`.cast` capture) lives in
`internal/agentrun/ptyrunner`, gated on `PYRY_RECORD_DIR`, reached **only** from the
`pyry agent-run` / dispatcher path. The two-head modal flow is a **mobile-relay** flow:
claude is hosted by `internal/supervisor`, which wires no `RecordTo`/`PYRY_RECORD_DIR`. The
two code paths are **disjoint** — no single run is both "a two-head modal resolution" and
"recorded by the flight recorder." Per [[po-audit-artifact-ac-check-harness-reachability]],
the architect scopes the AC to the variant whose import reaches the artifact — here, **none**
on the mobile path. **Disposition:** the CI test asserts AC1–AC3; the flight-recorder proper
is deferred to the operator live run ([mobile-live-e2e-runbook.md](../features/mobile-live-e2e-runbook.md)),
**not** a developer deliverable, no test code.

**What #793 *does* assert live for AC4's intent** is stronger for this ticket specifically:
the local arm's `internal/audit` record (`audit: remote permission decision`,
`source=local`, `outcome=dismissed_local`) **is** wired (the emitter holds the daemon logger)
and lands in `h.Stderr` (step 5). Auditing `source=local` is the distinguishing
security-relevant behaviour of the local arm, so asserting it live is a *stronger*
confirmation than a generic recording check. Genuine in-CI flight-recorder capture on the
mobile path would need wiring `RecordTo`/`PYRY_RECORD_DIR` into `internal/supervisor` — a
**production change**, surfaced but **not built** (Evidence-Based Fix Selection: the siblings
already deferred the same AC). Recommend the PO track it as an **epic-#597 follow-up**.

## Testing

One new `//go:build e2e` test asserting AC1–AC3 + AC4's live audit evidence in a single run,
plus one extended untagged detection assertion; **no production runtime change** (the change
is a default-off test-only fakeclaude mode).

- **AC1** (both surfaces observe) — steps 1–2: phone `modal_shown{permission, 4 options}`
  **and** the attach Master carrying the anchor; each with a dedicated `t.Fatal`.
- **AC2** (whichever answers first wins; winning keystroke exactly once) — steps 3–4: the
  local attach answers first; `modal_dismissed{source: local}` reaches the phone; `stdinLog`
  contains the local keystroke exactly once.
- **AC3** (loser dismissed + late answer no-op) — steps 3 + 6: the phone's `modal_shown` is
  dismissed by the local answer; the phone's subsequent `modal_answer` yields no second
  `modal_dismissed` and routes no keystroke (`stdinLog` unchanged).
- **AC4** (recorded for the audit trail) — step 5: `h.Stderr` contains the local arm's
  `dismissed_local` audit line (live evidence); the flight recorder proper is deferred.
- **Vacuous-pass guard** — the two observe-positives + the winner dismissal gate the
  loser-no-op negative.

Gates green (developer + code-review): `go build ./cmd/pyry`, `go vet ./...`,
`staticcheck ./...`, `go test -race ./...`, `make substrate-guard`, and
`go test -tags=e2e -run TestRelayV2_TwoHeadFirstAnswerWins ./internal/e2e/...` →
**non-vacuous PASS (~4.4 s full flow, not skipped)**, stable across `-count=3` (deterministic
sequencing — the local answer resolves and is awaited *before* the phone's late answer, so
there is no live race). #791's answered-permission e2e still passes (confirms the fakeclaude
change is a no-op when the new env is unset). Code-review ran the e2e itself (QA does **not**
compile `-tags=e2e` — the [#642]/[#680] CI coverage-gap note). Verdict **PASS**, two NITs
(the deliberate `Source`/`Outcome` `Errorf`-then-`break` vs the surrounding `Fatalf`; the
intentional #791 bring-up duplication) — no rework.
