# Ticket #1433 — The trailer gate reads the runner path on the presence side (offline)

`trailGate` fell through to `trailGateUsable` for any non-empty `terminal_reason` other than
`max_turns` — including on a `streamrunner` reading, where the Detail it published cited
ptyrunner's `emitter.Close()` and reap defer even though neither exists on that path
(`streamrunner.Run` passes claude's bytes through unchanged, and its reap lives in `cmd.Cancel`,
which never fires on a clean exit). A watchdog-killed stream run carrying `"idle_stall"` was
therefore certified usable, reached `trailAdmitProof`, and landed on
`trailOutcomeRunningAtTrailer` under a justification that structurally could not have fired.

This ticket gives that shape — `terminal_reason` present and non-empty, path owes none — an arm
of its own: it now answers the shipped `trailGateOutOfContract` and certifies nothing. `Reason`
stays empty, so `trailClassifyRun`'s C2 stays green unamended, C4 forces `Admit` empty, and the
run lands on `trailOutcomeOutOfContract` with **no amendment to the classifier at all**. It is
the #1420 step for the **presence** side (#1420 did this for absence); promoting the shape to a
value of its own, mirroring #1417, is **#1434**.

PR [#1435](https://github.com/pyrycode/pyrycode/pull/1435). Split from #1427 (itself re-filed
from the closed-NOT_PLANNED #1369). Security-sensitive (architect self-review PASS).

## Implementation

- **One new return site, placed after the budget arm and before the usable return.**
  `trailGate` now has **eleven** return sites (was ten), **six** of them `trailGateOutOfContract`
  (was five). The decision comes from `trailReasonAgainstPath`'s `trailReasonPresentOwesNone`
  answer, called via an `if` — not re-switched — because exactly one of its reachable answers
  here diverts; the other two (`trailReasonNamedOwesOne` on a ptyrunner reading,
  `trailReasonPathUnnamed` on an indeterminate one) fall through to the shipped usable return,
  which stays the fall-through.
- **Two ordering decisions, both stated at the arm's doc block, not left to return order:**
  - *The budget arm wins.* A `max_turns` trailer on a path that owes none has two candidate arms;
    placing the new one after the budget arm is what keeps the budget void's structural priority
    (it outranks every reap-side void) and is what limits the sweep's exemption set to exactly
    the usable row — measured both ways: placed before, the `max_turns` row goes red too.
  - *The present-and-blank arm keeps winning.* The gate's `reason == ""` branch returns before
    this site is reached, so a blank `terminal_reason` on a path that owes none stays
    path-invariantly out of contract, even though the reduction's `trailReasonPresentOwesNone`
    absorbs both the blank and the named input ("Empty or named, both land here"). Kept
    deliberately: #1419's arm publishes the `NO LIVE REPRO EXISTS` claim, which is true of a
    blank key and false of an absent one — the one absorbing reduction value cannot express that
    distinction.
- **Byte budget: cite the constant, don't embed the reduction's Detail.** The three absence arms
  embed `trailReasonAgainstPath`'s Detail because their three cases are otherwise
  indistinguishable in prose; here the marker assertions key on the *constant*
  (`trailGateAbsenceCaseMarkers()` returns constants, checked via `strings.Contains`), so citing
  the 32 B `trailReasonPresentOwesNone` constant instead of its 395 B Detail preserves every
  marker-shaped assertion, needs no trim to the shipped reduction, and avoids the
  truncate-past-the-marker hazard `reachCapCommand` creates on overflow. Measured at 445 B against
  a 470 B ceiling (512 − the 42 B `trailNeedle` the leak row asserts would still fit). The decoded
  `reason` scalar is deliberately never interpolated — this arm certifies nothing, so a value from
  the trailer entering its record would both violate that and make the byte budget a function of
  untrusted input.
- **New driver `TestTrailGateNamesThePresenceCaseOnAPathThatOwesNone`** — three rows (P1 the
  headline case, P2 the `max_turns`-wins ordering, P3 the present-and-blank-wins ordering), plus
  a pairwise-containment premise (the new constant checked against all three absence markers, both
  directions) mirroring `TestTrailGateNamesWhichAbsenceCaseFired`. P3 asserts the **case named in
  the Detail** rather than the value — this ticket's arm and the present-and-empty arm answer the
  *same* `trailGateOutOfContract`, so the value alone can't discriminate them.
- **`TestTrailGateReadsTheRunnerPathOnlyWhereARowDeclaresIt`'s exemption widens to cover the
  certified `Reason`.** The usable row gains `pathVaries: true` — it is now the first row in the
  tree whose *certified reason itself* moves with the reading (`"completed"` under ptyrunner,
  empty under streamrunner), which the shipped exemption (Detail + value only) didn't anticipate
  and didn't cover. A new companion sub-test repays the withdrawn coverage **positively**, per
  reading (value, certified reason, and marker), the same shape the absence arm's companion uses,
  plus a distinct-Detail count pinned at exactly two. Clause B (the `RunnerPath` echo check) keeps
  running unconditionally on every row and every reading, unchanged.
- **Leak sweep gains a fourth row** in `TestTrailAdmissibilityRecordsCarryNoCapturedBytes`'
  key-name sub-test, the first of the four to actually reach the new arm (the three shipped rows
  all decode to an empty `TerminalReason` and route into the absence branch). The needle plants
  as a key name, never as the decoded reason — planting it in the decoded reason would exercise
  the channel the shipped usable arm legitimately publishes, so a mutant that made the new arm
  certify would redden the wrong assertion and lose its sole red.
- **Every count this arm moves was re-derived from the code, not adjusted by one**, including the
  return-site arithmetic (ten → eleven, read at three → four, with the "why ten and not eleven"
  argument re-stated for a site a fixture row *does* now reach) and the "N arms answer
  `trailGateOutOfContract`" claim, which turned out to live at **four** sites, not the three the
  ticket itself enumerated — a fourth was found only by reading a live `t.Fatalf` format string a
  comment-only sweep would have missed (`TestTrailGateNamesWhichAbsenceCaseFired`'s own doc,
  `:1243` in the shipped-at-`ffe4120` numbering). No closed set grows: gate space stays six,
  outcome space stays twelve, `trailIsGateValue` and `TestTrailAdmissibilityConstantsAreClosed`
  are byte-identical against baseline.
- **Both stale `#1369` pointers corrected.** #1369 is closed NOT_PLANNED, re-filed as #1427, split
  into this ticket and #1434. One pointer (`trailGateAbsentOwesNone`'s doc) had asserted the
  presence shape was "reaching `trailGateUsable` today" — this arm makes that literally false at a
  streamrunner reading, so it needed rewriting, not just renumbering; the other (the absence arm's
  closing sentence) was a naming-only cite and just gets re-pointed.

## Patterns established

- **An asserting cite breaks on behavior change; a naming cite only goes stale on renumbering.**
  `trailGateAbsentOwesNone`'s doc said the presence shape "reach[es] `trailGateUsable` today" —
  that's a claim about where the shape *lands*, which this ticket falsifies outright, versus the
  sibling sentence naming `#1369`, which stays true in substance and only needed its issue number
  fixed. The two needed different remedies even though both cite the same closed issue.
- **A count claim can live in more places than the ticket that introduces the count thinks.** The
  "N arms answer X" claim was tracked at three sites by the ticket's own enumeration; a residual
  sweep that reads format strings as well as comments found a fourth. Comment-only numeral/word
  sweeps systematically miss claims embedded in `t.Fatalf`/`t.Errorf` format strings.
- **Widening an exemption on a sweep needs a positive companion, not just removed coverage.**
  Covering the certified `Reason` under `pathVaries` stops the sweep from catching a path-varying
  arm that starts to certify — the risk is mitigated by proving the variance positively, per
  reading, in a dedicated sub-test, the same discipline #1420 established for the Detail/value
  exemption.

## Lessons learned

From the PR body's own "Lessons learned" section (developer):

- **A `sole red` claim in a mutant matrix has to be measured per mutant, not asserted per row.**
  Three of the four spec-mandated mutants redden a second test beyond the one named as "sole red"
  (the sweep's `max_turns` row, its present-and-empty row, and the leak sweep's presence row). The
  shipped matrix now names the second red beside each rather than claiming a single sole red that
  measurement doesn't support.
- **A compound mutant can hide which assertion is actually load-bearing.** The obvious mutation
  for "the arm swallows present-and-empty" (hoisting the new arm above the `reason == ""` branch)
  also hoists it above the budget arm, so it reddens the ordering row too and proves nothing about
  which row is the sole discriminator for the swallow. Making the present-and-blank return
  delegate to the presence answer instead is the minimal mutation and isolates the intended row.
- **Re-deriving line cites must be idempotent, because the diff isn't finished when you run the
  sweep.** Applying a HEAD→working-tree line map once and then making further prose edits left
  roughly a third of the cites stale again in a way that looked correct. Re-deriving each cite
  from HEAD's number through a freshly computed map — never from whatever number currently sits in
  the file — is the re-runnable form, and is worth doing as the last step before commit.

From code review (one FAIL → rework → PASS):

- **A cite fix that adds the filename can itself displace downstream cites — sweep that
  displacement in the same commit.** The MUST FIX was `finding_attribution_fanout_test.go:344`'s
  `tdnParsePGIDs` cite: a cross-file insertion had shifted it from `:242-245` to `:252-255` — the
  *next* error branch in the same function, one the exercising fixture cannot reach — because the
  original cite was a bare `(:NNN)` that silently inherited whatever file preceded it rather than
  naming `teardown_liveness_test.go` outright. The fix was to name the file explicitly, which grew
  that line by enough to displace five further cites below it; doing the fix and its own
  displacement sweep in the same commit is what kept this a one-round rework instead of two.
- **A "the only row that declares X" claim needs to check what already declared X before the
  ticket landed**, not just what this ticket adds. The AC's "the usable row is the only row that
  declares `pathVaries`" was imprecise: row nine (the absence-shaped row) already declared it
  since #1420. Two rows declare it after this ticket, not one — recorded here as "the usable row
  gains it" rather than "the only row has it," per the reviewer's NIT.
