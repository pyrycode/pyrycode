# Ticket #1324 — Probe instrument: re-state the gather's and the record's prose about the trailer builder's old input (offline)

Since #1320 (merged at `eea9f91`), `finTrailerBuild` takes the gather's
`finSighting` carrier in place of a `trailObservation`. Two files #1320 never
opened — `finding_run_gather_test.go` and `finding_run_record_test.go` — still
reasoned about the builder's old posture to justify their own: `finSighting`'s
doc described the builder as a pending consumer under the closed-unbuilt
#1308, two sites described the guard as a State/pointer pair the builder
evaluates rather than the one bool it now reads, and the record's "trap-free"
contrast had inverted without being re-stated. Nine prose claims — eight
comments and one `t.Fatalf` string — went false, stale, or forward-looking
about work that had landed. No signature, type, constant, assertion or test
row changed.

## Implementation

- **The one real constraint was layout, not wording.** Both edited files are
  cited by exact line number from `finding_trailer_evidence_test.go` and
  `finding_artifact_write_test.go` — sixteen anchor endpoints in all — and
  this ticket may not touch either citing file. Every hunk had to replace
  exactly N lines with N lines, **at the same start line**, so line numbering
  stayed globally invariant rather than merely net-neutral. `wc -l` equality
  and `git diff --numstat` add==del are necessary but not sufficient: two
  compensating hunks satisfy both while moving every anchor between them. The
  checkable form is per-hunk `@@ -N,k +N,k @@`, confirmed for all nine hunks
  in review.
- **Site D was the hard one.** `finding_run_gather_test.go:445-446` (the
  agreement-obligation comment on the gather's carrier fill) sits *inside*
  `:442-453`, the exact range `finding_trailer_evidence_test.go:222` and
  `:293` cite as "a COPY of it". The comment had to stay exactly two lines in,
  two lines out, with `:443-444`'s State-operand-first ordering argument left
  verbatim — collapsing it would leave the forbidden file's delegation

## Patterns established

- **`wc -l` and `numstat` add==del are not sufficient to prove a line-cited
  file's cites survived a rewrite — per-hunk `@@ -N,k +N,k @@` at an
  unchanged start line is the checkable invariant.** Two compensating hunks
  (one `+1`, one `−1`) elsewhere in the file satisfy both weaker checks while
  still moving every anchor between them. Reusable anywhere a file is cited
  by exact line number from a file the current ticket cannot touch.
- **A "reflow this comment" instruction can silently retype prose the ticket
  marked unchanged.** Hand-rewrapping a paragraph around one replaced
  sentence risks a transcription slip nothing would catch. The checkable
  form: regenerate the wrapped block from `git show HEAD:<file>`, replace
  only the targeted sentence, and diff the whitespace-collapsed retained half
  against `HEAD` rather than trusting a manual re-read.
- **An inherited correction from a parent ticket can itself be false, and the
  reason is usually that the parent's assumption about the implementation
  didn't survive contact with what actually shipped.** Here the parent
  assumed per-call-site inline fills; #1320 shipped one fixture-side helper
  instead, which is a second computation of the same pair, not the
  absence of one. Before adopting a parent ticket's suggested replacement
  text verbatim, check it against what actually shipped, not against what
  the parent ticket assumed would ship.

## Lessons learned

(From the PR body and code review; see PR #1328.)

- **Line-width budget forces the wording, not taste.** Site F's `t.Fatalf`
  had to keep its field-justification clause and gain "the one bool
  `finTrailerBuild` gates on" inside four lines whose file neighbours run
  78–89 bytes. Measuring the file's existing maximum first turned "does this
  fit" into arithmetic, and the phrasings that fit were a strict subset of
  the phrasings that read well.
- **A retirement-adjacent rewrite should re-verify the arity of any "the two
  must agree" claim it re-states, not just restate it.** Code review
  independently confirmed the pair `State == trailSeen && …Trailer != nil` is
  computed in exactly two places package-wide before accepting "the two
  computations must agree" as exact rather than approximate.
- **A blast-radius sweep for line cites should search the whole repo, not
  just the two files a spec's anchor table names.** Four more cites into the
  edited files turned up outside the spec's own table on this ticket; all
  verified unaffected, but the spec's table was not exhaustive by
  construction and review treated it as a floor, not a ceiling.
