# Ticket #1038 — re-home `list_conversations` + `recent_workspaces` tests off the v1 Dispatcher harness

Split from #966 (the dead v1 `dispatch.Dispatcher` deletion). Two handler
tests — `list_conversations_test.go` and `recent_workspaces_test.go` — were
the last consumers of the orphaned v1 `Dispatcher` (`New`/`Config`/`Run`/
`Register`/`Outbound`, zero production callers since #913 slice 1) as a test
scaffold. This ticket migrates both onto the direct-call pattern every other
handler test in the package already uses, so the follow-on `Dispatcher`
deletion doesn't break their compilation. No production code changed.

## Implementation

`559191a` (spec) + `46b07e4` (dev), 121 lines changed across the two test
files, zero production files touched:

- **`list_conversations_test.go`** — replaced `runListConvDispatcher` (the
  `go d.Run(ctx)` + cancel teardown) and `recvOutbound(t, d)` with
  `newListConvConn(t) (*dispatch.Conn, func() protocol.RoutingEnvelope)`,
  mirroring `newCreateConvConn` in `create_conversation_test.go`: a buffered
  (`cap 4`) `out` channel, `dispatch.NewTestConn(listConvConnID, out, nil)`,
  and a `recv()` closure with a 2s timeout. `makeListConversationsFrame` (which
  marshaled to a `RoutingEnvelope` frame) became `makeListConversationsRequest`,
  returning a bare `protocol.Envelope` for direct handler invocation.
  `decodeConversationsResponse` was untouched — it already consumed a
  `RoutingEnvelope`, which `recv()` still produces.
- **`recent_workspaces_test.go`** — `runRecentWorkspaces` was rewritten to be
  self-contained: it used to call `runListConvDispatcher`/`recvOutbound` from
  the *sibling* file, both deleted here, so it now builds its own `out` +
  `dispatch.NewTestConn(recentWSConnID, out, nil)` and invokes the handler
  directly inline. `"context"` was added to the import block (needed for
  `context.Background()` — this file never imported it because it borrowed
  the sibling's context-carrying helper). `testLogger(t)` dropped from both
  files — the handlers take no logger; only the old `dispatch.Config` did.
- **Crux preserved**: `TestListConversations_InReplyToAndIDMonotonic` reuses
  a single `*dispatch.Conn` across two sequential `h(ctx, c, ...)` calls so
  `NextID` advances 1→2, matching the old harness's same-`ConnID` routing
  behavior. A fresh conn per call would have silently reset the second
  reply's `ID` back to 1 — the spec called this out explicitly and the
  implementation followed it.
- Every existing assertion (payload bytes, `InReplyTo`, `ID`, field
  projection, ordering, dedup, archived-flag, tie-break) carries over
  unchanged; the only net-new lines are explicit `if err := h(...); err !=
  nil { t.Fatalf }` checks, a strengthening over the old dispatcher's
  implicit log-and-drop.

Code review: PASS, no findings, all 5 ACs verified (see PR #1043).

## Patterns established

- Every handler test in `internal/relay/handlers` now uses the same
  direct-call harness shape: `dispatch.NewTestConn(connID, out, nil)` +
  `h(context.Background(), c, req)` + read the reply off a buffered `out`
  channel. `create_conversation_test.go`'s `newCreateConvConn` was already
  the template; this ticket brought the last two holdouts into line. The v1
  `dispatch.Dispatcher` (`New`/`Config`/`Run`/`Register`/`Outbound`) now has
  zero references anywhere in `internal/relay/handlers`, clearing the way
  for its deletion (the #966 follow-on).
- When migrating a shared test harness off a to-be-deleted primitive, grep
  for helpers borrowed *across sibling test files in the same package* before
  deleting them — `recent_workspaces_test.go`'s `runRecentWorkspaces` silently
  depended on `list_conversations_test.go`'s `runListConvDispatcher` /
  `recvOutbound`, which isn't obvious from reading either file in isolation
  and would have broken compilation if the files were migrated one at a time.
