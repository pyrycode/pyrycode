# Ticket #929 — TestRelayV2_InterruptStopsRunningTurn: keep the responding signal live until the producer subscription settles

`TestRelayV2_InterruptStopsRunningTurn` (`internal/e2e/relay_v2_interrupt_test.go`,
the #794 live remote-interrupt capstone) sat red since the #839/#854 lineage
merged. It failed deterministically at AC1 — "interactive phone A never observed
a non-idle turn_state before the interrupt; the harness never started a turn."
Flagged as a follow-up in [#918](918.md) and #930; this ticket fixes
it. #930 is the same-shape sibling (`TestTwoPhoneStructured_InteractiveReceivesStream`),
left red, not fixed here.

## Root cause — not a session-id divergence; a subscription-offset race

The original hunch was that the daemon and fakeclaude write/tail *different*
session files. Runtime evidence disproves that. The daemon spawns
`claude --session-id 66666666-6666-4666-8666-666666666666` (the seeded bootstrap
id, `seedBootstrapRegistry`), fakeclaude opens `<that-id>.jsonl` from
`PYRY_FAKE_CLAUDE_INITIAL_UUID` (same id), and the structured-turn producer's
diagnostic log confirms it subscribes to exactly that file. The two agree. The
title's "argv-immune fakeclaude honour --session-id" fix is a no-op here — both
sides already use the same id.

The real failure is a tail-offset race introduced when the bootstrap transcript
resolver changed:

- Pre-#854 the structured producer resolved the bootstrap transcript by
  recency (`resolveLatestSessionJSONL`). It found the pre-created
  `<initialUUID>.jsonl` **immediately at startup** and subscribed at a tiny
  offset, exactly as the #794/#642 spec assumes ("pre-create `<initialUUID>.jsonl`
  so the producer resolves at a tiny offset at startup and every appended line
  lands in the tailed range").
- #854 switched the bootstrap branch to `resolveOwnBootstrapJSONL`, which tails
  the transcript the daemon's OWN child has open (via the lsof PID probe) — a
  confidentiality fix so a second claude in the shared dir can't redirect the
  tail. But the probe returns "no jsonl open yet" until fakeclaude's child fd is
  seen, so the producer sleeps one `subscribeRetryDelay` (500 ms) and only then
  subscribes, **at EOF**. The conversation-bind re-subscribe (empty cursor →
  routed convID, both resolving to the bootstrap host) builds a fresh resolver
  that likewise tails from EOF.

The test dropped the single mid-turn assistant-text line right after the
`send_message` ack. That ack fires at enqueue time, ~500 ms before the producer's
subscription settles, so fakeclaude appends the line into the file *below* the
eventual EOF offset. The settled tail starts past it, no `turn_state` is ever
emitted, and AC1 times out. Real claude never hits this: it streams assistant
output continuously over the turn, so its output lands after the (delayed) tail
offset. fakeclaude's instant single-shot append races the 500 ms settle.

## Fix — re-drop the mid-turn line until AC1 observes the turn

Test-only, in `relay_v2_interrupt_test.go`. The mid-turn line is now RE-DROPPED
on a 250 ms ticker (a goroutine, stopped via `sync.Once`) instead of written
once. A real running turn streams output continuously until interrupted; the
re-drop mirrors that, so whichever tail settles first catches a responding line
and the emitter surfaces `turn_state{responding}`. The kicker is stopped the
instant AC1 observes the turn — strictly before the interrupt frame is sent — so
fakeclaude's bare-ESC handler stays the ONLY source of an end-of-turn line. No
guard or assertion is weakened:

- **Vacuous-pass guard #1** (a non-idle `turn_state` MUST precede the interrupt):
  unchanged; the kicker only makes the turn reliably *start*, it does not assert
  anything.
- **Vacuous-pass guard #2** (a `turn_end` MUST follow, and its ONLY source is the
  ESC handler): intact — the re-dropped line is assistant-text, never an
  `end_turn`, so re-dropping can never fabricate a `turn_end`; and the kicker
  stops before the interrupt, so no responding line trails the Esc.

The daemon path is untouched: the producer's EOF-tail-on-settle behaviour is
correct for real claude (content streams after the subscribe). The
regression was the harness assuming an *immediate* startup subscribe that #854's
PID probe no longer provides.

## Lessons learned

- **A "session file mismatch" hypothesis is cheap to falsify with one daemon log
  line.** Running the daemon with `-pyry-verbose` surfaces `turnbridge:
  subscribed to session jsonl path=… offset=… cold_start=…`; it named the exact
  file and offset, turning a guessed argv/session-id fix into a confirmed
  offset-race diagnosis in one run.
- **#930 shares this root cause.** `TestTwoPhoneStructured` fails identically
  (0 structured envelopes) for the same reason: its 4-line fixture, dropped once
  after the ack, lands below the settled EOF tail. Its fix is not a straight
  copy — the fixture's last line is an `end_turn`, so a blind re-drop would
  re-fire the turn end. Tracked separately as #930.
