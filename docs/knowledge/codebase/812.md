# Ticket #812 — Stream a large bundle to a paired client in frame-cap-respecting chunks

Delivers the **debug-bundle streaming primitive**: `StreamBundle` moves an
arbitrarily-large `[]byte` (the #811 assembler's output) to one addressed, open,
authenticated v2 conn as ordered, cap-respecting `debug_bundle_chunk` frames
ending in a `debug_bundle_done` completion marker. It rides the manager's own
**asynchronous** `Push` → `drainOnce` → `forwardEnvelope` path — the same path
every unsolicited daemon → client frame uses — never the synchronous
handler-reply channel. This defeats both walls that stop a bundle riding a normal
reply: the 65535-byte AEAD frame cap (`maxNoisePayloadBytes`) and the 8-slot
`handlerOutboundBuf` that deadlocks on >8 sends from a handler. **Ships unwired**
(test-driven only); the request verb that triggers a stream for the debug bundle
is sibling #813. Split from #803.

Spec: [`812-stream-bundle-frame-cap-chunks.md`](../../specs/architecture/812-stream-bundle-frame-cap-chunks.md).
The streaming method is documented in the manager's feature doc,
[v2-session-manager.md § Debug-bundle streaming](../features/v2-session-manager.md#debug-bundle-streaming-812--streambundle--bundleenvelopes--reassemblebundle);
the wire vocabulary in [protocol-package.md](../features/protocol-package.md) and
[protocol-mobile.md § Debug bundle](../../protocol-mobile.md#debug-bundle-v2).

## Implementation

- **Wire vocabulary — `internal/protocol`** (byte-generic, bundle-specific type
  strings, the architect's Simplicity-First call over reusing the
  message-transcript `message_chunk`/`backfill_done` vocab, which carries
  `[]MessagePayload`):
  - `codes.go` — a new v2-only const block: `TypeDebugBundleChunk =
    "debug_bundle_chunk"`, `TypeDebugBundleDone = "debug_bundle_done"`. Both are
    outbound binary → phone; both **MUST NOT** be added to `v1TypeSet`.
  - `messaging.go` — `DebugBundleChunkPayload{Seq int; Data []byte}` (`Data`
    auto-encodes std base64 via `encoding/json`) and `DebugBundleDonePayload{Total
    int}`. `Seq` is 0-based, contiguous, ascending; `Total` is the exact chunk
    count so the receiver detects truncation.
  - `compat_test.go` — the two types registered in **all three** drift-detector
    spots (`v2OnlyTypes`, the `TestTypeConstants_V1V2Partition` `all` list, and
    `TestIsV1Compatible`'s `-rejected` cases), never in `v1TypeSet`. Golden
    fixtures `testdata/debug_bundle_chunk.json` / `debug_bundle_done.json`.
- **Streaming primitive — `internal/relay/v2bundlestream.go`** (new file; the
  whole byte-stream concept in one place, depending only on `internal/protocol` +
  the in-package `maxNoisePayloadBytes`):
  - `bundleEnvelopes(blob []byte) ([]protocol.Envelope, error)` — pure chunker.
    Splits into `ceil(len/bundleChunkBytes)` `debug_bundle_chunk` envelopes with
    ascending 0-based `Seq`, then appends one `debug_bundle_done{Total: n}`. Empty
    blob → 0 chunks + `done{total:0}` (a valid stream reassembling to empty).
    `EventID` left **nil** on every envelope, so `forwardEnvelope`'s
    reconnect-replay dedup guard is inert for bundle frames; `ID` is
    non-load-bearing (set to `Seq`/`Total` for debuggability only — the receiver
    keys on Type+Seq+Total).
  - `StreamBundle(ctx, connID, blob) error` — a new `*V2SessionManager` method:
    build envelopes, then `m.Push(ctx, connID, env)` for each in order; returns
    the first `Push` error and stops (a not-open conn → `ErrConnNotFound`, no
    point continuing). Returns on **enqueue**, not delivery (delivery is async on
    `Run`). Logs one content-free debug line (`conn_id, chunks, bytes` counts).
  - `ReassembleBundle(frames []protocol.Envelope) ([]byte, error)` — exported,
    pure **receiver-contract reference + test oracle** (production use is
    phone-side, out of repo; the daemon has **no inbound caller**). Requires each
    chunk's `Seq == next`, requires `done.Total == next`, skips interleaved
    non-bundle frames, and returns `(nil, err)` on **any** failure — never partial
    or corrupt bytes.
- **`bundleChunkBytes = 48000`** — the raw bundle bytes per chunk, chosen with
  ~1.3 KB headroom below the frame cap (base64 ×4/3 + ~200 B JSON wrapper + 16 B
  AEAD tag → ~64216 B ciphertext < 65535). The **conservative const is the belt**;
  `TestStreamBundle_EveryFrameWithinCap` (which decrypts every emitted frame and
  asserts `len(ciphertext) <= maxNoisePayloadBytes`) is the **suspenders**.

## Patterns established

- **Ride the async push path, not the synchronous handler-reply channel — the
  whole point of the ticket.** `Push` enqueues onto the per-conn `pushQueue`
  (leaf-lock + non-blocking `drainCh` signal) and returns; `Run`'s `drainOnce`
  seals one envelope per pass on the single owner goroutine. So `StreamBundle` is
  callable from any goroutine — including a future #813 handler on the `Run`
  goroutine — and can emit N+1 frames of any size without touching `s.send` or
  the 8-slot `handlerOutboundBuf`. Bundle frames are **control-class** (`Type !=
  TypeAssistantDelta`), so the `pushQueue` drop policy never evicts them (they
  soft-overflow past the 256 cap) — all chunks are delivered, in order (AC#2).
- **Two independent integrity nets, different fabric.** The AEAD (ChaChaPoly)
  guarantees per-frame *content* integrity on the wire, so intra-chunk corruption
  is impossible; `Seq` + `Total` add deterministic *structural* gap / reorder /
  truncation / count-mismatch detection in `ReassembleBundle`. Crypto net +
  structural net — neither a stochastic rule.
- **Belt-and-suspenders on the frame cap.** A conservative human-chosen const
  bounds chunk size; a deterministic per-frame cap test enforces the invariant.
  The `bundleChunkBytes` doc-comment pins the rule: **if the cap test ever fails,
  LOWER the const — never raise it.**
- **A truthful receiver contract needs the reassembler in-repo.** You cannot test
  "fail cleanly on a truncated / reordered stream" (the correctness note) without
  a reassembler to fail; `ReassembleBundle` is exported as that oracle even though
  the daemon never calls it inbound.

## Lessons learned

Lifted from the PR body's "Lessons learned" section (developer-flagged, non-obvious):

- **`bundleChunkBytes = 48000` is deliberately conservative** (~1.3 KB headroom
  under the 65535 ciphertext cap); the invariant is enforced deterministically by
  `TestStreamBundle_EveryFrameWithinCap` — belt (conservative const) + suspenders
  (per-frame cap test), different fabric. If that test ever fails, **lower the
  const, never raise it.**
- **The AC#4 never-log test must set the slog handler to `LevelDebug` and assert
  the `v2.bundle.stream` line is actually captured**, else the "streamed bytes
  absent from log" check is vacuous — `StreamBundle` logs at debug, and an
  Info-only handler drops every record, so the test would pass by observing an
  empty log. `TestStreamBundle_NoBytesLogged` first asserts the line is present,
  then asserts neither the recognizable blob bytes nor their base64 appears in any
  emitted record.

## Notes

- **No ADR.** The architect's wire-vocabulary decision (add byte-generic
  bundle-specific type strings vs. reuse `message_chunk` / generalize a byte-stream
  type) is package/ticket-scoped — exactly one planned consumer (#813) — and is
  fully captured by the spec + the `codes.go` const-block comment. It is not a
  cross-cutting convention future tickets must follow (same call as #811).
- **Code review: PASS, no findings.** The `code-review` commit re-committed only
  the unrelated golden-file churn (`permission_protocol_v2.1.199.json` — the known
  non-defect auto-commit churn), not any implementation change.
- **Out of scope (deferred, no observed need):** *who* may trigger a stream (the
  DoS-trigger surface) and any per-request authorization are **#813's** concern —
  this primitive is unwired and faithfully streams whatever `(blob, conn)` it is
  handed. Chunk-level flow control is deferred: a multi-MB blob transiently buffers
  N+1 control-class envelopes in the `pushQueue` (memory bound ≈ blob size × ~1.33
  base64, released as `Run` drains) — acceptable because debug bundles are
  operator-initiated, infrequent, and already fully in RAM (#811 assembles
  in-memory).
