# Ticket #257 — e2e: migrate `spawnAttachableDaemon` to the argv-dropping wrapper

`spawnAttachableDaemon` (`internal/e2e/attach_pty.go`) wired the supervised "claude" as
`-pyry-claude=os.Args[0]` — the Go e2e test binary itself, unwrapped, with
`-- -test.run=TestHelperProcess` trailing. `Pool.Create` appends `--session-id <uuid>` to every
built session's claude argv (bootstrap included, since #839), which reached the Go test
framework's `flag.Parse()` and exited 2 (`flag provided but not defined: -session-id`) before
`TestHelperProcess` ever ran. Every test routing through `spawnAttachableDaemon` — the four
`TestE2E_Attach_*` PTY tests plus the stdio round-trip test — was red or skipped as a result. This
is mechanism 2 of #918's three-way decomposition (`docs/knowledge/codebase/918.md`); #918
(`/bin/sleep` default stand-in) and #929 (argv-immune fakeclaude daemon regression) are the
sibling mechanisms, no file overlap.

## Implementation

- `spawnAttachableDaemon` now calls `writeEchoClaude(t, home)` (the wrapper `spawnAutoAttachDaemon`
  / #163 already defined in `auto_attach.go`) and passes it as `-pyry-claude=`, dropped the
  trailing `"--", "-test.run=TestHelperProcess"` args (the wrapper supplies that itself via its own
  `exec` line), and added `E2E_HELPER_BIN=os.Args[0]` to the daemon's env. `writeEchoClaude` /
  `echoClaudeScript` were reused verbatim — no new helper.
- `StdioAttachClient.Stderr` (`internal/e2e/attach_stdio.go`) changed type from `*bytes.Buffer` to
  `*safeBuffer` (the mutex-wrapped buffer already used elsewhere in the package) to guard the
  `os/exec` stderr-copy-goroutine-vs-diagnostic-read race under `-race`. Every read site
  (`.String()`) is source-compatible; no other edits needed.
- Removed the `t.Skip` on `TestE2E_AttachStdio_BytesRoundTrip` (`attach_stdio_test.go`) and its
  stale rationale comment — the blocker it described (#257 itself) is what this ticket fixes.
- Removed the `t.Skip` on `TestE2E_AttachStdio_NoPTYInProcessTree` (`attach_stdio_no_pty_test.go`).
  Its cited reason was stale `#167` (landed independently); the test passed cleanly once
  `spawnAttachableDaemon` was fixed, so it stays unskipped rather than needing a new skip reason.
- Doc comment on `spawnAttachableDaemon` rewritten to describe the wrapper indirection, mirroring
  `spawnAutoAttachDaemon`'s comment.

Full write-up of the wrapper mechanism, the `--session-id` collision, and the now-corrected forward
references to this ticket lives in
[`features/e2e-harness.md`](../features/e2e-harness.md) — see § Helper "claude" via
`TestHelperProcess` re-exec, § Round-trip test unskipped by #257, and § Neither #167 nor #257
reaches this code path.

## Patterns established

- No new pattern — this is the second (and last) application of the argv-dropping wrapper pattern
  #163 established for `spawnAutoAttachDaemon`. Both `e2e`-tagged daemon-spawning helpers in the
  package now use it; the third `e2e || e2e_install`-tagged one (`harness.go`'s default stand-in)
  uses the sibling `writeSleepClaude` pattern from #918 for the same reason (survive
  `Pool.Create`'s appended flag) with a different wrapper shape (sleep vs. echo).
- Confirms the `harness.go` → `safeBuffer` build-tag precedent generalizes cleanly:
  `attach_pty.go` (`e2e || e2e_install`) referencing `writeEchoClaude` (`e2e`-only, in
  `auto_attach.go`) compiles under both supported build modes (`-tags e2e`, `-tags "e2e
  e2e_install"`); pure `-tags e2e_install` was already broken on `main` before this ticket touched
  anything, and stays that way (not a supported build mode).

## Lessons learned

- The `Pool.Create` `--session-id` append is unconditional (every built session, bootstrap
  included), not "non-bootstrap only" — the same false narrowing that tripped up #918's original
  scoping. Any future e2e stand-in that supervises a real Go test binary (or any binary with its
  own strict flag parser) as "claude" needs the argv-dropping wrapper treatment from the start;
  bare binaries don't survive `Pool.Create`.
- (From the PR description.) The stale `#167` gate on `TestE2E_AttachStdio_NoPTYInProcessTree` was
  purely the flag-parser blocker in disguise — once the wrapper landed the test passed with **no**
  fd-inspection change, confirming #167 itself had landed cleanly well before this ticket. A skip
  reason citing a landed ticket number is a reliable signal the real blocker moved elsewhere (here,
  silently onto #257) rather than the cited ticket regressing.
- Code review's full-suite run reconfirmed the same two pre-existing red-on-main tests #918 had
  already filed as #929 (`TestRelayV2_InterruptStopsRunningTurn`) and #930
  (`TestTwoPhoneStructured_InteractiveReceivesStream`) — byte-identical to `main`, fail in isolation
  with zero attach tests running, reference none of this ticket's changed symbols. No new ticket
  needed; existing attribution held.
