# Ticket #910 — `ResolveWorkdir` canonicalises path components to on-disk case

Reliability-review finding (2026-07-10), tracing back to a production incident on 2026-05-29 (#208): `ResolveWorkdir`'s doc comment claimed to "mirror how claude resolves a workdir before reading `~/.claude.json`'s projects map," but the body only ran `filepath.Abs` + `filepath.EvalSymlinks`. On a case-insensitive filesystem (default macOS APFS), `EvalSymlinks` preserves the **input** case of any non-symlink component, while claude canonicalises its cwd to the **on-disk** case before its trust lookup. A workdir configured with the wrong case (the real incident: `.../WorkSpace` in an agents-fork `.env`, `.../Workspace` on disk) made `trust.MarkWorkdirTrusted` pre-mark a `projects` key claude never reads — claude rendered the trust-folder modal, and `ptyrunner.Run`'s `WaitReady` classification aborted with `ErrTrustModalDetected`. Every dispatch on that fork parked until an operator diagnosed the path-case typo. `security-sensitive` because the fix touches the canonicaliser that feeds both the trust-map key and (in all three spawn flows) the child's spawn `WorkDir`. See [`features/agentrun-package.md`](../features/agentrun-package.md) § Key shape and [`features/agentrun-trust-subpackage.md`](../features/agentrun-trust-subpackage.md) § Key shape for the updated contract.

## Implementation

- **One production file, `internal/agentrun/workdir.go`** (+74/-5). No signature change — `ResolveWorkdir(workdir string) (string, error)` is unchanged, so there is no downstream fixture cascade and the fix reaches all three spawn flows (`agent-run`, daemon bootstrap, per-conversation) with zero consumer edits, since each routes its spawn cwd through `trust.MarkWorkdirTrusted`'s return value, which is `ResolveWorkdir`'s output.
- **New unexported `canonicalCase(path string) string`** runs after the existing `Abs` → `EvalSymlinks` steps. It walks the already-resolved, symlink-free, existing path component-by-component from the root, calling `os.ReadDir` at each level and rewriting the component to its on-disk spelling via `matchEntry`. It is infallible by construction — `path` is already validated by a successful `EvalSymlinks`, so `canonicalCase` only ever *improves* casing; any obstacle (unreadable ancestor) degrades to keeping the input component verbatim.
- **`matchEntry(entries []os.DirEntry, target string) string`** — the per-component rule, in priority order: (1) an exact-case entry always wins, regardless of any fold match — this is both the no-regression fast path (AC-3) and the case-sensitive-fs sibling-safety guarantee; (2) with no exact match, a *unique* `strings.EqualFold` match is the on-disk spelling (case-insensitive filesystems cannot hold two names differing only by case, so uniqueness is structural); (3) zero matches, or ≥2 fold matches with no exact one, keep the input component unchanged — never guess an arbitrary sibling.
- **No new error path.** `canonicalCase` cannot fail; the only errors `ResolveWorkdir` returns remain the pre-existing `Abs`/`EvalSymlinks` wraps, and a case-sensitive filesystem given a wrong-cased input still fails at `EvalSymlinks` (the path doesn't exist under that spelling) before `canonicalCase` ever runs — so wrong-case-on-case-sensitive-fs cannot resolve to a same-cased sibling by falling through the new step.
- **Confine helpers (`confineWorkdirToHome{,Creating}`, `withinDir` in `cmd/pyry/main.go`) are untouched.** The two daemon flows resolve the workdir twice: the confine helper's `EvalSymlinks`-based check runs first and produces a possibly-wrong-cased realpath; `trustMark`/`ResolveWorkdir` then re-resolves that same physical directory to on-disk case. Case-canonicalisation only re-spells components of the same inode (case-insensitive fs) or is a no-op (case-sensitive fs, exact match), so it cannot move the path outside `$HOME` after confinement already accepted it — no re-audit of the confinement code was needed.
- **Doc comment rewritten (AC-4)** to describe the actual three-step contract (`Abs` → `EvalSymlinks` → on-disk-case walk) instead of the prior "mirrors claude" claim that omitted case.
- **Tests** — `internal/agentrun/workdir_test.go` gained three cases (`_CaseMismatchFoldsToOnDiskCase`, `_CorrectlyCasedMixedCaseUnchanged`, `_SiblingSafetyCaseSensitive`); `internal/agentrun/trust/trust_test.go` gained one full round-trip (`TestMarkWorkdirTrusted_CaseMismatchWritesOnDiskKey`) asserting the written `projects` key equals `ResolveWorkdir`'s on-disk-cased output. All four case-dependent tests probe filesystem case-sensitivity **at runtime** (create a directory, `os.Stat` a differently-cased spelling) rather than gating on `runtime.GOOS`, and `t.Skip` when the probe doesn't match the scenario they need — robust against a case-sensitive APFS volume, which macOS permits but does not default to.

## Patterns established

- **Exact-match-first, unique-fold-only is the general shape for any case-insensitive-filesystem canonicaliser that must stay safe on case-sensitive filesystems.** Preferring an exact match unconditionally, and folding only when the fold is unambiguous, means the same code path is simultaneously "fix the bug on macOS APFS" and "never introduce sibling-confusion on Linux ext4" — no `runtime.GOOS` branch needed. Generalises to any future pyrycode path-canonicalisation code.
- **Runtime filesystem-case probing beats `runtime.GOOS` gating for case-sensitivity-dependent tests.** macOS APFS can be formatted case-sensitive, so `GOOS == "darwin"` is not a reliable proxy for "this test's case-insensitive-fs scenario applies here." Probe by creating a directory and `os.Stat`-ing a differently-cased spelling (or attempting to create a differently-cased sibling), then `t.Skip` if the probe doesn't match.
- **A canonicaliser sitting between an already-validated path and its consumer can be infallible by contract.** Because `canonicalCase` only runs on `EvalSymlinks`'s successful output, it never needs its own error return — "can only improve, never fail" is a stronger and simpler contract than "best-effort, may error."

## Lessons learned

- **A doc comment that promises a contract ("mirrors how claude resolves...") the code doesn't fully honour is itself a latent bug report.** The gap between "resolves symlinks" and "resolves symlinks *and case*" sat undetected until a real incident traced back to it. When a spec references matching an external system's behavior, the doc comment is worth auditing against that system's actual behavior, not just against the code's current behavior.
- **A single-caller, single-file fix can cover multiple consumer flows for free when those flows are documented to route through the same return value.** The architect's spec traced all three spawn flows (agent-run, daemon bootstrap, per-conversation) to confirm each uses `trustMark`'s return as its spawn cwd before concluding the fix needed no consumer edits — worth doing explicitly (a table, not just an assertion) whenever a shared-return-value argument is load-bearing for a fix's scope.
