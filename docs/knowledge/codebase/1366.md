# Ticket #1366 — Probe instrument: classify a result trailer's `terminal_reason` against the observed runner path (offline)

`resultTrailer.TerminalReason` is a plain `omitempty` string, so after decode
an **absent** `terminal_reason` and an emitted `"terminal_reason":""` are the
same value: `""`. #1357 landed the reading that separates them —
`trailScanResult.KeyNames`, the sorted top-level key names read off the full
line before the 512-byte cap — but nothing consumed it. This ticket ships the
predicate that does: absence means *opposite* things on the two runner
paths (ptyrunner's trailer is pyry's own and owes a non-empty reason by
construction; streamrunner's is claude's own `result` line on a healthy run
and owes none at all), and neither the decoded scalar nor the key names alone
can say which. The pair, plus the observed runner path, can. **No live
claude, no verdict reached, no production code touched, no caller** — one
new test-only file; #1367/#1368 wire it in.

## Implementation

- **One new file**, `internal/e2e/realclaude/trailer_terminal_reason_test.go`
  (643 lines, `//go:build e2e_realclaude`), plus a six-entry extension of
  `TestTrailAdmissibilityConstantsAreClosed`'s union map in
  `trailer_admissibility_test.go` and two re-pointed inbound cites
  (`finding_attribution_fanout_test.go:700`,
  `trail_run_outcome_test.go:1135` — both now land on
  `trailer_admissibility_test.go:984`, the shifted
  `TestTrailAdmissibilityRecordsCarryNoCapturedBytes` doc-comment line).
- **The value space** — six `reason-`-prefixed constants (the prefix mirrors
  `gate-`'s reason: a copy-paste between value spaces must look wrong, not
  plausible): `trailReasonAbsentOwesNone`, `trailReasonPresentOwesNone`,
  `trailReasonAbsentOwesOne`, `trailReasonBlankOwesOne`,
  `trailReasonNamedOwesOne`, `trailReasonPathUnnamed`. `Absent`/`Blank`/`Named`
  are three different words rather than three inflections of "present" —
  the space's whole point is refusing to collapse absence into emptiness, and
  near-identical identifiers would make that collapse a plausible typo.
  `trailReasonPresentOwesNone`'s doc comment carries the claim limit AC5
  requires: it says the line is *not that path's documented healthy shape*
  and never that pyry wrote it, citing `streamrunner/runner.go:170-176` (the
  passthrough) as the reason claude can produce the same reading —
  emptiness is deliberately not split further here, since a present-and-empty
  reason from streamrunner is as much "not the healthy shape" as a
  non-empty one.
- **The predicate** —
  `trailReasonAgainstPath(runnerReading string, keyNames []string, decodedReason string) trailReasonResult`.
  Pure, no error return, three scalars in (never `trailScanResult` or
  `trailObservation` — that would drag the verbatim-model-output `Line` field
  and the nil-`Trailer` pointer trap into reach). `keyNames` sits between the
  two same-typed strings so a parameter transposition isn't silently
  compiler-legal — no struct, since a transposition here only produces a
  wrong value, not a publication. Behaviour: reduce `runnerReading` with the
  shipped `finRecordRunnerLabel` (never re-parsed, never prefix-matched —
  `reachRunnerPathFromArgv` is explicitly not used because it keys on
  `--append-system-prompt-file`, which both argv builders pass, and has no
  `streamrunner` answer at all); read presence from `slices.Contains(keyNames,
  trailReasonKeyName)` alone, **never** from `decodedReason != ""`; switch on
  the reduced label (`"streamrunner"`, `"ptyrunner"`, default). The default
  arm is deliberately not the fall-through catch-all `trailGate`,
  `trailAdmitAttribution` and `trailClassifyRun` each refuse — there is no
  out-of-contract value in this space, because `trailReasonPathUnnamed`'s
  meaning ("the path reading names no runner") is a true, positive statement
  about the reading regardless of what it is, so it cannot launder a claim
  about pyry.
- **No input byte interpolates, at all.** Every arm's `Detail` (formatted
  through `trailDetail`, capped at 512 bytes) interpolates only this file's
  own constants, `finRecordRunnerIndeterminate`, the two bare runner-label
  literals, and file cites — never `runnerReading`, its reduced label, a key
  name, or `decodedReason`. Stronger than AC5 requires (the reading is
  admissible as one of `tdnRunnerFromArgv`'s constant answers), chosen to make
  the guarantee structural rather than a discipline.
- **`trailIsReasonValue(v string) bool`** — membership helper,
  `trailIsGateValue`'s shape verbatim. #1367/#1368 must call it rather than
  re-switch.
- **Closure is checked in two places** because the union map can't catch
  both failure modes: the six join the existing map (catches a *colliding*
  value, never an *unhandled* one — the doc comment there is amended to name
  `trailReasonAgainstPath` as the fourth space); the new table test asserts
  the set of values its nine rows *reach* is exactly the six (catches the gap
  the map can't).

## The five acceptance criteria, and how each is proved

- **AC1 (closed six-value set)** — the constants themselves, `reason-`
  prefixed and pairwise distinct; `TestTrailReasonAgainstPath`'s reached-set
  check (see below) is the executable half.
- **AC2 (presence from key names, never the scalar)** —
  `TestTrailReasonPresenceComesFromTheKeyNames` drives
  `trailKeyNamesNoTerminalReason()` and `trailKeyNamesEmptyTerminalReason()`
  under one fixed ptyrunner reading, asserts they reach *different* values
  (`trailReasonAbsentOwesOne` / `trailReasonBlankOwesOne`), and in the same
  test asserts both decode through `resultTrailer` to the identical `""` —
  the second half is what proves the decode alone could not have answered
  this.
- **AC3 (shipped reduction, indeterminate outranks a qualifying shape)** —
  `TestTrailReasonAgainstPath` reduces via `finRecordRunnerLabel` throughout;
  a dedicated sub-test drives all three `indeterminate (...)` variants
  `tdnRunnerFromArgv` can produce (empty argv, both flags, neither flag)
  against the present-and-non-empty shape that reaches
  `trailReasonNamedOwesOne` on ptyrunner, and asserts all three still land on
  `trailReasonPathUnnamed` — with a distinctness fatal so the sub-test can't
  silently drive one variant three times.
- **AC4 (exhaustive nine-row table)** — `TestTrailReasonAgainstPath` builds
  the cross product of three real `trailScan` shapes and three real
  `tdnRunnerFromArgv` readings in code (never hand-listed), asserts the
  generated row count is 9, asserts `got.Value != want` (not "is/is not
  unnamed" — see Lessons learned below on why that distinction matters), and
  asserts every Detail is non-empty and untruncated.
- **AC5 (no captured bytes, claim-limited V2)** —
  `TestTrailReasonResultCarriesNoCapturedBytes`, two sub-tests, one distinct
  needle per input position (`trailReasonNeedles()`). Sub-test A needles the
  key names and the decoded scalar; sub-test B needles the reading's
  parenthesised tail specifically — the part `finRecordRunnerLabel` strips —
  so a reduction that retained the whole string, or a `Detail` that echoed
  the reading, goes red there and nowhere else. Both fatal on the reached
  value (`trailReasonNamedOwesOne`) before marshalling, so a predicate
  answering `trailReasonPathUnnamed` can't pass by leaking nothing.

## Patterns established

- **A default arm can be the honest answer, not the forbidden catch-all,
  when its meaning is a true statement about the input regardless of what
  the input is.** `trailGate`/`trailAdmitAttribution`/`trailClassifyRun` all
  put their out-of-contract value behind a guard at the top specifically
  because an unrecognised input must never read as an answer about pyry.
  `trailReasonPathUnnamed` breaks that pattern deliberately and correctly:
  its meaning *is* "the path reading names no runner", which is true of
  every label outside the two known runners without exception — so there is
  no out-of-contract case left over to guard against. Test whether a default
  value asserts more than its input supports, not whether the arm is
  syntactically a default.
- **A record's V2-shaped value needs its claim limit stated at the constant,
  not just satisfied by the predicate's behaviour.** `trailReasonPresentOwesNone`
  could easily have been read as "streamrunner produced a terminal_reason,
  so something is wrong" — the doc comment forecloses that reading directly,
  citing the exact passthrough line (`streamrunner/runner.go:170-176`) that
  makes claude an equally plausible author. A future consumer reading only
  the constant name, not the predicate's internals, needs that limit written
  where they'll see it.
- **A cross-product table generated from independent shape/path lists, not
  hand-listed rows, is what keeps "the reading compared whole instead of by
  label" (M5) from going invisible.** Hand-typing bare `"ptyrunner"` /
  `"streamrunner"` tokens as path fixtures — instead of real
  `tdnRunnerFromArgv(...)` calls that carry the parenthesised reason —
  would make M5 green, because there would be nothing for a whole-string
  comparison to fail to match.

## Lessons learned

(From PR #1371's body.)

- **A "no input byte interpolates" rule is checkable only where the
  reduction throws bytes away.** The leak sweep's two sub-tests are not
  redundant: sub-test A needles the key names and the decoded scalar, but
  only sub-test B needles the parenthesised tail `finRecordRunnerLabel`
  strips, and only B goes red when a `Detail` echoes the reading it was
  handed. Needling the label itself would have been green against a leaking
  implementation, because the label survives the reduction legitimately.
- **A bare `(:NNN)` cite's nearest named file can be the wrong attribution.**
  The stateful last-named-file scan flagged `finding_run_gather_test.go:1947`'s
  `(:778)` as inheriting `trailer_admissibility_test.go` and therefore
  needing the shift. It doesn't: the prose says "the file's **own** C2
  idiom", and line 778 of the *citing* file is that idiom. Reading the
  cite's own sentence, not just the scan's answer, is what separates a
  self-reference from an inherited one — re-pointing it would have created
  the staleness the sweep exists to remove.
- **Detail headroom was measured on the output, not argued from the format
  string.** All six arms land at 155–395 bytes against the 512-byte cap
  (`trailReasonPresentOwesNone` is tightest, 117 bytes spare), measured by
  an overlay-added test rather than inferred; the table test additionally
  asserts no arm's `Detail` ends in the truncation marker.
- **The new file is 643 lines against the spec's ~480–520 estimate**
  (661 insertions total vs. the ~600-line red line). The overrun is entirely
  doc-comment prose the spec itself prescribed — the claim limit, the
  default-arm-is-not-a-catch-all argument, the parameter-order reasoning,
  and the two mutant-matrix consequences — at this family's documentation
  density; no content beyond the spec was added.
- **A closure-check bug can ship as a non-blocking SHOULD FIX when the
  property it half-checks is still fully covered elsewhere.** Code review
  found the reached-set loop at `:432` records the *expected* value from
  the hardcoded matrix rather than the *observed* `got.Value`, making its
  "catches a sixth value with no arm" doc comment inaccurate — but the
  per-row `got.Value != want[pi][si]` assertion already catches that
  mutation class, so the space stayed fully verified and the fix was left
  for a future touch of the file rather than a follow-up ticket.
