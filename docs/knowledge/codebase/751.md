# Ticket #751 — resolve `session/prompt` with `stopReason` on `TurnEnd`

The **join** that completes divergence 1 of epic
[#600](https://github.com/pyrycode/pyrycode/issues/600): the one genuinely
event-stream-to-RPC-return part of the ACP adapter. Pyrycode's neutral model ends a
turn with a [`turnevent.TurnEnd{Reason}`](../features/turnevent-package.md) event;
ACP models a turn as a `session/prompt` request that streams `session/update`
notifications and then **returns** a `stopReason`. This ticket flips
`acpTurnStreams`' `onTurnEnd` seam from `nil` to
[#749](749.md)'s `promptHolds.end`, so a turn's terminal `TurnEnd` resolves the
held `session/prompt` call with the ACP `stopReason` mapped from the neutral reason.

Both halves already shipped and were independently tested — [#796](796.md) wired the
outbound `turnbridge.Producer` → `acpTurnStream` sink and deliberately left
`onTurnEnd` nil; #749 built `promptHolds` and its idempotent `end` resolver. This is
purely the wire between them; net production change is ~12 lines across two
`cmd/pyry` files, and the substance is the AC1–AC5 test matrix.

Spec: [`specs/architecture/751-acp-resolve-prompt-stopreason.md`](../../specs/architecture/751-acp-resolve-prompt-stopreason.md).
Feature doc:
[`features/acp-package.md` § Outbound streaming adapter → "TurnEnd → held-call resolution"](../features/acp-package.md#turnend--held-call-resolution-751).

## Implementation

**2 production files edited, package `main` only, purely additive. No new package,
no new exported type, and — deliberately — no new mapping function.** The
reason→`stopReason` map is **identity and already lives in the sink**
(`string(e.Reason)` in `acpTurnStream.Handle`'s `TurnEnd` branch); the neutral
`TurnEndReason` values were shaped to the ACP `stopReason` set on purpose, so a
wrapper that returns `string(r)` would be ceremony. Divergence, if it ever appears,
is caught by AC1's literal-string table, not a speculative indirection
(Evidence-Based Fix Selection).

- **`cmd/pyry/acp_turn_streams.go` (edit)** — the per-process manager
  (`acpTurnStreams`, from #796) gains an `onTurnEnd func(sessionID, reason string)`
  field and a matching param on `newACPTurnStreams(ctx, pool, dir, onTurnEnd,
  logger)`. It is **nil-tolerant**. At the `start` flip site the manager seam is
  bound to the fixed `sessionID` and passed to the sink's own `onTurnEnd`, preserving
  the nil path so #796's pure-emit tests and the `dir == ""` path still pass `nil`
  through:

  ```go
  var onEnd func(string)
  if m.onTurnEnd != nil {
      onEnd = func(reason string) { m.onTurnEnd(sessionID, reason) }
  }
  sink := newACPTurnStream(m.transport, sessionID, onEnd, m.logger)
  ```

- **`cmd/pyry/acp.go` (edit)** — at the composition root, `serveACPWithPool` passes
  the bound method value `holds.end` into `newACPTurnStreams`. `promptHolds.end` has
  signature `end(sessionID, stopReason string)` — a `func(string, string)` — so it is
  directly assignable to the new seam. `holds` is declared **before** `streams`
  (and is the same instance the `session/prompt` handler registers against), so the
  closure is well-formed and shares the live registry. The stale comments at the
  `holds`/`streams` construction site (previously "until then a delivered prompt stays
  held until host disconnect") are updated to describe the wired resolution.

### Data flow (after this ticket)

```
claude turn ends
  → turnevent.TurnEnd{Reason}                        (producer Run goroutine, after the last session/update)
  → acpTurnStream.Handle → onTurnEnd(string(Reason)) (sink, identity map)
  → m.onTurnEnd(sessionID, reason) == promptHolds.end(sessionID, reason)   (delete-under-mu; no-op if no pending call)
  → Responder.Reply(promptResult{StopReason: reason})                       (the held session/prompt returns)
```

## Concurrency model

No new goroutines, no new locks. Two correctness pins, both already guaranteed by the
merged code — the tests here are regression guards, not new machinery:

- **Resolution rides the producer's single `Run` goroutine, after the last
  notification.** `onTurnEnd` is invoked **synchronously inside**
  `acpTurnStream.Handle`'s `TurnEnd` branch, on the same goroutine that emitted every
  prior `session/update`. So the `stopReason` return is strictly ordered after all
  notifications on the outbound wire (ACP's streaming-precedes-return contract) — it is
  **not** a racing goroutine that could resolve before a late chunk. This was the
  explicit constraint in the ticket's Technical Notes.
- **No `writeMu` re-entrancy.** The `TurnEnd` branch returns immediately after
  `onTurnEnd`; it never calls `transport.Notify`. So `holds.end → Responder.Reply`
  (which takes `writeMu`) does not nest inside a `Notify` (which also takes `writeMu`).
  This is *not* the `OnChange`-fan-out deadlock class ([#722](722.md)) — the terminal
  branch emits no frame of its own.
- **Exactly-once across every resolve race (AC3).** `promptHolds.end` deletes the
  entry under `mu` before replying, and #765's `Responder.done` CAS guards the frame
  write. A second `TurnEnd` (or an `end`/`fail` race) finds no entry → no-op; the CAS
  bounds it even if two callers captured the same `*Responder`. No change needed.

## Error handling

- **Identity mapping, no new error path.** A `TurnEnd` always maps to a success
  `Reply`, never a `ReplyError`. The error path (`promptHolds.fail` →
  `CodeInternalError`) belongs to #749's delivery failure and is untouched.
- **Cancelled is a result, not an error (AC2).** A cancelled turn (`session/cancel`,
  [#753](753.md)) surfaces as `TurnEnd{Reason: cancelled}`, which resolves the held
  call with `stopReason: "cancelled"` via the same `Reply` path — never a JSON-RPC
  error frame. (Whether a cancel actually *produces* the `cancelled` reason is
  turnbridge/#753's concern; #751 only asserts the resolution shape given that reason.)
- **No pending call (AC4).** `promptHolds.end` on a session with no registered hold is
  a no-op (`resp == nil` → return). A `TurnEnd` for a never-prompted session is handled
  without error and emits nothing.

## Patterns established

- **Wire the seam at the composition root with a bound method value.** The manager
  stays decoupled from the concrete `promptHolds` type — it holds a
  `func(sessionID, reason string)`, consistent with the codebase's
  accept-a-function-at-the-consumer idiom (`promptDeliverer` / `interrupter` /
  `resolve`). The join is one assignment (`holds.end`); the manager is testable with a
  recording double, and nil disables resolution.
- **The reason set was designed so the map is `string()` identity — assert the whole
  set anyway.** AC1's table writes the expected values as **literal ACP strings**
  (`"end_turn"`, `"max_tokens"`, `"max_turn_requests"`, `"refusal"`, `"cancelled"`),
  *not* `string(turnevent.X)`, so a future divergence between the neutral reason set
  and the ACP `stopReason` set fails **there** — the intended containment point, ahead
  of a speculative divergence handler in the sink.
- **The pre-planned nil seam paid off as a one-line flip.** #796 shipped the producer
  wiring with `onTurnEnd` nil and #749 shipped `promptHolds`; the T6→T7 hand-off cost
  a field, a param, a per-session closure, and one composition-root assignment — no
  existing structure touched (additive-by-file, continued from #796).

## Code review

**PASS**, no blocking findings
([PR #799](https://github.com/pyrycode/pyrycode/pull/799)).

- **One NIT (accepted, non-blocking):** the manager's non-nil `start`-path closure
  (`func(reason){ m.onTurnEnd(sessionID, reason) }`) has no direct end-to-end
  assertion *through* `start` — AC5 builds the sink directly with an equivalent
  closure rather than driving `start`. This is a deliberate, spec-documented simplicity
  tradeoff: the binding is correct-by-construction (fresh per-call local, no
  loop-variable capture) and the nil branch is already exercised by
  `TestACPTurnStreams_LifecycleTeardownJoinsProducer`.
- **`make e2e-realclaude` red = environmental, NOT a code defect.** Every live-claude
  invocation in the suite returned `error_during_execution` with all-zero token
  usage / `total_cost_usd:0` — the canonical signature of a claude auth/rate-limit/infra
  outage, not this diff. Attribution is airtight: the realclaude suite does **not**
  import `cmd/pyry` and never invokes any ACP entrypoint; it exercises the
  agent-run → ptyrunner/streamrunner path this ACP-adapter diff does not touch. Per the
  [#789 lesson](789.md), this is **PASS + flag**, not `needs-rework:developer` — the
  unit suite that *does* cover this diff is green. (Operator re-runs the gate in a
  healthy live-claude environment for a clean signal.)

## Lessons learned

- **Obtaining a real `*Responder` in a test requires one `Serve` pass over a real
  `session/prompt` frame.** A `*acp.Responder` is only handed out through dispatch, so
  the AC5 end-to-end test registers `session/prompt` on a transport, runs `Serve` once
  over a single `promptFrame` fed via `strings.NewReader` (the handler registers the
  hold, returns `ErrDeferred` writing no frame, then hits EOF and returns nil), and
  *then* builds the sink on that **same transport** with `onTurnEnd → holds.end`. Only
  then is a real held call available to resolve over the wired producer.
- **Use a buffer-backed transport writer for the ordering assertion, not a blocking
  pipe.** Writing notifications and the result into one `bytes.Buffer` lets every frame
  accumulate for a single post-hoc decode. The notifications-precede-return ordering
  AC5 asserts is **structural** — the producer emits the result strictly after the
  notifications on its one `Run` goroutine — so a buffer suffices; the concurrent
  `io.Pipe` shape (`promptHarness`) is valid but heavier and unnecessary here.

## Testing

All tests package `main`, `-race`-clean via `make check`; the two existing
`newACPTurnStreams(...)` call sites
(`TestACPTurnStreams_LifecycleTeardownJoinsProducer`,
`TestACPTurnStreams_EmptyDirDisablesStreaming`) pass `nil` for the new param — they
don't exercise resolution.

- **`TestACPTurnStream_TurnEndMapsAllReasons` (AC1, sink level, divergence catcher)** —
  tables over all five `TurnEndReason` values; asserts the recorded string equals the
  **literal ACP stopReason**, exactly one `onTurnEnd` call, and zero emitted frames per
  reason. (Replaces #796's single-reason `TestACPTurnStream_TurnEndSignalsAndEmitsNothing`.)
- **`TestACPPrompt_ResolvesWithMappedStopReason` (AC1/AC2, wire level)** — reuses
  `promptHarness`: sends a `session/prompt`, `waitEntered`, `endTurn(sess, reason)`,
  then asserts `reply.Error == nil` and `reply.Result.StopReason == reason` for each of
  the five reasons — `cancelled` explicitly, proving it is a **result frame, not a
  JSON-RPC error**.
- **`TestACPPrompt_ExactlyOneResolution` (AC3)** — resolves once, reads the single
  reply, calls `holds.end` again (duplicate `TurnEnd`), then drives a fresh synchronous
  reply and asserts *it* — not a stray duplicate frame — is the next frame on the wire.
- **`TestPromptHolds_EndNoPendingIsNoop` (AC4)** — direct unit: `end` on an absent
  session returns without panic and writes nothing.
- **`TestACPTurnStreams_ScriptedTurnResolvesHeldPromptAfterNotifications` (AC5, e2e)** —
  a held `session/prompt`, scripted `thinking`/`text` `session/update` frames, then a
  terminal `endOfTurn`, over one real `turnbridge.Producer` → sink on one transport
  buffer; decodes every frame and asserts the single result frame (id 42,
  `stopReason: end_turn`) lands **last**, strictly after every notification.
- **`decodeFrames` helper** — factored out of `streamHarness.frames` and shared with
  the AC5 test (a clean dedup, noted approvingly in review).

## Out of scope (deferred)

- **A `session/prompt` return path that goes through `start`.** AC5 wires an equivalent
  sink closure directly rather than driving the manager's `start`; a direct
  through-`start` e2e is the accepted NIT above, not built (correct-by-construction,
  nil branch already covered).
- **Divergence between the neutral reason set and the ACP `stopReason` set.** Identity
  today; if a future ACP-spec revision diverges either set, AC1's literal-string table
  fails first and forces an explicit divergence handler in the sink's `TurnEnd` branch —
  the intended containment point. Not pre-built (no observed divergence).
