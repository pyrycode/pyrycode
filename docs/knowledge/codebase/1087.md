# Ticket #1087 — `internal/streamsup`: persistent stream-json child lifecycle

First slice of the new `internal/streamsup` package, the stream-json sibling of `internal/supervisor`. Stands up process lifecycle only: spawn a long-lived headless `claude` in `--input-format/--output-format stream-json --verbose` mode (never `-p`), hold its stdin open across many turns, restart on crash with the supervisor's exponential-backoff-with-stability-reset ladder, resume with `--resume <id>` (stable on-disk id, no fork), and tear down cleanly (SIGTERM→SIGKILL grace + reap of detached descendant Bash process groups). Split from #1076; #1088 (turn I/O) and #1089 (turncommit/idle/stall gates) build on top. Ships unwired — no pool/relay/`cmd/pyry` consumer yet.

Full design writeup: [features/streamsup-package.md](../features/streamsup-package.md).

## Implementation

- New package `internal/streamsup`: `runner.go` (`Config`, `Runner`, `New`, `Run`, `Stdin`, `buildArgs`, `spawnAndWait`), `backoff.go` (`backoffTimer`, copied verbatim from `internal/supervisor/backoff.go` — cannot import across the PTY/stream-json dependency boundary), `reap.go` (`reapDescendantGroupsFn` seam → `agentrun.ReapDescendantGroups`).
- `buildArgs(base, firstRun, sessionID)` is pure: fixed stream-json prefix, then caller args, then `--session-id <id>` on first spawn or `--resume <id>` on every respawn — same `sessionID` both times, which is what keeps the on-disk id stable across a kill-and-restart.
- Held-open stdin is the deliberate inversion from `streamrunner` (which closes stdin after one turn): `cmd.StdinPipe()` opened before `cmd.Start()`, stored under a leaf mutex, never closed while the child lives. `Stdin()` returns `io.Writer` (not `io.WriteCloser`) so #1088's writer can't close a handle this package owns.
- Teardown mirrors `streamrunner`'s reap shape verbatim: `cmd.Cancel` reaps descendant Bash process groups then SIGTERMs, `cmd.WaitDelay` = 5s SIGKILL fallback. Fires only on ctx cancel, never on a spontaneous crash (no evidence claude orphans groups on self-exit — deliberately no speculative crash-path reaping).
- Import boundary (AC1): stdlib + `internal/agentrun` (root) only. No `internal/supervisor`, no sibling `agentrun` subpackage. Verified via `go list -deps ./internal/streamsup/... | grep pyrycode/internal/supervisor` (expect empty) — pinned in the package doc comment.

## Patterns established

- **`started`-gated `firstRun` flip.** Fixed in follow-up commit 66cc50e after initial review. The naive port from `supervisor.Run` flips `firstRun = false` unconditionally after each iteration; but `supervisor.buildClaudeArgs` *ignores* `firstRun` once a `sessionID` is set, while `streamsup.buildArgs` *branches* on it (`--session-id` vs `--resume`). A spawn-**setup** failure (`StdinPipe`/`cmd.Start` erroring before claude ever launches) under the naive port would flip `firstRun` anyway, so the next retry uses `--resume` against a session that `--session-id` never established — claude errors "no conversation found" forever, a permanent crash-loop that defeats the retry the backoff loop exists for. Fix: `spawnAndWait` returns `(started bool, waitErr error)`; `Run` only advances `firstRun` when `started` is true. **Any future `streamsup`-family runner with a similar first-spawn/respawn argv branch should gate the branch flip on `cmd.Start` success, not merely "the iteration completed."**
- **`TestMain`-dispatch fake-child harness, not `os.Args[0]`+`-test.run`.** `streamrunner`'s helper harness re-execs the test binary via `-test.run <TestName> --` after the fixed args. That trick breaks here because `buildArgs` puts the package's own fixed stream-json flags (`--input-format …`) *ahead of* any caller-supplied args — there's no way to make `-test.run` sort first, so `go test` sees unknown leading flags and exits 2 before the helper logic runs. Fix: dispatch the fake child from `TestMain` on an env var (`GO_STREAMSUP_HELPER=1`) checked *before* `flag.Parse`/`m.Run`, sidestepping flag parsing entirely. This is the harness shape to reuse for #1088/#1089 rather than reaching for streamrunner's trick.

## Lessons learned

- (From the PR body.) The runner prepends the fixed stream-json flags before the caller's args, so the `os.Args[0]`-as-fake-child harness can't put `-test.run` first (unknown leading flags make `go test` exit 2 before the helper runs). Dispatching the fake child from `TestMain` on an env var — before `flag.Parse` — sidesteps flag parsing entirely, which is cleaner than the streamrunner `-test.run … --` harness for a package whose `buildArgs` owns the argv prefix.
- Same underlying gotcha as the "Patterns established" `firstRun` entry above: when lifting a restart-loop shape between two runners, check whether the *donor*'s state flag is actually consumed the same way downstream (`supervisor.buildClaudeArgs` ignores `firstRun` once a session id is set; `streamsup.buildArgs` branches on it) — an unconditional lift silently changes behavior at the seam the two runners don't share.
